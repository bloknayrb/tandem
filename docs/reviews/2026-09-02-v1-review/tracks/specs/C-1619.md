# C — #1619 Audience gate closed on push only: the MCP reads still carry `{comment, audience: private}`

Branch `fix/privacy-and-authority-1769`. Closes #1619, folded with #1803 (its write-side twin) per `areas/annotations.md:31-32`. Probe: source-confirmed — the four reads gate on `type` only.

## Problem

`narrowForChannel` (`projection.ts:187-268`) requires `audience === "outbound" && type !== "note"` before anything reaches the channel. The pull surfaces — authoritative over every push path — test type alone:

- `mcp/annotations.ts:64` `channelVisibleReplies`: `annotation.type !== "comment"`.
- `:409-410` `tandem_getAnnotations`: `a.type !== "note"`.
- `:633` `tandem_exportAnnotations`: `a.type !== "note"`.
- `mcp/awareness.ts:614` `userActions`: `ann.author === "user" && ann.type === "comment"`; `:636` `userResponses`: `ann.author === "claude" && ann.type !== "note" && ann.status !== "pending"`.

So a stored `{comment, audience: "private"}` record is withheld from the channel and delivered on the next poll. Same reachability as #1803 (legacy envelope, stale-tab merge), plus the import asymmetry the issue names.

## Fix

One exported read-side predicate, next to the push-side one so the two cannot drift by inspection:

- **`projection.ts`**: `export function isClaudeFacing(ann: Pick<Annotation, "type" | "audience">): boolean { return ann.type !== "note" && ann.audience === "outbound"; }` — the conjunction `narrowForChannel` re-asserts at `:255-265`. Leave those two reason-carrying `if`s (they feed `onRefused`) and add one sentence that the predicate and this pair must agree (Test 5). Rewrite the header `:21-27` ("This closes the push half only… Tracked in #1619") to say the pull half now uses `isClaudeFacing`. Not the same predicate as C-1803's `isPrivateForClaude`: a private highlight is unreadable here but refused by its own arm on the write side.
- **`annotations.ts:64`**: `if (annotation.type !== "comment" || !isClaudeFacing(annotation)) return [];` — the single reply gate every Claude egress routes through (`:56-58`), so `collectInboxUserReplies` (`awareness.ts:706`) and both reads inherit it.
- **`:409-410`**: keep `notesExcluded`; add `const privateExcluded = results.filter((a) => !isClaudeFacing(a)).length; results = results.filter(isClaudeFacing);` and return `...(privateExcluded > 0 ? { privateExcluded } : {})` beside `notesExcluded`. `output-schemas.ts:174-181` gains `privateExcluded: z.number().optional()` with the "omitted when zero" phrasing (the SDK hard-validates). Disclosed, not silent — the `notesExcluded` precedent.
- **`:633`**: `const notesFiltered = annotations.filter(isClaudeFacing);` plus `const privateExcluded = annotations.filter((a) => a.type !== "note" && !isClaudeFacing(a)).length;` — the Solo base becomes Claude-facing, so `heldFromExport = notesFiltered.length - exportable.length` at `:646` is unchanged and correct. Emit `...(privateExcluded > 0 ? { privateExcluded } : {})` beside `heldFromExport` at the three payload sites — `:826` (sidecar JSON), `:851` (JSON response), `:859` (markdown arm's response object). No markdown footer exists and none is added. Rewrite the `:643-647` comment to name both counts. No `output-schemas.ts` entry exists for the export.
- **`awareness.ts:614`**: `&& isClaudeFacing(ann)`; `:636`: `ann.author === "claude" && isClaudeFacing(ann) && ann.status !== "pending"` (C-1770 adds `&& ann.resolvedBy !== "claude"`). Production records reach this function sanitized (`document-store.ts:220`), so they always carry `audience`. **Fixture sweep, a starting point:** `makeAnnotation` (`ydoc-factory.ts:41-58`) has no `audience` default, so any fixture reaching a Claude-facing read WITHOUT sanitize must pass `audience: "outbound"` — `awareness.test.ts` and `awareness-tools.test.ts` are the known ones; `annotations.test.ts`, `edit-annotation.test.ts`, `document-store.test.ts`, `annotation-text-snapshot.test.ts`, `multi-document.test.ts` are candidates. An assertion that a USER highlight is returned will red, and that is the fix working. **Do not** loosen to `audience !== "private"`: an absent field is not consent (`channel-eligible-brand.test.ts:227-236`).
- `docs/mcp-tools.md:634` (getAnnotations) and `:1036-1037` (checkInbox): one sentence each — records whose stored `audience` is not `outbound` are excluded on every Claude-facing read, matching the channel; `privateExcluded` reports the count. `:781` (export): the sidecar and response carry `heldFromExport` and `privateExcluded` as two separate floors, both absent when zero.

Critical Rule 1: no Y.Map keys change. No new tool, route or gate.
