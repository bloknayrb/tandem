# W13v — #1980 (Refs only) parked and quarantined annotation envelopes are never read back

Branch `fix/server-and-cli-small-correctness-fixes-2003`. **References #1980; the issue stays open.** This PR ships only the doctor-remediation sliver the triage identified as unambiguous, and names what remains. Ledger: no `areas/*.md` row — filed from the E2-upgrade group's spec review as the tracked home for a deferral in `docs/reviews/2026-09-02-v1-review/tracks/specs/E2-upgrade-1791.md`'s "Not in scope"; wave 13 row in `docs/plans/2026-09-06-open-issues-sweep.md`. Probe: read the two remediation strings in `src/cli/doctor.ts` against `src/server/annotations/store.ts` and `src/server/file-io/reaper.ts`.

## Problem

Three write-only archives hold the user's personal notes (ADR-027) and nothing in the product reads any of them back: `<hash>.json.future` (plus the `<hash>.json.future.<ts>-<hex>` archives #1985 added), `<hash>.json.corrupt.<ts>`, and `<hash>.json.partial.<8 hex>` (the shape correction is in Bryan's comment on the issue, which supersedes the body's `.corrupt.partial`).

The recovery affordance itself — `tandem doctor --recover-annotations`, a Restore entry — is a product decision about surface and UX and stays with the issue. **Two doctor remediation strings are unambiguous, though: they state things that are not true**, verified against current source.

1. `"Written by a newer Tandem. Update, and they load again; they are never deleted."` (the `parkedFuture` warn). Bryan's comment states this directly: *"the 'Update, and they load again' remediation this issue quotes is still the wrong promise: an upgraded build reads `<hash>.json`, and nothing reads any of these files back."* The park **renamed the file away**, so an upgrade finds nothing at the active name. The second half ("never deleted") is true and stays.
2. `"Safe to delete after inspection; kept 7d by design."` (the `quarantined` warn). There is no 7-day mechanism and no reaper: `ATOMIC_TEMP_RE` (`src/server/file-io/reaper.ts`) is `^`/`$`-anchored to `.tandem-tmp-<ms>-<12 hex>` — its own docstring names `<hash>.json.corrupt.<ts>` among the files it can never match — and no other caller unlinks one. The files are kept **forever**, not 7 days.

Both are the class of text a user acts on: (1) tells them to upgrade and stop worrying, (2) tells them a cleanup exists.

## Fix

Text only, in `src/cli/doctor.ts` — two `r.warn` remediation strings. No new check, no new count, no new flag, no scan change.

- `parkedFuture` → name the file and the manual route, e.g.: *"Written by a newer Tandem and renamed aside, so an upgraded build does not load them — it reads `<hash>.json`. They are never deleted; recovering one is manual today (rename it back over `<hash>.json` with Tandem closed). See #1980."*
- `quarantined` → drop the false 7-day claim, e.g.: *"Kept indefinitely — nothing deletes them. Safe to delete after inspection; reading one back is manual today. See #1980."*

Rules that bite: `runDoctor`'s path reads are an accepted, bounded security finding (#1609) whose bound is the **input** — do not widen these strings into anything that reads or opens a file, and do not add a remediation that instructs doctor to act. Critical Rule 3: doctor's reporter already owns its output stream; add no new write. The `.partial` warn (#1791/#1985) is already accurate and is **not** edited.

Issue-reference note for the strings: a bare `#1980` in a user-facing remediation line is fine here (doctor text already carries none, so either include the full URL or keep it as `#1980` — pick the shorter and stay consistent between the two).

## Tests

`tests/cli/doctor.test.ts` already has a spec asserting the `parkedFuture` warn is emitted, keyed on `r.data.parkedFuture` rather than on the string, so it stays green by construction. Add two assertions to it (and its quarantine sibling, creating a minimal one if none exists — the file already builds a temp annotations dir):

1. The `parkedFuture` remediation does **not** contain `"load again"`, and does contain `.json.future`. Kills a revert and kills a rewrite that stays vague about which file to look for.
2. The `quarantined` remediation does **not** contain `"7d"` and does contain `"nothing deletes"` (or the chosen phrase). Kills the false-mechanism claim specifically — the failure mode here is a string that sounds reassuring and names a cleanup that does not exist.

Negative-string assertions are used deliberately: the defect is a false promise, and a positive-only assertion passes on text that still carries it.

## Done when

Both strings corrected; the two assertions green; `npm test` passes. The PR body states, and the issue receives a comment stating, **what remains on #1980**: the recovery affordance itself — `tandem doctor --recover-annotations`, a Restore entry, or an equivalent — for all three archive shapes, which is a product decision about surface and is Bryan's to make.
