## Problem

Measured on `a6e7352f`.

**Fixture:**
- The fallback session holds `"alpha beta gamma"`. Its `ann-W` is at `{6,10}` over `"beta"`, with a live relRange and `textSnapshot: "beta"` set explicitly (the `seedHighlight` default `""` is a real claim that the range is empty).
- The winning session is corrupt.
- The envelope's `ann-W` is at `{9,13}`, its offsets in `"alpha XX beta gamma"`. It carries a higher `rev`, so the file wins `pickWinner`.

**Result:**
- **Without an envelope snapshot:** the live range is `{9,13}`, which slices `"a ga"`, and the relRange is minted there. A confident wrong anchor is persisted. **Reproduced.**
- **With `textSnapshot: "beta"`:** the record is `degraded`. The failure is visible, but the session's correct anchor was discarded.

**Why:** `mergeMap` lets the file win, and site (b)'s `repairClonedAnchors` in `openFromDisk` re-mints from the file's offsets.

**The file's record is newer everywhere except the anchor.** It wins only by `rev` or `editedAt`, and `refreshRange` never bumps `rev`. So the envelope's `content`, `status`, `suggestedText` and `rev` must survive. Only its anchor describes text that no longer exists.

## Fix

`pickWinner` and `mergeMap` do not change, so every other merge caller's result is unchanged by construction.

1. **`cloneFallbackIntoDoc` returns the cloned records.** Its return type becomes `ReadonlyMap<string, Annotation>`.
   - The map is read from the live map AFTER the site-(a) `repairClonedAnchors` call.
   - It is read through a new `annotationsById(map, filePath)` in `annotation-wiring.ts`, which wraps that file's existing `collectAnnotations(map, docHash(filePath))`. This adds no new `open.ts` import edge.
   - `RestoreResult.fallbackRestored?: boolean` becomes `fallbackAnnotations?: ReadonlyMap<string, Annotation>`, and its presence gates site (b).
2. **Site (b) runs one `withMcp` transaction.** `withMcp` is non-`DURABLE_SKIP`, so the observer persists the overlay. For each `[id, cloned]`:
   - `live` is the current normalized record. **If `live === undefined`, skip:** a winning tombstone stays a delete.
   - **Gate G:** `storedRangeStillMatches(cloned, docText)`, AND `relPosToFlatOffset` on `cloned.relRange` resolves to exactly `[cloned.range.from, cloned.range.to]`. If G fails, skip, and the envelope's record takes today's path, including #1764's degraded report.
   - **Skip when the offsets agree** (`live.range.from === cloned.range.from && live.range.to === cloned.range.to`).
   - **Suggestion carve-out:** if `live.suggestedText !== undefined && live.textSnapshot !== cloned.textSnapshot`, skip. Accept replaces the span verbatim, so the text must be the text the suggestion was written for.
   - **Otherwise overlay the anchor only:** `map.set(id, { ...live, range: cloned.range, relRange, textSnapshot })`. `relRange` and `textSnapshot` are copied from `cloned`, or deleted when `cloned` lacks them. `rev`, `content`, `status` and `suggestedText` stay `live`'s, so the durable `rev` never goes down.
   - After the loop, run `repairClonedAnchors(doc, map, resolved, { skipTransact: true })` in the same transaction.
3. **Imports:**
   - `withMcp` joins the existing `../../shared/origins.js` import.
   - `storedRangeStillMatches` and `relPosToFlatOffset` join the existing `../positions.js` import.
   - A second statement from either module would redden `tests/docs/documents-boundary.test.ts`.
   - No raw `.transact`.
4. **Docblocks:**
   - Rewrite `cloneFallbackIntoDoc`'s "session record should win" paragraph and the site-(b) comment to describe the anchor overlay, citing #1863.
   - Correct the "gated on `fallbackRestored`" phrase in `repairClonedAnchors`.

Both non-throwing shapes stay in #1863. Each needs a policy choice (refusing a restore, or decoding every session twice):
