## Problem

**Anchor half, re-measured after #1764 (`7989261d`, merged 09-08, after #1863 was filed 09-04).** #1764 gated `refreshRange`'s mint arms on `storedRangeStillMatches`, which narrows but does not close the issue.

The fixture is the "fallback annotations re-anchor" layout:
- The fallback session is `"alpha beta gamma"`, holding `ann-W` at `{6,10}` over `"beta"` with a live relRange.
- The winner is corrupt.
- The envelope's `ann-W` has range `{9,13}` (its offsets in the winner text `"alpha XX beta gamma"`), `rev 1`, and an `editedAt`, so the file wins the tie.

Measured on `a6e7352f`:
- **Envelope record without `textSnapshot`** (every browser highlight, and a drifted Word comment): after open the live range is `{9,13}`, which slices `"a ga"`, and the relRange resolves to `[9,13]`. That is a confident wrong anchor saved to disk. **Reproduced.**
- **With `textSnapshot: "beta"`**: `degraded`, with the relRange stripped and the range `{9,13}` left wrong. The failure is visible now, but the session's correct record was still thrown away.

Mechanism: `mergeMap`/`pickWinner` (`src/server/annotations/sync.ts`) let the file win, and site (b) in `openFromDisk` (`repairClonedAnchors`, `src/server/documents/open.ts`) then re-mints from the file's flat offsets. That is the first bullet's case.

**The two non-throwing shapes, measured:**
- **Annotations-only update:** clean and dirty sessions do NOT reproduce. `fragment.length === 0` takes the empty-fragment fall-through, whose `evictBestEffort` clears the ghost, and the envelope stays clean. That is already pinned by "empty-fragment fall-through clears authorship ghosts and keeps the envelope clean" (`session-restore.test.ts`). **The live-room variant reproduces:** a room already holding content (as when the tab closed but the room survived) passes `fragment.length > 0` on the ROOM's content, so the result is `restored`, the ghost is live, and the ghost is in the envelope.
- **Wrong-document update:** reproduces. A clean session whose `ydocState` is another document's opens `restored` with that content.

Neither shape has a fix without a policy choice: refusing a restore, or decoding every session twice to validate its own fragment. Both go to Bryan and stay in #1863.

## Fix

`src/server/documents/open.ts` only. `sync.ts`, `pickWinner` and `mergeMap` stay byte-identical, so every other merge caller is unchanged by construction.

**The record choice, verified.** The restored content IS the fallback's, byte-exact. The session record's anchor fields describe that text; the envelope's describe text that no longer exists. But the envelope's record may carry newer non-anchor fields, such as a note's edited text or a status. So the session record wins only when the two anchors DISAGREE, which is exactly when the file's offsets are proven to be computed against other text.

1. `cloneFallbackIntoDoc` returns `ReadonlyMap<string, unknown>`, instead of `void`, holding the annotation records it cloned. They are read back from the live `Y_MAP_ANNOTATIONS` AFTER the site-(a) `repairClonedAnchors` call inside the same transact, so each carries its live relRange. Annotations only; replies carry no anchor.
2. `RestoreResult`: replace `fallbackRestored?: boolean` with `fallbackAnnotations?: ReadonlyMap<string, unknown>`. Its presence (not its size) is the site-(b) gate. Set it where `fallbackRestored = true` is set today.
3. Site (b), after `finalizeDocOpen`, runs one `withMcp` transaction (the default origin the site already uses: non-`DURABLE_SKIP`, so the attached observer queues the write, which `mergeMap`'s `needsWrite: false` never would):
   - For each `[id, cloned]`: `const live = map.get(id)`. If `live !== undefined && !sameAnchor(live, cloned)`, then `map.set(id, cloned)`.
   - Then `repairClonedAnchors(doc, map, resolved, { skipTransact: true })`.
   - `live === undefined` means the merge applied a winning tombstone, and a delete stays a delete.
4. `sameAnchor(a, b)` is module-private: equal `range.from`, `range.to` and `textSnapshot`, read defensively from `unknown`. The `textSnapshot` term catches a same-length edit inside the span (`"beta"` → `"BETA"`), where equal offsets still describe different text.
5. `withMcp` JOINS the existing `../../shared/origins.js` import statement. A second statement from that module makes the `open.ts -> shared/origins.ts (value) x1` row x2 and reddens `documents-boundary.test.ts`. Critical Rule 2 holds: no raw `.transact`, and `withMcp` is the helper the site's own comment already names.
6. **Rev:** the restored record keeps the session's `rev`, which may be below the envelope's, and the snapshot writes it. The next open then ties. State this in the docblock. It is not bumped, because a bump would make the record no longer the session's.
7. Docblocks:
   - Rewrite `cloneFallbackIntoDoc`'s "Stated sharp … the session record should win over the envelope for cloned ids" paragraph and the site-(b) comment to describe this rule, citing #1863. They must NOT claim #1764 alone closed it.
   - In `src/server/documents/annotation-wiring.ts`, correct `repairClonedAnchors`' "gated on `fallbackRestored`" phrase.
