## Problem

**Anchor half, re-measured after #1764 (`7989261d`, merged 09-08, after #1863 was filed 09-04).** #1764 gated `refreshRange`'s mint arms on `storedRangeStillMatches`, which narrows but does not close the issue.

The fixture:
- The fallback session is `"alpha beta gamma"`, holding `ann-W` at `{6,10}` over `"beta"` with a live relRange and **`textSnapshot: "beta"` set explicitly**. `seedHighlight`'s default is `""`, which since #1764 is a real claim that the range holds no text. Left at the default, site (a) takes the contradiction arm and the row tests the wrong thing (`session-restore.test.ts`, the comment above `ann-S` in "fallback annotations re-anchor after an edit").
- The winner is corrupt.
- The envelope's `ann-W` has range `{9,13}` (its offsets in the winner text `"alpha XX beta gamma"`), and either a higher `rev` or an `editedAt` on a rev tie, so the file wins `pickWinner`.

Measured on `a6e7352f`:
- **Envelope record without `textSnapshot`** (every browser highlight, and a drifted Word comment): after open the live range is `{9,13}`, which slices `"a ga"`, and the relRange resolves to `[9,13]`. That is a confident wrong anchor saved to disk. **Reproduced.**
- **With `textSnapshot: "beta"`**: `degraded`, with the relRange stripped and the range `{9,13}` left wrong. The failure is visible now, but the session's correct anchor was still thrown away.

Mechanism: `mergeMap`/`pickWinner` (`src/server/annotations/sync.ts`) let the file win, and site (b) in `openFromDisk` (`repairClonedAnchors`, `src/server/documents/open.ts`) then re-mints from the file's flat offsets. That is the first bullet's case.

**What the envelope's record can carry that the session's cannot.** The file beats a cloned session record only by a higher `rev` or, on a tie, an `editedAt`. `refreshRange` never bumps `rev` (its `updated` arm is `{ ...ann, range }`), and `nextRev` is `prev.rev + 1` (`annotations/schema.ts`), called only by lifecycle writes. So a file win by rev always carries a lifecycle edit the fallback session lacks (a note's content, a dismissed/resolved status, a colour, `suggestedText`), and a file win by `editedAt` means an edit at some point. Those fields have nothing to do with the reverted document text, so a disagreeing anchor does not make them stale. **Only the anchor is proven wrong.**

**The two non-throwing shapes, measured:**
- **Annotations-only update:** clean and dirty sessions do NOT reproduce. `fragment.length === 0` takes the empty-fragment fall-through, whose `evictBestEffort` clears the ghost, and the envelope stays clean. That is already pinned by "empty-fragment fall-through clears authorship ghosts and keeps the envelope clean" (`session-restore.test.ts`). **The live-room variant reproduces:** a room already holding content (as when the tab closed but the room survived) passes `fragment.length > 0` on the ROOM's content, so the result is `restored`, the ghost is live, and the ghost is in the envelope.
- **Wrong-document update:** reproduces. A clean session whose `ydocState` is another document's opens `restored` with that content.

Neither shape has a fix without a policy choice: refusing a restore, or decoding every session twice to validate its own fragment. Both go to Bryan and stay in #1863.

## Fix

`sync.ts`, `pickWinner` and `mergeMap` stay byte-identical, so every other merge caller is unchanged by construction.

**The rule: overlay the session's ANCHOR onto the merged record; never replace the record.** The restored content is the fallback's, byte-exact. The session record's anchor trio (`range`, `relRange`, `textSnapshot`) describes that text, and the envelope's describes text that no longer exists. Every other field (`rev`, `content`, `status`, `color`, `suggestedText`, `editedAt`, …) stays the merged record's. This is anchor maintenance, not an edit, so the existing ADR-027 justification for `MCP_ORIGIN` over note records (`repairClonedAnchors`' docblock) still holds: no note content is ever rewritten.

1. **Capture the cloned records.** `cloneFallbackIntoDoc` returns `ReadonlyMap<string, Annotation>` instead of `void`. The map is read back from the live `Y_MAP_ANNOTATIONS` AFTER the site-(a) `repairClonedAnchors` call inside the same transact, so each record carries the relRange and outcome site (a) left it. Read it through a new helper exported from `annotation-wiring.ts` beside `repairClonedAnchors`, for example `collectClonedAnnotations(map, filePath)`, which wraps the `collectAnnotations(map, docHash(filePath))` call that file already makes. That keeps `open.ts` on its existing `./annotation-wiring.js` statement, with no new `open.ts -> server/mcp/annotations.ts` edge in `tests/docs/documents-boundary.test.ts`. Annotations only: replies carry no anchor.
2. **`RestoreResult`:** replace `fallbackRestored?: boolean` with `fallbackAnnotations?: ReadonlyMap<string, Annotation>`. Its presence (not its size) is the site-(b) gate. Set it where `fallbackRestored = true` is set today.
3. **Site (b)**, after `finalizeDocOpen`, runs ONE `withMcp` transaction: non-`DURABLE_SKIP`, so the attached observer queues the write, which `mergeMap`'s `needsWrite: false` never would. Inside it, for each `[id, cloned]`:
   - `const live` = the normalized current record (via the same `collectAnnotations` read). **`live === undefined` → skip**: the merge applied a winning tombstone, and a delete stays a delete.
   - **Gate G, "site (a) accepted the session's anchor":** `storedRangeStillMatches(cloned, docText)` holds AND `cloned.relRange` resolves (`relPosToFlatOffset`) to exactly `[cloned.range.from, cloned.range.to]`. If G fails, the session's anchor is no better evidenced than the envelope's. Skip it, so the envelope's record goes through `repairClonedAnchors` below and #1764's degraded path reports it, exactly as today.
   - **Disagreement D:** `live.range.from !== cloned.range.from || live.range.to !== cloned.range.to`, OR both `textSnapshot`s are defined and differ. A snapshot present on only one side with equal offsets is NOT a disagreement: both records slice the same live text, so there is no anchor evidence to act on.
   - **Suggestion carve-out:** if `live.suggestedText !== undefined` and `live.textSnapshot !== cloned.textSnapshot` (strict, `undefined` included), skip. The merged `suggestedText` was written as a replacement for the envelope's snapshot text, and Accept replaces the stored span verbatim, so pairing it with a span holding different text would rewrite text it was not written for. Skipping leaves the record to #1764's degraded path, which is visible and loses nothing. A pure shift (equal snapshots, different offsets) is overlaid normally.
   - **If G && D and not carved out:** `map.set(id, overlay)`, where `overlay = { ...live, range: cloned.range }` plus `relRange` and `textSnapshot` copied from `cloned` when present and DELETED from the overlay when `cloned` lacks them. The trio moves as one unit, because G verified it as one unit against the restored text.
   - After the loop: `repairClonedAnchors(doc, map, resolved, { skipTransact: true })`, inside the same transaction.
4. **Rev never goes down.** The overlay keeps `live.rev`, which is ≥ the session's by construction (the file won). The snapshot therefore never writes a lower rev over a higher one, and it never writes a live record whose rev a stored tombstone can beat when the merged one could not.
5. **Imports without new boundary rows.** `withMcp` JOINS `open.ts`'s existing `../../shared/origins.js` statement. `storedRangeStillMatches` (newly `export`ed) and `relPosToFlatOffset` JOIN the existing `../positions.js` statement. `extractText` is already imported. Adding a second statement from either module makes its `x1` row `x2` and reddens `tests/docs/documents-boundary.test.ts`. If `relPosToFlatOffset` is not exported from `positions.ts`, take the gate's resolve term from the module that does export it, and add that one row to the boundary pin in the same commit, saying so in the PR body. Critical Rule 2 holds: no raw `.transact`.
6. **`positions.ts` docblock.** `storedRangeStillMatches` is described as "the one predicate behind all three arms of `refreshRange`". Add that it is exported for the #1863 fallback overlay gate, which must agree with the mint arms' definition rather than re-state `snapshotContradicts`' rule. No behaviour change.
7. **Docblocks:**
   - Rewrite `cloneFallbackIntoDoc`'s "Stated sharp … the session record should win over the envelope for cloned ids" paragraph and the site-(b) comment to describe the overlay, gate G, the suggestion carve-out and the rev argument, citing #1863. They must NOT claim #1764 alone closed it.
   - In `src/server/documents/annotation-wiring.ts`, correct `repairClonedAnchors`' "gated on `fallbackRestored`" phrase.

## Tests

All in `tests/server/session-restore.test.ts`'s #1800 describe, beside "fallback annotations re-anchor after an edit". `seedEnvelope` gains an optional `tombstones` argument (test helper only). Every session `ann-W` below sets `textSnapshot` explicitly.

1. **Live case, "fallback restore overlays the session's anchor when the envelope's disagrees (#1863)".** `it.each` over the envelope record without and with `textSnapshot: "beta"`. This one may reuse the "re-anchor" layout with its session-only `ann-S`, because it asserts no durability. It asserts:
   - the live `ann-W` range is `{6,10}` and slices `"beta"`;
   - its relRange resolves to `[6,10]`;
   - after `insertTextPrefix(doc, "XXXX ")`, `refreshRange` gives `{11,15}`/`"beta"`.

   Red on master in both rows.
2. **Durability case, "the overlay reaches the on-disk envelope and keeps the envelope's non-anchor fields".** Modelled on "post-merge repair reaches the on-disk envelope". The session's ONLY annotation id is `ann-W`, so `mergeMap` returns `needsWrite: false` and queues nothing. There are no test-side map writes, and `closeStore` runs straight after `openFromDisk`. The envelope's `ann-W` is at `{9,13}` with `rev: 2`, `content: "newer text"` and `status: "dismissed"`. The session's is `{6,10}`, `"beta"`, a live relRange and `rev: 1`. Assert:
   - live: range `{6,10}`, `content === "newer text"`, `status === "dismissed"`, `rev === 2`;
   - envelope after `closeStore`: `ann-W` range `{6,10}`, relRange resolves to `[6,10]`, `content === "newer text"`, `status === "dismissed"`, `rev >= 2`.
3. **Tombstone and rev, "an overlaid record is not deleted by a tombstone the merged record survives".** The envelope holds tombstone `ann-W@2` AND alive `ann-W` at `rev: 2` with a disagreeing anchor `{9,13}` (delete, undo, one edit). The session's `ann-W` is `rev: 1` at `{6,10}`. The merge deletes the session copy (`2 > 1`) and re-inserts the file's rev 2 (`2 > 2` is false). Assert:
   - the live `ann-W` exists at range `{6,10}` with `rev === 2`;
   - after `closeStore`, the envelope's alive `ann-W.rev` is ≥ its tombstone's rev;
   - after `closeDocumentById` and a reopen, `ann-W` still exists. Record in the test comment which restore path the reopen took, since a reopen can take the fallback again.

   A wholesale re-set at rev 1 turns all three red.
4. **Snapshot-only disagreement, "equal offsets with a different snapshot still overlay".** The session's `ann-W` is `{6,10}`/`"beta"`. The envelope's is `{6,10}`/`"BETA"`, `rev: 2`, with no relRange. On master the envelope's contradicting snapshot makes site (b) answer `degraded`. Assert that the live `textSnapshot` is `"beta"` and the relRange resolves to `[6,10]`.
5. **Suggestion carve-out, `it.each` with two rows.** The envelope's `ann-W` is a `comment` with `suggestedText: "BETA!"`.
   - Row "text differs": envelope `{6,10}`/`"BETA"`. Assert no overlay: the live `textSnapshot` stays `"BETA"`, there is no relRange, and `refreshRange` answers `degraded`.
   - Row "pure shift": envelope `{9,13}`/`"beta"`. Assert overlay: range `{6,10}`, and `suggestedText` is still `"BETA!"`.
6. **Agreeing anchors, "… keeps the envelope's record when the anchors agree".** The session and the envelope both hold `ann-E` at `{6,10}`/`"beta"`, but the envelope has `content: "newer text"` and `rev: 2`. Assert the live content is `"newer text"`.
7. **Tombstoned cloned id, "… a tombstoned cloned id stays deleted".** The envelope tombstone for `ann-T` is at `rev 5`, above the session's `rev 1`, with no alive copy. Assert it is absent live and absent from the envelope.
8. **Global-change twin, "a non-fallback restore still lets the envelope win".** `writeSessionFile` (single, not corrupt) holds `ann-W` at `{6,10}` over `"alpha beta gamma"` with `content: "session"`. The envelope has `{9,13}`, `editedAt` and `content: "envelope"`. Assert the live content is `"envelope"` and the range is `{9,13}`. **Mark this in a comment as a characterization:** a clean single-session restore has the session text as the envelope's text, so `{9,13}` (which slices `"a ga"`) is a scope pin showing the overlay did not run outside the fallback path. It is not the desired anchor, and a later correct fix to the non-fallback path may legitimately change it.
9. **The existing two cases stay green UNEDITED, by gate G.** "fallback annotations re-anchor after an edit (session-only and merged)" and "post-merge repair reaches the on-disk envelope" both seed the session's `ann-E` with `seedHighlight`'s default `textSnapshot: ""` against the envelope's `"beta"`. `storedRangeStillMatches` refuses `""` over `"beta"`, so G fails, no overlay runs, and site (b) repairs the envelope's record as it does today (`rE.kind === "updated"`, and the envelope relRange resolves to `[6,10]`). Without G's snapshot term the `""`/`"beta"` pair would count as a disagreement and both cases would go red, as round-1 review measured. So these two cases are the named kill for that term. Do not edit their fixtures.
10. **Mutations, restoring from a file copy each time (never `git checkout`). Each must turn the named case red:**
    - overlay → wholesale `map.set(id, cloned)`: 2 and 3 red.
    - site-(b) `withMcp` → `withFileSync`: 2 red (the envelope keeps `{9,13}`).
    - drop G's `storedRangeStillMatches` term: 9 red (both existing cases).
    - drop D's snapshot term: 4 red.
    - drop the suggestion carve-out: 5 row "text differs" red.
    - drop `live === undefined → skip`: 7 red.

    - in `sync.ts` `pickWinner`, flip the `fileEdit` number / `ymapEdit` undefined heuristic to return `"ymap"` (a global precedence change): 8 red.
