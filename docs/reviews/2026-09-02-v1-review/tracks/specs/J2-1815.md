# J2 — #1815 "One click connects" oversells the wizard's Done step, which still waits on a real MCP connection

Branch `fix/product-copy-1814`. Closes #1815. Ledger row: `docs/reviews/2026-09-02-v1-review/areas/product.md:21`. Probe: none (product copy, read-verified against source).

## Problem

`sample/welcome.md:46` (pre-fix) read: *"…use the setup wizard — one click connects Claude Code, no API key needed."* The wizard writes Claude Code's MCP config in one click, but the Done step (`IntegrationWizardModal.svelte`) does not claim the connection itself is instant — its header already distinguishes `doneHeaderState === "connected"` ("Claude is connected to Tandem") from `"waiting"` ("Config written — waiting for Claude to connect"). Of the `whatsNext` block's four arms (~L1120-1130), the two that address a *newly written* config both treat restart as the action and `/mcp` as verification (or, for `"unreachable"`, something that follows the restart) — neither treats `/mcp` alone as sufficient. So the wizard's own UI is already honest; the promise that's wrong lives in the doc, not the component.

`README.md:44` reads: *"…it can install it for you in one click on all three platforms, and it writes the connection settings itself."* Read closely, this does not claim the *connection* happens in one click — it separately scopes "install" from "writes the connection settings," and the paragraph's next sentences already tell the reader Claude Code needs to be running locally. **README.md needs no change.**

## Fix

`sample/welcome.md:46` only, matching every arm of the wizard's own `whatsNext` block (restart as the action, `/mcp` as verification):

> Want to connect your AI? Open Settings → AI Assistant and use the setup wizard — one click writes Claude Code's connection settings, no API key needed. Restart Claude Code to pick them up, then type `/mcp` to verify — or just ask Claude to open a document. (Support for additional model providers is on the way.)
