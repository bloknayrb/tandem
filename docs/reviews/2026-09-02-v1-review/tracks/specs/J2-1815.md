# J2 — #1815 "One click connects" oversells the wizard's Done step, which still waits on a real MCP connection

Branch `fix/product-copy-1814`. Closes #1815. Ledger row: `docs/reviews/2026-09-02-v1-review/areas/product.md:21`. Probe: none (product copy, read-verified against source).

## Problem

`sample/welcome.md:46` (pre-fix) reads: *"…use the setup wizard — one click connects Claude Code, no API key needed."* The wizard writes Claude Code's MCP config in one click, but the Done step (`IntegrationWizardModal.svelte`) does not claim the connection itself is instant — its own header already distinguishes `doneHeaderState === "connected"` ("Claude is connected to Tandem") from `"waiting"` ("Config written — waiting for Claude to connect", ~L1040). The `whatsNext` block (~L1120-1130) has four arms, and they are not uniform: `"connected"` reads *"Claude is connected and talking to Tandem. Ask it to open a document."* and `"stdio-only"` reads *"Open Claude Desktop to start using Tandem."* — neither mentions restarting, because for those two arms nothing needs to be picked up. The other two arms are the ones relevant to a newly written config: the `"unreachable"` arm reads *"Tandem doesn't seem to be running. Start Tandem, then restart Claude and run `/mcp`."*, and the default arm reads *"Restart Claude Code, then type `/mcp` to verify — or just ask Claude to open a document."* **In both arms that address a newly-written Claude Code config, restart is the action and `/mcp` only verifies** (or, in the unreachable case, follows the restart) — no arm treats `/mcp` in an already-open session as sufficient on its own. So the wizard's own UI is already honest; the promise that is wrong lives in the doc, not the component.

Issue title also names README.md. `README.md:44` (current) reads: *"…it can install it for you in one click on all three platforms, and it writes the connection settings itself."* — read closely, this does **not** claim the *connection* happens in one click; it separately scopes "install" (one click) from "writes the connection settings" (a fact, not a timing claim), and the paragraph's next sentences already tell the reader Claude Code needs to be running locally. **README.md needs no change** — re-verify this reading before touching it, since the issue title lumps the two files together.

## Fix

`sample/welcome.md:46` only. Per the wave-table note ("prefer the copy fix"), and confirmed correct by the Done step's own honest wording above: replace the overclaim with language matching what one click actually does and what happens next — **restart as the action, `/mcp` as verification, matching every arm of the wizard's own `whatsNext` block, not just the default arm.**

New line 46: *"Want to connect your AI? Open Settings → AI Assistant and use the setup wizard — one click writes Claude Code's connection settings, no API key needed. Restart Claude Code to pick them up, then type `/mcp` to verify — or just ask Claude to open a document. (Support for additional model providers is on the way.)"*

`tests/fixtures/welcome-snapshot.md` is currently identical to `sample/welcome.md` (confirm with `diff sample/welcome.md tests/fixtures/welcome-snapshot.md` before editing either) and pinned to it in **flat-text space**: `tests/server/tutorial-annotations.test.ts` compares `extractText(liveDoc)` against `extractText(snapDoc)` — parsed markdown reduced to flat text, not raw bytes. For a same-shape prose edit like this one the two are equivalent, so both files must still change identically or the test fails.

**A matching implementation is already committed on this branch** (inside the `docs(specs): J2 review round 2` commit, which also touched the six spec files) — `git diff origin/master -- sample/welcome.md tests/fixtures/welcome-snapshot.md` shows both files already carry this exact line.
