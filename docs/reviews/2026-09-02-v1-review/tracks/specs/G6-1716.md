## Problem

`chatReveal` (`rail-content.svelte.ts:88`) is torn down from four places, all routing through `closeReveal` (`:103-107`): the capture-phase `pointerdown` + Escape effect (`:146-167`), the document-switch effect (`:171-174`), `App.svelte`'s `toggleRightPanel` (`:1204-1219`, the close at `:1211`) and `sendChatMessage` (`:1967`).

**Nothing observes effective visibility.** The rail can become visible without the user pinning it: in Solo with `soloRailHidden` set, `rightVisible` is false (`model.svelte.ts:120-123`); the user opens the reveal; the session flips to Tandem — mode lives in `CTRL_ROOM` and broadcasts, so this is not a local action — and `rightVisible` becomes true with `chatReveal` still true. Same shape when `settings.rightPanelVisible` flips from the Settings modal.

A **pinned** rail then renders as a float: `class:rail-floating-chrome` and `class:floating` (`App.svelte:2462-2465`), the `rail-float-shadow` block (`:2476-2482`), and `data-testid="rail-float-right"` (`:2468`). The testid is the part with teeth — it is how E2E identifies a floating rail (`tests/e2e/chat-reveal.spec.ts:63`), so a spec arriving in this state gets a wrong answer with nothing failing.

## Fix

**One derived rule, not a fifth manual clear site** — the reveal exists to show content over a *collapsed* rail, so its precondition failing should end it.

- `rail-content.svelte.ts`: add a fourth `$effect` beside the document-switch effect (`:171-174`), in the same shape — **both reads unconditional**:

```ts
$effect(() => {
  const visible = opts.getEffectiveRightVisible();
  if (chatReveal && visible) closeReveal();
});
```

  The short-circuited form (`if (chatReveal && opts.getEffectiveRightVisible())`) never calls the thunk while `chatReveal` is false, so the visibility dependency drops out of the effect between reveals. It would still converge, but it is not the shape of the sibling effect, which reads `getActiveTabId()` unconditionally (`:172`) before testing `chatReveal` (`:173`).
  `getEffectiveRightVisible` is already an injected thunk (`:52`), wired at `App.svelte:256` to `effectiveRightVisible` (`:1178`), a `$derived` over settings and mode — so the dependency is live.
- **It writes one of its own dependencies, which is fine here**: the document-switch effect already does exactly that and converges, and `closeReveal` is guarded (`:104`), so the second pass is a no-op.
- **Keep `toggleRightPanel`'s explicit `closeReveal()`** (`App.svelte:1205-1213`) rather than deleting it as redundant. It is the **synchronous** half: it lands the close in the same commit as `railPinSnap.right = true` (`:1206`), whose whole job is one frame. The effect flushes afterwards, so removing the direct call would let the pin-snap frame paint a still-floating shell.
- **The body's adjacent note:** `ChatState.acknowledgeVisible` is declared at `useChatState.svelte.ts:31` and implemented at `:232-236` with **zero callers** — `grep -rn acknowledgeVisible src/ tests/` on master returns only those two, the differently-named `acknowledgeVisibleMessages` (`:113`, called from the live effect at `:164`) and a prose mention in `model.svelte.ts:153`. Drop the member and its implementation; leave `acknowledgeVisibleMessages` and the prose alone.

Rules that bite: the new effect **registers no listener**, so the capture-phase teardown-identity rule is untouched; `chatRevealDocumentId` stays a plain `let` off the interface (`:99`); no markup change, so no testid snapshot regeneration.

## Tests

All in `tests/client/rail-content.svelte.test.ts`, whose harness exposes `setRightVisible` and is `$state`-backed per its rule 1 (`:16-31`, `:40-86`); `mount` (`:88-97`) builds the model inside a real `$effect.root`, which is what makes the new effect run.

1. **"a reveal closes when the rail becomes pinned"**: open a reveal over a collapsed rail, `setRightVisible(true)`, assert `revealOpen` is false. Kills today's code and any fix that only clears inside `toggleRightPanel`. It does **not** kill an inverted or dropped condition — spec 3 does.
2. **"the reveal is not resurrected when the rail unpins again"**: continue spec 1 with `setRightVisible(false)`, assert `revealOpen` stays false. Kills a `$derived` mirror of visibility rather than a one-way teardown.
3. **Inversion killer — "a collapsed rail leaves the reveal alone"**: with `rightVisible` false throughout, `openReveal()`, flush, assert `revealOpen` is **still true**. The surviving-open assertion after the first flush is the whole instrument: an inverted (`chatReveal && !visible`) or dropped condition closes the reveal at open time, which spec 1 cannot see.
4. The existing `:100` spec ("opens over a collapsed rail and no-ops over a pinned one") must stay green — it pins `openReveal`'s guard, which this effect complements.
5. `acknowledgeVisible`'s removal is pinned by `npm run typecheck` + `npm run typecheck:tests`; no spec asserts the member, so add none for a deleted one.
6. **Mutation test** (memory rule): delete the new effect's body, watch **spec 1** go red by name; invert its condition, watch **spec 3** go red by name. Restore from a file copy, never `git checkout`.
