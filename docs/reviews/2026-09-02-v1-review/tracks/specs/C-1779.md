# C — #1779 Solo copy promises "won't see your comments or edits"; only the user's annotations are held

Branch `fix/privacy-and-authority-1769`. Closes #1779 (the copy; the optional `selectedText` gating in its body is declined below). Ledger: `docs/reviews/2026-09-02-v1-review/areas/product.md:17`, `areas/annotations.md:43`. Probe: `src/server/events/queue.ts:182-187` and `:205-215` (what Solo holds), `awareness.ts:357-391` (what it does not).

## Problem

Three user-facing sentences describe Solo as hiding the user's work from the AI:

- `src/client/editor/toolbar/ModeToggle.svelte:30` — "your AI pauses and won't see your comments or edits until you switch back to Tandem".
- `sample/welcome.md:28` (mirrored byte-for-byte in `tests/fixtures/welcome-snapshot.md:28`, which `tests/server/tutorial-annotations.test.ts:97-101` compares against the live file's flat text).
- `docs/user-guide.md:296` — "the AI's pending annotations are held back from the document" (an opacity fade plus rail hide, `index.html`; `tandem_comment` in Solo still creates, decorates and toasts).

What Solo actually holds, from the code: the user's own `annotation:created` / `annotation:edited` / user `annotation:reply` events are dropped before buffering (`queue.ts:245`) and every other non-chat event is withheld from external consumers (`:186`); the pull surfaces hide the user's annotations and replies (`mode.ts:84-91`). **Chat is delivered in both directions regardless of mode** (`queue.ts:185` "the always-delivered channel"; the `chatMessages` bucket in `awareness.ts:362-376` has no mode gate; the shipped skill `:74` tells Claude to answer chat in Solo). `tandem_getTextContent`, `tandem_getContext`, `tandem_search` and `activity.selectedText` (`awareness.ts:389-391`) are ungated. The track's phrase "what is actually held (annotations and chat)" is wrong on chat — the copy must not say chat is held.

## Fix

Copy only; no behaviour change. One sentence, reused:

- `ModeToggle.svelte:30` `title`: "Write undisturbed — the comments and replies you write are held from your AI until you switch back to Tandem. It can still read the document and answer chat." The Tandem button's title (`:38`) is accurate; leave it. No `data-testid` changes (Critical Rule 7).
- `sample/welcome.md:28`: "**Solo mode** — write undisturbed. The comments and replies you write are held from your AI until you switch back to Tandem; it can still read the document and answer chat." Apply the identical edit to `tests/fixtures/welcome-snapshot.md:28`. Line 28 is not a tutorial anchor — `TUTORIAL_ANNOTATIONS` `targetText`s are "highlight text and your AI sees it" (`:3`), "edit this document at the same time" (`:9`), "accept or dismiss" (`:32`) and "simplify onboarding" (`:50`) — and the new sentence must not contain any of those substrings (`indexOf` would drift). Do not touch any other line.
- `docs/user-guide.md:296`: "**Solo** — the AI's pending annotations are faded and the annotation rail is hidden so you can write without reacting to them; the AI can still read the document and add annotations. Resolved annotations (accepted/dismissed) are always visible regardless of mode." `:293` and `:298` already describe the held direction correctly; `:302-312` (the hold table) is accurate and stays.
- `status-ai-view.ts:104` already reads "Solo · comments held" (#1287) — no edit; `tests/client/status-ai-view.test.ts:142-149` unaffected.

`selectedText` gating (the issue's optional half): **declined**. `awareness.ts:389` feeds the skill's selection-context rule (`SKILL.md:78`, "In Solo mode, hold reactions until the user sends a chat message"), and chat itself is delivered in Solo, so hiding the selection would remove context from the one interaction Solo permits. The copy above says the AI can read the document, which covers the selection. If Bryan wants it held, it is a queue/awareness gate with its own spec — listed under `bryan`.
