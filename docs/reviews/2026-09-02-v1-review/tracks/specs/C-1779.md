# C — #1779 Solo copy promises "won't see your comments or edits"; only the user's annotations are held

Branch `fix/privacy-and-authority-1769`. Closes #1779 (the copy; the optional `selectedText` gating in its body is declined below). Ledger: `areas/product.md:17`, `areas/annotations.md:43`. Probe: `src/server/events/queue.ts:182-187`, `:205-215` (what Solo holds), `awareness.ts:357-391` (what it does not).

## Problem

Two user-facing sentences describe Solo as hiding the user's work from the AI:

- `src/client/editor/toolbar/ModeToggle.svelte:30` — "your AI pauses and won't see your comments or edits until you switch back to Tandem".
- `sample/welcome.md:28` (mirrored byte-for-byte in `tests/fixtures/welcome-snapshot.md:28`, which `tests/server/tutorial-annotations.test.ts:97-101` compares against the live file's flat text).

What Solo actually holds: the user's own `annotation:created` / `annotation:edited` / user `annotation:reply` events are dropped before buffering (`queue.ts:245`) and every other non-chat event is withheld from external consumers (`:186`); the pull surfaces hide the user's annotations and replies (`mode.ts:84-91`). **Chat is delivered in both directions regardless of mode** (`queue.ts:185`; the `chatMessages` bucket in `awareness.ts:362-376` has no mode gate; the skill `:74` tells Claude to answer chat in Solo). `tandem_getTextContent`, `tandem_getContext`, `tandem_search` and `activity.selectedText` are ungated. **The wave-table phrase "what is actually held (annotations and chat)" is wrong on chat — the copy must not say chat is held.** The PR body records this correction so the reviewer does not reopen it.

## Fix

Copy only; no behaviour change. The status bar already got it right (`src/client/status/status-ai-view.ts:109`, #1287: "your comments and replies aren't sent to the AI until you switch to Tandem (chat and document edits still work)"), so the toggle takes the same wording:

- `ModeToggle.svelte:30` `title`: "Write undisturbed — your comments and replies aren't sent to your AI until you switch to Tandem (chat and document edits still work)." The Tandem button's title (`:38`) is accurate; leave it. No `data-testid` changes (Critical Rule 7).
- `sample/welcome.md:28`: "**Solo mode** — write undisturbed. The comments and replies you write are held from your AI until you switch back to Tandem; it can still read the document and answer chat." Apply the identical edit to `tests/fixtures/welcome-snapshot.md:28`. Line 28 is not a tutorial anchor — `TUTORIAL_ANNOTATIONS` `targetText`s are "highlight text and your AI sees it" (`:3`), "edit this document at the same time" (`:9`), "accept or dismiss" (`:32`) and "simplify onboarding" (`:50`) — and the new sentence contains none of those substrings. Do not touch any other line.

`selectedText` gating (the issue's optional half): **declined, and the decline covers the whole `activity` bucket.** `awareness.ts:388-391` delivers `activity` (`isTyping`, `cursor`, `lastEdit`, `selectedText`) on the pull path with no mode gate. Same rationale for all four: `awareness.ts:389` feeds the skill's selection-context rule (`SKILL.md:78`), chat is delivered in Solo and needs the context, and document text is ungated anyway. The copy says chat and document edits still work and makes no claim about activity. The decline is written into #1779's closing comment naming the `activity` object and its four fields, so it is answerable from a tracked surface. If Bryan wants any of it held, it is a queue/awareness gate with its own spec.
