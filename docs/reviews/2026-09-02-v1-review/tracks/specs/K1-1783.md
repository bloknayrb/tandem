## Fix

**Assertions.** Measured shape for the invalid-arguments case (probed against the real
`registerAnnotationTools` + `InMemoryTransport`): the SDK does **not** throw; it returns
`{ isError: true, content: [{ type: "text", text: "MCP error -32602: Input validation error: Invalid
arguments for tool tandem_comment: Required at text" }] }`. So:

- `mcp-tool-integration.test.ts:472` — delete the try/catch; assert `result.isError === true`, and
  match the text **loosely** on `result.content[0].text` (`/-32602/` only — **not** `/text/`, which
  the response envelope's own `type: "text"` satisfies for any text-content error, and never the
  literal string: see
  `tests/server/range-bounds-validation.test.ts:131-149`, which records that pinning Zod's wording
  makes an SDK bump read as a regression). Read `result.isError`/`content` directly, not through
  `parseResult` — the error text is not JSON. **And** assert no annotation was created off the
  `ydoc` returned by `setupDoc` — `ydoc.getMap<Annotation>(Y_MAP_ANNOTATIONS).size === 0`, the shape
  the neighbouring test at `:460-461` already uses. Not `tandem_getAnnotations`: that read is
  Solo-filtered (`src/server/mcp/annotations.ts:417`), so its emptiness is mode-dependent. The
  no-mutation half is what kills the behaviour the issue names — a server that accepted the call.
- `awareness.test.ts:130` — the module ledger `resetInbox()` clears is private, so the body cannot
  observe it. Replace it with the dedup property the `describe("surfacedIds deduplication")` block
  claims, driven through the exported `processInboxAnnotations` with a caller-owned `Map`:
  `processInboxAnnotations([ann], text, ledger, (a) => a, "doc1", "tandem", () => false)` — all
  seven parameters are required and none may be elided. `modeState` must be `"tandem"` here:
  `"indeterminate"` is **not** fail-closed (`src/server/mcp/awareness.ts:555`) and `"solo"` would
  hide the record for an unrelated reason, measuring the privacy hold instead of dedup. One user
  comment surfaces once, is absent on a second call with the same ledger, and returns after
  `ledger.clear()`. Keep `resetInbox()` in `beforeEach` (`:39`) where it belongs.
- `changelog-path.test.ts:32` — build the deep path under `mkdtempSync(join(os.tmpdir(), …))`
  rather than hard-coding `/tmp/no-such-project/…`, and assert **either** `toBeUndefined()` **or**
  that the returned path lies outside the created tree. `findRepoFile` (`src/server/mcp/server.ts:100-112`)
  walks up to 5 ancestors and needs `CHANGELOG.md` *and* `package.json` in the same directory, so a
  bare `/tmp` path is unlikely-but-not-guaranteed to be undefined — the existing body's own comment
  already hedges it ("unlikely to have CHANGELOG.md anywhere in its hierarchy"). One extra line
  makes the assumption self-checking instead of runner-dependent.
- `integrations/apply.test.ts:335` — after `applyConfig`, re-read `configPath` and assert
  `mcpServers.tandem.url` is the url passed in. Kills a silent no-op at the cap boundary, which
  `.not.toThrow()` would not.
- `file-watcher.test.ts:276` — the `suppressNextChange` one. **There are two `it`s with this exact
  title**; `:436` is `unwatchFile` and already asserts `watchedCount()`. Call `suppressNextChange`
  for an unwatched path, then fire a real change on a watched one through the existing
  `createMockWatcher`/`mockWatch` machinery and assert the callback still fires. Kills "the
  suppression leaked to another path".
- `events/wake-socket.test.ts:284` — **not** `expect(ws.readyState).toBe(ws.CLOSED)`: after
  `await closed` that is necessarily true and asserts nothing the await did not. The server kills
  the socket with `ws.terminate()` (`src/server/events/wake-socket.ts:231`), so capture the close
  **`code`** — `ws.once("close", (code) => resolve(code))`; the node `ws` client's close handler is
  `(code, reason)` and has **no `wasClean`** (that is the browser `CloseEvent`, and asserting it
  would pass on `undefined` for any behaviour) — and assert `code === 1006`, the abnormal closure
  `terminate()` produces because no close frame is sent. Follow with
  `await settlesTo(getSubscriberCount, baseline, "slot released")` — the discriminating shape the
  neighbouring spec at `:293-304` already uses.

**Skips.** Delete the empty `test.skip` at `settings-modal.spec.ts:155`, keeping its explanatory
comment as a plain comment pointing at `settings-and-filters.spec.ts`. For `keyboard-a11y.spec.ts`,
run `npx playwright test keyboard-a11y.spec.ts -g "panel switcher"` once and record which branch it
takes **in the comment above `:266-271` itself**, not only in the PR body (CLAUDE.md: a criterion
whose evidence is untracked fails silently). If the assertions run, the guard is dead weight of the
#1529 shape — replace the runtime `test.skip` with `await expect(annotations).toHaveCount(1)` so a
layout-default change goes red instead of silently skipping. Keep the guard only if the measurement
shows it genuinely fires; then make the tabbed layout deterministic in `boot(page)` instead.
**Never widen this into a `test.skip` audit** — one spec, one measurement.

**Hook runner.** New `tests/scripts/workflow-state-hook.test.ts` (that directory is in
`tsconfig.tests.node.json` and in vitest's node project): `spawnSync("bash", ["tests/hooks/test_workflow_state.sh"], { cwd: ROOT })`,
assert `status === 0` and that stdout matches `/^OK: (\d+) assertions passed\.$/m` with the count
**pinned** — `expect(Number(m[1])).toBe(24)`, today's measured value. `N >= 1` is too weak for the
reason the count line is being read at all: the script is `set -uo pipefail`, **not `set -e`**
(`tests/hooks/test_workflow_state.sh:11`), so a helper that stops firing *degrades* the count and
still reaches `echo "OK: …"` at `:227`. The exact number is what detects a fixture that quietly
stops asserting; raise it in the same commit that adds a case.
`it.skipIf(process.platform === "win32")` with a comment saying `check` is ubuntu-only, so this runs
in CI on every PR; the script itself cleans up its `.claude/.workflow-state/test-stop-*` dirs.

**Two E2E, one new file `tests/e2e/inbox-pull-path.spec.ts`**, modelled on
`tests/e2e/annotation-lifecycle.spec.ts` (same `McpTestClient` + `createFixtureDir` /
`cleanupAllOpenDocuments` lifecycle) and using the existing helpers `selectTextStable`,
`openAnnotatePopup`, `submitAnnotation(page, "comment")`. No new `data-testid` — `mode-solo-btn` and
`mode-tandem-btn` are already in `__snapshots__/testid-set.snap.txt:285-286`, so no snapshot
regeneration. **Every cross-process step is `expect.poll`ed**: `submitAnnotation` returns on the
click (`tests/e2e/helpers.ts:288-295`) and the record reaches the server over Hocuspocus, so a bare
first call is a lag-flake and a bare *negative* call is worse — Playwright does not retry a passing
negative assertion.

1. *user annotates → Claude polls*: boot, open the fixture over MCP, **then assert the precondition
   before creating anything** — `expect.poll` on `tandem_status()` until `mode === "tandem"`,
   clicking `mode-tandem-btn` if it is not. Mode is global server state for the whole `test:e2e` run
   and three existing specs flip it (`settings-and-filters.spec.ts:410`,
   `mode-toggle-geometry.spec.ts:182`, `keyboard-shortcuts.spec.ts:229`); all three restore today,
   but a leaked Solo from a future one must fail here as a *stated* precondition, not as a
   mysterious empty `userActions` (`readModeState()` also has an `indeterminate` value,
   `src/server/mcp/awareness.ts:555`). Then create a user **comment** in the
   UI, `expect.poll` on `tandem_checkInbox` until `userActions` contains it (match on `content`), and
   a second poll does not (the dedup ledger — kills an implementation that re-reports everything).
2. *Solo holds on the pull path*, ordered so the negative assertion has a positive control:
   (a) still in **Tandem**, create the user comment and `expect.poll` on `tandem_getAnnotations`
   until it is present — that read never writes `surfaced` (only `processInboxAnnotations` does,
   `awareness.ts:635`), so it proves server-side arrival without poisoning the dedup ledger;
   (b) click `mode-solo-btn` and `expect.poll` until `tandem_status()` reports `mode: "solo"` —
   the flip is written from the browser into `CTRL_ROOM` and read server-side by `readModeState()`,
   so an earlier poll would fail for an unrelated reason; (c) `tandem_checkInbox` → `userActions`
   does not contain it; (d) click `mode-tandem-btn`, poll `tandem_status()` to `"tandem"`, poll
   `tandem_checkInbox` → it arrives. Creating in Tandem forgoes the `heldInSolo` stamp
   (`src/server/annotations/lifecycle.ts:1181`), which the `"solo"` branch of `hideFromAI` ignores
   anyway — it hides every `author === "user"` record server-authoritatively
   (`src/server/mode.ts:84-91`), so the control being tested is the same one. Mode is **global, not
   per-document** (`Y_MAP_MODE` in `CTRL_ROOM`), so an `afterEach` restores Tandem even on failure
   and **asserts the restore server-side** via `tandem_status` — a click that silently no-ops leaves
   every later spec in the run in Solo.

Reserved ports only (`scripts/test-ports.ts`); `reuseExistingServer: false` stays.

## Tests

annotation created" (accepting the invalid call), the ledger `clear()` round trip (broken dedup),

classes, with the examples, into a header comment in each scanner. `find_no_expect.py`'s header must

scanners where they are — promoting one to `scripts/ci/` is a "consider" in
`tracks/K-tests-and-lows.md`, not part of this PR.**
