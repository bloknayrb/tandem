## Fix

**Assertions.** Measured shape for the invalid-arguments case (probed against the real
`registerAnnotationTools` + `InMemoryTransport`): the SDK does **not** throw; it returns
`{ isError: true, content: [{ type: "text", text: "MCP error -32602: Input validation error: Invalid
arguments for tool tandem_comment: Required at text" }] }`. So:

- `mcp-tool-integration.test.ts:472` — delete the try/catch; assert `result.isError === true`, the
  text contains `-32602` and names the missing field `text`, **and** that no annotation was created
  (`tandem_getAnnotations` returns an empty list). Read `result.isError`/`content` directly, not
  through `parseResult` — the error text is not JSON. The second assertion is the one that kills the
  behaviour the issue names: a server that accepted the call.
- `awareness.test.ts:130` — the module ledger `resetInbox()` clears is private, so the body cannot
  observe it. Replace it with the dedup property the `describe("surfacedIds deduplication")` block
  claims, driven through the exported `processInboxAnnotations(…, surfaced, …)` with a caller-owned
  `Map`: one user comment surfaces once, is absent on a second call with the same ledger, and
  returns after `ledger.clear()`. Keep `resetInbox()` in `beforeEach` (`:39`) where it belongs.
- `changelog-path.test.ts:32` — `expect(findChangelogPath("/tmp/no-such-project/a/b/c/d/e/f")).toBeUndefined()`.
- `integrations/apply.test.ts:335` — after `applyConfig`, re-read `configPath` and assert
  `mcpServers.tandem.url` is the url passed in. Kills a silent no-op at the cap boundary, which
  `.not.toThrow()` would not.
- `file-watcher.test.ts:276` — the `suppressNextChange` one. **There are two `it`s with this exact
  title**; `:436` is `unwatchFile` and already asserts `watchedCount()`. Call `suppressNextChange`
  for an unwatched path, then fire a real
  change on a watched one through the existing `createMockWatcher`/`mockWatch` machinery and assert
  the callback still fires. Kills "the suppression leaked to another path".
- `events/wake-socket.test.ts:284` — add `expect(ws.readyState).toBe(ws.CLOSED)` after the await.

**Skips.** Delete the empty `test.skip` at `settings-modal.spec.ts:155`, keeping its explanatory
comment as a plain comment pointing at `settings-and-filters.spec.ts`. For `keyboard-a11y.spec.ts`,
run `npx playwright test keyboard-a11y.spec.ts -g "panel switcher"` once and record which branch it
takes: if the assertions run, correct the comment (the guard is not a permanent skip) and change
nothing else; if the guard fires on every run, make the tabbed layout deterministic in `boot(page)`
so the assertions execute. **Never widen this into a `test.skip` audit** — one spec, one measurement.

**Hook runner.** New `tests/scripts/workflow-state-hook.test.ts` (that directory is in
`tsconfig.tests.node.json` and in vitest's node project): `spawnSync("bash", ["tests/hooks/test_workflow_state.sh"], { cwd: ROOT })`,
assert `status === 0` and that stdout matches `/^OK: (\d+) assertions passed\.$/m` with N ≥ 1 — the
count line is what distinguishes "ran and passed" from "exited 0 having asserted nothing".
`it.skipIf(process.platform === "win32")` with a comment saying `check` is ubuntu-only, so this runs
in CI on every PR; the script itself cleans up its `.claude/.workflow-state/test-stop-*` dirs.

**Two E2E, one new file `tests/e2e/inbox-pull-path.spec.ts`**, modelled on
`tests/e2e/annotation-lifecycle.spec.ts` (same `McpTestClient` + `createFixtureDir` /
`cleanupAllOpenDocuments` lifecycle) and using the existing helpers `selectTextStable`,
`openAnnotatePopup`, `submitAnnotation(page, "comment")`. No new `data-testid` — `mode-solo-btn` and
`mode-tandem-btn` are already in `__snapshots__/testid-set.snap.txt:285-286`, so no snapshot
regeneration.

1. *user annotates → Claude polls*: boot, open the fixture over MCP, create a user **comment** in the
   UI, `tandem_checkInbox` returns it in `userActions` (match on `content`), and a second poll does
   not (the dedup ledger — kills an implementation that re-reports everything each call).
2. *Solo holds on the pull path*: click `mode-solo-btn`, create the comment, poll — `userActions`
   does not contain it; click `mode-tandem-btn`, poll again — it does. Mode lives in `CTRL_ROOM` and
   is **global, not per-document** (`Y_MAP_MODE`), so restore Tandem in an `afterEach` even on
   failure or every later spec in the run inherits Solo.

Reserved ports only (`scripts/test-ports.ts`); `reuseExistingServer: false` stays.

## Tests

The changes are the tests. The discriminating pairs are named inline above: `isError` + "no
annotation created" (accepting the invalid call), the ledger `clear()` round trip (broken dedup),

scanners where they are — promoting one to `scripts/ci/` is a "consider" in `tracks/K-tests-and-lows.md`,
not part of this PR.**
