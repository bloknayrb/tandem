# Gc2a — #1774 find/replace is off by one per hard break

Branch `fix/position-mapping-1776`. Closes #1774. Ledger: `docs/reviews/2026-09-02-v1-review/areas/client-editor.md:19`. Probe: harness `experiments/harness/a-bugs.test.ts` describe B, re-measured on this branch 2026-09-08 with a two-break fixture (below).

## Problem

`walkMatches` (`src/client/editor/extensions/find-replace.ts:74-86`) searches `node.textContent` (`:81`) and maps every match with `pos + 1 + idx` (`:84`). The two coordinate counts disagree at exactly one node type. Measured on this branch, on `<p>alpha<br>beta gamma<br>delta gamma</p><p>plain gamma</p>`:

| | contribution to `node.textContent` | contribution to PM positions |
|---|---|---|
| text node | `text.length` | `text.length` |
| `hardBreak` | **0** (`textContent` is `textBetween(0, size, "")`) | **1** (`nodeSize` of a non-text leaf) |

So the index-into-text and the PM offset drift by one per *preceding* break inside the block. Measured matches for `gamma`: `[11,16] [22,27] [37,42]`, covering `" gamm"`, `"a gam"`, `"gamma"` — drift 1, 2, 0. `replaceAll` with `DELTA` produced `"alpha\nbetaDELTAa\ndeltDELTAma\nplain DELTA"`: the replacement ate the space, left a stray `a`, and the count and highlight both looked right because the decoration is drawn at the same wrong offset. **The drift compounds per break, so a one-break fixture with a single match cannot tell a real fix from a constant `-1`** — hence two breaks and three matches below.

`hardBreak` is the schema's only inline non-text node (measured: `image` and `horizontalRule` are block leaves, and `walkMatches` visits only `isTextblock` nodes), so it is the whole of the bug today.

## Fix

One line, `find-replace.ts:81`:

```ts
const text = node.textBetween(0, node.content.size, undefined, "\n");
```

Every inline leaf then contributes exactly one character, and a non-text leaf's `nodeSize` is 1, so char index equals PM offset within the textblock **by construction** rather than by counting breaks — which is why this is preferred over subtracting a per-break correction. Pass the `leafText` argument explicitly rather than relying on a node's `spec.leafText`: the passed value wins, so a future inline leaf that declares a multi-character `leafText` cannot silently re-break the alignment. Add a two-line comment naming the 0-vs-1 asymmetry so the next reader does not "tidy" it back to `textContent`.

Consequences to state in the PR body:

- A query can no longer match **across** a break — `"alphabeta"` previously matched and produced a range spanning the break. `"\n"` is the separator `doc.textBetween(…, "\n", "\n")` already uses everywhere else in this codebase, and it reads as a line break to `\b` and `\s`; regex `.` does not cross it.
- `replaceActive`, `replaceAll` and `buildDecoSet` are unchanged: they consume `MatchRange` and were always correct given correct input.
- **These are PM positions, not flat offsets.** `walkMatches` deliberately stays in the ProseMirror system because its consumers are `Decoration.inline` and `tr.insertText`; do not route it through `src/client/positions.ts`. (CLAUDE.md, three coordinate systems.)
- No `$state` write is added — this is plugin state, not a Svelte handler, so the `createCoalescingTick` rule is not engaged. No `data-testid` is added or renamed, so `__snapshots__/testid-set.snap.txt` is not regenerated.
- Cost is unchanged in order: `textBetween` walks the same block `textContent` already walked, on the same `docChanged` path.

## Tests

New `tests/client/find-replace-hard-break.test.ts` (harness B converted and extended to two breaks). Not added to `tests/client/live-regions-find-replace.test.ts`, which tests the Svelte bar's live region rather than `walkMatches`. Fixture: `<p>alpha<br>beta gamma<br>delta gamma</p><p>plain gamma</p>`, query `gamma`.

1. **Every match covers exactly the query.** For each match, `doc.textBetween(from, to, "\n", "\n") === "gamma"`. Fails on master at drift 1 *and* 2, so it also kills a constant `-1` correction that fixes only the first break — the reason the fixture has two.
2. **Replace-all writes the right text.** After `replaceAll(view, "DELTA")` the document text is exactly `"alpha\nbeta DELTA\ndelta DELTA\nplain DELTA"`. Kills a fix that corrects only the decoration; reproduces and then forbids the character-eating corruption in the issue body.
3. **`replaceActive`** on the match after one break replaces exactly that match and leaves its neighbours intact.
4. **Control, no hard break.** A two-paragraph document with no `<br>` still matches exactly and returns the same count. Kills an over-correction that adds an offset unconditionally.
5. **No match spans a break.** Query `"alphabeta"` returns 0 matches. Pins the `"\n"` semantics and kills a "fix" that keeps a zero-width leaf placeholder and merely subtracts.

No new E2E spec: the bar is already driven through `tests/e2e/keyboard-shortcuts.spec.ts`, and the group's e2e stage runs the suite. Mutation-check each of (1)–(5) by restoring `textContent` from a file copy and confirming which go red.

## Done when

(1)–(5) pass and each is shown to fail with `textContent` restored; `npm run typecheck` + `npm test` green; the E2E suite green on the reserved ports.
