# Gc1 — #1773 The open dialog's per-session `×` and "Clear all" delete saved sessions with no confirmation, undo or toast

Branch `fix/client-state-highs-1772`. Closes #1773. Ledger: `docs/reviews/2026-09-02-v1-review/areas/client-ui.md:19`. Probe: none (source-confirmed); the E2E is written here.

## Problem

In `src/client/components/FileOpenDialog.svelte`, the per-row `×` (`:369-378`, testid `session-delete`) calls `deleteSession(session.filePath)` (`:64-72`) which awaits `deleteSessionByPath` immediately, and "Clear all" (`:326-334`, testid `sessions-clear-all`) calls `clearSessions` (`:74-81`) → `clearAllSessions`. There is no `confirm(`, no two-step arm, no undo and no toast anywhere in the file. The `×` is a 14 px glyph sitting 6 px from the row's reopen button; one stray click permanently discards a saved session — its persisted Y.Doc state, its `sourceFileMtime`, and the annotation count the row itself advertises. "Clear all" does that to every session, and both are one click from the dialog's most-used control.

## Fix

The **inline two-step confirm** the bulk bar already uses (`src/client/panels/BulkActions.svelte:47-85` swaps the row's contents whole between a rest state and a confirm state), applied twice in `FileOpenDialog.svelte`. Two new component-local `$state` cells beside the existing session state (`:35-42`):

```
let pendingDeletePath = $state<string | null>(null);
let clearAllArmed = $state(false);
```

- **Per row.** `session-delete` becomes the *arm*: `onclick={() => { pendingDeletePath = session.filePath; clearAllArmed = false; }}`. Its testid stays. Its `aria-label` gains an ellipsis — `aria-label={`Delete session for ${filename}…`}` — plus `aria-expanded={pendingDeletePath === session.filePath}`, because the current label (`:373`, `Delete session for ${filename}`) now describes a control that only *arms*: a screen-reader user would otherwise be told the button deletes, activate it, and get no announcement that a confirm step appeared. When `pendingDeletePath === session.filePath`, that row renders a confirm pair in place of the `×`, wrapped in a container with `role="status"` `aria-live="polite"` so the swap is announced — `session-delete-confirm` ("Delete", `aria-label={`Confirm delete session for ${filename}`}`) wired to the confirm handler below, and `session-delete-cancel` ("Cancel") clearing `pendingDeletePath`. Arming a different row overwrites `pendingDeletePath`, so at most one row is ever armed. (No testid is renamed by any of this, so Critical Rule 7 is unaffected by the a11y half.)
- **Clear all.** `sessions-clear-all` arms (`clearAllArmed = true; pendingDeletePath = null;`); while armed, that row is swapped for the sentence "Clear all N saved sessions?" plus `sessions-clear-all-confirm` and `sessions-clear-all-cancel`. Keeping it behind its own explicit confirm is the issue's requirement; it must **not** share the row-level flag (the BulkActions lesson at `SidePanel.svelte:521-523`: a third value on one flag renders the wrong row's wording against the wrong action).
- **`deleteSession` (`:64-72`) and `clearSessions` (`:74-81`) are untouched.** The disarm lives in the confirm button's `onclick`, which clears first and then calls: `onclick={() => { pendingDeletePath = null; void deleteSession(session.filePath); }}` and `onclick={() => { clearAllArmed = false; void clearSessions(); }}`. So a slow or failed request cannot leave a resolved row armed, and neither function learns anything about confirm state.
- **No `bind:this` and no focus `$effect` for either confirm.** Focus stays where the click left it. The BulkActions focus effect (`SidePanel.svelte:210-215`) is explicitly **not** part of what is being copied: the rows live in a keyed `{#each}` (`FileOpenDialog.svelte:339`, keyed on `session.filePath`), so a single shared bound ref is nulled by the other row's teardown — the exact hazard recorded at `SidePanel.svelte:193-198` for the two bars — and an `$effect` reading a `$state` that `bind:this` writes is the update-depth shape this codebase has already been burned by.
- `toggleSessions` (`:57-63`) clears both flags, so collapsing and re-expanding the section never re-mounts into a confirm state. That is the same hazard `SidePanel.svelte:529-531` records for the promote bar.
- **No `confirm()`** — it blocks Playwright and the browser-automation sessions this project verifies with, and #1824 already lists the per-tab `confirm()` loop as a Low to remove.
- **No Escape branch and no blur handler.** The dialog's own `onkeydown` (`:192-194`) closes on Escape and unmounts the whole component, which discards both flags — so "disarm on Escape" is satisfied structurally without touching the Escape owner pinned by `tests/client/escape-owner.test.ts`. A `blur` disarm is actively wrong here: blur fires before click, so it would make Confirm and Cancel unclickable.
- **Critical Rule 7.** `session-delete` and `sessions-clear-all` keep their exact names — four selectors are **added**, none renamed or removed. Regenerate `tests/design-system-impl/__snapshots__/testid-set.snap.txt` in the same commit (`npx vitest run tests/design-system-impl/testid-coverage.test.ts -u`). This is the snapshot Gc1-1772's Fix section calls unchanged; that clause is scoped to the #1772 commit, and this commit's diff to it is expected. For `docs/design-system-impl/testid-manifest.md`, do **not** add only the four new rows: the "Tabs strip & file open" family (`:99-103`) currently lists no session selector at all, while the snapshot (`:372-380`) already holds nine shipped ones (`session-delete`, `session-reopen`, `session-row`, `sessions-clear-all`, `sessions-empty`, `sessions-error`, `sessions-loading`, `sessions-section`, `sessions-toggle`) — the silent drift Critical Rule 7 warns about. Add a single `sessions-*` line to that family listing the existing nine **and** the four new ones, so the entry is self-consistent rather than a partial listing of one feature.
- **No server change.** `deleteSessionByPath` / `clearAllSessions` (`src/client/utils/sessions.ts`) and their routes are untouched: no new mutating `/api` route or MCP tool, so the license-gated set (both halves) and `NON_LOOPBACK_ALLOWED` are unchanged. No Y.Doc write, so Critical Rules 1–2 are not in play.
- Styling from semantic tokens only — reuse the row's existing `var(--tandem-fg-subtle)` / `var(--tandem-error-fg-strong)` / `var(--tandem-error-bg)`; no raw hex or rgba (`check-token-violation.sh` + pre-commit).
