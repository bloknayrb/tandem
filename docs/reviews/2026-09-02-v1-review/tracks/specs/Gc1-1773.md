# Gc1 — #1773 The open dialog's per-session `×` and "Clear all" delete saved sessions with no confirmation, undo or toast

Branch `fix/client-state-highs-1772`. Closes #1773. Ledger: `docs/reviews/2026-09-02-v1-review/areas/client-ui.md:19`. Probe: none (source-confirmed); the E2E is written here.

## Problem

In `src/client/components/FileOpenDialog.svelte`, the per-row `×` (`:369-378`, testid `session-delete`) calls `deleteSession(session.filePath)` (`:64-72`) which awaits `deleteSessionByPath` immediately, and "Clear all" (`:326-334`, testid `sessions-clear-all`) calls `clearSessions` (`:74-81`) → `clearAllSessions`. There is no `confirm(`, no two-step arm, no undo and no toast anywhere in the file. The `×` is a 14 px glyph sitting 6 px from the row's reopen button; one stray click permanently discards a saved session — its persisted Y.Doc state, its `sourceFileMtime`, and the annotation count the row itself advertises. "Clear all" does that to every session.

## Fix

The **inline two-step confirm** the bulk bar already uses (`src/client/panels/BulkActions.svelte:47-85` swaps the row's contents whole between a rest state and a confirm state), applied twice in `FileOpenDialog.svelte`. Two new component-local `$state` cells beside the existing session state (`:35-42`):

```
let pendingDeletePath = $state<string | null>(null);
let clearAllArmed = $state(false);
```

- **Per row.** `session-delete` becomes the *arm*: `onclick={() => { pendingDeletePath = session.filePath; clearAllArmed = false; }}`. Its testid stays. Its `aria-label` gains an ellipsis — `` aria-label={`Delete session for ${filename}…`} `` — because the button now only arms. When `pendingDeletePath === session.filePath`, that row renders a confirm pair **in place of** the `×`: `session-delete-confirm` ("Delete", `` aria-label={`Confirm delete session for ${filename}`} ``) and `session-delete-cancel` ("Cancel", clearing `pendingDeletePath`). Arming a different row overwrites `pendingDeletePath`, so at most one row is ever armed.
- **Clear all.** `sessions-clear-all` arms (`clearAllArmed = true; pendingDeletePath = null;`); while armed, that row is swapped for the sentence "Clear all N saved sessions?" plus `sessions-clear-all-confirm` and `sessions-clear-all-cancel`. Keeping it behind its own explicit confirm is the issue's requirement; it must **not** share the row-level flag (the BulkActions lesson at `SidePanel.svelte:521-523`: a third value on one flag renders the wrong row's wording against the wrong action).
- **`deleteSession` (`:64-72`) and `clearSessions` (`:74-81`) are untouched.** The disarm lives in the confirm button's `onclick`, which clears first and then calls: `onclick={() => { pendingDeletePath = null; void deleteSession(session.filePath); }}` and `onclick={() => { clearAllArmed = false; void clearSessions(); }}`. So a slow or failed request cannot leave a resolved row armed.
- **No `bind:this` and no focus `$effect` for either confirm.** Focus stays where the click left it. The BulkActions focus effect (`SidePanel.svelte:210-215`) is explicitly not part of what is copied: the rows live in a keyed `{#each}` (`FileOpenDialog.svelte:339`), so a single shared bound ref is nulled by the other row's teardown — the hazard recorded at `SidePanel.svelte:193-198`.
- **No `aria-expanded`.** It would be permanently `"false"`: the row swaps whole, so the button carrying it leaves the DOM at the moment the value would become true. `BulkActions.svelte:47-85`, the pattern being copied, carries none.
- `toggleSessions` (`:57-63`) clears both flags, so collapsing and re-expanding never re-mounts into a confirm state.
- **No `confirm()`** — it blocks Playwright and the browser-automation sessions this project verifies with.
- **No Escape branch and no blur handler.** The dialog's own `onkeydown` (`:192-194`) closes on Escape and unmounts the component, discarding both flags, so "disarm on Escape" holds structurally without touching the Escape owner pinned by `tests/client/escape-owner.test.ts`. A `blur` disarm is actively wrong: blur fires before click, making Confirm and Cancel unclickable.
- **Critical Rule 7.** `session-delete` and `sessions-clear-all` keep their exact names; **four** selectors are added (`session-delete-confirm`, `session-delete-cancel`, `sessions-clear-all-confirm`, `sessions-clear-all-cancel`), none renamed or removed. Regenerate `tests/design-system-impl/__snapshots__/testid-set.snap.txt` in the same commit (`npx vitest run tests/design-system-impl/testid-coverage.test.ts -u`). This is the snapshot Gc1-1772 calls unchanged; that clause is scoped to the #1772 commit, so this diff is expected. Add the four new selectors to the manifest's "Tabs strip & file open" family (`docs/design-system-impl/testid-manifest.md:99-103`).
- **No server change.** `deleteSessionByPath` / `clearAllSessions` (`src/client/utils/sessions.ts`) and their routes are untouched: no new mutating `/api` route or MCP tool, so the license-gated set and `NON_LOOPBACK_ALLOWED` are unchanged. No Y.Doc write, so Critical Rules 1–2 are not in play.
- Styling from semantic tokens only — reuse the row's existing `var(--tandem-fg-subtle)` / `var(--tandem-error-fg-strong)` / `var(--tandem-error-bg)`; no raw hex or rgba.

## Review corrections (scope cut)

Rounds 1 and 2 added an accessibility subsystem and a documentation repair that #1773 does not ask for. The cut removes them; the round-2 blocking finding is fixed directly.

**Fixed, not removed**

- **The `fetchMock` reassignment did not install the stub.** Confirmed in `tests/client/FileOpenDialog.test.ts`: `:33` declares, `:37` assigns, `:38` calls `vi.stubGlobal("fetch", fetchMock)` — which captures the function value — and the outer `beforeEach` runs before any nested one. The Tests section now requires `fetchMock.mockImplementation(...)` on the already-installed mock (or a second `vi.stubGlobal`), and states both consequences of getting it wrong: zero rows, and case (a)'s discriminating half passing vacuously against a never-called mock.

**Removed**

- **The two `LiveRegion` announcers, their two testids (`session-delete-announcer`, `sessions-clear-all-announcer`) and case (a)'s a11y assertions.** #1773 asks for a confirmation step, not for an announced one. The added-selector count drops six → four, the Critical Rule 7 bullet and Done-when shrink with it, and the "one host per message / `aria-atomic`" reasoning that came with `LiveRegion` leaves the spec entirely. The `aria-label` ellipsis on the arm stays — it is one character in an existing label and keeps that label from lying about what the button does.
- **The manifest drift repair.** Round 1 required a `sessions-*` line covering the **nine already-shipped** selectors the manifest never listed. Real, but pre-existing and unrelated to this issue: the manifest is a convenience copy no test reads (Critical Rule 7), so the drift is not load-bearing and belongs in its own commit. This spec adds only its own four rows.
- **The E2E's cancel → `toHaveCount(2)` settling round trip.** Replaced by `expect.poll` on the counter, which addresses the same sampling race in one line without a second interaction path to keep working.
