# Gc1 — #1773 The open dialog's per-session `×` and "Clear all" delete saved sessions with no confirmation, undo or toast

Branch `fix/client-state-highs-1772`. Closes #1773. Ledger: `docs/reviews/2026-09-02-v1-review/areas/client-ui.md:19`. Probe: none (source-confirmed); the E2E is written here.

## Problem

In `src/client/components/FileOpenDialog.svelte`, the per-row `×` (`:369-378`, testid `session-delete`) calls `deleteSession(session.filePath)` (`:64-72`) which awaits `deleteSessionByPath` immediately, and "Clear all" (`:326-334`, testid `sessions-clear-all`) calls `clearSessions` (`:74-81`) → `clearAllSessions`. There is no `confirm(`, no two-step arm, no undo and no toast anywhere in the file. The `×` is a 14 px glyph sitting 6 px from the row's reopen button; one stray click permanently discards a saved session — its persisted Y.Doc state, its `sourceFileMtime`, and the annotation count the row itself advertises. "Clear all" does that to every session, and both are one click from the dialog's most-used control.

## Fix

The **inline two-step confirm** the bulk bar already uses (`src/client/panels/BulkActions.svelte:47-85` swaps the row's contents whole between a rest state and a confirm state), applied twice in `FileOpenDialog.svelte`. Two new component-local `$state` cells beside the existing session state (`:35-42`):

```
let pendingDeletePath = $state<string | null>(null);
let clearAllArmed = $state(false);
```

- **Per row.** `session-delete` becomes the *arm*: `onclick={() => { pendingDeletePath = session.filePath; clearAllArmed = false; }}`. Its testid and `aria-label` stay. When `pendingDeletePath === session.filePath`, that row renders a confirm pair in place of the `×` — `session-delete-confirm` ("Delete", `aria-label={`Confirm delete session for ${filename}`}`) wired to `deleteSession(session.filePath)`, and `session-delete-cancel` ("Cancel") clearing `pendingDeletePath`. Arming a different row overwrites `pendingDeletePath`, so at most one row is ever armed.
- **Clear all.** `sessions-clear-all` arms (`clearAllArmed = true; pendingDeletePath = null;`); while armed, that row is swapped for the sentence "Clear all N saved sessions?" plus `sessions-clear-all-confirm` → `clearSessions()` and `sessions-clear-all-cancel`. Keeping it behind its own explicit confirm is the issue's requirement; it must **not** share the row-level flag (the BulkActions lesson at `SidePanel.svelte:521-523`: a third value on one flag renders the wrong row's wording against the wrong action).
- `deleteSession` / `clearSessions` keep their bodies and their `sessionsError` handling; each clears its own armed flag **before** the `await`, so a slow or failed request cannot leave a resolved row still armed.
- `toggleSessions` (`:57-63`) clears both flags, so collapsing and re-expanding the section never re-mounts into a confirm state. That is the same hazard `SidePanel.svelte:529-531` records for the promote bar.
- **No `confirm()`** — it blocks Playwright and the browser-automation sessions this project verifies with, and #1824 already lists the per-tab `confirm()` loop as a Low to remove.
- **No Escape branch and no blur handler.** The dialog's own `onkeydown` (`:192-194`) closes on Escape and unmounts the whole component, which discards both flags — so "disarm on Escape" is satisfied structurally without touching the Escape owner pinned by `tests/client/escape-owner.test.ts`. A `blur` disarm is actively wrong here: blur fires before click, so it would make Confirm and Cancel unclickable.
- **Critical Rule 7.** `session-delete` and `sessions-clear-all` keep their exact names — four selectors are **added**, none renamed or removed. Regenerate `tests/design-system-impl/__snapshots__/testid-set.snap.txt` in the same commit (`npx vitest run tests/design-system-impl/testid-coverage.test.ts -u`) and add the four rows to `docs/design-system-impl/testid-manifest.md` (a convenience copy no test reads — update it precisely because it drifts silently).
- **No server change.** `deleteSessionByPath` / `clearAllSessions` (`src/client/utils/sessions.ts`) and their routes are untouched: no new mutating `/api` route or MCP tool, so the license-gated set (both halves) and `NON_LOOPBACK_ALLOWED` are unchanged. No Y.Doc write, so Critical Rules 1–2 are not in play.
- Styling from semantic tokens only — reuse the row's existing `var(--tandem-fg-subtle)` / `var(--tandem-error-fg-strong)` / `var(--tandem-error-bg)`; no raw hex or rgba (`check-token-violation.sh` + pre-commit).

## Tests

**1. Component, appended to `tests/client/FileOpenDialog.test.ts`** (a new `describe`; the file's `beforeEach` already does `vi.stubGlobal("fetch", …)`, so **no `vi.mock` of `utils/sessions.js`** — mocking it would test the mock and would be file-wide over the existing 162 lines). Give the stub a URL-aware implementation: `GET /api/sessions` (`API_SESSIONS`) returns two rows, `POST /api/sessions/delete` and `/api/sessions/clear` return `{ ok: true }`. Click `sessions-toggle` to expand, `await tick()`, then:

- **a) The fix, per row.** Click `session-delete` on row 1. Assert **no fetch call whose URL contains `API_SESSIONS_DELETE`** and that both rows are still rendered (`session-row` count 2). This is the discriminating assertion — a confirm affordance that still fires the request is exactly the bug. Then click `session-delete-confirm`; assert exactly one `API_SESSIONS_DELETE` call, with the right `filePath` in its body, and one remaining row.
- **b) Cancel.** Arm, click `session-delete-cancel`; assert zero delete calls, two rows, and `session-delete` back on that row.
- **c) One row armed at a time.** Arm row 1, then click row 2's `session-delete`; assert exactly one `session-delete-confirm` in the DOM and that it belongs to row 2. Kills a shared boolean flag that arms every row at once.
- **d) Clear all.** Click `sessions-clear-all`; assert no `API_SESSIONS_CLEAR` call and the rows still present; click `sessions-clear-all-confirm`; assert one call and `sessions-empty` rendered. Then a second run cancelling instead: zero calls.
- **e) The two confirms are independent.** Arm a row, then click `sessions-clear-all`; assert the row's confirm is gone and only the clear-all confirm is showing. Kills one shared flag driving both — the BulkActions failure mode named in the Fix.
- **f) Collapse disarms.** Arm a row, click `sessions-toggle` twice; assert the row renders `session-delete`, not `session-delete-confirm`.

**2. E2E, new `tests/e2e/session-delete-confirm.spec.ts`.** Deterministic without any server-side session state: `page.route("**/api/sessions", …)` fulfils a two-row list (precedent `settings-modal.spec.ts:164`), and `page.route("**/api/sessions/delete", …)` records the call and fulfils. Open a document via MCP, `page.goto("/")`, `Control+o` → `file-open-dialog` visible (the `keyboard-shortcuts.spec.ts:72-76` flow), click `sessions-toggle`, click `session-delete`; assert `session-delete-confirm` is visible **and** the recorded delete-call count is 0; click `session-delete-cancel`; then repeat through `session-delete-confirm` and assert the count is 1 and the row is gone. Same for `sessions-clear-all` against a routed `**/api/sessions/clear`. Reserved harness ports only — never 3478/3479. No conditional `if (rows > 0)` guard anywhere: a skipped-by-data E2E is green forever and reads as a pass (the #1529 lesson).
