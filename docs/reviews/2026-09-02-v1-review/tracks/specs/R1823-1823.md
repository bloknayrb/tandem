## Problem

1. **Production stderr filter drops format placeholders** (`index.ts:79-99`, not `:76-94`). `const msg = args.map(String).join(" ")` stringifies each arg and joins, so `console.error("failed for %s (%s):", id, p, err)` prints `failed for %s (%s): id p Error: boom` — placeholders literal, **and the Error's stack gone** (`String(err)` is `"Error: boom"`; `util.format(err)` is the full stack). Objects become `[object Object]`. **Production-only**: the `else` branch aliases to `console.error`, which formats normally. Measured, not quoted: **52** single-line placeholder sites in `src/server/` (`grep -rnE 'console\.(log|warn|info|error)\([^)]*%[sdifjoOc]' src/server/ --include=*.ts | wc -l`), not the issue's 48; **168** multi-arg sites total, every one losing `util.inspect` formatting. The single-line regex is a lower bound — it cannot see calls wrapped across lines.
2. **Sentry ships the hostname and absolute frame paths** (`sentry.ts:94` `sendDefaultPii: false`, `:99` `beforeSend`). The hook scrubs `event.message` and `exception.values[].value` and nothing else. **Measured with a real captured event under our exact options** (`defaultIntegrations: false` included): `server_name: "DESKTOP-QB8F1UO"` and frames carrying an absolute `filename` with `in_app: true`. **Anchor correction — there is no `abs_path` key at all** in `@sentry/node` 10.73 (frame keys are `filename,module,function,lineno,colno,in_app,debug_id`), so a fix that scrubs `abs_path` is a silent no-op. `contexts` holds only `trace` + `runtime`; `breadcrumbs` is empty. `docs/security.md:172` currently *documents* this leak as a known bound (written by #1901 out of #1821), so the code fix makes that paragraph false.
3. **stdio never exits on stdin EOF** (`index.ts:188-192`, not `:735-752`). The handler's entire body is a `console.error`. Nothing else closes on EOF: `StdioServerTransport` registers only `data` and `error` on stdin (SDK `server/stdio.js:43-44`), never `end`/`close`. The server survives its client forever.
4. **The SIGTERM/6 s item is REFUTED as written, and two comments are false.** There is no comment at `index.ts:229-233`; the constant is `SIGTERM_GRACE_MS = 6_000` at `supervisor.ts:1935`. It is **not dead code**: on Windows `c.kill("SIGTERM")` is `TerminateProcess`, the reaper dies at once, `exit` fires, and the race resolves immediately — only the SIGKILL escalation is unreachable there. What *is* false is the rationale: `index.ts:265-270` says routing through SIGTERM "gives Claude a chance to flush", and `reaper/src/windows.rs` is a Job Object + `WaitForSingleObject` with **no signal handler at all** — the SIGTERM→grace→SIGKILL relay is `#[cfg(unix)]` (`reaper/src/common.rs:11`), so `TerminateProcess` closes the job handle and `KILL_ON_JOB_CLOSE` kills Claude with no flush window. `cli/start.ts:58`'s "(correct cross-platform behavior)" overstates the same thing.
5. **`existing-config.ts:221` has no BOM strip and no size cap.** A BOM'd `~/.claude.json` throws in `JSON.parse` → `status: "malformed"` → the wizard pre-selects skip and calls the file broken, while `applyConfig` (`apply.ts:1109`) and `readConfigForMutation` (`:1276`) both strip U+FEFF and rewrite the same file happily. Two surfaces disagree about one file — the #1801/#1802 shape. The read is request-driven (`GET /api/integrations/existing`, wired at `mcp/server.ts:907`) and parses synchronously, which is what the cap is for.
6. **Orphaned `.tandem-setup-*.tmp` are never reaped** (created `apply.ts:954`). Every error path calls `unlinkOrLeak` (`:1019`), so orphans arise only from a SIGKILL between `writeFile` and `rename`, or a failing `unlink`. Destinations are `$HOME` (beside `~/.claude.json`), the Claude Desktop config dir, and `~/.claude/skills/tandem/`.
7. **`queue.ts` tracks ids before the forward decision.** Tracking runs at `:273`; `const forwardExternally = shouldForwardExternally(event)` is bound *after* it, at `:289`, above the delivery-state join at `:320`. In **Solo** with an external consumer attached, the events `isUserPrivacyHeld` does not drop — `annotation:accepted`, `annotation:dismissed`, and a **Claude-authored** `annotation:reply` — increment `emittedPayloadIds` even though the fan-out skips every external subscriber (`:328`). `wasEmittedViaChannel` then returns true and `tandem_checkInbox` stamps `alreadyPushed: true` (`awareness.ts:822`, `:952`) on an item nothing outside the process received — exactly the lie the `Track only when the fan-out below is non-empty` comment (`:253-272`) narrowed the gate to remove.
8. **Store-lock `startedAtMs` is written and never compared.** Written `lockfile.ts:25`, parsed `:44`, and **no comparison site exists anywhere in `src/`** (grep: only the write, the parse, the type and docblocks). So `tryReclaimStaleLock` (`store.ts:233`) rests on `isPidAlive` alone (`:156`), and after a reboot a reused PID makes a dead holder look live → `"readonly"` until the user finds `POST /api/store/reclaim-lock`.
9. **A symlink refusal is reported as "check permissions".** `assertPathSafe` throws `PathRejectedError` (`apply.ts:632`), which is **not** a `ConfigRefusalError`; `setup.ts:341` records `refusals` only for the latter, so the all-failed branch fails the `refusals.length === failures` test at `:183` and falls to the generic `"Setup failed — could not write any configuration. Check file permissions."` at `:185` — the dead end #1802 removed for the other two refusal classes, still live for this one.
10. **`setup --apply` after `rotate-token` drops the token.** Anchor wrong: `grep -n token src/cli/setup.ts` returns **nothing**. Reproduced by reading instead: `writeTargets` (`setup.ts:330`) calls `buildMcpEntries(CHANNEL_DIST, { withChannelShim, targetKind })` with **no `token`**, while `applyConfigWithToken` (`apply.ts:2528`) passes one; `buildMcpEntries` emits `headers.Authorization` / `env.TANDEM_AUTH_TOKEN` only `if (opts.token)` (`:503,512,520`), and `applyConfig` merges `{...existing.mcpServers, ...ops.create}` (`:1190-1192`) — a whole-entry replace at the `tandem` key. So the header written by rotation is gone. Bounded, not fatal: the auth middleware exempts loopback, so the default install keeps working and only an off-loopback (Cowork/LAN) client 401s.
11. **`--help` drift is one line.** Every dispatched command appears in the help text (`cli/index.ts:48-88`) **except `start`** (dispatched `:193`, documented only as bare `tandem`). `docs/cli.md:127` already documents `tandem start`, so the drift is one-sided — no docs twin.
12. **"stdio-mode" is shown during the HTTP startup window.** `initial-reason.ts:37` returns `"stdio-mode"` as the fallback for every non-kill-switch, non-deferral case, so an HTTP start holds it from boot until `startLauncherSupervisor()` assigns a supervisor — and the HTTP server is already listening by then (`index.ts:737-760` awaits `startMcpServerHttp`; the launcher block is `:820+`, with an **awaited** `refreshAllMcpEntryBinaries()` between them, measured at ~524 ms on Windows). In that window `GET /api/launcher/status` answers `{available:false, reason:"stdio-mode"}`, the client's first successful read sets `settledOnce` (`useAiReadiness:498`), `isTransientlyUnavailable` is false → readiness resolves **`unconfigured`** and a fully-configured user is shown the setup CTA — the outcome `useAiReadiness:704-715` calls "worse than saying nothing" for the deferral case.

## Fix

Ten separable commits. **Critical Rule 3 governs 1 and 3: every `console.*` in `src/server/` goes to stderr by design — do not route anything to stdout.** `src/server/index.ts` must never be imported by a test (importing it runs `main()` → `freePort()` → kills whatever holds :3478/:3479); `launcher/initial-reason.ts` exists for exactly that reason and is the extraction precedent.

- **(1)** New `src/server/log-filter.ts`, modelled on `initial-reason.ts` (pure module, no import side effects, its own docblock saying why it is not in `index.ts`): export `SUPPRESSED_PATTERNS` and `formatLogLine(args: unknown[]): string | null` (`null` = suppressed), body `const msg = format(...args)` from `node:util` then the existing pattern test. `index.ts:86-89`'s `filteredError` becomes a three-line caller. `util.format` keeps the `^`-anchored patterns working — the formatted string still starts with the first arg's text.
- **(2)** Extend the existing `beforeSend` (`sentry.ts:99`) only: `delete event.server_name`, and map each `exception.values[].stacktrace.frames[]` `filename` through the existing `scrub()`. **Scrub `filename`, not `abs_path`** — the latter does not exist in this SDK, per the probe. Then rewrite `docs/security.md:172`'s "they do **not** touch stack-trace frame paths … or `server_name`" sentence to state what now happens. No claims test pins that paragraph (`tests/docs/security-findings-claims.test.ts` pins the open-findings count and enumeration only; `sentry` does not appear in it) — measured, so the doc edit stands alone.
- **(3)** `index.ts:189-191`: after the existing log line, `void shutdown("stdin EOF")`. `shutdown` is already idempotent via `markShuttingDown()` and already ends in `process.exit(0)`, so this is one added call, not a new path.
- **(4)** **Comments only, no behaviour change.** Correct `index.ts:265-270` to say the flush window is POSIX-only and that on Windows the reaper is terminated outright with `KILL_ON_JOB_CLOSE` doing the killing; correct `cli/start.ts:56-59` to drop "(correct cross-platform behavior)" and say what actually happens per platform. The behaviour question — whether Windows should get a graceful reaper stop — is **Bryan's**, and is the same family as the OPEN #1994 (macOS); it is listed under `bryan`, not filed as a second issue, because no decision has been taken yet.
- **(5)** `readOneTarget` (`existing-config.ts:218`): `stat` first and, over `MAX_CONFIG_BYTES` (already exported at `apply.ts:241`; this file already imports from `./apply.js`), return the existing `status: "error"` with a message naming size and cap; then `if (raw.charCodeAt(0) === 0xfeff) raw = raw.slice(1)` before `JSON.parse`. **Deliberately reusing `"error"` rather than adding an `"oversize"` status**: `ExistingConfigReadStatus` is mapped by the client (`components/integration-target-card-reason.ts`), so a new member is a second surface for a Low.
- **(6)** Smallest safe change, in `apply.ts`'s `atomicWrite`: before writing, sweep `dirname(dest)` for siblings matching an **anchored** `^\.tandem-setup-[0-9a-f-]{36}\.tmp$` older than 1 hour, unlink-tolerantly (Windows can refuse a file another process holds). **I rejected extending `file-io/reaper.ts`**: its docblock and CLAUDE.md both make "annotations + sessions dirs only, never user document dirs" the safety boundary, and these temps live in `$HOME` and `~/.claude` — worse than what that boundary refuses. Sweeping at write time keeps deletion inside a directory Tandem is already committing a write to, with the same 1-hour age gate and an equally tight regex. `uninstall-scrub.ts:603` already allowlists this exact shape, so the name is unchanged.
- **(7)** Move `const forwardExternally = shouldForwardExternally(event)` above the tracking line and add it as a conjunct: `if (forwardExternally && externalSubscribers.size > 0 && trackPayloadId(event))`. Restores the stated invariant "tracked ⇒ handed to ≥1 external consumer". `chat:message` always forwards, so it is unaffected; the privacy-held set was already dropped upstream.
- **(8)** In `tryReclaimStaleLock`, before `isPidAlive`: if `lock.startedAtMs` is present and predates this boot by a margin (`Date.now() - os.uptime() * 1000 - 5 * 60_000`), treat the lock as stale. `store.ts` gains a `node:os` import. The margin is the whole safety argument — a backwards wall-clock jump is the one way this could steal a live holder's lock, and five minutes is far wider than NTP step corrections. **`doctor.ts:2733`'s `isPidLive` is deliberately OUT of scope**: it reports, it does not gate, and the issue anchors on the store.
- **(9)** `WriteOutcome` (`setup.ts:277`) gains `pathRejections: PathRejectedError["reason"][]`, populated in the same `catch` that fills `refusals`; the all-failed branch gets one more arm naming the real reason via the already-exported `pathRejectionReason` (`apply.ts:347`), with a remedy that says to replace the symlink rather than to check permissions.
- **(10)** `runSetup`'s apply path reads the token with `readTokenFromFile` from `src/shared/auth/token-file.js` (what `rotate-token.ts` already uses) and threads it into `buildMcpEntries`. **The file reader, not `resolveAuthTokenCandidate`** — in env-token mode the token is injected at launch and must never be baked into a config, which is exactly what `rotate-token.ts:27-38` refuses. Absent file (first run) keeps today's omit-the-header behaviour.
- **(11)** One help line for `start`, worded from `docs/cli.md:127` ("Explicit alias for bare `tandem`").
- **(12)** Add `"starting"` to `LauncherUnavailableReason` (`contract.ts:63`) and to `isTransientlyUnavailable` (`:85`); `resolveInitialLauncherReason` returns `"stdio-mode"` only when `env.TANDEM_TRANSPORT` is stdio, else `"starting"`. Additive and safe: **no exhaustive switch over that type exists anywhere in `src/client`** (measured — neither `spawn-failed` nor `disabled-by-env` appears there), the reason is loopback-only so nothing changes for a LAN viewer, and `isTransientlyUnavailable`'s own docblock names itself the seam "that makes the enum extensible". Reading `TANDEM_TRANSPORT` inside the resolver preserves its single-authority property.
