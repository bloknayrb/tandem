## Problem

1. **Production stderr filter drops format placeholders** (`index.ts:79-99`, not `:76-94`). `const msg = args.map(String).join(" ")` stringifies each arg and joins, so `console.error("failed for %s (%s):", id, p, err)` prints `failed for %s (%s): id p Error: boom` — placeholders literal, **and the Error's stack gone** (`String(err)` is `"Error: boom"`; `util.format(err)` is the full stack). Objects become `[object Object]`. **Production-only**: the `else` branch aliases to `console.error`, which formats normally. Measured, not quoted: **52** single-line placeholder sites in `src/server/` (`grep -rnE 'console\.(log|warn|info|error)\([^)]*%[sdifjoOc]' src/server/ --include=*.ts | wc -l`), not the issue's 48. The single-line regex is a lower bound — it cannot see calls wrapped across lines. **No count is claimed for multi-arg sites**: the round-1 draft carried a "168" that no command reproduces (a same-spirit grep returns 141 and the total `console.*(` count is 466), so the PR body says "every multi-arg call site" without a number.
2. **Sentry ships the hostname and absolute frame paths** (`sentry.ts:94` `sendDefaultPii: false`, `:99` `beforeSend`). The hook scrubs `event.message` and `exception.values[].value` and nothing else. **Measured with a real captured event under our exact options** (`defaultIntegrations: false` included): `server_name: "DESKTOP-QB8F1UO"` and frames carrying an absolute `filename` with `in_app: true`. **Anchor correction — there is no `abs_path` key at all** in `@sentry/node` 10.73 (frame keys are `filename,module,function,lineno,colno,in_app,debug_id`), so a fix that scrubs `abs_path` is a silent no-op. `contexts` holds only `trace` + `runtime`; `breadcrumbs` is empty. `docs/security.md:172` currently *documents* this leak as a known bound (written by #1901 out of #1821) — **and its sentence is explicitly about all three `beforeSend`/`before_send` hooks**, of which this PR fixes one. The other two are measured unchanged and filed as #2023: `src/client/sentry.ts:81-92` (WebView) rewrites `event.message`, each `exception.value`, `request.url` and drops `request.data`, touching no frame and no `server_name`; `src-tauri/src/sentry_reporting.rs:143-157` (`scrub_event`) takes `event.message` and each `exception.value` and nothing else.
3. **stdio never exits on stdin EOF** (`index.ts:188-192`, not `:735-752`). The handler's entire body is a `console.error`. Nothing else closes on EOF: `StdioServerTransport` registers only `data` and `error` on stdin (SDK `server/stdio.js:43-44`), never `end`/`close`. The server survives its client forever. **The handler is registered at MODULE scope, so it is armed from import time, while `restoreCtrlSession()`/`restoreOpenDocuments()` are awaited inside `main()` at `:553-560`** — which is what makes the naive fix unsafe (see Fix 3).
4. **The SIGTERM/6 s item is REFUTED as written, and two comments are false.** There is no comment at `index.ts:229-233`; the constant is `SIGTERM_GRACE_MS = 6_000` at `supervisor.ts:1935`. It is **not dead code**: on Windows `c.kill("SIGTERM")` is `TerminateProcess`, the reaper dies at once, `exit` fires, and the race resolves immediately — only the SIGKILL escalation is unreachable there. What *is* false is the rationale: `index.ts:265-270` says routing through SIGTERM "gives Claude a chance to flush", and `reaper/src/windows.rs` is a Job Object + `WaitForSingleObject` with **no signal handler at all** — the SIGTERM→grace→SIGKILL relay is `#[cfg(unix)]` (`reaper/src/common.rs:11`), so `TerminateProcess` closes the job handle and `KILL_ON_JOB_CLOSE` kills Claude with no flush window. `cli/start.ts:58`'s "(correct cross-platform behavior)" overstates the same thing.
5. **`existing-config.ts:221` has no BOM strip and no size cap.** A BOM'd `~/.claude.json` throws in `JSON.parse` → `status: "malformed"` → the wizard pre-selects skip and calls the file broken, while `applyConfig` (`apply.ts:1109`) and `readConfigForMutation` (`:1276`) both strip U+FEFF and rewrite the same file happily. Two surfaces disagree about one file — the #1801/#1802 shape. The read is request-driven (`GET /api/integrations/existing`, wired at `mcp/server.ts:907`) and parses synchronously, which is what the cap is for.

Every error path calls `unlinkOrLeak` (`:1019`), so orphans arise only from a SIGKILL between `writeFile` and `rename`, or a failing `unlink`. Destinations are `$HOME` (beside `~/.claude.json`), the Claude Desktop config dir, and `~/.claude/skills/tandem/`.

## Fix

Ten separable commits. **Critical Rule 3 governs 1 and 3: every `console.*` in `src/server/` goes to stderr by design — do not route anything to stdout.** `src/server/index.ts` must never be imported by a test (importing it runs `main()` → `freePort()` → kills whatever holds :3478/:3479); `launcher/initial-reason.ts` exists for exactly that reason and is the extraction precedent.

- **(1)** New `src/server/log-filter.ts`, modelled on `initial-reason.ts` (pure module, no import side effects, its own docblock saying why it is not in `index.ts`): export `SUPPRESSED_PATTERNS` and `formatLogLine(args: unknown[]): string | null` (`null` = suppressed). **The two inputs stay separate, and that is the contract:** test `SUPPRESSED_PATTERNS` against `args.map(String).join(" ")` — today's exact shape — and return `format(...args)` from `node:util` only when nothing matched. Formatting *before* testing would silently widen production suppression: `/Invalid access/i` is the one unanchored pattern, `util.format(err)` emits the full stack where `String(err)` emits `name: message`, so any unrelated fatal whose stack frames happen to contain that text would be dropped with no trace, in the sidecar build where diagnosis is hardest. Split this way, suppression is byte-identical to today and only the emitted text improves. `index.ts:86-89`'s `filteredError` becomes a three-line caller.
- **(2)** Extract the inline hook (`sentry.ts:99`) to an **exported named function** `scrubEvent(event)` that `Sentry.init` passes by reference (`beforeSend: scrubEvent`) — the test must drive the real hook, and there is no exported options object to reconstruct. `scrubEvent` keeps today's message/`exception.value` scrubbing and adds: `delete event.server_name`, and map each `exception.values[].stacktrace.frames[]` `filename` through the existing `scrub()`. **Scrub `filename`, not `abs_path`** — the latter does not exist in this SDK, per the probe. Then rewrite `docs/security.md:172` **as a three-way split, never as a blanket claim**: the sidecar hook (`src/server/sentry.ts`) now deletes `server_name` and `~`-redacts each frame `filename`, while the WebView (`src/client/sentry.ts`) and the Rust shell (`src-tauri/src/sentry_reporting.rs`) still ship both untouched (#2023); drop the `abs_path` half of the parenthetical for the sidecar only. Add #2023 to `docs/security.md`'s `## Open findings` register, which is that file's own stated tracked home. No claims test pins the Telemetry paragraph (`tests/docs/security-findings-claims.test.ts` pins the open-findings count and enumeration only; `sentry`/`server_name` appear in no file under `tests/`) — measured, which is exactly why a half-true rewrite would ship silently.
- **(3)** `index.ts`: add a module-level `let startupComplete = false`, set `true` immediately after `await restoreOpenDocuments(...)` resolves (`:559-561`, outside the transport branch, so it runs in both modes).
