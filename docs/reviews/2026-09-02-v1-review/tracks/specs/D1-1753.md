Branch `fix/markdown-fidelity-1753`. Closes #1753 (both halves, under [decision A](../../decisions.md)). Ledger: `docs/reviews/2026-09-02-v1-review/areas/server-data.md:20`.

For the per-case figures, write a scratch `.ts` importing `loadMarkdown` / `saveMarkdown` / `mdParser` / `serializeMdast` from `src/server/file-io/markdown.ts` and `npx tsx` it. **Build every `\` with `String.fromCharCode(92)` or via the Write tool — a bash heredoc eats the backslashes and turns every case below into its un-escaped twin, which measures SAME and reads like a pass.** All figures re-measured 2026-09-09.

## Problem

**Half A (wikilinks) — decision A: out of scope, warn instead.** Measured: `"See [[Other Note]] and ![[image.png]]\n"` → `"See \\[[Other Note]] and !\\[[image.png]]\n"`. Bryan decided 2026-09-06 that Obsidian vaults are out of scope for v1. **The README does not currently say so** — `grep -n -i "obsidian\|wikilink" README.md` returns only the origin story at `README.md:18` — so the sentence has to be written.

**Half B (escapes) — the issue's own example is refuted; the real defect is narrower and worse.** `"This is \\*not emphasis\\* here.\n"` round-trips byte-identical; so do `\#`, `\_`, `` \` ``, `\!`, `\<`, `\+`. The escapes that *are* dropped are all positions where `remark-stringify`'s `safe()` adds no escape, so the un-escaped form re-parses to the identical text node — invisible, and the deliberate other side of #1448's diff-noise work.

The one shape that genuinely corrupts:

```
A \[label] here.

[label]: https://example.com
```
round-trips to `A [label] here.` — a live shortcut reference link. Rule 1 in `markdown.ts`'s `text` handler guards exactly this with `activeRefDefs.has(normalizeLabel(label))`, and the guard is **structurally dead**: `serializeMdast` collects labels with `visit(tree, "definition", …)`, but a reference definition never reaches the tree as a `definition` node — it is a `markdownRaw` paragraph (#981 / ADR-042) re-emitted as `{ type: "html", value: "[label]: https://example.com" }` (verified by dumping `yDocToMdast(doc).children`: `["paragraph","html"]`). So `activeRefDefs` is always empty for a file loaded through the Y.Doc. The corrupt output is a stable fixed point, so idempotency-only suites are green on it.

## Fix

**1. `src/server/file-io/markdown.ts`, `serializeMdast` (the `visit(tree, "definition", …)` block).** Also collect labels from raw-carrier `html` nodes, which is where reference and footnote definitions actually live:

```ts
visit(tree, "html", (node) => {
  for (const line of node.value.split("\n")) {
    const m = /^ {0,3}\[([^\\\[\]\n]{1,999})\]:/.exec(line);
    if (m) activeRefDefs.add(normalizeLabel(m[1]));
  }
});
```
Bounded quantifier and a class excluding `\`, `[`, `]` — the linearity posture rule 1's own class documents. Footnote labels (`[^1]`) match and are added; that is strictly conservative (an extra member can only *keep* an escape, never strip one). The `definition` visit stays — a tree built by `appendMdast` from pasted markdown can still carry real `definition` nodes.

**2. Warn once on `[[`, returned from `markdownAdapter.apply`.** When the decoded content matches `/\[\[[^\]\n]+\]\]/`, return `{ kind: "other", error: undefined, message: "<fileName> contains [[wikilinks]]. Tandem does not preserve them — they are saved as literal text. Obsidian-style vaults are not supported in this release." }`. `"other"` is the documented extension point (`types.ts`), and `populate.ts:155-163`'s `"other"` arm already turns it into one `pushNotification` deduped on `load-other:${ctx.dedupSource}` — one toast per file per open, which is the "once" decision A asks for. **No new `LoadIssue` variant.** `apply` is the right side because `ApplyContext` carries `fileName` (`types.ts:136-138`), `apply` returns `LoadIssue[]` (`types.ts:161`), and `populate.ts:222` passes `{ fileName: ctx.displayName }` — a message composed in `parse` could not name the file. Also update `types.ts:84`'s "Always empty for md today" comment, which this falsifies.

**The `a[[i]]` false positive is accepted, not engineered around.** The predicate also matches R's `a[[i]]` and a nested Python list literal, in prose or in a fence. The notification is warn-only, deduped once per file per open, changes no bytes and blocks nothing; excluding fenced regions would mean a second scanner agreeing with the parser about fence boundaries. Record the acceptance here; no test pins it.

**3. `README.md`:** one sentence in the file-format section — wikilinks and embeds are saved as literal text; Obsidian/Logseq/Foam vaults are not a supported input for this release.

Rules that bite: the `text` handler is `remark-stringify`-frozen at module scope and `activeRefDefs` is read at call time — set it in `serializeMdast` before `stringify`, never inside the handler. No Y.Doc write, no origin helper, no Y.Map key, no MCP error code, so `docs/mcp-tools.md`'s Errors lines are unchanged.

## Tests

`tests/server/file-io/markdown-escaping.test.ts` (existing home for this handler):

1. **The killer.** `A \[label] here.\n\n[label]: https://example.com\n` round-trips byte-identical on **pass 1** (the corrupt form is already a fixed point, so idempotency proves nothing). It fails against a fix that scans only `definition`-typed nodes. It does **not** discriminate a fix that deleted rule 1 — measured: with rule 1 gone the escape simply stays and this input is byte-identical. Test 3 is the sole guard against that.
2. **Collapsed form.** `Escaped \[label][] now.\n\n[label]: https://example.com\n` → measured `Escaped \[label]\[] now.\n\n…` — DIFF, an extra `\[]`, because rule 1's label class is non-empty and cannot un-escape the empty `[]`. Assert what the fix guarantees, in the idiom `markdown-escaping.test.ts:103-121` already uses: `expect(out).toMatch(/\\\[label]/)` (no live collapsed reference link) plus `parseEqual(out, input)`. Record in the comment that the residual `\[]` is measured and renders identically. Chasing byte-identity here pushes toward re-adding a `\[]` un-escape rule — the #1448 corruption class rule 3 exists to warn about.
3. **Rule 1 still fires.** `A \[label] here.\n` with **no** definition anywhere → `A [label] here.\n`, unchanged from today. Without this a "just delete rule 1" fix passes 1 and 2 and re-opens the #1448 diff noise.
4. **Footnote definition does not over-block.** `See \[note] and [^1] here.\n\n[^1]: body\n` — `[note]` is still un-escaped.

Wikilink half, in the existing `tests/server/file-io/` adapter suite: loading `"See [[Note]]\n"` returns exactly one issue with `kind: "other"` whose `message` contains the `ctx.fileName` passed in; `"No brackets here\n"` returns none; the round-trip of `[[Note]]` still produces `\[[Note]]` (the escape half is deliberately not fixed, and pinning the old output keeps a "while I'm here" wikilink node from landing unreviewed).
