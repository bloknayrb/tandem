## Problem

**Half A (wikilinks) — decision A: out of scope, warn instead.** Measured: `"See [[Other Note]] and ![[image.png]]\n"` → `"See \\[[Other Note]] and !\\[[image.png]]\n"`. Bryan decided 2026-09-06 that Obsidian vaults are out of scope for v1: README says so, Tandem warns once on open. **The README does NOT currently say so** — `grep -n -i "obsidian\|wikilink" README.md` returns one hit, the origin story at `README.md:18`, and nothing about wikilinks not being preserved. The wave note's "README already says so" is wrong; the sentence has to be written.

**Half B (escapes) — the issue's own example is refuted, and the real defect is different and worse.** `"This is \\*not emphasis\\* here.\n"` round-trips **byte-identical**; so do `\#`, `\_`, `\` ` `, `\!`, `\<`, `\+`. A sweep of every ASCII punctuation char in prose and line-leading position found the escapes that *are* dropped (`\!`, `\"`, `\#`, `\$`, `\%`, `\&`, `\'`, `\(`, `\)`, `\+`, `\,`, `\-`, `\.`, `\/`, `\:`, `\;`, `\<`, `\=`, `\>`, `\?`, `\@`, `\]`, `\^`, `\{`, `\|`, `\}`, `\~`, `\\`) are all positions where `remark-stringify`'s `safe()` adds no escape, so the un-escaped form re-parses to the identical text node — invisible, and the deliberate other side of the #1448 diff-noise work (rules 1/4/5 in `markdown.ts`'s `text` handler exist to cancel escapes `safe()` *added*; the parse discards which side wrote them).

The one shape that genuinely corrupts:

```
A \[label] here.

[label]: https://example.com
```
round-trips to `A [label] here.` — an un-escaped **shortcut reference link**. Rule 1 guards exactly this with `activeRefDefs.has(normalizeLabel(label))`, and the guard is **structurally dead**: `serializeMdast` collects labels with `visit(tree, "definition", …)`, but a reference definition never reaches the tree as a `definition` node. It is stored as a `markdownRaw` paragraph (#981 / ADR-042) and re-emitted as `{ type: "html", value: "[label]: https://example.com" }` — verified by dumping `yDocToMdast(doc).children`, which is `["paragraph","html"]`. So `activeRefDefs` is **always empty for a file loaded through the Y.Doc**, and every `\[label]` is un-escaped regardless of what the document defines. Worse with a collapsed form: `Escaped \[label][] now.` → `Escaped [label]\[] now.` — a live collapsed reference link plus a stray `\[]`. Both are stable fixed points, so every idempotency-only suite is green on them (#1448's own lesson).

## Fix

**1. `src/server/file-io/markdown.ts`, `serializeMdast` (the `visit(tree, "definition", …)` block).** Also collect labels from raw-carrier `html` nodes, which is where every reference and footnote definition actually lives:

```ts
visit(tree, "html", (node) => {
  for (const line of node.value.split("\n")) {
    const m = /^ {0,3}\[([^\\\[\]\n]{1,999})\]:/.exec(line);
    if (m) activeRefDefs.add(normalizeLabel(m[1]));
  }
});
```
Bounded quantifier and a class excluding `\`, `[`, `]` — same linearity posture rule 1's own class documents. Footnote labels (`[^1]`) match too and are added; that is strictly conservative (an extra member can only *keep* an escape, never strip one), and rule 1's own label class already admits `^1`. The `definition` visit stays — a tree built by `appendMdast` from pasted markdown can still carry real `definition` nodes.

**2. Warn once on `[[`, emitted from `apply`, not `parse`.** When the decoded content matches `/\[\[[^\]\n]+\]\]/`, emit `{ kind: "other", error: undefined, message: "<fileName> contains [[wikilinks]]. Tandem does not preserve them — they are saved as literal text. Obsidian-style vaults are not supported in this release." }`. That is the documented extension point (`types.ts`: "Reserved for future partial-load categories… a sum-type extension so the existing handler doesn't need updates"), and `populate.ts:155-163`'s `"other"` arm already turns it into one `pushNotification` deduped on `load-other:${ctx.dedupSource}` — one toast per file per open, which is the "once" decision A asks for. **No new `LoadIssue` variant**: a new kind would force a new arm in `notifyIssue`'s exhaustive switch and buy nothing.

**The issue is returned from `markdownAdapter.apply`, using `ctx?.fileName`.** An earlier draft composed it in `parse` and settled for a generic subject ("This file contains…") on the grounds that `parse` has no filename. It does not need to: `ApplyContext` carries `fileName` (`src/server/file-io/types.ts:136-138`), `apply` **returns** `LoadIssue[]` (`types.ts:161`), `populate.ts:222` calls `adapter.apply(doc, prepared, { fileName: ctx.displayName })`, and `applyPreparedContent` notifies parse-issues and apply-issues identically — so surfacing and dedup are unchanged and every other arm of `notifyIssue` (`populate.ts:113-160`) names the document. A generic subject would make this the one load notification that cannot say which file it is about. Detecting in `parse` and *carrying* a flag to `apply` is also fine; what must not ship is the nameless message. Also update `types.ts:84` — the `Prepared` md arm's "Always empty for md today — placeholder for future warnings" comment, which this change falsifies. `writeImportLossReport` early-returns on non-docx, so this issue reaches no fidelity banner.

**The `a[[i]]` false positive is decided here, not in the test.** `/\[\[[^\]\n]+\]\]/` over the whole decoded file also matches R's `a[[i]]`, a nested Python list literal `x[[0]]`, and either of those inside a fenced code block. **Accept it**: the notification is warn-only, deduped once per file per open, changes no bytes and blocks nothing, while excluding fenced regions means a second scanner that has to agree with the parser about fence boundaries. Pin the accepted behaviour with an assertion (`parse`/`apply` on `"An array index a[[i]] here.\n"` DOES report the issue), so the predicate cannot be narrowed later without a red test — and so a future reader hitting the toast on a technical doc finds the decision instead of re-deriving it.

**3. `README.md`:** one sentence in the file-format section — wikilinks and embeds are saved as literal text; Obsidian/Logseq/Foam vaults are not a supported input for this release.

Rules that bite: the `text` handler is `remark-stringify`-frozen at module scope and `activeRefDefs` is read at call time (`markdown.ts`'s own comment) — set it in `serializeMdast` before `stringify`, never inside the handler. No Y.Doc write, no origin helper, no Y.Map key, no MCP error code, so `docs/mcp-tools.md`'s Errors lines are unchanged.

## Tests

`tests/server/file-io/markdown-escaping.test.ts` (existing home for this handler):

1. **The killer.** `A \[label] here.\n\n[label]: https://example.com\n` round-trips byte-identical. It discriminates one thing: a fix that scans only `definition`-typed nodes leaves `activeRefDefs` empty on the Y.Doc path and un-escapes the label, so it fails. **It does not discriminate a fix that dropped rule 1 entirely** — measured: with rule 1 gone every `\[label]` simply stays escaped, so this input round-trips byte-identical and the test PASSES. **Test 3 is the sole guard against deleting rule 1**; do not read test 1 as covering it. Assert on **pass 1**, not idempotency: the corrupt form is already a fixed point.
2. **Collapsed form — NOT byte-identical; use the suite's existing idiom.** Measured against the proposed fix (`serializeMdast(mdParser.parse(x))`, which populates `activeRefDefs` from the source's real `definition` node — the same state the `html` scan creates for the Y.Doc path): `Escaped \[label][] now.\n\n[label]: https://example.com\n` → `Escaped \[label]\[] now.\n\n…` — **DIFF**, an extra `\[]`. Rule 1's label class `[^\\\]\n`]+` is non-empty, so `safe()`'s escape on the *empty* `[]` can never be un-escaped, and no fix in this spec's scope removes it. Chasing byte-identity here would push the implementer toward re-adding a `\[]` un-escape rule, which is the #1448 corruption class this handler's rule 3 exists to warn about. So assert what the fix actually guarantees, in the idiom `markdown-escaping.test.ts:103-121` already uses for this family: `expect(out).toMatch(/\\\[label]/)` — the escape survives, so no live collapsed reference link — plus `parseEqual(out, input)`. Record in the test comment that the residual `\[]` is measured and renders identically. (Test 1's shortcut shape *does* measure SAME under the same simulation; that is why only it carries a byte-identity assertion.)
3. **Rule 1 still fires.** `A \[label] here.\n` with **no** definition anywhere → `A [label] here.\n` unchanged from today. Without this a "just delete rule 1" fix passes tests 1 and 2 and re-opens the #1448 diff noise it was written for.
4. **Footnote definition does not over-block.** `See \[note] and [^1] here.\n\n[^1]: body\n` — `[note]` is still un-escaped (the `[^1]` label is in the set but `note` is not).
