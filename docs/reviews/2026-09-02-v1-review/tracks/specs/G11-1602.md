# G11 — #1602 Reviewer agents report severity but never a disposition

Branch `fix/process-docs-four-issues-from-an-outside-debugging-study-1602`. Closes #1602. Ledger: `docs/plans/2026-09-06-open-issues-sweep.md:111` ("G11 process docs ... CLAUDE.md edits — last, to limit conflicts"). No probe — this is a docs-only process group, not an MCP/`/api` surface change.

## Problem

Four adversarial-reviewer agent files each carry a `## Output Format` section: `.claude/agents/security-reviewer.md:32`, `crdt-reviewer.md:48`, `annotation-model-reviewer.md:60`, `svelte-migration-reviewer.md:124`. Measured on the current worktree (post-G4/D3 merge, master `7aff6259`): every anchor is exact, every file opens its `## Output Format` block with exactly one `**Severity**: Critical / High / Medium / Low / Info` line, and every file's `## Output Format` is its last section — each closes with its own "Start by reading…" instruction after the finding-shape bullets. The files are **not** byte-identical: `crdt-reviewer.md` and `annotation-model-reviewer.md` insert an `**Invariant**` bullet, `svelte-migration-reviewer.md` a `**Pattern**` bullet, `security-reviewer.md` phrases `**Proof**` as "how to trigger it (or why the existing mitigation works)" instead of the other three's "concrete scenario." None of the four say what a Critical finding *obliges*. `CLAUDE.md`'s Development Workflow ("spawn adversarial agents to review the plan from multiple angles before writing any code") goes straight to "implement" with no disposition rule, so the ship/don't-ship call is unconstrained orchestrating-session judgment.

Measured: `grep -rl "\.claude/agents" tests/` returns nothing — zero files in `tests/` read `.claude/agents/`. Whatever text this fix adds is enforced by nothing mechanical; it drifts silently exactly like the four review agents already drift from each other. That is the same defect class the G4 issues (#1613 wiring-test-tree config drift) fixed for the test tree, and it is worth saying so in the PR body rather than pretending an equivalent guarantee exists here.

## Fix

Insert a `## Disposition` section into each of the four agent files, **immediately before their `## Output Format` heading** (not appended at end of file — the file's tail is the "Start by reading…" line, a bad insertion point). Each section states the domain's blocking set and explicitly retires "unlikely in practice" / "pre-existing class of problem" as grounds for shipping past it, per the issue's acceptance criteria and its citation of the study's failure mode (a reviewer that *detected* a data-corruption bug and then approved the merge anyway on a likelihood judgment).

Exact insertions (each preceded and followed by the existing blank line already adjacent to `## Output Format`, so the file's surrounding spacing is unchanged):

**`.claude/agents/security-reviewer.md`**, before line 32:
```
## Disposition

A **Critical** or **High** severity finding blocks the change. No weighing of exploit
likelihood, no "pre-existing class of problem," no filing a follow-up and shipping anyway — fix
it, or withdraw the finding on the merits (a demonstration it does not hold), not on
plausibility.

```

**`.claude/agents/crdt-reviewer.md`**, before line 48:
```
## Disposition

A finding blocks the change when it is a range/coordinate invariant violation that can desync an
annotation from the text it anchors to (a wrong `assoc`, a skipped staleness check, an offset
that ignores a heading prefix or a surrogate pair), or a wrong origin-tag helper from
`src/shared/origins.ts` (Critical Rule 2 — "picking the wrong one is a silent bug"). No weighing
of how rare the triggering input shape is, no "pre-existing class of problem" — fix it, or
withdraw the finding on the merits.

```

**`.claude/agents/annotation-model-reviewer.md`**, before line 60:
```
## Disposition

A finding blocks the change when it is an ADR-027 privacy leak (a note, or a private comment,
reaching Claude via an MCP tool response or a channel event), a wrong origin-tag helper from
`src/shared/origins.ts`, or loss/corruption of an annotation record. No weighing of how rarely
the path is hit, no "pre-existing class of problem" — fix it, or withdraw the finding on the
merits.

```

**`.claude/agents/svelte-migration-reviewer.md`**, before line 124:
```
## Disposition

A finding blocks the change when it is a `state_unsafe_mutation` crash reachable in production,
or a reactive bug that silently drops a user's edit (stale UI presented as current, a change the
user believes saved but never re-rendered or persisted). No weighing of how rarely the
interaction pattern occurs, no "pre-existing class of problem" — fix it, or withdraw the finding
on the merits.

```

Second half — `CLAUDE.md`'s Development Workflow, so the orchestrating session is bound too, not just the subagent. Insert as a new paragraph immediately after the existing workflow paragraph's last sentence ("...repeat the same loop on the fixes.") and before the `**\`/diverge\`**` paragraph:

```
**A Critical or High finding from an adversarial reviewer blocks the change (#1602)** — for the
orchestrating session too, not just the subagent that raised it. No weighing of exploit
likelihood, no "pre-existing class of problem," no filing a follow-up and shipping anyway: fix
it, or withdraw the finding on the merits, not on plausibility.
```

**Deliberate non-mechanism, stated as a decision rather than an oversight:** no CI/test gate is added over this prose. `tests/` reads none of `.claude/agents/` today (measured above), and the repo's existing answer to "an advisory artifact needs a guarantee" — ADR-051, a wiring test inside `check` — does not fit here: ADR-051 pins that a *mechanism* still runs (a CI step exists, a script is still invoked). What would need pinning here is that a *model* obeyed an instruction on a *specific review*, which no static test can observe from the repo alone. A text-presence test (`## Disposition` appears in all four files) is available and would be cheap, but it only proves the heading exists, not that a reviewer honors it — indistinguishable from theater, and the issue's own acceptance criteria don't ask for one ("each of the four agent files contains a disposition rule," "`CLAUDE.md` names the obligation" — both satisfied by the text itself). Per the MINIMALITY RULE, no gate is added beyond what the issue asks for.

## Tests

None can discriminate a compliant future review from a non-compliant one — this is prompt text, not runtime code, and the whole point of the section above is that nothing in `tests/` reads it. The only checks that apply:
1. Manual diff review at implementation time: all four files contain `## Disposition` immediately before `## Output Format` (not appended at file end), each with the domain-specific blocking set above.
2. `CLAUDE.md`'s Development Workflow contains the new paragraph, in the stated position.
3. Full `npm test` stays green — nothing currently asserts on these files' contents, so this is a null result, not evidence the fix works; state that plainly in the PR body rather than implying a test proved it.

## Done when

All four `.claude/agents/*.md` files carry their `## Disposition` section in the stated position; `CLAUDE.md`'s Development Workflow carries the new paragraph; `npx biome format --write` run on the changed files; `npm run typecheck` and `npm test` green (unaffected, confirming no regression).

## Not in scope

A CI/test gate over agent-file prose (explicitly declined above, with reasoning). Adding a per-finding `**Disposition**` bullet to the `## Output Format` finding shape itself — the issue asks for a policy section stating what severity *obliges*, not a new field each finding must fill in; conflating the two would also touch the very finding-shape inconsistencies (`**Invariant**` vs `**Pattern**` vs neither) the issue explicitly flags as a separate, pre-existing fact and does not ask this issue to reconcile.
