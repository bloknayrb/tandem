# G11 — #1602 Reviewer agents report severity but never a disposition

Branch `fix/process-docs-four-issues-from-an-outside-debugging-study-1602`. Closes #1602. Ledger: `docs/plans/2026-09-06-open-issues-sweep.md:111`. No probe — docs-only.

## Problem

Four adversarial-reviewer agent files each carry a `## Output Format` section: `.claude/agents/security-reviewer.md:32`, `crdt-reviewer.md:48`, `annotation-model-reviewer.md:60`, `svelte-migration-reviewer.md:124`. Re-measured on the current worktree: every anchor is exact, every file opens `## Output Format` with one `**Severity**: Critical / High / Medium / Low / Info` line, and every file's `## Output Format` is its *last* section — each closes with its own "Start by reading…" instruction, so the insertion point is before that heading, not the end of the file. The files are not byte-identical (`**Invariant**` in crdt/annotation-model, `**Pattern**` in svelte, a differently-phrased `Proof` line in security) — irrelevant to this fix, which touches none of that.

None of the four say what a Critical finding *obliges*, and `CLAUDE.md`'s Development Workflow goes straight from "spawn adversarial agents" to "implement" with no disposition rule. Measured: `grep -rl "\.claude/agents" tests/` returns nothing — zero files in `tests/` read `.claude/agents/`.

## Fix

Insert a `## Disposition` section into each of the four agent files, immediately before their `## Output Format` heading (not appended at end of file).

**`.claude/agents/security-reviewer.md`**, before line 32:
```
## Disposition

A Critical or High severity finding blocks the change. No weighing of exploit likelihood, no
"pre-existing class of problem" — fix it, withdraw it on the merits, or point to an existing,
dated entry in `docs/security.md`'s Accepted (bounded) register. A *new* acceptance is Bryan's
call, never this review's.

```

**`.claude/agents/crdt-reviewer.md`**, before line 48:
```
## Disposition

A finding blocks the change when it is a range/coordinate invariant violation that can desync an
annotation from the text it anchors to, or a wrong origin-tag helper from `src/shared/origins.ts`
(Critical Rule 2). No weighing of how rare the triggering input shape is, no "pre-existing class
of problem" — fix it, or withdraw the finding on the merits.

```

**`.claude/agents/annotation-model-reviewer.md`**, before line 60:
```
## Disposition

A finding blocks the change when it is an ADR-027 privacy leak (a note, or a private comment,
reaching Claude), a wrong origin-tag helper from `src/shared/origins.ts`, or loss/corruption of
an annotation record. No weighing of how rarely the path is hit, no "pre-existing class of
problem" — fix it, or withdraw the finding on the merits.

```

**`.claude/agents/svelte-migration-reviewer.md`**, before line 124:
```
## Disposition

A finding blocks the change when it is a `state_unsafe_mutation` crash reachable in production,
or a reactive bug that silently drops a user's edit. No weighing of how rarely the interaction
pattern occurs, no "pre-existing class of problem" — fix it, or withdraw the finding on the
merits.

```

Second half — `CLAUDE.md`'s Development Workflow, so the orchestrating session is bound too. Insert as a new paragraph after "...repeat the same loop on the fixes." and before the `**\`/diverge\`**` paragraph:

```
**A finding inside an adversarial reviewer's own stated blocking set stops the change (#1602)**
— for the orchestrating session too, not just the subagent that raised it. No shipping past it
on a likelihood judgment or by calling it a pre-existing class of problem: fix it, withdraw it
on the merits, or — the one standing exception — point to it as an already-accepted, bounded,
dated entry in [docs/security.md](docs/security.md#open-findings)'s register; a *new* acceptance
made mid-review does not count. Full study:
[docs/spikes/ai-debugging-blind-spots-audit.md](docs/spikes/ai-debugging-blind-spots-audit.md).
```

This deliberately does **not** restate a severity threshold in `CLAUDE.md` — it defers entirely to "the reviewer's own stated blocking set," which for security *is* Critical/High (stated once, in `security-reviewer.md`) and for the other three is the consequence list stated in their own Disposition section. One clause, one place, no second copy to drift out of sync with the first.

## Tests

No CI gate is added. `tests/` reads none of `.claude/agents/` today (measured above), and these are prompt files read wholesale by a model on every invocation of that agent — a presence-only test could prove the text still exists but nothing about whether a given review honored it, so it would not close the actual gap named here. That gap (a `## Disposition` section silently deleted) is stated, not fixed; the issue's own acceptance criteria ask only that the text exist, which manual review at implementation time confirms.

1. All four files contain `## Disposition` immediately before `## Output Format`.
2. `CLAUDE.md`'s Development Workflow contains the new paragraph, in the stated position.
3. No automated check covers `CLAUDE.md`'s links — `invariant-citations.test.ts:47`'s `SCANNED_ROOTS` is `["src", "src-tauri/src", "tests", "scripts", "infra"]`, so `CLAUDE.md` is outside its scan, and `dangling-citations.ts` matches only label-less `§N` citation shapes, never markdown links, so it would not resolve one either way. Both targets verified by hand instead: `git ls-files --error-unmatch docs/spikes/ai-debugging-blind-spots-audit.md` succeeds (tracked), and `docs/security.md:183` is `## Open findings`, giving the `#open-findings` anchor.
4. Full `npm test` stays green — a null result (nothing currently asserts on these files' contents), stated as such rather than implied as proof.

## Done when

All four `.claude/agents/*.md` files carry `## Disposition` in the stated position; `CLAUDE.md`'s Development Workflow carries the new paragraph; no formatter applies (`.md` is outside `biome.json`'s `files.includes` — confirmed: `npx biome format CLAUDE.md` exits 1) so hand-wrap to each file's existing column width; `npm run typecheck` and `npm test` green.

## Not in scope

A CI/test gate over agent-file prose (declined above). A per-finding `**Disposition**` bullet inside the `## Output Format` finding shape itself — the issue asks for a policy section, not a new field every finding must fill in.
