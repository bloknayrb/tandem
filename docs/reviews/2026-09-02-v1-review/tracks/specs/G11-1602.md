# G11 — #1602 Reviewer agents report severity but never a disposition

Branch `fix/process-docs-four-issues-from-an-outside-debugging-study-1602`. Closes #1602. Ledger: `docs/plans/2026-09-06-open-issues-sweep.md:111` ("G11 process docs ... CLAUDE.md edits — last, to limit conflicts"). No probe — this is a docs-only process group, not an MCP/`/api` surface change.

## Problem

Four adversarial-reviewer agent files each carry a `## Output Format` section: `.claude/agents/security-reviewer.md:32`, `crdt-reviewer.md:48`, `annotation-model-reviewer.md:60`, `svelte-migration-reviewer.md:124`. Measured on the current worktree (post-G4/D3 merge, master `7aff6259`): every anchor is exact, every file opens its `## Output Format` block with exactly one `**Severity**: Critical / High / Medium / Low / Info` line, and every file's `## Output Format` is its last section — each closes with its own "Start by reading…" instruction after the finding-shape bullets. The files are **not** byte-identical: `crdt-reviewer.md` and `annotation-model-reviewer.md` insert an `**Invariant**` bullet, `svelte-migration-reviewer.md` a `**Pattern**` bullet, `security-reviewer.md` phrases `**Proof**` as "how to trigger it (or why the existing mitigation works)" instead of the other three's "concrete scenario." None of the four say what a Critical finding *obliges*. `CLAUDE.md`'s Development Workflow ("spawn adversarial agents to review the plan from multiple angles before writing any code") goes straight to "implement" with no disposition rule, so the ship/don't-ship call is unconstrained orchestrating-session judgment.

Measured: `grep -rl "\.claude/agents" tests/` returns nothing — zero files in `tests/` read `.claude/agents/`. Whatever text this fix adds is enforced by nothing mechanical; it drifts silently exactly like the four review agents already drift from each other. That is the same defect class the G4 issues (#1613 wiring-test-tree config drift) fixed for the test tree, and it is worth saying so in the PR body rather than pretending an equivalent guarantee exists here.

## Fix

Insert a `## Disposition` section into each of the four agent files, **immediately before their `## Output Format` heading** (not appended at end of file — the file's tail is the "Start by reading…" line, a bad insertion point). Each section states the domain's blocking set and explicitly retires "unlikely in practice" / "pre-existing class of problem" as grounds for shipping past it, per the issue's acceptance criteria and its citation of the study's failure mode (a reviewer that *detected* a data-corruption bug and then approved the merge anyway on a likelihood judgment).

Exact insertions (each preceded and followed by the existing blank line already adjacent to `## Output Format`, so the file's surrounding spacing is unchanged):

**`.claude/agents/security-reviewer.md`**, before line 32:
```
## Disposition

A **Critical** or **High** severity finding blocks the change. No weighing of exploit
likelihood, no "pre-existing class of problem" — fix it, withdraw it on the merits (a
demonstration it does not hold), or accept it explicitly: a stated bound plus a dated tracked
issue in `docs/security.md`'s Accepted section. That acceptance is Bryan's call, not the
reviewing session's; what's banned is shipping past a finding on a silent likelihood judgment,
never a real acceptance Bryan has made.

```

**`.claude/agents/crdt-reviewer.md`**, before line 48:
```
## Disposition

A finding blocks the change when it is a range/coordinate invariant violation that can desync an
annotation from the text it anchors to (a wrong `assoc`, a skipped staleness check, an offset
that ignores a heading prefix or a surrogate pair), or a wrong origin-tag helper from
`src/shared/origins.ts` (Critical Rule 2 — "picking the wrong one is a silent bug"). No weighing
of how rare the triggering input shape is, no "pre-existing class of problem" — fix it, or
withdraw the finding on the merits.

```

**`.claude/agents/annotation-model-reviewer.md`**, before line 60:
```
## Disposition

A finding blocks the change when it is an ADR-027 privacy leak (a note, or a private comment,
reaching Claude via an MCP tool response or a channel event), a wrong origin-tag helper from
`src/shared/origins.ts`, or loss/corruption of an annotation record. No weighing of how rarely
the path is hit, no "pre-existing class of problem" — fix it, or withdraw the finding on the
merits.

```

**`.claude/agents/svelte-migration-reviewer.md`**, before line 124:
```
## Disposition

A finding blocks the change when it is a `state_unsafe_mutation` crash reachable in production,
or a reactive bug that silently drops a user's edit (stale UI presented as current, a change the
user believes saved but never re-rendered or persisted). No weighing of how rarely the
interaction pattern occurs, no "pre-existing class of problem" — fix it, or withdraw the finding
on the merits.

```

Second half — `CLAUDE.md`'s Development Workflow, so the orchestrating session is bound too, not just the subagent. Insert as a new paragraph immediately after the existing workflow paragraph's last sentence ("...repeat the same loop on the fixes.") and before the `**\`/diverge\`**` paragraph:

```
**A finding in an adversarial reviewer's stated blocking set — and any security finding rated
Critical or High — blocks the change (#1602)**, for the orchestrating session too, not just the
subagent that raised it. No weighing of exploit likelihood, no "pre-existing class of problem,"
no filing a follow-up and shipping anyway: fix it, withdraw it on the merits, or accept it
explicitly — a stated bound plus a dated tracked issue in `docs/security.md`'s Accepted section
(see Security below). That acceptance is Bryan's call, never the implementing session's. Full
study: [docs/spikes/ai-debugging-blind-spots-audit.md](docs/spikes/ai-debugging-blind-spots-audit.md).
```

This is phrased over **the reviewer's own stated blocking set**, not bare severity: three of the four Disposition sections below (crdt, annotation-model, svelte) key blocking on *category* — "a range/coordinate invariant violation," "an ADR-027 privacy leak," "a `state_unsafe_mutation` crash" — and never use a severity word at all, while only security-reviewer's is severity-keyed (`Critical`/`High`). An earlier draft of this paragraph said "A Critical or High finding... blocks," which is a narrower and contradicting rule: a crdt-reviewer finding rated High but outside its category list would block per that phrasing and not per the agent file, and a category finding rated Medium would block per the agent file and not per that phrasing. Phrasing the CLAUDE.md line over "stated blocking set, plus security's own Critical/High" makes CLAUDE.md the single owner of the union and leaves each agent file as the domain-specific set it already is — no reconciliation needed there.

It also names a third disposition arm — accept it explicitly, bounded and dated — because the absolute "fix it or withdraw it" framing this paragraph originally used contradicts a live, documented Tandem process: CLAUDE.md's own Security section records four findings that took exactly that third route (#1654, #1599, #1609, #1488 — "accepted rather than fixed," each "still a live code condition"), and the Development Workflow's own dated-gates rule institutionalizes filing a dated issue for exactly this shape. The issue's actual target — the study's failure mode of shipping past a *detected* bug on a silent, undocumented likelihood judgment — is unaffected: what's banned is a silent judgment call, not a recorded, dated, Bryan-approved bound.

**Deliberate non-mechanism, stated as a decision rather than an oversight:** no CI/test gate is added over this prose. `tests/` reads none of `.claude/agents/` today (measured above), and the repo's existing answer to "an advisory artifact needs a guarantee" — ADR-051, a wiring test inside `check` — does not fit here: ADR-051 pins that a *mechanism* still runs (a CI step exists, a script is still invoked). A text-presence test (`## Disposition` appears in all four files) is available and cheap, and it would catch one real thing: deletion of a Disposition section, which today is detected by nothing (measured above — zero files in `tests/` read `.claude/agents/`). It would prove nothing about whether a reviewer *honors* the section on a given review — that is a fact about a specific run, not about the repo, and no static test can observe it from here. The line that decides whether to add one anyway: `.github/ISSUE_TEMPLATE/*.md` (#1605) is read by a human who can silently delete a line, so presence is the whole contract available to test; these four files are consumed wholesale by a model on every invocation of that agent, so presence was never going to be the whole contract, and a presence-only test would read as proving more than it does. Per the MINIMALITY RULE, and because the issue's own acceptance criteria don't ask for a gate ("each of the four agent files contains a disposition rule," "`CLAUDE.md` names the obligation" — both satisfied by the text itself), no test is added — the drift-detection gap (a deleted section goes unnoticed) is named here rather than silently left unstated.

## Not in scope

A CI/test gate over agent-file prose (explicitly declined above, with reasoning). Adding a per-finding `**Disposition**` bullet to the `## Output Format` finding shape itself — the issue asks for a policy section stating what severity *obliges*, not a new field each finding must fill in; conflating the two would also touch the very finding-shape inconsistencies (`**Invariant**` vs `**Pattern**` vs neither) the issue explicitly flags as a separate, pre-existing fact and does not ask this issue to reconcile.

## Review corrections (round 1)

**Adopted:**
- Third disposition arm — "accept it explicitly, bounded and dated" — added to both the CLAUDE.md paragraph and the security-reviewer.md insertion. The original "fix it, or withdraw it, no filing a follow-up and shipping anyway" absolute contradicted CLAUDE.md's own Security section, which records four findings (#1654, #1599, #1609, #1488) accepted rather than fixed, and the Development Workflow's own dated-gates rule. Only security-reviewer.md's text changed among the four agent files — none of the other three touches the acceptance register, so they needed no third arm.
- Severity-vs-consequence reconciliation — the CLAUDE.md paragraph now reads "a finding in an adversarial reviewer's stated blocking set — and any security finding rated Critical or High — blocks the change," replacing the earlier severity-only phrasing that contradicted the three category-keyed agent files (crdt, annotation-model, svelte carry no severity term). A paragraph explaining the reconciliation is inserted after the fix block so a future reader sees the reasoning, not just the outcome. The three non-security agent files needed no wording change — they were already correct; only CLAUDE.md's summary of them was wrong.
- Reworded the "Deliberate non-mechanism" paragraph to state precisely what a presence test would and would not catch (deletion, not obedience) instead of dismissing it wholesale as "theater," and to name the audience distinction against #1605's template test (human-edited vs. model-consumed) rather than leaving the two specs' opposite conclusions unreconciled.
- Removed the `npx biome format --write` step from "Done when" — measured: it exits 1 on `.md` paths (`biome.json`'s `files.includes` has no `.md` entry). Replaced with a hand-wrap instruction.
- Added a link to `docs/spikes/ai-debugging-blind-spots-audit.md` ("Full study:") in the CLAUDE.md paragraph, and a Tests item confirming `tests/build/dangling-citations.ts` must resolve it — partial adoption of the "cut to one sentence and link out" suggestion; not fully compressed to one sentence because the third-arm and union-framing content is load-bearing (it's what makes the paragraph not contradict the rest of the file), but the link gives a future reader the fuller argument without inlining it.

**Not adopted:**
- Dropping security-reviewer.md's own Critical/High severity sentence to a bare pointer at CLAUDE.md (one review comment's secondary suggestion). Security is the one domain where severity-as-written already has a shared, calibrated meaning (Critical/High Sev definitions are used project-wide, not just by this agent), so restating "Critical or High blocks" in the agent's own file is not duplication in the same way the old CLAUDE.md line was — it's the domain owning its own instance of a term CLAUDE.md also uses in the union statement. Removing it would make security-reviewer.md read as if only CLAUDE.md's summary applied, which is backwards: the agent file is what the reviewing session actually reads mid-review.
- Adding a four-file `## Disposition`-presence test under `tests/docs/` (offered as the alternative to reasoning-in-prose). Declined per the reworded paragraph's own logic: these files are consumed wholesale by the model performing the review, so the model reading the text is the mechanism, not a test asserting the text is there for a model that will read the whole file regardless. Revisit if a future incident shows a `## Disposition` section actually got deleted unnoticed — that would be the concrete instance the current reasoning is missing.
