# W13v — #1995 a superseded spawn's late exit clears the successor's `confirmTimer`; `startInternal` ignores a breaker tripped during its await

Branch `fix/server-and-cli-small-correctness-fixes-2003`. Closes #1995. Ledger: no `areas/*.md` row — filed from G1 (#1866 #1868 #1867 #1780) implementation, which fixed the third symptom of the same root and left these two; tracked home is the wave 13 row in `docs/plans/2026-09-06-open-issues-sweep.md`. Probe: read from source, not reproduced — the issue says so, and item 2 was observed once in `tests/server/launcher/supervisor-turn-delivery.test.ts` before G1's exit-handler guard closed the window that exposed it.

## Problem

Both items share one root, already documented in `spawnOnce`'s exit handler: `stopInternal` does not wait for a handle that is already `killed` (the stdin-gone #1757, receipt #1867 and sign-in #1780 kills all leave one), and `respawn` then lowers `stopRequested` and `breakerTripped`. So a user relaunch can start a new spawn before the old one's `exit` lands.

**1. The late exit clears the successor's `confirmTimer`.** `confirmTimer` is supervisor-scoped (declared beside `child`), while `resumeConfirmed` is per-spawn (a `let` inside `spawnOnce`). G1 added `const wasCurrent = child === spawned` and guards the restart on it — but the `confirmTimer` clear above that sits unguarded:

```ts
const wasCurrent = child === spawned;
if (wasCurrent) child = null;

// Cancel the confirmation timer — the process has already exited.
if (confirmTimer) { clearTimeout(confirmTimer); confirmTimer = null; }
```

When the exiting spawn is superseded, `confirmTimer` no longer holds that spawn's handle — `spawnOnce` overwrote it with the successor's. Clearing it leaves the successor's `resumeConfirmed` false for its whole life, so `shouldClearSession({resuming, code, resumeConfirmed})` is satisfied by **any** later non-zero exit and `clearSavedSession()` deletes `launcher-session.json`. The conversation pointer is lost — the #1169 / #1268 class.

**2. `startInternal` re-checks `stopRequested` after `await buildPlan()` but not `breakerTripped`.** The function opens with `if (child) return; if (breakerTripped) return;`, then awaits `buildPlan()`, then re-checks only `stopRequested`. A trip landing inside that await (a sign-in trip on a relaunched child, or `scheduleRestart`'s own trip) still spawns.

## Fix

Two guards in `src/server/launcher/supervisor.ts`. No new state, no new timer, no new option.

- **`spawnOnce`'s `spawned.on("exit")` handler:** move the `confirmTimer` clear inside `if (wasCurrent)`, beside `child = null`, with a comment naming why it is identity-guarded and why every non-current path still cancels: the long-lived `spawned.on("error")` handler clears it explicitly (its existing comment says so), and `stopInternal` clears it before killing. The exit handler is the only unguarded one.
- **`spawnOnce`'s confirmation timer:** hold the handle in a local and have the callback null the shared slot only if it still owns it —
  ```ts
  const timer = setTimeout(() => {
    resumeConfirmed = true;
    if (confirmTimer === timer) confirmTimer = null;
  }, RESUME_CONFIRM_MS);
  confirmTimer = timer;
  ```
  Same identity discipline, and it is what makes the first guard complete: a superseded spawn's own leaked timer would otherwise fire 30 s later and null the successor's handle out of the shared slot, leaving `stopInternal` with nothing to cancel. One line; not a mechanism.
- **`startInternal`, after `await buildPlan()`:** `if (breakerTripped) return;` beside the existing post-await `stopRequested` check, sharing its `console.error` shape ("Breaker tripped while building the spawn plan — not spawning"). The pre-await `if (breakerTripped) return;` stays: this is a re-check of a flag that can move during the await, exactly like `stopRequested`.

Rules that bite: nothing here touches a Y.Doc, a Y.Map key, an MCP tool or an `/api` route — Critical Rules 1, 2 and 9 are not engaged. Critical Rule 3 holds by construction: the supervisor already logs through `console.error`, and the new line must too — a `console.log` here would still be redirected in `index.ts`, but the file's convention is `console.error` and the stdin channel to the child must not gain a writer.

## Tests

In `tests/server/launcher/supervisor.test.ts` (it owns the spawn/exit lifecycle; the turn-delivery file owns wake delivery). The issue names the shape the test needs: `RESUME_CONFIRM_MS` (30 s) under fake timers alongside the harness's real-timer helpers, so use `vi.useFakeTimers()` scoped to these specs and the stub CLI (`stub-claude-cli.cjs`) the file already drives.

1. **A superseded spawn's late exit does not confirm-starve its successor.** Drive: start a resuming spawn, kill it in a way that leaves a `killed` handle, `respawn()` so a second resuming spawn is current, *then* deliver the first spawn's `exit`. Advance fake timers past `RESUME_CONFIRM_MS`, exit the successor non-zero, and assert `launcher-session.json` **still exists** / `clearSavedSession` was not called. Kills the shipped code, whose successor is stuck at `resumeConfirmed === false`.
2. **The current spawn's own exit still cancels its timer.** A single resuming spawn exits non-zero before `RESUME_CONFIRM_MS`; assert the session **is** cleared and that advancing timers afterwards throws nothing and does not re-enter the callback. Kills an over-fix that guards the clear on something other than identity (e.g. drops the clear entirely), which would leave a live timer after every exit.
3. **The stale callback does not steal the successor's handle.** After (1)'s setup, advance past the *first* spawn's timer deadline, then call `stop()`; assert the successor's confirmation never fires afterwards (its `resumeConfirmed` stays false — observable via a subsequent non-zero exit clearing the session). Kills the version that guards only the exit handler and leaves the callback nulling the shared slot.
4. **`startInternal` refuses to spawn when the breaker trips during `buildPlan()`.** Make `buildPlan` await a deferred promise; set `breakerTripped` via the public path that trips it while that await is pending; resolve; assert no spawn happened and the "not spawning" line was logged. Kills the shipped code and kills a fix that moves the check *before* the await only.
