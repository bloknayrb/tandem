# G10 — #1702 the two inbox collectors share three parameters with no shared type, and it has drifted twice

Branch `fix/awareness-hygiene-selection-staleness-and-one-inbox-poll-context-1702`. Closes #1702: both acceptance boxes, with exactly what enforces box 2 stated under Tests 1. Not a v1-review ledger row — no `areas/*.md` row, experiment or `refuted.md` entry cites it; it is sweep wave 8 group G10 (`docs/plans/2026-09-06-open-issues-sweep.md:101`). Probe: none — the failure is a signature shape, pinned by a type test, by handler-level behaviour tests and by mutation of the call sites below. Lands before #1624 (same file, same handler).

## Problem

Measured on `4f112aa4`, `src/server/mcp/awareness.ts`:

- `processInboxAnnotations(allAnnotations, fullText, surfaced, refreshAll, documentId, modeState, wasChannelEmitted)` (`:672-684`)
- `processUnsurfacedInboxAnnotations(unsurfaced, fullText, surfaced, modeState, wasChannelEmitted, documentId)` (`:731`, private) — a **third** order, called from `:721-728`
- `collectInboxUserReplies(allAnnotations, fullText, loadReplies, replySurfaced, modeState, documentId, wasChannelEmitted)` (`:890-900`)

The same three values from one poll are passed in three different positional orders. `documentId: string` and `modeState: ModeState` (a string union) can be swapped at a call site without a type error.

ADR-027 and the Solo gate depend on these parameters:
- `modeState` feeds `hideFromAI` (`:752`, `:908`). In `src/server/mode.ts:85-92`, `solo` hides every `author === "user"` record and `indeterminate` hides only records with `heldInSolo === true`.
- `wasChannelEmitted` stamps `alreadyPushed` (`:822`, `:922`).
- `documentId` scopes both ledgers (`inboxLedgerKey`, `ledgerKey`).

Units 8j-2 and 8j-3 each silently lost one of these parameters to a default, and the loss was found only by reading. The handler (`:457-477`) passes the three values separately to each collector. Nothing fails if a fourth shared value is added positionally to only one collector.

No handler-level test pins `alreadyPushed` on either bucket, and none pins the Solo hold on `userReplies`:
- The only `tandem_checkInbox` Solo pins that go through the real tool are `annotation-promote-pull-surface.test.ts:249` and `held-in-solo-stamp.test.ts:204`. Both read only `userActions`/`userResponses`.
- Every `alreadyPushed` pin calls the collectors directly (`awareness-tools.test.ts:299-360`, `:840-870`).

So if the handler gave replies a wrong `wasChannelEmitted` or a collapsed `modeState`, no test would notice today. The docblock at `:652` already says this about the pre-8j-2 default.

## Fix

`src/server/mcp/awareness.ts` only (plus test call sites). Behaviour-identical.

1. Export, next to `InboxUserAction`:
   ```ts
   export interface InboxPollContext {
     /** Privacy gate for `hideFromAI`. `"indeterminate"` is NOT fail-closed — see processInboxAnnotations. */
     modeState: ModeState;
     /** Scopes both surfaced ledgers — see `surfacedIds` / `replySurfacedIds`. */
     documentId: string;
     /** Stamps the advisory `alreadyPushed`; never a suppression. */
     wasChannelEmitted: (payloadId: string) => boolean;
   }
   ```
   All three fields required, none optional — an optional field is the 8j-2 default under a new name.
2. Signatures, context as the single trailing parameter on all three:
   `processInboxAnnotations(allAnnotations, fullText, surfaced, refreshAll, ctx: InboxPollContext)`;
   `processUnsurfacedInboxAnnotations(unsurfaced, fullText, surfaced, ctx: InboxPollContext)`, called with the same `ctx` object (no spread, no rebuild). The type cannot enforce this because the private function is not exported; mutation rows 5–7 enforce it.
   `collectInboxUserReplies(allAnnotations, fullText, loadReplies, replySurfaced, ctx: InboxPollContext)`.
   Bodies read `ctx.modeState` / `ctx.documentId` / `ctx.wasChannelEmitted` (destructure at the top is fine). No other line in the bodies changes.
3. Handler (`:457-477`): build once, pass the same object to both collectors:
   `const pollCtx: InboxPollContext = { modeState, documentId: store.documentId, wasChannelEmitted: wasEmittedViaChannel };`
   `modeState` stays the single `readModeState()` of this poll (the comment at `:435-439` explains why). It must not be `reportedMode(modeState)`: that maps `indeterminate` to `TANDEM_MODE_DEFAULT` (`mode.ts:54-56`) and would release `heldInSolo`-stamped records. Test 2(c) pins this.
4. Docblocks: the "`modeState` and `wasChannelEmitted` are REQUIRED" paragraph (`:646-657`) keeps its 8j-2/8j-3 history in two sentences and points at `InboxPollContext`; the per-parameter JSDoc at `:678-683`, `:735-737`, `:896-899` moves onto the interface fields. The handler comment at `:452-456` names `pollCtx`. `annotations.ts:69` and `output-schemas.ts:236` name the functions only — unchanged; re-grep before asserting.
5. Rule 2 is not touched (no Y.Doc write moves); `refreshAll` stays a batch callback outside the context — it is per-collector, not shared.

**Call-site census.** Every positional call under `tests/` is converted: `awareness-tools.test.ts`, `adr027-note-write-guards.test.ts`, `awareness.test.ts`, `inbox-ledger-undo.test.ts` (its helper at `:80`), `read-audience-filter.test.ts`. Each positional trio becomes `{ modeState, documentId, wasChannelEmitted }` with **the same values**, so no fixture changes. No exact count is claimed: line-anchored and bare-name greps disagree because of imports and describe titles. The completeness check is that `npm run typecheck:tests` fails on any site left unconverted. `tests/e2e/inbox-pull-path.spec.ts` names the collectors only in comments and is unchanged.

It is outside `tsconfig.tests.node.json` and the root vitest `tests/**` include, so nothing will flag it; after this change it throws at runtime if hand-run through its own `harness/vitest.config.ts`. L : never;` then `expectTypeOf<Last<Parameters<typeof processInboxAnnotations>>>().toEqualTypeOf<InboxPollContext>()` and the same for `collectInboxUserReplies`.
   - Test comment, in substance: "Enforced by `npm run typecheck:tests` (CI `check`, required), not by vitest's runtime. A new per-poll value goes on `InboxPollContext`, never into these tuples. This guards against ACCIDENTAL drift. Someone who deliberately adds a positional parameter can edit the tuple in the same change; test 2 is the behavioural pin."
   - What acceptance box 2 actually gets, stated plainly for the `## Closes` review:
     - A value added to `InboxPollContext` reaches both collectors by construction, because the call site cannot pass it to only one.
     - A value added positionally to one collector turns `typecheck:tests` red (rows 9–10).
     - A collector that receives the context but ignores a field is not caught by the type. For the three existing fields, rows 1–8 and test 2 catch that.
2. **Handler-level, both buckets** (same file, new `describe("tandem_checkInbox passes one poll context to both collectors (#1702)")`).
   - Setup: build the in-memory MCP client the way `held-in-solo-stamp.test.ts:216-222` builds `mcpClient`. Use `attachObservers` plus an inert `subscribe(..., "external")` as in `awareness-tools.test.ts:840-857`, and unsubscribe in `finally`.
   - Use **three separate `it` blocks, each with a fresh docId**, and rely on the file's `beforeEach` `resetInbox()` (`:57-58`). The surfaced ledgers are module-level, so one shared block would pass without testing anything.
   - Unwrap `{ error: false, data }` and read `id` keys as `held-in-solo-stamp.test.ts:234-243` does. Every case includes a positive control.
   - **(a) `alreadyPushed`.** Call `setCtrlMode("tandem")` **before** the writes; a cleared mode key is `indeterminate`, and the push hold fails closed on that (`:333-336`). Write a user comment with `writeUserComment`, which sets `audience: "outbound"` (`:278-292`); without it #1619 filters the record. Under `withBrowser`, write the `commentParent` fixture and a user reply on it. One `tandem_checkInbox` → `userActions[0].alreadyPushed === true` **and** `userReplies[0].alreadyPushed === true`.
   - **(b) Solo hold, both buckets.** Call `setCtrlMode("solo")` **before** any write, and do not poll in Tandem before the Solo poll. Use the same record shapes. Poll → neither `userActions` nor `userReplies` contains the ids. Then `setCtrlMode("tandem")` → both ids surface on the next poll, which proves the hold wrote no ledger entry. The two buckets are held by different conditions:
     - The annotation observer stamps the Solo comment `heldInSolo` (`src/server/annotations/held-in-solo.ts:109-123`, annotations map only).
     - A reply written from the browser is not stamped, so it is held **only** by `modeState === "solo"`. Row 2 relies on this.
   - **(c) Indeterminate holds only stamped records.** Call `setCtrlMode("tandem")` first, so the observer stamps nothing. Write two user comments and two replies: one comment and one reply with `heldInSolo: true` on the stored record, and one of each without it. Then `setCtrlMode(null)` and poll once. In both buckets, the stamped records are absent and the unstamped ones are present. The unstamped records are the positive control against a mutation that hides everything.
