# G10 — #1702 the two inbox collectors share three parameters with no shared type, and it has drifted twice

Branch `fix/awareness-hygiene-selection-staleness-and-one-inbox-poll-context-1702`. Closes #1702 (both acceptance boxes). Not a v1-review ledger row — no `areas/*.md` row, experiment or `refuted.md` entry cites it; it is sweep wave 8 group G10 (`docs/plans/2026-09-06-open-issues-sweep.md:101`). Probe: none — the failure is a signature shape, pinned by a type test and by mutation of the call sites below. Lands before #1624 (same file, same handler).

## Problem

Measured on `4f112aa4`, `src/server/mcp/awareness.ts`:

- `processInboxAnnotations(allAnnotations, fullText, surfaced, refreshAll, documentId, modeState, wasChannelEmitted)` (`:672`)
- `processUnsurfacedInboxAnnotations(unsurfaced, fullText, surfaced, modeState, wasChannelEmitted, documentId)` (`:731`, private) — a **third** order, called from `:721`
- `collectInboxUserReplies(allAnnotations, fullText, loadReplies, replySurfaced, modeState, documentId, wasChannelEmitted)` (`:890`)

Three positional orders for the same three values from one poll. `documentId: string` and `modeState: ModeState` (a string union) transpose at a call site without a type error. ADR-027 and the Solo gate ride on these parameters: `modeState` feeds `hideFromAI` (`:752`, `:908`); `wasChannelEmitted` stamps `alreadyPushed` (`:822`, `:922`); `documentId` scopes both ledgers (`inboxLedgerKey`, `ledgerKey`). Units 8j-2 and 8j-3 each lost one of them silently (defaults), found by reading. The handler (`:457-477`) passes the three values separately to each collector. Nothing fails if a fourth shared value is added positionally to one collector only.

No handler-level test pins `alreadyPushed` on either bucket, and none pins the Solo hold on `userReplies`: the only real-tool `tandem_checkInbox` Solo pins are `annotation-promote-pull-surface.test.ts:249` and `held-in-solo-stamp.test.ts:204`, both on `userActions`; every `alreadyPushed` pin drives the collectors directly (`awareness-tools.test.ts:299-360`, `:840-870`). So a handler that handed replies a wrong `wasChannelEmitted` is, today, observed by nothing. The docblock at `:652` already says so for the pre-8j-2 default.

## Fix

`src/server/mcp/awareness.ts` only (plus test call sites). Behaviour-identical.

1. Export, next to `InboxUserAction`:
   ```ts
   export interface InboxPollContext {
     /** Privacy gate for `hideFromAI`. `"indeterminate"` is NOT fail-closed — see processInboxAnnotations. */
     modeState: ModeState;
     /** Scopes both surfaced ledgers — see `surfacedIds` / `replySurfacedIds`. */
     documentId: string;
     /** Stamps the advisory `alreadyPushed`; never a suppression. */
     wasChannelEmitted: (payloadId: string) => boolean;
   }
   ```
   All three fields required, none optional — an optional field is the 8j-2 default under a new name.
2. Signatures, context as the single trailing parameter on all three:
   `processInboxAnnotations(allAnnotations, fullText, surfaced, refreshAll, ctx: InboxPollContext)`;
   `processUnsurfacedInboxAnnotations(unsurfaced, fullText, surfaced, ctx: InboxPollContext)`, called with the same `ctx` object (no spread, no rebuild);
   `collectInboxUserReplies(allAnnotations, fullText, loadReplies, replySurfaced, ctx: InboxPollContext)`.
   Bodies read `ctx.modeState` / `ctx.documentId` / `ctx.wasChannelEmitted` (destructure at the top is fine). No other line in the bodies changes.
3. Handler (`:457-477`): build once, pass the same object to both collectors:
   `const pollCtx: InboxPollContext = { modeState, documentId: store.documentId, wasChannelEmitted: wasEmittedViaChannel };`
   `modeState` stays the single `readModeState()` of this poll (the comment at `:435-439` is why), not `reportedMode(modeState)` — that collapses `indeterminate` and would release `heldInSolo`-stamped records.
4. Docblocks: the "`modeState` and `wasChannelEmitted` are REQUIRED" paragraph (`:646-657`) keeps its 8j-2/8j-3 history in two sentences and points at `InboxPollContext`; the per-parameter JSDoc at `:678-683`, `:735-737`, `:896-899` moves onto the interface fields. The handler comment at `:452-456` names `pollCtx`. `annotations.ts:69` and `output-schemas.ts:236` name the functions only — unchanged; re-grep before asserting.
5. Rule 2 is not touched (no Y.Doc write moves); `refreshAll` stays a batch callback outside the context — it is per-collector, not shared.

Test call sites (36, measured by `grep -c`): `awareness-tools.test.ts` ×32, `adr027-note-write-guards.test.ts` ×1, `awareness.test.ts` ×1, `inbox-ledger-undo.test.ts` ×1 (its helper at `:80`), `read-audience-filter.test.ts` ×1. Each positional trio becomes `{ modeState, documentId, wasChannelEmitted }` with **the same values** — no fixture changes. `tests/e2e/inbox-pull-path.spec.ts` names the collectors only in comments; unchanged.
