# B — #1766 Critical Rule 6 is endpoint-only: a range spanning a heading prefix passes and can delete the heading

Branch `fix/annotation-anchors-1764`. Closes #1766 (both halves: the spanning range, and documenting the exclusive-end asymmetry). Ledger: `docs/reviews/2026-09-02-v1-review/areas/crdt.md:21`.

## Problem

`validateRange`'s heading gate (`src/server/positions.ts`) resolves **only the two endpoints**:

```
if (startPos.clampedFromPrefix || endPos.clampedFromPrefix) return { ok: false, code: "HEADING_OVERLAP" };
```

On `"para\n## Head\nnext"` both `validateRange(4, 9)` and `(0, 9)` pass with `rejectHeadingOverlap: true`, because neither endpoint sits inside `"## "` even though the interior contains all of it. `tandem_edit(4, 13, "X")` on `"Para one\n## Head\nTail"` produces `"ParaXead\nTail"` — the heading is gone. That is what Critical Rule 6 exists to prevent.

The related asymmetry is real and is not a bug: `to` equal to the *first* character of a heading prefix is rejected even though the end is exclusive, because `resolveToElement(to)` lands at offset 0 of the heading and reports `clampedFromPrefix`. It is simply undocumented.

**`rejectHeadingOverlap` is not `tandem_edit`-only, and that governs the shape of the fix.** Three callers, measured:

| Caller | Site | What it does with a range |
|---|---|---|
| `tandem_edit` | `src/server/mcp/document.ts` (`validateRange`) | **Rewrites document text** |
| `tandem_comment` / `tandem_suggest` | `annotations.ts:311` → `YDocStore.anchorRange` (`document-store.ts:283-289`, whose docblock says "**`rejectHeadingOverlap` is unconditional and is NOT a parameter**") | Creates an annotation; writes no text |
| local-model anchor resolution | `src/server/local-model/tools.ts:204` (`anchoredRange`) | Creates an annotation; writes no text |

So ORing an interior scan into the shared term would **newly refuse annotation creation across a heading**: on `"Intro para\n## Section\nBody text"`, `tandem_comment` over `[0, 25]` — a comment about a whole section — succeeds today and would answer "Target the text content only", advice a multi-section comment cannot follow. Rule 6 is about *editing* heading markup; annotating across a heading is legal and stays legal.

## Fix

Add an interior scan behind its **own** option, passed only by `tandem_edit`; keep the endpoint check exactly as it is.

- **`src/shared/positions/ydoc.ts`** — next to `resolveToElement`, which owns this walk today:
  `export function rangeOverlapsHeadingPrefix(fragment: Y.XmlFragment, from: FlatOffset, to: FlatOffset): boolean`. Walk the fragment's direct children accumulating flat offsets with **the same arithmetic `resolveToElement` uses**: each element contributes `getHeadingPrefixLength + getElementTextLength`, and **a non-`Y.XmlElement` child must consume no separator**. In `resolveToElement` (`ydoc.ts:340-362`) the `\n` is added per child index under `i < fragment.length - 1`, but a non-element child hits `continue` **before** that line — the same rule `extractTextWithBreaks` states as "one separator between *emitted* elements" (`mcp/document-model.ts:298-300`). A walker that drops the `continue` shifts every later element's `blockStart` by one. Mirror the loop shape, `continue` included, rather than re-deriving it.
  For each element with `getHeadingPrefixLength(node) > 0` the prefix occupies `[blockStart, blockStart + prefixLen)`; return `true` on the standard half-open overlap `blockStart < to && blockStart + prefixLen > from`. Same file as the resolver on purpose — a fifth independent walker over the separator contract is how the existing four would drift — and heading prefixes are top-level only, so a top-level walk is complete.
- **`src/server/positions.ts`** — a **new, separate** option on `RangeValidationOpts`: `rejectHeadingInterior?: boolean`. Inside the existing `if (rejectHeadingOverlap)` block, after the `startPos`/`endPos` resolution and the `unresolvable` arm, keep `startPos.clampedFromPrefix || endPos.clampedFromPrefix` exactly as it is and OR in `(opts?.rejectHeadingInterior === true && rangeOverlapsHeadingPrefix(fragment, from, to))`. Union rather than replacement, for two reasons: the overlap predicate alone would newly *accept* `to === blockStart`, silently relaxing behaviour `tandem_edit` callers and `tests/server/local-model/tools.test.ts` depend on; and the endpoint rule stays the rule for the two annotation-creation callers.
- **`src/server/mcp/document.ts`** — the one call site that gains `rejectHeadingInterior: true` (the `validateRange` call in `tandem_edit`). `YDocStore.anchorRange` and `local-model/tools.ts:204` are **not** changed and keep the endpoint-only rule.
- **`src/server/mcp/document.ts`, the message — and the site is not `rangeFailureToError`.** `grep -rn rangeFailureToError src/` returns only `mcp/annotations.ts:105` (the definition) and `:314` (its sole caller, inside `tandem_comment`/`tandem_suggest`); its `HEADING_OVERLAP` arm at `annotations.ts:120-124` returns `'Range overlaps with heading markup (e.g., "## "). Target the text content only.'` and **must not change** — the annotation tools keep the endpoint-only rule, so "split the edit at the heading boundary" is advice a comment author cannot follow. The site to edit is `tandem_edit`'s own **inline** `mcpError` in the `if (v.code === "HEADING_OVERLAP")` branch immediately after the `validateRange` call this spec edits, today `'Edit range overlaps with heading markup (e.g., "## "). Target the text content only. Use tandem_resolveRange to find the text position.'` — it gains the actionable alternative ("split the edit at the heading boundary and issue one call per block"), since "target the text content only" is not followable for an interior overlap.
- **Nothing about the check order moves.** Critical Rule 4 puts heading overlap last, after emptiness — so an empty range inside a prefix still answers `empty` without `allowEmpty` and `HEADING_OVERLAP` with it. This adds a term to the last check, not a new position in the sequence.
- **`CLAUDE.md` Critical Rule 6** — "A range whose **start, end or interior** overlaps a heading prefix (e.g. `## `) returns INVALID_RANGE — the interior term applies to `tandem_edit` only; annotation creation refuses the endpoints alone, so a comment may span a heading."
- **`docs/architecture.md`** — add to the coordinate-systems bullets near `:647-654` (there is no "start or end inside a prefix" sentence there to replace; the nearest text is the top-level-heading-prefix bullet at `:654`): the interior rule and which callers carry it, plus one sentence on the exclusive end — a `to` equal to the first character of a heading prefix is rejected, because the exclusive end still resolves into the heading block.

7. `tests/server/resolve-textblock.test.ts` (or `tests/server/positions.test.ts` — **not `tests/shared/`**, which holds no `resolveToElement` spec) — the separator contract, with **`extractText`'s own offsets as the oracle**: a fragment `[heading, non-element child, second heading]`, deriving the second heading's block start `bs2` from `extractText` and asserting **`rangeOverlapsHeadingPrefix(fragment, bs2 + prefixLen, bs2 + prefixLen + 2) === false`** — a range starting exactly one unit past the end of the second heading's prefix. **This is the one boundary that flips when the walker adds a separator for the non-element child**: with a correct walker the predicate evaluates `bs2 + prefixLen > bs2 + prefixLen`, false; with the `continue` dropped every later block start is one unit high and it evaluates `bs2 + 1 + prefixLen > bs2 + prefixLen`, true. Do not use a range covering the prefix itself, or one ending at `bs2` — both answer the same under either walker and pin nothing.

## Done when

`validateRange(4, 9)` and `(0, 9)` are refused once `rejectHeadingInterior` is passed and still pass without it; `tandem_edit(4, 13, "X")` on the heading fixture is refused through the registered tool with a message naming the split, while `rangeFailureToError`'s message (`annotations.ts:120-124`) is byte-identical to today; `tandem_comment` across a heading still succeeds; Critical Rule 6 and `docs/architecture.md` say "start, end or interior" for `tandem_edit`, name the annotation exception and document the exclusive end; `npm run typecheck` + `npm run typecheck:tests` + suite green.

## Assumptions

- **The interior rule is `tandem_edit`'s, not `validateRange`'s.** Measured from the three-caller table. Widening the shared flag would refuse a comment spanning a section, which is legal today and has no phrasing the caller could follow.
- **The exclusive-end asymmetry is documented, not removed.** The issue calls it "undocumented", not wrong, and relaxing it would let `tandem_edit` delete the newline separating a paragraph from the heading below it.
- **Top-level scan only.** A nested heading contributes no prefix (`resolveToTextblock`'s documented contract), so descending would find nothing and would need a fifth copy of the separator arithmetic.
- **The predicate is a boolean, not a position.** No caller needs to know *which* heading; returning one would invite a message that names it and a second consumer.

## Not in scope

`YDocStore.anchorRange` and `local-model/tools.ts:204` gaining the interior term — see the caller table. The `HEADING_OVERLAP` wire code itself (`tandem_edit`'s inline message text is in scope; the code is not). **`rangeFailureToError` (`annotations.ts:105`, its `HEADING_OVERLAP` arm at `:120-124`) is explicitly NOT changed**, and test 4 pins its message unchanged. Heading prefixes inside list items or table cells, which do not exist in this model.
