# W13a — #1961 `skills/tandem/SKILL.md` still says "Start the Tauri app" instead of "the desktop app"

Branch `fix/activity-awareness-honesty-1918`. Closes #1961. Split out of #1824 item O during K-client review round 1 (sweep ledger `docs/plans/2026-09-06-open-issues-sweep.md:464`); it rides here because K-client's ownership excluded `skills/` and `tests/skill-instruction-contract.test.ts`.

## Problem

`skills/tandem/SKILL.md:159`'s not-running message tells Claude to tell the **user**: "Start the Tauri app or run `tandem start`". Tauri is the framework; the product name everywhere user-facing is "the desktop app".

**The same sentence also ships from `src/`, and that is where users hit it:** `src/cli/mcp-stdio.ts:1413` and `:1430` (the synthesized `-32000` connect-failure messages an MCP client shows when the server is not running) and `src/cli/preflight.ts:68`. They are in scope under the two-person "fix it rather than file it" rule — Fix step 5.

`docs/troubleshooting.md` holds no "Tauri app" string at all (its sole Tauri mention, `:162`, is developer-facing and stays). The remaining `src/` matches are `Tauri app-data dir` in `src/server/platform.ts:39`, `src/server/mcp/routes/license.ts:170` and `SettingsLicenseTab.svelte:136` — a directory name, untouched.

## Fix

This is the group's **single skill commit**, carrying two body edits so the version bump and hash are computed once:

1. `skills/tandem/SKILL.md:159`: "Start the Tauri app" → "Start the desktop app". Nothing else in that block changes.
2. `skills/tandem/SKILL.md:84`: remove the `selectionAt` re-stamp caveat per `W13a-1991.md` — "while the document is the user's active tab, any edit that moves the selection re-stamps it, including yours, so a recent value does not prove a recent selection, but an old one proves it is old" becomes "`activity.selectionAt` is when the user last made that selection; a remote edit that shifts **or rewrites** the selected span updates the offsets and `selectedText` without re-stamping the time." The wording must match the schema and `docs/mcp-tools.md`. The following background-tab (#1997) sentence stays verbatim.
3. Frontmatter `version: 25` → **`26`** (`origin/master` carries 25 as of this writing; re-check at implementation time and use the next integer above whatever it carries).
4. In the same commit, `tests/skill-instruction-contract.test.ts`: the `expect(skill).toMatch(/^version:\s*25$/m)` literal at `:113` and the `{ version: "25", bodyHash: "7b8da6d8092b" }` pair at `:434`. Recompute the hash exactly as that test does — `sha256` over the body after the frontmatter, CRLF→LF normalised, hex `.slice(0, 12)` — **after** both body edits are final. Add one entry to the version-narration comment above `:113` in its existing style, and re-read the wake assertions against the bumped file: both edited paragraphs are outside the wake section, and that re-reading is the step the tripwire exists for.
5. **In the same PR but `src/` only — no skill bump, no contract-test literal:** `src/cli/mcp-stdio.ts:1413`, `src/cli/mcp-stdio.ts:1430` and `src/cli/preflight.ts:68`, "Start the Tauri app" → "Start the desktop app". Keep the rest of each sentence byte-identical. These carry no test, so the PR body must say they were changed.

Rule that bites: the two refresh comparisons differ by one character (`refreshExistingSkillIfStale` bails at `>=`, `installSkill` at `>`), so a body edit at an unchanged `version` reaches nobody — which is why step 3 is not optional for a one-word change.
