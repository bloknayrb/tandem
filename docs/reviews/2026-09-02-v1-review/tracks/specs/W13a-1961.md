## Fix

This is the group's **single skill commit**, and it carries two body edits so the version bump and hash are computed once:

1. `skills/tandem/SKILL.md:159`: "Start the Tauri app" → "Start the desktop app". Nothing else in that block changes; the "say all three parts" paragraph below it still holds.
2. `skills/tandem/SKILL.md:84`: remove the `selectionAt` re-stamp caveat per `W13a-1991.md` — the sentence "while the document is the user's active tab, any edit that moves the selection re-stamps it, including yours, so a recent value does not prove a recent selection, but an old one proves it is old" becomes "`activity.selectionAt` is when the user last made that selection; a remote edit that shifts it updates the offsets without re-stamping the time." The following sentence about a background tab (#1997) stays verbatim.
3. Frontmatter `version: 25` → **`26`** (re-check `origin/master` at implementation time and use the next integer above whatever it carries — the sweep has had two groups move this number).
4. In the same commit, `tests/skill-instruction-contract.test.ts`: the `expect(skill).toMatch(/^version:\s*25$/m)` literal at `:113`, and the `{ version: "25", bodyHash: "7b8da6d8092b" }` pair at `:434`. Recompute the hash exactly as that test does — `sha256` over the body after the frontmatter, CRLF→LF normalised, hex `.slice(0, 12)` — **after** both body edits are final; do not hand-copy it from a failure message without re-reading the diff.
5. Extend the version-narration comment block above `:113` with one entry in its existing style: moved to 26 by W13a (#1961 + #1991) — the not-running remedy names the desktop app, and the Reacting to Document Events paragraph drops the `selectionAt` re-stamp caveat; both paragraphs are outside the wake section and every wake assertion below was re-read against the bumped file and is unchanged. That re-reading is a real step, not boilerplate: the comment says so and the tripwire exists for it.

Rule that bites: the two refresh comparisons differ by one character (`refreshExistingSkillIfStale` bails at `>=`, `installSkill` at `>`), so a body edit at an unchanged `version` reaches nobody — which is exactly why step 3 is not optional for a one-word change.
