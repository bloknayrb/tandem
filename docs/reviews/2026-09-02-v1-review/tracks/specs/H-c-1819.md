## Problem

**1. `daysRemaining` is display-unclamped, and H-a narrowed the stored route without closing it.**
`license-state.ts` computes `Math.max(0, Math.ceil((expiresAt - nowMs) / 86_400_000))` — a *lower*
clamp only. Two routes reach a value above `TRIAL_DAYS`, and they are not the same route:

- **Stored value, still live but now bounded.** H-a's `trialBodyIsUsable` accepts any `firstRunAt`
  up to `nowMs + TRIAL_FUTURE_SLACK_MS` (24 h), so a `firstRunAt` half a day in the future is
  "usable", `ensureTrialStarted` leaves it alone, and the banner reads **"15 of 14 days left"**.
  H-a took this from unbounded to `TRIAL_DAYS + 1`; it did not make it unreachable. Do not describe
  the clamp as dead code for stored values.
- **In-session clock change, fully open.** `ensureTrialStarted` runs **once**, at startup
  (`src/server/index.ts:382-385`, both transports). `resolveLicenseState` re-reads per dispatch with
  a live `Date.now()`. A clock moved backwards *after* boot yields `14 + N` with no repair until the
  next restart — the issue's own "24 of 14 days left".

One clamp at the source covers all three consumers, which is why it belongs here and not in the
client: `LicenseBanner.svelte:22-24` (`{days} of {TRIAL_DAYS}`), `SettingsLicenseTab`'s pill via
`license-ui.ts`, and `src/cli/license.ts:64`.

**2. A licensed device whose update window has ended is told "You're running the latest version."**
`show_up_to_date_dialog` (`src-tauri/src/lib.rs:2242-2255`) has one arm. H-a covered what the device
can *see by itself* — `WithheldReason::{StatusUnavailable, NoEntitlement}` via
`show_update_withheld_dialog` — and its `Licensed` docblock deliberately keeps routing to the Worker
even with a locally-expired window, so the lapsed-entitlement 204 arrives as `Ok(None)` and falls
into the up-to-date arm. H-b's spec hands this case over in writing ("license UX copy … belongs to
H-c"). The local `update_window_current` is already fetched on that path and already used, for a
`log::warn!` in `resolve_update_route` — it reaches the log and not the screen. `SettingsLicenseTab`
already carries the equivalent warning (`data-testid="license-update-window-ended"`); the dialog is
the surface that still lies.

## Fix

**Server (`src/server/license/license-state.ts`), the trial arm:**

- `const rawDays = Math.ceil((expiresAt - nowMs) / 86_400_000);` then
  `const daysRemaining = Math.min(TRIAL_DAYS, Math.max(0, rawDays));` — add `TRIAL_DAYS` to the
  existing `./paths.js` import (it is re-exported there beside `TRIAL_MS`).
- `if (rawDays > TRIAL_DAYS) warnOnce("trial:days-clamp", …)` — the issue asks for the log-once, and
  `warnOnce` (`:31`) is the file's own two-arg helper.
- **Display only.** `nowMs < expiresAt` is untouched: a backwards clock still lengthens the trial,
  which is ADR-040 §3's deliberately soft clock. Say so in the comment so the next reader does not
  "finish" this by hardening the gate — that is a different decision and not this issue's.

**Rust (`src-tauri/src/lib.rs`), display-only, four small edits:**

- New pure `fn local_window_ended(route: &UpdateRoute, probe: Option<&LicenseStatusResponse>) -> bool`
  — literally the conjunction `resolve_update_route` already evaluates for its `log::warn!`
  (`matches!(route, UpdateRoute::Licensed(_)) && !probe.is_some_and(|p| p.update_window_current)`).
  Hoist it, use it for both the existing log line and the new return value; **no new probe, no new
  request.** H-a's `update_route` is the precedent for a pure, `cargo test`-reachable classifier.
- `resolve_update_route` returns `(UpdateRoute, bool)`. Because it early-returns `Public` on an empty
  `LICENSE_UPDATE_ENDPOINT` **before probing**, a dark build gets `false` with zero new I/O — that
  early return is the byte-identity argument, unchanged from H-a.
- `UpdateOutcome::Serve(Updater)` becomes the struct variant `Serve { updater, local_window_ended }`.
  Two match sites: `check_for_update:2565` binds both; `install_update:2656` takes
  `Serve { updater, .. }` (a served update is not a no-update, so the flag is irrelevant there).
- `show_up_to_date_dialog(app, window_ended)` renders a pure
  `fn up_to_date_copy(window_ended: bool, version: &str) -> (&'static str, String)`:
  - `false` → **byte-identical to today**: title `"No Updates Available"`, body
    `"You're running the latest version of Tandem (v{version})."`, `MessageDialogKind::Info`.
  - `true` → title `"Update Window Ended"`, `MessageDialogKind::Warning` (matching the withheld
    dialog and `SettingsLicenseTab`'s `.license-warning`), body: the window has ended, **v{version}
    keeps running forever**, and *"To receive new releases again, renew from Settings → License."*
    **No URL literal in Rust** — `TANDEM_PURCHASE_URL` lives once in `src/shared/constants.ts` and is
    already rendered as a link in that tab; a native message dialog cannot hold a link anyway, so
    pointing at the tab reuses the tracked copy instead of minting a drifting second one.

**`tests/docs/license-flip-consts.test.ts:320` must be updated in the same commit.** It counts the
literal `show_up_to_date_dialog(app)` in the compacted crate and expects exactly 1; the new spelling
is `show_up_to_date_dialog(app,window_ended)`. Change the literal, keep the count and the message —
the guarantee ("shown only for a real `Ok(None)`, never on the withheld arm") is unchanged, and the
new literal still cannot be satisfied by the *definition* line, which is what made the original
spelling discriminating.

## Tests

**`tests/server/license-state.test.ts`** (extend; all with `gateEnabled: true`, injected `now`):

1. `firstRunAt = now + 12h` → `daysRemaining === 14`. Kills "H-a's two-sided bound made the clamp
   unreachable" — this body is *usable*, so the repair never touches it.
2. Clock moved back: resolve with `now = firstRunAt - 10d` → `status === "trial"` and
   `daysRemaining === 14`. Kills a clamp applied only to the stored path.
3. Anti-over-clamp: `firstRunAt = now - 13.5d` → `daysRemaining === 1`; `firstRunAt = now` → `14`.
   Kills `Math.min(TRIAL_DAYS, …)` written as an unconditional `TRIAL_DAYS`, and kills a clamp that
   swallowed the existing `Math.max(0, …)`.
4. The over-range case warns, and warns **once** across two resolves (`warnOnce` is module-keyed, so
   isolate with `vi.resetModules()` + dynamic import, the pattern the file already uses for the
   `verify:` and `trial:repair` warnings).

**`src-tauri/src/lib.rs` `#[cfg(test)]`** (beside H-a's `update_route` cases):

5. `up_to_date_copy(false, "9.9.9")` equals the two exact strings above. This is the byte-identity
   pin: any rewording of the healthy dialog fails here.
6. `up_to_date_copy(true, "9.9.9")`: title `!= "No Updates Available"`, body contains "update window
   has ended", body does **not** contain "latest version". Kills the one-string-for-both
   implementation that #1786's Settings comment describes as the current failure.
7. `local_window_ended` truth table: `Licensed` + `update_window_current: false` → true; `Licensed` +
   `true` → false; **`Public` + `update_window_current: false` → false**; `NoUpdates(_)` → false. The
   `Public` row is the discriminating one — a **trial** device reports
   `update_window_current: false` (`license-state.ts`, trial arm), so a flag keyed on the probe alone
   tells every evaluator their update window ended.
8. `probe: None` → false (a dead sidecar is `StatusUnavailable`, already its own dialog).

**Not a new test file, and no new scanner.** `license-flip-consts.test.ts` gets one literal updated,
nothing added.

## Not in scope

Hardening the trial clock against a backwards system clock (ADR-040 §3 makes it soft on purpose).
Any Worker-side detector for the lapsed entitlement — that is #1786/H-b, and the two meet only at
this dialog. `install_update`'s path (it has an update in hand). A date in the dialog: the licensed
arm's `expiresAt` is nested under `license` on the wire and Rust's `LicenseStatusResponse` reads flat
fields only, so a date costs a new deserialize field for prose the Settings warning already omits.
