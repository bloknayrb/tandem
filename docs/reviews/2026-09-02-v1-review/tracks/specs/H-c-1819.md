## Problem

**1. `daysRemaining` is display-unclamped.** `license-state.ts:205` is `Math.max(0, Math.ceil(…))` — a
*lower* clamp only. Two routes exceed `TRIAL_DAYS`, and they differ:

- **Stored value — bounded by H-a, not closed.** `trialBodyIsUsable` (`:106-111`) accepts any
  `firstRunAt` up to `nowMs + TRIAL_FUTURE_SLACK_MS` (24 h), so a `firstRunAt` half a day ahead is
  "usable", `ensureTrialStarted` leaves it, and the banner reads **"15 of 14 days left"**. H-a took
  this from unbounded to `TRIAL_DAYS + 1`. Not dead code.
- **In-session clock change — fully open.** `ensureTrialStarted` runs **once**, at startup
  (`src/server/index.ts:382-385`); `resolveLicenseState` re-reads per dispatch on a live `Date.now()`,
  so a clock moved back after boot yields `14 + N` until restart — the issue's "24 of 14 days left".

One clamp at the source covers all three consumers (`LicenseBanner.svelte:22-24`, the Settings pill via
`license-ui.ts`, `src/cli/license.ts:64`).

**2. A licensed device whose update window has ended is told "You're running the latest version."**
`show_up_to_date_dialog` (`lib.rs:2242-2255`) has one arm, and a lapsed-entitlement 204 arrives as
`Ok(None)` and lands in it. The local `update_window_current` is already fetched and already used on
that path — for a `log::warn!` in `resolve_update_route` (`:2491-2503`). It reaches the log, not the
screen. **The flag is the LOCAL view and the copy must not pretend otherwise:** after a KV-only renewal
a device the Worker still considers entitled, holding a stale local `expiresAt`, would be told its
window ended. So the copy reports **the device's own view, not a verdict**; the authoritative detector
stays #1786/H-b's Worker `reason`, invisible through `Ok(None)`. `SettingsLicenseTab`'s
`license-update-window-ended` line already claims the same thing from the same field.

## Fix

**Server — `src/server/license/license-state.ts`, the trial arm:**

- `const rawDays = Math.ceil((expiresAt - nowMs) / 86_400_000);` then
  `const daysRemaining = Math.min(TRIAL_DAYS, Math.max(0, rawDays));` (`TRIAL_DAYS` joins the existing
  `./paths.js` import), plus `if (rawDays > TRIAL_DAYS) warnOnce("trial:days-clamp", …)` — the issue
  asks for the log-once and `warnOnce` (`:31`) is the file's own helper.
- **Display only.** `nowMs < expiresAt` is untouched: a backwards clock still lengthens the trial,
  which is ADR-040 §3's deliberately soft clock. Say so in the comment, with one sentence recording
  that the `warnOnce` is reachable on a shipped dark build — `runLicenseStatus`
  (`src/cli/license.ts:105-112`) and `darkInstallInfo()` (`src/server/mcp/routes/license.ts:62-72`,
  every dark `GET /api/license/status`) both force `gateEnabled: true` — and harmless, since it writes
  to `console.error` (stderr, Critical Rule 3) once per process.

**Rust — `src-tauri/src/lib.rs`, display-only:**

- Pure `fn local_window_ended(route: &UpdateRoute, probe: Option<&LicenseStatusResponse>) -> bool` —
  the conjunction `resolve_update_route` already evaluates for its `log::warn!`, hoisted. **No new
  probe, no new request.** Docblock: this is the LOCAL view, a KV-only renewal can make it disagree
  with the Worker, and that is accepted because `SettingsLicenseTab` already asserts the same thing
  from the same field.
- `resolve_update_route` returns `(UpdateRoute, bool)`. **Bind the flag once** —
  `let local_window_ended = local_window_ended(&route, probe.as_ref());` — and use that binding for
  both the existing `if` around the `log::warn!` and the returned tuple, so log and dialog cannot
  diverge. The empty-endpoint early return is `(UpdateRoute::Public, false)` *before* probing: the
  byte-identity argument, unchanged from H-a.
- `UpdateOutcome::Serve(Updater)` becomes `Serve { updater: tauri_plugin_updater::Updater,
  local_window_ended: bool }`. Four sites: `:2543` and `:2551` end `.map(UpdateOutcome::Serve)` — a
  struct variant has no function-style constructor — and become `.map(|updater| UpdateOutcome::Serve
  { updater, local_window_ended })`; `:2565` binds both; `:2656` takes `Serve { updater, .. }`.
- **`show_up_to_date_dialog` keeps its signature and body byte-identical.** The branch goes in
  `check_for_update`'s `Ok(None)` arm (`:2594-2599`): `if local_window_ended {
  show_update_window_ended_dialog(app) } else { show_up_to_date_dialog(app) }`. That is what lets
  `license-flip-consts.test.ts:320-327` stand **unedited** — its `show_up_to_date_dialog(app)` count
  is still 1 and still catches the withheld-arm mutation its docblock names. Widening the signature
  would force a respelling of that literal, and the spellings on offer either go stale or stop
  matching a lazily-added `…(app, false)` arm: a pin disarmed in the commit claiming to preserve it.
- New `fn show_update_window_ended_dialog(app: &tauri::AppHandle)` mirroring
  `show_update_withheld_dialog`: `MessageDialogKind::Warning`, `attach_main_window_or_warn`, strings
  from a pure `fn window_ended_copy(version: &str) -> (&'static str, String)` so `cargo test` reaches
  the copy. Title `"Update Window Ended"`; body says **this device's license shows an update window
  that has ended**, so new releases may no longer be offered here; **v{version} keeps running
  forever**; *"To receive new releases again, renew from Settings → License."* **No URL literal in
  Rust** — `TANDEM_PURCHASE_URL` lives once in `src/shared/constants.ts` and a native dialog holds no
  link.
- **Kill the forward references to this issue.** `lib.rs:2306` and `:2380-2383` both say "#1819 owns
  the final wording"; closing #1819 would strand them. The two `WithheldReason::dialog_copy` pairs
  **stand as written** — one names a licensing state, the other a local server that is not answering,
  the invariant those docblocks say must survive, and neither overlaps the new copy. Edit the
  **docblocks only**, to state the decision ("Wording settled in #1819; what must survive any later
  rewrite is that the two arms say different things"). Do not reword the strings.
