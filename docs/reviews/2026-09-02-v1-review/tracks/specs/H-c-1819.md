(`resolveLicenseState` takes `gateEnabled` as a **dep**, so the armed path needs no env var) plus
`cargo test` for the Rust half. **Do NOT start `experiments/server-probes/run.sh`** — it binds
4918/4919 and H-b holds that pair for the duration of this wave.

**The gate stays dark.** `LICENSE_GATE_ENABLED` stays `false`, `LICENSE_UPDATE_ENDPOINT` stays `""`;
`tests/docs/license-flip-consts.test.ts` (H-a) turns `check` red on a half-flip.

**One identifier for one concept: `local_window_ended`.** The pure fn, the `Serve` field, the
`show_up_to_date_dialog` parameter and the two pinned call literals all spell it that way. Do not
reintroduce a second spelling.

**The dialog pin is argument-AGNOSTIC, and that is deliberate.** A pin spelled
`show_up_to_date_dialog(app,local_window_ended)` would be satisfied only by the *one* call that
happens to pass a variable of that name — so a lazy withheld arm, which must pass a second argument
to compile and whose obvious spelling is `show_up_to_date_dialog(app, false)`, would **not** be
counted, the count would stay 1, and the test would stay green while shipping exactly the mutation
its docblock says it catches. The pin is therefore the prefix `show_up_to_date_dialog(app,` — which
counts every call regardless of the second argument and still cannot be satisfied by the definition
line, which compacts to `show_up_to_date_dialog(app:&tauri::AppHandle,local_window_ended:bool)`
(`(app:` ≠ `(app,`). Round 2 caught this: the round-1 spelling disarmed the assertion in the same
commit that claimed to preserve it.

## Problem

**1. `daysRemaining` is display-unclamped, and H-a narrowed the stored route without closing it.**
`license-state.ts` computes `Math.max(0, Math.ceil((expiresAt - nowMs) / 86_400_000))` — a *lower*
clamp only. Two routes reach a value above `TRIAL_DAYS`, and they are not the same route:

- **Stored value, still live but now bounded.** H-a's `trialBodyIsUsable` accepts any `firstRunAt`
  up to `nowMs + TRIAL_FUTURE_SLACK_MS` (24 h), so a `firstRunAt` half a day in the future is
  "usable", `ensureTrialStarted` leaves it alone, and the banner reads **"15 of 14 days left"**.
  H-a took this from unbounded to `TRIAL_DAYS + 1`; it did not make it unreachable. Do not describe
  the clamp as dead code for stored values.
- **In-session clock change, fully open.** `ensureTrialStarted` runs **once**, at startup
  (`src/server/index.ts:382-385`, both transports). `resolveLicenseState` re-reads per dispatch with
  a live `Date.now()`. A clock moved backwards *after* boot yields `14 + N` with no repair until the
  next restart — the issue's own "24 of 14 days left".

One clamp at the source covers all three consumers, which is why it belongs here and not in the
client: `LicenseBanner.svelte:22-24` (`{days} of {TRIAL_DAYS}`), `SettingsLicenseTab`'s pill via
`license-ui.ts`, and `src/cli/license.ts:64`.

**2. A licensed device whose update window has ended is told "You're running the latest version."**
`show_up_to_date_dialog` (`src-tauri/src/lib.rs:2242-2255`) has one arm. H-a covered what the device
can *see by itself* — `WithheldReason::{StatusUnavailable, NoEntitlement}` via
`show_update_withheld_dialog` — and its `Licensed` docblock deliberately keeps routing to the Worker
even with a locally-expired window, so the lapsed-entitlement 204 arrives as `Ok(None)` and falls
into the up-to-date arm. H-b's spec hands this case over in writing ("license UX copy … belongs to
H-c"). The local `update_window_current` is already fetched on that path and already used, for a
`log::warn!` in `resolve_update_route` — it reaches the log and not the screen. `SettingsLicenseTab`
already carries the equivalent warning (`data-testid="license-update-window-ended"`); the dialog is
the surface that still lies.

**The new flag is the LOCAL view, and the copy must not pretend otherwise.** `UpdateRoute::Licensed`'s
docblock (`lib.rs:2410-2415`) says the Worker's KV is the authority and that a client short-circuiting
on its own copy of the window turns the Worker's `expired` branch into dead code. This spec does not
short-circuit anything — routing is untouched — but the flag it reads *is* that local copy, and
`updater.check()` answers `Ok(None)` identically for "the Worker withheld as expired" and "there is
genuinely nothing newer". A device the Worker still considers entitled after a KV-only renewal,
sitting on the current version with a stale local `expiresAt`, would be told its window ended. So the
**copy reports the device's own view rather than a verdict** (see Fix), and the authoritative
detector remains #1786/H-b's Worker `reason`, which this dialog cannot see through `Ok(None)`.
`SettingsLicenseTab`'s `license-update-window-ended` line already makes the same claim from the same
local field, so the two surfaces stay self-consistent.

## Fix

**Server (`src/server/license/license-state.ts`), the trial arm:**

- `const rawDays = Math.ceil((expiresAt - nowMs) / 86_400_000);` then
  `const daysRemaining = Math.min(TRIAL_DAYS, Math.max(0, rawDays));` — add `TRIAL_DAYS` to the
  existing `./paths.js` import (it is re-exported there beside `TRIAL_MS`).
- `if (rawDays > TRIAL_DAYS) warnOnce("trial:days-clamp", …)` — the issue asks for the log-once, and
  `warnOnce` (`:31`) is the file's own two-arg helper.
- **Display only.** `nowMs < expiresAt` is untouched: a backwards clock still lengthens the trial,
  which is ADR-040 §3's deliberately soft clock. Say so in the comment so the next reader does not
  "finish" this by hardening the gate — that is a different decision and not this issue's.
- **Reachability note for the reviewer, not a regression — and it is TWO paths, not one.** Both force
  `gateEnabled: true` *regardless of the build flag*, so the trial arm — and therefore this new
  `warnOnce` — is reachable on a shipped dark build with a skewed clock:
  - `runLicenseStatus` (`src/cli/license.ts:105-112`) — any `tandem license` invocation.
  - **`darkInstallInfo()` (`src/server/mcp/routes/license.ts:62-72`)**, called from
    `toLicenseStatusWire`'s dark arm and from `scrubForNonLoopback` (`:88-91`), i.e. on **every dark
    build's `GET /api/license/status` poll**. With no `license.json` that resolution falls straight
    into the trial arm (`license-state.ts:201-217`) where the clamp and the `warnOnce` live. A
    reviewer who reads only the CLI half will conclude the warn cannot fire in a running dark server;
    it can, so name both in the code comment.

  This is harmless and inside Critical Rule 3: `warnOnce` writes via `console.error`, so it goes to
  stderr and does not interleave with the command's `console.log` output on stdout — and it is
  **once per process**, so the dark build's byte-identity constraint is satisfied at the level that
  matters (one stderr line on a skewed clock, not a per-poll flood). Record both paths in the code
  comment so a reviewer does not read it as arming something in the dark build.

**Rust (`src-tauri/src/lib.rs`), display-only:**

- New pure `fn local_window_ended(route: &UpdateRoute, probe: Option<&LicenseStatusResponse>) -> bool`
  — literally the conjunction `resolve_update_route` already evaluates for its `log::warn!`
  (`matches!(route, UpdateRoute::Licensed(_)) && !probe.is_some_and(|p| p.update_window_current)`).
  Hoist it, use it for both the existing log line and the new return value; **no new probe, no new
  request.** H-a's `update_route` is the precedent for a pure, `cargo test`-reachable classifier. Its
  docblock records that it is the LOCAL view only, that it can disagree with the Worker after a
  KV-only renewal, and that this is accepted because `SettingsLicenseTab`'s
  `license-update-window-ended` line already asserts the same thing from the same field.
- `resolve_update_route` returns `(UpdateRoute, bool)`, and **the `bool` must be produced by calling
  `local_window_ended(&route, probe.as_ref())`** — not by re-inlining the conjunction and not by a
  literal. Because the fn early-returns `Public` on an empty `LICENSE_UPDATE_ENDPOINT` **before
  probing**, a dark build gets `false` with zero new I/O — that early return is the byte-identity
  argument, unchanged from H-a; spell that arm `(UpdateRoute::Public, false)`.
  **The producer needs its own pin** (third assertion below): `resolve_update_route` takes an
  `AppHandle` and is unreachable from `cargo test`, so a lazy body that returns `(route, false)`
  without ever calling `local_window_ended` compiles, passes tests 5–8 (which exercise only the pure
  fns), warns nothing (no clippy step, no `deny(warnings)`) — and ships #1819 half 2 as green. That
  is the same silent-starvation shape this spec guards on the consumer side; the producer side needs
  the same treatment.
- `UpdateOutcome::Serve(Updater)` becomes the struct variant
  `Serve { updater: tauri_plugin_updater::Updater, local_window_ended: bool }`. **Four sites, not
  two** — the two *construction* sites are the ones a struct variant breaks, because a struct variant
  has no function-style constructor and `.map(UpdateOutcome::Serve)` is exactly that:
  - `lib.rs:2543` (the `Licensed` arm) and `lib.rs:2551` (the `Public` arm) both end
    `.map(UpdateOutcome::Serve)` and become
    `.map(|updater| UpdateOutcome::Serve { updater, local_window_ended })`.
  - `check_for_update:2565` binds both fields; `install_update:2656` takes `Serve { updater, .. }`
    (a served update is not a no-update, so the flag is irrelevant there).
- `show_up_to_date_dialog(app, local_window_ended)` renders a pure
  `fn up_to_date_copy(local_window_ended: bool, version: &str) -> (&'static str, String)`:
  - `false` → **byte-identical to today**: title `"No Updates Available"`, body
    `"You're running the latest version of Tandem (v{version})."`, `MessageDialogKind::Info`.
  - `true` → title `"Update Window Ended"`, body phrased as **this device's own
    view**, not a verdict: this device's license shows an update window that has ended, so new
    releases may no longer be offered here; **v{version} keeps running forever**; and *"To receive
    new releases again, renew from Settings → License."*
    **No URL literal in Rust** — `TANDEM_PURCHASE_URL` lives once in `src/shared/constants.ts` and is
    already rendered as a link in that tab; a native message dialog cannot hold a link anyway, so
    pointing at the tab reuses the tracked copy instead of minting a drifting second one.
  - **The dialog KIND is chosen inside `show_up_to_date_dialog`, not returned by the pure fn**, and
    is therefore a **hand-check, not a cargo assertion**: `if local_window_ended {
    MessageDialogKind::Warning } else { MessageDialogKind::Info }`, matching the withheld dialog and
    `SettingsLicenseTab`'s `.license-warning`. `up_to_date_copy` deliberately stays
    `-> (&'static str, String)`: widening it to carry the kind buys one assertion over a one-line
    mapping of a bool the fn already receives, at the cost of a third tuple element every test row
    must then thread. It is out of Done-when for that reason — do not read its absence there as the
    kind being optional.

- **`WithheldReason::dialog_copy` — settle the copy and kill the forward reference.** Two docblocks
  in `src-tauri/src/lib.rs` currently address this issue by number: `show_update_withheld_dialog`
  (`:2306`, "#1819 owns the final wording; the misattribution is not a wording question") and
  `dialog_copy` (`:2380-2383`, "#1819 owns the final wording; what is NOT wording … is that the two
  arms say different things"). H-a wrote those as a hand-off **to this issue**, so closing #1819
  without discharging them leaves the crate carrying a forward reference to a closed issue and the
  withheld copy with no owner. Review both `(title, body)` pairs as part of this issue. **They stand
  as written** — `StatusUnavailable` names a local server that is not answering and offers Settings →
  Restart server; `NoEntitlement` names a licensing state and says Tandem keeps running — which is
  exactly the invariant the docblock says must survive, and neither overlaps the new
  `up_to_date_copy` arms. So the edit is to the **docblocks only**: replace "#1819 owns the final
  wording" with a statement of the decision (e.g. "Wording settled in #1819; what must survive any
  later rewrite is that the two arms say different things — one is a licensing state, the other is a
  local server that is not answering"), in both places, in this commit. Do not reword the strings
  themselves; `tests/docs/license-flip-consts.test.ts` does not pin them, so a drive-by rewording
  would be unreviewed and untested.

**`tests/docs/license-flip-consts.test.ts` gets one literal RESPELLED and TWO assertions added, in
the same commit.** All three halves are required, and the two additions are the load-bearing ones —

- **Respell the existing `:320` count as the argument-agnostic prefix, in the two-form shape.**
  Today it counts `show_up_to_date_dialog(app)` and asserts 1. Replace it with
  `countOccurrences(COMPACT_RUST_CODE, "show_up_to_date_dialog(app,") +
  countOccurrences(COMPACT_RUST_CODE, "show_up_to_date_dialog(&app,")`, still `.toBe(1)`, keeping
  the message. Two things about that shape:
  - **Argument-agnostic is the point**, per the rule near the top of this spec: a pin spelled
    `show_up_to_date_dialog(app,local_window_ended)` would leave `show_up_to_date_dialog(app, false)`
    — the obvious spelling of a lazily-added withheld arm — uncounted, so the count would stay 1 and

    definition line (`show_up_to_date_dialog(app:&tauri…`, `(app:` ≠ `(app,`), so it stays
    discriminating.
  - **The `&app` form mirrors `show_update_withheld_dialog`'s pin (`:309-318`)**, which counts both
    because `install_update` holds an owned `AppHandle`. `show_up_to_date_dialog` has no
    `install_update`-side call today and must not grow one (a served update is not a no-update), so
    counting both forms is what makes "must not grow one" an assertion rather than a comment.
- **New assertion 1 — the consumer:**
  `expect(countOccurrences(COMPACT_RUST_CODE, "=up_to_date_copy(local_window_ended,")).toBe(1)`,
  sibling to `:309-318` and carrying the same kind of rationale sentence. The literal pins the

  `fn show_up_to_date_dialog(app, _local_window_ended) { …existing inline format!… }` plus an
  `up_to_date_copy` called only from `#[cfg(test)]` also passes everything. That green-suite outcome
  is #1786's silent starvation shipped verbatim.
- **New assertion 2 — the producer:**
  `expect(countOccurrences(COMPACT_RUST_CODE, "local_window_ended(&route,")).toBe(1)`. The
  definition compacts to `fnlocal_window_ended(route:&UpdateRoute,probe:Option<&LicenseStatusResponse>)->bool`,
  which does not contain `(&route,`, so the literal counts the `resolve_update_route` call site
  alone. Rationale sentence: `resolve_update_route` takes an `AppHandle` and is unreachable from
  `cargo test`, so nothing else can catch a body that returns `(route, false)` and never computes the
  flag — and that body *is* #1819 half 2.
- The file's own recorded mutation-check list (`:30-35`) names
  `Ok(UpdateOutcome::Withheld(_)) => show_up_to_date_dialog(app)`, the pre-change spelling. Update
  that line to the post-change spelling (`… => show_up_to_date_dialog(app, false)` ⇒ red) and add
  the two new mutations to the same list: `up_to_date_copy(false, version)` inside the dialog ⇒ red;
