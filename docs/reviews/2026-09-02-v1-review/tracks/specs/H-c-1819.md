## Problem

**1. `daysRemaining` is display-unclamped, and H-a narrowed the stored route without closing it.**
`license-state.ts` computes `Math.max(0, Math.ceil((expiresAt - nowMs) / 86_400_000))` — a *lower*
clamp only. Two routes reach a value above `TRIAL_DAYS`, and they are not the same route:

- **Stored value, still live but now bounded.** H-a's `trialBodyIsUsable` accepts any `firstRunAt`
  up to `nowMs + TRIAL_FUTURE_SLACK_MS` (24 h), so a `firstRunAt` half a day in the future is
  "usable", `ensureTrialStarted` leaves it alone, and the banner reads **"15 of 14 days left"**.
  H-a took this from unbounded to `TRIAL_DAYS + 1`; it did not make it unreachable. Do not describe
  the clamp as dead code for stored values.
- **In-session clock change, fully open.** `ensureTrialStarted` runs **once**, at startup
  (`src/server/index.ts:382-385`, both transports). `resolveLicenseState` re-reads per dispatch with
  a live `Date.now()`. A clock moved backwards *after* boot yields `14 + N` with no repair until the
  next restart — the issue's own "24 of 14 days left".

One clamp at the source covers all three consumers, which is why it belongs here and not in the
client: `LicenseBanner.svelte:22-24` (`{days} of {TRIAL_DAYS}`), `SettingsLicenseTab`'s pill via
`license-ui.ts`, and `src/cli/license.ts:64`.

**2. A licensed device whose update window has ended is told "You're running the latest version."**
`show_up_to_date_dialog` (`src-tauri/src/lib.rs:2242-2255`) has one arm. H-a covered what the device
can *see by itself* — `WithheldReason::{StatusUnavailable, NoEntitlement}` via
`show_update_withheld_dialog` — and its `Licensed` docblock deliberately keeps routing to the Worker
even with a locally-expired window, so the lapsed-entitlement 204 arrives as `Ok(None)` and falls
into the up-to-date arm. H-b's spec hands this case over in writing ("license UX copy … belongs to
H-c"). The local `update_window_current` is already fetched on that path and already used, for a
`log::warn!` in `resolve_update_route` — it reaches the log and not the screen. `SettingsLicenseTab`
already carries the equivalent warning (`data-testid="license-update-window-ended"`); the dialog is
the surface that still lies.

**The new flag is the LOCAL view, and the copy must not pretend otherwise.** `UpdateRoute::Licensed`'s
docblock (`lib.rs:2410-2415`) says the Worker's KV is the authority and that a client short-circuiting
on its own copy of the window turns the Worker's `expired` branch into dead code. This spec does not
short-circuit anything — routing is untouched — but the flag it reads *is* that local copy, and
`updater.check()` answers `Ok(None)` identically for "the Worker withheld as expired" and "there is
genuinely nothing newer". A device the Worker still considers entitled after a KV-only renewal,
sitting on the current version with a stale local `expiresAt`, would be told its window ended. So the
**copy reports the device's own view rather than a verdict** (see Fix), and the authoritative
detector remains #1786/H-b's Worker `reason`, which this dialog cannot see through `Ok(None)`.
`SettingsLicenseTab`'s `license-update-window-ended` line already makes the same claim from the same
local field, so the two surfaces stay self-consistent.

## Fix

**Server (`src/server/license/license-state.ts`), the trial arm:**

- `const rawDays = Math.ceil((expiresAt - nowMs) / 86_400_000);` then
  `const daysRemaining = Math.min(TRIAL_DAYS, Math.max(0, rawDays));` — add `TRIAL_DAYS` to the
  existing `./paths.js` import (it is re-exported there beside `TRIAL_MS`).
- `if (rawDays > TRIAL_DAYS) warnOnce("trial:days-clamp", …)` — the issue asks for the log-once, and
  `warnOnce` (`:31`) is the file's own two-arg helper.
- **Display only.** `nowMs < expiresAt` is untouched: a backwards clock still lengthens the trial,
  which is ADR-040 §3's deliberately soft clock. Say so in the comment so the next reader does not
  "finish" this by hardening the gate — that is a different decision and not this issue's.
- **Reachability note for the reviewer, not a regression.** `runLicenseStatus`
  (`src/cli/license.ts:105-112`) resolves with `gateEnabled: true` *regardless of the build flag*, so
  the trial arm — and therefore this new `warnOnce` — runs on any `tandem license` invocation,
  including on a shipped dark build with a skewed clock. That is harmless and inside Critical Rule 3:
  `warnOnce` writes via `console.error`, so it goes to stderr and does not interleave with the
  command's `console.log` output on stdout. Record this in the code comment so a reviewer does not
  read it as arming something in the dark build.

**Rust (`src-tauri/src/lib.rs`), display-only:**

- New pure `fn local_window_ended(route: &UpdateRoute, probe: Option<&LicenseStatusResponse>) -> bool`
  — literally the conjunction `resolve_update_route` already evaluates for its `log::warn!`
  (`matches!(route, UpdateRoute::Licensed(_)) && !probe.is_some_and(|p| p.update_window_current)`).
  Hoist it, use it for both the existing log line and the new return value; **no new probe, no new
  request.** H-a's `update_route` is the precedent for a pure, `cargo test`-reachable classifier. Its
  docblock records that it is the LOCAL view only, that it can disagree with the Worker after a
  KV-only renewal, and that this is accepted because `SettingsLicenseTab`'s
  `license-update-window-ended` line already asserts the same thing from the same field.
- `resolve_update_route` returns `(UpdateRoute, bool)`. Because it early-returns `Public` on an empty
  `LICENSE_UPDATE_ENDPOINT` **before probing**, a dark build gets `false` with zero new I/O — that
  early return is the byte-identity argument, unchanged from H-a.
- `UpdateOutcome::Serve(Updater)` becomes the struct variant
  `Serve { updater: tauri_plugin_updater::Updater, local_window_ended: bool }`. **Four sites, not
  two** — the two *construction* sites are the ones a struct variant breaks, because a struct variant
  has no function-style constructor and `.map(UpdateOutcome::Serve)` is exactly that:
  - `lib.rs:2543` (the `Licensed` arm) and `lib.rs:2551` (the `Public` arm) both end
    `.map(UpdateOutcome::Serve)` and become
    `.map(|updater| UpdateOutcome::Serve { updater, local_window_ended })`.
  - `check_for_update:2565` binds both fields; `install_update:2656` takes `Serve { updater, .. }`
    (a served update is not a no-update, so the flag is irrelevant there).
- `show_up_to_date_dialog(app, local_window_ended)` renders a pure
  `fn up_to_date_copy(local_window_ended: bool, version: &str) -> (&'static str, String)`:
  - `false` → **byte-identical to today**: title `"No Updates Available"`, body
    `"You're running the latest version of Tandem (v{version})."`, `MessageDialogKind::Info`.
  - `true` → title `"Update Window Ended"`, `MessageDialogKind::Warning` (matching the withheld
    dialog and `SettingsLicenseTab`'s `.license-warning`), body phrased as **this device's own
    view**, not a verdict: this device's license shows an update window that has ended, so new
    releases may no longer be offered here; **v{version} keeps running forever**; and *"To receive
    new releases again, renew from Settings → License."*
    **No URL literal in Rust** — `TANDEM_PURCHASE_URL` lives once in `src/shared/constants.ts` and is
    already rendered as a link in that tab; a native message dialog cannot hold a link anyway, so
    pointing at the tab reuses the tracked copy instead of minting a drifting second one.

**`tests/docs/license-flip-consts.test.ts` gets one literal updated AND one assertion added, in the
same commit.** Both halves are required and the second is the load-bearing one:

- The existing count at `:320` pins the literal `show_up_to_date_dialog(app)` at exactly 1; the new
  spelling is `show_up_to_date_dialog(app,local_window_ended)`. Change the literal, keep the count
  and the message — the guarantee ("shown only for a real `Ok(None)`, never on the withheld arm") is
  unchanged, and the new literal still cannot be satisfied by the *definition* line, which compacts
  to `show_up_to_date_dialog(app:&tauri::AppHandle,local_window_ended:bool)`.
- **New, sibling to `show_update_withheld_dialog is called from both withheld boundaries` (`:309-318`)
  and carrying the same kind of rationale sentence:**
  `expect(countOccurrences(COMPACT_RUST_CODE, "=up_to_date_copy(")).toBe(1)`. Without it, a lazy
  `fn show_up_to_date_dialog(app, _local_window_ended) { …existing inline format!… }` plus an
  `up_to_date_copy` called only from `#[cfg(test)]` **compiles and passes every other test in this
  spec**: there is no clippy step and no `deny(warnings)` anywhere in `.github/workflows/*.yml` or in
  the crate (grep returns nothing), so the dead-code and unused-variable warnings fail nothing, and
  `COMPACT_RUST_CODE` strips `#[cfg(test)]` bodies (`:120-124,160`) so the test-only calls inflate no
  count. That green-suite outcome is #1786's silent starvation shipped verbatim; this assertion is
  the only thing that catches it.
- The file's own recorded mutation-check list (`:30-35`) names
  `Ok(UpdateOutcome::Withheld(_)) => show_up_to_date_dialog(app)`, the pre-change spelling. Update
  that line alongside the `:320` literal so the file's record matches the pin it now carries.

## Tests

**`tests/server/license-state.test.ts`** (extend; all with `gateEnabled: true`, injected `now`):

1. **The stored route is still live, demonstrated rather than asserted.** Write a `trial.json` whose
   `firstRunAt` is `now + 12h` into a named temp `TANDEM_APP_DATA_DIR`
   (`mktemp -d -t tandem-XXXXXX`), call `await ensureTrialStarted(dir, () => now, true)`, and assert
   the file's bytes are **unchanged** — `trialBodyIsUsable` accepts it, because `+12h` is under
   `TRIAL_FUTURE_SLACK_MS` (`license-state.ts:106,111`), so the H-a repair never touches it. *Then*
   `resolveLicenseState` and assert `daysRemaining === 14`. Only the un-repaired write is what kills
   "H-a's two-sided bound made the clamp unreachable" — resolving alone does not consult
   `trialBodyIsUsable` at all (`:201-205` reads `trialFirstRunAt` directly), so a resolve-only test
   is just a second raw-15 case and settles nothing.
2. Clock moved back: resolve with `now = firstRunAt - 10d` → `status === "trial"` and
   `daysRemaining === 14`. Kills a clamp applied only to the stored path.
3. Anti-over-clamp: `firstRunAt = now - 13.5d` → `daysRemaining === 1`; `firstRunAt = now` → `14`.
   Kills `Math.min(TRIAL_DAYS, …)` written as an unconditional `TRIAL_DAYS`, and kills a clamp that
   swallowed the existing `Math.max(0, …)`.
4. The over-range case warns, and warns **once** across two resolves. `loggedOnce`
   (`license-state.ts:30`) is module-global, so call **`_resetLicenseWarningsForTests()`**
   (exported at `license-state.ts:38` for exactly this) in a `beforeEach` — precedent
   `tests/server/license-activation-errors.test.ts:17,375` — and observe with
   `vi.spyOn(console, "error")`, since `warnOnce` writes to `console.error` (`:34`), not
   `console.warn`. **Tests 1 and 2 both trip the same `trial:days-clamp` key before this case runs**
   (raw 15 and raw 24), so without the reset this case observes zero warns and passes for the wrong
   reason. Do **not** reach for `vi.resetModules()` + dynamic import: this file imports only
   `{ describe, expect, it }` (`:5`) and has never used that shape, so a spec claiming it as "the
   pattern the file already uses" is describing a file that does not exist.

**`src-tauri/src/lib.rs` `#[cfg(test)]`** (beside H-a's `update_route` cases):

5. `up_to_date_copy(false, "9.9.9")` equals the two exact strings above. This is the byte-identity
   pin: any rewording of the healthy dialog fails here.
6. `up_to_date_copy(true, "9.9.9")`: `assert_eq!(title, "Update Window Ended")` (an equality, not a
   `!=` — `"No Updates Available!"` passes the inequality); body contains "update window"; body
   contains **"Settings"**, which is the Done-when's "points at renewal" and is otherwise asserted by
   nothing; body does **not** contain "latest version". Kills the one-string-for-both implementation
   that #1786's Settings comment describes as the current failure, and kills a body that names the
   problem without naming the remedy.
7. `local_window_ended` truth table: `Licensed` + `update_window_current: false` → true; `Licensed` +
   `true` → false; **`Public` + `update_window_current: false` → false**; `NoUpdates(_)` → false. The
   `Public` row is the discriminating one — a **trial** device reports
   `update_window_current: false` (`license-state.ts`, trial arm), so a flag keyed on the probe alone
   tells every evaluator their update window ended.
8. `probe: None` — **and name the route**, because the predicate is
   `matches!(route, Licensed(_)) && !probe.is_some_and(…)`:
   `local_window_ended(&UpdateRoute::Licensed("x".into()), None) == true`, with a comment noting the
   pair is unreachable from `resolve_update_route` (step 2 answers `NoUpdates(StatusUnavailable)`
   first, which is already its own dialog). Asserting `false` here would contradict the one-line
   implementation this spec specifies, and asserting it for a non-`Licensed` route merely duplicates
   test 7's `NoUpdates(_)` row.

**No new test file and no new scanner.** `license-flip-consts.test.ts` gets one literal updated, one
assertion added, and one docblock line corrected — enumerated in Fix.

## Done when

`daysRemaining` never exceeds `TRIAL_DAYS` on either route and logs once when it would have; the
manual "check for updates" dialog on a licensed device with a locally-ended window says so **and
points at Settings → License**, while every other device sees byte-identical copy; the flip-consts
literal is updated and the new `up_to_date_copy` call-site assertion is present; `npx vitest run`,
`npm run typecheck`, `cargo test` green; both flip consts unchanged.

## Not in scope

Hardening the trial clock against a backwards system clock (ADR-040 §3 makes it soft on purpose).
Any Worker-side detector for the lapsed entitlement — that is #1786/H-b, and the two meet only at
this dialog; the local flag here cannot substitute for it, per the Problem section's last paragraph.
`install_update`'s path (it has an update in hand). A date in the dialog: the licensed arm's
`expiresAt` is nested under `license` on the wire and Rust's `LicenseStatusResponse` reads flat
fields only, so a date costs a new deserialize field for prose the Settings warning already omits.
