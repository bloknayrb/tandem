# G10 — #1624 `tandem_checkInbox`'s `activity` drops `selection.timestamp`, so an old selection reads as current

Branch `fix/awareness-hygiene-selection-staleness-and-one-inbox-poll-context-1702`. Closes #1624 (both proposed items: surface the timestamp; document the field on the tool description, the output schema, `docs/mcp-tools.md` and the shipped skill). Not a v1-review ledger row — filed 2026-08-26 from the same live investigation as #1621/#1622/#1623 (`B-1622.md:3`); sweep wave 8 group G10. Probe: the issue's own payload (`cursor` ~450 chars from `selectedText`) reproduced as a vitest fixture. Implemented after #1702.

## Problem

`tandem_checkInbox` (`src/server/mcp/awareness.ts`, handler `:416-576`) reads `store.getUserAwareness()` (`document-store.ts:370-384`), slices `selectedText` from `Y_MAP_SELECTION`'s stored flat `from`/`to` (`:511-514`), and emits `activity: { isTyping, cursor, lastEdit, selectedText }` (`:567-572`). `selection.timestamp` is typed on the record and dropped. `cursor`/`lastEdit` come from `Y_MAP_ACTIVITY`, a different record with a different write trigger, so the two halves of one object have independent ages and only one is labelled.

**The issue's lifetime claim is wrong in two ways — measured, not repeated** (`src/client/editor/extensions/awareness.ts`, Plugin 2 `update()`, `:188-273`):

- `Y_MAP_SELECTION` is **not dwell-gated**. A non-empty selection is written after a **150 ms client debounce** (`:217-226`). The 1 s `SELECTION_DWELL` lives in `src/server/events/observers/awareness.ts:56-86` and fills only the chat-attachment buffer (`getBufferedSelection`), which `tandem_checkInbox` never reads. So "last dwelled selection" — the wording #1624 proposes — would document a gate this field does not have.
- It does **not** persist until the next selection. Any change to a collapsed ProseMirror selection (click, arrow key, typing) writes `{ from, to: from, timestamp }` **immediately** (`:194-205`), which the handler maps to `selectedText: null`.
- What it *does* survive: the editor losing focus (chat panel), switching tabs, closing the browser — no write on any of those (`destroy()` at `:275-279` only clears timers; nothing on the server clears it on disconnect). Server-side it is cleared only by `clearDocMaps` (`documents/populate.ts:316`, from `evictPartialDocState` and `clearAndReload`) and the watcher reload (`documents/watcher.ts:166-167`).

So the real stale window is "selected, then left the editor", and in the issue's payload the stale half is as likely `cursor`: it is written only when the document changes (`:232-272`; pinned by `activity-cursor-flat.test.ts` (5b)), so a selection made after the last edit sits ~450 chars from a `cursor` older than it. Neither field is wrong; the payload does not say which is newer. `selectionAt` beside `lastEdit` answers that. The fix below documents what the code does, not what the issue guessed.

## Fix

1. `awareness.ts` handler, beside `selectedText`: `const selectionAt = hasSelection && typeof selection!.timestamp === "number" ? selection!.timestamp : null;` and `activity: { isTyping, cursor, lastEdit, selectedText, selectionAt }`. Null exactly when `selectedText` is null — a collapsed record's timestamp is a caret move, not a selection's age. The `typeof` guard is because the MCP SDK validates structured output against the schema and fails the **whole** response on a mismatch (docblock on `InboxUserAction`); an `undefined` would take the inbox down, not just the field.
2. `src/server/mcp/output-schemas.ts` `checkInboxOutputShape.activity`: `selectedText: z.string().nullable().describe(...)` and `selectionAt: z.number().nullable().describe(...)`. Text: "The user's most recent non-empty selection in this document, sliced at poll time from its stored flat offsets (≤100 chars). Cleared when the caret collapses in the editor; NOT cleared when focus leaves the editor or the tab changes, so it is not necessarily what the user is looking at now." / "Epoch ms of the editor's last write of that selection (browser clock, like `lastEdit`); null when `selectedText` is null. Compare with `lastEdit` to tell which half of `activity` is newer." Additive; no exact-shape pin on `activity` exists (`mcp-output-schemas.test.ts`, `mcp-tool-integration.test.ts`, `wake-url-surfacing.test.ts` grepped).
3. Tool descriptions: `tandem_checkInbox` (`:406`) gains one sentence: "`activity.selectedText` is the user's most recent selection, not necessarily a current one — `activity.selectionAt` says when it was made." `tandem_getActivity` (`:352-354`) "use tandem_checkInbox's `activity.selectedText` for what the user has selected" → "…for the user's most recent selection (and `activity.selectionAt` for its age)". No test pins either description string (grepped `tests/` on `4f112aa4`); re-grep at implement time.
4. `docs/mcp-tools.md`: add `"selectionAt": null` to the Returns block (`:1101`); one Notes bullet after the `activity.cursor` bullet (`:1112`) stating the measured lifetime above (150 ms debounce, not the 1 s dwell; cleared on caret collapse; survives blur/tab switch/disconnect; `selectionAt` vs `lastEdit`); `:1071` "For what the user has selected" → "For the user's most recent selection". `:1051` names the coordinate system only — unchanged.
5. `skills/tandem/SKILL.md:84` "the current selection shows up under `activity.selectedText`" → "the user's most recent selection shows up under `activity.selectedText`, and `activity.selectionAt` says when it was made — it survives focus moving to chat or another tab, so it is not proof of what the user is looking at now". Bump frontmatter `version` to the next integer after `origin/master` (21 → 22 at `4f112aa4`; re-check at rebase), and update both literals in `tests/skill-instruction-contract.test.ts` — `:109` (`/^version:\s*21$/m`) and `:428` (`{ version, bodyHash }`) — in the same commit.
