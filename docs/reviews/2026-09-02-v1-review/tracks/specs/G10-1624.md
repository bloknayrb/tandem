Branch `fix/awareness-hygiene-selection-staleness-and-one-inbox-poll-context-1702`. **Refs #1624; does not close it** (carve-out #1991). The PR's `## Closes` list and `closes[]` contain #1702 only. Because #1624's symptom ("a twenty-minute-old selection reads as current") still occurs after any edit that moves the selection until #1991 lands, #1624 stays open. Sweep wave 8 group G10. Anchors were re-verified against `origin/master` `c1a4df93`: the touched files are unchanged since `4f112aa4`, and SKILL.md is `version: 21` with the stale sentence at `:84`.

## Problem

The `tandem_checkInbox` handler (`src/server/mcp/awareness.ts`) slices `selectedText` from `Y_MAP_SELECTION`'s stored `from`/`to` and emits `activity: { isTyping, cursor, lastEdit, selectedText }`. The record's `timestamp` is dropped. `cursor` and `lastEdit` come from a different record (`Y_MAP_ACTIVITY`), so the two halves of `activity` have independent ages, and only one of them is labelled. SKILL.md:84 calls `selectedText` "the current selection".

### What writes `Y_MAP_SELECTION`: measured, not repeated from the issue

Writer: `src/client/editor/extensions/awareness.ts`, Plugin 2 `update()` (`:188-273`). A scratch vitest probe was run on 2026-09-15 and deleted afterwards. It used happy-dom, fake timers and the `boundEditor` setup, and applied remote changes with `Y.applyUpdate` from a second `Y.Doc`.

| Event | Result |
|---|---|
| Non-empty selection | written after a 150 ms debounce, **not** the 1 s dwell |
| Collapse (click, arrow, typing) | `{from, to: from}` written immediately, so `selectedText` becomes null |
| Remote edit that shifts the selection (e.g. Claude's `tandem_edit` above it) | **re-written with a fresh `Date.now()`**. Probe: +20 min, then an insert before the selection moved `from` 31→33 and `timestamp` 1000150→2200150 |
| Remote deletion spanning the selection | collapsed write, so the selection is cleared |
| Editor blur (focus moves to chat) | no write |
| Clicking an annotation card (`useAnnotationReview.svelte.ts:811`) or chat anchor (`ChatPanel.svelte:199`) | `setTextSelection` over that range, then the same 150 ms write (read from code, not probed) |

The re-stamp happens because y-tiptap restores the relative selection after every remote change, and Plugin 2 has no `ySyncPluginKey` filter. That is #1991. The matching `lastEdit` re-stamp is #1918.

**The issue's premise is partly refuted.** The field is not dwell-gated, so "last dwelled selection" would describe a gate that does not exist. It does not persist until the next selection; it clears on collapse. And its timestamp is when the record was last written, not when the selection was made. The smallest change that still closes the gap is to surface the timestamp and state exactly those three facts. Tab switch, reload and disconnect were not measured through the real provider, so no surface says anything about them.

## Fix

Server and docs only; `src/client/**` is not changed.

1. **Handler.** Beside `selectedText`, add `const selectionAt = hasSelection && typeof selection!.timestamp === "number" ? selection!.timestamp : null;` and put `selectionAt` in `activity`. It is null exactly when `selectedText` is null. The `typeof` guard is needed because an `undefined` fails the SDK's structured-output validation for the whole response.
2. **`output-schemas.ts` `checkInboxOutputShape.activity`.**
   - `selectedText.describe("The most recent non-empty selection in the editor for this document, including one made by clicking an annotation card or chat anchor (≤100 chars). Cleared when the selection collapses, including by a remote edit that deletes it; not cleared when focus leaves the editor, so not necessarily what the user is looking at now.")`
   - `selectionAt: z.number().nullable().describe("Epoch ms when the editor last wrote the selection record; null when selectedText is null. Any document change that moves the selection re-stamps it, including your own edits (#1991), so a recent value does not prove the user just selected this; an old value does prove it is old.")`

   No exact-shape pin exists on `activity`; re-grep `tests/` at implement time.
3. **Tool descriptions** in `awareness.ts`.
   - `tandem_checkInbox`: add one sentence carrying the two caveats from Fix 2.
   - `tandem_getActivity`: "for what the user has selected" → "for the most recent selection (see `activity.selectionAt`)".
4. **`docs/mcp-tools.md`.**
   - Add `"selectionAt": null` to the `tandem_checkInbox` Returns block.
   - Add one Notes bullet stating the Fix 2 semantics: a 150 ms debounce, not the dwell; cleared on collapse or remote deletion; not cleared on blur; re-stamped by any edit that moves it, including Claude's (#1991).
   - Under `tandem_getActivity`, change "For what the user has selected" to "For the most recent selection".
5. **`skills/tandem/SKILL.md:84`.**
   - Replace "the current selection shows up under `activity.selectedText`" with "the most recent non-empty selection shows up under `activity.selectedText` (including one made by clicking an annotation card or chat anchor); it is not cleared when focus moves to chat. `activity.selectionAt` is when the editor last wrote it: any edit that moves the selection re-stamps it, including yours, so a recent value does not prove a recent selection, but an old one proves it is old."
   - Bump `version` to the next integer after `origin/master`: 21 → 22, re-checked at rebase.
   - In the same commit, update `tests/skill-instruction-contract.test.ts`: the `version` regex literal, the `{ version, bodyHash }` literal with a recomputed hash, and one bump-history sentence.
