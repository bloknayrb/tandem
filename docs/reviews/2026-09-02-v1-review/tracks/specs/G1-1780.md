# G1 — #1780 A never-signed-in Claude Code is not recognised; the user gets no sign-in guidance

Branch `fix/launcher-stdin-wake-delivery-and-the-logged-out-claude-code-dead-end-1866`. Closes #1780. Ledger: `docs/reviews/2026-09-02-v1-review/areas/product.md:18` (its `supervisor.ts:1205-1250` citation is stale). Probe: `scratchpad/probe-loggedout.cjs`, run 2026-09-15. It launched the real `claude` 2.1.272 on Windows 11 under `CLAUDE_STREAM_JSON_FLAGS` + `--session-id`, with `HOME`, `USERPROFILE`, `APPDATA`, `LOCALAPPDATA` and `CLAUDE_CONFIG_DIR` pointed at a fresh `mktemp -d -t tandem-XXXXXX` and every `CLAUDE*`/`ANTHROPIC*` variable removed. Bryan's real `~/.claude` was not read, moved or logged out of.

## Problem — the issue's premise is refuted, and the real failure is quieter

The review read the auth path from code and assumed an immediate exit, which would then be counted as a crash until the breaker trips. What was observed instead, with stdin held open as the supervisor holds it:

```
t+0.06 WRITE turn 1
t+2.45 {"type":"system","subtype":"init"}
t+2.54 {"type":"assistant", content:[{type:"text",text:"Not logged in · Please run /login"}]}
t+2.55 {"type":"result","subtype":"success","is_error":true,"result":"Not logged in · Please run /login","terminal_reason":"api_error","api_error_status":null}
t+7.55 WRITE turn 2 → identical init / assistant / result
t+40.06 stdin ended by the probe → EXIT code=1 signal=null
```

stderr was empty for the whole run. **The process does not exit while stdin is open.** It answers every turn with an error `result`. The exit (code 1) happens only after stdin ends, and an earlier run with a closed pipe (`printf | claude`) showed the same code-1 exit. Under the supervisor, then:

- the child stays alive and `status()` reports `running: true`;
- `useAiReadiness` shows the AI as ready, with no chip and no CTA;
- `result` clears the latch, so every later wake gets another `Not logged in` and nothing more.

Nothing on any surface says "sign in". `docs/troubleshooting.md:134-142` already describes this case, but its mechanism ("exits immediately… retries until the breaker trips") is wrong and it says Tandem "cannot yet tell them apart".

## Fix

**Classify on what was observed: the `result` envelope, not stderr or the exit code.** `src/server/launcher/supervisor.ts`:

- Module constant `const NOT_SIGNED_IN_RESULT = /\bnot logged in\b/i;`. Its docblock quotes the measured envelope, the CLI version and the date, and says an expired login was **not** measured and may read differently.
- `handleStdoutLine`: widen the parsed type with `result?: unknown`. In the `result` branch, after `clearLatch()` and **before** `flushPendingWake()`:

  ```ts
  if (parsed.is_error === true && typeof parsed.result === "string" && NOT_SIGNED_IN_RESULT.test(parsed.result)) {
    lastError = "needs-login";
    breakerTripped = true;
    console.error("[Launcher] Claude Code is not signed in — not retrying. Run `claude` in a terminal to sign in, then use Check again.");
    if (child === spawned) { try { spawned.kill("SIGTERM"); } catch { /* best-effort, as stopInternal */ } }
    return;
  }
  ```

  `breakerTripped` makes the exit handler's `scheduleRestart()` a no-op, so there is no retry. Returning before `flushPendingWake` stops a second doomed wake from being written. The kill is direct and does not go through `onStdinGone`, so it never counts toward G1-1868's delivery streak. Any owed wake crosses to the next spawn through teardown, as usual.
- `src/shared/launcher/contract.ts`: `LauncherErrorCode` gains `"needs-login"`, with a docblock sentence: the CLI is installed and answers, but is not signed in, and the remedy is to sign in and then re-check.

**Client. `AiChip` gains a member instead of reusing `restart`.** `src/client/hooks/useAiReadiness.svelte.ts`:

- `AiChip = "connect" | "setup" | "sign-in" | "restart" | null`, with a doc bullet for `sign-in`.
- `chip` derivation: `lastError === "needs-login" ? "sign-in"` beside the `cli-unusable` arm.
- `AI_CTA["sign-in"]` = `{ label: "Check Claude sign-in", title: "Claude Code isn't signed in. Run “claude” in a terminal and sign in, then click to check again.", ariaLabel: "Claude Code is not signed in. Check again after signing in.", action: "restart" }`. A relaunch is the re-check: `respawn` clears the breaker, and a still-signed-out CLI re-trips within about 3 s.

The `Record` makes `App.svelte` (addressed-AI notice) and `StatusBar.svelte` pick it up without edits. `src/client/components/EmptyState.svelte` needs an explicit `{:else if connected && aiChip === "sign-in"}` branch, because it switches on chip literals and would otherwise fall through to the positioning copy. The branch holds the sub line "Claude Code needs to be signed in. Open a terminal, run `claude`, and finish signing in." (with `claude` in `<code>`) and one button, `data-testid="empty-state-sign-in-recheck"` `data-ai-chip="sign-in"` "Check again", calling `onRestartClaude`. **Critical Rule 7:** this adds a testid, so regenerate `tests/design-system-impl/__snapshots__/testid-set.snap.txt` in the same commit. No selector is renamed or removed.

The new text: Tandem now detects a never-signed-in Claude Code, which stays running and answers "Not logged in", and shows **Check again**; the steps are to run `claude`, finish the login, then click Check again. The intro sentence "Two causes … Tandem cannot yet tell them apart" becomes one about the remaining restart cause. "An expired login" in the section's first paragraph stays among the unclassified causes, because it was not measured.
