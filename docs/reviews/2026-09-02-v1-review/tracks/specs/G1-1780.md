## The issue's premise is refuted by measurement

**How it was measured.** Both probes ran the real `claude` 2.1.272 on Windows 11 on 2026-09-15:
- Environment: `HOME`, `USERPROFILE`, `APPDATA`, `LOCALAPPDATA` and `CLAUDE_CONFIG_DIR` all pointed at a fresh `mktemp -d -t tandem-XXXXXX`, and every `CLAUDE*`/`ANTHROPIC*` variable was removed. Bryan's `~/.claude` was not read, moved or logged out of.
- Flags: `CLAUDE_STREAM_JSON_FLAGS` with stdin held open. The second probe also passed `--mcp-config` pointing at a logging MCP endpoint.

```
t+0.06  WRITE turn 1
t+2.45  {"type":"system","subtype":"init"}
t+2.55  {"type":"result","subtype":"success","is_error":true,"result":"Not logged in · Please run /login","terminal_reason":"api_error"}
t+7.55  WRITE turn 2 → identical init / result
t+40.06 stdin ended by the probe → EXIT code=1        (stderr empty throughout)
second probe: MCP initialize + GET /mcp stream open at spawn (fresh and --resume) before any turn;
KILL → EXIT code=null signal=SIGTERM, no DELETE; --resume of that session loads, is silent until
a turn is written, then answers the same "Not logged in" result.
```

**What that means.** The CLI does not exit while stdin is open. It answers every turn with an error `result`, so under the supervisor:
- it stays `running: true` and holds an MCP stream;
- the UI reports ready;
- each wake gets another "Not logged in" and nothing more.

It is never counted as a crash. The failure the issue describes is real, but quieter than described. `docs/troubleshooting.md:137` repeats the wrong mechanism.

## Fix

The classifier keys on the `result` envelope, because that is what was observed. It does not use stderr or the exit code. All of the following is in `supervisor.ts`.

- **`NOT_SIGNED_IN_RESULT`.** Add `const NOT_SIGNED_IN_RESULT = /^Not logged in\b/;`, anchored and case-sensitive. Its docblock quotes the envelope, the CLI version and the date. It also says an expired login was not measured, and that a mismatch fails soft to today's behaviour.
- **`loginRecheckOwed`.** Add a supervisor-level `let loginRecheckOwed = false;`.
  - The trip below sets it. Only a `result` that is not a sign-in result clears it. `stop()`, `stopInternal` and `respawn` do not touch it.
  - Why it is needed: Check again goes through `relaunch` → `respawn`. The SIGTERM kill keeps the saved session, because `shouldClearSession` (:294) needs a non-null exit code. So `buildPlan` resumes (:918). A resumed spawn writes no turn (:1161), and the CLI is silent until it receives one.
- **`handleStdoutLine`.** Widen the parsed type with `result?: unknown`. In the `result` branch (:1195), after `clearLatch()` and the G1-1867/G1-1868 resets, and before `flushPendingWake()`:
  ```ts
  if (parsed.is_error === true && typeof parsed.result === "string" && NOT_SIGNED_IN_RESULT.test(parsed.result)) {
    if (child === spawned) {
      lastError = "needs-login";
      breakerTripped = true;
      loginRecheckOwed = true;
      console.error("[Launcher] Claude Code is not signed in — not retrying. Run `claude` in a terminal to sign in, then use Check again.");
      try { spawned.kill("SIGTERM"); } catch { /* best-effort */ }
    }
    return;
  }
  if (child === spawned) loginRecheckOwed = false;
  ```
  - `breakerTripped` makes `scheduleRestart` return, so there is no retry.
  - Returning early skips the pending wake's doomed write.
  - The kill does not go through `onStdinGone`, so G1-1868's streak never counts it.
- **`spawnOnce`'s resumed branch** (:1161) becomes `else if (wakeOwedAcrossSpawns || loginRecheckOwed) { if (sendTurn(SUPERVISOR_WAKE_PROMPT)) wakeOwedAcrossSpawns = false; }`.
  - It writes one turn either way.
  - A fresh spawn's bootstrap turn is already the re-check.
  - This is the spawn's first write, so G1-1867's receipt check applies.
- **The saved session is kept, not cleared.** Clearing it is irreversible (#1268), and an expired login on a real conversation was not measured.
- **`contract.ts`.** `LauncherErrorCode` (:106) gains `"needs-login"`, meaning the CLI answers but is not signed in, and the remedy is to sign in and re-check.

**Client changes.**

- **`useAiReadiness.svelte.ts`**
  - `AiChip` (:207) gains `"sign-in"`.
  - The `chip` derivation (:729) maps `lastError === "needs-login"` to `"sign-in"`, next to the existing `cli-unusable` arm.
  - `AI_CTA["sign-in"]` is `{ label: "Check Claude sign-in", title: "Claude Code isn't signed in. Run “claude” in a terminal and sign in, then click to check again.", ariaLabel: "Claude Code is not signed in. Check again after signing in.", action: "restart" }`.
- **`EmptyState.svelte`** switches on chip literals, so it needs its own branch before `aiChip === "restart"` (:173): `{:else if connected && aiChip === "sign-in"}`.
  - The branch shows "Claude Code needs to be signed in. Open a terminal, run <code>claude</code>, and finish signing in."
  - It has one button, "Check again", with `data-testid="empty-state-sign-in-recheck"` and `data-ai-chip="sign-in"`, calling `onRestartClaude`.
  - Regenerate the testid snapshot in the same commit. The change only adds a testid; none is renamed.
- **Known limitation.** While the signed-out child is alive, its MCP stream keeps `state` at `ready` (measured). The chip shows once that stream closes after the kill. That close was read from `server.ts` (`res.once("close")` → `openStreams`) but not measured against a running Tandem, so the smoke row is what verifies it.
