# H-a — #1788 Armed license gate correctness: a blank `firstRunAt` is a perpetual trial, restricted mode is asymmetric, and no test ever exercises armed+restricted

Branch `fix/armed-license-gate-correctness-and-the-second-const-that-must-flip-with-the-first-1788`. Closes #1788. Ledger: `docs/reviews/2026-09-02-v1-review/areas/armed-license-gate.md:21-23`. Probe: `experiments/server-probes/run.sh` (scratch server on 4918/4919, `TANDEM_LICENSE_GATE=1`, isolated app-data dir) + `raw/gapfill-F.txt`.

**Nothing here flips.** `LICENSE_GATE_ENABLED` stays `false` in `tsup.config.ts`. Every change below is a no-op while the gate is dark: `resolveLicenseState` returns `{gateActive:false}` at `license-state.ts:72` *before* it reads `trial.json`, and `gatedTool` is `withErrorBoundary` plus a `licenseGate()` that returns `null` when the gate is inactive (`license-gate.ts:42`). Byte-identical while dark is a constraint on this PR, not something it relaxes.

## Problem

1. **`firstRunAt: ""` is a perpetual 14-day trial** — a real fail-open. `license-state.ts:129` reads `tf?.firstRunAt ? new Date(tf.firstRunAt).getTime() : nowMs`, so `""`, `null`, `0` and a missing key all take the *absent-file* branch on **every dispatch**, and `ensureTrialStarted` never rewrites the file (`flag: "wx"`, `:191`). A non-empty *unparseable* value fails the opposite way (NaN ⇒ restricted). Two directions for one file; decision 5 says the empty string is treated like the unparseable one.
2. **Restricted mode is asymmetric.** `tandem_resolveAnnotation` (`annotations.ts:525`) is on `withErrorBoundary`, so Claude can accept/dismiss while restricted; the human cannot, because accept/dismiss is a write to the document room's `Y.Map('annotations')` and Surface A marks document rooms read-only (`connection-gate.ts:17`). Decision F: restricted is symmetric read-only.
3. **The armed suite never exercises restricted.** `TANDEM_LICENSE_GATE=1 npx vitest run` is 10,140 green because no `trial.json` means a *fresh* trial, and every unit test injects `gateEnabled`/`LicenseState` itself. That is why (1) and (2) could both be true and nothing was red. This is the load-bearing deliverable; treat (1) and (2) as things it should have caught.

**Three facts re-verified against `master` @ `06403bec` (2026-09-10); none has drifted.**
- Decision F's "the other annotation mutators" is **a set of exactly one**: `tandem_comment`, `tandem_editAnnotation`, `tandem_annotationReply`, `tandem_removeAnnotation` are already `gated` in `TOOL_GATES`. The MCP half of F is one row.
- **There is no `/api` twin for resolve/accept/dismiss.** `src/shared/api-paths.ts` has `API_ANNOTATION_REPLY` and `API_REMOVE_ANNOTATION` and nothing else annotation-shaped; the browser accepts over Hocuspocus. Critical Rule 9's both-halves requirement is therefore satisfied **by construction**, not by an edit — stated in the doc because "no twin exists" and "twin exists and was forgotten" look identical from a grep.
- **Decision F's `/api/mode/release` clause is NOT implemented, deliberately.** `license-gate-api-coverage.test.ts` carries an `API_MODE_RELEASE` row added 2026-09-08 — *after* F — saying `ungated`, because mode lives in `CTRL_ROOM`, which Surface A never marks read-only: a restricted user can still toggle Solo→Tandem, so gating only the release strands their annotations behind a Held pill with reads still open. That is worse than what gating prevents, and the later review is the only one of the two that reasoned about the user afterwards. This PR keeps the row ungated and records the conflict; re-gating one row later is a one-line change, shipping a state a user cannot leave is not. **Bryan's call** — posted on #1788 (comment 5612504584), unanswered as of 2026-09-10.

## Fix

- **`src/server/license/license-state.ts:128-129`** — branch on the *file*, not on the value:
  `const firstRunAt = tf ? new Date(tf.firstRunAt).getTime() : nowMs;`
  A `trial.json` that exists is authoritative even when its `firstRunAt` is unusable. Measured coercions (`node -e`): `new Date("")` and `new Date(undefined)` ⇒ `NaN`; `new Date(null)` and `new Date(0)` ⇒ `0`. `NaN` makes `nowMs < expiresAt` false ⇒ restricted; `0` makes `expiresAt` = 1970-01-15 ⇒ restricted for any real clock. So all four falsy shapes reach restricted by two different routes — say so in the comment, because `null ⇒ 0` is the one a reader will get wrong. The absent-file branch (day 0) is unchanged, which is what keeps `ensureTrialStarted`'s soft clock (ADR-040 §3) intact. Unparseable *JSON* also stays day-0: `readJson` returns `null` for both, and separating them needs a `stat` the issue does not ask for — see Not in scope.
- **`src/server/mcp/annotations.ts:525`** — `withErrorBoundary("tandem_resolveAnnotation", …)` → `gatedTool("tandem_resolveAnnotation", …)`. `gatedTool` is already imported (`:33`). No handler-body change: the gate runs before the handler, so every `LifecycleResult` arm is untouched.
- **`tests/helpers/tool-gates.ts` (new)** — move `TOOL_GATES` (the `ToolGate` type, the list, and the two list-scoped rationale blocks) out of `license-gate-coverage.test.ts` verbatim, then flip the one row. The move is what lets the new armed test drive the same list instead of a second copy, and it is the same "one binding, not a comment saying the copies match" rationale `tests/helpers/mcp-source.ts` already carries. `license-gate-coverage.test.ts` imports `TOOL_GATES` and is otherwise unchanged. Do **not** import the list from the `.test.ts` file — that would register its `describe`s twice.
  The flipped row's `why` **replaces**, never deletes, the old justification (the head-of-list comment says the `why` IS the review):
  `{ name: "tandem_resolveAnnotation", gate: "gated", why: "decision F (#1788, #1827): restricted is SYMMETRIC read-only. Accept/dismiss is a write to the document room's annotation map, which Surface A already refuses from the browser when restricted — leaving the MCP twin ungated let Claude triage a document its own user cannot. Supersedes the earlier 'only flips annotation status, gating it would needlessly block triage', which weighed the write and not the asymmetry. No /api twin exists (api-paths.ts has reply + remove only), so Critical Rule 9's second half is satisfied by construction" }`
- **`tests/server/license-gate-api-coverage.test.ts`** — append one sentence to the `API_MODE_RELEASE` `why`, keeping `ungated`: decision F asked for the opposite; the 2026-09-08 reasoning won because `CTRL_ROOM` is exempt from Surface A, so gating only the release traps a restricted user in Held; open for Bryan on #1788. No row moves.

A decision recorded as taken and silently half-done is the failure mode `docs/plans/2026-09-06-open-issues-sweep.md` exists to prevent.

## Tests

**`tests/server/license-armed-restricted.test.ts` (new)** — the fixture #1788 item 4 asks for, and the only test in the repo where `GATE_ENABLED` is really true.

- Arm at module-evaluation time: a `vi.hoisted(() => …)` block (`tests/cli/doctor-path-safety.test.ts` is the precedent) that `mkdtemp`s a fixture dir, writes `trial.json` with `firstRunAt` 30 days old, and sets `process.env.TANDEM_LICENSE_GATE = "1"` **and** `TANDEM_APP_DATA_DIR`. Hoisted, because `GATE_ENABLED` is a module-level const read once at import (`gate-flag.ts:33`); a `beforeAll` is too late. `afterAll` restores both saved values explicitly — the forks pool reuses a worker across files, so a leaked `TANDEM_LICENSE_GATE=1` would arm the gate for whatever file runs next. `resolveAppDataDir()` is re-read per call (`platform.ts:11`, and `resolveLiveLicenseState` calls it, not the module const), so later cases can repoint `TANDEM_APP_DATA_DIR` at a second fixture dir.
- **Anti-vacuity first:** assert `GATE_ENABLED === true` and `resolveLiveLicenseState()` is `{gateActive:true, status:"restricted"}`. Without this every assertion below passes on a dark build — which is precisely how 10,140 tests stayed green over two fail-opens.
- **Surface A:** `applyConnectionGate({}, "some-doc-room", state)` clamps `readOnly`; the same call with `CTRL_ROOM` does not. Kills a fix that makes restricted total and takes chat/mode down with it.
- **Surface B, MCP:** capture every handler by registering `registerDocumentTools` / `registerAnnotationTools` / `registerApplyTools` / `registerNavigationTools` / `registerAwarenessTools` / `registerDiagnosticsTools` against a fake `{tool, registerTool}` receiver (the `captureTandemOpen` shape in `license-force-open-gate.test.ts:41-51`; the handler is the last argument in both registration forms). Then `it.each(GATED)` — imported from `tests/helpers/tool-gates.ts`, so it cannot drift from the static coverage test — asserts each handler called with `{}` returns an envelope whose `code` is `LICENSE_REQUIRED`. Safe because the gate returns before the handler, so no argument validation runs. **`tandem_resolveAnnotation` is in that set only after the row flip**, which is the behavioural pin for fix 2: revert `annotations.ts:525` and this case goes red while `license-gate-coverage.test.ts` also goes red — two independent detectors, static and behavioural.
- **The escape hatch, three named tools only** (`tandem_getAnnotations`, `tandem_getTextContent`, `tandem_status`): the envelope is *not* `LICENSE_REQUIRED` (a `NO_DOCUMENT` here is a pass). Deliberately not `it.each(UNGATED)` — calling every ungated handler with `{}` reaches `tandem_save`, `tandem_open` and `tandem_search`, i.e. real filesystem work and a worker spawn. The static test already covers the full ungated set.
- **Surface B, `/api`:** `licenseGateMiddleware(req, res, next)` against a `res` stub sends 403 `LICENSE_REQUIRED` and never calls `next`. One case; per-route wiring belongs to `license-gate-api-coverage.test.ts`.
- **The fail-open, end to end:** repoint `TANDEM_APP_DATA_DIR` at a second fixture whose `trial.json` is `{"version":1,"firstRunAt":""}` and assert `resolveLiveLicenseState().status === "restricted"`. This is the one that would have caught a perpetual trial through the real disk path; the unit cases below cannot, because they inject `appDataDir`.

**`tests/server/license-state.test.ts`** — four cases beside the existing "no trial.json yet ⇒ trial at day 0" (which must stay green and is the discriminating twin): `firstRunAt` of `""`, `null`, `0` and a `trial.json` with the key absent each resolve to `restricted`; a valid recent ISO `firstRunAt` still resolves to `trial`. Use a realistic `now` (e.g. `Date.UTC(2026,0,1)`), **not** the file's `now: () => 0` idiom — at epoch 0 a `firstRunAt` of `null` coerces to `0` and would read as a live trial, which would make the `null` case pass for the wrong reason.
