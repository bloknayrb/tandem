## Problem

1. **`firstRunAt: ""` is a perpetual 14-day trial** — a real fail-open. `license-state.ts:129` reads `tf?.firstRunAt ? new Date(tf.firstRunAt).getTime() : nowMs`, so `""`, `null`, `0` and a missing key all take the *absent-file* branch on **every dispatch**. A non-empty *unparseable* value fails the opposite way (NaN ⇒ restricted). Two directions for one file; the issue and decision 5 both say the empty string is treated like the unparseable one.
2. **Restricted mode is asymmetric.** `tandem_resolveAnnotation` (`annotations.ts:525`) is on `withErrorBoundary`, so Claude can accept/dismiss while restricted; the human cannot, because accept/dismiss is a write to the document room's `Y.Map('annotations')` and Surface A marks document rooms read-only (`connection-gate.ts:17`). Decision F: restricted is symmetric read-only.
3. **The armed suite never exercises restricted.** `TANDEM_LICENSE_GATE=1 npx vitest run` is green because no `trial.json` means a *fresh* trial and every unit test injects `gateEnabled`/`LicenseState` itself. That is why (1) and (2) could both be true with nothing red. This is the load-bearing deliverable; (1) and (2) are things it should have caught.

**Three facts re-verified against the worktree (2026-09-10); none has drifted.**
- Decision F's "the other annotation mutators" is **a set of exactly one**: `tandem_comment`, `tandem_editAnnotation`, `tandem_annotationReply`, `tandem_removeAnnotation` are already `gated`. The MCP half of F is one row plus a rewritten `why`.
- **There is no `/api` twin for resolve/accept/dismiss.** `src/shared/api-paths.ts` has `API_ANNOTATION_REPLY` and `API_REMOVE_ANNOTATION` and nothing else annotation-shaped; the browser accepts over Hocuspocus. Critical Rule 9's both-halves requirement is satisfied **by construction**, not by an edit — stated because "no twin exists" and "twin exists and was forgotten" look identical from a grep.
- **Decision F's `/api/mode/release` clause is NOT implemented, deliberately.** `license-gate-api-coverage.test.ts:108-111` carries an `API_MODE_RELEASE` row added 2026-09-08 — *after* F — saying `ungated`, because mode lives in `CTRL_ROOM`, which Surface A never marks read-only: a restricted user can still toggle Solo→Tandem, so gating only the release strands their annotations behind a Held pill with reads still open. ## Fix

- **`src/server/license/license-state.ts:128-129` — the dispatch path, and nothing else in this file.**
  ```ts
  /** A parsed trial.json whose `firstRunAt` can actually run a clock. */
  function hasUsableFirstRunAt(tf: unknown): tf is TrialFile {
    if (typeof tf !== "object" || tf === null) return false;
    const v = (tf as TrialFile).firstRunAt;
    return typeof v === "string" && Number.isFinite(Date.parse(v));
  }
  ```
  `Date.parse` on a string-typed field, not `new Date(x).getTime()`: `new Date(null)` and `new Date(0)` are a **finite** `0`, a 1970 epoch that reads as a usable timestamp, while `new Date("")` is `NaN`. Typing the field first is what makes `null` and `0` fail here.
  ```ts
  // readJson<unknown>, not <TrialFile>: the cast is blind (:42-48), and a
  // TrialFile-typed `tf` narrows the false branch to `null`, making the `: NaN`
  // arm `never` to tsc — the arm that carries decision 5 for a whole-body scalar.
  const tf = readJson<unknown>(trialFilePath(appDataDir));
  // A trial.json that PARSES to a non-null body is authoritative even when its
  // firstRunAt is unusable: "", null, 0 and a missing key all resolve to NaN,
  // and NaN makes `nowMs < expiresAt` false ⇒ restricted (decision 5). Only an
  // absent or wholly unreadable file is day 0, which keeps ensureTrialStarted's
  // soft clock (ADR-040 §3) intact.
  const firstRunAt = hasUsableFirstRunAt(tf) ? Date.parse(tf.firstRunAt) : tf === null ? nowMs : NaN;
  ```
  `tf === null` covers an absent file, an unreadable one, unparseable JSON **and** a body that is the literal `null` — `readJson` cannot separate them and does not try. Any other scalar body (`0`, `""`, `false`) is not null and reaches `NaN` ⇒ restricted.
  **`ensureTrialStarted` is untouched** (see Not in scope).

**`tests/server/license-state.test.ts`** — beside the existing "no trial.json yet ⇒ trial at day 0", which must stay green and is the discriminating twin:
- `firstRunAt` of `""`, `null`, `0`, and a `trial.json` with the key absent, each ⇒ `restricted`; a valid recent ISO `firstRunAt` still ⇒ `trial`. **Split the clock, and it splits the opposite way to the earlier draft.** The positive case (valid recent ISO ⇒ `trial`) needs a realistic `now` (`Date.UTC(2026,0,1)`), as the neighbouring `"not-a-date"` case at `:265-277` already uses. The four falsy cases need `now: () => 0` — **epoch 0 is the discriminating clock here, not the misleading one.** Math: `TRIAL_MS` is `1_209_600_000` (`paths.ts:8`). Drop `typeof v === "string"` from `hasUsableFirstRunAt` and `firstRunAt: 0` resolves through a string-coercing `Date.parse(0)` → `"0"` → `946684800000`, or through a lazy `new Date(0).getTime()` → `0`; either way `expiresAt` lands in 1970–2000, so at `Date.UTC(2026,0,1)` (~`1.767e12`) the assertion still reads `restricted` and **passes with the guard removed**. At `now: () => 0` the same mutation reads `trial` and goes red. Same shape for `null` under the `new Date` spelling the Fix section warns about (`new Date(null).getTime() === 0`).
- **Record the mutation each falsy case exists to catch**, one line in the file: revert `typeof v === "string" &&` (and, separately, revert the whole `hasUsableFirstRunAt` change back to `tf?.firstRunAt ? … : nowMs`) and watch them go red. - ~~**Repairing a corrupt `trial.json`.**~~ **In scope after PR review round 1 (`cr-3`).** The cut argued the new closed path was "identical to what a non-empty unparseable value already does today", and that comparison is what made it look free: it is true of the *state* and false of the *exit*. `ensureTrialStarted` returned on `existsSync`, so nothing ever rewrote the file — post-flip the device is restricted on every boot, forever, told "your trial has ended" having never had one, with no in-app recovery and no `licenseUnverifiable` code to diagnose it. Reachable from a hand-edited file, a `{}` / `0` / `[]` body, or a `firstRunAt` written by a schema revision this build does not understand — and the spec itself pins `firstRunAt: 0` as restricted, which is exactly what an epoch-ms revision would write.

  The errno discrimination the cut named as the cost is one `try`/`catch` and is now the load-bearing half: the repair fires **only** on a body this process successfully read *and* parsed into a non-`null` value that still cannot run a clock. A read failure (a Windows AV/indexer lock) or an unparseable body leaves the file strictly alone — rewriting on a failed read would reset a real, running clock, and `readJson` already reads an unparseable body as day 0, so that case is not stuck either. The create path keeps `flag: "wx"` (concurrent first boots, first writer wins); only the repair path writes with `"w"`, and two processes repairing at once both write roughly-now. A repair grants one fresh 14-day trial, which is no new abuse surface: deleting `trial.json` already does that, and ADR-040 §3 makes the clock soft by design. Six unusable-body shapes plus the two leave-alone cases are covered in `license-state.test.ts`, each asserting the resolved *state* rather than the file bytes.

## Review corrections (post-cut)

One finding against the cut spec, adopted as given.

- **The `firstRunAt: null` / `0` unit cases were non-discriminating at the `now` the spec mandated, and the stated rationale for that `now` was inverted.** The Tests section required `Date.UTC(2026,0,1)` and forbade the file's `now: () => 0` idiom on the grounds that "at epoch 0 a `firstRunAt` of `null` coerces to `0` and the `null` case would pass for the wrong reason" — but the Fix section's own rationale (`new Date(null)` and `new Date(0)` are a **finite** `0`) says that coercion is precisely what needs pinning, and a realistic clock is what hides it. Math, re-measured: `TRIAL_MS` = `1_209_600_000` (`src/server/license/paths.ts:8`), so a `firstRunAt` that coerces to `0` (or, under the spec's `Date.parse` spelling, `Date.parse(0)` → `"0"` → `946684800000`) expires in 1970 or 2000 — **`restricted` at a 2026 clock, with the `typeof v === "string"` guard removed.** The assertion passed on the mutation it existed to catch; the `typeof` half of `hasUsableFirstRunAt` was pinned by nothing. Fixed by splitting the clock: the positive "valid recent ISO ⇒ trial" case keeps `Date.UTC(2026,0,1)` (matching the neighbouring `"not-a-date"` case at `tests/server/license-state.test.ts:265-277`, where a realistic clock *is* correct), while the four falsy cases move to `now: () => 0`, where the untyped coercion reads `trial` and goes red. The mutation each case exists to catch is now recorded in the file.
