**Three local helpers are NOT same-shape parsers and must not be flattened into one.** Measured, each holds behaviour the generic `parseResult` does not:

- `mcp-output-schemas.test.ts:114-117`'s `textEnvelope(result: ToolResult): { error: boolean; data?: unknown }` returns **`{ error: true }`** when no text content is present, where `parseResult` returns `null`. `:321`, `:577` and `:588` read `.error` off it directly, so a pass-through would throw rather than fail. Its body, its `{ error: true }` fallback and its return type all stay; only the client/transport construction moves.
- `held-in-solo-stamp.test.ts:229-237`'s `inboxIds` is parse **plus** a `.data ?? {}` unwrap **plus** a two-bucket `.map((a) => a.id)`. The comment at `:223-228` records that getting exactly that unwrap wrong once made `expect(await inboxIds()).not.toContain("s1")` unable to fail. Only its `JSON.parse(content.find(...)?.text ?? "{}")` half is replaced; the body becomes `const data = parseResult(await client.callTool(...))?.data ?? {}` and both maps stay verbatim.
- `awareness-tools.test.ts:1145-1163`'s `connectInbox` returns `{ client, poll }` and `poll` reads `result.structuredContent` (`:1157`), never the text envelope. It survives as a thin wrapper: only its server/transport/client construction is replaced, and `poll` keeps reading `structuredContent`.

**The point is not line count.** Driving the *registered* handler is what separates a real tool test from one that reimplements the filter and asserts its own model — the live counter-example is `tests/server/annotation-tools.test.ts:115`'s "tandem_getAnnotations tool logic" block, and ADR-035 Unit 8g exists because of it. ~20 lines of boilerplate is exactly the friction that produces the next hand-rolled filter test; a one-line import makes the right shape the easy one. The in-repo precedent for the extraction itself is `tests/helpers/mcp-source.ts`: "a comment saying the copies match cannot keep them matching; one binding can."

**Two files that look like copies and are not.** `tests/server/mcp-stdio-ports.test.ts:45` links a pair but hands `serverTransport` to `startMcpServerStdio` — production code builds the server, there is no registrar list, so it is not this harness and is not rewritten as one. `tests/server/restore-backup.test.ts:110` never links a transport at all: it captures handlers off a fake `{ tool: … } as unknown as McpServer` and parses through a `ToolResult`-typed `parseResult`. It stays exactly as it is; its typed parser is a real difference, not noise, and is **not** flattened into an untyped one to make the migration uniform.

## Fix

New `tests/helpers/mcp-harness.ts`, exporting:

```ts
export async function setupMcpServer(
  registrars: Array<(server: McpServer) => void>,
): Promise<{ client: Client; close: () => Promise<void> }>;
// Return type left inferred from JSON.parse, mirroring wire-code-fixtures.ts:13.
export function parseResult(result: { content: unknown });
```

- **The parameter type is the structural minimum the helper actually reads — `{ content: unknown }` — with the `as Array<{ type: string; text?: string }>` cast kept inside the helper.** A parameter typed `Awaited<ReturnType<Client["callTool"]>>` would be rejected at several existing call sites that hold narrower local types (`mcp-output-schemas.test.ts:107-111`'s `ToolResult`, `export-path-canonicalization.test.ts:101-102`'s inline cast, `edit-annotation.test.ts:33` and `resolve-annotation.test.ts:37`'s narrow parameter shape), and that is a `typecheck:tests` failure, not a runtime one. The structural minimum accepts both the SDK result and every locally-typed one with no cast at any call site. The return type is left inferred — no explicit `any`, and no lint rule is involved either way (`biome.json:21-23` sets `"linter": { "enabled": false }`; the pre-push hook runs the formatter only, so do not invent a suppression comment).
- **It imports no `src/` module** — only `Client`, `InMemoryTransport` and `McpServer` from `@modelcontextprotocol/sdk`. This is load-bearing, not tidiness: seven of the sixteen (`convert-error-mapping`, `html-read-only`, `mcp-wire-codes`, `mcp-wire-codes-mocked`, `range-bounds-validation`, `save-tool-allow-image-loss`, `wake-url-surfacing`) decide their module graph with hoisted `vi.mock` factories and `await import`. **This constraint is stricter than its precedent:** `tests/helpers/wire-code-fixtures.ts:5-6` says "imports no `src/server` module" and does import `src/shared/constants.js` at `:11`. SDK-only is the right rule here, and the new file carries its own sentence saying so.
- Registrars are passed as closures, so arity-2 registrars fit unchanged: `mcp-output-schemas.test.ts:95` and `:203` become `(s) => registerDiagnosticsTools(s, opts)`. No `server` handle is returned — nothing measured needs one, and returning it invites a caller to register after connect.
- **`parseResult` moves here and `wire-code-fixtures.ts:13` loses it**, its two consumers (`mcp-wire-codes`, `mcp-wire-codes-mocked`) importing it from `mcp-harness.js` instead. No re-export shim: a compatibility re-export is the thing that lets the two drift back apart. `wire-code-fixtures.ts` keeps `createMinimalDocx` and `seedAcceptedSuggestion`.
- Migrate all **16**, each keeping its own registrar list as its own argument, and each deleting its local `setupMcpClient`/`setupClient`/`mcpClient` body and its local `parseResult`. The two same-shape parsers keep their names as thin wrappers where a call site reads better that way (`html-read-only`'s `call()` stays, its body becoming `parseResult(await client.callTool(...))`; likewise `wake-url-surfacing`'s `parsed()`). `textEnvelope`, `inboxIds` and `connectInbox` keep their bodies as Problem describes.
- **`close` is called in the scope that creates the client**, not unconditionally in `afterEach` — four sites create theirs inside an `it` or a per-call helper, and an `afterEach` would hold no handle to them:
  - `afterEach` for the file-level clients created in a `beforeEach`. **Five files have no `afterEach` today** (`edit-annotation`, `resolve-annotation`, `convert-error-mapping`, `save-tool-allow-image-loss`, `mcp-output-schemas`) and gain one, plus the vitest import.
  - the creating `it` or helper, via `try/finally` or an explicit close, for `export-path-canonicalization.test.ts:73-81` (`mcpClient()` is called per `exportEnvelope()` at `:98-100`, several times in one test — a module-level handle would close only the last), `mcp-output-schemas.test.ts:202-222` (a second inline client inside one `it`), `held-in-solo-stamp.test.ts:215-221` and `awareness-tools.test.ts:1145` (the latter two already close, at `:250` and in `finally` at `:1188/1211/1253`).
  - **`close()` awaits `client.close()` then `server.close()`**, so the helper's guarantee is at least as strong as the hand-written closes it replaces, which close the client only.
- **Measured close coverage: five of the sixteen close today** — `annotation-promote-pull-surface:156`, `awareness-tools:1188/1211/1253`, `held-in-solo-stamp:250`, `range-bounds-validation:98`, `read-audience-filter:142` (seven call sites). **Eleven do not, and gain a close.** (`mcp-stdio-ports:39` closes but is not migrated, so it is out of this tally.) **The justification is hygiene and uniformity, not a live bug:** `node_modules/@modelcontextprotocol/sdk/dist/esm/inMemory.js` shows `InMemoryTransport` holds only `_messageQueue` and `_otherTransport` — no timer, socket or fd — and its `close()` awaits `other?.close()`, so one `client.close()` already tears down both halves. Do not tell a reviewer these eleven calls fix a leak that surfaces as an unrelated timeout; that is not a property of this transport.
- Rules that bite: `tests/helpers/**/*.ts` is already inside `tsconfig.tests.node.json`'s include (`:71`, a whole directory, not a suffix glob), so the new file is typechecked by `typecheck:tests` and the orphan sweep in `tests/scripts/typecheck-tests-wiring.test.ts` stays green — verify, do not assume. No `src/` change, so no Y.Map key, origin-tag, `data-testid`, license-gate or `NON_LOOPBACK_ALLOWED` surface is touched; say that explicitly in the PR body so no reviewer goes looking. `npx biome format --write` over every changed file before each commit.

**Observational identity is the contract.** Same tests, same assertions, same counts. If a migration would change what a test asserts, that is a finding to report in the PR body, not a cleanup to absorb. The one deliberate behavioural delta is the **eleven** new `close()` calls; if adding one turns a file red, that is a finding too.

## Tests
