## Problem

The issue's mechanism holds. Six test files each stand up their own in-memory MCP server — link an `InMemoryTransport` pair, construct an `McpServer`, run a registrar list, connect a `Client` — and four also define their own `parseResult`. They are the six the issue names, all still present:

| `edit-annotation.test.ts` | `setupMcpClient:22` | `:33` | no |

| `annotation-promote-pull-surface.test.ts` | `setupMcpClient:79` | `:90` | yes (`:156`) |

**The issue's scale claim is stale, and this spec deliberately does not chase it.** The probe returns **17** files linking a transport pair, not 6. Migrating all of them is a ~16-file mechanical rewrite the issue does not ask for; this spec migrates **the six the issue names** and files the remainder as its own issue (see Boundary). Ten files are left byte-identical on purpose.

**`textEnvelope` is not a copy of `parseResult` and is not flattened into one.** At `mcp-output-schemas.test.ts:114-117` it is typed `{ error: boolean; data?: unknown }` and its no-text branch returns **`{ error: true }`**, where `parseResult` returns `null`; `:321`, `:577` and `:588` read `.error` off it directly, so a pass-through would throw rather than fail. Body, fallback and return type all stay — only the client/transport construction moves.

**Two files that look like copies and are not**, both untouched: `mcp-stdio-ports.test.ts:45` links a pair but hands `serverTransport` to `startMcpServerStdio` — production code builds the server, there is no registrar list. `restore-backup.test.ts:110` links no transport at all; it captures handlers off a fake `{ tool: … } as unknown as McpServer` and parses through a `ToolResult`-typed `parseResult`. That typed parser is a real difference, not noise, and is not flattened to make anything uniform.

**The point is not line count.** Driving the *registered* handler is what separates a real tool test from one that reimplements the filter and asserts its own model — the live counter-example is `tests/server/annotation-tools.test.ts:115`'s "tandem_getAnnotations tool logic" block, and ADR-035 Unit 8g exists because of it. ~20 lines of boilerplate is exactly the friction that produces the next hand-rolled filter test; a one-line import makes the right shape the easy one. Precedent for the extraction is `tests/helpers/mcp-source.ts`: "a comment saying the copies match cannot keep them matching; one binding can." **Put this in the PR body** — read as deduplication, it will be undervalued and later undone.

## Fix

New `tests/helpers/mcp-harness.ts`:

```ts
export async function setupMcpServer(
  registrars: Array<(server: McpServer) => void>,
): Promise<{ client: Client; close: () => Promise<void> }>;
export function parseResult(result: { content: unknown });
```

- **Parameter type is the structural minimum the helper reads — `{ content: unknown }` — with the `as Array<{ type: string; text?: string }>` cast kept inside.** A parameter typed `Awaited<ReturnType<Client["callTool"]>>` is rejected at call sites holding narrower local types (`mcp-output-schemas:107-111`'s `ToolResult`, `export-path-canonicalization:101`'s inline cast, `edit-annotation:33`, `resolve-annotation:37`) — a `typecheck:tests` failure, not a runtime one. Return type left inferred, mirroring `tests/helpers/wire-code-fixtures.ts:13`. No lint rule is involved either way: `biome.json:21-23` disables the linter and the pre-push hook runs the formatter only, so do not invent a suppression comment.
- **It imports no `src/` module** — only `Client`, `InMemoryTransport` and `McpServer` from `@modelcontextprotocol/sdk`, so a file deciding its module graph with hoisted `vi.mock` factories can import it safely. Stricter than its precedent (`wire-code-fixtures.ts:5-6` says "no `src/server` module" yet imports `src/shared/constants.js` at `:11`); the new file carries its own sentence saying so.
- Registrars are closures, so arity-2 registrars fit unchanged: `mcp-output-schemas:95` and `:203` become `(s) => registerDiagnosticsTools(s, opts)`. No `server` handle is returned — nothing here needs one, and returning it invites registration after connect.
- Migrate the six, each keeping **its own registrar list as its own argument**, each deleting its local harness body, and the four with one deleting their local `parseResult`. `textEnvelope` keeps body, fallback and return type; only its client construction moves.
- **`tests/helpers/wire-code-fixtures.ts` is left alone.** Its `parseResult:13` serves two files outside this scope; folding it in now pulls them in too. Say in the PR body that it is a known second copy, reconciled when the remainder issue lands — and add no re-export shim, which is what lets two copies drift back apart.
- **`close` is called in the scope that creates the client.** `afterEach` for file-level clients built in a `beforeEach` — **five** of the six gain a new **file-level** `afterEach`: `edit-annotation`, `resolve-annotation`, `mcp-output-schemas`, `export-path-canonicalization` (per-call, in `exportEnvelope`) and `mcp-tool-integration` (a new file-level `afterEach` beside the existing `afterAll(() => shutdownSearchWorker())` at `:125` — **not** inside the `:236` `afterEach`, which is scoped to the `#1796` describe opened at `:233` and only `fs.rm`s `convertTempDirs`; `:1089` is the same shape inside the `#314` describe and `:2098` is `afterEach(resetDeliveryStateForTests)`). `mcp-tool-integration` already imports `afterEach` at `:15`, so only the other four add the vitest import. **Only `annotation-promote-pull-surface:155-156` closes today** — a file-level `afterEach` whose `await client.close()` becomes `await close()`; `grep -n "close()" tests/server/mcp-tool-integration.test.ts` returns nothing, so that file's client is never closed. The two per-call sites close in the creating `it`/helper: `export-path-canonicalization:73-81` (`mcpClient()` runs per `exportEnvelope()` at `:98-100`, several times in one test — a module-level handle would close only the last) and `mcp-output-schemas:202-222` (a second inline client inside one `it`).
- **`close()` awaits `client.close()` then `server.close()`**, so the helper is at least as strong as the hand-written client-only closes it replaces. **The new close calls — one per migrated site that has none today, `mcp-tool-integration` included — are the one deliberate delta, and they are hygiene, not a leak fix** — `node_modules/@modelcontextprotocol/sdk/dist/esm/inMemory.js` shows `InMemoryTransport` holds only `_messageQueue` and `_otherTransport`, no timer/socket/fd, and its `close()` already awaits `other?.close()`. Do not sell it to a reviewer as fixing a timeout.
- `tests/helpers/**/*.ts` is already a whole-directory include in `tsconfig.tests.node.json:71`, so the new file is typechecked and the orphan sweep in `tests/scripts/typecheck-tests-wiring.test.ts` stays green — verify, do not assume. No `src/` change, so no Y.Map key, origin-tag, `data-testid`, license-gate or `NON_LOOPBACK_ALLOWED` surface is touched; say so in the PR body. `npx biome format --write` before each commit.

**Observational identity is the contract.** Same tests, same assertions, same counts. A migration that changes what a test asserts is a finding for the PR body, not a cleanup to absorb.
