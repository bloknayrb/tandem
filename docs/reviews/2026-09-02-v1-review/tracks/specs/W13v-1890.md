# W13v — #1890 `tandem channel` still exits 1 when the server is down at spawn

Branch `fix/server-and-cli-small-correctness-fixes-2003`. Closes #1890. Ledger: no `areas/*.md` row — filed against the F-runtime track after #1889 shipped #1804; the gap is recorded in the sweep ledger `docs/plans/2026-09-06-open-issues-sweep.md`, which is its tracked home along with the wave 13 row. Probe: spawn `runChannelCli()` against a closed port and observe the process, converted to a vitest spec below.

## Problem

#1804 (shipped in #1889) made the SSE consumer never exit and never stop retrying, because neither push-path host is respawned inside a Claude Code session. That holds for `dist/channel/index.js` — but the plugin spawns `npx -y tandem-editor@<ver> channel`, i.e. `runChannelCli()`:

```ts
export async function runChannelCli(): Promise<void> {
  await ensureTandemServer();
  await runChannel({ skipReachabilityLog: true });
}
```

`ensureTandemServer` (`src/cli/preflight.ts`) probes `/health` once and, on failure, writes two stderr lines and `process.exit(1)`. If Tandem is not up at the moment Claude Code starts the plugin's MCP servers — the desktop app still booting, the user opening Claude Code first — the host dies before `runChannel` installs the infinite consumer, and the push path is gone for the rest of that session.

**What makes the fix two lines:** `runChannel` already owns a non-fatal reachability report. `src/channel/run.ts` logs `Cannot reach Tandem server at <url>` plus `Start it with: tandem start` to stderr and then *continues anyway* ("the event bridge will retry, and the server may start later"). `runChannelCli` passes `skipReachabilityLog: true` precisely because the fatal preflight had already probed. Dropping the fatal probe and letting the non-fatal one run removes the exit and leaves a diagnostic in place, in one move — option (a) of the issue's fix shape.

**Recorded narrowing — the two probes are not equivalent, and the difference goes away with the deletion.** `ensureTandemServer` → `probeTandemServer` (`src/cli/preflight.ts:33-60`) issues an HTTP `fetch(${url}/health)` and distinguishes `kind: "unhealthy"` (a non-2xx `/health`) from `kind: "unreachable"`, reporting "running but unhealthy — check the host logs." `runChannel`'s surviving probe, `checkServerReachable` (`src/channel/run.ts:228-254`), is a raw TCP `createConnection` to host:port: it resolves true for **anything listening**, including a wedged Tandem or an unrelated process on 3479. So the deletion loses the unhealthy-server verdict outright; what survives covers the **down** case only. That is accepted here (the exit is the defect; #1804 owns the consumer's probe), but it must not be described as restoring the same diagnostic, and the `preflight.ts` docstring rewrite carries the same sentence.

## Fix

- `src/cli/channel.ts`: `runChannelCli` becomes `await runChannel();` — no preflight, no `skipReachabilityLog`. Update the module docstring, which currently says "Runs the unified preflight, then hands off"; the replacement names #1804, says reachability is the consumer's — reported once and never fatal — and names the narrowing above (TCP connect, not `/health`; a listening-but-unhealthy server now reads as reachable).
- `src/cli/preflight.ts`: **delete `ensureTandemServer`.** It has exactly one `src` caller (this one) and zero references in `.claude-plugin/` or shipped docs; leaving an exported fail-fast helper that nothing calls invites a future caller to reintroduce the exit. `probeTandemServer` stays untouched (`src/cli/mcp-stdio.ts` is its consumer). Rewrite the module docstring's two-flavour paragraph to the one flavour that remains, naming #1890 for why the fatal one went **and recording that the `unhealthy` verdict now has no consumer on the channel path**.
- `src/channel/run.ts`: **keep `RunChannelOptions.skipReachabilityLog` and rewrite its docblock.** After this change it has no `src` caller — `src/channel/index.ts:27` calls `runChannel()` bare and `src/cli/channel.ts` will too — and exactly one test caller, `tests/channel/permission-forward.test.ts:70`. Its current text ("The CLI wrapper runs a strict preflight upstream and we don't want to double-log … noise") becomes false the moment the preflight is deleted, which is the same stale-claim hazard the `ensureTandemServer` deletion is justified by. The replacement says: kept for tests that do not want the probe's stderr; no production caller since #1890 removed the upstream preflight.
- **Assumption, recorded:** option (a) over option (b). Option (b) (a `waitForUpstream` grace window with opt-in fail-fast) would add an option nothing would pass — there is no surviving caller that wants fail-fast; the `tandem setup` / `doctor` callers the issue speculates about do not exist today.
- **Critical Rule 3:** every line here is `process.stderr` / `console.error`. `runChannel`'s reachability lines are already `console.error`, and `console.*` is redirected in `index.ts` — but this is a stdio MCP host, so a `process.stdout.write` added here would corrupt the wire directly. Nothing in the diff writes to stdout.
- `docs/architecture.md` § "Retry Semantics": the sentence "**The consumer never exits and never stops retrying (#1804).**" reads as covering both entries. Extend it to name them — the standalone `dist/channel/index.js` **and** the `tandem channel` subcommand the plugin spawns (`src/cli/channel.ts`), the latter true only since #1890 removed its fail-fast preflight.

No Y.Doc write, no Y.Map key, no MCP tool or `/api` route: Critical Rules 1, 2 and 9 are not engaged.

The spec's comment must say **down-server**, not "the same diagnostic": per the narrowing above, the unhealthy-server message is gone either way.
3. **Resolved: no spec covers `runChannel`'s own "unreachable → two stderr lines → continues" branch, and this PR does not add one.** Checked: `tests/channel/` holds `event-bridge`, `fetch-with-timeout`, `permission-forward`, `reply-abort` and `run-timeouts`, and none drives that branch (`grep -rn "Cannot reach Tandem\|checkServerReachable" tests/`: zero hits). Reaching it means running `runChannel` for real, which connects a `StdioServerTransport` and installs signal handlers; the branch is #1804's, not #1890's, and standing that harness up is out of proportion to a one-line call-site change. Recorded as a known gap rather than left as an unresolved conditional.
4. `tests/cli/preflight.test.ts`: rewrite its five specs onto `probeTandemServer`, preserving each fixture and assertion minus the exit — 200 → `{ok: true}` and `/health` was the URL fetched; rejection → `{ok: false, kind: "unreachable"}` with the reason echoed; non-2xx → `kind: "unhealthy"` and "HTTP 500"; timeout → `kind: "unreachable"`; `TANDEM_URL` honoured when no url is passed. Rename the describe. This keeps every behaviour the deleted function's tests were actually pinning (all of them live in `probeTandemServer`) and kills a silent loss of coverage alongside the deletion.
