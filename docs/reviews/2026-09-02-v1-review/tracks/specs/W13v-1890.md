# W13v — #1890 `tandem channel` still exits 1 when the server is down at spawn

Branch `fix/server-and-cli-small-correctness-fixes-2003`. Closes #1890. Ledger: no `areas/*.md` row — filed against the F-runtime track after #1889 shipped #1804; the gap is recorded in the sweep ledger `docs/plans/2026-09-06-open-issues-sweep.md`, which is its tracked home along with the wave 13 row. Probe: spawn `runChannelCli()` against a closed port and observe the process, converted to a vitest spec below.

## Problem

#1804 (shipped in #1889) made the SSE consumer never exit and never stop retrying, because neither push-path host is respawned inside a Claude Code session. That holds for `dist/channel/index.js` — but the plugin spawns `npx -y tandem-editor@<ver> channel`, i.e. `runChannelCli()`:

```ts
export async function runChannelCli(): Promise<void> {
  await ensureTandemServer();
  await runChannel({ skipReachabilityLog: true });
}
```

`ensureTandemServer` (`src/cli/preflight.ts`) probes `/health` once and, on failure, writes two stderr lines and `process.exit(1)`. If Tandem is not up at the moment Claude Code starts the plugin's MCP servers — the desktop app still booting, the user opening Claude Code first — the host dies before `runChannel` installs the infinite consumer, and the push path is gone for the rest of that session.

**What makes the fix two lines:** `runChannel` already owns a non-fatal reachability report. `src/channel/run.ts` logs `Cannot reach Tandem server at <url>` plus `Start it with: tandem start` to stderr and then *continues anyway* ("the event bridge will retry, and the server may start later"). `runChannelCli` passes `skipReachabilityLog: true` precisely because the fatal preflight had already probed. Dropping the fatal probe and letting the non-fatal one run restores the diagnostic and removes the exit in one move — option (a) of the issue's fix shape.

## Fix

- `src/cli/channel.ts`: `runChannelCli` becomes `await runChannel();` — no preflight, no `skipReachabilityLog`. Update the module docstring, which currently says "Runs the unified preflight, then hands off"; the replacement names #1804 and says reachability is the consumer's, reported once and never fatal.
- `src/cli/preflight.ts`: **delete `ensureTandemServer`.** It has exactly one `src` caller (this one) and zero references in `.claude-plugin/` or shipped docs; leaving an exported fail-fast helper that nothing calls invites a future caller to reintroduce the exit. `probeTandemServer` stays untouched (`src/cli/mcp-stdio.ts` is its consumer). Rewrite the module docstring's two-flavour paragraph to the one flavour that remains, naming #1890 for why the fatal one went.
- **Assumption, recorded:** option (a) over option (b). Option (b) (a `waitForUpstream` grace window with opt-in fail-fast) would add an option nothing would pass — there is no surviving caller that wants fail-fast; the `tandem setup` / `doctor` callers the issue speculates about do not exist today.
- **Critical Rule 3:** every line here is `process.stderr` / `console.error`. `runChannel`'s reachability lines are already `console.error`, and `console.*` is redirected in `index.ts` — but this is a stdio MCP host, so a `process.stdout.write` added here would corrupt the wire directly. Nothing in the diff writes to stdout.
- `docs/architecture.md` § "Retry Semantics": the sentence "**The consumer never exits and never stops retrying (#1804).**" reads as covering both entries. Extend it to name them — the standalone `dist/channel/index.js` **and** the `tandem channel` subcommand the plugin spawns (`src/cli/channel.ts`), the latter true only since #1890 removed its fail-fast preflight.

No Y.Doc write, no Y.Map key, no MCP tool or `/api` route: Critical Rules 1, 2 and 9 are not engaged.
