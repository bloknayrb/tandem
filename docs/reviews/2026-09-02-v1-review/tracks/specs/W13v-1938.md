## Problem

`docs/mcp-tools.md:64`, the shared `LICENSE_REQUIRED` error-code row:

> The license gate is active and restricted. Reads, plain `tandem_open`, saves and exports still work; **content mutations do not.**

Decision F (#1827 F, shipped as #1788) moved `tandem_resolveAnnotation` from `ungated` to `gated` — verified against current source: `tests/server/license-gate-coverage.test.ts` carries its `gate: "gated"` row with decision F's reasoning ("restricted is SYMMETRIC read-only for annotation CONTENT and STATUS writes"). Accept/dismiss is an annotation **status** flip, not a content mutation, so a reader applying the row's rule concludes it still works. The row is saved from being wrong today only by its closing sentence, "Never returned while the gate ships dark."

## Fix

One clause, in `docs/mcp-tools.md` only — the wording the issue proposes:

> ... saves and exports still work; content mutations **and annotation status changes** do not.

No code change, no test change, no gate-table change: the gated set itself is already correct and CI-enforced by the two coverage tables (Critical Rule 9), and this edit brings the prose mirror into line with them. Nothing in `tests/` asserts the old clause (grep for `content mutations` across `tests/`: zero hits), so no pinned string breaks.

The rest of the row is left alone, including the `force: true` sentence and "Never returned while the gate ships dark" — that last clause is what keeps the row honest about the dark flag and must survive the edit.
