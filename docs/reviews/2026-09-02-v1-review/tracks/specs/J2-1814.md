# J2 — #1814 Integration wizard empty-state headline keyed on `existing.length`, not CLI presence

Branch `fix/product-copy-1814`. Closes #1814. Ledger row: `docs/reviews/2026-09-02-v1-review/areas/product.md:20`. Probe: none (UI copy, read-verified against source — no `probe-tools.mts` case; a component test is the discriminator).

## Problem

`IntegrationWizardModal.svelte`'s connect-empty state picks its headline from `{:else if wizard.existing.length === 0}` (~L876 pre-fix) and always renders **"We couldn't find Claude on this computer."** (~L878) — `existing` is the list of *detected MCP config targets* (`useIntegrationWizard.svelte.ts` populates it from `GET /api/integrations/existing`'s `installs`, and the server route returns every detected target, configured or not — `src/server/integrations/api-routes.ts`'s `readExisting()`), not "targets with a Tandem entry." So `existing.length === 0` means no MCP config target was detected at all, and it says nothing about whether the Claude CLI itself is installed. Two lines below, the same empty state ALSO renders a `showInstalledNotOnPath` hint ("Claude Code is installed…") when `cliStatus.presence === "INSTALLED_NOT_ON_PATH"` (L169). So the ordinary first run — CLI installed, never configured for Tandem — sees "We couldn't find Claude" directly above "Claude Code is installed," contradicting itself in the same view.

## Fix

`src/client/components/IntegrationWizardModal.svelte`. `createClaudeCliStatus()` (`cliStatus`, wired at ~L167) already exposes the signal this headline needs — the same hook already drives two sibling derived flags right where the fix belongs:

- L168: `const showInstallCta = $derived(cliStatus.presence === "NOT_INSTALLED");`
- L169: `const showInstalledNotOnPath = $derived(cliStatus.presence === "INSTALLED_NOT_ON_PATH");`

Add a third, beside them: `const emptyStateFoundInstall = $derived(cliStatus.presence === "INSTALLED_ON_PATH" || cliStatus.presence === "INSTALLED_NOT_ON_PATH");`. `null` (still probing, before the GET resolves) reads as "not found" — matching `showInstallCta`'s own loading behavior, so there is no headline flash. In the empty-state markup (~L878), swap the literal string for a conditional keyed on `emptyStateFoundInstall` alone: found → **"Claude Code is installed, but hasn't connected to Tandem yet."**; otherwise → unchanged **"We couldn't find Claude on this computer."** Do **not** touch `wizard.existing.length === 0` itself — it still decides which of the two top-level branches renders (this one vs. the non-empty per-target list at ~L1307); only the string *inside* this branch changes.

**Do not gate the headline on `wizard.errorMessage`.** A round-2 pass of this spec added a `&& !wizard.errorMessage` conjunct on the theory that a failed `GET /api/integrations/existing` leaves `existing: []` while `emptyStateFoundInstall` could still read `true`, letting the new headline claim a state ("hasn't connected to Tandem yet") the wizard never determined. That state is unreachable: `setError()` (`useIntegrationWizard.svelte.ts:227-231`) sets `errorMessage` and `step = "error"` together, and the empty-state branch only renders inside `{#if wizard.step === "connect"}` (`IntegrationWizardModal.svelte:862`) — `step === "error"` renders a separate, mutually exclusive arm (`:1227`). Every transition back to `"connect"` (`begin()`, `reset()`) clears `errorMessage` to `null` in the same assignment. So `step === "connect" && errorMessage !== null` cannot occur, and the guard is dead code that a test can only exercise by hand-constructing an impossible stub state.

**Trim the redundant `showInstalledNotOnPath` hint lead.** With the new headline, the `INSTALLED_NOT_ON_PATH` case now stacks two consecutive sentences that both open "Claude Code is installed": the new headline, then the existing hint (~L919-925) — *"Claude Code is installed. Open a new terminal and run `claude` once, then choose "Check again"."* Trim the hint's redundant lead so it reads **"Open a new terminal and run `claude` once, then choose "Check again"."** This is presentation only — it changes no gating, and `showInstalledNotOnPath` itself (which branch renders) is unchanged.

**A matching implementation already sits uncommitted in this worktree** (branch `fix/product-copy-1814`, not yet committed): `IntegrationWizardModal.svelte` gained `emptyStateFoundInstall` (with no `errorMessage` guard — matching this round's correction) and the conditional headline keyed on it, and `tests/client/integration-wizard-install.test.ts` gained an `it.each` covering the four presence cases (Tests items 1–4 below). What it does **not** yet do: the `showInstalledNotOnPath` hint trim (line ~923 still reads "Claude Code is installed. Open a new terminal…", the redundant lead) and its discriminating test assertion (Tests item 2's hint check). Verify the four presence cases against this spec, add the hint trim and its test, then commit.

## Tests

`tests/client/integration-wizard-install.test.ts` already stubs `createClaudeCliStatus` via a mutable `cliStub` (the file's existing install-CTA suite is the model). Add a sibling `describe`:

1. `presence: "INSTALLED_ON_PATH"`, `existing: []` → new headline (kills a fix that keys on `existing.length` alone, or on `showInstallCta`/`showInstalledNotOnPath` individually rather than their union).
2. `presence: "INSTALLED_NOT_ON_PATH"`, `existing: []` → new headline (kills a fix that only checks one of the two INSTALLED_* values).
3. `presence: "NOT_INSTALLED"` → old headline (kills an over-fold that shows the new text unconditionally).
4. `presence: null` → old headline (kills a fix that flashes the new text before the GET resolves — same discriminator as the file's existing install-CTA loading test).
5. `presence: "INSTALLED_ON_PATH"` **with one entry pushed into `wizard.existing`** → `[data-testid="integration-wizard-empty"]` is `null` (the non-empty per-target branch renders instead). **This is already pinned** by the file's existing install-CTA suite at `tests/client/integration-wizard-install.test.ts:196-208` (`beforeEach` pushes a detected install, the test sets `presence: "INSTALLED_ON_PATH"` and asserts the empty-state testid is `null`) — do not add a duplicate case; if the new describe block wants its own local assertion of this fact for readability, keep it to one line and note the cross-reference in a comment rather than treating it as new coverage.

Case 2 (`presence: "INSTALLED_NOT_ON_PATH"`) also asserts the trimmed `showInstalledNotOnPath` hint: the success-banner text (`q(container, "integration-wizard-install-success")`) starts with "Open a new terminal" and does not contain "Claude Code is installed." — otherwise the hint-trim in Fix has no discriminating test and a revert of it would go unnoticed.
