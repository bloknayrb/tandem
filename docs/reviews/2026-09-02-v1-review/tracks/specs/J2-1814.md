# J2 — #1814 Integration wizard empty-state headline keyed on `existing.length`, not CLI presence

Branch `fix/product-copy-1814`. Closes #1814. Ledger row: `docs/reviews/2026-09-02-v1-review/areas/product.md:20`. Probe: none (UI copy, read-verified against source — a component test is the discriminator).

## Problem

`IntegrationWizardModal.svelte`'s connect-empty state picks its headline from `{:else if wizard.existing.length === 0}` (~L876 pre-fix) and always renders **"We couldn't find Claude on this computer."** — `existing` is the list of *detected MCP config targets* (`useIntegrationWizard.svelte.ts` populates it from `GET /api/integrations/existing`'s `installs`), not "targets with a Tandem entry." So `existing.length === 0` means no MCP config target was detected at all, and says nothing about whether the Claude CLI itself is installed. Two lines below, the same empty state ALSO renders a `showInstalledNotOnPath` hint ("Claude Code is installed…") when `cliStatus.presence === "INSTALLED_NOT_ON_PATH"` (L169). So the ordinary first run — CLI installed, never configured for Tandem — sees "We couldn't find Claude" directly above "Claude Code is installed," contradicting itself in the same view.

## Fix

`src/client/components/IntegrationWizardModal.svelte`. `createClaudeCliStatus()` (`cliStatus`, wired at ~L167) already exposes the signal this headline needs, beside its two sibling derived flags:

- L168: `const showInstallCta = $derived(cliStatus.presence === "NOT_INSTALLED");`
- L169: `const showInstalledNotOnPath = $derived(cliStatus.presence === "INSTALLED_NOT_ON_PATH");`

Add a third: `const emptyStateFoundInstall = $derived(cliStatus.presence === "INSTALLED_ON_PATH" || cliStatus.presence === "INSTALLED_NOT_ON_PATH");`. `null` (still probing) reads as "not found," matching `showInstallCta`'s own loading behavior — no headline flash. In the empty-state markup (~L878), swap the literal string for a conditional keyed on `emptyStateFoundInstall` **alone**: found → **"Claude Code is installed, but hasn't connected to Tandem yet."**; otherwise → unchanged **"We couldn't find Claude on this computer."** Do not touch `wizard.existing.length === 0` itself — it still decides which top-level branch renders; only the string inside this branch changes.

**No `wizard.errorMessage` guard.** `setError()` (`useIntegrationWizard.svelte.ts:227-231`) sets `errorMessage` and `step = "error"` in the same call, and the empty-state branch only renders inside `{#if wizard.step === "connect"}` (`:862`) — `step === "error"` is a separate, mutually exclusive arm (`:1227`). Every transition back to `"connect"` (`begin()`, `reset()`) clears `errorMessage` to `null` in the same assignment. So `step === "connect" && errorMessage !== null` cannot occur; a guard on it would be dead code testable only by hand-constructing an impossible stub state. Don't add one.

**Trim the redundant `showInstalledNotOnPath` hint lead.** With the new headline, the `INSTALLED_NOT_ON_PATH` case stacks two consecutive sentences both opening "Claude Code is installed": the new headline, then the existing hint (~L919-925). Trim the hint's lead so it reads **"Open a new terminal and run `claude` once, then choose "Check again"."** Presentation only — no gating change.

A matching implementation sits uncommitted in this worktree (branch `fix/product-copy-1814`): verify the four presence cases and the hint trim against this spec before committing.
