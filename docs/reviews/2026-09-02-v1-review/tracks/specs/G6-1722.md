# G6 — #1722 (rail half) Rail toggles are silent no-ops on a read-only settings blob

Branch `fix/rail-seam-a-tab-switch-inside-a-chat-reveal-a-reveal-that-outlives-its-pin-and-rail-toggles-that-refuse-in-silence-1719`. **Refs #1722 — the issue stays open.** Ledger: none — non-review issue; sweep row wave 9 `G6 rail seam` in `docs/plans/2026-09-06-open-issues-sweep.md`, and row 8 `E2-upgrade` (#1985, MERGED) for the half that already landed.

**Scope is the rail half only**, per the owner's comment of 2026-09-15: the `updateSettings` boolean and the deduplicated refusal warning landed in #1985, and **#1964's radiogroup `readOnly` contract is a separate open issue** (verified OPEN, titled as extending #1722). `Refs` rather than `Closes` because #1964 extends this issue and the owner's comment keeps the two linked; whether #1722 closes on #1964's merge is Bryan's call.

## Problem

`updateSettings` returns `boolean` since #1985 — declared at `useTandemSettings.svelte.ts:39`, implemented at `:114-129`, returning `false` on the `_readOnly` short-circuit (`:115-118`), which also fires the one registered refusal handler. That handler is registered once at `App.svelte:283-296` and pushes a warning notification with `dedupKey: "settings-readonly"` (`:294`).

**The rail half never consumes it.** `toggleLeft` (`model.svelte.ts:165-169`) and `toggleRight` (`:171-180`) both return `void`, so neither the model nor its caller can tell a refused write from an applied one. The user-visible outcome of a refused rail toggle today is: the #1985 notification fires, and the rail does not move — correct, but unexplained at every layer beneath that notification.

**The issue title's second half — "and drop keyboard focus" — does not hold, and this spec does not inherit it.** Read on master, `focusToggleTarget`'s warn (`App.svelte:1190`) is unreachable for both ids it can build (`:1185`):

- `panel-edge-collapse-${side}` is the `edgeCollapse` snippet (`App.svelte:2810-2823`), rendered unconditionally inside `.rail-full` (`:2487`), and `.rail-shell.collapsed .rail-full { display: none }` (`:3325`) **hides rather than unmounts** it.
- `peek-strip-${side}` is `PeekStrip`'s own button (`src/client/panels/PeekStrip.svelte:84-93`, testid at `:86`), mounted unconditionally at `App.svelte:2561-2567` and hidden by inline style while the rail is open (`style={collapsed ? "" : "display: none;"}`, `:91`); its comment at `:81-83` says "Always rendered (instance persists)".

So on a refusal nothing re-renders, `document.querySelector` finds a hidden element on **both** branches, `el.focus()` (`:1188`) is a no-op against `display: none`, and the `else` (`:1189-1191`) never runs. **That is a read of the source, not a browser measurement** — and no claim in this spec, in the PR body, or in any test rests on where focus actually lands.

`tests/client/layout-model.svelte.test.ts`'s `makeSettingsState` (`:45-79`) has no `_readOnly` axis; its own comment at `:71-73` says so and names this group as the owner.

## Fix

The user-visible signal already exists (#1985). This makes the rail path **report** the refusal at the model layer — no second notification channel, and no claimed focus repair.

- `model.svelte.ts`: `toggleLeft` and `toggleRight` return `boolean` — the value `updateSettings` returned. `toggleRight` has two branches (`:172-179`); each returns its own call's result, so the hidden→show branch (which writes `rightPanelVisible` and, in solo, `soloRailHidden`) reports its single write. Update the interface declarations at `:109-111`, which currently say `void`.
- **Define the boolean in those interface docs**: "the write was applied — i.e. not refused as read-only". It is **not** a persistence signal: `updateSettings` wraps `localStorage.setItem` in a `try`/`catch` that swallows the failure (`useTandemSettings.svelte.ts:120-124`), then assigns and returns `true` (`:127-128`). Say so, so a later reader cannot take it for a durability guarantee.
- `App.svelte`: `if (!layoutModel.toggleLeft()) return;` before `focusToggleTarget("left", nextVisible)` (`:1201-1202`), and the same on the right before `:1218`. **This is a defensive skip of a state change that did not happen, not a focus fix** — on refusal nothing unmounts, so the unguarded call resolves a hidden element and does nothing. The PR body must claim no user-visible delta from it.
- `focusToggleTarget` and its `console.warn` are **unchanged**, and no reachable case for the warn was measured — do not write that it covers a genuine unmount race.
- `toggleLeftPanel` / `toggleRightPanel` keep returning `void`: their consumers (the builtin-action bag at `App.svelte:981-982`, and the markup) all discard.
- **Left as-is, stated rather than discovered:** the float-clearing writes and the reveal teardown + `railPinSnap` block run *before* the toggle (`:1198-1199`, `:1205-1213`), so a refused pin still dismisses a hover float and an open reveal. Re-ordering them to chase a rare refusal risks the `.collapsed.floating` frame the comment at `:1195-1197` exists to prevent; the refusal notification explains why the rail did not move.

**File set:** `src/client/layout/model.svelte.ts`, `src/client/App.svelte`, `tests/client/layout-model.svelte.test.ts`. No markup change, so no testid is added or renamed and the snapshot is untouched.

## Tests

1. **Give `makeSettingsState` the `_readOnly` axis** its `:71-73` comment defers to this group: a second argument whose read-only form applies nothing and returns `false`. This is the harness half that made all six toggle specs structurally blind.
2. **"toggleLeft reports a refused write and changes nothing"**: read-only harness, `expect(model.toggleLeft()).toBe(false)`, and assert the **whole** settings object is unchanged (precedent: the whole-object comparison at `:344-365`; a two-key assertion passes a write that lands elsewhere).
3. **"toggleRight reports a refused write in BOTH branches"**: once visible→hide, once solo-hidden→show. Two cases, because a fix that returns the boolean from only the first branch passes a single-case spec while the show path still reports success.
4. **"toggleLeft/toggleRight report `true` when the write lands"**: the positive twin, without which a constant `false` passes 2 and 3.
5. The existing toggle specs (`:328-449`) keep passing unchanged, ignoring the return value — the regression net for the signature change.
6. **No new E2E.** The only assertion the earlier draft offered (`document.activeElement` is not `<body>` after a refused toggle) is satisfied on master for the reason given in the Problem section, so it would pin nothing; and the rail-did-not-move half pins #1985's short-circuit, not anything this PR changes. **Say plainly in the PR body that the `App.svelte` guard carries no test.**
7. **Mutation test** (memory rule): make `toggleRight` return a constant `true` and watch **spec 3** go red by name; make the harness's read-only form return `true` and watch **specs 2 and 3** go red. Restore from a file copy, never `git checkout`.

## Review corrections (scope cut)

**Removed**

- **`tests/e2e/rail-toggle-readonly.spec.ts` and every `_readOnly` E2E seeding recipe.** Six findings hit this spec, on two mechanisms it did not need: the seeding recipe (an unknown future key stamps nothing — the stamp is gated on `schemaVersion > CURRENT_SCHEMA_VERSION`) and the focus discriminator (green on master). Removing the E2E makes both moot; the substantive behaviour is specs 1–4, which are unit-level and discriminating.
- **The "measure master first" step** (boot a read-only blob, record `document.activeElement` and the console). It existed to decide whether that E2E was worth writing. With no E2E and no focus claim anywhere, nothing hangs on the measurement, so requiring it would be work in service of a deleted assertion.
- **The `<body>`-drop premise**, inherited from the issue title. Refuted in the Problem section with citations, and the `App.svelte` guard is described as what it is.

**Kept**

- The `boolean` returns on both toggles and the `App.svelte` guard — the owner's 2026-09-15 comment names exactly these two as the rail half.
- The `_readOnly` harness axis, which `makeSettingsState`'s own comment assigns to this group and which specs 2–4 need.

**Not adopted**

- **"Re-point the E2E at the rail-did-not-move half plus the #1985 refusal notification"** — that pins #1985's merged code, not this change.
- **"Spy on `HTMLElement.prototype.focus` / `document.querySelector` in a unit test"** — `focusToggleTarget` lives in `App.svelte`, which has no component-level unit harness here; standing one up for a one-line defensive skip is out of proportion, and item 6 states the guard is untested instead of dressing it in a spec that cannot fail.
