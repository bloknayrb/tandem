## Problem

`executeRun` (`src/server/local-model/collaborator.ts`) captures the Y.Doc once — `const ydoc = open.doc;` at `:312` — and hands it to `deps.runTurn({ ydoc, … })` at `:326` for an entire model turn. Hocuspocus replaces a room's Y.Doc in `onLoadDocument` (`src/server/yjs/provider.ts:281-307`: merge state, `existing.destroy()`, `documents.set(documentName, document)`, `lifecycle.onDocSwapped`), so a browser connecting to that room mid-run leaves the loop writing annotations and replies into a destroyed instance — silently, because `Y.Map.set` on a detached doc does not throw. The tool returns `{ok: true}`, the loop records a successful effect, and nothing appears in the UI.

**The issue's quoted code is stale — do not paste it.** `stillOwner` is not a one-conjunct presence test. Measured on `f72c56cb`, `:302-303`:

```ts
const stillOwner = () =>
  current?.token === token && !abort.signal.aborted && requireDocument(req.docName) !== null;
```

Two of the three conjuncts are correct and stay: `current?.token === token` defends against supersession, `!abort.signal.aborted` against cancellation. Only `requireDocument(…) !== null` is wrong, and **neither of the other two sees a swap** — the token is unchanged and nothing aborts. Its twin `isOwner` (`:197-200`, called at `:215`, `:239`, `:287`) has the identical three conjuncts, and the comment at `:298-301` ends "Mirrors the sink's `isOwner()`."

## Fix

`src/server/local-model/collaborator.ts` only. Precedent: `src/server/annotations/lifecycle.ts:81-92` ("A lifecycle is constructed per synchronous operation and is never stored on a long-lived object… anything holding a pre-swap doc… writes into a destroyed doc silently") and `src/server/local-model/tools.ts:304-309`, which states the same hazard at `dispatch`. This run cannot be re-constructed per operation — it *is* the long-lived holder — so it compares identity instead.

1. **`executeRun`: resolve the doc before defining the predicate.** Move `const open = requireDocument(req.docName); if (!open) return; const ydoc = open.doc;` (today `:307`, `:312`) above the `stillOwner` definition, keep `if (!stillOwner()) return;` and the `cachedConfig` guard in their current order, then:
   ```ts
   const stillOwner = () =>
     current?.token === token && !abort.signal.aborted && requireDocument(req.docName)?.doc === ydoc;
   ```
   `?.doc === ydoc` is **false when `requireDocument` returns null**, so identity strictly subsumes the presence check — no separate null test, and the closed-doc behaviour at `:308`/`:344` is unchanged. At `:308` the comparison is trivially true (same call, same instance), so the top-of-run check keeps exactly its current meaning.
2. **Give the sink the same conjunct — deliberately, and say so in the PR body.** `makeSink`'s ctx gains `ydoc: Y.Doc` (it is constructed at `:317`, after the capture); add `const docSwapped = () => requireDocument(ctx.docName)?.doc !== ctx.ydoc;` and replace the third conjunct of `isOwner` with `!docSwapped()`. This is a judgement call, not a mechanical mirror: `appendClaudeChatMessage` / `updateClaudeChatMessage` write to `CTRL_ROOM` (`src/server/mcp/awareness.ts:198`), never to the captured doc, so a swap does **not** discard a sink write. It is changed anyway because (a) the `:298-301` comment declares the two mirrors and a silent divergence is worse than either behaviour, and (b) `isOwner` is the only predicate evaluated *during* the turn, which is what makes 3 possible.
3. **Abort on swap** — the issue's own suggested fix ("aborting the turn if it changed"). One line in `write()` (`:212-225`), after `cancelTimer()` and before the `isOwner()` early return: `if (docSwapped()) ctx.abort.abort();`. `write()` runs only from a deferred timer, never on the `onContentDelta` stack, so this respects the file's nested-txn invariant. It does not disturb #1292's cap ordering at `:238-255`: that comment forbids aborting *before* `write()` so the marker can still land; here a swapped doc has already failed `isOwner`, so no marker was reachable either way. Without this the run keeps issuing tool writes into the destroyed doc until the turn ends; `abort.signal` is already passed to `runTurn` at `:337`.
4. **Comments.** Update `:298-301` to say identity, not presence, and name #1657; the `:244` line ("`stillOwner()` carries the same abort clause") stays true unchanged.

Rules that bite: no Y.Doc write is added, so no origin-tagging change (Critical Rule 2) — the existing `withMcp` chat writes are untouched. No Y.Map key, no `data-testid`, no new MCP tool or `/api` route, no `NON_LOOPBACK_ALLOWED` change, no skill edit.
