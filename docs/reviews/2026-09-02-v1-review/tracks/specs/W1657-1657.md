## Problem

`executeRun` (`src/server/local-model/collaborator.ts`) captures the Y.Doc once — `const ydoc = open.doc;` at `:312` — and hands it to `deps.runTurn({ ydoc, … })` at `:326` for an entire model turn. Hocuspocus replaces a room's Y.Doc in `onLoadDocument` (`src/server/yjs/provider.ts:281-307`: merge state, `existing.destroy()`, `documents.set(documentName, document)`, `lifecycle.onDocSwapped`), so a browser connecting to that room mid-run leaves the loop writing annotations into a destroyed instance — silently, because `Y.Map.set` on a detached doc does not throw. The tool returns `{ok: true}`, the loop records a successful effect, and nothing appears in the UI.

**The issue's quoted code is stale — do not paste it.** `stillOwner` is not a one-conjunct presence test. Measured on `f72c56cb`, `:302-303`:

```ts
const stillOwner = () =>
  current?.token === token && !abort.signal.aborted && requireDocument(req.docName) !== null;
```

Two of the three conjuncts are correct and stay: `current?.token === token` defends against supersession, `!abort.signal.aborted` against cancellation. Only `requireDocument(…) !== null` is wrong, and **neither of the other two sees a swap** — the token is unchanged and nothing aborts. Its twin `isOwner` (defined at `:197-200`, **called exactly once, at `:215`**; the `:239` and `:287` mentions are prose inside comments) carries the identical three conjuncts, and the comment at `:298-301` ends "Mirrors the sink's `isOwner()`."

**Two mechanism facts the fix rests on, both measured:**

- `requireDocument` re-resolves through the provider map on every call — `doc: getOrCreateDocument(current.docName)` (`src/server/documents/registry.ts:354-365`) — so comparing `requireDocument(…)?.doc` against the captured instance actually observes a swap. That is why identity comparison works at all; say so in the PR body.
- `getOrCreateDocument` **creates** on a map miss (`provider.ts:52-63`), so `requireDocument` is non-null whenever the registry entry exists, phantom or not. The existing `:301` sentence "`requireDocument` never fabricates a phantom room" is **false** — do not carry it forward into the rewritten comment.

## Fix

Two files: `src/server/local-model/collaborator.ts` and `src/server/local-model/loop.ts`. Precedent: `src/server/annotations/lifecycle.ts:81-92` ("A lifecycle is constructed per synchronous operation and is never stored on a long-lived object… anything holding a pre-swap doc… writes into a destroyed doc silently") and `src/server/local-model/tools.ts:304-309`, which states the same hazard at `dispatch`. This run cannot be re-constructed per operation — it *is* the long-lived holder — so it compares identity instead.

### 1. `executeRun`: resolve the doc before defining the predicate

Move `const open = requireDocument(req.docName); if (!open) return; const ydoc = open.doc;` (today `:307`, `:312`) above the `stillOwner` definition, keep `if (!stillOwner()) return;` and the `cachedConfig` guard in their current order, then:

```ts
const stillOwner = () =>
  current?.token === token && !abort.signal.aborted && requireDocument(req.docName)?.doc === ydoc;
```

`?.doc === ydoc` is false when `requireDocument` returns null, so **identity subsumes presence and additionally rejects a re-created instance** (a doc evicted from the provider map while the registry entry survives). That added rejection is intended; it is not "behaviour unchanged". At `:308` the comparison is trivially true (same call, same instance), so the top-of-run check keeps its current meaning.

**`ydoc` must be declared before the `stillOwner` definition**, not merely before the first call — the predicate closes over it, and TypeScript does not reliably catch a closure-over-`const` TDZ, so the `:308` call would throw `ReferenceError` at runtime.

### 2. The sink's `isOwner` is deliberately LEFT on presence — this is a reversal from round 0

Round 0 specced mirroring the conjunct into `isOwner`. **Dropped**, for two independent reasons:

- **A swap cannot endanger a sink write.** `appendClaudeChatMessage` / `updateClaudeChatMessage` write to `CTRL_ROOM` (`src/server/mcp/awareness.ts:194-199`), never to the captured doc. A document-room swap leaves those writes perfectly valid.
- **Mirroring would silently delete the #1292 truncation marker on the swap path** — a write that lands correctly today. The cap branch (`:236-255`) commits the marker through `write()`, which would then fail an identity-based `isOwner()` and drop it. Round 0's justification ("a swapped doc has already failed `isOwner`, so no marker was reachable either way") was circular: that unreachability is created by the change itself.

Consequence to state in the PR body: **the two predicates now diverge on purpose**, and the `:298-301` comment must say so rather than claiming a mirror. Post-swap streamed partials still land in `CTRL_ROOM` chat; that is correct, not residue.

### 3. Abort on swap — at the TURN BOUNDARY, not inside `write()`

Add to the sink's ctx a `ydoc: Y.Doc` (the sink is constructed at `:317`, after the capture at `:312`) and a module-local predicate:

```ts
const docSwapped = () => requireDocument(ctx.docName)?.doc !== ctx.ydoc;
```

Call it from **`onTurnEnd` (`:267`), placed AFTER the existing `if (truncated) return;` at `:271`**:

```ts
onTurnEnd: (info) => {
  if (truncated) return;          // #1292: unchanged, and the swap check must stay BELOW it —
  if (docSwapped()) ctx.abort.abort();   // aborting above it would strand the cap marker.
  …
}
```

Round 0 put this line in `write()`. **That is wrong twice** and both are fixed here:

- `write()` runs only when content deltas were pushed (`push()` schedules the only timers, `:255-262`) plus the terminal `flushFinal()` (`:280`, called synchronously from `:347`/`:354`/`:368`/`:386` — so round 0's "`write()` runs only from a deferred timer" was also factually wrong). **A tool-only turn streams no content, so `write()` never runs and the swap was never noticed** — exactly the case #1657 is about (annotation writes silently discarded).
- Inside `write()` the abort precedes the `isOwner()` early return, which already contains `!ctx.abort.signal.aborted`, so it would drop the cap marker as in §2.

`onTurnEnd` fires on **every** turn — `loop.ts:218` (`hadToolCalls: false`) and `loop.ts:221` (`true`) — and is called from the loop body after `await chat()`, never on the `onContentDelta` stack, so the file's nested-txn invariant holds.

**Coverage is complete, not partial, and the reason is worth writing down:** `dispatch` is synchronous and the whole tool-call `for` loop (`loop.ts:229-240`) runs without an await, so the only point at which a swap can interleave is the `await chat()`. A check evaluated once per turn boundary therefore sees every swap before any tool write of the following turn.

### 4. `loop.ts`: honour an abort raised by `onTurnEnd`

`opts.onTurnEnd?.({hadToolCalls: true})` at `:221` runs **after** the existing post-`chat()` abort re-check at `:203-207` and **before** the dispatch loop, so an abort raised there is not seen until the next iteration — the swapped turn's tool writes would still land. Add, immediately after `:221`:

```ts
if (signal?.aborted) {
  metrics.exit = "aborted";
  break;
}
```

Same shape and same comment idiom as the `:203` check. The `hadToolCalls: false` branch needs nothing: it already breaks with `exit = "clean"`, and `executeRun`'s identity-based `stillOwner()` at `:344` suppresses the terminal actions.

### 5. Consequence to record, not to fix silently

Making `stillOwner` identity-based also suppresses the terminal `pushNotification` calls (`:355`, `:369`, `:394`) on a swap. Those go to the notification buffer, not to the captured doc, so they remain *deliverable* after a swap; today presence lets them through. **Decision: keep them inside the gate.** A "the local model stopped before finishing" toast for a run whose document-bound effects were all discarded is a stale message about invisible work, and splitting the gate would leave `executeRun` with two ownership notions. State the choice in the PR body rather than letting it read as an unremarked side effect.

### 6. Comments

Rewrite `:298-301`: identity not presence, name #1657, say the sink deliberately **diverges** (it writes to `CTRL_ROOM`, and its presence test protects the #1292 marker), and say the predicate compares the live instance against the captured one so a re-created *or* replaced instance both read as loss of ownership. **Delete the "never fabricates a phantom room" sentence** — see Problem. The `:244` line ("`stillOwner()` carries the same abort clause") stays true unchanged; add one sentence at the cap branch noting the swap abort sits below the `truncated` latch for exactly the reason that comment gives.

Rules that bite: no Y.Doc write is added, so no origin-tagging change (Critical Rule 2). No Y.Map key, no `data-testid`, no new MCP tool or `/api` route, no `NON_LOOPBACK_ALLOWED` change, no skill edit.

**Alternatives rejected (put a compressed form in the PR body).** Re-resolving the doc per operation — the `lifecycle.ts:81-92` precedent — would let a swapped run *continue* rather than abort, and `onLoadDocument` merges the old state into the new doc (`provider.ts:284-289`), so continuation is defensible. Rejected as larger than the issue asks (it reaches into `loop.ts`'s `dispatch` call and `tools.ts`). The fix therefore trades a silent discard for a silent abort: `exit === "aborted"` is intentionally notification-free (`:398`), and that is left as-is for symmetry with supersede/close.

## Tests

Helper shared by the collaborator arms, faithful to `provider.ts:285-295` — **it must swap, not close: a close is already caught by today's presence check and would stay green against the old code**:

```ts
function swapDoc(id: string, text: string) {
  const old = getOrCreateDocument(id);
  removeDocument(id);                    // provider map entry only
  const fresh = getOrCreateDocument(id); // new instance, same room name
  populateYDoc(fresh, text);
  old.destroy();
  return fresh;
}
```

Extend the existing provider import at `tests/server/local-model/collaborator.test.ts:33` to `import { getOrCreateDocument, removeDocument } from "../../../src/server/yjs/provider.js";` (`removeDocument` is exported at `provider.ts:65` and deletes the map entry only). The registry entry from `setupDoc` (`:134-141`) is left in place, so `requireDocument()` keeps returning non-null throughout — that is the discriminating condition.

**Timing rule for every collaborator arm:** the swap must happen with only **microtasks** awaited since the delta was pushed. Use a deferred released in the same microtask chain; do not `await` a timer.
