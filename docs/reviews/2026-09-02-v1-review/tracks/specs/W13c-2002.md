# W13c — #2002 OutlinePanel counts annotations per heading by stale flat `range.from`, ignoring `relRange`

Branch `fix/client-rail-pulse-outline-and-tutorial-fixes-2014`. Closes #2002. Ledger:
`docs/reviews/2026-09-02-v1-review/areas/crdt.md:23` (the #1823 L row, bullet "OutlinePanel attributes by
stale flat `from`"; `OutlinePanel.svelte:148`, now `:159`). Probe: the new bound-editor spec below, which is
the issue's own "move text under an annotation and assert the count follows it".

## Problem

`src/client/components/OutlinePanel.svelte:136-166`, `headingAnnotationCounts`, resolves each annotation with

```ts
annPositions.push(flatOffsetToPmPos(ed.state.doc, ann.range.from));
```

Flat offsets are the **server's** coordinate system and the stored `range` is only as fresh as the server's
last refresh. Every other client consumer of an annotation position — `extensions/annotation.ts:114`,
`extensions/annotationPing.ts:148`, `useMarginPositions.svelte.ts:144`, `useAnnotationReview.svelte.ts:308`
— goes through `annotationToPmRange(ann, doc, ydoc)`, which prefers the CRDT-anchored `relRange` and falls
back to flat (`src/client/positions.ts:485-509`). The outline is the one place that does not, so after a
local edit moves text and before the server refresh lands, an annotation buckets under the wrong heading.

**Measured bound, confirmed in the worktree:** the count is inert today. `App.svelte:2436-2442` and
`:2447-2453` render the outline `PanelSlot` with `focusTrigger`, `editor`, `headings` and `visible` only —
no `annotations`, no filter props — so `annotations` defaults to `[]` (`OutlinePanel.svelte:28`) and the
badge never renders. The issue anticipates this and says to fix it anyway, "because a wrong count is not
something anyone would think to look for". This spec agrees, and does **not** wire `annotations` up — that
is a feature, not this fix.

## Fix

Use the shared resolver, and give the panel the one input it needs to do so. Three files, no new mechanism.

**`src/client/components/OutlinePanel.svelte`:**
- Import `annotationToPmRange` from `../positions` instead of `flatOffsetToPmPos` (same module; the import
  at `:9` is the only consumer of `flatOffsetToPmPos` in this file).
- Add `ydoc?: Y.Doc | null` to `Props` and destructure it with `ydoc = null` (`import type * as Y from "yjs"`,
  type-only — the panel never constructs or writes a doc). **Optional with a null default is load-bearing:**
  `annotationToPmRange` takes `ydoc: Y.Doc | null` and falls back to flat offsets when it is null, which is
  exactly today's behaviour, so the existing three-arg-less test callers and both `PanelSlot` branches keep
  compiling and keep passing.
- In `headingAnnotationCounts`, inside the existing `try`, **null-guarded — not a bare `.from`**:

  ```ts
  const resolved = annotationToPmRange(ann, ed.state.doc, ydoc);
  if (!resolved) continue;
  annPositions.push(resolved.from);
  ```

  `annotationToPmRange` is typed `PmRangeResult | null` (`src/client/positions.ts:485-509`; it returns
  `null` when `relRange` does not resolve and `ann.range` is absent), so
  `annotationToPmRange(...).from` is a strict-null-checks error and would fail the spec's own
  "`npm run typecheck` green" Done-when. **`!` and `?.` are both forbidden**: a non-null assertion throws a
  `TypeError` straight into the surrounding `catch`, and `?.from` pushes `undefined` into a `number[]`.
  Every other consumer already null-checks — `extensions/annotation.ts:114-115`. The null arm is a *skip*,
  the same outcome the `catch` produces, and it is worth a one-line comment saying so.
- The `catch` stays, but **its rationale in the code comment must not claim an out-of-range throw**: the flat
  fallback does not throw on an out-of-range offset, it clamps — `flatOffsetToPmPos` falls out of its loop
  and returns the end of the last block (`src/client/positions.ts:260-277`), so a stale offset past the end
  silently buckets under the last heading (unchanged from today). The `catch` covers
  `resolveWithinNode`/doc-shape failures.
- `.from` is the right endpoint: it is what `range.from` was.
- `ydoc` is a `$props()` member, so the `$derived.by` picks it up as a dependency with no extra work.

**`src/client/components/PanelSlot.svelte`:** add `ydoc?: Y.Doc | null` to `OutlineSlotProps` (`:26-35`) and
pass `ydoc={(rest as OutlineSlotProps).ydoc}` in **both** `kind === "outline"` branches (`:63-71` and
`:79-85`).

**`src/client/App.svelte`:** pass `ydoc={activeTab?.ydoc ?? null}` on **the one** outline `PanelSlot`,
`:2436` — the same expression already used at `:2320`, `:2348`, `:2560`. **There is exactly one.** An
earlier draft named a second at `:2447`; that is the `<PeekStrip side="left" … kind="outline" … />` at
`:2445-2451`, a different component whose `kind` is an unrelated prop — `grep -n "<PanelSlot"
src/client/App.svelte` returns `2436`, `2537`, `2556`, and the latter two are chat and side. Putting `ydoc`
on `PeekStrip` would be an unknown prop. The `PanelSlot.svelte` half is unchanged from the draft: its **two**
`kind === "outline"` template branches (`:63-71` and `:79-85`) are real and both need the pass-through.
This thread-through is what makes the fix real the day `annotations` is wired; without it the panel would
resolve with a permanent `null` ydoc and the bug would survive the rename.

Rules that bite: no Y.Doc **write** anywhere here, so no `src/shared/origins.ts` helper and no `Y.Map` key —
the panel only reads through `relRangeToPmPositions`. Never a raw offset: `annotationToPmRange` is the only
new call. No `data-testid` added, renamed or removed, so `__snapshots__/testid-set.snap.txt` is untouched.
No colour — the badge's tokens at `:331-345` are unchanged.

## Tests

`tests/client/outline-annotation-counts.test.ts` (new; a separate file from `OutlinePanel.svelte.test.ts`,
which is `happy-dom` + `render` with `editor: null` and would gain a Yjs/Tiptap import for nothing). The
nearest neighbour is `tests/client/outline-panel-author-filter.test.ts` — real annotations, `OutlinePanel`,
and the `countBadge(container)` helper at `:57-68` — but it renders with no real editor and no Y.Doc, so
this file is separate rather than an extension of it; **confirm its four existing cases still pass after the
resolver swap** (they pass `annotations` with no `ydoc`, so they exercise the flat fallback, which is
unchanged).

The harness is `tests/client/decoration-survives-sync.test.ts:63-82`'s `boundEditor`: a real `Y.Doc`,
`loadMarkdown`, a real `Editor` with `buildSchemaExtensions()` + `Collaboration` + `AnnotationExtension`, and
`rangeOf` (`extractText`, the server projection — `doc.textBetween` drops the `"## "` prefix and this
fixture has headings, so that distinction is not theoretical here). `anchorFlatRange`
(`src/shared/positions/ydoc.ts`) mints the `relRange`, as that file already does.

Fixture: `## Alpha\n\nfirst body\n\n## Beta\n\nsecond body\n` — one annotation on `second body`, i.e.
under Beta. `headings` is built from the PM doc the way `createHeadings` does
(`src/client/utils/headings.ts:55`).

**Assert on the rendered badge, via `countBadge`.** The count pill renders only under `{#if count > 0}` and
carries no `data-testid` (`OutlinePanel.svelte:331-350`), so "the trailing count span of
`outline-heading-2-0`" does not exist for a zero count. Reuse
`outline-panel-author-filter.test.ts:57-68`'s `countBadge` helper — it finds the pill by its
`title$='annotation(s)'` attribute and returns `null` when absent — parameterised by heading index, and
phrase every expectation as "Alpha: no badge; Beta: badge text `1`". **No `data-testid` is added**, so
`__snapshots__/testid-set.snap.txt` stays untouched (Critical Rule 7).

1. **Baseline.** Render `OutlinePanel` with `editor`, `headings`, `annotations: [ann]`, `ydoc` → Alpha no
   badge, Beta `1`. Kills a fix that resolves everything to position 0.
2. **The discriminating spec.** **Render through `PanelSlot` with `kind="outline"` and `ydoc`, not through
   `OutlinePanel` directly.** This is the only spec that exercises the slot hop, and the hop cannot fail
   closed at the type level: `PanelSlot`'s prop union carries a catch-all member
   `| { kind: "chat" | "side" | "outline"; visible?: boolean; [key: string]: any }`
   (`src/client/components/PanelSlot.svelte:38-43`), so a missing `ydoc` on `OutlineSlotProps` or a missing
   `ydoc=` at the `App.svelte` call site is not a compile error. Without this, an implementation that edits
   `OutlinePanel` and its unit specs while forgetting `PanelSlot`/`App` is fully green with the bug intact.

   Then: insert **exactly 30 characters** into the Alpha body paragraph through the editor
   (`editor.commands.insertContentAt`), leaving `ann.range` at its pre-edit values — precisely the "server
   has not refreshed the stored flat range yet" state. **The length is arithmetic, not taste.** Flat text is
   `## Alpha\nfirst body\n## Beta\nsecond body` (`extractText` joins elements with a single
   `FLAT_SEPARATOR` — `src/server/mcp/document-model.ts:184`, `src/shared/offsets.ts:13`), so
   `rangeOf("second body")` is `{ from: 28 }` and the Beta heading's flat start is `20`. After inserting `N`
   characters into `first body` the Beta heading starts at `20 + N`, and `flatOffsetToPmPos` maps any offset
   **inside** the heading block — the `"## "` prefix included — to `resolveWithinNode(child, 0,
   childStart)`, i.e. heading `pos + 1` (`src/client/positions.ts:222-244`), which still satisfies
   `p >= h.pos` for the Beta bucket (`OutlinePanel.svelte:164-169`; `h.pos` is the heading node position,
   `src/client/utils/headings.ts:55`). So for any `N <= 8` the stale `28` is still inside `## Beta` and the
   count reads `[0, 1]` **on master too** — "insert several characters", as round 0 wrote it, proves
   nothing. `N = 30` puts `28` well inside the grown Alpha body. Better still: compute the required length
   from `rangeOf`/`extractText` in the test rather than hard-coding it, and assert the derivation.

   **Re-render with a rebuilt `headings` array.** `headingAnnotationCounts` is a `$derived.by` whose tracked
   inputs are `editor` (identity), `headings`, `annotations` and the three filter props
   (`OutlinePanel.svelte:136-169`); it reads `ed.state.doc` imperatively and a Tiptap transaction is
   invisible to Svelte's dependency graph. Re-rendering with the **same** `headings` reference therefore
   recomputes nothing and the assertion reads the pre-edit numbers on fixed and unfixed code alike. So
   recompute `headings` from the post-edit `ed.state.doc` the way `createHeadings` does — a fresh array
   with fresh `pos` values, which is also what `App.svelte` really does — and pass **that** to `rerender`.

   Expect Alpha no badge, Beta `1` on the fix. **Record the master control explicitly: on today's code the
   same spec reads Alpha `1`, Beta no badge**, and assert the two differ rather than only asserting the
   fixed value, so a stale derived cannot look like a pass. Kills the current implementation and any fix
   that keeps reading `ann.range.from`.
3. **Fallback preserved.** Same annotation with `relRange` deleted and `ydoc` passed → still counts under
   Beta on the un-edited document. Kills a fix that hard-requires `relRange` and drops flat-only annotations
   (imported Word comments carry no `relRange`; `annotationToPmRange` warns and falls back, and this pins
   that the panel keeps them).
4. **`ydoc` omitted** (the prop's default) → same result as 3, no throw. Kills a non-optional prop, and pins
   that `PanelSlot`'s existing callers cannot regress to a crash.
5. **The null arm is a skip.** An annotation with neither `relRange` nor `range` (so `annotationToPmRange`
   returns `null`) alongside the Beta annotation → Beta still reads `1`, no throw. Kills a bare `.from`,
   a `!` assertion and a `?.from` that pushes `undefined`.
6. **App.svelte passes `ydoc` on the outline slot.** A source-claims assertion (the shape
   `tests/docs/*-claims.test.ts` uses): read `src/client/App.svelte`, find the single `<PanelSlot`
   occurrence with `kind="outline"`, and assert its attribute block contains `ydoc=`. Needed because the
   catch-all union member means the call site cannot fail closed at the type level; an E2E over the outline
   badge would be acceptable instead, a type change would not.

## Done when

`flatOffsetToPmPos` no longer appears in `OutlinePanel.svelte`, and the new call is the null-guarded
three-line form (no `!`, no `?.`); `ydoc` is threaded panel → slot → App on the one outline `PanelSlot`
and both of `PanelSlot`'s outline branches; the six specs pass; **spec 2 is observed red on stashed master
with the recorded control value (Alpha `1`, Beta none)** before the PR goes up; `npm run typecheck` and
`npm run typecheck:tests` green.

## Not in scope

Wiring `annotations` / `activeFilter*` into the outline `PanelSlot` (a feature — #1714's filter parity note
at `OutlinePanel.svelte:152-157` stays true and stays inert). The pre-existing prop drift between
`PanelSlot`'s two outline branches (`:79-85` omits `activeFilterAuthor`/`activeFilterStatus`) — noted in the
PR body, not fixed here. The other #1823 CRDT Lows. `src/server/positions.ts`.

**Making the count live.** Threading `ydoc` in makes the resolution CRDT-anchored, **not** independently
reactive: the `$derived.by`'s tracked inputs remain `editor`, `headings`, `annotations` and the filters, and
`relRangeToPmPositions` reads the Y.Doc imperatively with nothing subscribed to it. In practice `headings`
does move on document edits (`App.svelte`'s `createHeadings`), which is what keeps this from being a new
defect and is why spec 2 rebuilds `headings`. Making the derived independently live is out of scope — do
not read the thread-through as a liveness guarantee.
