# W13c — #2002 OutlinePanel counts annotations per heading by stale flat `range.from`, ignoring `relRange`

Branch `fix/client-rail-pulse-outline-and-tutorial-fixes-2014`. Closes #2002. Ledger:
`docs/reviews/2026-09-02-v1-review/areas/crdt.md:23` (the #1823 L row, bullet "OutlinePanel attributes by
stale flat `from`").

## Problem

`src/client/components/OutlinePanel.svelte:136-166`, `headingAnnotationCounts`, resolves each annotation with

```ts
annPositions.push(flatOffsetToPmPos(ed.state.doc, ann.range.from));
```

Flat offsets are the **server's** coordinate system and the stored `range` is only as fresh as the server's
last refresh. Every other client consumer (`extensions/annotation.ts:114`, `extensions/annotationPing.ts:148`,
`useMarginPositions.svelte.ts:144`, `useAnnotationReview.svelte.ts:308`) goes through
`annotationToPmRange(ann, doc, ydoc)`, which prefers the CRDT-anchored `relRange` and falls back to flat
(`src/client/positions.ts:485-509`). The outline is the one place that does not, so after a local edit moves
text and before the server refresh lands, an annotation buckets under the wrong heading.

**Measured bound:** the count is inert today. `App.svelte:2436-2442` renders the outline `PanelSlot` with
`focusTrigger`, `editor`, `headings` and `visible` only, so `annotations` defaults to `[]`
(`OutlinePanel.svelte:28`) and the badge never renders. The issue anticipates this and says to fix it anyway,
"because a wrong count is not something anyone would think to look for". This spec agrees and does **not**
wire `annotations` up — that is a feature, not this fix.

## Fix

Use the shared resolver, and give the panel the one input it needs. Three files, no new mechanism.

**`src/client/components/OutlinePanel.svelte`:**
- Import `annotationToPmRange` from `../positions` instead of `flatOffsetToPmPos` (the import at `:9` is this
  file's only consumer of the latter).
- Add `ydoc?: Y.Doc | null` to `Props` and destructure with `ydoc = null` (`import type * as Y from "yjs"`).
  **Optional with a null default is load-bearing:** `annotationToPmRange` takes `ydoc: Y.Doc | null` and
  falls back to flat offsets when it is null — exactly today's behaviour — so existing callers keep
  compiling and passing.
- In `headingAnnotationCounts`, inside the existing `try`, **null-guarded, not a bare `.from`**:

  ```ts
  const resolved = annotationToPmRange(ann, ed.state.doc, ydoc);
  if (!resolved) continue; // same skip the catch performs
  annPositions.push(resolved.from);
  ```

  It is typed `PmRangeResult | null` (`positions.ts:485-509`), so `annotationToPmRange(...).from` is a
  strict-null-checks error. **`!` and `?.` are both forbidden**: the assertion throws a `TypeError` into the
  surrounding `catch`, and `?.from` pushes `undefined` into a `number[]`. `extensions/annotation.ts:114-115`
  is the precedent.
- The `catch` stays, but **its comment must not claim an out-of-range throw**: `flatOffsetToPmPos` clamps
  (`positions.ts:260-277`); the `catch` covers `resolveWithinNode`/doc-shape failures. `.from` is the right
  endpoint — it is what `range.from` was — and `ydoc`, being a `$props()` member, is picked up by the
  `$derived.by` with no extra work.

**`src/client/components/PanelSlot.svelte`:** add `ydoc?: Y.Doc | null` to `OutlineSlotProps` (`:26-35`) and
pass `ydoc={(rest as OutlineSlotProps).ydoc}` in **both** `kind === "outline"` branches (`:63-71`, `:79-85`).

**`src/client/App.svelte`:** pass `ydoc={activeTab?.ydoc ?? null}` on **the one** outline `PanelSlot`,
`:2436` — the expression already used at `:2320`, `:2348`, `:2560`. **There is exactly one**
(`grep -n "<PanelSlot" src/client/App.svelte` → `2436`, `2537`, `2556`; the latter two are chat and side).
An earlier draft named a second at `:2447`; that is the `<PeekStrip side="left" … kind="outline" … />` at
`:2445-2451`, a different component whose `kind` is an unrelated prop. Without this thread-through the panel
resolves with a permanent `null` ydoc and the bug survives the rename.

No Y.Doc **write** anywhere, so no `src/shared/origins.ts` helper and no `Y.Map` key. Never a raw offset.
No `data-testid` added, renamed or removed, so `__snapshots__/testid-set.snap.txt` is untouched. No colour.

## Tests

`tests/client/outline-annotation-counts.test.ts` (new). Harness:
`tests/client/decoration-survives-sync.test.ts:63-82`'s `boundEditor` — real `Y.Doc`, `loadMarkdown`, real
`Editor` with `buildSchemaExtensions()` + `Collaboration` + `AnnotationExtension`, plus `rangeOf`
(`extractText`, the server projection) and `anchorFlatRange` (`src/shared/positions/ydoc.ts`) to mint the
`relRange`. Fixture: `## Alpha\n\nfirst body\n\n## Beta\n\nsecond body\n`, one annotation on `second body`
(under Beta); `headings` is built from the PM doc the way `createHeadings` does
(`src/client/utils/headings.ts:55`). Assert on the rendered badge via
`outline-panel-author-filter.test.ts:57-68`'s `countBadge` helper (it finds the pill by
`title$='annotation(s)'` and returns `null` when absent — the pill renders only under `{#if count > 0}` and
carries no testid), phrased as "Alpha: no badge; Beta: badge text `1`". **Confirm that file's four existing
cases still pass** after the resolver swap; they pass no `ydoc`, exercising the unchanged flat fallback.

1. **Baseline.** Render `OutlinePanel` with `editor`, `headings`, `annotations: [ann]`, `ydoc` → Alpha no
   badge, Beta `1`. Kills a fix that resolves everything to position 0.
2. **The discriminating spec.** **Render through `PanelSlot` with `kind="outline"` and `ydoc`**, not through
   `OutlinePanel` directly — that is the only exercise of the slot hop, and the hop cannot fail closed at the
   type level because `PanelSlot`'s prop union carries a catch-all member
   `| { kind: "chat" | "side" | "outline"; visible?: boolean; [key: string]: any }` (`PanelSlot.svelte:38-43`).

   Insert **at least 30 characters** into the Alpha body paragraph (`editor.commands.insertContentAt`),
   leaving `ann.range` at its pre-edit values — the "server has not refreshed yet" state. **The length is
   arithmetic, not taste.** Flat text is `## Alpha\nfirst body\n## Beta\nsecond body` (`extractText` joins
   elements with a single `FLAT_SEPARATOR` — `src/server/mcp/document-model.ts:184`,
   `src/shared/offsets.ts:13`), so `rangeOf("second body")` is `{ from: 28 }` and the Beta heading's flat
   start is `20`. `flatOffsetToPmPos` maps any offset **inside** a heading block, `"## "` prefix included, to
   heading `pos + 1` (`positions.ts:222-244`), which still satisfies `p >= h.pos` for the Beta bucket
   (`OutlinePanel.svelte:164-169`) — so for any `N <= 8` the stale `28` reads `[0, 1]` **on master too**.
   Prefer computing the length from `rangeOf`/`extractText` over hard-coding it.

   **Re-render with a rebuilt `headings` array.** `headingAnnotationCounts` is a `$derived.by` whose tracked
   inputs are `editor`, `headings`, `annotations` and the filter props (`:136-169`); it reads `ed.state.doc`
   imperatively, and a Tiptap transaction is invisible to Svelte's dependency graph, so a re-render with the
   **same** `headings` reference recomputes nothing and reads the pre-edit numbers on fixed and unfixed code
   alike. Recompute `headings` from the post-edit doc the way `createHeadings` does — a fresh array with
   fresh `pos` values, which is what `App.svelte` really does — and pass that.

   Expect Alpha no badge, Beta `1` on the fix; **the master control is Alpha `1`, Beta no badge**. Assert the
   two differ, so a stale derived cannot look like a pass.
3. **Fallback preserved.** Same annotation with `relRange` deleted and `ydoc` passed → still counts under
   Beta on the un-edited document. Kills a fix that hard-requires `relRange` and drops flat-only annotations
   (imported Word comments carry none).
4. **The null arm is a skip.** An annotation with neither `relRange` nor `range` alongside the Beta
   annotation → Beta still reads `1`, no throw. Kills a bare `.from`, a `!` assertion and a `?.from`.
