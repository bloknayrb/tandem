## Problem

Both layers are from the issue body and both re-verified:

1. **Today:** `const LICENSE_UPDATE_ENDPOINT: &str = "";` (`lib.rs:178`) is a **second** const that must flip at v1.0, in a second language, with nothing linking it to `LICENSE_GATE_ENABLED` (`tsup.config.ts:20`). `entitled_license_id` (`:2321-2336`) opens with `if LICENSE_UPDATE_ENDPOINT.is_empty() { return None; }`, and `build_updater`'s `None` arm (`:2355`) is `app.updater()` — the **public** manifest from `tauri.conf.json:107-109`. Flip the tsup const alone and the run gate arms while the update window stays inert.
2. **After the flip:** `entitled_license_id` returns `None` whenever `update_window_current` is false — and that `None` lands on the same public manifest. A customer whose year is up is offered exactly the builds everyone else gets. The const is necessary and not sufficient.

## Fix

**Rust (`src-tauri/src/lib.rs`) — make the route a three-way and let the Worker keep deciding entitlement for anyone who reaches it.** The issue names the choice: *"the `tauri.conf.json` endpoint has to be neutralised, **or** the `None` arm has to mean 'no updates'."* Take the second: it is the one that cannot be forgotten at flip time.

```rust
/// Which manifest an update check may use. Three outcomes, not two: today's
/// `Option<String>` collapsed "no Worker configured", "gate dark", "trial" and
/// "not entitled" onto one `None`, and that `None` is the PUBLIC manifest (#1785).
#[derive(Debug, PartialEq)]
enum UpdateRoute {
    /// The public manifest from `tauri.conf.json`. Reached while no endpoint is
    /// compiled in (pre-v1.0, byte-identical to shipped behaviour), when the
    /// sidecar reports the gate dark, for a TRIAL device, and for any probe body
    /// that does not positively say `restricted` — an evaluator, and an older or
    /// scrubbed sidecar, keep receiving builds exactly as today.
    Public,
    /// This device holds a license id: the Worker, with the opaque
    /// `X-Tandem-License-Id`. Sent even when the LOCAL update window has ended —
    /// the Worker's KV is the authority and its `expired` reason is the detector
    /// #1786 (H-b) hangs off. A client that short-circuits on its own copy of the
    /// window turns that branch into dead code in production.
    Licensed(String),
    /// Serve NO manifest — never the public one. A restricted device, or a probe
    /// that could not answer at all. The reason is carried for the log line only.
    NoUpdates(&'static str),
}
```

`#[derive(Debug, PartialEq)]` is required, not decorative: `assert_eq!(update_route(…), UpdateRoute::Public)` needs both.

- **`LicenseStatusResponse` gains `#[serde(default)] status: Option<String>`.** Today it deserializes only `gate_active` / `license_id` / `update_window_current` (`:2303-2312`), which makes **trial and restricted indistinguishable in Rust** — and both report `update_window_current: false` (`license-state.ts:136`, `:150`), so without this field any "not entitled ⇒ no manifest" rule freezes every evaluator on the day the gate flips. The wire already carries it: `toLicenseStatusWire` returns the active `LicenseState` arms verbatim (`src/server/mcp/routes/license.ts:22-52`) and the updater probes loopback, so it gets the unscrubbed shape. `#[serde(default)]` keeps a partial body from failing deserialization, exactly like its siblings.
- **`fn update_route(endpoint: &str, probe: Option<&LicenseStatusResponse>) -> UpdateRoute`** — pure, synchronous, `#[cfg(test)]`-reachable, no `AppHandle`. **The parameter is `probe`, never `status`**: the struct gained a `status` FIELD one bullet above, and a parameter of the same name makes step 2 (*no response at all*) and step 5 (*the response's `status` field*) read as the same test. In order:
  1. `endpoint.is_empty()` ⇒ `Public` — the shipped path, byte-identical.
  2. `probe.is_none()` ⇒ `NoUpdates("status-unavailable")` — **fail closed**: this is the product's only post-purchase control, and an unreachable sidecar means Tandem is barely running anyway.
  3. `!probe.gate_active` ⇒ `Public` — a sidecar reporting a dark gate against a configured endpoint is a mismatched build, not an entitlement question.
  4. `probe.license_id: Some(id)` ⇒ `Licensed(id)`, **regardless of `update_window_current`**.
  5. `probe.status.as_deref() == Some("restricted")` ⇒ `NoUpdates("no-entitlement")`.
  6. otherwise ⇒ `Public`.
  Steps 5 and 6 are deliberately *deny-by-name* rather than allow-by-name: a trial device, a scrubbed body and an older sidecar that predates the `status` field all land on `Public`, which is today's behaviour and no regression, whereas the opposite default freezes evaluators. `update_window_current` stops being the routing discriminant and is carried into the `Licensed` arm's log line, so the local view and the Worker's `reason` can be correlated and the field is not dead.
- **`entitled_license_id` becomes `async fn resolve_update_route(app: &tauri::AppHandle) -> UpdateRoute`** — same body, same "never errors" discipline, same probe, and it **keeps the endpoint check first, so while the const is empty it returns `Public` without probing at all**. That early return is the byte-identity argument for the whole change.
- **`build_updater` returns `Result<Option<Updater>, String>`; `None` means "no manifest served".** `Public` ⇒ `Ok(Some(app.updater()?))` (unchanged). `Licensed(lid)` ⇒ `Ok(Some(…endpoints(vec![endpoint])…header("X-Tandem-License-Id", lid)…))` (unchanged). `NoUpdates(reason)` ⇒ **`log::warn!`** naming the reason, then `Ok(None)`. `Url` parsing stays inside the `Licensed` arm, so a malformed configured endpoint is still `Err`, not a silent fall-through to public.
  **`log::warn!`, not `log::info!`, and this is not style.** `lib.rs:1166-1170` sets `LevelFilter::Warn` for release builds, so an `info!` writes **zero bytes** — the crate records that exact trap at `:200` as the #1416 bug. This is the fail-closed "no updates" state on an unattended 8-hourly path.
- **Both callers.** `check_for_update` (`:2360`): `Ok(Some(u)) => u` (unchanged), `Err(e) =>` unchanged, and a new `Ok(None) =>` arm that logs at `warn` and, when `manual`, calls `show_update_error_dialog(app, …)` with a plain placeholder line — **never `show_up_to_date_dialog`**, because "You're running the latest version" is the exact lie #1786 exists to detect. `install_update` (`:2431`): `Ok(None)` ⇒ `Err("UPDATE_WITHHELD".to_string())` — machine-readable, because the neighbouring `.ok_or_else(|| "No update available")` means something genuinely different. **#1819 (H-c) owns the final wording** and may split the placeholder into its own dialog; say so in a comment.
  **State the boundary rather than overclaiming it:** a `Licensed` device whose *Worker-side* entitlement has lapsed receives a 204 from the Worker and is still told "up to date". The client genuinely cannot distinguish that — CLAUDE.md's "the Worker's `reason` enum is the only detector" is about exactly this case, and it is #1786's to surface.

## For Bryan (PR body)

1. **Restricted installs receive no in-app update after the flip** (`NoUpdates(NoEntitlement)`): no request is issued, the user gets an honest line on a manual check rather than "You're up to date", and the auto path logs at `warn`. It is a change for that population against today, which currently receives real public builds. The alternative arm is `Public` (as today), and it is one `match` arm to reverse with a named test case pinning it.

   **It withholds SECURITY patches, not only feature builds, and the decision should be taken knowing that.** A restricted install still runs: it binds Express on `127.0.0.1:3479` and Hocuspocus on `:3478`, still opens local files, still serves `/api` and the MCP surface — restricted clamps *writes*. So a machine that stops buying keeps running the loopback servers indefinitely, and a future fix for a loopback-reachable issue of a class this codebase has already had (the CORS `null`-origin grant #1291, the `/api/save` simple-request CSRF, the UNC/NTLM path) never reaches it: `.endpoints()` **replaces** the manifest list rather than falling back, the 8-hourly `check_for_update` issues no request, and the only trace is a `log::warn!` the user never sees. Frozen-at-installed-version is the real shape of this arm. The narrower alternative, if that is the wrong trade: keep `NoUpdates` for feature builds but let security releases come from the public manifest — still one arm, but it needs the manifest split first, so it is a Worker-side decision rather than a one-line reversal.

   The privacy side is genuinely better: it keeps restricted devices off Tandem's Cloudflare Worker entirely, which `docs/security.md` notes has platform-level request logging outside Tandem's control, and it keeps "only outbound traffic is loopback plus the public release host" true after the flip.
2. **Trial installs keep receiving public builds**, as does any probe body that does not positively say `restricted` (older sidecar, scrubbed body). Stated because the first draft withheld them silently: every trialing device reports `update_window_current: false`, so a blanket "not entitled ⇒ no manifest" would have frozen every evaluator the day the gate flips.
