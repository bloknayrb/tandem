Branch `fix/armed-license-gate-correctness-and-the-second-const-that-must-flip-with-the-first-1788`. Closes #1785. Ledger: `docs/reviews/2026-09-02-v1-review/areas/armed-license-gate.md:18-19` and `areas/infra-license-worker.md:18`. Probe: none — the whole path is unreachable while the const is empty; the evidence is `src-tauri/src/lib.rs` read directly (line numbers re-verified against `master` @ `06403bec`).

**Nothing here flips.** `LICENSE_UPDATE_ENDPOINT` stays `""`. The deliverable is the *link* between the two consts, so that flipping one without the other is loud, plus the "no updates" branch the issue's own suggested fix names. Neutralising `tauri.conf.json`'s public endpoint, and any Worker deploy, is Bryan's at flip time.

## Problem

Two layers, both from the issue body, both re-verified:

1. **Today:** `const LICENSE_UPDATE_ENDPOINT: &str = "";` (`lib.rs:178`) is a **second** const that must flip at v1.0, in a second language, with nothing linking it to `LICENSE_GATE_ENABLED` in `tsup.config.ts:20`. `entitled_license_id` (`lib.rs:2321-2336`) opens with `if LICENSE_UPDATE_ENDPOINT.is_empty() { return None; }`, and `build_updater`'s `None` arm (`:2342-2357`) is `app.updater()` — the **public** manifest from `tauri.conf.json:107-109`. Flip the tsup const alone and the run gate arms while the update window stays inert.
2. **After the flip:** `entitled_license_id` also returns `None` for "gate active, window expired" — and that `None` lands on the same public manifest. A customer whose year is up is offered exactly the builds everyone else gets, so the update window still gates nobody. The const is necessary and not sufficient.

`docs/security.md:181` and `docs/licensing-explained.md:15-24, :448-453` already describe (1) accurately after #1821's sweep; their line citations (`:171`, `:2298`, `:2317-2332`) have drifted and their "neutralising the public endpoint is part of the flip" sentence stops being true once (2) is fixed here.

## Fix

**Rust — make the route a four-way, and let the Worker keep deciding entitlement (`src-tauri/src/lib.rs`).** The issue names the choice: *"the `tauri.conf.json` endpoint has to be neutralised, **or** the `None` arm has to mean 'no updates'."* Take the second, because it is the one that cannot be forgotten at flip time — but "no updates" must not be spelled *"send no request at all"*, which is the shape review killed and the next section explains.

```rust
/// Which manifest an update check may use. Four outcomes, not two: today's
/// `Option<String>` collapsed "no Worker configured", "configured but this
/// device holds no license id" and "configured, entitlement expired" onto one
/// `None`, and that `None` is the PUBLIC manifest (#1785).
#[derive(Debug, PartialEq)]
enum UpdateRoute {
    /// The public manifest from `tauri.conf.json`. Reached while no endpoint is
    /// compiled in (pre-v1.0, byte-identical to shipped behaviour), when the
    /// sidecar reports the gate dark, and for a TRIAL device — an evaluator
    /// keeps receiving builds exactly as today.
    Public,
    /// This device holds a license id: the Worker, with the opaque
    /// `X-Tandem-License-Id`. Sent even when the LOCAL update window has ended —
    /// the Worker's KV is the authority and its `expired` reason is the detector.
    Licensed(String),
    /// An endpoint IS compiled in and this device has no license id to send
    /// (restricted). The Worker, with NO header: it answers the byte-identical
    /// 204 and logs `no-header`, so the install is withheld AND visible to the
    /// operator. The USER is told the truth by `check_for_update`, which branches
    /// on this route in its `Ok(None)` arm — a 204 here means "withheld", never
    /// "you're up to date" (#1785 blocking finding, round 3).
    Unidentified,
    /// Configured, but the loopback probe could not answer at all. Serve NO
    /// manifest — never the public one. Client-side only, so #1786 (H-b) must
    /// hang its copy off this reason string, not off the Worker's enum. The
    /// reason is RETURNED (see `UpdateOutcome` below), not merely logged —
    /// a log line is not a value #1786 can branch on, and at release log level
    /// it is not even written.
    Withheld(&'static str),
}
```

**`#[derive(Debug, PartialEq)]` is required, not decorative:** `assert_eq!(update_route(…), UpdateRoute::Public)` needs both, and `check_for_update`'s `Ok(None)` arm compares `route == UpdateRoute::Unidentified`. `UpdateOutcome` needs neither — nothing compares or prints it.

- **`LicenseStatusResponse` gains `#[serde(default)] status: Option<String>`.** Today it deserializes only `gate_active` / `license_id` / `update_window_current` (`:2303-2312`), which makes trial, restricted and licensed-with-expired-window **indistinguishable in Rust** — the classifier literally cannot express the decision below without it. The wire already carries it: `toLicenseStatusWire` returns the active `LicenseState` arms verbatim (`src/server/mcp/routes/license.ts:22-52`), and the updater probes loopback, so it gets the unscrubbed shape. `#[serde(default)]` keeps a scrubbed or partial body from failing deserialization, exactly like its siblings.
- **`fn update_route(endpoint: &str, probe: Option<&LicenseStatusResponse>) -> UpdateRoute`** — pure, `#[cfg(test)]`-reachable, no `AppHandle`, and synchronous so its cases need no runtime at all. **The parameter is named `probe`, never `status`**: the struct gained a `status` FIELD one bullet above, and the two referents sit one step apart in the order below. A parameter called `status` makes step 2 (*the whole probe response is absent*) and step 6 (*the response's `status` field reads `trial`*) look like the same test, which is how rules 2 and 6 get implemented as one. In order:
  1. `endpoint.is_empty()` ⇒ `Public`.
  2. `probe.is_none()` — no response at all — ⇒ `Withheld("status-unavailable")` — **fail closed**: this is the product's only revenue control, and the sidecar being unreachable means Tandem is barely running anyway.
  3. `!probe.gate_active` ⇒ `Public` — a sidecar reporting a dark gate against a configured endpoint is a mismatched build, not an entitlement question.
  4. `probe.license_id: Some(id)` ⇒ `Licensed(id)`, **regardless of `update_window_current`**.
  5. `probe.status.is_none()` ⇒ `Public` — **the response arrived but carries no `status` field.** `#[serde(default)]` makes that shape reachable from a scrubbed, partial or version-skewed body, and it is a *build-skew* signal rather than an entitlement answer, so it must not fall through to step 7. It routes `Public` because the two ways to be wrong are not symmetric: `Public` for a restricted device is today's behaviour and no regression, while `Unidentified` for a **trial** device freezes an evaluator on their installed build — the exact failure For-Bryan item 2 exists to prevent, and an older sidecar that predates the `status` field cannot tell the two populations apart. Step 4 still wins first, so a licensed device with a skewed body is unaffected.
  6. `probe.status.as_deref() == Some("trial")` ⇒ `Public`.
  7. otherwise (restricted; or licensed with no id) ⇒ `Unidentified`.
  `update_window_current` stops being the routing discriminant and is carried into the `Licensed` arm's log line instead, so the local view and the Worker's `reason` can be correlated (and so the field is not dead). **That is the substantive change review forced, and the reason is worth keeping in front of the next reader:** a client that short-circuits on its own copy of the window never issues the request, which turns the Worker's `expired` branch (`infra/license-update-worker/src/worker.ts:112`) and its `no-header` branch (`:98`) into dead code in production. CLAUDE.md calls the Worker's `reason` enum *"the only detector"* for a missing entitlement, and `docs/licensing-explained.md:448-465` describes exactly the header-less and expired requests the Worker is built to answer. Withholding at the client would delete the detector that #1786 (H-b) is supposed to build on.
- **`entitled_license_id` becomes two functions, so the early return is observable.** `async fn resolve_update_route_with<F, Fut>(endpoint: &str, probe: F) -> UpdateRoute where F: FnOnce() -> Fut + Send, Fut: Future<Output = Option<LicenseStatusResponse>> + Send` holds the logic. **The `Send` bounds are load-bearing and must be written even though the test does not need them** — the crate already records why, on the analogous injectable seam: `lib.rs:551-557` says real callers hand the returned future to `tauri::async_runtime::spawn`, which requires `Future + Send + 'static`, *"while the test's `block_on` imposes neither — so without them the test would compile and the call sites would not."* The real caller chain here ends at exactly that `spawn` (`lib.rs:1368-1373`, the 8-hourly interval task). It and **keeps the endpoint check first, so while the const is empty it returns `Public` without invoking the probe at all**; `async fn resolve_update_route(app: &AppHandle) -> UpdateRoute` is the thin wrapper that supplies the real loopback probe (same body, same total-failure discipline — it still never errors). That early return is the byte-identity argument for this whole change, and splitting it is what lets a test assert the probe was **not called** rather than asserting a pure function that never had a probe in it.
- **`build_updater` returns `Result<UpdateOutcome, String>`, and `UpdateOutcome` is what carries the reason.** `Option<Updater>` cannot: `None` binds nothing, so every consumer below that needs the reason string would have it out of scope. Declare it beside `UpdateRoute`:
  ```rust
  /// What `build_updater` resolved to. `Withheld` carries the SAME
  /// `&'static str` the route did, because the reason has three consumers
  /// (the manual-check dialog, `install_update`'s error string, and #1786's
  /// future client surface) and a log line reaches none of them.
  ///
  /// `Ready` carries the ROUTE as well as the updater. Without it the caller
  /// cannot tell an honest "nothing newer" 204 from the Worker's withholding
  /// 204, and `Unidentified` would be answered with "You're running the latest
  /// version" — the exact lie #1786 exists to detect (#1785, round 3).
  enum UpdateOutcome {
      Ready { updater: tauri_plugin_updater::Updater, route: UpdateRoute },
      Withheld(&'static str),
  }
  ```
  `Public` ⇒ `Ok(UpdateOutcome::Ready { updater: app.updater()?, route })` (the updater itself unchanged). `Licensed(lid)` ⇒ `Ok(Ready { … })` over `…endpoints(vec![endpoint])…header("X-Tandem-License-Id", lid)…` (unchanged). `Unidentified` ⇒ the same builder **without** the header, still `Ready`, carrying `route: Unidentified`. `Withheld(reason)` ⇒ **`log::warn!`** naming the reason, then `Ok(UpdateOutcome::Withheld(reason))`.
  **`log::warn!`, not `log::info!`, and this is not a style preference.** `lib.rs:1166-1170` sets `log::LevelFilter::Warn` for `cfg!(not(debug_assertions))`, so an `info!` in a release build writes **zero bytes** — the crate already records that exact trap at `lib.rs:200` ("logging at `info` — below the release `LevelFilter::Warn` floor … which is exactly the bug #1416 was filed about"). `Withheld` is the fail-closed "no updates, ever" state on an unattended 8-hourly path; at `info` it would be completely silent, which is the failure #1786 is supposed to detect arriving with no trace for #1786 to hang off. The pre-existing `log::info!("No update available")` at `:2374` is left alone — that one is genuinely benign.
  **Consequence for the PR body: after the flip the public manifest is reachable only for trial, skewed-probe and dark-gate devices**, so `tauri.conf.json`'s endpoint stops being the entitlement hole and its removal drops from "must not forget" to "verify — and check the trial path first".
- **Both callers, and both bind `reason` from the arm.** `check_for_update` (`:2359-2362`): `Ok(UpdateOutcome::Ready { updater, route }) =>` binds both, `Err(e) =>` the existing dialog, and a new `Ok(UpdateOutcome::Withheld(reason)) =>` arm that warns and, when `manual`, calls `show_updates_withheld_dialog(app, reason)` before returning. `install_update` (`:2430-2439`): `UpdateOutcome::Withheld(reason)` ⇒ `Err(format!("UPDATE_WITHHELD:{reason}"))` — machine-readable at the boundary, because the neighbouring `.ok_or_else(|| "No update available")` means something genuinely different ("the server has nothing newer") and #1786 must not have to tell them apart by parsing English.
  **`Withheld` must not reach `show_up_to_date_dialog` — and neither may `Unidentified`.** "You're running the latest version" is the exact lie #1786 exists to detect. Reserving the rule for `Withheld` alone leaves the lie shipped by a different door, and this is measured, not hypothetical: `Unidentified` sends a header-less request, `infra/license-update-worker/src/worker.ts:98` (`if (!lid) return reject("no-header")`) answers the byte-identical 204, `updater.check()` therefore resolves `Ok(None)`, and `lib.rs:2372-2378` is `Ok(None) => { log::info!("No update available"); if manual { show_up_to_date_dialog(app); } return; }`. A restricted install would be told every 8 hours that it is up to date while updates are being withheld from it — and it is also a regression against today for that population, which currently gets real public builds.
  So the route is **carried past `build_updater`** (that is why `Ready` holds it) and the `updater.check()` `Ok(None)` arm branches on it:
  - `route == UpdateRoute::Unidentified` ⇒ **not** `show_up_to_date_dialog`. Log at `warn` and, when `manual`, `show_updates_withheld_dialog(app, "no-entitlement")` — the same honest placeholder branch the `Withheld` arm uses, with the wording owned by #1819 (H-c). The client chose this route, so it already knows the truth; no Worker signal is needed to say it.
  - every other route ⇒ the existing `log::info!("No update available")` + `show_up_to_date_dialog`, byte-identical.
  **State the boundary rather than overclaiming it:** a `Licensed` device whose *Worker-side* entitlement has lapsed also receives a 204 and is still told "up to date". That one the client genuinely cannot distinguish — CLAUDE.md's "the Worker's `reason` enum is the only detector" is about exactly this case, and it is #1786's (H-b) to surface. `Unidentified` is different in kind because the classification happened locally. Do not "consolidate" the two arms on the grounds that both end in a 204.
  Collapsing any of this back — routing `Withheld` into the up-to-date dialog, or dropping the `Unidentified` branch from the `Ok(None)` arm — is the single likeliest future edit; the source-scan test below is what makes each of them red.
- **The manual-check dialog** is one small `show_updates_withheld_dialog(app, reason)` with honest placeholder copy naming the update window. It has **two** callers, both created here: `build_updater`'s `Withheld` arm (`"status-unavailable"`) and `check_for_update`'s `Ok(None)` arm under `Unidentified` (`"no-entitlement"`). **#1819 (H-c) owns the final wording and the ended-window branch of the up-to-date dialog** — this PR creates the branch it will write into, and says so in a comment. All of it is unreachable while the const is empty.
- `Url` parsing stays inside the `Licensed`/`Unidentified` arms, so a malformed configured endpoint is still `Err`, not a silent fall-through to public.

## Tests

`update_route` cases, each killing a specific wrong implementation. One per arm, and one per *population*, because a case list that cannot tell trial from expired-licence lets a later edit change the trial policy while staying green. **Every case states its `status` field explicitly** — never `..Default::default()` for it — because `probe.status: None` is now its own routing step and a case that leaves it defaulted no longer says which arm it means:

- empty endpoint + `probe: None` ⇒ `Public` — kills a fix that makes a *dark* build stop checking for updates. This is the shipped path and the byte-identity guarantee.
- **empty endpoint, probe not called.** Call `resolve_update_route_with("", probe)` where `probe` flips an `AtomicBool`; assert the flag is still `false` and the route is `Public`. This is the case that actually protects the dark build: the pure classifier has no probe in it, so no reordering of `update_route` could ever start one, and the mutation this kills lives in the adapter.
- configured + `gate_active`, `update_window_current`, `license_id: Some`, `status: Some("licensed")` ⇒ `Licensed("…")`.
- **configured + `license_id: Some` + `update_window_current: false` + `status: Some("licensed")` ⇒ `Licensed("…")`** — **the case the issue names**, and the one that is `app.updater()` today. It routes to the Worker *with* the header so the Worker returns its 204 and logs `expired`; the assertion is that the public manifest is not chosen, not that the client withholds.
- **configured + `status: "trial"` (`license_id: None`, `update_window_current: false`) ⇒ `Public`** — named for the population. Every trialing device sets `update_window_current: false` (`src/server/license/license-state.ts:136`), so without this case a "tidy" that folds trial in with restricted silently stops shipping builds to every evaluator.
- **configured + `status: "restricted"` ⇒ `Unidentified`** — also named for the population (`license-state.ts:150`). Pins the open decision below: no update is served, and the Worker logs `no-header` rather than nothing being logged at all. Its user-facing half — that this route is answered with the withheld dialog and never with "You're up to date" — is not reachable from `update_route` and is pinned by asserts 4 and 5 of the source scan instead; the two together are what make `Unidentified` a complete arm rather than a classification with an invisible consequence.
- configured + `gate_active: false` ⇒ `Public` — a mismatched build must not be treated as an entitlement failure.
- configured + `license_id: None`, `status: Some("licensed")`, both flags true ⇒ `Unidentified` — kills an `unwrap_or_default()` that would send an empty header. **`status` is spelled out** rather than defaulted: left as `None` this case would be indistinguishable from the new step-5 case below, and would pass against a `Public` implementation of it.
- **configured + response present + `status: None` (`license_id: None`, `gate_active: true`) ⇒ `Public`** — the version-skew / scrubbed-body case, and the one that is *not* step 2. Named because the two `status`es make it the easiest case to reason wrongly about, and because folding it into step 7 would freeze every evaluator running an older sidecar.
- configured + `probe: None` (no response at all) ⇒ `Withheld("status-unavailable")` — pins fail-closed, so a later "be forgiving when the sidecar is slow" edit is a visible diff. **This is the case the previous bullet must not collapse into**, and asserting both is what proves the implementation reads the outer `Option` and the field separately.

**A source-scan guard — `tests/docs/update-route-dialog-claims.test.ts` (new, TypeScript)**, because the rule that a withheld user must not be told "You're up to date" is otherwise carried by a comment and nothing else, and a Rust test of `build_updater` itself is out of reach.

**It is deliberately NOT a Rust `#[cfg(test)]` scan over `include_str!("lib.rs")`**, which was the first draft and is defeated three separate ways — each one measured, none hypothetical:

- **It counts the definition.** `src-tauri/src/lib.rs:2242` is `fn show_up_to_date_dialog(app: &tauri::AppHandle) {`, so the needle `show_up_to_date_dialog(` already has **two** matches (the `fn`, and the call at `:2376`) before a line of test is written. "Exactly one" is red on current source, and the natural repair — loosening the count — is a non-discriminating check.
