# E1 — #1758 `tandem` from npm kills the desktop's server: the store-lock retry runs before `freePort`

Branch `fix/desktop-core-1761`. Closes #1758. Ledger: `docs/plans/2026-09-06-open-issues-sweep.md:413`; area rows `docs/reviews/2026-09-02-v1-review/areas/server-runtime.md:18` and `areas/product.md:16`. Probe: `tests/server/platform.test.ts`; the two-instance race is a smoke line (Bryan).

## Problem

In `src/server/index.ts` a second instance on the default ports (a) waits up to 30 s for the annotation-store lock and commits to `readonly` (`:335-360`), then (b) reaches `freePort(wsPort); freePort(mcpPort)` (`:609-610`) and **SIGKILLs / `taskkill /F`s** whatever holds them (`src/server/platform.ts:51-61`, `:178-249`). `freePort` looks up a listening PID and kills it; it cannot ask whether that PID is a healthy Tandem serving a human. So `tandem` from a terminal — which `doctor` and several docs suggest running — kills the desktop app's sidecar under the user's open documents, and the survivor is the read-only instance that cannot save annotations. The stdio branch has the same shape at `:767`.

**The npm flavor is the bug; the desktop's own child is not.** The Tauri shell delegates port reclamation *to* the sidecar it spawns — `src-tauri/src/sidecar.rs:1450-1453`: "a stale `tsx watch` dev session, an older release process, or any other listener on the MCP/WS ports can answer /health but be incompatible with this app's auth token / session state … The sidecar's own `freePort()` step on start handles port conflicts cleanly." The sidecar *is* `src/server/index.ts` in HTTP mode, so a refusal placed there without a carve-out fires inside the desktop's child and removes the app's only self-heal.

**Doc state, re-derived.** `docs/release-smoke-checklist.md:217-220` certifies the opposite of the code ("the npm server retries for 30s and gives up rather than displacing the app. Correct behaviour") and must be withdrawn. `docs/troubleshooting.md`'s "Port already in use" section (from `:147`) already describes the current kill **accurately** and cites #1758, so it needs updating for the new refusal, not correcting. `tests/scripts/e2e-guard-wiring.test.ts:185-196` forbids any harness port literal in that file, so the rewritten paragraph must keep the existing `4478`/`4479` example bytes intact.

## Fix

Probe before the lock; refuse rather than displace — **in the npm flavor only**; reserve `freePort` for listeners that fail the probe.

- **New `probeTandemInstance(mcpPort, schedule?): Promise<{ pid: number; version: string } | null>` in `src/server/platform.ts`**, beside `freePort` / `waitForPort` — that is where port lifecycle lives and the pairing ("`freePort` is for listeners that fail this probe") should be readable in one file. `fetch("http://127.0.0.1:<mcpPort>/health")` with an `AbortSignal.timeout(timeoutMs)`; return `null` on any throw, non-2xx, non-JSON, or a body without `status === "ok"` **and** a numeric `pid` **and** a string `version`.
  - **Three attempts, 1 s timeout each, ~250 ms apart; a positive result short-circuits.** A single 1 s window is not enough evidence to authorise a SIGKILL: a healthy Tandem whose event loop is briefly blocked (a `.docx` convert, a large `extractText`) answers slowly, probes as `null`, and is then killed — the outcome this spec exists to prevent, reached through the fix.
  - `schedule` is an optional `{attempts, timeoutMs, delayMs}` with exactly those defaults, and **no production call site passes one**. It exists so the absence test runs in ~150 ms rather than ~3.5 s against vitest's 5 s default.
  - Always `127.0.0.1`, never the bind host — this asks "is something already on the loopback port I am about to take".
- **`pid` is what #1812 adds to `/health`.** A pre-fix Tandem probes as `null` and is still `freePort`ed — today's behaviour, and the right call for an upgrade replacing its own predecessor. State that in the PR body; it is why the two issues ship together.
- **One pure decision function**, in the same module: `decideStartupAction({ probe, mode, isSidecar }): "refuse" | "proceed" | "skip-freeport"`.
  - **`isSidecar` is derived from argv, not from the environment.** `TANDEM_TAURI_SIDECAR` is **inherited by every descendant** of the sidecar: `tauri-plugin-shell`'s `Command::new` never calls `env_clear()` (documented in-repo at `sidecar.rs:1548-1556`, the mechanism that already shipped one defect via an ambient `TANDEM_MCP_PORT`), and `supervisor.ts:912` spawns the auto-launched Claude Code with `env: process.env`. So an npm `tandem` run from an auto-launched session's own shell would read `"1"`, take the sidecar carve-out, and SIGKILL the desktop's server — **this issue's exact bug, surviving on the path the product's own auto-launch creates.** The repo already treats this variable as too weak for provenance (`integrations/apply.ts:1572-1576` "The env var alone is not sufficient"; `cli/doctor.ts:1411-1414`). Argv is not inherited by grandchildren, which is what makes it the discriminant: `start_sidecar` already passes `.args([server_js_str])` (`sidecar.rs:1542`), so add one flag beside it — `--tauri-sidecar` — and read it from `process.argv`. `TANDEM_TAURI_SIDECAR` is left unchanged for its existing consumers, and **E1-1787's `flavor` reads the same argv flag.**
  - argv flag present → `"proceed"`, whatever the probe says. **The desktop keeps today's `freePort` recovery because the shell owns the port lifecycle and has no other one.** Log the probe result; do not act on it.
  - **`TANDEM_TAURI_SIDECAR=1` in the environment with the argv flag absent → `"refuse"` (http).** That is the descendant case: a `tandem` that merely inherited the variable is not the sidecar and must not get its carve-out.
  - `probe !== null && mode === "http"` → `"refuse"`. The issue's case.
  - `probe !== null && mode === "stdio"` → `"skip-freeport"`. Do not exit (see below); skip the kill.
  - `probe === null` → `"proceed"`. Today's behaviour: `freePort` still runs.
- **`src/server/index.ts`, HTTP mode:** run the probe as the **first** thing in `main()`'s HTTP path — before `claimAppDataDir` (E1-1787), the backup sweep at `:299`, the trial clock at `:315` and the store-lock block at `:332`, all of which touch app-data. The agreed order across both specs is **probe (HTTP only) → claim → sweep → trial → lock.** On `"refuse"`, print to stderr and `process.exit(1)`:
  `[Tandem] Tandem is already running at http://127.0.0.1:<mcpPort> (v<version>, pid <pid>). Not starting a second instance — quit the running one first, or run on different ports: see "Port already in use" in docs/troubleshooting.md (TANDEM_PORT, TANDEM_MCP_PORT and TANDEM_URL all have to match).`
  Exit **1**, not 0: this is a refusal to start, and 0 would read as success to a wrapper script. Nothing has been mutated at this point — no lock taken, no port killed — which is the point of probing first.
  - **The message must name all three variables.** An either/or invites the user to set only the MCP port; the probe then finds that port free, startup proceeds, and `freePort(wsPort)` SIGKILLs the desktop's Hocuspocus on :3478 — `freePort` keys on the port, not the bind address (`platform.ts:179-210`, `:212-249`). Naming all three, and pointing at the doc section that already says "All three need to match" (`docs/troubleshooting.md:162`), is what keeps the remedy from re-creating the bug. **That partial-configuration case is a named residual, not a mechanism here** — see the scope cut.
- **`src/server/index.ts`, stdio mode (`:767`):** same probe; on `"skip-freeport"` skip `freePort(wsPort)` and log `[Tandem] Another Tandem is serving :<mcpPort> — leaving :<wsPort> alone`. Do not exit: an MCP client's init would fail, and the branch already tolerates a Hocuspocus bind failure (`:775-777`). Skipping the kill converts "silently killed the desktop" into "MCP works, Hocuspocus did not bind", which is the honest outcome.
- **`freePort` itself is unchanged.** It stays the tool for a listener that answers nothing — a wedged process, a crashed sidecar, an unrelated program. Do not put the probe inside it: its other callers (the E2E harness's own boot, `scripts/`) have different needs, and a probe hidden inside a kill primitive is implicit control.
- **Docs, in the same PR, one paragraph each:** withdraw `docs/release-smoke-checklist.md:217-220`'s "gives up rather than displacing" certification as never having matched the code, and say §4 now refuses with a named message. Update `docs/troubleshooting.md`'s "Port already in use" section (from `:147`): an npm `tandem` now identifies the holder first and refuses rather than killing a live Tandem; `freePort` still frees a listener that does not answer `/health` as a Tandem; the desktop app is deliberately exempt because its shell relies on `freePort` to reclaim its own port; and setting only one of the three variables still exposes the other port. Keep the `4478`/`4479` example bytes intact.
- Rules that bite: no Y.Doc write, so Critical Rules 1–2 are inert; no new `/api` route or MCP tool, so Rule 9 and `NON_LOOPBACK_ALLOWED` are untouched.

## Tests

1. `tests/server/platform.test.ts` — `probeTandemInstance` against a real `http.createServer` on an ephemeral port: (a) a Tandem-shaped body → `{pid, version}`; (b) `{status:"ok", version:"x"}` with **no** `pid` → `null`; (c) a 200 of `"hello"` → `null`; (d) 404 → `null`; (e) nothing listening → `null`. **What (b) kills:** accepting any JSON `status: "ok"` as Tandem, which would let an unrelated health endpoint block startup forever — a refusal that cannot be recovered from is worse than the bug. **What (c)/(d) kill:** a `res.ok`-only check.
2. Same file: a server that never responds → resolves `null`. Drive it with an explicit short schedule (`{attempts: 3, timeoutMs: 50, delayMs: 10}`) and an explicit `{ timeout: 15_000 }`. **Kills** a missing timeout, which would hang every startup behind a black-holed port.
3. Same file: a server that answers a Tandem-shaped body only on its **third** request → returns `{pid, version}`, again on a short schedule. **Kills** the single-shot probe, under which a momentarily-blocked healthy Tandem is classified absent and then SIGKILLed.
4. Same file — `decideStartupAction`, one row per outcome:
   - `{probe: null, mode: "http", isSidecar: false}` → `"proceed"`. Kills a refusal that fires with no evidence, **and** is the "probe says no → the kill still happens" half.
   - `{probe: {…}, mode: "http", isSidecar: false}` → `"refuse"`. The issue's case.
   - `{probe: {…}, mode: "http", isSidecar: true}` → `"proceed"`. **Kills a refusal that strands the desktop app behind its own orphaned sidecar** — on macOS/Linux there is no job object (`sidecar.rs:1620-1629` is Windows-only), so a force-quit shell leaves a live sidecar; with an unconditional refusal the fresh child exits 1, `wait_for_health` bails, and `start_sidecar` burns all `MAX_RESTARTS` into the "Retry Server Start" dialog with nothing left to clear the orphan.
   - `{probe: {…}, mode: "stdio", isSidecar: false}` → `"skip-freeport"`. Kills the stdio branch inheriting the exit, which would break every MCP client that spawns it.
   - **The argv derivation itself, through the helper that computes `isSidecar` (`isTauriSidecar(argv, env)` or equivalent), not a hand-passed boolean:** argv carrying `--tauri-sidecar` → `true`; argv without it but `TANDEM_TAURI_SIDECAR=1` in the env → `false`, and fed through `decideStartupAction` with a positive probe in `http` mode → `"refuse"`. **Kills** keying the carve-out on the inherited env var, under which an npm `tandem` launched from an auto-launched Claude Code session SIGKILLs the desktop's own sidecar — the issue's bug reached through the fix.
5. Same file, one **source-shape** case, because the fix is call-site ordering and no test can drive `main()` (the module binds ports on import). Following the repo's existing pattern for exactly this (`tests/docs/loopback-gate-claims.test.ts`, `tests/server/document-write-rearm.test.ts`), read `src/server/index.ts` as text and assert by index that the `decideStartupAction(` call appears **before** the store-lock block and before **both** `freePort(` occurrences, and that the `"refuse"` arm's body contains `process.exit(1)`. **What it kills:** the laziest passing implementation — landing both functions fully tested and never calling them, or calling them after `freePort`. Under that implementation every other test here is green and Done-when's behavioural clauses are all unchecked.
   - **The same case also pins E1-1787's `index.ts` wiring, which no other test in this PR reaches.** Assert that `claimAppDataDir(` appears **before** `sweepBackupsOnStartup` (`src/server/index.ts:305`), before `ensureTrialStarted` (`:321`) and before `acquireStoreLock(` (`:341`), and that its `refused` arm's body contains `process.exit(1)`. **What it kills:** landing `app-data-owner.ts` fully tested and never calling it — E1-1787's tests all drive `claimAppDataDir` directly against `mkdtemp` dirs, so every one of them stays green while the fix ships nothing. Claiming after those three would also sweep and stamp two different directories.
6. The two-instance cross-process run stays a smoke line (Bryan); the PR body says tests 4 and 5 together stand in for it.

## Done when

Starting `tandem` from npm while a current-version Tandem holds :3479 exits 1 with the named message and kills nothing; the **desktop sidecar** still runs `freePort` and self-heals against a stale holder; a wedged non-Tandem listener is still freed; a slow-but-answering server is not classified absent; stdio mode leaves the port alone and logs; **the sidecar carve-out is keyed on the `--tauri-sidecar` argv flag, so a descendant that merely inherited `TANDEM_TAURI_SIDECAR` still refuses**; **test 5 pins that the decision is consulted before the lock and before both `freePort` calls, that the refusal exits 1, and that `claimAppDataDir` precedes the sweep, the trial clock and the store lock with its `refused` arm exiting 1**; the smoke-checklist certification is withdrawn and the troubleshooting section describes the new behaviour and the partial-configuration residual.

## Not in scope

Attaching as a client to the running instance (the issue's second option — a feature). Multi-instance support on non-default ports. `freePort`'s SIGKILL semantics and its port-keyed (not bind-address-keyed) lookup: a Tandem bound to a LAN interface via `TANDEM_BIND_HOST` is invisible to the 127.0.0.1 probe and would still be killed — name that in the PR body beside the pre-#1812 limit. #1812's health-poll identity check (its own spec in this PR). Whether `doctor` should suggest a different command when an instance is already running (#1790, wave 3).

- **The new `tests/server/startup-probe-wiring.test.ts` file, and four of its six clauses.** Folded into `tests/server/platform.test.ts` as one case asserting only what the issue's fix turns on: the decision precedes the store lock and both `freePort` calls, and the refuse arm exits 1.
