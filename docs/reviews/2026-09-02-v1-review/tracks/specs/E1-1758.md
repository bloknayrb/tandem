# E1 — #1758 `tandem` from npm kills the desktop's server: the store-lock retry runs before `freePort`

Branch `fix/desktop-core-1761`. Closes #1758. Ledger: `docs/plans/2026-09-06-open-issues-sweep.md:413`; area rows `docs/reviews/2026-09-02-v1-review/areas/server-runtime.md:18` and `areas/product.md:16`. Probe: `tests/server/platform.test.ts`; the two-instance race is a smoke line (Bryan).

## Problem

In `src/server/index.ts` a second instance on the default ports (a) waits up to 30 s for the annotation-store lock and commits to `readonly` (`:335-360`), then (b) reaches `freePort(wsPort); freePort(mcpPort)` (`:609-610`) and **SIGKILLs / `taskkill /F`s** whatever holds them (`src/server/platform.ts:51-61`, `:178-249`). `freePort` looks up a listening PID and kills it; it has no way to ask whether that PID is a healthy Tandem serving a human. So `tandem` from a terminal — which `doctor` and several docs suggest running — kills the desktop app's sidecar under the user's open documents, and the survivor is the read-only instance that cannot save annotations. The stdio branch has the same shape at `:767` (`freePort(wsPort)` with no probe).

Two docs certify the opposite: `docs/release-smoke-checklist.md:209-214` ("the npm server retries for 30s and gives up rather than displacing the app. Correct behaviour") and `docs/troubleshooting.md:141` calls the killed listener "stale".

## Fix

Probe before the lock; refuse rather than displace; reserve `freePort` for listeners that fail the probe.

- **New `probeTandemInstance(mcpPort): Promise<{ pid: number; version: string } | null>` in `src/server/platform.ts`**, beside `freePort` / `waitForPort` — that is where port lifecycle already lives and the pairing ("`freePort` is for listeners that fail this probe") should be readable in one file. `fetch("http://127.0.0.1:<mcpPort>/health")` with an `AbortSignal.timeout(1000)`; return `null` on any throw, non-2xx, non-JSON, or a body without `status === "ok"` **and** a numeric `pid` **and** a string `version`. Always `127.0.0.1`, never the bind host — this asks "is something already on the loopback port I am about to take".
  - **`pid` is what #1812 adds to `/health`.** A pre-fix Tandem therefore probes as `null` and is still `freePort`ed, which is today's behaviour and is the right call for an upgrade replacing its own predecessor. State that limit in the PR body; it is the reason the two issues ship together.
- **`src/server/index.ts`, HTTP mode:** run the probe as the **first** thing in `main()`'s HTTP path — before the backup sweep at `:299`, the trial clock at `:315` and the store-lock block at `:332`, all of which already touch app-data. On a non-null result, print to stderr and `process.exit(1)`:
  `[Tandem] Tandem is already running at http://127.0.0.1:<mcpPort> (v<version>, pid <pid>). Not starting a second instance — quit the running one first, or set TANDEM_PORT / TANDEM_MCP_PORT to run on different ports.`
  Exit **1**, not 0: this is a refusal to start, and a 0 would read as success to a wrapper script. Nothing has been mutated at this point — no lock taken, no port killed — which is the whole point of probing first.
- **`src/server/index.ts`, stdio mode (`:767`):** same probe, **different action** — skip `freePort(wsPort)` and log `[Tandem] Another Tandem is serving :<mcpPort> — leaving :<wsPort> alone`. Do not exit: an MCP client's init would fail, and the branch already tolerates a Hocuspocus bind failure (`:775-777` catches and logs). Skipping the kill converts "silently killed the desktop" into "MCP works, Hocuspocus did not bind", which is the honest outcome.
- **`freePort` itself is unchanged.** It stays the tool for a listener that answers nothing — a wedged process, a crashed sidecar, an unrelated program. Do not add the probe inside it: three of its callers (the E2E harness's own boot, `scripts/`, the stdio path) have different needs, and a probe hidden inside a kill primitive is the kind of implicit control the reviewers should reject.
- **Docs, in the same PR:** rewrite `docs/release-smoke-checklist.md:209-214` — §4 now refuses with a named message instead of contending, and the "gives up rather than displacing" certification is withdrawn as never having matched the code. Rewrite `docs/troubleshooting.md:141`'s "Port already in use" paragraph: Tandem now identifies the holder first and only kills a listener that does not answer `/health` as a Tandem.
- Rules that bite: none of this writes to a Y.Doc, so Critical Rules 1–2 are inert; no new `/api` route or MCP tool, so Rule 9 and `NON_LOOPBACK_ALLOWED` are untouched; `/health` is not a mutating route.

## Tests

1. `tests/server/platform.test.ts` — `probeTandemInstance` against a real `http.createServer` on an ephemeral port: (a) a Tandem-shaped body → returns `{pid, version}`; (b) `{status:"ok", version:"x"}` with **no** `pid` → `null`; (c) a 200 of `"hello"` → `null`; (d) 404 → `null`; (e) nothing listening → `null`. **What (b) kills:** accepting any JSON `status: "ok"` as Tandem, which would let an unrelated health endpoint block startup forever — a refusal that cannot be recovered from is worse than the bug. **What (c)/(d) kill:** a `res.ok`-only check.
2. Same file: a server that never responds → the probe resolves `null` within ~1.2 s. **What it kills:** a missing timeout, which would hang every startup behind a black-holed port.
3. `tests/server/platform.test.ts` — assert `freePort` is still exported and unchanged in signature (it has existing specs; do not weaken them). The discriminating pair is "probe says no → kill still happens".
4. No test drives `main()`'s exit path (the module binds ports on import). Cover the decision by keeping the probe pure and asserting it; state in the PR body that the two call sites are read-verified, and put the two-instance run on the smoke lines.

Starting `tandem` while a current-version Tandem holds :3479 exits 1 with the named message and kills nothing; a wedged non-Tandem listener is still freed; stdio mode leaves the port alone and logs; both doc claims are corrected.
