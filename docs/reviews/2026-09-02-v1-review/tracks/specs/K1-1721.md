# K1 — #1721 `accessibility.spec.ts` asserts only axe `violations`, so contrast failures land in `incomplete` and the run stays green

Branch `fix/test-gates-1784`. **Refs #1721 only** — the issue stays open, because its options (1)
and (2) need the "why do these nodes go incomplete" answer that is still unestablished. This PR ships
option **3** (the count pin) from the issue's own list. Ledger:
`docs/plans/2026-09-06-open-issues-sweep.md:224` ("count-pin only"). Probe: the issue's own mutation
— set `--tandem-author-user-bg` to `#4a4a4a` in `index.html`, run `-g "annotation card"`, record
whether the pinned count moves.

## Problem

`tests/e2e/accessibility.spec.ts:502` ends every scan with `expect(results.violations).toEqual([])`.
axe has three buckets — `violations`, `passes`, `incomplete` — and **nothing in the suite reads
`incomplete`**. `color-contrast` is not in `disableRules` (`:93-127`), so the rule runs; this is a
bucketing gap, not a disabled rule. The assertion is shared by the loop over **16** surfaces × 3
themes (`:487-505`), so the gap is suite-wide. The issue's measurement stands: a mid-grey card behind
dark body text reported `violations: []` in all three themes. Its *mechanism* is explicitly not
established, and the file's comment at `:300-345` already says so at length.

## Fix

A per-surface ceiling on color-contrast `incomplete` nodes, and nothing else — the gate must not
depend on the undecided colour question in #1683, and a count ceiling does not.

- New pure module `tests/e2e/axe-incomplete.ts` — **not** `.test.ts`/`.spec.ts`, so Playwright's
  `testDir: "tests/e2e"` default `testMatch` does not collect it and vitest's node project
  (`include: ["tests/**/*.test.ts"]`) does not either. It is typechecked by
  `tsconfig.tests.e2e.json`'s whole-directory include, so no config edit and no orphan. It imports
  nothing (declare its own `type AxeBucketEntry = { id: string; nodes: unknown[] }`) so it also
  resolves into the node program when the unit test imports it. Two functions:
  - `colorContrastNodeCount(entries: AxeBucketEntry[]): number` — nodes of the `color-contrast`
    entry, `0` when the rule is absent.
  - `checkIncompleteBaseline(key, observed, baseline): string | null` — `null` when
    `observed <= baseline[key]`, otherwise a message naming key, observed and baseline. **A key with
    no baseline entry returns a message, not `null`** (fail closed): a surface added to `SURFACES`
    must be measured, not silently unmeasured, which is the shape of the gap this issue is about.
- New `tests/e2e/axe-incomplete-baseline.json` — a flat `{ "<theme> / <surface.name>": <count> }`
  object plus a `$comment` string. `checkIncompleteBaseline` is only ever called with a
  `` `${theme} / ${surface.name}` `` key, so the `$comment` entry is never looked up as a count.
  Seed it by running `npx playwright test accessibility.spec.ts` on the reserved ports and committing
  the observed counts. **Then reconcile against CI**: the gate lands inside `check`, a required status
  check, and CI installs its own Chromium (`ci.yml:366`) while this container aliases build 1194 in
  place of the 1234 `@playwright/test@1.58` expects — and `color-contrast` `incomplete` is a
  per-**node** count moved by line wrapping and font fallback. So read the first CI run's counts from
  the job log and commit `max(local, CI)` per key, recording in `$comment` which keys disagreed and by
  how much. Never pad beyond an observed number; when a deliberate UI change raises a key, re-run that
  surface and commit the newly observed number with a one-line reason in `$comment`, never lowering
  another key in the same edit.
- `accessibility.spec.ts`: read the baseline once at module scope with `readFileSync` + `JSON.parse`
  (the file's existing style; no `resolveJsonModule` dependency), and inside the existing test,
  **immediately after `const results = await scan(page)` and before either assertion**, bind the
  observed count **once** and use that one binding for both the log and the assertion:

  ```ts
  const key = `${theme} / ${surface.name}`;
  const incompleteNodes = colorContrastNodeCount(results.incomplete);
  console.log(`${key} = ${incompleteNodes}`);          // seeding aid — see the procedure above
  expect(results.violations).toEqual([]);
  expect(checkIncompleteBaseline(key, incompleteNodes, baseline)).toBeNull();
  ```

  **One binding, not two expressions.** Two independent expressions is how a one-word slip to
  `colorContrastNodeCount(results.violations)` ships a permanently-green gate: `:502` already asserts
  `violations` is empty, so the observed count would be 0 for all 48 keys and `observed <= baseline`
  would always hold. With one binding, the seeding step reads the same number the assertion uses, so a
  `violations`-wired gate can only produce an all-zero baseline — which is visible in the committed
  file rather than hidden in a passing run. The log is deliberately permanent and ungated so a later
  re-seed can read CI's numbers without a code change. Keep all of it inside the existing `try` so the
  `finally` still runs `surface.close?.()`.
- Rewrite the block at `:318-334`. It currently states "NOTHING in this suite reads
  `results.incomplete`, so whatever axe files there is unasserted by construction" — that sentence
  becomes false with this change. Say what the pin does and does not buy: it makes a **jump** loud; it
  does not say any individual incomplete node is acceptable, and it is not a contrast gate for the
  user tint. Record the `#4a4a4a` mutation probe's outcome **in this rewritten block**, not only in
  the PR body (untracked evidence fails silently). Keep the "mechanism NOT established" and "do not
  repeat the `withRules` claim" paragraphs — still true, still the trap for the next reader.

## Tests

`tests/scripts/axe-incomplete-baseline.test.ts` (vitest node project; `tests/scripts/**` is in
`tsconfig.tests.node.json`), importing `../e2e/axe-incomplete.js`. The issue asks for one unit test
over the pure comparison function; it needs four `it`s, because three of the four kill an obvious
wrong implementation:

- observed **above** baseline → a message naming the key. This is the one the issue names: it proves
  the gate goes red.
- observed **equal** → `null`, and observed **below** → `null`. Without the equal case a `>=` typo
  passes the red case and then quietly fails every surface.
- **a key with no baseline row** → a non-null message naming the key:
  `checkIncompleteBaseline("dark / a surface with no baseline row", 0, {})`. Observed is `0`
  deliberately, so a `?? 0` variant is killed alongside the `baseline[key] ?? Infinity` and the early
  `if (baseline[key] === undefined) return null` ones. Without this `it` the fail-closed clause in
  `Fix` — the shape of the gap this issue is about — is asserted by nothing, and every surface added
  to `SURFACES` runs permanently unmeasured with `check` green.
- `colorContrastNodeCount`: an `incomplete` array holding only a non-contrast rule counts `0`; one
  holding `color-contrast` with 3 nodes counts `3`. Kills a count-of-entries implementation.

The `#4a4a4a` mutation probe is the second, weaker signal: run it and record whether the
annotation-card key exceeded its baseline. **Report that either way** — if the count does not move,
the pin still detects a jump, which is what option 3 buys and all it claims, and that measurement
belongs on #1721 as a comment because it narrows what options (1) and (2) will have to explain.

## Done when

`axe-incomplete.ts` (two functions) and the baseline JSON are committed and reconciled against the
first CI `check` run; the a11y loop asserts the ceiling as well as `violations`, off the single
`incompleteNodes` binding; the four unit assertions pass; the stale "nothing reads incomplete"
comment is rewritten and carries the probe outcome; a full `accessibility.spec.ts` run is green on the
reserved ports **and** in CI; `npm run typecheck:tests` green; the probe outcome is also a comment on
#1721. If the seeded baseline is all zeros, that is evidence the wrong bucket is wired, not a clean
result: dump `results.incomplete` raw, verify by eye, and record the outcome on #1721 and in the
rewritten spec block before shipping.

## Review corrections (scope cut)

- **The sixth `it` is removed** — the round-3 blocking finding against it is thereby moot. It asserted
  (a) that some committed baseline value is non-zero and (b) that `accessibility.spec.ts`, read as
  text, contains `colorContrastNodeCount(results.incomplete)` and not `…(results.violations)`. The
  finding was right that (a) alone does not prove the wiring; (b) proves it but is a source-text drift
  guard over a file the issue did not ask to guard. The **single named binding** — which the same
  finding proposes as its primary fix — is what the spec keeps: with the log and the assertion reading
  one variable, a `violations`-wired gate cannot be seeded with non-zero counts, so the defect shows
  up as an all-zero committed baseline. `Done when` states that outcome and what to do about it.
- **The "exactly 48 keys" comparison test in `accessibility.spec.ts` is removed**, and with it the
  `$`-prefix key-exclusion rule and the unexported-`SURFACES` reasoning it needed. Stale-key detection
  is a drift guard the issue did not ask for; the fail-closed missing-key path (which #1721 *does*
  imply, since an unmeasured surface is the same gap) stays.
- **The `unknownBaselineKeys` third function** was already dropped in round 2 and stays dropped.
- **The three-run local seeding, the per-key spread in `$comment`, the sanctioned re-seed-on-two-CI-
  reds escape hatch, and the `git log -- …` provenance sentence are removed.** Seeding is one local
  run reconciled against the first CI run, with disagreements recorded — the rest was procedure for a
  gate this size does not need.
- **The seeding-outcome branch is compressed** into two sentences in `Done when` rather than its own
  Tests subsection.
- **The unit file goes from six `it`s to three.** The issue asks for one; the equal-case twin and the
  `colorContrastNodeCount` case are kept because each kills a specific wrong implementation, and the
  spec now says so instead of arguing the point across two correction rounds.

## Review corrections (post-cut)

- **A fourth `it` covers the fail-closed missing-key branch.** `Fix` requires a key with no baseline
  entry to return a message, and calls that "the shape of the gap this issue is about", but the three
  prescribed `it`s never passed an absent key: `const limit = baseline[key] ?? Infinity` (or an early
  `return null` on `undefined`) passes all three, and any surface later added to `SURFACES` then runs
  unmeasured forever while the required `check` job stays green — the same unasserted-by-construction
  failure #1721 is filed about. The new case passes `observed: 0` so a `?? 0` variant dies with it.
  `Done when` now says four assertions.
