# D1 — #1799 inline image splits its paragraph into three blocks; fence meta string dropped

Branch `fix/markdown-fidelity-1753`. Closes #1799 (both halves). Ledger: `docs/reviews/2026-09-02-v1-review/areas/server-data.md:24` (filed `[read]`, agent-reported).

**Reproducing the measurements** (no probe file is tracked — `experiments/` is not in the worktree): a scratch `npx tsx` script that imports `loadMarkdown` / `saveMarkdown` / `mdParser` from `src/server/file-io/markdown.ts` and `yDocToMdast` from `src/server/file-io/mdast-ydoc.ts`, prints `JSON.stringify` of input and output for each shape below, and for the fence table prints `mdParser.parse(f).children[0]`'s `lang` / `meta`. Re-run 2026-09-09; the fence-table row for `` ``` {1,3} `` is what refutes the earlier "meta but no lang" case.

## Problem

Both halves reproduce on a bare `loadMarkdown` → `saveMarkdown`:

```
"Text before ![x](a.png) text after\n"   -> "Text before\n\n![x](a.png)\n\ntext after\n"
"- one ![x](a.png) two\n- three\n"       -> "- one\n\n  ![x](a.png)\n\n  two\n- three\n"   (list goes loose)
'```ts title="x.ts" {1,3}\nconst a = 1;\n```\n' -> "```ts\nconst a = 1;\n```\n"
```

1. `src/server/file-io/mdast-ydoc.ts`, `case "paragraph"`: `if (node.children.some((c) => c.type === "image")) return splitParagraphImages(...)`. The predicate is `some`, so a paragraph with prose **around** an image is split into three blocks. #153 needed only the standalone case (`![alt](url)` alone in its paragraph, which is how CommonMark parses a block image). Consequences per the issue: an opened-only file is rewritten into three paragraphs, a list item goes loose (changing rendering for every item in the list), and two block separators are inserted into the flat text, moving every annotation offset after the image.
2. Same file, `case "code"` → `el.setAttribute("language", node.lang)`: `node.meta` is dropped, so `` ```ts title="x.ts" {1,3} `` saves as `` ```ts ``. Docusaurus/MkDocs/Shiki titles and line-highlight ranges vanish silently.

## Fix

**Half 1 — narrow the promotion predicate, and let the existing raw-run path carry the rest.** In `case "paragraph"`, promote only when the paragraph is *nothing but* images plus whitespace-only text:

```ts
const onlyImages =
  node.children.some((c) => c.type === "image") &&
  node.children.every((c) => c.type === "image" || (c.type === "text" && c.value.trim() === ""));
if (onlyImages) return splitParagraphImages(node.children, deferred);
```

Nothing else is needed on the build side: the inline walk already has `case "image"`, which calls `insertRaw(xmlText, serializeMdastInline(node) || node.alt || node.url, marks)` and whose comment already says it exists for "truly-inline images … so the URL/title survive the round-trip instead of degrading to alt-text only (#981)". Today that arm is nearly unreachable because the paragraph case swallows every image; the fix makes it the normal path. `splitParagraphImages` stays exactly as it is — its whitespace trimming is what keeps a lone `![x](a.png)` from leaving an empty paragraph, and multi-image paragraphs (`![a](1.png)![b](2.png)`) still promote.

**The trade, decided here:** an inline image inside prose is now stored as a `rawMarkdown` run and therefore shown in the editor as literal `![x](a.png)` rather than as a picture — the same treatment footnote references, reference links and inline HTML already get under ADR-042. That is the correct v1 trade: the alternative the issue proposes (a Tiptap inline image node) is a client schema change plus a y-prosemirror mapping, and until it exists the block-promotion path is silently rewriting the user's file. Listed for Bryan as a visible behaviour change, not as a blocker.

**Two consequences of the trade that are not about rendering, both recorded rather than fixed here:**

- **The image's literal markdown enters the flat-offset coordinate system.** Today the promoted block image has an empty `getElementText()` and `mdast-ydoc.ts:215-218` names that as "preserving flat-offset alignment"; afterwards `![x](a.png)` is real flat text that `deltaToPhrasingContent` re-emits verbatim (`:948`). So an annotation range or a `tandem_edit` can now land **mid-construct** — inside `![x](a`, say — and Critical Rule 6's `rejectHeadingInterior` has no raw-run analogue, so a `tandem_edit` over that span rewrites it and corrupts the image on save. This is the same exposure raw links and inline HTML already carry under ADR-042 and is not new in kind; it is new in *reach*, because inline images are common. Spec 10 documents the current behaviour so the exposure is on record rather than discovered later, and the PR body names it. Building a raw-run interior guard is a separate piece of work.
- **Existing annotations past an inline image shift.** See spec 8 — the recovery is `degraded`, which is correct, but it means an upgrade re-degrades those records once.

**The `sanitizeImageSrc` path is affected, so it is no longer listed as out of scope.** `imageToYxml` (`mdast-ydoc.ts:433-439`) calls `sanitizeImageSrc(node.url)` and, on rejection, downgrades to a plain-text paragraph carrying alt/title. After the narrowing, a **prose-surrounded** image routes to the inline `case "image"` arm (`:575-582`, `insertRaw(xmlText, serializeMdastInline(node) …)`), which never consults the sanitizer. The outcome is inert — a `rawMarkdown` text run, never an `image` element with a `src`, so nothing renders it as an image — and it stops rewriting the user's file, which is an improvement. But it is a routing change, not "untouched"; spec 9 pins it. Standalone images still promote and still go through the sanitizer.

**Half 2 — carry the whole info string in the `language` attribute.** On load, build from both halves defensively rather than with a ternary that can interpolate `null`:

```ts
el.setAttribute("language", [node.lang ?? "", node.meta ?? ""].join(" ").trim());
```
On save (`case "codeBlock"`): split the stored value at the first whitespace run — first token → `lang`, remainder → `meta` (`null` when empty). The `??`-and-trim form is deliberate: a naive `` node.meta ? `${node.lang} ${node.meta}` : node.lang `` interpolates the literal string `"null "` whenever `lang` is null, and the save-side split would then emit ` ```null … `. Measured, remark never actually produces `lang: null` with a non-null `meta` (see below), so this is belt-and-braces against a future parser change rather than a live defect — but the defensive form costs nothing and the ternary hides a wrong literal. The precedent is the client's own paste path, `src/client/editor/utils/markdown-paste.ts:227,232`, which already stores the **full** `tok.info` in `language`; today file-open and paste disagree, and this aligns them. **This is why the meta does not get a Y.XmlElement attribute of its own:** `language` is in Tiptap's CodeBlock schema, and `editor-extensions.ts:291-293` records that anything not in the client schema is deleted by y-prosemirror on sync — an unknown `meta` attribute would survive the server round-trip and be dropped the moment a browser edited the document, which is a worse failure than the one being fixed. Consequence to state in the PR body: the rendered `<code>` class becomes `language-ts title="x.ts"`; that is already true of pasted fences today.

Rules that bite: `setAttribute` here takes a string, so no `as any` (that gotcha is heading levels); no Y.Map key, no origin helper, no new MCP error code, so `docs/mcp-tools.md` needs no Errors edit.

## Tests

`tests/server/mdast-ydoc.test.ts` and `tests/server/file-io/roundtrip-corpus.test.ts`:

1. `Text before ![x](a.png) text after\n` round-trips byte-identical **and** `collectBlocks`/the fragment holds exactly ONE block. The block count is the discriminating half — a fix that re-joined the three paragraphs at save time would pass a byte check and still move every annotation offset.
2. `- one ![x](a.png) two\n- three\n` byte-identical; assert the list is still tight (`spread === false`), which is the rendering-visible half.
3. Standalone `![x](a.png)\n` still becomes a block `image` element with `src` — pins #153 against an over-narrow predicate.
4. `![a](1.png)![b](2.png)\n` (two images, no prose) still promotes to two image blocks.
5. `![x](a.png) trailing\n` — image first, prose after: one paragraph, byte-identical. Kills a predicate keyed on "the first child is an image".
6. Fence meta — **only reachable shapes; the "meta but no lang" case is deleted.** Measured with the repo's own remark stack, 2026-09-09:

   | source info string | mdast | remark's own re-stringify |
   |---|---|---|
   | `` ```ts title="x.ts" {1,3} `` | `lang: "ts"`, `meta: "title=\"x.ts\" {1,3}"` | unchanged |
   | `` ```ts `` | `lang: "ts"`, `meta: null` | unchanged |
   | `` ``` {1,3} `` | `lang: "{1,3}"`, `meta: null` | ```` ```{1,3} ```` — **the space is lost at the serializer layer** |
   | `` ```ts␠␠{1,3} `` (two spaces) | `lang: "ts"`, `meta: "{1,3}"` | ```` ```ts {1,3} ```` — **collapsed at parse** |

   mdast splits the info string at the first whitespace and never produces `meta` without `lang`, so a fence with meta and no lang does not exist and `split(" ")[0]` was already correct on every reachable input — the third case could not pass before or after the fix and killed nothing. The three specs that do discriminate: `` ```ts title="x.ts" {1,3} `` **byte-identical**; `` ```ts `` still yields `lang: "ts"`, `meta: null`; and the double-space fence asserted on **`lang`/`meta` values, not bytes** (`lang: "ts"`, `meta: "{1,3}"`) — byte-identity is unachievable there because remark itself collapses the run at parse time, below anything `mdast-ydoc.ts` controls. That third spec is what pins the split as *first whitespace run*: a `split(" ")` over the stored `"ts {1,3}"` gives the same answer here, but the value assertion is the one that stays honest if the stored form ever carries a multi-space meta.
7. New corpus fixtures `inline-image.md` and `fence-meta.md` registered **clean** (no `blockedOn`) in `roundtrip-corpus.test.ts`, which asserts byte-identity on pass 1. `fence-meta.md` carries only the byte-identical shapes (rows 1 and 2), not the double-space fence.
8. **Stored annotations past an inline image come back `degraded`, not silently re-anchored.** Narrowing the promotion predicate changes the flat-offset coordinate system for every already-annotated document containing a prose-inline image: measured, `"Text before ![x](a.png) text after\n"` gives `extractText` `"Text before\n\ntext after"` (3 blocks) today and `"Text before ![x](a.png) text after"` (1 block) after, moving every stored offset past the image by 11. Seed an envelope record anchored after the image with a `textSnapshot` captured under the old layout, and assert `anchor: "degraded"` (`storedRangeStillMatches`, `positions.ts:832,856`) rather than a resurrection at a wrong offset. The recovery is safe; it is not obvious, and nothing else in this spec records it.
9. **A rejected image `src` in prose stores a raw run and no `image` element.** `Text ![x](javascript:alert(1)) after` round-trips byte-identical, produces no `image` element and no `src` attribute anywhere in the fragment. This pins the sanitizer-routing change described in §Fix.
10. **Mid-construct range, behaviour documented not fixed.** A document whose annotation range starts inside the raw image run (e.g. over `![x](a`) — round-trip it and assert whatever the current behaviour is, with a comment naming the exposure (no `rejectHeadingInterior` analogue for raw runs) and pointing at §Fix. The spec exists so the exposure is on record and a later guard has a starting assertion, not because this PR changes it.
