Branch `fix/markdown-fidelity-1753`. Closes #1799 (both halves). Ledger: `docs/reviews/2026-09-02-v1-review/areas/server-data.md:24` (filed `[read]`, agent-reported).

For the individual figures, a scratch `npx tsx` script importing `loadMarkdown` / `saveMarkdown` / `mdParser` from `src/server/file-io/markdown.ts` that prints input and output per shape, and `mdParser.parse(f).children[0]`'s `lang` / `meta` for the fence table. ## Problem

Both halves reproduce on a bare `loadMarkdown` → `saveMarkdown`:

```
"Text before ![x](a.png) text after\n"   -> "Text before\n\n![x](a.png)\n\ntext after\n"
"- one ![x](a.png) two\n- three\n"       -> "- one\n\n  ![x](a.png)\n\n  two\n- three\n"   (list goes loose)
'```ts title="x.ts" {1,3}\nconst a = 1;\n```\n' -> "```ts\nconst a = 1;\n```\n"
```

1. `src/server/file-io/mdast-ydoc.ts`, `case "paragraph"`: `if (node.children.some((c) => c.type === "image")) return splitParagraphImages(...)`. The predicate is `some`, so a paragraph with prose **around** an image is split into three blocks. #153 needed only the standalone case. Consequences: an opened-only file is rewritten into three paragraphs, a list item goes loose, and two block separators enter the flat text, moving every annotation offset after the image.
2. Same file, `case "code"` → `el.setAttribute("language", node.lang)`: `node.meta` is dropped, so `` ```ts title="x.ts" {1,3} `` saves as `` ```ts ``. Docusaurus/MkDocs/Shiki titles and line-highlight ranges vanish silently.

## Fix

**Half 1 — narrow the promotion predicate; the existing raw-run path carries the rest.** In `case "paragraph"`, promote only when the paragraph is *nothing but* images plus whitespace-only text:

```ts
const onlyImages =
  node.children.some((c) => c.type === "image") &&
  node.children.every((c) => c.type === "image" || (c.type === "text" && c.value.trim() === ""));
if (onlyImages) return splitParagraphImages(node.children, deferred);
```

Nothing else is needed on the build side: the inline walk already has `case "image"` (`:575-582`), which calls `insertRaw(xmlText, serializeMdastInline(node) || node.alt || node.url, marks)` and whose comment says it exists for "truly-inline images … so the URL/title survive the round-trip instead of degrading to alt-text only (#981)". Today that arm is nearly unreachable; the fix makes it the normal path. `splitParagraphImages` is unchanged — its whitespace trimming is what keeps a lone `![x](a.png)` from leaving an empty paragraph, and multi-image paragraphs still promote.

**The trade, decided here:** an inline image inside prose is stored as a `rawMarkdown` run and shown in the editor as literal `![x](a.png)` rather than as a picture — the treatment footnote references, reference links and inline HTML already get under ADR-042. That is the correct v1 trade: the alternative (a Tiptap inline image node) is a client schema change plus a y-prosemirror mapping, and until it exists the promotion path is silently rewriting the user's file. List it for Bryan as a visible behaviour change.

**Two consequences to state in the PR body, not to test here.** (a) The image's literal markdown enters the flat-offset coordinate system, so an annotation range or `tandem_edit` can land mid-construct; that is the same exposure raw links and inline HTML already carry under ADR-042 — new in reach, not in kind. (b) Existing annotations past an inline image shift by the construct's length; `storedRangeStillMatches` (#1764) answers `degraded` and writes nothing, so they recover safely rather than resurrecting at a wrong offset.

**`sanitizeImageSrc` routing changes, so it is not "untouched".** `imageToYxml` (`:433-439`) calls `sanitizeImageSrc(node.url)` and downgrades a rejected URL to a plain-text paragraph. After the narrowing, a **prose-surrounded** image routes to the inline arm, which never consults the sanitizer. The outcome is inert — a `rawMarkdown` text run, never an `image` element with a `src`, so nothing renders it — and it stops rewriting the user's file. Spec 7 pins it. Standalone images still promote and still go through the sanitizer.

**Measured residual: half 1 removes the paragraph split, not every rewrite.** An inline image whose URL contains characters `remark-stringify` escapes still changes bytes on save — measured, `![x](javascript:alert(1))` serializes back as `![x](javascript:alert\(1\))`, two characters longer, because the raw run is produced by `serializeMdastInline` rather than copied from the source. The three-block split is gone either way; byte-identity holds for ordinary URLs (specs 1, 2, 5) and not for these. State it in the PR body.

**Half 2 — carry the whole info string in the `language` attribute**, keeping the existing guard's intent (store the attribute only when there is something to store):

```ts
const info = [node.lang ?? "", node.meta ?? ""].join(" ").trim();
if (info) el.setAttribute("language", info);
```
The guard is not incidental: `mdast-ydoc.ts:246-254` states the precedent on list `spread` — "Stored only when true, so a tight list writes no attribute and reconciles against the editor's default without a phantom transaction." An unconditional `setAttribute` would put `language=""` on every bare fence, with identical bytes (`lang: lang || null`, `:722`), which is why it would go unnoticed. On save (`case "codeBlock"`), split the stored value at the first whitespace run — first token → `lang`, remainder → `meta` (`null` when empty). The `??`-and-trim form is deliberate: a naive ternary interpolates the literal `"null "` when `lang` is null. Precedent: the client's paste path (`src/client/editor/utils/markdown-paste.ts:227,232`) already stores the full `tok.info` in `language`; today file-open and paste disagree. **The meta gets no attribute of its own:** `language` is in Tiptap's CodeBlock schema, and `editor-extensions.ts:291-293` records that anything not in the client schema is deleted by y-prosemirror on sync. Consequence for the PR body: the rendered `<code>` class becomes `language-ts title="x.ts"`, already true of pasted fences.

Rules that bite: `setAttribute` takes a string here, so no `as any` (that gotcha is heading levels); no Y.Map key, no origin helper, no new MCP error code, so `docs/mcp-tools.md` needs no Errors edit.
