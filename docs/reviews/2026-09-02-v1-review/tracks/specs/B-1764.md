# B — #1764 A read path persists a collapsed or unverified re-anchor, and `kind` is invisible

Branch `fix/annotation-anchors-1764`. Closes #1764 (items 1–4 of its body; the client-side split mapping in its "Suggested fix" is NOT taken — see Not in scope).
Ledger: `docs/reviews/2026-09-02-v1-review/areas/crdt.md:17-19`.

## Problem

`refreshRange` (`src/server/positions.ts`) writes through the caller's `map` on three arms, and its only caller in the read path is `listAnnotationsRefreshed` (`src/server/mcp/document-store.ts`), a **read**:

1. **Collapse is an `updated`.** A block split, heading toggle or join resolves both RelativePositions onto one offset; the guard above rejects only `newFrom > newTo`, so `{4,4}` is returned as `updated` and `map.set`. That destroys the stored flat range — the fallback the watcher's snapshot relocation needs.
2. **The dead-relRange (`repaired`) arm re-anchors from the annotation's STORED flat offsets with no `textSnapshot` comparison**, and persists it. If the text moved while the relRange died, it mints a confident anchor over the wrong span.
3. **The lazy-attach arm (`!ann.relRange`) is the same unverified mint.** Fixing only (2) is defeated one call later.
4. Once a collapse is persisted, undo resolves the two zero-width anchors to opposite ends and the record is `failed` forever.
5. Every MCP consumer except the `.docx` export discards `kind`, so none of this has a visible symptom.

**A collapse has two causes needing opposite answers.** A split/toggle/join collapses two live anchors while the annotated text is still present — persisting `{n,n}` destroys the fallback. Deleting the annotated span produces the same shape (`fromRel` assoc 0, `toRel` assoc -1 both land on the deletion point) and there `{n,n}` is correct. The discriminator is the stored `textSnapshot`.

## Fix

- **`src/server/positions.ts`** — one module-private predicate used on all three arms:
  `function storedRangeStillMatches(ann: Annotation, text: string): boolean` — `ann.textSnapshot === undefined || !snapshotContradicts(ann, text.slice(ann.range.from, ann.range.to))`.
  **`undefined` is the only carve-out, and it belongs to the two mint arms alone** — the collapse arm requires a snapshot, see its bullet below. Do not also short-circuit an empty or non-string snapshot: `src/shared/snapshot.ts:158-176` already distinguishes all three (an empty snapshot is a real claim; a non-string one fails *toward* contradiction) and already handles truncation by prefix. Do not inline a second copy of that rule. An out-of-bounds stored range slices to `""` and therefore contradicts, which is the clamp #1765's body asks for.
  - **Resolve the flat text at most once per batch.** Add an internal 4th parameter `refreshRange(ann, ydoc, map?, getText?: () => string)`, defaulting to a per-call memoized `() => extractText(ydoc)`; `refreshAllRanges` builds **one** memoized getter and passes it to every iteration. So the text is materialised at most once per `refreshAllRanges` call and **not at all** when no annotation reaches a guard arm. No public options widening and no new `HoistTag`.
  - Lazy-attach arm: predicate false ⇒ `{kind: "degraded", annotation: ann}`, **no write**.
  - Dead-relRange arm: predicate false ⇒ take the existing strip path (`delete stripped.relRange`, `map.set`, `degraded`) instead of minting. Stripping is required by the "strip dead relRange, never preserve" gotcha; it removes a field, it does not mint an anchor.
  - Collapse guard, immediately after the `newFrom > newTo` arm (the two "the CRDT no longer describes this annotation" verdicts sit together) and before the unchanged-offsets `ok` arm:
    `if (newFrom === newTo && ann.range.from !== ann.range.to && ann.textSnapshot !== undefined && storedRangeStillMatches(ann, getText())) return {kind: "degraded", annotation: ann}` — no write, so the flat range and the relRange both survive for relocation and undo. A genuine deletion contradicts, falls through to today's `updated {n,n}`, and keeps `docx-comment-export.ts` from writing a Word comment over unrelated text.
    **The explicit `ann.textSnapshot !== undefined` is the whole point of this arm not reusing the mint arms' carve-out**, and inheriting it would be a `.docx` regression on the one population that has no snapshot by construction. `docx-comments.ts` strips `textSnapshot`/`textSnapshotTruncated`/`textSnapshotBreaks` off every imported Word comment on the drift path and notes that "Import notes don't carry one today"; `docx-comment-export.ts` admits exactly those records via `isImportRoundtrip`, skips only `kind === "failed"`, and writes `refreshed.annotation.range` into the saved file. So for an imported Word comment whose annotated text the user genuinely deleted, a snapshot-less preserve would turn today's zero-width `{n,n}` anchor at the deletion point into a stale non-empty span and export the Word comment over unrelated text — a byte change in the user's document. With the snapshot required, a snapshot-less collapse keeps writing `{n,n}`.
  - **Critical Rule 2:** no new transaction — every `map.set` here is already inside `refreshAllRanges`' `withMcp` (or the watcher's outer `withReload` via `skipTransact`); this change only removes writes. **Critical Rule 4 is untouched** — `validateRange`'s order is not on this path.
- **`src/server/mcp/document-store.ts`** — `listAnnotationsRefreshed()` returns `RefreshResult[]` (drop the trailing `.map((r) => r.annotation)`). No second method, no compat wrapper. Two `src/` call sites (`mcp/annotations.ts:411`, `:688`) and **five test call sites that `typecheck:tests` will catch** (`tests/server/rename-document.test.ts:957,959,1031,1034`, `tests/server/document-store.test.ts:324`) each gain `.map((r) => r.annotation)`. Update the method docblock.
- **`src/server/mcp/output-schemas.ts`** — add to `annotationWithRepliesSchema` **only** (`annotationBaseShape` is shared with `checkInbox` and must not grow): `anchor: z.enum(["degraded", "failed"]).optional()`. The emitted set is the two degradation verdicts, not all five kinds: `updated` fires for every annotation past any edit, `attached` on the first refresh of a pre-relRange record, and `repaired` for the whole collection after any reload — emitting them buries the one signal #1764 asks for.
- **`src/server/mcp/annotations.ts`** — `tandem_exportAnnotations` adds `.map((r) => r.annotation)` at its call site. `tandem_getAnnotations` keeps its filter chain by building `const kindById = new Map(refreshed.map((r) => [r.annotation.id, r.kind]))` and `let results = refreshed.map((r) => r.annotation)`; the reply assembly spreads `...(kind === "degraded" || kind === "failed" ? { anchor: kind } : {})`.
- **`src/server/documents/watcher.ts`** — comments only: the two blocks that justify their behaviour with "`refreshAllRanges` above has already re-anchored a fresh `relRange` from the STALE flat offsets" now hold only when the stored range still matches its snapshot. Restate both. `allowEmpty: true` on the relocation anchor stays — the truncated branch's own `Math.min(...)` clamp can produce a zero span independently of #1764.
- **`CLAUDE.md`, the Y.js/CRDT gotcha naming #1764** — it currently states the `repaired` arm re-anchors "with **no `textSnapshot` comparison**" and calls the difference "unmeasured", both false after this fix, in the file auto-loaded into every session (`grep -n 'relRange\|repaired\|textSnapshot' AGENTS.md` is empty, so `AGENTS.md` needs nothing — but it is **not** the only stale surface: two tracked docs state the removed behaviour as live rationale and get their own bullets below). Rewrite in place, same length: the strip-dead-relRange half is unchanged and still the rule; the two mint arms and the collapse arm are gated on `storedRangeStillMatches`; a stored range that no longer holds its snapshot answers `degraded` and writes nothing; `tandem_getAnnotations` surfaces that as `anchor: "degraded"`; the one remaining unverified mint is a record carrying no `textSnapshot`. Delete "the difference is unmeasured".

- **`docs/decisions.md`, ADR-032's Amendment (2026-09-08)** — it states that "**exactly one caller anywhere reads `kind`**" (the `.docx` export) and that every other consumer discards it, naming `mcp/document-store.ts:229`, and concludes "there is no MCP error response for a degraded range … This is the 'no visible symptom' half of #1764." - **`docs/mcp-tools.md`** §`tandem_getAnnotations` — one line documenting `anchor`: present only when the anchor is untrustworthy (`degraded` = "the anchor no longer describes this text; the range shown is the last one the server trusted"), absent on every healthy refresh.

## Tests

1. `tests/server/positions.test.ts` — **collapse**: a non-empty range whose `textSnapshot` still matches, spliced so both relPos resolve to one offset ⇒ `degraded`, `annotation.range` unchanged, and `map.get(id)` **untouched** (`toBe` the pre-call object). Kills a fix that returns `degraded` but still writes.
2. Same file — **an already-empty range still refreshes normally**: a point annotation (`from === to`) resolving to a new equal pair returns `updated`. Kills a bare `newFrom === newTo` guard.
3. Same file — **a genuine deletion still collapses**: delete the annotated span so the stored slice no longer holds the snapshot ⇒ `updated` with `{n,n}` **written**.
4. Same file — **repair refuses on a contradicting snapshot**: kill the relRange with `ann.range` now over different text ⇒ `degraded`, `relRange` absent on the stored record, nothing minted. Plus the negative twin: with the text at `ann.range` unchanged the same call still returns `repaired` **with** a relRange (otherwise the fix could refuse everything). A byte-exact clone (the `repairClonedAnchors` shape, `documents/annotation-wiring.ts`) is `repaired` — the #1800 regression guard.
5. Same file — **lazy attach refuses on a contradicting snapshot**: no `relRange`, stored offsets no longer holding the snapshot ⇒ `degraded`, nothing minted. Kills fixing only the `repaired` arm.
6. Same file — **no snapshot, both halves diverge** (Assumptions is not a test, and a "consistency" tidy here changes `.docx` export bytes silently): a snapshot-less record still gets `attached`/`repaired` on the mint arms, while the same record with both anchors collapsed is **`updated` with `{n,n}` written** — the collapse arm's carve-out is the opposite of the mint arms'. Kills a fix that reuses `storedRangeStillMatches` unqualified on the collapse arm, which would preserve a stale non-empty span for an imported Word comment and export it over unrelated text.
7. `tests/server/mcp-tool-integration.test.ts` — the `anchor` field, written to discriminate: after a `tandem_edit` that shifts annotations (`updated`) there is **no** `anchor` key; after a reload that re-anchors them (`repaired`) still **no** `anchor` key; after collapsing one annotation's anchors with its snapshot intact, that record carries `anchor: "degraded"` and the others none. Kills a schema-only change and the noisy five-kind enum.

## Assumptions

- **A record with no `textSnapshot` keeps today's unverified mint** — there is nothing to verify against, and refusing would strand every pre-snapshot record permanently.
- **The collapse arm carves out the opposite way: no snapshot means no preserve.** A collapse is treated as spurious only when a snapshot positively says the stored text is still there; with nothing to verify against it falls through to today's `updated {n,n}`. The snapshot-less population is not empty and is not incidental — it is **imported Word comments**, which `docx-comments.ts` strips the snapshot from on the drift path ("Import notes don't carry one today") and which `docx-comment-export.ts` then writes back into the user's `.docx` at whatever range the refresh returns. Preserving a stale non-empty span for one of those would export a Word comment over unrelated text: a byte change in the user's document on the exact population an `undefined`-permissive predicate would cover. With the snapshot required, **the export's bytes are unchanged for every snapshot-less record**.
- **The `.docx` export's bytes change for a spuriously collapsed annotation, by design** — it now exports at the stored span, which is where the text still is. The export source is untouched.
- **A contradicting re-anchor answers `degraded`, not `failed`** — `failed` is the export's skip signal, so promoting a recoverable stale anchor to it would drop a real comment.
- **`refreshRange` keeps its `map` parameter and `listAnnotationsRefreshed` keeps passing it** — removing the write wholesale would stop relRange re-attachment reaching the durable envelope.

## Review corrections (post-cut)

Two findings from the post-cut review round, both adopted directly into the text above.

- **The collapse arm no longer inherits the mint arms' `undefined` carve-out** (blocking). The snapshot-less population is not empty: `docx-comments.ts` strips `textSnapshot`/`textSnapshotTruncated`/`textSnapshotBreaks` off every imported Word comment on the drift path and says so in its own comment; `docx-comment-export.ts` admits exactly those records via `isImportRoundtrip`, skips only `kind === "failed"`, and writes `refreshed.annotation.range` into the saved `.docx`. The collapse guard now requires `ann.textSnapshot !== undefined`, the Assumptions bullet names imported Word comments and states the export's bytes are unchanged for them, and **test 6's second half is inverted**: a snapshot-less collapse must still write `{n,n}`. As it stood, that test pinned the regression.
- **"The only stale surface" was claimed off a grep of `AGENTS.md` alone**, and two tracked docs state the removed behaviour as live rationale. `docs/gotchas.md:99` justifies the reload relocation with "*skipping* is no better, because `refreshAllRanges` has already minted a fresh `relRange` from the stale offsets — so the record ends up durably pinned to the wrong text and never revisited" — the file `CLAUDE.md` names as the home for this mechanism. `docs/decisions.md`'s ADR-032 **Amendment (2026-09-08)** — added by this same sweep's wave-3 docs-drift PR — states that exactly one caller reads `kind`, names `mcp/document-store.ts:229` among the discarders, and calls that the "no visible symptom" half of #1764; this PR changes `:229` and makes `tandem_getAnnotations` read `kind`, falsifying every clause.
