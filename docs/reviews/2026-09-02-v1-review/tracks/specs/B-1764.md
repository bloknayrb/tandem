# B — #1764 A read path persists a collapsed or unverified re-anchor, and `kind` is invisible

Branch `fix/annotation-anchors-1764`. Closes #1764 (all four numbered items of its body; the client-side split mapping in its "Suggested fix" is explicitly NOT taken — see Not in scope). Ledger: `docs/reviews/2026-09-02-v1-review/areas/crdt.md:17-19`. Probe: `experiments/crdt-verify.ts` (the `{4,4}` / `{4,5}` / `{1,1}` section) and `experiments/harness/f-undo.test.ts`, `f2-undo.test.ts`, `f3-undo.test.ts`.

## Problem

`refreshRange` (`src/server/positions.ts`) has three arms that write through the caller's `map` and one blind spot:

1. **Collapse is an `updated`.** When both RelativePositions resolve to the same offset (block split, heading toggle, block join), `newFrom === newTo`, the guard above only rejects `newFrom > newTo`, so the arm at the end returns `{kind: "updated"}` and `map.set`s `{4,4}`. The caller is `listAnnotationsRefreshed` (`src/server/mcp/document-store.ts`), a **read**. That `map.set` destroys the stored flat range — the fallback the watcher's relocation pass needs.
2. **The `repaired` arm re-anchors from the annotation's STORED flat offsets with no `textSnapshot` comparison** and persists the result. If the text moved while the relRange died, it mints a fresh, confident anchor over the wrong span. CLAUDE.md calls this difference unmeasured; the tests below measure it.
3. **The lazy-attach arm (`!ann.relRange`) is the same mint from the same unverified stored offsets.** Fixing only (2) is defeated one call later: a `degraded` result strips the relRange, and the next refresh takes the lazy path and mints the identical wrong anchor.
4. Once a collapse has been persisted, undo resolves the two zero-width anchors to opposite ends, `newFrom > newTo` fires, and the record is `failed` forever. The precondition is the persistence in (1).
5. Every MCP consumer except the `.docx` export discards `kind`, so none of the above has a visible symptom: `tandem_getAnnotations` reports a detached annotation as healthy.

## Fix

Surface `kind` first (it is what makes the rest observable), then stop persisting the two bad outcomes. No new `RefreshResult` kind — `degraded` already means "resolution did not produce a trustworthy range", so `assertNeverRefreshResult` and the `.docx` export switch are untouched.

- **`src/server/mcp/output-schemas.ts`** — add to `annotationWithRepliesSchema` (only; `annotationBaseShape` is shared with `checkInbox` and must not grow):
  `anchor: z.enum(["updated", "attached", "repaired", "degraded", "failed"]).optional().describe(...)`. Omitted when the refresh was `"ok"`, so a healthy read is byte-identical to today.
- **`src/server/mcp/document-store.ts`** — `listAnnotationsRefreshed()` returns `RefreshResult[]` (drop the trailing `.map((r) => r.annotation)`). No second method and no compat wrapper: two call sites, both in `src/server/mcp/annotations.ts`. Update the class docblock at the top of the file and the `{@link listAnnotationsRefreshed}` reference on `refreshAnnotations`.
- **`src/server/mcp/annotations.ts`** — `tandem_exportAnnotations` adds `.map((r) => r.annotation)` at its call site (no behaviour change). `tandem_getAnnotations` keeps its filter chain unchanged by building `const kindById = new Map(refreshed.map((r) => [r.annotation.id, r.kind]))` and `let results = refreshed.map((r) => r.annotation)`; the `annotationsWithReplies` assembly spreads `...(kind !== "ok" ? { anchor: kind } : {})`.
- **`src/server/positions.ts` `refreshRange`** — one module-private predicate, used at both mint sites:
  `function storedRangeStillMatches(ann, ydoc): boolean` — `true` when `ann.textSnapshot` is absent or not a non-empty string (nothing to verify — see the assumption below), otherwise `!snapshotContradicts(ann, extractText(ydoc).slice(ann.range.from, ann.range.to))`. `snapshotContradicts` (`src/shared/snapshot.ts`) is the single home for this comparison and already handles truncated snapshots by prefix; **do not inline a second copy of that rule.** An out-of-bounds stored range slices to `""` and therefore contradicts, which is the clamp #1765's body asks for — no separate length clamp.
  - Lazy-attach arm: when the predicate is false, return `{kind: "degraded", annotation: ann}` and **do not write**.
  - Dead-relRange arm: when the predicate is false, take the existing strip path (`delete stripped.relRange`, `map.set`, `degraded`) instead of minting. Stripping is required by the "strip dead RelativePositions, never preserve them" gotcha — it removes a field that resolves to null, it does not mint an anchor.
  - Collapse guard, immediately after the existing `newFrom > newTo` arm so the two "the CRDT no longer describes this annotation" verdicts sit together, and before the unchanged-offsets `ok` arm: `if (newFrom === newTo && ann.range.from !== ann.range.to) return {kind: "degraded", annotation: ann}` — no write, so the stored flat range and the relRange both survive for the watcher's snapshot relocation and for undo.
  - `extractText` is materialized only inside the predicate and only when a snapshot is present, so the common `ok`/`updated` path pays nothing.
  - **Critical Rule 2:** no new transaction. Every `map.set` here is already inside `refreshAllRanges`' `withMcp` (or the watcher's `withReload` via `skipTransact`); this change only removes writes.
  - **Critical Rule 4 is untouched** — `validateRange`'s check order is not on this path.
- **`docs/mcp-tools.md`** §`tandem_getAnnotations`: document `anchor`, naming `degraded` as "the anchor no longer describes this text; the range shown is the last one the server trusted".
- **`docs/architecture.md`** coordinate-systems section: add the paragraph-split caveat (a client block split collapses both RelativePositions; the server keeps the flat range and reports `degraded`).
- **`docs/decisions.md`** ADR-032: one sentence — `tandem_getAnnotations` now carries `kind` as `anchor`, so "MCP errors switch on kind" is no longer true of the `.docx` export alone.

## Tests

1. `tests/server/positions.test.ts` — **collapse**: build a doc, anchor `[from,to)` non-empty, splice the underlying XmlText so both relPos resolve to one offset, call `refreshRange(ann, doc, map)`; expect `kind === "degraded"`, `annotation.range` **unchanged**, and `map.get(id)` **untouched** (`toBe` the pre-call object). Kills a fix that returns `degraded` but still writes, and one that renames `updated` without keeping the range.
2. Same file — **collapse of an already-empty range still refreshes normally**: a point annotation (`from === to`) resolving to a new equal pair returns `updated`, not `degraded`. Kills a bare `newFrom === newTo` guard.
3. Same file — **repair refuses on a contradicting snapshot**: kill the relRange (replace the element's content), leave `ann.range` pointing at different text, `textSnapshot` from before; expect `degraded`, `relRange` absent on the stored record, and **no** `{fromRel,toRel}` minted. Then assert the negative twin: with the text at `ann.range` unchanged, the same call still returns `repaired` **with** a relRange. Without the twin the fix could refuse everything.
4. Same file — **byte-exact clone still repairs (#1800 regression guard)**: the `repairClonedAnchors` shape — records copied verbatim onto a doc whose content is byte-identical — must return `repaired`. `src/server/documents/annotation-wiring.ts` documents that path as "only safe because the clone is byte-exact"; this pins that the new guard reads it as safe.
5. Same file — **lazy attach refuses on a contradicting snapshot**: an annotation with no `relRange` whose stored offsets no longer hold its snapshot returns `degraded` and mints nothing. This is the test that kills fixing only the `repaired` arm.
6. Same file — **no snapshot ⇒ unchanged behaviour**: a record with no `textSnapshot` still gets `attached` / `repaired`.
7. `tests/server/mcp-tool-integration.test.ts` — `tandem_getAnnotations` on a healthy document returns records with **no** `anchor` key; after collapsing one annotation's anchors, the same call returns `anchor: "degraded"` on that record and none on the others. Kills a schema-only change that never populates the field.
8. `tests/client/annotation-block-split.test.ts` (new, `// @vitest-environment happy-dom`) — the three harness files `experiments/harness/f-undo.test.ts`, `f2-undo.test.ts`, `f3-undo.test.ts` rewritten as one spec with the assertions inverted: Enter before the range, Enter inside it, and the toolbar heading toggle each leave `refreshRange`'s stored range intact (`degraded`, not `{4,4}`); undo afterwards resolves the annotation back to its original offsets rather than `failed`. This is the harness→spec conversion the track's Done-when requires.

## Done when

Nothing writes a collapsed or snapshot-contradicting range from `refreshRange`; `crdt-verify.ts` prints the original ranges or `degraded`, never `{4,4}`; `tandem_getAnnotations` carries `anchor`; the three docs lines land; typecheck + suite green.

## Assumptions

- **An annotation with no `textSnapshot` keeps today's unverified re-anchor.** There is nothing to verify against and refusing would strand every pre-snapshot record permanently.
- **A contradicting re-anchor answers `degraded`, not `failed`** (the issue and the track both float `failed`). `failed` is the `.docx` export's skip signal, so promoting a recoverable stale anchor to `failed` would drop a real comment from an export; `degraded` leaves the stored flat range usable.
- **`refreshRange` keeps its `map` parameter and `listAnnotationsRefreshed` keeps passing it.** Removing the write wholesale would stop the relRange re-attachment reaching the durable envelope; the narrow fix is to stop persisting the two untrustworthy outcomes.
- **`failed` stays non-recoverable and unwritten.** Stripping an inverted relRange would hand the record straight to the lazy-attach mint this spec is restricting.
