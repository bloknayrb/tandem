## Problem

#630's item 2 has two clauses left. The first — *"`startup-file-error` does not exist anywhere in the tree … a double-click whose classification succeeds and whose sidecar POST then fails still surfaces nothing"* — **is refuted at HEAD.** It shipped as a reason code on the existing buffered bus rather than as a second event:

- `post_paths_and_surface` (`src-tauri/src/lib.rs:559-577`) records `CODE_OPEN_FAILED` (`startup_rejection.rs:170`, literally `"open-failed"`) for every failed POST and resolves the batch through `surface_startup_rejection`.
- `handle_opened_urls` (`lib.rs:659`) records the same code for `OpenRoute::ServerUnavailable`.
- The client renders it at `src/client/utils/startup-rejection.ts`'s `case "open-failed"`, with an explicit comment that the arm is byte-identical to `default` on purpose so a Rust-side rename shows up as version skew.
- `startup_rejection.rs:601 a_failed_post_surfaces_the_open_failed_code_once` already pins it.

**Adding a distinct `startup-file-error` event now would be a regression, not the fix.** CLAUDE.md's Files gotcha is explicit that rejection delivery is two-surfaced and the **buffer** is load-bearing: the reason code is buffered unconditionally and drained by `get_startup_rejection`, and the event is a payload-free nudge that must never become the carrier. A second event would be a second carrier.

The second clause is real and is the only thing this PR does: *"the regex assertion the body specifies should land in the same commit as the failure surface, asserting no `Authorization: Bearer` content reaches the wire."* It never landed.

**What is actually true today, stated precisely, because the round-1 review showed the earlier wording was misleading.** The leak is impossible *by type*, not merely by current code: `RejectionBatch::record` takes `&'static str` (`startup_rejection.rs:227`), `resolve` returns `Option<&'static str>` (`:238`), and `post_paths_and_surface`'s sink is `impl FnOnce(&'static str) + Send` (`lib.rs:565`), whose docblock (`:553-556`) and `buffer_startup_rejection_code`'s (`startup_rejection.rs:102-110`) both call that bound load-bearing — "a compile error rather than a thing tests have to notice". So the tempting edit the old spec named, `batch.record(&e)` or `batch.record(&format!("open-failed: {e}"))`, is **E0308/E0597 and never reaches a test**. The only mutation that compiles is a deliberate `Box::leak`.

That makes the new test a **pin on the bound's consequence**, not a discovery of runtime behaviour: while the `'static` bound stands, its substring assertions are unreachable. It is worth writing anyway for the one regression the type system does not stop — a future widening of `record`/`resolve`/`surface` to `&str`, which is exactly what the docblocks warn against and which today nothing in `tests/` would notice. The bound itself is therefore pinned too (below), so the widening reddens something.

## Tests

**1. One new `#[test]` in `startup_rejection.rs`'s test module, `a_post_error_carrying_a_bearer_token_never_reaches_the_surface`:**

- Drive `run_batch_with(&["a.md"], &["a.md"], None, "POST http://127.0.0.1:3479/api/open failed: authorization: Bearer tandem-secret-abc123")`.
- Assert the surfaced vector is exactly `vec!["open-failed"]`.
- Assert no surfaced code contains the token material, **normalising case explicitly** — `str::contains` is case-sensitive and the surfaced values are `&'static str`, so write `code.to_ascii_lowercase().contains("bearer")` and the same for `"tandem-secret"` and `"authorization"`, not a bare `contains("Bearer")` that the seeded fixture happens to satisfy.
- Assert every surfaced code is a member of the known `CODE_*` set.
- The test's docblock states two things a later reader will otherwise get wrong: (a) while `record`/`resolve`/`surface` are `&'static str`, these substring assertions are **unreachable**, so this is a pin on that bound rather than on behaviour; (b) the adjacent WebView-visible channel is deliberately out of scope — `lib.rs:573` logs `log::warn!("request_open_file ({what}) failed for {}: {e}", …)` with the raw error, and `tauri-plugin-log` registers `TargetKind::Webview` at `LevelFilter::Warn` in release, so warn lines *are* forwarded to the WebView as `log://log` events. Nothing leaks there today, because the `Bearer` header is built at `lib.rs:296-298` and `reqwest::Error`'s `Display` does not render request headers — but this test says nothing about it, and must not be read as covering it.

**2. A type-signature pin**, added as one `it()` to the existing `tests/docs/startup-open-failure-wiring-claims.test.ts` (an added case in a file that already scans Rust via `rustSourceDefining`, not new framework):

- Assert `startup_rejection.rs`'s code view still matches `/fn record\(&mut self, code: &'static str\)/` and `/fn resolve\(&self\) -> Option<&'static str>/`, and `lib.rs`'s still matches `/surface: impl FnOnce\(&'static str\)/`.
- Each regex carries a trailing boundary (the closing paren is the boundary), so a rename or a widening to `&str` fails the match rather than matching as a prefix.
- The failure message names the consequence: widening any of the three lets a formatted `String` — an error body, a path, a header — reach the buffer the WebView renders, and the Rust test above is what would then start doing real work.

What each half kills: the equality assertion kills a change that records the error text instead of the constant; the substring assertions name the actual hazard in the failure message and catch a code "enriched" with context under a widened signature; the membership assertion kills a new dynamic code minted from a `String` leak; the signature pin is what makes the widening itself visible. Keeping `"boom"` on the five existing call sites preserves them as the negative controls.

## Done when

`run_batch_with` exists with `run_batch` delegating; the token-leak test and the signature pin pass; the PR body records the **inverted mutation in the form that actually compiles** — `batch.record(Box::leak(format!("{CODE_OPEN_FAILED}: {e}").into_boxed_str()))` at `lib.rs:574`, which reddens the substring assertions — and states that the naive `batch.record(&e)` is refused by the type system, which is the first layer; `cargo test` green; the PR body says #630 stays **open** and states the refutation of its first clause, so nobody re-files `startup-file-error`.

**Not adopted**

- *Relax `RejectionBatch::record` / `resolve` and `post_paths_and_surface`'s sink from `&'static str` to `&str` so the named mutation compiles* (blocking finding 3's stated fix). Refuted: that relaxation **is** the regression. `buffer_startup_rejection_code`'s docblock (`startup_rejection.rs:102-110`) records that `Display for OpenedUrlRejection` embeds the resolved path, so a `&str` sink would accept `&format!("{reason}")` and put a filesystem path on the wire to the DOM — "a compile error rather than a thing tests have to notice" — and `lib.rs:553-556` adds that the `Send`/`'static` bounds are what make the test's `block_on` and the real `tauri::async_runtime::spawn` agree; without them the test compiles and the call sites do not. Weakening a production safety type to make a demonstration mutation runnable inverts the point of the issue. The same finding's alternative (option (b) in finding 11) is adopted instead: the compiling `Box::leak` mutation plus a signature pin.
