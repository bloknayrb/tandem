## Problem — both clauses of item 2 are refuted at HEAD

**Clause 1** — *"`startup-file-error` does not exist anywhere in the tree … a double-click whose classification succeeds and whose sidecar POST then fails still surfaces nothing"*. It shipped as a reason code on the existing buffered bus rather than as a second event:

- `post_paths_and_surface` (`src-tauri/src/lib.rs:559-577`) records `CODE_OPEN_FAILED` (`startup_rejection.rs:170`, literally `"open-failed"`) for every failed POST and resolves the batch through `surface_startup_rejection`.
- `handle_opened_urls` (`lib.rs:659`) records the same code for `OpenRoute::ServerUnavailable`.
- The client renders it at `src/client/utils/startup-rejection.ts`'s `case "open-failed"`, with a comment that the arm is byte-identical to `default` on purpose so a Rust-side rename shows as version skew.
- `startup_rejection.rs:601 a_failed_post_surfaces_the_open_failed_code_once` already pins it.

Adding a distinct `startup-file-error` event now would be a **regression**: CLAUDE.md's Files gotcha is explicit that rejection delivery is two-surfaced and the **buffer** is load-bearing — the code is buffered unconditionally and drained by `get_startup_rejection`, and the event is a payload-free nudge that must never become the carrier. A second event is a second carrier.

**Clause 2** — *"the regex assertion the body specifies should land in the same commit as the failure surface, asserting no `Authorization: Bearer` content reaches the wire"*. The assertion never landed, but the leak it describes is **impossible by type, not by current code**:

- `RejectionBatch::record` takes `&'static str` (`startup_rejection.rs:227`), `resolve` returns `Option<&'static str>` (`:238`), and `post_paths_and_surface`'s sink is `impl FnOnce(&'static str) + Send` (`lib.rs:565`).
- Both docblocks (`lib.rs:553-556`, `startup_rejection.rs:102-110`) call that bound load-bearing — "a compile error rather than a thing tests have to notice".
- So every mutation the issue body implies — `batch.record(&e)`, `batch.record(&format!("open-failed: {e}"))` — is E0308/E0597 and never reaches a test. The only compiling mutation is a deliberate `Box::leak`.

A runtime test written against that bound therefore **cannot fail while the bound stands**: its substring assertions are unreachable, and it would restate `a_failed_post_surfaces_the_open_failed_code_once` with an unused error string. The only thing that would make it discriminating is a signature pin — a source-scanning drift guard in `tests/docs`, which is a mechanism the issue did not ask for and which this scope cut removes.

## Fix

**None. No production change, no test change, no new dependency.** The sliver this group authorised is "the unambiguous one"; measurement shows it is not unambiguous — it needs a design call (spend a test on a type-guaranteed property, or pin the signatures with a scanner), so per the group's own instruction this spec makes no change and says so.

The PR body carries the refutation, so the evidence is tracked rather than living only here:

- clause 1 is already implemented as `CODE_OPEN_FAILED` on the buffered bus, with the four citations above — nobody should re-file `startup-file-error`;
- clause 2's hazard is refused by the `&'static str` bound at three sites, with those citations;
- #630 stays **open** on items 4–8 and the macOS hardware validation.

## Review corrections (scope cut)

**Removed**

- *The `tests/docs/startup-open-failure-wiring-claims.test.ts` type-signature pin* — removed, not repaired. It is a source-scanning drift guard over three Rust signatures; #630 asked for a token-leak assertion, not a gate on the crate's type surface. Routed to `bryan` as a decision instead.
- *The new `a_post_error_carrying_a_bearer_token_never_reaches_the_surface` test and the `run_batch_with` seam* — removed. With the signature pin gone the test is non-discriminating by construction (two blocking findings said so: the assertions are unreachable while the `'static` bound stands, and the mutation named in Done-when does not compile). Shipping a test that cannot fail, plus a refactor of an existing helper to feed it, is exactly the framework the minimality rule forbids.
- *The Done-when mutation record* (`Box::leak(...)`) — gone with the test.

**Fixed directly**

- Both blocking findings are made moot by the removals rather than answered: there is no mutation to record and no unreachable assertion to caveat. The refutation they rest on is now the spec's whole content.

**Not adopted**

- *Relax `record` / `resolve` / `surface` from `&'static str` to `&str` so the named mutation compiles* (blocking finding 3's stated fix). That relaxation **is** the regression: `Display for OpenedUrlRejection` embeds the resolved path, so a `&str` sink would accept `&format!("{reason}")` and put a filesystem path on the wire to the DOM. Weakening a production safety type to make a demonstration mutation runnable inverts the point of the issue.
