## Problem

#630's item 2 has two clauses left. The first — *"`startup-file-error` does not exist anywhere in the tree … a double-click whose classification succeeds and whose sidecar POST then fails still surfaces nothing"* — **is refuted at HEAD.** It shipped as a reason code on the existing buffered bus rather than as a second event:

- `post_paths_and_surface` (`src-tauri/src/lib.rs:559-577`) records `CODE_OPEN_FAILED` (`startup_rejection.rs:170`, literally `"open-failed"`) for every failed POST and resolves the batch through `surface_startup_rejection`.
- `handle_opened_urls` (`lib.rs:659`) records the same code for `OpenRoute::ServerUnavailable`.
- The client renders it at `src/client/utils/startup-rejection.ts`'s `case "open-failed"`, with an explicit comment that the arm is byte-identical to `default` on purpose so a Rust-side rename shows up as version skew.
- `startup_rejection.rs:601 a_failed_post_surfaces_the_open_failed_code_once` already pins it.

**Adding a distinct `startup-file-error` event now would be a regression, not the fix.** CLAUDE.md's Files gotcha is explicit that rejection delivery is two-surfaced and the **buffer** is load-bearing: the reason code is buffered unconditionally and drained by `get_startup_rejection`, and the event is a payload-free nudge that must never become the carrier. A second event would be a second carrier.

The second clause is real and is the only thing this PR does: *"the regex assertion the body specifies should land in the same commit as the failure surface, asserting no `Authorization: Bearer` content reaches the wire."* It never landed. It is currently true **by construction** (the surfaced value is a `&'static str` constant, and `request_open_file` builds the `Bearer` header at `lib.rs:296-298` while its error strings are formatted from `reqwest`'s `Display`), but nothing pins it. An implementation that "improved" the toast by recording `&e` instead of `CODE_OPEN_FAILED` — the obvious, tempting edit — would put the POST error text, and with it anything `reqwest` ever decides to include, into the buffer the WebView renders. Every existing test uses the error string `"boom"`, so none of them would notice.

## Fix

Test-only. No production Rust or TypeScript changes.

- `src-tauri/src/startup_rejection.rs`, test module: split the hard-coded `Err("boom".to_string())` out of `run_batch` (`:546-590`). Add `fn run_batch_with(paths, failing, seed, err: &'static str) -> Vec<&'static str>` holding the existing body with `err` substituted for `"boom"`, and make `run_batch` a one-line delegation passing `"boom"`. Five existing call sites are untouched, which keeps this a strictly additive seam.
- Add the assertion described below. No `httpmock`, no new dev-dependency, no `build_open_request` factoring: the existing injected-poster seam (`post_paths_and_surface` is generic over the poster precisely so it is testable with neither an HTTP server nor an `AppHandle`, per its docblock at `lib.rs:551-558`) serves, and the task's instruction is to prefer no new dependency.

Rules that bite: `CARGO_TARGET_DIR=C:/Users/blokn/Documents/Github/tandem/src-tauri/target` on every cargo call; the worktree needs the `src-tauri/binaries/{node-sidecar,tandem-reaper}-$TRIPLE{,.exe}` stubs. Nothing here touches Y.Doc writes, MCP tools, `/api` routes or `NON_LOOPBACK_ALLOWED`.

## Tests

One new `#[test]` in `startup_rejection.rs`'s test module, `a_post_error_carrying_a_bearer_token_never_reaches_the_surface`:

- Drive `run_batch_with(&["a.md"], &["a.md"], None, "POST http://127.0.0.1:3479/api/open failed: authorization: Bearer tandem-secret-abc123")`.
- Assert the surfaced vector is exactly `vec!["open-failed"]`, **and** that no surfaced code contains `"Bearer"`, `"tandem-secret"` or `"authorization"` (case-insensitively), and that every surfaced code is a member of the known `CODE_*` set.

What each half kills: the equality assertion kills a change that records the error text instead of the constant; the substring assertions kill a change that *appends* or *formats* the error onto the code (`format!("open-failed: {e}")`), which the equality alone would also catch but which would be re-introduced the moment someone "enriches" the code with context — the substring form names the actual hazard in the failure message, which is what a future reader needs. The membership assertion kills a new dynamic code minted from a `String` leak. Keeping `"boom"` on the five existing call sites preserves them as the negative controls.
