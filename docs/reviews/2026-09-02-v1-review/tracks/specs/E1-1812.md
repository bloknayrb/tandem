# E1 — #1812 Sidecar health poll accepts any HTTP 2xx, so it passes against an old process

Branch `fix/desktop-core-1761`. Closes #1812. Ledger: `docs/plans/2026-09-06-open-issues-sweep.md:413`; area rows `docs/reviews/2026-09-02-v1-review/areas/tauri.md:21` and `areas/server-runtime.md:21`. Probe: `tests/server/health-route.test.ts` + `cargo test`; the cross-process case is a smoke line (Bryan).

## Problem

`wait_for_health` (`src-tauri/src/sidecar.rs:1736-1760`) returns `Ok(())` on `resp.status().is_success()` from `HEALTH_URL`. It never compares the responder with the child it just spawned (`child.pid()` at `:1638`, stored into `SidecarState` at `:1690`). So a 2xx from a **previous** process still holding :3479 — one waiting on the annotation-store lock, one dying slowly, or one an unrelated `tandem` started — is accepted as "our sidecar is healthy": `SIDECAR_HEALTHY` is promoted, the pending-open queue is drained at a server the shell does not own, and when the old process finally exits the shell has no signal because the process it watches is a different one. The UI stays green with no backend.

**The same blindness has a second call path, and it is the one that writes.** `graceful_stop_request` (`sidecar.rs:633-672`) POSTs `/api/shutdown` whenever `owns_child` is true, and the comment there states the consequence verbatim: with a foreign Tandem on :3479 "the POST hits *that* server, which flushes and exits, while this log line claims a graceful stop". It also records a window nobody has to misconfigure anything to reach — the child is stored into `SidecarState` **before** `wait_for_health` runs, so `owns_child` is true for up to `HEALTH_TIMEOUT` while a different process may be answering. Both `sidecar.rs:1560-1566` and `:648-672` name **#1812** as the fix for exactly this. Round 1 refused the original spec's deferral: closing #1812 while leaving that gap would leave two source comments pointing at a closed issue and an untracked defect, so the fix covers both call paths.

`/health` (`src/server/mcp/routes/health.ts`) publishes `status`, `version`, `transport` publicly and `hasSession` / `push` / `delivery` to loopback callers. **Nothing identifies the process.**

## Fix

Add a process identity to `/health`, and make both the post-spawn poll and the graceful-stop POST require it to match the spawned child.

- `src/server/mcp/routes/health.ts`: inside the existing `isLoopback(req.socket.remoteAddress)` block, add `body.pid = process.pid`. **Loopback-only, deliberately** — the file's docblock already establishes that identity/presence signals are withheld from LAN callers, and this is one. Read `process.pid` directly; do not add a `HealthHandlerDeps` field for it (a dep would be a seam with exactly one possible value, and the factory already exists so the gate can be driven).
- **Extend that route's own field enumeration in the same edit.** The docblock at `health.ts:37-41` reads "Public: `status`, `version`, `transport`. Loopback-only: `hasSession`, `push` and `delivery`" and then tells the next reader to keep it in mind before adding a field. Add `pid` to the loopback-only list with one sentence: it is a process identity, which is a presence signal in the same class as `hasSession`; and record why `generationId` is not an option (next bullet) there rather than only in the PR body, because that is where the next person will look.
- **Do NOT expose `generationId`.** It is pinned as the Hocuspocus provider's auth token (CLAUDE.md, Y.js/CRDT), so publishing it on `/health` would hand a connection credential to any loopback page — and the CORS allowlist is port-wildcarded. The issue offers `generationId`/PID as alternatives; PID is the one that is safe here.
- `src-tauri/src/sidecar.rs` — **split the poll so the call site is testable**, matching the `check_health` / `check_health_at` shape the file already uses (`:1769`, `:1788`, whose docblock says the URL parameter exists precisely so a test listener can be substituted):
  - `async fn wait_for_health_at(client, health_url: &str, sidecar_dead: &AtomicBool, child_pid: u32, timeout: Duration) -> Result<(), String>` holds today's loop, with the loop bound read from the **parameter** rather than from the module const. On a 2xx, read the body and accept only when `health_body_is_our_child(&body, child_pid)`. A mismatch or a missing/unparseable `pid` is **not** an error — record it in `last_error` and keep polling, so the timeout handles it.
  - **The `timeout` parameter is load-bearing, not symmetry.** `HEALTH_TIMEOUT` is `Duration::from_secs(30)` (`sidecar.rs:100`) and the elapsed check uses `std::time::Instant` (`:1741`), which `tokio::time::pause()` cannot advance — so without the parameter test 3's discriminating `Err` case costs **30 s of real wall clock** on all three required `rust-test` legs (`.github/workflows/ci.yml:61-63`) and in the pre-push hook, and the cheapest way out for an implementer is to delete the case that does the discriminating. This is the same seam shape the file already uses for the URL (`check_health` / `check_health_at`, `:1769-1773`, whose docblock says the parameter exists so a test listener can be substituted).
  - **Two distinct mismatch log lines, at `warn`, once per distinct observed state** (repeating either every 250 ms poll would bury the log): `"health answered by a different process (pid {observed}, expected {child_pid}) — still waiting"`, and — separately — `"health body carries no pid — this sidecar predates the identity check; still waiting"`. Splitting them is what makes the stale-`dist` dev state diagnosable; see the behaviour bullet below.
  - `wait_for_health(client, sidecar_dead, child_pid)` becomes the `HEALTH_URL` + `HEALTH_TIMEOUT` wrapper; its one call site is `:1695`.
  - `fn health_body_is_our_child(body: &str, child_pid: u32) -> bool` is the pure predicate.
- `src-tauri/src/sidecar.rs`, `graceful_stop_request`: before the `owns_child` POST, GET `endpoints.health` and compare against the owned child's pid. **Skip the POST ONLY on a positive foreign identity** — a 2xx body carrying a parseable numeric `pid` that differs from the child's. Log `"shutdown target is not our child (pid {observed}, expected {child_pid}) — skipping the flush request"` and fall through to the existing hard-kill arm.
  - **Every other identity-GET outcome POSTs exactly as today**: a transport error, a timeout, a non-2xx, an unparseable body, or a 2xx body with **no `pid` key**. Log the reason at `warn` and proceed. This is not caution for its own sake — the POST is what flushes the user's unsaved edits (`sidecar.rs:634-645`), and the function's own comment records the defect of keying the safe arm on the wrong error class verbatim (`:686-727`: "Keying the safe arm on `is_timeout()` was the first fix repeating the defect one error class over"), which is why only `is_connect()` and a non-2xx are read as "nothing started" and everything else becomes `Posted::Unconfirmed`. A health GET that stalls after connecting is not evidence of a foreign process. And the pid-less body is not an edge case: **`/health` gains `pid` in this same PR, so every previously-built sidecar answers without one** — a stale `target/debug/dist` under `cargo tauri dev`, a shell/sidecar version skew, an update in flight. Treating that as foreign would hard-kill the flush on *every* Quit, by default, against any sidecar that predates the change.
  - **Bound the identity GET with its own short timeout — 1 s, well under `EXIT_GRACEFUL_BUDGET`.** The same call runs inside the exit budget (`graceful::attempt`'s `tokio::time::timeout(budget, …)`, `sidecar.rs:1198-1226`), so an unbounded probe against a listener that accepts and never answers can consume the budget and reach the hard kill with no flush attempted at all.
  - **Both call sites take the pid, and they are not symmetric.** `stop_sidecar_gracefully` (`:565-582`) already holds the `SidecarState` guard and can read `child.pid()` beside the `owns_child` derivation. The exit path cannot: `graceful::attempt` (`:1171-1226`) receives `owned_child` inside `Prep` (`:1059-1071`), so the pid must be captured in `graceful::prepare_inner` (`:1121-1127`, the same `try_state`/poison-tolerant lock read) and carried through `Prep` as an `Option<u32>` — and deliberately **not** echoed into `Outcome`, which reports the verdict rather than the target. The five existing unit tests that construct `graceful_stop_request` directly (`:3002`, `:3138`, `:3184`, `:3228`, `:3267`) each take the new argument.
  - Update both source comments (`:1560-1566` and `:648-672`) to say the identity check now exists, what it does **not** do (a pid-less or unreachable `/health` still POSTs), and keep `#1825`'s hardcoded-URL half named as still open.
- **Leave `check_health`, `check_health_at`, `wait_for_port_release` and `wait_for_server_gone` alone.** They ask "is *anything* answering", which is the correct question for the port-release wait (any responder means the port is still held) and for the debug-only adoption fast path at `sidecar.rs:1454` (`cfg!(debug_assertions)`), which is what lets `cargo tauri dev` attach to a hand-started `dev:standalone`. Narrowing them would break both. **This is also what keeps the desktop's port-conflict recovery intact** — see the next bullet.
- **The poll's behaviour change also fires against the shell's OWN child when the built sidecar predates this PR — record it in `docs/gotchas.md` (Desktop / Tauri) and the PR body.** `wait_for_health` polls the child just spawned (`:1695`, pid captured `:1638`), and the desktop dev loop does **not** rebuild the sidecar when server code changes (the project gotcha: `build:server` + copy into `target/debug/dist` + restart). A stale `dist` answers `/health` with no `pid`, which the poll correctly declines, so the loop burns the full 30 s `HEALTH_TIMEOUT` × `MAX_RESTARTS` and lands in "Retry Server Start" with nothing in the log to explain it. The distinct `"health body carries no pid — this sidecar predates the identity check"` line is the diagnosis; the fix is to rebuild `dist`. This is the one case where the poll and the shutdown POST deliberately diverge: the poll must decline an unidentified responder (accepting it restores the bug), while the POST must proceed (skipping it destroys the flush).
- **Behaviour change worth naming in the PR body, and read it together with E1-1758.** In a **release** build, a foreign or pre-upgrade Tandem on :3479 now makes `wait_for_health` time out rather than falsely succeed, so the shell takes its existing `Err` arm — kill our child, back off, retry, and after `MAX_RESTARTS` the "Retry Server Start" dialog with `port_holder_for_dialog` naming the holder. That is only safe because **E1-1758's refusal does not fire for the Tauri sidecar**: the child still runs `freePort` on start (`sidecar.rs:1450-1453` designates that as the shell's port-conflict handler), so a stale holder is cleared on the next attempt and the app self-heals. If that carve-out is ever removed, this change turns an automatic recovery into a permanent dialog — say so in the PR body so the two are never separated.

## Tests

1. `tests/server/health-route.test.ts` (already drives `makeHealthHandler` with a synthetic non-loopback request): assert `pid` is `process.pid` for a loopback request and **absent** for `203.0.113.5`. **Additionally: `PUBLIC_KEYS` (`:57`) stays a three-element list and `pid` must never join it.** That constant — asserted by equality at `:95-97` and `:99-101` — is what makes hoisting the field out of the loopback gate fail; a fix that adds `"pid"` to `PUBLIC_KEYS` would keep the new case green while reopening the exact regression this file was written for.
2. `src-tauri/src/sidecar.rs` — a `#[cfg(test)]` unit test over `health_body_is_our_child`: matching pid → true; different pid → false; **body with no `pid` key → false**; non-JSON body → false. **What each kills:** the third case kills a `serde` default or `unwrap_or(child_pid)` that treats an unidentified responder as ours (which restores today's bug against every pre-fix server), and the fourth kills a `contains("pid")` string check.
3. `src-tauri/src/sidecar.rs` — **a call-site test, because the predicate alone does not pin that anything consults it.** Stand up a loopback `tokio` `TcpListener` (the file already does this at `:2512`, `:2959`, `:3033`, `:3076`, including a canned 404 for `check_health_at`) and drive `wait_for_health_at` against it, passing `timeout: Duration::from_secs(1)`: a listener serving `{"status":"ok","pid":<child_pid + 1>}` must return `Err`; one serving `{"status":"ok","pid":<child_pid>}` must return `Ok`. **What it kills:** `health_body_is_our_child` existing, passing its four cases, and never being called — under which every other test here stays green and Done-when reads satisfied. The explicit `timeout` argument is what makes the `Err` case cost ~1 s rather than 30 s on every required leg; see the Fix bullet.
4. `src-tauri/src/sidecar.rs` — the same listener shape against `graceful_stop_request`, **three cases, and the last two are the ones that protect the user's edits**:
   - `owns_child: true` and a health listener reporting a **foreign pid** → the shutdown endpoint receives **no** request. **What it kills:** the identity check landing on the poll only, which is the half round 1 refused to defer.
   - `owns_child: true` and a health listener answering `{"status":"ok"}` with **no `pid`** → the shutdown endpoint **MUST** receive the request. **What it kills:** treating "unidentified" as "foreign" — which is the DEFAULT outcome against every sidecar built before this PR, so that reading would hard-kill the flush on every Quit while all the other tests here stayed green.
   - `owns_child: true` and a health listener that **accepts the connection and never answers** → the shutdown endpoint **MUST** still receive the request, and the whole call must return well inside the exit budget. **What it kills:** a fail-closed identity GET that both skips the flush on a transient stall and burns the budget doing it — the defect class `graceful_stop_request`'s own comment (`:686-727`) records having shipped once already.
5. `src-tauri/src/sidecar.rs` — a `#[cfg(test)]` case pinning that `graceful::prepare_inner` carries the owned child's pid into `Prep` and that `attempt` passes it through: construct the `Prep` by hand with `Some(pid)` and assert the value reaching `graceful_stop_request` is that pid (the existing five direct-construction tests at `:3002`, `:3138`, `:3184`, `:3228`, `:3267` are the shape to follow). **What it kills:** wiring the identity check into `stop_sidecar_gracefully` only, leaving the exit path — the Quit that actually loses edits — passing `None` and therefore never checking anything.

## Done when

`/health` carries `pid` for loopback callers only and its docblock enumeration names it; `wait_for_health` accepts only the child it spawned, logs the two distinct mismatch lines, takes its timeout as a parameter, and has a test driving the real call site at ~1 s; `graceful_stop_request` skips the `/api/shutdown` POST **only** on a positive foreign pid and POSTs on every inconclusive outcome (pid-less body, non-2xx, unparseable, transport error, stall), with its identity GET separately bounded; both call sites carry the pid, the exit path's through `Prep`; both `sidecar.rs` comments naming #1812 are updated; the stale-`dist` dev consequence is in `docs/gotchas.md`; `check_health` and the port-release waits are unchanged; `PUBLIC_KEYS` is still three elements.
