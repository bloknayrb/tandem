# E1 — #1812 Sidecar health poll accepts any HTTP 2xx, so it passes against an old process

Branch `fix/desktop-core-1761`. Closes #1812. Ledger: `docs/plans/2026-09-06-open-issues-sweep.md:413`; area rows `docs/reviews/2026-09-02-v1-review/areas/tauri.md:21` and `areas/server-runtime.md:21`. Probe: `tests/server/health-route.test.ts` + `cargo test`; the cross-process case is a smoke line (Bryan).

## Problem

`wait_for_health` (`src-tauri/src/sidecar.rs:1736-1760`) returns `Ok(())` on `resp.status().is_success()` from `HEALTH_URL`. It never compares the responder with the child it just spawned (`child.pid()` at `:1638`, stored into `SidecarState` at `:1690`). So a 2xx from a **previous** process still holding :3479 — one waiting on the annotation-store lock, one dying slowly, one an unrelated `tandem` started — is accepted as "our sidecar is healthy": `SIDECAR_HEALTHY` is promoted, the pending-open queue is drained at a server the shell does not own, and when the old process exits the shell has no signal. The UI stays green with no backend.

**The same blindness has a second call path, and it is the one that writes.** `graceful_stop_request` (`sidecar.rs:633-672`) POSTs `/api/shutdown` whenever `owns_child` is true, and the comment there states the consequence verbatim: with a foreign Tandem on :3479 "the POST hits *that* server, which flushes and exits, while this log line claims a graceful stop". The child is stored into `SidecarState` **before** `wait_for_health` runs, so `owns_child` is true for up to `HEALTH_TIMEOUT` while a different process may be answering. Both `sidecar.rs:1560-1566` and `:648-672` name **#1812** as the fix for exactly this, so closing the issue while covering only the poll would leave two source comments pointing at a closed issue.

`/health` (`src/server/mcp/routes/health.ts`) publishes `status`, `version`, `transport` publicly and `hasSession` / `push` / `delivery` to loopback callers. **Nothing identifies the process.**

## Fix

- `src/server/mcp/routes/health.ts`: inside the existing `isLoopback(req.socket.remoteAddress)` block, add `body.pid = process.pid`. **Loopback-only, deliberately** — the docblock already establishes that identity/presence signals are withheld from LAN callers, and this is one. Read `process.pid` directly; no `HealthHandlerDeps` field (a dep with exactly one possible value). Add `pid` to the loopback-only list in that file's own docblock enumeration (`health.ts:37-41`) in the same edit.
- **Do NOT expose `generationId`.** It is pinned as the Hocuspocus provider's auth token (CLAUDE.md, Y.js/CRDT), so publishing it on `/health` hands a connection credential to any loopback page, and the CORS allowlist is port-wildcarded. The issue offers `generationId`/PID as alternatives; PID is the safe one.
- `src-tauri/src/sidecar.rs` — **split the poll so the call site is testable**, matching the `check_health` / `check_health_at` shape the file already uses (`:1769-1773`, whose docblock says the URL parameter exists so a test listener can be substituted):
  - `async fn wait_for_health_at(client, health_url: &str, sidecar_dead: &AtomicBool, child_pid: u32, timeout: Duration) -> Result<(), String>` holds today's loop, with the bound read from the **parameter**. On a 2xx, read the body and accept only when `health_body_is_our_child(&body, child_pid)`. A mismatch or a missing/unparseable `pid` is **not** an error — record it in `last_error` and keep polling, so the timeout handles it.
  - **The `timeout` parameter is load-bearing, not symmetry.** `HEALTH_TIMEOUT` is `Duration::from_secs(30)` (`sidecar.rs:100`) and the elapsed check uses `std::time::Instant` (`:1741`), which `tokio::time::pause()` cannot advance — so without it test 3's discriminating `Err` case costs **30 s of real wall clock** on all three required `rust-test` legs (`.github/workflows/ci.yml:61-63`) and in the pre-push hook, and the cheapest way out for an implementer is to delete the case that does the discriminating.
  - **Two distinct `warn` lines, once per distinct observed state** (repeating either every 250 ms poll would bury the log): `"health answered by a different process (pid {observed}, expected {child_pid}) — still waiting"`, and separately `"health body carries no pid — this sidecar predates the identity check; still waiting"`. The second is the diagnosis for a stale `target/debug/dist` under `cargo tauri dev`, where the shell's own child answers without a `pid` and the loop burns `HEALTH_TIMEOUT` × `MAX_RESTARTS`; the fix there is to rebuild `dist`. Name that in the PR body.
  - `wait_for_health(client, sidecar_dead, child_pid)` becomes the `HEALTH_URL` + `HEALTH_TIMEOUT` wrapper; its one call site is `:1695`.
  - `fn health_body_is_our_child(body: &str, child_pid: u32) -> bool` is the pure predicate.
- `src-tauri/src/sidecar.rs`, `graceful_stop_request`: before the `owns_child` POST, GET `endpoints.health` and compare against the owned child's pid. **Skip the POST ONLY on a positive foreign identity** — a 2xx body carrying a parseable numeric `pid` that differs. Log `"shutdown target is not our child (pid {observed}, expected {child_pid}) — skipping the flush request"` and fall through to the existing hard-kill arm.
  - **Every other identity-GET outcome POSTs exactly as today**: transport error, timeout, non-2xx, unparseable body, or a 2xx body with **no `pid` key**. Log the reason at `warn` and proceed. The POST is what flushes the user's unsaved edits (`sidecar.rs:634-645`), and the function's own comment records this exact defect class shipping once already (`:686-727`: "Keying the safe arm on `is_timeout()` was the first fix repeating the defect one error class over"), which is why only `is_connect()` and a non-2xx read as "nothing started". A health GET that stalls after connecting is not evidence of a foreign process. And a pid-less body is not an edge case: **`/health` gains `pid` in this same PR, so every previously-built sidecar answers without one** — treating that as foreign would hard-kill the flush on *every* Quit against any pre-change sidecar.
  - **Bound the identity GET at 1 s**, well under `EXIT_GRACEFUL_BUDGET`. The same call runs inside `graceful::attempt`'s `tokio::time::timeout(budget, …)` (`sidecar.rs:1198-1226`), so an unbounded probe against a listener that accepts and never answers can consume the budget and reach the hard kill with no flush attempted.
  - **Both call sites pass the pid, as `Option<u32>`, and `None` means "no check" (today's behaviour).** `stop_sidecar_gracefully` (`:565-582`) already holds the `SidecarState` guard and reads `child.pid()` beside the `owns_child` derivation. The exit path receives `owned_child` inside `Prep` (`:1059-1071`), so the pid is captured in `graceful::prepare_inner` (`:1121-1127`, the same poison-tolerant lock read) and carried through `Prep` — and deliberately **not** echoed into `Outcome`, which reports the verdict rather than the target. The five existing unit tests that construct `graceful_stop_request` directly (`:3002`, `:3138`, `:3184`, `:3228`, `:3267`) take the new argument.
  - Update both source comments (`:1560-1566` and `:648-672`) to say the identity check now exists, what it does **not** do (a pid-less or unreachable `/health` still POSTs), and keep `#1825`'s hardcoded-URL half named as still open.
- **Leave `check_health`, `check_health_at`, `wait_for_port_release` and `wait_for_server_gone` alone.** They ask "is *anything* answering", which is right for the port-release wait and for the debug-only adoption fast path at `sidecar.rs:1454` (`cfg!(debug_assertions)`) that lets `cargo tauri dev` attach to a hand-started `dev:standalone`.
- **Read the release-build consequence together with E1-1758, in the PR body.** A foreign or pre-upgrade Tandem on :3479 now makes `wait_for_health` time out rather than falsely succeed, so the shell takes its existing `Err` arm — kill our child, back off, retry, then the "Retry Server Start" dialog. That is only safe because **E1-1758's refusal does not fire for the Tauri sidecar**: the child still runs `freePort` on start (`sidecar.rs:1450-1453`), so a stale holder is cleared on the next attempt and the app self-heals. If that carve-out is ever removed, this change turns an automatic recovery into a permanent dialog.

## Tests

1. `tests/server/health-route.test.ts` (already drives `makeHealthHandler` with a synthetic non-loopback request): `pid` is `process.pid` for a loopback request and **absent** for `203.0.113.5`. The absent half is what kills hoisting the field out of the loopback gate.
2. `src-tauri/src/sidecar.rs` — a `#[cfg(test)]` unit test over `health_body_is_our_child`: matching pid → true; different pid → false; **no `pid` key → false**; non-JSON → false. **What each kills:** the third kills a `serde` default or `unwrap_or(child_pid)` that treats an unidentified responder as ours (restoring today's bug against every pre-fix server); the fourth kills a `contains("pid")` string check.
3. `src-tauri/src/sidecar.rs` — **a call-site test, because the predicate alone does not pin that anything consults it.** Stand up a loopback `tokio` `TcpListener` (the file already does this at `:2512`, `:2959`, `:3033`, `:3076`) and drive `wait_for_health_at` with `timeout: Duration::from_secs(1)`: a listener serving `{"status":"ok","pid":<child_pid + 1>}` returns `Err`; one serving `{"status":"ok","pid":<child_pid>}` returns `Ok`. **What it kills:** `health_body_is_our_child` existing, passing test 2, and never being called. The explicit `timeout` is what makes the `Err` case cost ~1 s rather than 30 s on every required leg.
4. `src-tauri/src/sidecar.rs` — the same listener shape against `graceful_stop_request`, `owns_child: true`, three cases:
   - health listener reporting a **foreign pid** → the shutdown endpoint receives **no** request. **Kills** the identity check landing on the poll only.
   - health listener answering `{"status":"ok"}` with **no `pid`** → the shutdown endpoint **MUST** receive the request. **Kills** treating "unidentified" as "foreign" — the default outcome against every sidecar built before this PR, which would hard-kill the flush on every Quit while every other test stayed green.
   - health listener that **accepts and never answers** → the shutdown endpoint **MUST** still receive the request, and the call must return well inside the exit budget. **Kills** a fail-closed identity GET that both skips the flush on a transient stall and burns the budget doing it.

## Done when

`/health` carries `pid` for loopback callers only and its docblock enumeration names it; `wait_for_health` accepts only the child it spawned, logs the two distinct mismatch lines, and takes its timeout as a parameter with a test driving the real call site at ~1 s; `graceful_stop_request` skips the POST **only** on a positive foreign pid and POSTs on every inconclusive outcome, with its identity GET bounded at 1 s; both call sites pass the pid (the exit path's through `Prep` — read-verified, see the scope cut); both `sidecar.rs` comments naming #1812 are updated; `check_health` and the port-release waits are unchanged.
