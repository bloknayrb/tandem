# W13v — #2003 `getSection` re-matches a same-named sub-heading and cuts the section short

Branch `fix/server-and-cli-small-correctness-fixes-2003`. Closes #2003. Ledger: no `areas/*.md` row — #2003 carries the `v1-review` label but was filed out of K-server planning (#1823) rather than an area sweep; its tracked home is the wave 13 row in `docs/plans/2026-09-06-open-issues-sweep.md`. Probe: the fixture in the issue body (a reviewer probe during K-server planning), converted to a vitest spec below.

## Problem

`getSection` (`src/server/mcp/document.ts`, the `for` loop over `fragment`) runs its name comparison on **every** heading, including headings encountered while `inSection` is already true:

```ts
if (node.nodeName === "heading") {
  const level = Number(node.getAttribute("level") ?? 1);
  if (inSection && level <= sectionLevel) break;
  if (text.trim().toLowerCase() === sectionName.trim().toLowerCase()) {
    inSection = true;
    sectionLevel = level;      // <- reset to the DEEPER level
    lines.push(headingPrefix(level) + text);
    continue;
  }
}
```

A sub-heading with the same name as the section is deeper, so the `break` guard (`level <= sectionLevel`) does not fire; the match arm then resets `sectionLevel` from 2 to 3, and the next `###` sibling — which belongs to the section — satisfies `level <= sectionLevel` and ends it.

Fixture (`extractText` shape): `## Costs` / `intro` / `### Costs` / `detail` / `### Sub` / `more` / `## Next`. `getSection(fragment, "Costs")` returns `"## Costs\nintro\n### Costs\ndetail"`; `### Sub` and `more` are silently dropped.

Two callers: `tandem_getTextContent({section})` and the dark local-model `read_section` tool (`src/server/local-model/tools.ts`). Both hand the AI a truncated section with no signal that anything is missing.

## Fix

One conjunct, in `getSection` only:

```ts
if (!inSection && text.trim().toLowerCase() === sectionName.trim().toLowerCase()) {
```

A same-named sub-heading then falls through to the existing `if (inSection)` branch and is emitted as a heading line (`headingPrefix(level) + text`) like any other, with `sectionLevel` left at the opening heading's level. The conjunct cannot alter the not-yet-in-section path at all, so first-match-wins is preserved by construction. Coverage, stated accurately: the existing `"A"` spec (`tests/server/document-tools.test.ts:69-80`) pins the ordinary `level <= sectionLevel` break and the `"Parent"` spec (`:82-93`) pins sub-heading inclusion — **neither fixture contains a duplicate heading name, so neither pins first-match-wins today**; new spec 1's fixture, whose second `Costs` is the only duplicate name in the suite, is what pins it.

Rules that bite:
- **Critical Rule 5** — this is the `extractText` coordinate system; `headingPrefix` is already applied here and must stay, so the returned text keeps heading prefixes exactly as today for every unaffected input.
- **Critical Rule 4/6** — no range validation, anchoring or write is involved: `getSection` is pure and returns text. No offsets change for any document where the bug did not fire.
- No Y.Doc write, so no origin helper; no Y.Map key; no new MCP tool or `/api` route, so no license-gate row.

Not a new flag, a new option or a new error: a section that opens and never closes early is the only behaviour change.

## Tests

In `tests/server/document-tools.test.ts`, in the existing `describe("tandem_getTextContent — section filtering via getSection()")` block (its `"A"` and `"Parent"` specs stay as the discriminating twins for the ordinary break and for sub-heading inclusion):

1. **The issue's fixture.** Build `## Costs` / `intro` / `### Costs` / `detail` / `### Sub` / `more` / `## Next`; assert `result.found === true`, `result.text` contains `more` and `### Sub`, and does **not** contain `## Next`. Kills the shipped code (which drops `more`) and kills an over-fix that removes the `break` guard entirely (which would swallow `## Next`).
2. **The same-named sub-heading is kept as a line, not skipped.** Same fixture: assert `result.text` contains `### Costs` and `detail`. Kills a "fix" that `continue`s past an in-section same-named heading instead of falling through — that would drop the sub-heading line and its text, trading one truncation for another.
3. **Deeper same-named heading does not change the closing level.** A fixture with `## Costs` / `### Costs` / `## Next`: assert the result is exactly `"## Costs\n### Costs"`. This is a **regression pin, not a kill**: a variant that guards only the *reset* of `sectionLevel` while still taking the match arm is observationally equivalent to the conjunct — both arms push the identical `headingPrefix(level) + text` line — so no spec can separate them, and the conjunct is taken because it is the simpler of the two. Do not label this spec as killing that variant.
4. **The section text is a verbatim contiguous slice of `extractText`.** On spec 1's fixture, assert `extractText(ydoc).includes(result.text)` **and** that `extractText(ydoc).indexOf(result.text)` equals `extractText(ydoc).indexOf("## Costs")` — i.e. the slice starts at the section heading's flat offset. This is the fix's real content: `getSection` builds heading lines as `headingPrefix(level) + flattenHeadingText(getElementText(node))` and joins with `"\n"` (`document.ts:288-313`), and `extractTextWithBreaks` does the identical thing (`document-model.ts:290-319`, `:311`), with `getElementText` being `collectElementFlat`, the same producer `extractText` uses for non-headings. The two agree character-for-character, and the shipped bug is precisely what makes the section text stop being a slice. One new import (`extractText` from `src/server/mcp/document-model.js`); it is the assertion that survives any future re-shaping of `getSection`.

No new test file; no fixture helper beyond the file's existing document builder.

## Done when

The four specs are green, the pre-existing `getSection` specs are untouched and green, `npm run typecheck` and `npm test` pass.

## Not in scope

`getOutline`'s duplicate-name ambiguity (an AI cannot address the second `Costs` at all — a different, unfiled question); `read_section` in `src/server/local-model/tools.ts` (dark, and it inherits the fix by calling `getSection`); any change to `headingPrefix` or `flattenHeadingText`.

**The NaN/zero `level` never-break path.** `document.ts:294` and `:305` read `Number(node.getAttribute("level") ?? 1)`; if the section-opening heading yields `NaN`, `sectionLevel` is `NaN`, `level <= sectionLevel` is false for every later heading, and the section runs to the end of the fragment. `headingPrefix(NaN)` returns `""` (`src/shared/offsets.ts:67-70`), which matches `extractText`'s own treatment, so the coordinate systems do not diverge — only the termination does. This is pre-existing and unchanged by the conjunct, and **no new spec may build its fixture on a heading without an integer `level`**, or it would be resting on that path rather than on the fix.
