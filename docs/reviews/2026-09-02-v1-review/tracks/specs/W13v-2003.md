# W13v — #2003 `getSection` re-matches a same-named sub-heading and cuts the section short

Branch `fix/server-and-cli-small-correctness-fixes-2003`. Closes #2003. Ledger: no `areas/*.md` row — #2003 carries the `v1-review` label but was filed out of K-server planning (#1823); tracked home is the wave 13 row in `docs/plans/2026-09-06-open-issues-sweep.md`. Probe: the fixture in the issue body, converted to a vitest spec below.

## Problem

`getSection` (`src/server/mcp/document.ts`, the `for` loop over `fragment`) runs its name comparison on **every** heading, including headings seen while `inSection` is already true:

```ts
if (node.nodeName === "heading") {
  const level = Number(node.getAttribute("level") ?? 1);
  if (inSection && level <= sectionLevel) break;
  if (text.trim().toLowerCase() === sectionName.trim().toLowerCase()) {
    inSection = true;
    sectionLevel = level;      // <- reset to the DEEPER level
    lines.push(headingPrefix(level) + text);
    continue;
  }
}
```

A same-named sub-heading is deeper, so the `break` guard does not fire; the match arm then resets `sectionLevel` from 2 to 3, and the next `###` sibling — which belongs to the section — satisfies `level <= sectionLevel` and ends it.

Fixture (`extractText` shape): `## Costs` / `intro` / `### Costs` / `detail` / `### Sub` / `more` / `## Next`. `getSection(fragment, "Costs")` returns `"## Costs\nintro\n### Costs\ndetail"`; `### Sub` and `more` are silently dropped. Two callers — `tandem_getTextContent({section})` and the dark `read_section` (`src/server/local-model/tools.ts`) — hand the AI a truncated section with no signal.

## Fix

One conjunct, in `getSection` only:

```ts
if (!inSection && text.trim().toLowerCase() === sectionName.trim().toLowerCase()) {
```

A same-named sub-heading then falls through to the existing `if (inSection)` branch and is emitted as a heading line (`headingPrefix(level) + text`) like any other, with `sectionLevel` left at the opening heading's level. The conjunct cannot alter the not-yet-in-section path, so first-match-wins is preserved by construction.

Rules that bite: this is the `extractText` coordinate system (Critical Rule 5) — `headingPrefix` is already applied here and stays, so the returned text keeps heading prefixes exactly as today. No range validation, no Y.Doc write, no Y.Map key, no new tool or `/api` route. No new flag, option or error code: a section that opens and no longer closes early is the only behaviour change.

## Tests

In `tests/server/document-tools.test.ts`, in the existing `describe("tandem_getTextContent — section filtering via getSection()")` block (its `"A"` and `"Parent"` specs stay as the twins for the ordinary break and for sub-heading inclusion; neither fixture has a duplicate heading name, so neither pins first-match-wins — spec 1's does):

1. **The issue's fixture.** `## Costs` / `intro` / `### Costs` / `detail` / `### Sub` / `more` / `## Next`; assert `found === true`, `text` contains `more` and `### Sub`, and does **not** contain `## Next`. Kills the shipped code (drops `more`) and kills an over-fix that removes the `break` guard (swallows `## Next`).
2. **The same-named sub-heading is kept as a line.** Same fixture: assert `text` contains `### Costs` and `detail`. Kills a "fix" that `continue`s past an in-section same-named heading, trading one truncation for another.

No new test file, no fixture helper beyond the file's existing document builder. **No new fixture may use a heading without an integer `level`**: `Number(getAttribute("level") ?? 1)` can yield `NaN`, whose never-break path is pre-existing and unchanged by the conjunct — a fixture resting on it would not be testing this fix.
