# W13v — #2008 `/api` labels a Windows permission refusal `FILE_LOCKED` (423)

Branch `fix/server-and-cli-small-correctness-fixes-2003`. Closes #2008. Ledger: no `areas/*.md` row — filed out of #1823 (K-server) after PR #2007 fixed the MCP half; tracked home is the wave 13 row in `docs/plans/2026-09-06-open-issues-sweep.md`. Probe: the measured errno/syscall table in the issue body (Windows 11 26200, Node 24.2.0), reused as the test matrix below.

## Problem

`errorCodeToLabel` (`src/server/mcp/routes/_shared.ts`) keys on the errno alone:

```ts
case "EBUSY":
case "EPERM":
  return "FILE_LOCKED";
```

with the matching `423` arm in `errorCodeToHttpStatus`, and `sendApiError` then overrides the body detail with "File is locked by another program."

On Windows libuv reports `ERROR_ACCESS_DENIED` as `EPERM`, not `EACCES`. The issue's measurements: `EPERM` on `open` is always a refusal (unwritable directory, unreadable file), while `EPERM` on `rename` is a lock or the read-only attribute. So an ordinary permission refusal over `/api` reaches the user as "locked by another program" — the close-Word-and-retry loop #1796 removed for `tandem_convertToMarkdown`. PR #2007 split this on the MCP surface (`lockOrPermissionCode`, `src/server/mcp/response.ts:121-129`); the `/api` twins did not follow.

**Reach, measured:** `sendApiError` is the only consumer of `errorCodeToLabel`. `POST /api/save`'s ordinary-save branch reports failure in a **200 body** from `SaveResult.errorCode` and never reaches `sendApiError`, so it is not a carrier and needs no new plumbing. The carriers are the raw-errno throws reaching `sendApiError`: `POST /api/open`, `POST /api/apply-changes`, `/api/save`'s save-as `catch`, and every other route delegating to it.

## Fix

One conditional at the top of `sendApiError`, in `src/server/mcp/routes/_shared.ts` only:

```ts
const e = err as NodeJS.ErrnoException;
// #2008: EPERM is libuv's Windows ERROR_ACCESS_DENIED as well as its lock
// signal, and only the failing syscall separates them. Same rule as
// `lockOrPermissionCode` (src/server/mcp/response.ts) — read its docblock for
// the measurements. Written out here rather than imported: `_shared.ts` is the
// leaf every /api route imports and must stay one (see below).
const code = e.code === "EPERM" && e.syscall === "open" ? "PERMISSION_DENIED" : (e.code ?? "");
```

That is the whole behaviour change.

- `EPERM` + `syscall: "open"` → `PERMISSION_DENIED` → **403**, label `PERMISSION_DENIED`, generic message "Permission denied." (both already exist; the case was added for convert in #1796).
- The **loopback body detail changes for that one case**: `detail` is `label === "FILE_LOCKED" ? "File is locked…" : (e.message ?? String(err))`, so a loopback caller now gets the raw errno message (which embeds the absolute path) and the `console.warn` line changes with it. That matches what `EACCES` already does and sits inside #1294's design (loopback gets the real path; non-loopback gets `GENERIC_ERROR_MESSAGE.PERMISSION_DENIED`), but it is observable, so it is recorded here.
- `EACCES`, `EBUSY`, and `EPERM` on `rename`/no syscall → unchanged.

**`_shared.ts` must gain no import from `../response.js`.** `response.ts` pulls `events/queue.js` → `yjs/provider.js` → `@hocuspocus/server`, and 22 modules import `_shared.ts`, so that edge would land Hocuspocus in every `/api` route's module init. `tests/docs/documents-boundary.test.ts:342-347` records `sendOpenResult` being taken *out* of `_shared.ts` for exactly this reason — "A leaf every route imports has to stay a leaf" — and its inventory tracks only edges into `server/documents/`, so it would not turn red on this one. The one duplicated conditional, cross-referenced by comment in both directions, is the price of the leaf.

`errorCodeToLabel` / `errorCodeToHttpStatus` keep their `EBUSY`/`EPERM` arms and signatures — they are exported, directly tested, and still reached by `EPERM` on a non-`open` syscall. Add a one-line pointer comment on the `EPERM` arm naming `sendApiError` as where the split happens.

**No new error code and no new label**, so `ERROR_LABELS`, `GENERIC_ERROR_MESSAGE`, the exhaustiveness sweep and Critical Rule 9's license-gate tables need no edit. **Client:** nothing in `src/client/` keys on `423`, `FILE_LOCKED` or `PERMISSION_DENIED` (grep: zero hits) — and `src/client/` belongs to W13c. **Docs:** `docs/mcp-tools.md`'s `/api` errors lines already list both codes; add the syscall clause so they match the MCP rows at `:46` / `:144` — `423 FILE_LOCKED` (`EBUSY`, or `EPERM` from a syscall other than `open`), `403 PERMISSION_DENIED` (`EACCES`, or `EPERM` from `open`). Critical Rule 3 is untouched: `sendApiError` logs through `console.error`/`console.warn`.

## Tests

In `tests/server/routes/path-scrub.test.ts` — which already imports `sendApiError`, `errorCodeToLabel`, `ERROR_LABELS` and `GENERIC_ERROR_MESSAGE` and drives `sendApiError` against a fake `res`/`req`. A new describe over the issue's measured matrix; each case asserts status and `error` label:

1. `{ code: "EPERM", syscall: "open" }` → **403** `PERMISSION_DENIED`. Kills the shipped code and kills a blanket `EPERM` remap.
2. `{ code: "EPERM", syscall: "rename" }` → **423** `FILE_LOCKED`, detail "File is locked by another program." Kills the blanket remap and kills deleting the `EPERM` arm from `errorCodeToLabel`.
3. `{ code: "EBUSY", syscall: "open" }` → **423** `FILE_LOCKED`. Kills a fix keyed on `syscall === "open"` alone.
4. `{ code: "EPERM" }` with **no** `syscall` → 423 `FILE_LOCKED`. Pins the fail-toward-current-behaviour choice.
5. `{ code: "EACCES" }` → 403 `PERMISSION_DENIED`. The no-regression twin.

## Done when

The five cases are green; the existing `errorCodeToLabel` / `errorCodeToHttpStatus` tests and the `ERROR_LABELS` exhaustiveness sweep are unchanged and green; `docs/mcp-tools.md`'s `/api` lines carry the syscall clause; `npm run typecheck` and `npm test` pass.
