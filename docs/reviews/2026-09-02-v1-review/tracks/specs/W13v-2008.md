# W13v — #2008 `/api` labels a Windows permission refusal `FILE_LOCKED` (423)

Branch `fix/server-and-cli-small-correctness-fixes-2003`. Closes #2008. Ledger: no `areas/*.md` row — filed out of #1823 (K-server) after PR #2007 fixed the MCP half; tracked home is the wave 13 row in `docs/plans/2026-09-06-open-issues-sweep.md`. Probe: the measured errno/syscall table in the issue body (Windows 11 26200, Node 24.2.0), reused as the test matrix below.

## Problem

`errorCodeToLabel` (`src/server/mcp/routes/_shared.ts`) keys on the errno alone:

```ts
case "EBUSY":
case "EPERM":
  return "FILE_LOCKED";
```

with the matching `423` arm in `errorCodeToHttpStatus`, and `sendApiError` then overrides the body detail with "File is locked by another program."

On Windows libuv reports `ERROR_ACCESS_DENIED` as `EPERM`, not `EACCES`. The issue's measurements show `EPERM` on `open` is always a refusal (an unwritable directory, an unreadable file), while `EPERM` on `rename` is a lock or the read-only attribute. So an ordinary permission refusal over `/api` reaches the user as "locked by another program" — the close-Word-and-retry loop #1796 removed for `tandem_convertToMarkdown`.

PR #2007 already split this on the MCP surface through `lockOrPermissionCode` (`src/server/mcp/response.ts:121-129`), keyed on `syscall`. The `/api` twins of the same operations did not follow.

**Reach, measured against current source (narrower than the issue body assumes):** `sendApiError` is the only consumer of `errorCodeToLabel`. `POST /api/save`'s ordinary-save branch reports failure in a **200 body** built from `SaveResult.errorCode` and never reaches `sendApiError`, so it is not a carrier and `SaveResult.errorSyscall` needs no new plumbing. The carriers are the raw-errno throws that reach `sendApiError`: `POST /api/open`, `POST /api/apply-changes`, `/api/save`'s save-as `catch`, and every other route delegating to it.

## Fix

One derivation at the top of `sendApiError`, reusing the predicate #2007 already wrote — **no second copy of the syscall rule** — and one **move** that keeps `routes/_shared.ts` a leaf.

**Step 1 — move the predicate into a leaf module.** `routes/_shared.ts` today imports only express types, `shared/cross-basename.js` and `auth/middleware.js`, and 22 modules import it (every `src/server/mcp/routes/*` plus integrations/, launcher/, models/ api-routes). `src/server/mcp/response.ts` imports `../events/queue.js` → `../yjs/provider.js` → `@hocuspocus/server`, so an `_shared.ts → response.ts` edge would pull the event queue, the Yjs provider and Hocuspocus into the module init of every `/api` route and of `tests/server/routes/path-scrub.test.ts`. **That is the exact shape the repo forbids**: `tests/docs/documents-boundary.test.ts:342-347` records `sendOpenResult` being taken *out* of `_shared.ts` for this reason — "A leaf every route imports has to stay a leaf" — and that inventory tracks only edges into `server/documents/`, so it would **not** turn red on this one. The rule would fail silently.

So: create `src/server/mcp/errno.ts`, a dependency-free leaf holding `lockOrPermissionCode` verbatim (it depends on nothing — `response.ts:121-129` is a pure three-line switch) with its existing docblock. `src/server/mcp/response.ts` **re-exports** it (`export { lockOrPermissionCode } from "./errno.js";`) so its current surface is unchanged and **no existing importer is edited** — `src/server/mcp/document.ts` and `src/server/mcp/docx-apply.ts` keep importing it from `response.js`, which matters because `docx-apply.ts` belongs to W13s this wave and must not be touched. `routes/_shared.ts` imports from the leaf.

**Step 2 — the derivation in `sendApiError`:**

```ts
import { lockOrPermissionCode } from "../errno.js";
...
const e = err as NodeJS.ErrnoException;
// #2008: EPERM is libuv's Windows ERROR_ACCESS_DENIED as well as its lock
// signal. `lockOrPermissionCode` is the split #2007 drew for the MCP twins
// (EPERM on `open` = refusal, any other syscall = lock); re-deriving it here
// is what let /api answer a permission refusal with "locked by another
// program". Only the PERMISSION_DENIED verdict is adopted — FILE_LOCKED and
// `null` leave the raw errno to the tables below unchanged.
const code = lockOrPermissionCode(e) === "PERMISSION_DENIED" ? "PERMISSION_DENIED" : (e.code ?? "");
```

That is the whole behaviour change. Consequences:

- `EPERM` + `syscall: "open"` → code `PERMISSION_DENIED` → **403**, label `PERMISSION_DENIED`, generic message "Permission denied." (already in `GENERIC_ERROR_MESSAGE` and `ERROR_LABELS`; the `PERMISSION_DENIED` case was added for convert in #1796).
- **The loopback body detail changes for that one case**, and the spec records it rather than implying only the status and label move: `sendApiError`'s `detail` is `label === "FILE_LOCKED" ? "File is locked by another program." : (e.message ?? String(err))`, so an `EPERM`+`open` now yields the raw errno message — which embeds the absolute path — to a loopback caller, and the `console.warn` line changes with it. That matches what `EACCES` already does and sits inside #1294's design (loopback gets the real path; non-loopback gets `GENERIC_ERROR_MESSAGE.PERMISSION_DENIED`), but it is an observable change and is pinned by test cases 6 and 7 below.
- `EACCES` → routes through the same branch to the identical status/label/message it has today. No observable change.
- `EPERM` + `rename`/other, and `EBUSY` → untouched: 423 `FILE_LOCKED`.

**No new error code and no new label**, so `ERROR_LABELS`, `GENERIC_ERROR_MESSAGE` and `tests/server/routes/path-scrub.test.ts`'s exhaustiveness sweep need no edit, and Critical Rule 9's license-gate tables need no row (no new tool or route).

`errorCodeToLabel` / `errorCodeToHttpStatus` keep their `EBUSY`/`EPERM` arms and their signatures — they are exported and directly tested, and `EPERM` on a non-`open` syscall still reaches them. Add a one-line pointer comment on the `EPERM` arm naming `sendApiError` as the place the split happens, so the next reader does not conclude the table is the whole story.

**Client:** nothing in `src/client/` keys on `423`, on `FILE_LOCKED` or on `PERMISSION_DENIED` (grep: zero hits); the browser renders `message`. No client edit — and `src/client/` belongs to W13c this wave.

**Docs:** `docs/mcp-tools.md` HTTP-API section, the `POST /api/open` errors line, already lists both `423 FILE_LOCKED` and `403 PERMISSION_DENIED`; add the syscall clause so it matches the MCP rows at `:46` and `:144` — `423 FILE_LOCKED` (`EBUSY`, or `EPERM` from a syscall other than `open`), `403 PERMISSION_DENIED` (`EACCES`, or `EPERM` from `open`). Same clause for any sibling `/api` route line in that section that names either code.

Critical Rule 3 (stdout) is untouched — `sendApiError`'s logging already goes to `console.error`/`console.warn`, both redirected to stderr.

## Tests

In `tests/server/routes/path-scrub.test.ts` — the file that already imports `sendApiError`, `errorCodeToLabel`, `ERROR_LABELS` and `GENERIC_ERROR_MESSAGE` and drives `sendApiError` against a fake `res`/`req` for both loopback and non-loopback callers, a new describe covering the issue's measured matrix. Each case asserts status, `error` label and `message`:

1. `{ code: "EPERM", syscall: "open" }` → **403**, `PERMISSION_DENIED`. Kills the shipped code (423/`FILE_LOCKED`) and kills a fix that maps all `EPERM` to `PERMISSION_DENIED`.
2. `{ code: "EPERM", syscall: "rename" }` → **423**, `FILE_LOCKED`, detail "File is locked by another program." Kills the blanket remap in (1) and kills deleting the `EPERM` arm from `errorCodeToLabel`.
3. `{ code: "EBUSY", syscall: "open" }` → **423**, `FILE_LOCKED`. Kills a fix keyed on `syscall === "open"` alone rather than on the errno first.
4. `{ code: "EPERM" }` with **no** `syscall` → 423 `FILE_LOCKED` (`lockOrPermissionCode` returns `FILE_LOCKED` for an undefined syscall — pins the fail-toward-current-behaviour choice rather than leaving it to inference).
5. `{ code: "EACCES" }` → 403 `PERMISSION_DENIED`, unchanged. The no-regression twin.
6. Non-loopback `req` on case 1 → body message is exactly `GENERIC_ERROR_MESSAGE.PERMISSION_DENIED`, never the raw `e.message`. Kills a fix that bypasses the label path and writes a detail string directly (#1294's path-scrub would go with it).
7. **Loopback positive control on case 1** → body message is the errno `e.message` (path included), *not* "File is locked by another program." Pins the detail change recorded in the Fix section, so the loopback half cannot silently keep the lock wording.

**Module-graph check (this is what replaces the old "typecheck confirms no cycle" line — `tsc` does not detect ESM import cycles and would not have caught the real hazard):** assert in the same file, or in the nearest existing import-shape test, that `src/server/mcp/routes/_shared.ts` contains no import from `../response.js`, and that `src/server/mcp/errno.ts` has zero imports. One grep-shaped assertion; it is the only thing that keeps the leaf a leaf, because `documents-boundary.test.ts` cannot see this edge.

## Done when

The seven cases are green; the module-graph assertion is green; `lockOrPermissionCode` exists in exactly one place (`src/server/mcp/errno.ts`) and `response.ts` re-exports it with no importer edited; the existing `errorCodeToLabel` / `errorCodeToHttpStatus` unit tests and the `ERROR_LABELS` exhaustiveness sweep in the same file are unchanged and green; `docs/mcp-tools.md`'s `/api` lines carry the syscall clause; `npm run typecheck` and `npm test` pass.

## Not in scope

`POST /api/save`'s ordinary-save 200-body failure shape (`SaveResult.errorCode` / `errorSyscall`) — it does not pass through `sendApiError`, and changing its envelope is a client-visible contract change belonging with W13c; the read-only-attribute-vs-lock ambiguity on `EPERM`+`rename`, which the errno cannot resolve and which `docs/mcp-tools.md:46` already records; `src/server/mcp/docx-apply.ts` (owned by W13s this wave — and untouched by construction, since `response.ts` keeps re-exporting the predicate).

## Review corrections (round 1)

**Adopted**

- *(blocking, and three non-blocking restatements of it)* `import { lockOrPermissionCode } from "../response.js"` in `routes/_shared.ts` would give the leaf every route imports an edge into `response.ts` → `events/queue.js` → `yjs/provider.js` → `@hocuspocus/server`, which `tests/docs/documents-boundary.test.ts:342-347` forbids by name and cannot detect. The Fix now **moves** the predicate to a dependency-free `src/server/mcp/errno.ts` and has `response.ts` re-export it, so `document.ts` and `docx-apply.ts` are untouched (the latter matters: W13s owns it). The Fix section states the rule and cites the test.
- *(non-blocking)* "the typecheck also confirms the new import introduces no cycle" is a verification that cannot verify the claim — `tsc` does not detect ESM cycles, and the real hazard was module-init weight, not a cycle. Replaced with an explicit module-graph assertion in the Tests section, plus a `Done when` item naming the single-copy property.
- *(non-blocking)* The consequences list claimed only status/label changes. Added the loopback detail change for `EPERM`+`open` (errno message with path, matching `EACCES`) and its `console.warn` line, plus new test 7 as the loopback positive control beside the existing non-loopback case 6.

**Not adopted**

No behavioural difference, so the cheaper placement is taken.
