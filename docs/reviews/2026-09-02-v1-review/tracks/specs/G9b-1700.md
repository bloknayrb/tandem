## Problem

`requireDocument` (`src/server/documents/registry.ts`, re-exported by `src/server/mcp/document-service.ts`) returns `{ doc: Y.Doc }`. Counted by `\brequireDocument\s*\(` over comment-stripped source, on `a6e7352f`:

| File | Call sites |
|---|---|
| `src/server/mcp/document.ts` | 7 |
| `src/server/mcp/docx-apply.ts` | 1 |
| `src/server/local-model/collaborator.ts` | 4 (ships dark) |

That is 12, as the issue says. `src/server/mcp/document-store.ts` mentions the name only in a comment.

`tests/server/document-store-surface.test.ts` pins `YDocStore`'s and `AnnotationLifecycle`'s member lists by name. Its own header says that is blind to a third file growing a raw handle, and nothing notices a new `requireDocument` importer.

**Census**, by a TypeScript-AST walk over every `.ts` file in `src/server` and `src/shared` (210 files on `a6e7352f`), for class members whose type annotation matches `/\bY\.(Doc|Map|XmlFragment|Array|Text|XmlElement|XmlText)\b/`:
- **Public raw-typed members: zero.** The walk skips `#private`, `private` and `protected`, and includes constructor parameter properties.
- **Unannotated public members whose initializer or body references `this.<a raw-typed member>`: zero.**
- **Hidden raw-typed members:** exactly two, `YDocStore.#ydoc` and `YDocStore.#map` (`src/server/mcp/document-store.ts`). No public member references either.
- **Out of scope for the scan:** five INTERFACE fields, `SyncContext.ydoc`, `PerKeyObserverDeps.map`, `RunTurnOpts.ydoc`, `RunLoopOpts.ydoc` and `DispatchCtx.ydoc`. All five are context/option bags.
- Every `src/server` yjs import is `import * as Y from "yjs"`, so the `Y.` spelling is the whole population.

## Fix

A new vitest file, `tests/server/raw-doc-handle-guard.test.ts`, which runs in `check` like `tests/scripts/audit-origins.test.ts` (Critical Rule 2's pattern: the gate is a test). No script and no `package.json` entry. It reads the shared `SRC_FILES` / `stripComments` / `filesMentioning` from `tests/helpers/src-tree.ts`, never `readFileSync`, because that helper's header records the Windows contention cost of a second walk.

1. **`requireDocument` mention set, exact equality**, against the named allowlist `REQUIRE_DOCUMENT_FILES`:
   - `src/server/documents/registry.ts` (definition)
   - `src/server/local-model/collaborator.ts`
   - `src/server/mcp/document-service.ts` (re-export)
   - `src/server/mcp/document.ts`
   - `src/server/mcp/docx-apply.ts`

   A new importer, alias or re-export turns it red.
   - Check at file level, NOT per-file counts. PR #2007 owns `document.ts` and `docx-apply.ts`, and a count pin would redden on its unrelated edits. This PR does not edit those files.
   - The assertion message names `REQUIRE_DOCUMENT_FILES` and says to edit it. If #2007 removes the import from either file, this goes red correctly, and whichever PR merges second needs a one-line allowlist edit. State that merge-order dependency in the PR body.
2. **No public raw-handle class member in `src/server` or `src/shared`.** For each `.ts` file under those two prefixes in `SRC_FILES`, run `ts.createSourceFile` and visit every `ClassDeclaration`/`ClassExpression`.
   - **Collect the class's raw-typed members first, at any visibility:** properties, accessors and methods whose annotation text matches `RAW = /\bY\.(Doc|Map|XmlFragment|Array|Text|XmlElement|XmlText)\b/`, plus constructor parameter properties (any parameter carrying a modifier).
   - **Flag a public member** (not a `#name`, not `private` or `protected`), static included, when any of these holds:
     - (a) its type annotation matches `RAW`. This covers properties with `readonly`/`declare`/`accessor`/`!`/`?`, string and computed names, get/set accessors, and methods by return type.
     - (b) it is a constructor parameter carrying `public` or `readonly` whose type matches `RAW`.
     - (c) it has NO type annotation, and its initializer or body text contains `this.<name>` for a raw-typed member collected above. This covers `readonly ydoc = this.#ydoc`, `readonly getDoc = () => this.#ydoc`, and `get doc() { return this.#doc }`.
   - Report entries shaped `file#Class.member`. The expected set equals the named allowlist `ALLOWED_PUBLIC_RAW_MEMBERS: readonly string[] = []`.
   - The detector is one in-file function, so the positive controls call it.
3. **Positive controls** (the audit-origins "still detects" pattern), on inline sources. Each is its own `it` with `expect(detect(src)).toStrictEqual([...])` written inline, never through an `assert*` helper: `docs/reviews/2026-09-02-v1-review/experiments/scan-zero-assert.mjs` does not recognize arbitrary helper names and would report such an `it` as assertion-free.

   Flagged:
   - A `class A { readonly doc: Y.Doc }`
   - B `class B { getMap(): Y.Map<unknown> { … } }`
   - C `class C { constructor(public readonly doc: Y.Doc) {} }`
   - F `class F { doc: Y.Doc }` (no modifier)
   - G `class G { get doc(): Y.Doc { … } }`
   - H `class H { accessor doc: Y.Doc }`
   - I `class I { "doc"!: Y.Doc }`
   - J `class J { static doc: Y.Doc }`
   - K `class K { #doc: Y.Doc; get doc() { return this.#doc } }` (unannotated getter)
   - L `class L { #doc: Y.Doc; readonly getDoc = () => this.#doc }` (unannotated arrow property)
   - M `class M { frag: Y.XmlFragment }` (a widened type)

   Not flagged:
   - D `class D { #doc: Y.Doc; private m: Y.Map<unknown> }`
   - E `interface E { ydoc: Y.Doc }` (scope)
   - N `class N { constructor(private readonly doc: Y.Doc) {} }`
   - O `class O { constructor(doc: Y.Doc) {} }` (a plain parameter, not a property)

   This stops "zero" being a zero-of-zero. Also add a census floor: the walk visited more than 150 files under the two prefixes (210 measured).
4. **Header, stating the bound:**
   - A syntax scan cannot see an untyped initializer that reaches the doc through a call rather than `this.` (`readonly doc = getOrCreateDocument(id)`, the first defeat `document-store-surface.test.ts` lists), or a handle returned through a local alias (`const d = this.#doc; return d`).
   - It does not cover interfaces, exported functions, or other raw routes (`getOrCreateDocument` has ~11 importers).
   - The member scan covers `src/server` and `src/shared` only. `src/client` is outside #1700's server-side seam.
   - It reports; it does not confine. Checkbox 1 is still the real work, and #1700 stays open.
   - Name #1700.

No `src/` change. Leave `docs/decisions.md` untouched. `src/server/mcp/document-store.ts` and `document-store-surface.test.ts` already say "Tracked as #1700" and stay correct.

## Tests

The guard is the test. Discrimination:
- Adding `import { requireDocument } from "../documents/registry.js"` to any other `src/server` file turns case 1 red.
- Adding `readonly ydoc: Y.Doc` to any class in `src/server` or `src/shared` turns case 2 red.

**Mutations, restoring from a file copy each time (never `git checkout`):**
- Comment out the private-modifier skip: controls D and N go red.
- Replace the regex with `/Y\.Document/`: controls A to C and F to J go red.
- Narrow the regex back to `(Doc|Map)`: control M goes red.
- Delete arm (c): controls K and L go red.
- Drop the static/no-modifier handling (flag only members carrying `readonly` or `public`): controls F and J go red.
- Add `src/server/mcp/navigation.ts` to `REQUIRE_DOCUMENT_FILES`: case 1 goes red.
