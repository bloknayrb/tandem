## Problem

`requireDocument` (`src/server/documents/registry.ts`, re-exported by `src/server/mcp/document-service.ts`) returns a raw `Y.Doc`. On `a6e7352f`, counting `\brequireDocument\s*\(` over comment-stripped source finds call sites in three files:

| File | Call sites |
|---|---|
| `src/server/mcp/document.ts` | 7 |
| `src/server/mcp/docx-apply.ts` | 1 |
| `src/server/local-model/collaborator.ts` | 4 |

That is 12 in total.

`tests/server/document-store-surface.test.ts` pins the member lists of `YDocStore` and `AnnotationLifecycle`. Its header says it cannot see a third file that grows a raw handle.

A census on `a6e7352f` found zero public class members typed `Y.Doc` or `Y.Map` in `src/server` or `src/shared`. The only raw-typed class members are `YDocStore.#ydoc` and `YDocStore.#map`, and both are private.

## Fix

One vitest file, `tests/server/raw-doc-handle-guard.test.ts`. It runs inside `check`, following the pattern of `tests/scripts/audit-origins.test.ts`, where the gate is a test and not a script's exit code. It reads `SRC_FILES`, `stripComments` and `filesMentioning` from `tests/helpers/src-tree.ts` rather than walking the tree again.

1. **`requireDocument` importer set, exact equality.** `filesMentioning("requireDocument")` must equal `REQUIRE_DOCUMENT_FILES`:
   - `src/server/documents/registry.ts`
   - `src/server/local-model/collaborator.ts`
   - `src/server/mcp/document-service.ts`
   - `src/server/mcp/document.ts`
   - `src/server/mcp/docx-apply.ts`

   The check is by file, not by count. PR #2007 edits `document.ts` and `docx-apply.ts`, and a count pin would go red on those unrelated edits. The failure message names `REQUIRE_DOCUMENT_FILES`.
2. **No public raw-typed class member.** For each `.ts` file under `src/server/` or `src/shared/` in `SRC_FILES`, parse it with `ts.createSourceFile`. Visit every class's property declarations, get accessors, methods and constructor parameter properties. Flag a member when both of these hold:
   - It is public: not a `#name`, and not `private` or `protected`.
   - Its type annotation text matches `/\bY\.(Doc|Map)\b/`.

   Report entries shaped `file#Class.member`. The expected set is `ALLOWED_PUBLIC_RAW_MEMBERS: readonly string[] = []`. The detector is one in-file function `detect(src)`.
3. **Two inline controls**, each with its `expect` written inline:
   - `class A { readonly doc: Y.Doc }` → `["A.doc"]`
   - `class B { #doc: Y.Doc; private m: Y.Map<unknown> }` → `[]`

   These keep the zero result from being a zero-of-zero.
4. **Header comment:**
   - Name #1700.
   - State that the scan is syntactic. An untyped member that reaches the doc another way is invisible to it, and so are interfaces and exported functions.
   - State that it reports rather than confines. Checkbox 1 remains the real work.

## Tests

The guard is the test. Mutations, each restored from a file copy (never `git checkout`):
- Drop the private-modifier skip: control B goes red.
- Replace the regex with `/Y\.Document/`: control A goes red.
- Add `src/server/mcp/navigation.ts` to `REQUIRE_DOCUMENT_FILES`: case 1 goes red.

## Done when

- **CI leg:** the ubuntu `check` job runs it. It reads source text only, so no platform-gated path is involved.
