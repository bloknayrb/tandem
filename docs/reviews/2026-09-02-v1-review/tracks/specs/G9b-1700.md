## Problem

`requireDocument` (`src/server/documents/registry.ts`, re-exported by `src/server/mcp/document-service.ts`) returns `{ doc: Y.Doc }`. Counted by `\brequireDocument\s*\(` over comment-stripped source, on `a6e7352f`:

| File | Call sites |
|---|---|
| `src/server/mcp/document.ts` | 7 |
| `src/server/mcp/docx-apply.ts` | 1 |
| `src/server/local-model/collaborator.ts` | 4 (ships dark) |

That is 12, as the issue says. `src/server/mcp/document-store.ts` mentions the name only in a comment.

`tests/server/document-store-surface.test.ts` pins `YDocStore`'s and `AnnotationLifecycle`'s member lists by name. Its own header says that is blind to a third file growing a raw handle, and nothing notices a new `requireDocument` importer.

Census of public class members typed `Y.Doc`/`Y.Map` in `src/server` (a TypeScript-AST walk skipping `#private`, `private` and `protected`, and including constructor parameter properties): **zero**. The only such members are five INTERFACE fields: `SyncContext.ydoc`, `PerKeyObserverDeps.map`, `RunTurnOpts.ydoc`, `RunLoopOpts.ydoc` and `DispatchCtx.ydoc`. All five are context/option bags. Every `src/server` yjs import is `import * as Y from "yjs"`, so the `Y.` spelling is the whole population.

## Fix

A new vitest file, `tests/server/raw-doc-handle-guard.test.ts`, which runs in `check` like `tests/scripts/audit-origins.test.ts` (Critical Rule 2's pattern: the gate is a test). No script and no `package.json` entry. It reads the shared `SRC_FILES` / `stripComments` / `filesMentioning` from `tests/helpers/src-tree.ts`, never `readFileSync`: that helper's header records the Windows contention cost of a second walk.

1. **`requireDocument` mention set, exact equality**, against the named allowlist `REQUIRE_DOCUMENT_FILES`:
   - `src/server/documents/registry.ts` (definition)
   - `src/server/local-model/collaborator.ts`
   - `src/server/mcp/document-service.ts` (re-export)
   - `src/server/mcp/document.ts`
   - `src/server/mcp/docx-apply.ts`

   A new importer, alias or re-export turns it red. File level, NOT per-file counts: PR #2007 owns `document.ts`/`docx-apply.ts`, and a count pin would redden on its unrelated edits. This PR does not edit those files.
2. **No public raw-handle class member in `src/server`.** For each `src/server/**/*.ts` in `SRC_FILES`, run `ts.createSourceFile` and visit every `ClassDeclaration`/`ClassExpression` member:
   - properties, get/set accessors and methods (by return type);
   - constructor parameters carrying `public`/`readonly`;
   - skipping `#name`, `private` and `protected`.

   Flag a member whose type-annotation text matches `/\bY\.(Doc|Map)\b/`. The expected set equals the named allowlist `ALLOWED_PUBLIC_RAW_MEMBERS: readonly string[] = []`, entries shaped `file#Class.member`. The detector is one exported-in-file function, so the positive controls call it.
3. **Positive controls** (the audit-origins "still detects" pattern), on inline sources:
   - `class A { readonly doc: Y.Doc }` → flagged
   - `class B { getMap(): Y.Map<unknown> { … } }` → flagged
   - `class C { constructor(public readonly doc: Y.Doc) {} }` → flagged
   - `class D { #doc: Y.Doc; private m: Y.Map<unknown> }` → not flagged
   - `interface E { ydoc: Y.Doc }` → not flagged (scope)

   This stops "zero" being a zero-of-zero. Also add a census floor: the walk visited more than 100 `src/server` files.
4. **Header, stating the bound:**
   - A syntax scan cannot see an untyped initializer (`readonly doc = getOrCreateDocument(id)`, the first defeat `document-store-surface.test.ts` lists).
   - It does not cover interfaces, exported functions, or other raw routes (`getOrCreateDocument` has ~11 importers).
   - It reports; it does not confine. Checkbox 1 is still the real work, and #1700 stays open.
   - Name #1700.

No `src/` change. Leave `docs/decisions.md` untouched. `src/server/mcp/document-store.ts:53` and `document-store-surface.test.ts:29` already say "Tracked as #1700" and stay correct.
