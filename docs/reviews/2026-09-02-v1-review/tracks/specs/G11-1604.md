# G11 — #1604 CLAUDE.md: state that the absence of a rule is not evidence of safety

Branch `fix/process-docs-four-issues-from-an-outside-debugging-study-1602`. Closes #1604. Ledger: `docs/plans/2026-09-06-open-issues-sweep.md:111`. No probe — docs-only.

## Problem

Nothing resembling this rule exists in `CLAUDE.md` today (confirmed by reading the full file on the current worktree). The file's own header already states its admission test — "This file states rules; the linked docs hold the detail... Everything else is one link away" — which is a statement about what the file *contains*, not about what silence *means*. The issue's argument is that an agent about to change something un-ruled reads that silence as clearance, when every existing rule here exists precisely because its violation failed silently; the un-ruled areas are the ones nothing will object to either. The issue's acceptance criterion is explicit and narrow: the rule must be **inline in `CLAUDE.md`, not delegated to a linked doc** — "an agent that would over-trust the docs is by definition not going to take the hop."

## Fix

One paragraph, appended to the existing header blockquote (`> ...`) — the natural place for "how to read this file" guidance, immediately continuing the existing sentence "If you are about to work in an area, read its doc first." Insert after that line and before the blank line + `## Critical Rules`:

```
>
> **The absence of a rule is not evidence of safety (#1604).** This file and `docs/gotchas.md`
> record failures already survived — they are not a specification of what's safe. Finding no rule
> for your change means nobody has been bitten there yet, not that nothing can go wrong; reason
> from what actually reaches the code, not from what these docs happen to name.
```

Matches the surrounding blockquote's `>`-per-line style and its existing blank-`>`-line paragraph separator (used once already, between the "Scope of this file" and "This file states rules" paragraphs). No other file changes — the issue names only `CLAUDE.md`, and `docs/gotchas.md` is referenced by the new sentence, not edited (it is not itself claiming to be a specification anywhere the new sentence would contradict).
