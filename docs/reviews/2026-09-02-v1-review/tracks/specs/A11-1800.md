## Problem

`maybeRestoreSession` (`src/server/documents/open.ts:759-840`) calls `restoreYDoc(doc, session)` (`:780`; `session/manager.ts:165-168` = `Y.applyUpdate(doc, Buffer.from(session.ydocState, "base64"))`) with no `try/catch`. A truncated or bit-flipped blob throws, the throw propagates out of `openFromDisk`, and: Recents fails, `tandem_open` by path fails (open consults the session first), `restoreOpenDocuments` (`document-service.ts:1617-1640`, `openFromRestore` at `:1627`) logs "Failed to restore" at `:1637` and skips the tab. Nothing quarantines the file, so the next attempt fails identically; the only recovery is deleting the session file by hand (`docs/troubleshooting.md` does not name it — grep `session` there finds only MCP-session prose). The annotation store already quarantines its corrupt envelope to `<target>.corrupt.<ts>` (`annotations/store.ts:593-604`); the session store has no equivalent. Two more places destroy or hide the evidence: `loadSession`'s `SyntaxError` branch (`manager.ts:129-135`) **unlinks** an unparseable file, and `listSessionFilePaths` does its own `JSON.parse` (`:490`) and on any error logs "Skipping unreadable session file" (`:517-519`) — so at boot an unparseable session never reaches `loadSession` at all and the tab silently does not come back, which is #1800's symptom for the other corruption class.

**Measured (two probes on df34592, yjs 13.6.30, Node 24):** after a throwing `applyUpdate` the SAME `Y.Doc` holds the successfully-integrated structs — a len−1 cut of a 6-paragraph/4-annotation source leaves `fragLen 6, annotations 4, awareness 1, user-awareness 1, documentMeta [readOnly, externalConflict]` — with no `pendingStructs`, **and Yjs emits one update for those structs before the exception escapes** (the `half` and `bitflip` shapes die in the decoder and emit nothing). A client attached to the room sees that partial state momentarily. Clearing and repopulating the same doc converges every peer shape probed (a peer that applied the same truncated bytes, a peer synced from the post-throw state vector, a fresh peer from `encodeStateAsUpdate`). So recovery on the same doc is sound and re-minting is unnecessary — which matters because `getOrCreateDocument` (`src/server/yjs/provider.ts:51-58`) returns whatever the `documents` map holds, and `onLoadDocument` (`:164-190`) makes the Hocuspocus-provided instance authoritative. A reachable normal-open case has a live client on it: close the tab in one window (`POST /api/close` drops it from `openDocs`) while a second window still holds the room — `afterUnloadDocument` evicts only when `shouldKeepDocument` is false, keyed on `getOpenDocs().has(name)` (`bootstrap/hocuspocus-lifecycle.ts:37-42`), so the next `openFromDisk` of that path reaches `:401` with a Hocuspocus-owned doc that has a client. A fresh doc would strand it with no `onDocSwapped`.
