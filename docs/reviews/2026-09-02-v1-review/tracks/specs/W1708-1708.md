## Problem

Seven paths refuse to save / close / toggle and tell the user nothing. Verified on master `4da4efa0`:

1. `useDocumentWorkspace.svelte.ts:183` types `saveDocumentTarget` as `Promise<void>` and `:518` awaits `saveExactTarget` without reading its boolean. `tabs/target-save.ts` returns a bare `false` at **four** sites — `:25` (id no longer resolves), `:31` (ydoc changed across the `tick()`), `:33` (source view with no registered `SourceViewCommands`), `:38` (the formatted-branch re-resolve). The issue enumerates only the first three; `:38` is real and gets the same treatment.
2. `saveDocumentTargetAfterSourceCommit:472` — its guard at `:478`, `if (!tab || (expectedYdoc && tab.ydoc !== expectedYdoc)) return false;` — is the one refusal of the four that does not notify (`:483`, `:495` and the delegated arms do). `SourceView.svelte`'s `saveWithIntent:213` sets `errorMessage` only when `onSave` **throws**, so a returned `false` renders nothing.
3. `triggerSave` (`builtin.svelte.ts:431`) is silent on re-entry unless `announceBusy` is passed; the workspace injects it as `(documentId) => Promise<boolean>` (`:107`) and never passes it. `triggerSaveAs:268` returns `false` at `:269` with **no announce option at all**.
4. `requestToggleSourceView:293` and `requestToggleSourceViewTarget:279` optional-chain `sourceViewCommands.get(id)?.exit()` (`:297` and `:290`); an unregistered id resolves normally and the user stays in source view. The target arm awaits `tick()` first; the active arm does not, and `App.svelte:2980` keys `SourceView` on `{#key activeTab.id}`, so the remount gap is a real window.
5. `enterSourceView:256` returns silently for a non-`.md` or read-only document. Every *visible* affordance is gated (`App.svelte:2348` formatting bar, the tab menu's `writable && format === "md"`), but the **Ctrl+Shift+E** shortcut (`keybindings.ts:102` → `App.svelte:1508`) is not.
6. `reopenClosedTab:411` treats `{ok: true}` as "a tab arrived". It means HTTP 2xx; the tab materialises later over Yjs. The record is popped at `:412` and restored only inside `handleFailure:431`.
7. `closeTabAndRecord:331` tolerates an unresolvable id: it skips the guards and the stack push but still runs `clearSourceDraft`, `onTabClosed` and `closeTab`. No guard, no log.

## Fix

The model for every new notification is `handleFailure` (`:431`): name the thing, carry the reason, carry a `dedupKey` so a retry loop cannot spam toasts (the `pushNotification` docblock at `:119` is why). **Semantic tokens / testids do not bite** — no new markup, no new `data-testid`, so no snapshot regeneration. `$state` is written only from plain async functions, never a Tiptap handler.

- **`tabs/target-save.ts`** — export `type SaveTargetOutcome = { ok: true } | { ok: false; reason: "no-such-tab" | "tab-changed" | "no-source-commands" | "delegated" }`; `saveExactTarget` returns it. `:25` → `no-such-tab`; `:31` and `:38` → `tab-changed`; `:33` → `no-source-commands`; a `false` from `commands.save()` or `saveCommitted()` → **`delegated`**. That fourth reason is the load-bearing one: both downstreams already speak for themselves, so notifying on every `false` double-toasts.
- **`useDocumentWorkspace.svelte.ts`**
  - `pushSaveNotification:462` gains an optional third `dedupKey` param (still `type: "launcher"`, still `generateNotificationId()`).
  - `saveDocumentTarget:509` returns `Promise<SaveTargetOutcome>` and notifies on the three non-`delegated` reasons, `dedupKey: "save-target:<reason>:<tabId>"`, severity `warning`: `no-such-tab` → "Not saved — that document is no longer open."; `tab-changed` → "Not saved — the document reloaded while saving. Try again."; `no-source-commands` → "Not saved — the Markdown source editor hasn't finished loading. Try again." Interface `:183` changes with it.
  - `saveDocumentTargetAfterSourceCommit:478`: split the guard — `!tab` → the `no-such-tab` copy; ydoc mismatch → "Not saved — the document reloaded from disk. Your source edits are still here; try again." Both `warning`, both `dedupKey`ed.
  - Injected `triggerSave` type `:107` widens to `(documentId: string, opts?: { announceBusy?: boolean }) => Promise<boolean>`; `:501` passes `{ announceBusy: true }`. **`App.svelte` needs no edit** — the real `triggerSave` already has that signature, so the diff in the shared file stays zero.
  - `requestToggleSourceView:293`: `await tick()` before the lookup (mirroring the target arm's own tick, immediately above `:290`), then an explicit `const commands = …get(id) ?? null` — absent → `warning`, "Couldn't leave source view — the Markdown source editor is still loading. Try again.", dedupKey `source-view-exit:<id>`. Same at `:290`.
  - `requestToggleSourceView` also notifies when the active tab cannot ENTER (item 5): read-only → "Source view isn't available — this document is read-only."; non-`.md` → "Source view is only available for Markdown documents." Severity `info` (a rule explanation, not a failure; `info` expires from the tray so a mistyped shortcut does not pollute a log). `enterSourceViewTarget` and `enterSourceView` stay silent — the issue says the gated-menu twin is defence-in-depth, and `enterSourceView` is a private step of the toggle (it has no caller outside `:300`).
  - `reopenClosedTab`: after `result.ok`, poll `opts.getTabs()` for `rec.filePath` every `250ms` up to `8000ms` (two module consts), **inside the `try`** so `inflightReopens` holds across the wait. On timeout: `closedTabStack.push(rec)` and `warning` "Couldn't reopen `<basename>`: the server accepted it but no tab appeared.", dedupKey `reopen-no-tab:<path>`. Restoring is safe even if the tab lands late — the `existing` check at `:417` turns the next Ctrl+Alt+T into an activate.
  - `closeTabAndRecord:331`: if the id does not resolve, `console.warn` and `return false` **before any side effect**. No toast: the tab is already absent from the user's view. The bulk loops (`closeEachUntilCancelled:393`) `break` on `false`, which is safe by construction — their ids come from a snapshot of `getOrderedTabs()` taken immediately before, and this function removes only the id it was handed.
- **`actions/builtin.svelte.ts:269`** — move the `saveAsInflight` early return below the destructure and announce `notifyUser("info", "A Save As is already in progress…", { dedupKey: "save-as-inflight", id: "save-as-inflight" })`, byte-for-byte the shape `triggerSave:438` uses. **Unconditional, no `announceBusy` flag**: `triggerSaveAs` has exactly one caller (`useDocumentWorkspace.svelte.ts:486`) and it is always a user gesture, so the flag would have no `false` case to serve.
- **`tabs/DocumentTabs.svelte:45`** — widen `onSaveTarget` to `=> void | Promise<unknown>`. Required, not cosmetic: `Promise<SaveTargetOutcome>` is **not** assignable to `Promise<void>`, so without it `App.svelte:2745` is a type error. `:208` already `await`s and ignores the value.
