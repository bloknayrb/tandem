## Problem

Seven paths refuse to save / close / toggle and tell the user nothing. Verified on master `4da4efa0`; every line number below was re-read in the worktree, not carried over from the issue body.

1. `useDocumentWorkspace.svelte.ts:183` types `saveDocumentTarget` as `Promise<void>` and `:509` awaits `saveExactTarget` without reading its boolean. `tabs/target-save.ts` returns a bare `false` at **four** sites — `:25` (id no longer resolves), `:31` (closed OR ydoc changed across the `await deps.afterActivate()`), `:33` (source view with no registered `SourceViewCommands`), `:38` (the formatted-branch re-resolve). Three are reachable. **`:38` is defensive, not a live silent failure**: between `before` at `:24` and `current` at `:37` the formatted branch awaits nothing — only the synchronous `deps.isSourceView(deps.tabId)` runs — and production binds `resolveTarget`/`isSourceView` to synchronous reads of unchanged state (`useDocumentWorkspace.svelte.ts:521,523`), so `current` is necessarily `before`. It is handled for symmetry and pinned by a mock-driven spec; the PR body must say so rather than counting it as a fourth user-visible bug.
2. `saveDocumentTargetAfterSourceCommit:472` — its guard at `:478`, `if (!tab || (expectedYdoc && tab.ydoc !== expectedYdoc)) return false;` — is the one refusal of the four that does not notify (`:483`, `:495` and the delegated arms do). `SourceView.svelte`'s `saveWithIntent:213` sets `errorMessage` only when `onSave` **throws** (`:222`), so a returned `false` renders nothing.
3. `triggerSave` (`builtin.svelte.ts:431`) is silent on re-entry unless `announceBusy` is passed; the workspace injects it as `(documentId) => Promise<boolean>` (`:107`) and never passes it. `triggerSaveAs:268` returns `false` at `:269` with **no announce option at all**.
4. `requestToggleSourceView:293` and `requestToggleSourceViewTarget:279` optional-chain `sourceViewCommands.get(id)?.exit()` (`:296` and `:290`); an unregistered id resolves normally and the user stays in source view. The target arm awaits `tick()` first (`:289`); the active arm does not, and `App.svelte:2980` keys `SourceView` on `{#key activeTab.id}`, so the remount gap is a real window.
5. `enterSourceView:256` returns silently for a non-`.md` or read-only document. Every *visible* affordance is gated (`App.svelte:2348` formatting bar, the tab menu's `writable && format === "md"`), but the **Ctrl+Shift+E** shortcut (`actions/keybindings.ts:102` → `App.svelte:1508`) is not.
6. `reopenClosedTab:411` treats `{ok: true}` as "a tab arrived". It means HTTP 2xx; the tab materialises later over Yjs. The record is popped at `:412` and restored only inside `handleFailure:431`.
7. `closeTabAndRecord:331` tolerates an unresolvable id: it skips the guards and the stack push but still runs `clearSourceDraft`, `onTabClosed` and `closeTab`. No guard, no log.

## Fix

The model for every new notification is `handleFailure` (`:431`): name the thing, carry the reason, carry a `dedupKey` so a retry loop cannot spam toasts (the `pushNotification` docblock at `:119` is why). **Semantic tokens / testids do not bite** — no new markup, no new `data-testid` (`toast-container` already exists: `ToastContainer.svelte:14`, snapshot line 474), so no snapshot regeneration. `$state` is written only from plain async functions, never a Tiptap handler. Tense follows `shared/types.ts:686-694`: `warning`/`error` persist in the tray, which is a LOG, so their copy is past tense and carries **no trailing "Try again."**; `info` expires and may instruct.

- **`tabs/target-save.ts`** — export `type SaveTargetOutcome = { ok: true } | { ok: false; reason: "no-such-tab" | "tab-changed" | "no-source-commands" | "delegated" }`; `saveExactTarget` returns it. Each of `:31` and `:38` is **two** conditions and must be split, not collapsed: `!after` / `!current` → `no-such-tab` (the tab was closed), the `isSameTarget` mismatch → `tab-changed` (a different incarnation). `:25` → `no-such-tab`; `:33` → `no-source-commands`; a `false` from `commands.save()` or `saveCommitted()` → **`delegated`**.
  - **Why `delegated` notifies nothing — measured, not assumed.** A `false` reaches it from four places and none of them is user-silent. `saveCommitted` is `saveDocumentTargetAfterSourceCommit`, which item 2 makes notify on every arm. `commands.save` is `SourceView.saveWithIntent`, whose three `false` arms are: `:214` `saveCommandInFlight || saving` and the `|| saving` half of `:217` — both concurrent with a save the user can see, because `:267` disables the exit button on `saving` and `:319-320` make the textarea `readonly` + `aria-busy`; the `!(await initialization)` half of `:217`, which resolves false only after the mount fetch failed and set `errorMessage` at `:143`, already on screen as the `role="alert"` strip at `:303` (its only other false case is `cancelled`, i.e. the component is being torn down); and `:220`'s `onSave`, which is `saveDocumentTargetAfterSourceCommit` again. A toast on `delegated` therefore double-reports. This paragraph, not "the downstream speaks for itself", is what the silence spec's comment must carry.
- **`useDocumentWorkspace.svelte.ts`**
  - `pushSaveNotification:462` gains an optional third `dedupKey` param (still `type: "launcher"`, still `generateNotificationId()`), and **all four** call sites pass one — the three existing (`:483` read-only, `:495` Save As explainer, `:514` no-active-document) as well as the new ones. Holding Ctrl+S on any of the three appends a fresh toast *and* a fresh tray row today (`useNotifications.svelte.ts:178`, `:240`), which is the same spam the keys exist to stop. Keys: `save-target:read-only:<tabId>`, `save-target:save-as-explainer:<tabId>`, `save-target:no-active-doc`.
  - `saveDocumentTarget:509` returns `Promise<SaveTargetOutcome>` and notifies on the three non-`delegated` reasons, `dedupKey: "save-target:<reason>:<tabId>"`, severity `warning`: `no-such-tab` → "Not saved — that document is no longer open."; `tab-changed` → "Not saved — the document reloaded while saving."; `no-source-commands` → "Not saved — the Markdown source editor wasn't ready yet." Interface `:183` changes with it.
  - `saveDocumentTargetAfterSourceCommit:478`: split the guard — `!tab` → the `no-such-tab` copy; ydoc mismatch → "Not saved — the document reloaded while saving. Check the text before saving again." Both `warning`, both `dedupKey`ed. **No reassurance about surviving edits**: `commit()` clears the draft before `onSave` is called (`SourceView.svelte:178` → `updateSourceDraft(dirty:false)` deletes the entry at `useDocumentWorkspace.svelte.ts:247-252`), and `App.svelte:2980` keys `SourceView` on `activeTab.id`, so a tab switch remounts with no `initialDraft`. Only the mounted component's local `currentMarkdown` survives, which the copy must not promise.
  - Injected `triggerSave` type `:107` widens to `(documentId: string, opts?: { announceBusy?: boolean }) => Promise<boolean>`; `:501` (the `opts.triggerSave(tab.id)` tail of `saveDocumentTargetAfterSourceCommit`) passes `{ announceBusy: true }`. **This half needs no `App.svelte` edit** — `App.svelte:1890` passes the real `triggerSave` by reference and it already has that signature.
  - `requestToggleSourceView:293`: `await tick()` before the lookup (mirroring the target arm's own tick at `:289`), then an explicit `const commands = …get(id) ?? null` — absent → `warning`, "Couldn't leave source view — the Markdown source editor was still loading.", dedupKey `source-view-exit:<id>`. Same at `:290`. The three callers that can reach this notification are the palette action (`App.svelte:1026`), the formatting-bar toggle (`App.svelte:2348`) and Ctrl+Shift+E **with focus outside the source-view container**; focus *inside* it never arrives here, because `App.svelte:1509-1513` resolves `sourceCommandsForEvent(e)` off the container (`useDocumentWorkspace.svelte.ts:225-230`) and exits through that object directly.
  - `requestToggleSourceView` also notifies when the active tab cannot ENTER (item 5): read-only → "Source view isn't available — this document is read-only."; non-`.md` → "Source view is only available for Markdown documents." Severity `info` (a rule explanation, not a failure; `info` expires from the tray so a mistyped shortcut does not pollute a log). It must go through the injected `pushNotification` (`NotificationsState["push"]`, bound at `App.svelte:1892`) — that is `ingest(n, true)` (`useNotifications.svelte.ts:285`), the only path on which an `info` actually pops (`:251-254`); the SSE path passes `false` and would record it invisibly. `enterSourceViewTarget` and `enterSourceView` stay silent — the issue says the gated-menu twin is defence-in-depth, and `enterSourceView` is a private step of the toggle (its only `src` caller is `:300`).
  - `reopenClosedTab`: after `result.ok`, poll `opts.getTabs()` for `rec.filePath`, **inside the `try`** so `inflightReopens` holds across the wait. The first check runs immediately, before any wait, so a tab that is already there costs nothing. The interval and ceiling are **injectable**: `CreateDocumentWorkspaceOpts` (`:81`) gains optional `reopenPollMs` / `reopenTimeoutMs`, defaulting to the module consts `250` / `8000`; `App.svelte` passes neither. Without that, every existing reopen spec sits on a real 8s ceiling. On timeout: `closedTabStack.push(rec)` and a notification built like `handleFailure` — `type: "general-error"`, severity `warning`, "Couldn't reopen `<basename>`: the server accepted it but no tab appeared.", dedupKey `reopen-no-tab:<path>`. (`type` matters: this module builds two different envelopes on purpose, per the `:115-121` docblock, and the reopen twin at `:436` is `general-error`.) Restoring is safe even if the tab lands late — the `existing` check at `:417` turns the next Ctrl+Alt+T into an activate.
  - `closeTabAndRecord:331`: if the id does not resolve, `console.warn` and return **before any side effect** — and return **`true`**, not `false`. `false` is reserved for "the user stopped the batch here" (#1824 item H, docblock `:327-330`), and `closeEachUntilCancelled:393` `break`s on it; returning `false` for a ghost id would silently truncate a bulk close. Update that docblock to say so. The spec's earlier safety argument was wrong about the mechanism and is retracted: `closeTab` is `yjsSync.handleTabClose`, which removes nothing locally — it switches the active tab and POSTs `/api/close`, with the list reconciled by the server broadcast. What makes a ghost id unreachable *today* is that `closeOtherTabs:400` sources ids from `getOrderedTabs()` while `closeTabAndRecord` resolves against `getTabs()`, and production's `orderedTabs` is `$derived` over `getTabs()` with `.filter(Boolean)` (`useTabOrder.svelte.ts:35-41`). The harness deliberately lets those two diverge (`document-workspace.svelte.test.ts:63-69`), which is exactly why the guard is testable.
- **`actions/builtin.svelte.ts:269`** — announce on the `saveAsInflight` early return with `notifyUser("info", "A Save As is already in progress…", { dedupKey: "save-as-inflight", id: "save-as-inflight" })`, byte-for-byte the shape `triggerSave:438` uses. **Leave the early return where it is**: the earlier instruction to move it below the destructure bought nothing, because `notifyUser` is module-level and does not read `opts.notify`. **Unconditional, no `announceBusy` flag**: `triggerSaveAs` has exactly one caller (`useDocumentWorkspace.svelte.ts:486`) and it is always a user gesture, so the flag would have no `false` case to serve.
- **`tabs/DocumentTabs.svelte:45`** — widen `onSaveTarget` to `=> void | Promise<unknown>`. Required, not cosmetic: `Promise<SaveTargetOutcome>` is **not** assignable to `Promise<void>`, so without it `App.svelte:2745` is a type error. `:208` already `await`s and ignores the value.
- **`src/client/App.svelte:1028` — exactly one line.** `save: async () => documentWorkspace.saveDocumentTarget(yjsSync.activeTabId, "save"),` is a concise-body arrow, so widening the return type makes it `Promise<SaveTargetOutcome>` where `ActionDeps.save` is `Promise<void>` (`actions/executor.ts:164`) — TS2322, and `npm run typecheck` runs `svelte-check --fail-on-warnings` over `src/client`, so it is a hard red. Brace the body exactly as the `saveAs` sibling at `:1029-1031` already does: `save: async () => { await documentWorkspace.saveDocumentTarget(yjsSync.activeTabId, "save"); },`. **Do NOT widen `ActionDeps.save` / `ActionDeps.saveAs`** to absorb the new return type — the fix is local. This is save wiring, which this group owns; G6 owns the rail half. It is the only `App.svelte` line this group touches.
