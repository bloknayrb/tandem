## Problem

Three `beforeSend` hooks, one of which was fixed in #1823 and two of which were not:

- `src/server/sentry.ts` `scrubEvent` (sidecar, the model): scrubs `event.message` and each `exception.value`, **deletes `event.server_name`**, and `~`-redacts every `frame.filename` / `frame.abs_path`.
- `src/client/sentry.ts:81-92` (WebView): an **inline** `beforeSend` arrow that rewrites `event.message`, each `exception.values[].value`, `request.url`, and drops `request.data`. It never touches `stacktrace.frames[]` and never removes `server_name`.
- `src-tauri/src/sentry_reporting.rs` `scrub_event` (`:143-157`): takes `event.message` and each `exception.value` and nothing else. Same two gaps.

So with a DSN set, both of those reporters ship the machine hostname (each SDK's `server_name` default — nothing sets it, so the default is what egresses) and absolute frame paths, which in a source-run or dev build sit under the user's home directory. `sendDefaultPii: false` covers neither: it governs IPs, cookies and request bodies.

Bound, unchanged by this fix: opt-in only, and the data lands in the operator's own project.

## Fix

Mirror the sidecar in both, changing nothing about *what* the existing scrubbers do.

**WebView — `src/client/sentry.ts`.** Extract the inline arrow into a named, exported-for-test `scrubEvent(event: SentryBrowser.ErrorEvent): SentryBrowser.ErrorEvent` next to `initCrashReporting`, pass it **by reference** (`beforeSend: scrubEvent`) exactly as `src/server/sentry.ts` does, keeping its comment ("By reference, not inline"). Body = today's four rewrites plus the two gaps, in the sidecar's order:

```ts
delete event.server_name;
for (const exception of event.exception?.values ?? []) {
  if (exception.value) exception.value = scrubText(exception.value);
  for (const frame of exception.stacktrace?.frames ?? []) {
    if (frame.filename) frame.filename = scrubText(frame.filename);
    if (frame.abs_path) frame.abs_path = scrubText(frame.abs_path);
  }
}
```

`scrubText` (not `redactPaths` alone) is the right callee: it is what the file already uses, it composes `redactPaths` + `redactSecrets`, and a frame path can legitimately carry a token in a query string on a bundled asset URL. `beforeBreadcrumb` is untouched. The `@sentry/browser` import at module top is already `import type`, so the extracted function adds no runtime dependency and the existing test file keeps loading without the optional dep. Add `scrubEvent` to the `__test` export alongside `scrub`/`redactSecrets`/`redactPaths` — do not rename the existing keys, the current specs key on them.

**Rust shell — `src-tauri/src/sentry_reporting.rs`.** Split `scrub_event` into today's env read plus a pure inner function, mirroring how `redact_home` is already the pure, unit-tested half:

- `fn scrub_event(event: &mut Event<'static>)` — keeps `let Some(home) = home_dir_string() else { return }` and delegates.
- `fn scrub_event_with_home(event: &mut Event<'static>, home: &str)` — today's message + `exception.value` loop, plus `event.server_name = None;` and a `fn scrub_frames(st: &mut Stacktrace, home: &str)` helper applied to each `exception.stacktrace`, to `event.stacktrace` and to each `thread.stacktrace`. Fields are `Option<String>` on `sentry::protocol::Frame` (`filename` at `v7.rs:201`, `abs_path` at `:204`), `event.server_name` is `Option<Cow<'a, str>>` (`:1643`), `event.stacktrace` is `Option<Stacktrace>` (`:1674`) and `threads` is `Values<Thread>` (`:1680`) — verified against `sentry-types-0.42.0`.

Covering `threads` and the top-level `stacktrace` as well as exceptions is deliberate and is four lines, not a framework: the panic integration puts the backtrace on the exception, but the native/minidump and thread paths carry frames too, and leaving one uncovered leaves the same failure possible. `server_name = None` (not a redaction) matches the sidecar's `delete`.

**Server-side comment.** `src/server/sentry.ts`'s doc comment above `scrubEvent` says the other two "still ship both — tracked as #2023". Update it in the same commit or it becomes a false claim that no test can catch.

Rules that bite: nothing here touches Y.Doc, Y.Map keys, `data-testid`, MCP tools, `/api` routes or `NON_LOOPBACK_ALLOWED`. ## Tests

**`tests/client/sentry-scrub.test.ts`** (extends the existing file; it already imports `__test` and loads without `@sentry/browser` installed). Build a literal event object and assert on the returned value:

1. `server_name` present → **absent** after. Kills a fix that only adds frame scrubbing.
2. An exception with `stacktrace.frames: [{ filename: "/Users/alice/app/src/x.ts", abs_path: "/Users/alice/app/src/x.ts" }]` → both become `/Users/[user]/…`. Kills a fix that only deletes `server_name`, and — because it asserts **both** fields — kills one that scrubs `filename` and forgets `abs_path` (the field Sentry's issue view actually shows).
3. The pre-existing behaviour survives: `message`, `exception.value` and `request.url` scrubbed, `request.data` dropped. Kills a rewrite that swaps the new loop in over the old body.
4. An event with no `exception`, no `request` and no frames returns without throwing. Kills a non-optional-chained walk, which would crash `beforeSend` and — since Sentry drops an event whose hook throws — turn a privacy fix into silent telemetry loss.

**Rust, `#[cfg(test)] mod tests` in `src-tauri/src/sentry_reporting.rs`** beside the five `redact_home` cases, all against `scrub_event_with_home(&mut event, "/home/alice")` so no env read is involved:

5. `event.server_name = Some("build-box".into())` → `None` after.
6. An `Exception` with a `Stacktrace` whose frame has `filename`/`abs_path` under `/home/alice` → both `~/…`. The exception-only twin of spec 2.
7. A frame reached through `event.threads` (not through `exception`) → also redacted. This is the one that kills the obvious "loop over exceptions" fix, which is the shape the sidecar model would suggest.
8. An event with an empty `exception.values`, no `stacktrace` and no `threads` is a no-op and does not panic.

No new test file is needed on either side; both hosts already exist.

## Not in scope

Unifying the three hooks into one shared implementation: they are three SDKs and two languages, and the sidecar's own divergence (`request`/breadcrumbs are WebView-only) is intended. Changing the opt-in posture, the DSN handling, or `sendDefaultPii`.
