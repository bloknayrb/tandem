# W13s — #2023 the WebView and Rust-shell `beforeSend` hooks still ship `server_name` and absolute stack-frame paths

Branch `fix/security-applychanges-doc-swap-and-sentry-scrubbing-2037`. Closes #2023. Ledger: none — #2023 is a non-review issue; its tracked home is the **Telemetry** paragraph of `docs/security.md:184`, which currently names it open. Probe: not runnable in-repo — observing a real event needs `TANDEM_SENTRY_DSN` pointed at a live Sentry/GlitchTip project, which is Bryan's (listed under `bryan`). The in-repo stand-in is the unit specs below.

## Problem

Three `beforeSend` hooks, one fixed in #1823 and two not:

- `src/server/sentry.ts` `scrubEvent` (sidecar, the model): scrubs `event.message` and each `exception.value`, **deletes `event.server_name`**, and `~`-redacts every `frame.filename` / `frame.abs_path` on exception stacktraces.
- `src/client/sentry.ts:81-92` (WebView): an **inline** `beforeSend` arrow that rewrites `event.message`, each `exception.values[].value`, `request.url`, and drops `request.data`. It never touches `stacktrace.frames[]` and never removes `server_name`.
- `src-tauri/src/sentry_reporting.rs` `scrub_event` (`:143-157`): takes `event.message` and each `exception.value` and nothing else. Same two gaps.

So with a DSN set, both of those reporters ship the machine hostname (each SDK's `server_name` default — nothing sets it, so the default egresses) and absolute frame paths, which in a source-run or dev build sit under the user's home directory. `sendDefaultPii: false` covers neither: it governs IPs, cookies and request bodies.

Bound, unchanged by this fix: opt-in only, and the data lands in the operator's own project.

## Fix

Mirror the sidecar in both, changing nothing about *what* the existing scrubbers do.

**WebView — `src/client/sentry.ts`.** Extract the inline arrow into a named `scrubEvent(event: SentryBrowser.ErrorEvent): SentryBrowser.ErrorEvent` next to `initCrashReporting` and pass it **by reference** (`beforeSend: scrubEvent`) exactly as `src/server/sentry.ts` does, keeping its "By reference, not inline" comment. Body = today's four rewrites plus the two gaps, in the sidecar's order:

```ts
delete event.server_name;
for (const exception of event.exception?.values ?? []) {
  if (exception.value) exception.value = scrubText(exception.value);
  for (const frame of exception.stacktrace?.frames ?? []) {
    if (frame.filename) frame.filename = scrubText(frame.filename);
    if (frame.abs_path) frame.abs_path = scrubText(frame.abs_path);
  }
}
```

`scrubText` (not `redactPaths` alone) is the right callee: it is what the file already uses, it composes `redactPaths` + `redactSecrets`, and a bundled-asset frame path can carry a token in a query string. `beforeBreadcrumb` is untouched. Frames come from `event.exception.values[].stacktrace` only, and that is scoping, not an oversight: `@sentry/browser` populates neither `event.stacktrace` nor `event.threads`. The `@sentry/browser` import at module top is already `import type`, so the extracted function adds no runtime dependency and the existing test file keeps loading without the optional dep. Add `scrubEvent` to the `__test` export alongside `scrub`/`redactSecrets`/`redactPaths` — do not rename the existing keys, the current specs key on them.

**Rust shell — `src-tauri/src/sentry_reporting.rs`.** Split `scrub_event` into today's env read plus a pure inner function, mirroring how `redact_home` is already the pure, unit-tested half — and **hoist the hostname deletion out of the home-gated half**:

- `fn scrub_event(event: &mut Event<'static>)`:
  ```rust
  event.server_name = None;
  let Some(home) = home_dir_string() else { return };
  scrub_event_with_home(event, &home);
  ```
  The order is the contract. `home_dir_string()` returns `Option<String>` (`:161-165`) and today's `scrub_event` opens with `let Some(home) = home_dir_string() else { return }` (`:143`), so leaving `server_name = None` inside the inner function would make hostname removal **conditional on a home-directory lookup succeeding** — on any host where `dirs::home_dir()` yields `None` the hostname would still egress, and no inner-function spec could see it. Deleting a hostname is not a redaction and needs no home; the sidecar deletes unconditionally (`src/server/sentry.ts:110`).
- `fn scrub_event_with_home(event: &mut Event<'static>, home: &str)` — today's message + `exception.value` loop, plus `event.server_name = None;` **again** (idempotent, so spec 5 still pins the inner function) and a `fn scrub_frames(st: &mut Stacktrace, home: &str)` helper applied to each `exception.stacktrace`. Fields are `Option<String>` on `sentry::protocol::Frame` (`filename` at `v7.rs:210`, `abs_path` at `:213`) and `event.server_name` is `Option<Cow<'a, str>>` (`:1683`) — verified against **`sentry-types` 0.49.2**, which `src-tauri/Cargo.lock:5773-5774` pins (`sentry` 0.49.2 at `:5645`). `server_name = None` (not a redaction) matches the sidecar's `delete`.

  Exception stacktraces only, exactly like the sidecar: the panic integration puts the backtrace on the exception, and the app registers no minidump/native crash handler, so `event.stacktrace` and `event.threads` are not populated on this path.

## Tests

**`tests/client/sentry-scrub.test.ts`** (extends the existing file; it already imports `__test` and loads without `@sentry/browser` installed). Build a literal event and assert on the returned value:

1. `server_name` present → **absent** after. Kills a fix that only adds frame scrubbing.
2. An exception with `stacktrace.frames: [{ filename: "/Users/alice/app/src/x.ts", abs_path: "/Users/alice/app/src/x.ts" }]` → both become `/Users/[user]/…`. Asserting **both** fields kills a fix that scrubs `filename` and forgets `abs_path` (the field Sentry's issue view shows).
3. Pre-existing behaviour survives: `message`, `exception.value` and `request.url` scrubbed, `request.data` dropped. Kills a rewrite that swaps the new loop in over the old body.
4. An event with no `exception`, no `request` and no frames returns without throwing. Kills a non-optional-chained walk — Sentry drops an event whose hook throws, turning a privacy fix into silent telemetry loss.
5. **`scrubEvent` is the hook `Sentry.init` actually receives.** Without it, specs 1-4 all pass against a fix that adds `scrubEvent` and leaves the inline arrow wired — the leak ships green. Mirror `tests/server/sentry-scrub.test.ts:185-199` exactly: read `src/client/sentry.ts`, slice from `Sentry.init({` to the matching close, and `expect(initCall).toMatch(/beforeSend:\s*scrubEvent/)`. **Scoped to the call slice, not the file** — that scoping was measured on the sidecar twin, where a file-wide regex stayed green with the hook unwired because the docblock contains the literal string.

**Rust, `#[cfg(test)] mod tests` in `src-tauri/src/sentry_reporting.rs`**, beside the five `redact_home` cases:

6. `scrub_event_with_home(&mut event, "/home/alice")` with `event.server_name = Some("build-box".into())` → `None` after.
7. Same driver, an `Exception` with a `Stacktrace` whose frame has `filename`/`abs_path` under `/home/alice` → both `~/…`. The exception-only twin of spec 2.
8. Same driver, an event with an empty `exception.values` and no stacktrace is a no-op and does not panic.
9. **The outer `scrub_event` clears `server_name` with no home dir involved.** Specs 6-8 drive the inner function, so none can see the early return. Build an event with `server_name = Some("build-box".into())`, call `scrub_event(&mut event)`, assert `None`. Pins the hoist, and that `scrub_event` is more than a stub.

No new test file on either side; both hosts already exist.
