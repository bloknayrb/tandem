# G4 — #1613 `tests/tauri-driver` has a tsconfig nothing invokes, and a real error sitting in it

Branch `fix/typecheck-tests-three-configs-and-a-mock-idiom-that-check-nothing-1613`. Closes #1613
(both numbered items in its "What closing this needs"). No `areas/*.md` ledger row — a non-review
issue, scheduled at `docs/plans/2026-09-06-open-issues-sweep.md:110` (wave 10). Probe:
`npx tsc -p tests/tauri-driver/tsconfig.json --noEmit` **from the main checkout** — a fresh
worktree has no `tests/tauri-driver/node_modules` and reports three TS2688s (missing `types`
entries) instead of the real error, which is itself the issue's point.

## Problem

Every anchor in the issue body re-measured true on `f6559305`. `tests/tauri-driver/package.json`
has exactly one script, `{"test": "wdio run ./wdio.conf.ts"}` — no `tsc`. No
`tsc -p tests/tauri-driver` appears in `package.json`, `.github/workflows/` or `.husky/`.
`tauri-webdriver.yml` is `workflow_dispatch` only (since #1197). So
`tests/tauri-driver/tsconfig.json` is invoked by nothing, and running it by hand reports
`wdio.conf.ts(152,3): error TS2353: ... 'host' does not exist in type 'Config'`, exit 2.

**`host` is dead config, and the answer is `hostname`.** The harness pins
`webdriverio@9.28.0`; `@wdio/types` `Connection` (`build/Options.d.ts:36`) declares `hostname?:
string` and no `host` at all — the key was renamed in WebdriverIO v5 and the config has carried
the v4 spelling since. Today the session therefore connects to the default
`DEFAULT_HOSTNAME = "localhost"` (`@wdio/utils/build/index.js:101`) rather than the `127.0.0.1`
the file says, which is why nothing has ever visibly broken: `tauri-driver` binds loopback and
`localhost` resolves there.

**One tracked claim rests on the dead key.** `tests/tauri-driver/README.md`'s `extract-zip`
advisory says the harness "sets `host`/`port` to the `tauri-driver` proxy on 127.0.0.1:4444, so
`@wdio/utils`' `startWebDriver` short-circuits on `definesRemoteDriver()`". Measured,
`definesRemoteDriver` (`@wdio/utils/build/index.js:324-328`) reads `options.hostname` — never
`host` — OR `Boolean(options.port)`. The conclusion still holds, but **only `port` carries it
today**; `host` contributes nothing. That advisory is the justification for a knowingly-accepted
unpatched CVE, so its mechanism sentence has to be right.

**The second half of the issue is already half-done and must not be re-done.** #1602 corrected
the false "It is checked, just not by these configs" in
`tests/scripts/typecheck-tests-wiring.test.ts`'s carve-out comment; master's text is honest. What
survives is the *unrun config* — fix the TS2353 and, with no runner, the next error sits unseen
exactly as this one did.

## Fix

1. **`tests/tauri-driver/wdio.conf.ts:152`** — `host: "127.0.0.1"` → `hostname: "127.0.0.1"`.
   Preserves the file's stated intent and pins the literal loopback address rather than inheriting
   `localhost` (which can resolve to `::1` first). Keep `port: 4444` unchanged.
   **This is the only behavioural change in the group, and the PR body must say so in one line:**
   the effective connect target moves `localhost` → `127.0.0.1`; `tauri-driver` binds loopback, so
   this is expected inert, and #1197's unreproduced `DevToolsActivePort` failure is downstream of
   the connect, not caused by it. The alternative — deleting the dead key — clears the same TS2353
   with a provably zero runtime delta; it is rejected because it would silently concede that the
   file's stated intent was never in force, and the loopback pin is the intent worth keeping.
2. **`tests/tauri-driver/README.md`**, the `extract-zip` paragraph — rewrite the mechanism
   sentence to name `hostname`/`port`. **After item 1 the short-circuit is satisfied by `hostname`
   AND `port`; before it, `port` alone carried it.** The historical claim (`host` contributing) is
   the part that was wrong — say so in that tense, and do **not** weaken the acceptance itself.
3. **`.github/workflows/tauri-webdriver.yml`** — **move** the existing `Install harness
   dependencies` step (`working-directory: tests/tauri-driver`, `run: npm install`) up to
   immediately after the `Install root dependencies` step (`npm ci --ignore-scripts`, which
   follows `actions/setup-node`), and add the typecheck step immediately after it with the same
   `working-directory` and a bare `run: npx tsc -p tsconfig.json --noEmit`.
   **The position is load-bearing, not cosmetic.** In its filed position the pair sits after
   `cargo install tauri-driver`, `cargo install tauri-cli`, `node scripts/download-node-sidecar.mjs`,
   `node scripts/build-reaper.mjs` and `cargo tauri build --debug --no-bundle`, inside a job with
   `timeout-minutes: 45` whose own header says it *fails on every run* (#1197) — so on a dispatch
   the typecheck would be gated behind ~10 minutes of Rust/desktop build it does not need, and any
   of those legs failing or timing out skips it entirely. It needs only checkout + setup-node +
   that `npm install`. Moved up, it is reachable even when the heavy legs die.
   **This is the chosen end of the issue's two, and the reason is cost:** the install it depends on
   already happens in that job, so the marginal cost is one `tsc` on an 8-file program, whereas
   folding the config into `typecheck:tests` would add a second `npm ci` to the *required* `check`
   job for a dispatch-only harness.
4. **`tests/scripts/typecheck-tests-wiring.test.ts`** — update the `tests/tauri-driver` carve-out
   comment in the orphan sweep. It is still excluded from the three configs. **The replacement
   sentence must not say "it is now checked."** Required shape: *checked only when the
   dispatch-only `tauri-webdriver.yml` is manually run; no PR or push checks it, and that workflow
   has not had a successful run since 2026-08-08 (#1197).* The same sentence goes in the PR body.
   Nothing else in that file changes.
5. **`CLAUDE.md`, the Testing & E2E bullet (line 215)** — its final clause currently reads
   **`tests/tauri-driver/` is excluded and is genuinely typechecked by nothing** — its own tsconfig
   is never invoked and currently holds an unseen TS2353.* Items 1 and 3 make **both** halves false,
   and nothing turns red: the wiring test's `docs match the wiring` describe asserts only
   `/typecheck:tests/` and `/typecheck-tests-wiring/` against `CLAUDE.md`, and
   `grep -rn "genuinely typechecked" tests/` returns nothing. `CLAUDE.md` is auto-loaded into every
   session, so a stale rule statement there is the worst residue this group can leave. Amend the
   clause to say the TS2353 is fixed and the directory is excluded from the three test configs and
   checked **only** by the dispatch-only `tauri-webdriver.yml` — never on a PR or push.
   **Ordering with G4-1614:** #1614's item 5 rewrites the *same bullet* (its "Three configs now own
   it" clause). This edit lands first, in #1613's commit; #1614's edit is applied on top of it.

Rules that bite: the step must be a **bare `run:`** with no `if:` and no `|| true` — this repo's
repeat failure is a gate that reports success when it could not evaluate (#1229, #1399, #1529),
and the neighbouring wiring tests exist because of it. Do **not** add `tests/tauri-driver` to any
`tsconfig.tests.*.json` `include`; the orphan sweep's `.filter()` prefix exclusion must stay.
