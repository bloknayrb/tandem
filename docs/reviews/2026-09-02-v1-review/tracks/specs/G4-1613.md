# G4 — #1613 `tests/tauri-driver` has a tsconfig nothing invokes, and a real error sitting in it

Branch `fix/typecheck-tests-three-configs-and-a-mock-idiom-that-check-nothing-1613`. Closes #1613
(both numbered items in its "What closing this needs"). No `areas/*.md` ledger row — a non-review
issue, scheduled at `docs/plans/2026-09-06-open-issues-sweep.md:110` (wave 10). Probe:
`npx tsc -p tests/tauri-driver/tsconfig.json --noEmit` **from the main checkout** — a fresh
worktree has no `tests/tauri-driver/node_modules` and reports three TS2688s (missing `types`
entries) instead of the real error, which is itself the issue's point.

## Problem

Every anchor in the issue body re-measured true on `f6559305`. `tests/tauri-driver/package.json`
has exactly one script, `{"test": "wdio run ./wdio.conf.ts"}` — no `tsc`. No
`tsc -p tests/tauri-driver` appears in `package.json`, `.github/workflows/` or `.husky/`.
`tauri-webdriver.yml` is `workflow_dispatch` only (since #1197). So
`tests/tauri-driver/tsconfig.json` is invoked by nothing, and running it by hand reports
`wdio.conf.ts(152,3): error TS2353: ... 'host' does not exist in type 'Config'`, exit 2.

**`host` is dead config, and the answer is `hostname`.** The harness pins
`webdriverio@9.28.0`; `@wdio/types` `Connection` (`build/Options.d.ts:36`) declares `hostname?:
string` and no `host` at all — the key was renamed in WebdriverIO v5 and the config has carried
the v4 spelling since. Today the session therefore connects to the default
`DEFAULT_HOSTNAME = "localhost"` (`@wdio/utils/build/index.js:101`) rather than the `127.0.0.1`
the file says, which is why nothing has ever visibly broken: `tauri-driver` binds loopback and
`localhost` resolves there.

**One tracked claim rests on the dead key.** `tests/tauri-driver/README.md`'s `extract-zip`
advisory says the harness "sets `host`/`port` to the `tauri-driver` proxy on 127.0.0.1:4444, so
`@wdio/utils`' `startWebDriver` short-circuits on `definesRemoteDriver()`". Measured,
`definesRemoteDriver` (`@wdio/utils/build/index.js:324-328`) reads `options.hostname` — never
`host` — OR `Boolean(options.port)`. The conclusion still holds, but **only `port` carries it
today**; `host` contributes nothing. That advisory is the justification for a knowingly-accepted
unpatched CVE, so its mechanism sentence has to be right.

**The second half of the issue is already half-done and must not be re-done.** #1602 corrected
the false "It is checked, just not by these configs" in
`tests/scripts/typecheck-tests-wiring.test.ts`'s carve-out comment; master's text is honest. What
survives is the *unrun config* — fix the TS2353 and, with no runner, the next error sits unseen
exactly as this one did.

## Fix

1. **`tests/tauri-driver/wdio.conf.ts:152`** — `host: "127.0.0.1"` → `hostname: "127.0.0.1"`.
   Preserves the file's stated intent and pins the literal loopback address rather than inheriting
   `localhost` (which can resolve to `::1` first). Keep `port: 4444` unchanged.
2. **`tests/tauri-driver/README.md`**, the `extract-zip` paragraph — rewrite the mechanism
   sentence to name `hostname`/`port` and say the short-circuit is satisfied by `port` alone.
   Do **not** weaken the acceptance itself; only the sentence that explains it was wrong.
3. **`.github/workflows/tauri-webdriver.yml`** — add a typecheck step immediately after the
   existing `Install harness dependencies` step (`working-directory: tests/tauri-driver`,
   `run: npm install`), with the same `working-directory` and a bare
   `run: npx tsc -p tsconfig.json --noEmit`. **This is the chosen end of the issue's two, and the
   reason is cost:** the install it depends on already happens in that job, so the marginal cost is
   one `tsc` on an 8-file program, whereas folding the config into `typecheck:tests` would add a
   second `npm ci` to the *required* `check` job for a dispatch-only harness. State plainly in the
   PR body that the workflow is dispatch-only, so this runs when the harness runs and not on every
   PR — that is strictly more than today's zero and is not dressed up as more than it is.
4. **`tests/scripts/typecheck-tests-wiring.test.ts`** — update the `tests/tauri-driver` carve-out
   comment in the orphan sweep: it is still excluded from the three configs, and it is now checked
   by `tauri-webdriver.yml`. Nothing else in that file changes.

Rules that bite: the step must be a **bare `run:`** with no `if:` and no `|| true` — this repo's
repeat failure is a gate that reports success when it could not evaluate (#1229, #1399, #1529),
and the neighbouring wiring tests exist because of it. Do **not** add `tests/tauri-driver` to any
`tsconfig.tests.*.json` `include`; the orphan sweep's `.filter()` prefix exclusion must stay.

## Tests

1. **Mutation (the load-bearing one).** Restore `host:` in `wdio.conf.ts` from a file copy and
   confirm `npx tsc -p tests/tauri-driver/tsconfig.json --noEmit` exits 2 with TS2353 naming
   `host`; put `hostname` back and confirm exit 0. This is what proves the config now *has* a
   green baseline to protect — a config that compiles proves nothing on its own.
2. **One assertion added to `tests/scripts/typecheck-tests-wiring.test.ts`**, in the existing
   `docs match the wiring` describe: parse `.github/workflows/tauri-webdriver.yml` and assert some
   step has `working-directory: tests/tauri-driver` and a `run` that `.trim()`s to exactly
   `npx tsc -p tsconfig.json --noEmit`, with no `if:` and no `continue-on-error`. **What wrong
   implementation it kills:** deleting the step (or masking its exit code) while leaving the
   carve-out comment claiming the directory is checked — which silently restores exactly the state
   #1613 was filed about. It is one assertion in a file that already parses workflows, not a new
   guard file; a new wiring framework would be over-build for a dispatch-only harness.

`npm run typecheck:tests` and the vitest suite stay green.
