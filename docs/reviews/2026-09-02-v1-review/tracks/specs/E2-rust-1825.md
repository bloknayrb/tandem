## Problem

The bullet reads:

> Sidecar inherits the shell env (`sidecar.rs:443` comment says otherwise): `TANDEM_MCP_PORT` / `TANDEM_BIND_HOST` from a login shell change the desktop's ports silently.

**Measured against current master: this is already fixed, and the fix is not this group's to re-do.** `sidecar_env_pairs` (`src-tauri/src/sidecar.rs:1587-1596`) now returns `TANDEM_PORT`, `TANDEM_MCP_PORT` and `TANDEM_BIND_HOST` explicitly, and `start_sidecar` folds every pair onto the command at `:1730-1732`. It landed in `717eeff9` (#1925, wave 5's E1 group), which also wrote the evidence into the function's own docblock (`:1568-1581`): `tauri-plugin-shell`'s `Command::new` never calls `env_clear()`, `spawn` hands a plain `std::process::Command` to `SharedChild::spawn`, and that inherits by default — so an ambient `TANDEM_MCP_PORT` did reach the child and move it off :3479, after which the shell missed its own child on every health poll and (post-#1756) POSTed `/api/shutdown` at whatever else answered :3479 on every Quit. There is a test: `sidecar_env_pairs_exports_both_data_dir_variables` (`:4078`).

The bullet's parenthetical — "the `sidecar.rs:443` comment says otherwise" — is also stale twice over: the line has drifted, and the comment now states the inheritance correctly and at length rather than denying it.

**What genuinely remains under this bullet is a different claim than the one written**, and the code says so in two places (`sidecar.rs:1580` "It does not fix #1825 (those are still hardcoded)"; `:763-766` "#1825 (derive the URL) is still open"): `HEALTH_URL` / `SHUTDOWN_URL` are hardcoded `127.0.0.1:3479` literals rather than derived from `MCP_PORT` / `SIDECAR_BIND_HOST`. With the spawn site pinning the ports, those literals are correct by construction for the desktop sidecar — the remaining exposure is drift between the two halves, not an ambient-env hole.
