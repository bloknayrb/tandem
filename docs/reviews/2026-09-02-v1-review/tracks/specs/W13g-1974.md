## Problem

**1. `tests/perf/performance.spec.ts:446-450` cites #1288 present-tense** ("`#1288` is that
wait"). #1288 is closed, and `docs/perf-gate-results.md:215`'s own heading says "`#1288` does not
reproduce, and its proposed mechanism is refuted" — Run 1's 7851ms reading was a harness artifact
(margin pipeline never mounted), not a regression later fixed. The comment sends the next reader
to a withdrawn explanation.

**2. `docs/perf-gate-results.md`'s Run 3 section (`:376-410`) records only the 311ms total for
`annotation-accept`, no click/settle split**, yet its closing paragraph (`:405-409`) asserts "No
residual ... click-dispatch motion coupling to file a follow-up issue for" — a claim Run 3's own
table can't support, since it never recorded the split. Runs 1-2 are analysed almost entirely in
terms of that split (`:206-207`'s table), and the harness prints it every run
(`performance.spec.ts:477-479`).

A real split does exist, just not attached to Run 3: PR #1973's own "Verification" body records a
*different* sample — `annotation-accept: 340.0ms; breakdown "click-dispatch 335ms, post-click
settle 5ms"` (≈98.5% click-dispatch) — under the new (#1734) definition. Splicing that onto Run 3's
311ms row would misattribute one sample's breakdown to another's total.

## Fix

1. **`performance.spec.ts:446-450`** — rewrite the `#1288` comment as historical: name it closed
   and refuted, cross-reference `docs/perf-gate-results.md §"#1288 does not reproduce, and its
   proposed mechanism is refuted"` (matching this file's own `:33` citation style — its only two
   `docs/perf-gate-results.md` citations are `:26` and `:33`). In the same comment, record that
   under the current (#1734) definition the most recent sample (PR #1973's own verification body)
   put ~335 of a 340ms total in this same click-stability wait — so the split stays motivated as a
   live concern, not a settled non-issue. Keep the substantive point unchanged: Playwright's
   click-stability wait is a real, distinct cost worth isolating.

2. **`docs/perf-gate-results.md`'s Run 3 closing paragraph** — narrow the claim to what the table
   supports: state plainly Run 3 recorded only the total, not the split, so "no residual
   click-dispatch motion coupling" isn't something this run's data can assert. Cite the real split
   from PR #1973's body as corroborating context — clearly labeled a separate sample (not folded
   into Run 3's table), with a retrievable pointer (the PR number) and a note that it's not
   reproducible from any tracked file (only the PR body has it).

3. **Leave the Run 1 / Run 2 `#1288` citations untouched** (`:76`, `:147`) — both already
   past-tense and scoped to what Run 1 observed, inside sections marked SUPERSEDED/historical.

4. **Leave the successor-measurement decision (whether `annotation-accept` should measure from
   click-completion) to Bryan** — PR #1973's own body already calls it a judgement call, not
   something a measurement settles. List under `bryan`.
