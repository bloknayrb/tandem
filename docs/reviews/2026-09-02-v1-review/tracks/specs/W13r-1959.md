# W13r — #1959 a successful post-boot sidecar crash-restart is silent

Branch `fix/sidecar-restart-toast-and-rust-test-harness-residue-1970`. Closes #1959 (the client half of #1809). Ledger: `docs/plans/2026-09-06-open-issues-sweep.md`, Wave 13 (2026-09-20); non-review issue, so no `areas/*.md` row and no experiment. Probe: none available — no browser E2E can drive a Tauri event, so the probe is the vitest spec below plus Bryan's hardware smoke.

## Problem

Since #1809 a post-boot sidecar crash is respawned. The **breaker trip** surfaces (`sidecar.rs:2139` emits `sidecar-restart-failed`, `App.svelte:301` toasts it), but a **successful** crash-restart emits nothing. The user's tabs go Disconnected and silently reconnect through the Hocuspocus generation gate — correct recovery, read by a human as a glitch.

## Fix

Two halves, modelled line-for-line on the `BreakerTripped` emit (`sidecar.rs:2136-2144`) and on `utils/startup-rejection.ts` + its `App.svelte:370` call site.

**Rust — `src-tauri/src/sidecar.rs`.**

- Add `pub(crate) const EVENT_SIDECAR_RESTARTED: &str = "sidecar-restarted";` beside `RestartCause` (`:490`).
- Add a pure discriminant beside it:

  ```rust
  /// Whether a restart with this cause is worth telling the user about.
  /// Extracted so the decision is testable without an `AppHandle`: the emit
  /// itself needs a real spawn, this does not.
  pub(crate) fn announces_successful_restart(cause: RestartCause) -> bool {
      matches!(cause, RestartCause::PostBootCrash)
  }
  ```

- Emit it from `restart_sidecar_for`'s success arm, `Ok(SpawnOutcome::Started) => {}` at `:568`, **gated on `announces_successful_restart(cause)`** — not from the `CrashRestartDecision::Restart` arm at `:2094` as the issue body proposes. **This is a deliberate divergence and the spec's one design call:** the `Restart` arm is a *decision*, taken before `stop_sidecar_gracefully` and `start_sidecar` have run. Emitting there makes the toast a lie whenever the restart then fails or is declined — and those two arms (`:604`, `:633`) emit `sidecar-restart-failed`, so the user would get "restarted" immediately followed by "failed to restart". `Ok(SpawnOutcome::Started)` is the only point where success is known, it is in the same file, and `RestartCause` is `Copy` so `cause` is already available inside the spawned task (it is read at `:533` before the spawn). `UserInitiated` restarts stay silent because `NetworkSettings.svelte` already gives that click its own feedback.
- **Both `PostBootCrash` callers are in scope, and the copy has to be true of both.** `restart_sidecar_for(_, PostBootCrash)` is called from the `CrashRestartDecision::Restart` arm (`:2094`) **and** from `recover_deferred_crash` (`:310`), which pays the debt latched while spawns were suppressed — that is a genuine post-boot crash whose restart was merely deferred, so "Tandem server restarted after a crash." is accurate there too, and the gate deliberately does not distinguish them. It fires at whatever moment the suppression is released (today the update download's failure arm), which can be shortly after boot; the accepted reading is "a crash happened and the server is back", and the alternative — gating additionally on `DEFERRED_CRASH` so the debt-payment path stays silent — is listed under `bryan` with the copy rather than decided here.
- **One accepted false positive, debug builds only.** `SpawnOutcome::Started` also covers "(debug builds only) an external `dev:standalone` server was already answering `/health`" (`sidecar.rs:1764-1766`), where no child was spawned. A crash-restart in a `cargo tauri dev` session can therefore toast a restart that adopted an existing server. Release builds always spawn, so this cannot reach a user; recorded rather than guarded.
- Payload-free: `handle.emit(EVENT_SIDECAR_RESTARTED, ())`. The `BreakerTripped` site passes a code string only as a log-side distinction; there is nothing to distinguish here. Follow its error handling exactly — `if let Err(emit_err) = … { log::error!(…) }`, never `unwrap`.
- Do **not** add a `log::warn!` for the success case: `:2090-2093` already warns "crashed after boot — restarting" above the release `LevelFilter::Warn` floor.
- Leave the breaker-trip copy alone. The issue's third bullet asks to "consider" it; considered — "Tandem server failed to restart." is true of a tripped breaker as well as of a failed manual click, and rewording it is a second change in a file this PR is already editing for #1970.

**Client — new `src/client/utils/sidecar-restart-toast.ts` + `src/client/App.svelte`.**

- Export `SIDECAR_RESTARTED_EVENT = "sidecar-restarted"`, `SIDECAR_RESTARTED_MESSAGE = "Tandem server restarted after a crash."`, `buildSidecarRestartedNotification(now: number): TandemNotification` and `wireSidecarRestarted(deps): () => void`.
- **The notification object is built in the module, not at the call site.** `buildSidecarRestartedNotification(now)` returns exactly:

  ```ts
  {
    id: `sidecar-restarted-${now}`,
    type: "general-error",
    severity: "info",
    message: SIDECAR_RESTARTED_MESSAGE,
    dedupKey: "sidecar-restarted",
    timestamp: now,
  }
  ```

  This is the round-1 correction: with the payload inline in `App.svelte` the only test that could see it was one the test itself constructed, so flipping `severity` to `"error"` or dropping `dedupKey` would have shipped green. Mirrors `startup-rejection.ts:119`, where the copy lives inside the module (`deps.push(messageForStartupRejection(code), code)`) precisely so `tests/client/startup-rejection.test.ts` pins it.
- `wireSidecarRestarted(deps)` is shaped like `wireStartupRejection` (`startup-rejection.ts:106`): `deps.loadEvent: () => Promise<{ listen: … }>`, **`deps.push: (notification: TandemNotification) => void`**, optional `deps.warn`; a `cancelled` latch; `unlisten` released by the returned cleanup; a `.catch` that warns rather than throws. On each delivered event it calls `deps.push(buildSidecarRestartedNotification(Date.now()))`. It is deliberately simpler than `wireStartupRejection` — there is no buffer and no drain. **Docblock wording (round-1 correction):** say *"losing this notice is acceptable — it describes a recovery that has already succeeded — which is why no buffer is warranted"*, **not** "a crash-restart only ever happens while the WebView is alive". The latter is overstated: `recover_deferred_crash` (`sidecar.rs:310`) can restart before `App.svelte` mounts, and a nudge with no listener is simply dropped. Say it that way so nobody reads the missing buffer as an oversight, and nobody reads the docblock as a proven invariant.
- `App.svelte`, immediately after the existing `sidecar-restart-failed` block (`:296-324`), inside a `if (isTauriRuntime())` guard: call `wireSidecarRestarted({ loadEvent: () => import("@tauri-apps/api/event"), push: (n) => notifications.push(n) })` and pass the returned cleanup to `onDestroy`. The call site is now a one-liner with no design decisions in it.
  - `severity: "info"` is the call: only `info` expires (`TandemNotification` docblock, `src/shared/types.ts:701-710`), and a recovery notice that persists in the activity tray as a warning outlives what it describes. `type: "general-error"` because the union has no success member and the sibling listener already uses it; no `errorCode`, because this is not an error.
  - `dedupKey: "sidecar-restarted"` so three crashes inside the breaker budget collapse into one toast with a count, matching `tests/client/notification-dedup.test.ts`'s contract.
  - Copy is not given in the issue; see `assumptions` / `bryan`.
  - **The call-site wiring itself stays unpinned**, and that is stated here so review does not read spec 3 as covering it: nothing asserts that the returned cleanup is actually handed to `onDestroy`, nor that the block sits inside `isTauriRuntime()`. Same shape as the sibling listener at `App.svelte:319-322`, which is likewise unpinned; pinning it would mean mounting `App.svelte`, which this PR does not take on.
- Rules that bite: the `push` closure runs from a Tauri event callback, **not** from a Tiptap handler and not inside a Svelte reaction, so `createCoalescingTick` is not needed — `notifications.push` is the same call the existing listener makes. No `localStorage`. No new colour (the toast reuses existing token-driven styles). **No new `data-testid`**, so `tests/design-system-impl/__snapshots__/testid-set.snap.txt` is untouched. No Y.Doc write, no MCP tool, no `/api` route, so Critical Rules 1, 2 and 9 are not engaged.

## Tests

`tests/client/sidecar-restart-toast.test.ts` (new, `// @vitest-environment happy-dom`, modelled on `tests/client/startup-rejection.test.ts`), driving `wireSidecarRestarted` with a fake `listen`:

1. **A delivered event pushes exactly one notification, and it is the module's own object.** Assert the value handed to the injected `push` — `severity === "info"`, `type === "general-error"`, `dedupKey === "sidecar-restarted"`, `message === SIDECAR_RESTARTED_MESSAGE`, `errorCode === undefined`. Because `buildSidecarRestartedNotification` produces it, this is the real payload and not a shape the test invented. Kills a wiring registered for the wrong event name, copy that drifts from the exported constant, and a severity or dedup change that would leave a recovery notice permanently in the activity tray.
2. **Two events push twice** — dedup is the toast layer's job, not this module's. Kills a "fire once then unlisten" implementation that would swallow the second crash in a breaker window.
3. **Cleanup unlistens, and an event delivered after cleanup pushes nothing.** Kills the leak the `cancelled` latch exists for, and the "listener resolved after destroy" race `wireStartupRejection` already guards. It does **not** cover the `onDestroy` registration in `App.svelte`; see the Fix note.
4. **A rejecting `loadEvent` warns and does not throw** (inject `warn`). Kills an unguarded `.then` chain that would produce an unhandled rejection in browser mode.

**Rust**, in `sidecar.rs`'s existing `crash_restart_tests` module (no new file):

- `#[test] fn sidecar_restarted_event_name_is_stable()` asserting `assert_eq!(EVENT_SIDECAR_RESTARTED, "sidecar-restarted")`, with a comment naming `src/client/utils/sidecar-restart-toast.ts`'s `SIDECAR_RESTARTED_EVENT` as the other half. Precedent: `startup_rejection.rs:522 open_failed_code_is_stable`.
- `#[test] fn only_a_crash_restart_announces_itself()` asserting `announces_successful_restart(RestartCause::PostBootCrash)` is `true` and `announces_successful_restart(RestartCause::UserInitiated)` is `false`. **Round-1 correction:** without it, an implementation that emits unconditionally from the `Ok(SpawnOutcome::Started)` arm passes every other test here and toasts "Tandem server restarted after a crash." when the user clicks Restart server in `NetworkSettings`. No `AppHandle` needed.

**Cross-language pin — an added case in an existing file, not new framework.** Add one `it()` to `tests/docs/startup-open-failure-wiring-claims.test.ts`, modelled on the existing `it("agrees with the client on the nudge event's name")` (`:324`):

- `rustSourceDefining(/const EVENT_SIDECAR_RESTARTED: &str/, "EVENT_SIDECAR_RESTARTED")`, match its literal, match `SIDECAR_RESTARTED_EVENT = "…"` in `src/client/utils/sidecar-restart-toast.ts` (stripped with the file's own `stripTsComments`), assert the two are equal.
- Assert the Rust `code` view matches `/\.emit\(EVENT_SIDECAR_RESTARTED/`, so the emit site passes the constant rather than a second literal.

**Round-1 correction:** the previous draft said "do not add a source-scanning guard for the emit; that is the framework the minimality rule forbids." That was factually wrong — the framework already exists, is already imported by that file, and its own in-test comment (`:326-331`) records that a Rust `assert_eq!` plus a client test asserting the client against itself is exactly the pair that lets the two sides desync silently while every toast stops arriving. Five added lines in a file that already does this for the sibling event is not new framework.

## Done when

A post-boot crash-restart that succeeds emits `sidecar-restarted`; a failed or declined one still emits only `sidecar-restart-failed`; a user-initiated restart emits neither, and `only_a_crash_restart_announces_itself` pins that; the four vitest specs, the two Rust tests and the added wiring-claims case pass; `docs/architecture.md:857` names the new surface; `npm run typecheck` (including `svelte-check`) and `cargo test` green; `bryan` carries the hardware smoke and the copy decision (including whether the deferred-recovery path should stay silent).

## Not in scope

Rewording the breaker-trip toast; any change to `CrashRestartDecision` or the breaker budget; extracting the existing `sidecar-restart-failed` listener out of `App.svelte`; pinning `App.svelte`'s `onDestroy` registration; `CHANGELOG.md`; `src/client/components/settings*` and `Settings*.svelte` (owned by W13t).
