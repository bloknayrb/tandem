## Problem

1. **Every settings-backed control outside the modal is a silent no-op after a downgrade.** `useTandemSettings.svelte.ts:92` is `if (settings._readOnly) return;` — the #659 defence that stops a downgraded client clobbering a newer blob. It returns `void`, so none of the **ten** `updateSettings(...)` call sites (`App.svelte:998,1016,2207,2293,2297,2314,2320`; `layout/model.svelte.ts:166,173,176`) can tell refused from applied. Only `SettingsModal.svelte:814` renders `SettingsReadonlyBanner`. Extends #1722.
2. **The integrations future-schema error becomes `{"error":"INTERNAL"}`.** `integrations/storage.ts:104-106` throws a precise message; all seven `sendInternal` callers (`api-routes.ts:518,575,608,662,809,1124,1186`) flatten it to a 500 with "Internal server error". The wizard is dead with no hint, and `checkAnnotationStore` (`doctor.ts:2766`) has no `integrations.json` counterpart.
3. **`welcome.md` is only ever copied when absent.** `copy_sample_files` (`lib.rs:2078`) gates each file on `if !dest.exists()` (`:2120`), so a desktop upgrader keeps the release-N sample forever. `injectTutorialAnnotations` anchors by `fullText.indexOf(def.targetText)` (`tutorial-annotations.ts:63-68`) and `console.error`s the miss, so changed target strings drop the tutorial for upgraders only. **The bundled half is already guarded** — `tests/server/tutorial-annotations.test.ts:81-118` pins the live `sample/welcome.md` against every target — and **npm installs are unaffected**, because `index.ts:718` reads `sample/welcome.md` from the package dir directly. Desktop-only, and invisible to CI by construction.
4. **The CHANGELOG stamp is written before the open is attempted.** `checkVersionChange` (`version-check.ts:31-34`) writes the version file *inside itself*, then `index.ts:692-697` attempts `openFromDisk(CHANGELOG.md)`. A failed open (missing bundle file) means that release's notes never open: the next start reads `current`. **The rest of item 4 is measured NOT live**: `CLAUDE.md`'s Files/Sessions gotcha already states the `if (transportMode === "http")` bound explicitly ("do not read either as unconditional"), and the "outside every launcher branch" comment the issue attributes to `apply.ts` is at `index.ts:657` and says *launcher* branch, which is true — `grep -n "launcher branch" src/server/integrations/apply.ts` returns nothing.

## Fix

**Item 1 — `src/client/hooks/useTandemSettings.svelte.ts`.** `updateSettings` returns `boolean` (`false` on the `_readOnly` short-circuit, `true` otherwise) — this is #1722's half, done once, here. Surface it **centrally, not per call site**: add a module-level `let onWriteRefused: (() => void) | null` plus `export function setSettingsWriteRefusedHandler(fn: (() => void) | null): void`, invoked from the short-circuit before returning `false`. `App.svelte` wires it once beside `const notifications = createNotifications()` (`:271`) to `notifications.push({ type: "general-error", severity: "warning", message: "…", dedupKey: "settings-readonly" })`. One wiring line covers all ten call sites; `useNotifications.svelte.ts`'s dedup collapses repeated clicks into a count badge instead of a toast storm. Message in **past tense** (`types.ts:646-654`) and it must name the cause: settings were written by a newer version of Tandem, so this one will not change them. **Do not** consume the boolean in `layout/model.svelte.ts` or skip `focusToggleTarget` — that is #1722's rail half and belongs to group **G6 rail seam** (wave 9, `#1719 #1716`); doing it here would collide. `createNotifications` is **not** a singleton, which is why the handler is a setter rather than an import.

**Item 2 — `src/server/integrations/storage.ts` + `api-routes.ts` + `src/cli/doctor.ts`.** Export `class IntegrationsFutureSchemaError extends Error` carrying `{ found: number; supported: number }`, thrown at `storage.ts:104`. Add the branch **inside `sendInternal` (`api-routes.ts:1199`)**, not at the seven call sites: `409` with `error: "CONFLICT"`, a stable `code`, and a message the response builds itself — `integrations.json was written by a newer Tandem (schemaVersion N; this build supports M). Update Tandem, or remove the integrations file.` **The thrown message's `${filePath}` must not reach the wire**: `GET /api/integrations/*` is LAN-reachable and CLAUDE.md's MCP/Server gotcha forbids resolved paths in those responses; the path stays in the `console.error` line `sendInternal` already writes. Model: `sendKeychainError` (`:1211`), which is the same shape one layer out. Then a `checkIntegrationsFile` recorder section in `doctor.ts` beside `checkAnnotationStore` (`:2766`): read `integrations.json`, and `r.warn` when its `schemaVersion` exceeds `INTEGRATIONS_SCHEMA_VERSION` (`shared/integrations/contract.ts`), mirroring the `futureActive` warn at `doctor.ts:2859-2864` in wording and remediation.

**Item 3 — `src-tauri/src/lib.rs`.** Extract the body of `copy_sample_files` into a pure `fn sync_sample_dir(src_dir: &Path, dest_dir: &Path, version: &str) -> Result<(), String>` (the `AppHandle` wrapper keeps only the two path lookups, so the logic is unit-testable). The rule, which refreshes **once per version, never per launch**: read `dest_dir/.tandem-sample-version`; if it equals `version`, keep today's `if !dest.exists()` behaviour exactly and return. Otherwise, for each bundled file whose bytes differ from the on-disk copy, move the on-disk copy to `<file-name>.pre-<version>.bak` and write the bundled bytes; then write the marker. A user edit made *after* an upgrade survives until the next upgrade, and is preserved as a `.bak` even then. The model is `version-check.ts`'s `last-seen-version` stamp — name it in the doc comment. `.tandem-sample-version` and `*.bak` are inert to everything that reads that directory (`index.ts:718` joins one fixed name). **Lesson 2:** this compiles on all three targets by construction (`std::fs` only, no `cfg`), and the three CI `rust-test` legs are what actually execute it — a local Windows `cargo test` is not sufficient evidence.

**Item 4 — `src/server/version-check.ts` + `index.ts`.** Split the write out: `checkVersionChange` becomes read-only and a new `stampVersion(currentVersion, versionFilePath)` performs the `mkdir` + `writeFile`. `index.ts:692-697` calls `stampVersion` **after** a successful `openFromDisk`, and also on `first-install` (where no open is attempted) — otherwise every launch reports `first-install`. A repeatedly-failing open now retries each launch and logs each time, which is the intended trade. Also change the log line at `:695` from "upgraded to vX" to a version-change-neutral wording: a *downgrade* opens the running build's own `CHANGELOG.md`, which is the correct document for the version now running, so the content is right and only the word is wrong — no semver comparator. **No behaviour change to the `transportMode === "http"` bound**: making stdio refresh skills is a behaviour change no issue asks for. Refresh `CLAUDE.md`'s stale `src/server/index.ts:591` citation to `:655` in the auto-open/skill-refresh bullet — **and touch nothing else in `CLAUDE.md`**, because PR #1979 is open against its security-findings bullet.

## Tests

1. `tests/client/` (new or beside `use-tandem-settings-migration.test.ts`): with `_readOnly: true`, `updateSettings({theme:"dark"})` returns `false`, localStorage is untouched, **and** the registered refusal handler fired exactly once; with `_readOnly` absent it returns `true` and the handler does not fire. Kills a fix that returns the boolean but never surfaces it, and one that toasts on every write.
2. `tests/server/integrations/` (beside the storage suite): a `schemaVersion`-too-new file makes `store.read()` reject with `IntegrationsFutureSchemaError`; driving that error through `sendInternal` yields **409**, a body whose `message` names both numbers, and **no substring of the file path** — that last assertion is the one that kills the naive `message: err.message` fix.
3. `tests/cli/doctor.test.ts`: a future-schema `integrations.json` produces a warn row; a current one does not.
4. `src-tauri/src/lib.rs` `#[cfg(test)]` with `tempfile` (already a dev-dependency), four cases: fresh dest copies and writes the marker; **same marker version leaves a user-edited file untouched** (kills an unconditional overwrite); a bumped marker refreshes an untouched file; a bumped marker with an edited file writes `<name>.pre-<version>.bak` **and** the new bytes (kills a fix that silently discards the edit).
5. `tests/server/changelog-on-update.test.ts`: migrate the six existing specs to the read/stamp split, and add the discriminating one — `checkVersionChange` alone leaves the version file **unwritten**, so a failed open still reports `upgraded` on the next call. That case is the whole point of item 4 and no existing spec covers it.
6. Mutation-test each (lesson 5): revert the `stampVersion` move, the `sendInternal` branch, the marker check and the refusal handler in turn, and name the test that goes red for each. Restore from a file copy, never `git checkout`.
