## Problem

Since #1757, `makeStdinGoneHandler` (:439) SIGTERMs a live child whose stdin errors, and the exit handler calls `scheduleRestart()` (:1304). If every replacement has the same broken stdin, the loop never trips at a cadence of one wake per 30 s or slower:
- The rolling breaker window (10 attempts in 5 min) never fills.
- `restartIndex` resets after 30 s alive.
- `status()` reports `running: true` between kills.

Before #1757 the throw reached `captureFatal` (opt-in Sentry). Now the only trace is a `console.error` line.

## Fix

1. **Counter.** In `createSupervisor`, add `let deliveryKillStreak = 0;` and `const DELIVERY_KILL_LIMIT = 3;`. The docblock says it counts consecutive kills with no time window, and that 3 means the same failure on three successive children.
2. **Count once per spawn, and only for a kill we issued.**
   - `makeStdinGoneHandler(spawned, isCurrent, onKill?)` calls `onKill?.()` inside its existing guards (the liveness check is at :459), immediately before `spawned.kill("SIGTERM")`.
   - In `spawnOnce`, add a per-spawn `let killedForDelivery = false;` and `function markDeliveryKill(): void { killedForDelivery = true; }`. Declare both above the binding at :977, which becomes `const onStdinGone = makeStdinGoneHandler(spawned, () => child === spawned, markDeliveryKill);`.
   - The exit handler does the counting. Real Node sets `signalCode` only at exit, so a second `'error'` or a G1-1867 receipt timeout can call `onKill` again before exit. The per-spawn boolean still counts that spawn once, which covers criterion 7.
3. **Trip.** In `spawned.on("exit")`, between `if (stopRequested) return;` (:1302) and `scheduleRestart()`:
   ```ts
   if (killedForDelivery && ++deliveryKillStreak >= DELIVERY_KILL_LIMIT) {
     breakerTripped = true;
     // Same guarded, fail-open probe as scheduleRestart's trip: a missing CLI (exit 127)
     // can have its stdin error land before Node records the exit; route that to Setup.
     let cliUsable = true;
     try { cliUsable = probeCliUsable(); } catch (err) { console.error("[Launcher] CLI probe failed; reporting a wake-delivery failure:", err); }
     lastError = cliUsable ? "wake-delivery-failed" : "cli-unusable";
     console.error(cliUsable
       ? `[Launcher] Claude was ended ${deliveryKillStreak} times in a row because it stopped accepting turns — giving up. Restart Claude Code to retry.`
       : "[Launcher] Claude kept failing to accept turns and the Claude CLI is missing or cannot be started — check the integration setup.");
     if (cliUsable) reportDeliveryTrip(DELIVERY_TRIP_REPORT);
     return;
   }
   ```
   Setting `breakerTripped` reuses every existing gate: `startInternal`, `scheduleRestart`, and relaunch via the client's Restart CTA.
4. **Reset** `deliveryKillStreak = 0` in two places:
   - In `handleStdoutLine`'s `result` branch, beside `clearLatch()` (:1196). This reset is deliberately not applied to other envelopes: `init` proves receipt, not completion.
   - In `respawn`, beside `breakerTripped = false; recentAttempts = [];` (:1485).
5. **Contract.** `LauncherErrorCode` (`contract.ts:106`) gains `"wake-delivery-failed"`. Its docblock says the child kept refusing turns and the remedy is to restart. There is no client change, because `useAiReadiness`'s `chip` (:723-733) already maps any stopped `lastError` other than `cli-unusable` to `restart`.
6. **Durable telemetry (criterion 4), through the existing opt-in path only.**
   - `SupervisorOpts.reportDeliveryTrip?: (message: string) => void`, defaulting to a no-op. `supervisor.ts` does not import `sentry.ts`, because that module imports `./mcp/server.js`.
   - `const DELIVERY_TRIP_REPORT = "launcher: wake delivery failed on consecutive sessions";`. The string is fixed, with no path, id, count or content.
   - `sentry.ts` gains `export function captureWarning(message: string): void { if (!sentry) return; try { sentry.captureMessage(scrub(message), "warning"); } catch {} }`. Update the header sentence at :21 ("We only ever capture `Error`s…") to name this warning.
   - `index.ts`: widen the `./sentry.js` import (:63) and pass `reportDeliveryTrip: captureWarning` at `createSupervisor({` (:138).
   - `docs/security.md` :172: "…and Node uncaught exceptions (sidecar)" becomes "…Node uncaught exceptions plus one fixed-string warning when the launcher gives up on a Claude session that stopped accepting turns (sidecar)". Run `tests/docs/` afterwards.
   - With `TANDEM_SENTRY_DSN` unset, `sentry` is `null`, so nothing new leaves the machine.

## Tests

These go in the shared file and use the G1-1866 harness. Each test injects `reportDeliveryTrip: vi.fn()`. A "delivery kill" means `failWrite(child)` on a live child. Its session is kept, so the successor resumes and its owed `[WAKE]` is the next write to fail.

1. **Slow cadence trips.** Use `vi.useFakeTimers({ toFake: ["Date"] })`. Delivery-kill children 1–3, with `vi.setSystemTime(Date.now() + 11 * 60_000)` between them; 11 min is above both the 5-min breaker window and the 10-min latch. Assert:
   - `status()` is `{ running: false, lastError: "wake-delivery-failed" }`;
   - `spawn` was called 3 times;
   - `reportDeliveryTrip` was called once with the fixed string.
2. **Fast cadence** trips at the same count with no clock advance.
3. **Healthy delivery resets the streak.**
   - Delivery-kill children 1 and 2.
   - Child 3 receives `[WAKE]`, pushes `init` then `result`, then `exitChild(child3, 1)`. That is an ordinary crash within `RESUME_CONFIRM_MS`, so child 4 is fresh.
   - Delivery-kill children 4 and 5. Child 6 spawns and is running, with no `lastError`.
   - **3b.** Same as 3, except child 3 pushes only `init` and is then delivery-killed. The trip happens at child 3.
4. **No double count within one spawn.** For children 1 and 2, in order:
   - run `failCallbacksOnly(all held)`;
   - set `stdin.writable = false`;
   - emit `stdin` `"error"` twice, synchronously, before the deferred `exit`.

   Child 3 receives `[WAKE]` and stays alive. It is running, with no `lastError`.
5. **Ordinary exits are distinct, and the missing-CLI race routes to Setup.**
   - **5a.** Three children exit via `exitChild(child, 1)` with no stdin error. `lastError` is not `wake-delivery-failed`, and restarts continue.
   - **5b.** Use `probeCliUsable: () => false`. For three children, synchronously:
     - run `failCallbacksOnly`;
     - set `writable = false`;
     - emit `"error"` while `exitCode` is null, so `kill` is called;
     - then `exitChild(child, 127)` before the deferred signal exit.

     Assert `lastError === "cli-unusable"` and that `reportDeliveryTrip` was not called.
6. **User relaunch resets.** After test 2's trip, call `relaunch(dir)`. One more delivery kill does not trip.

`supervisor.test.ts`, `makeStdinGoneHandler` units:
- `onKill` runs before `kill` for a current live child.
- It is not called for a superseded child (`isCurrent: () => false`).
- It is not called for a child already exited (`exitCode: 127`).
