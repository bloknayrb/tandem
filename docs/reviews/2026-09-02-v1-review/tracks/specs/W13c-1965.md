## Problem

`src/client/hooks/useTutorial.svelte.ts:113-121` — the step-1 effect (the "Ask a question" step,
`OnboardingTutorial.svelte`'s `BASE_STEPS[1]`, displayed as step 2) advances on one condition only:

```ts
if (annotations.some(isNonTutorialUserAnnotation)) { … currentStep = 2; }
```

The step's own copy and `docs/user-guide.md`'s quick-tour item 2 ("Or type in the Chat panel.") both say
sending a chat message also completes it. A user who only uses Chat during that step is stuck: nothing
advances, and nothing explains why.

## Fix

The issue's own shape — a fourth getter, matching the three already there. Three files.

**`src/client/hooks/useTutorial.svelte.ts`:**
- `createTutorial(getAnnotations, getEditor, getActiveTabFileName, getChatMessages)` — a fourth parameter
  `getChatMessages: () => ChatMessage[]`, typed from `../../shared/types`. **A getter, not a value**, for the
  reason `rail-content.svelte.ts:39-46` spells out: a by-value capture freezes at mount, and
  `chatState.messages` is `[]` then, so a frozen read makes the branch permanently dead.
- Extend the step-1 effect's condition, **time-scoped against `stepAdvancedAt`**:

  ```ts
  if (
    annotations.some(isNonTutorialUserAnnotation) ||
    getChatMessages().some((m) => m.author === "user" && m.timestamp > stepAdvancedAt)
  )
  ```

  **The `m.timestamp > stepAdvancedAt` term is required, not a refinement.** Chat is durable and app-global:
  `src/server/session/manager.ts:713-827` snapshots and restores `Y_MAP_CHAT`, `useChatState.svelte.ts:41`
  repopulates `messages` from the ctrl Y.Doc on connect, and `ChatMessage.documentId` is optional
  (`src/shared/types.ts:676`), so the array is not document-scoped either. `restartTutorial` (`:167-172`)
  resets only `currentStep`/`stepAdvancedAt`/`completed` — it cannot clear chat history. Without the
  timestamp term, every tutorial replay and any first run against a server with prior chat would see the
  step-0 effect advance to 1 and the chat term already true, advancing to 2 in the same flush: "Ask a
  question" silently auto-skips, which is #1965's own failure inverted. `stepAdvancedAt` is stamped on entry
  to step 1 at `:107-108` (and reset to `0` by `restartTutorial`), and `ChatMessage.timestamp` is a required
  `number` (`types.ts:675`). It is a plain `let`, not `$state`, so reading it adds no dependency — the effect
  still re-runs off `getChatMessages()`/`getAnnotations()`.

  This is a code decision, not a product one, so #1965 stays a closer: the intended behaviour is stated by
  the step's own copy (an action taken *during* the step), and the annotation term is already effectively
  time-scoped because a *new* user annotation is what satisfies it.

  The `stepAdvancedAt = Date.now()` / `currentStep = 2` body is unchanged — the step-2 editor handler's
  2-second guard (`:131`) depends on that stamp being refreshed by either route. `||` short-circuits, so the
  chat getter is evaluated only when the annotation term is false, which is the only case where it can decide
  anything; the effect self-disqualifies on `currentStep !== 1` after either advance.
- **Required, not optional:** a call site that forgets the argument must be a compile error.
  `npm run typecheck:tests` catches the one test caller below.

**`src/client/App.svelte:2186-2190`:** pass `() => chatState.messages` as the fourth argument. `chatState` is
created at `:1966` and exposes `messages` as a getter over `$state` (`useChatState.svelte.ts:41,196-198`), so
the thunk reads live state; it is declared above the `createTutorial` call.

**`tests/client/use-tutorial-restart.svelte.test.ts:39-43`:** add `() => []` as the fourth argument. That
test never reaches step 1, so an empty-array stub is sufficient.

Rules that bite: **no Tiptap event handler is involved** — this reads `$state` inside an existing `$effect`,
so `createCoalescingTick` does not apply and adding it would defer the advance for no reason. ChatPanel stays
always mounted (nothing here touches mounting). No `data-testid`, no Y.Doc write, no colour, no skill edit.

## Tests

`tests/client/use-tutorial-chat-advance.svelte.test.ts` (new `.svelte.test.ts` — the runes need the Svelte
compiler; `use-tutorial-restart.svelte.test.ts:22-27` is the harness precedent: `$effect.root` + `flushSync` +
`happy-dom` for `localStorage`, with `localStorage.clear()` in `afterEach`).

Drive to step 1 the way the hook does: `getActiveTabFileName` returns `"welcome.md"`, and the annotation stub
first returns one **resolved** tutorial seed (id prefixed with `TUTORIAL_ANNOTATION_PREFIX` from
`src/shared/constants`, `status !== "pending"`) so the step-0 effect advances to 1. Then swap the stubs and
`flushSync()`. Every chat message stub carries a `timestamp`; advancing ones are stamped **after** the step-0
advance (e.g. `Date.now() + 1000`, or captured from a `vi.setSystemTime` clock).

1. **The discriminating spec.** At step 1, `getChatMessages` returns one `{ author: "user", timestamp: <after
   the advance> }` and `getAnnotations` returns **only the resolved seed** → `currentStep` becomes 2. Kills
   today's code, and any fix that ORs the chat term into the wrong step's effect.
2. **Claude-authored messages do not advance.** One `{ author: "claude" }`, no user annotation → still step
   1. Kills `chatMessages.length > 0`, which would advance the instant seeded Claude traffic arrives.
3. **The annotation route still works.** No chat messages, one non-tutorial user annotation → step 2. Kills
   a fix that replaces the annotation term instead of adding to it.
4. **Empty chat, empty annotations → holds at step 1.** The negative that stops `return true`-shaped
   regressions and pins that the step does not auto-skip.
5. **A pre-existing chat message does not advance the step.** At step 1, `getChatMessages` returns one
   `{ author: "user", timestamp: <before the step-1 stamp> }` and no user annotation → still step 1. Pins the
   timestamp term: without it this is the replay case that silently skips "Ask a question" for every user
   with any chat history. Cleanest construction: `vi.useFakeTimers()` with the message stamped before the
   step-0 advance.
