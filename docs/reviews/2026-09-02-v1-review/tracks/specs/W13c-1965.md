# W13c — #1965 Tutorial step 2 has no chat-only advance branch (#1824 item M)

`docs/reviews/2026-09-02-v1-review/areas/product.md:26` (the L row ending "tutorial step 2 has no AI-absent
branch"). Probe: the new hook spec below, which is the issue's own stated test.

## Problem

`src/client/hooks/useTutorial.svelte.ts:113-121` — the step-1 effect (the "Ask a question" step,
`OnboardingTutorial.svelte`'s `BASE_STEPS[1]`, displayed as step 2) advances on one condition only:

```ts
if (annotations.some(isNonTutorialUserAnnotation)) { … currentStep = 2; }
```

The step's own copy and `docs/user-guide.md`’s quick-tour item 2 ("Or type in the Chat panel.") both say sending a chat message also completes it. A user
who only uses Chat during that step is stuck: nothing advances, and nothing explains why.

## Fix

The issue's own shape — a fourth getter, matching the three already there. Three files.

**`src/client/hooks/useTutorial.svelte.ts`:**
- `createTutorial(getAnnotations, getEditor, getActiveTabFileName, getChatMessages)` — a fourth parameter
  `getChatMessages: () => ChatMessage[]`, typed from `../../shared/types` (the same module `Annotation`
  comes from in this file). **A getter, not a value**, for the reason `rail-content.svelte.ts:39-46`
  spells out at length: a by-value capture freezes at mount, and `chatState.messages` is `[]` then, so a
  frozen read would make this branch permanently dead — a fix that compiles, ships, and does nothing.
- Extend the step-1 effect's condition:
  `if (annotations.some(isNonTutorialUserAnnotation) || getChatMessages().some((m) => m.author === "user"))`.
  Both terms are read inside the effect so both are tracked. The `stepAdvancedAt = Date.now()` /
  `currentStep = 2` body is unchanged — the step-2 editor handler's 2-second guard
  (`:131`) already depends on that stamp being refreshed on every advance, by either route.
- **Required, not optional:** a call site that forgets the argument must be a compile error, not a silent
  regression to today's behaviour. `tests/scripts/typecheck-tests-wiring.test.ts` keeps `tests/` typechecked,
  so the one test caller below is caught by `npm run typecheck:tests`.

**`src/client/App.svelte:2186-2190`:** pass `() => chatState.messages` as the fourth argument.
`chatState` is created at `:1966` and exposes `messages` as a getter over `$state`
(`useChatState.svelte.ts:41,196-198`), so the thunk reads live state. It is declared above the
`createTutorial` call, so no reordering is needed.

**`tests/client/use-tutorial-restart.svelte.test.ts:39-43`:** add `() => []` as the fourth argument. That
test never reaches step 1 (it asserts `tutorialActive` and `currentStep === 0` around `restartTutorial`), so
an empty-array stub is sufficient — the issue says so and the source confirms it.

Rules that bite: **no Tiptap event handler is involved** — this reads `$state` inside an existing `$effect`,
not from a ProseMirror dispatch, so `createCoalescingTick` does not apply and adding it would defer the
advance for no reason. ChatPanel stays always mounted (unchanged — nothing here touches mounting). No
`data-testid`, no Y.Doc write, no colour, no skill edit.

## Tests

`tests/client/use-tutorial-chat-advance.svelte.test.ts` (new `.svelte.test.ts` — the runes need the Svelte
compiler; `use-tutorial-restart.svelte.test.ts:22-27` is the harness precedent: `$effect.root` + `flushSync`
+ `happy-dom` for `localStorage`, and `localStorage.clear()` in `afterEach`).

Drive to step 1 the way the hook itself does: `getActiveTabFileName` returns `"welcome.md"`, and the
annotation stub first returns one **resolved** tutorial seed (id prefixed with `TUTORIAL_ANNOTATION_PREFIX` from `src/shared/constants`,
`status !== "pending"`) so the step-0 effect advances to 1. Then swap the stubs and `flushSync()`.

1. **The discriminating spec.** At step 1, `getChatMessages` returns one `{ author: "user" }` message and
   `getAnnotations` returns **only the resolved seed** (no user annotation) → `currentStep` becomes 2.
   Kills today's code, and kills any fix that ORs the chat term into the wrong step's effect.
2. **Claude-authored messages do not advance.** One `{ author: "claude" }` message, no user annotation →
   still step 1. Kills `chatMessages.length > 0`, which would advance the instant the seeded welcome/Claude
   traffic arrives and make the step un-completable-by-doing.
3. **The annotation route still works.** No chat messages, one non-tutorial user annotation → step 2. Kills
   a fix that replaces the annotation term instead of adding to it.
4. **Empty chat, empty annotations → holds at step 1.** The negative that stops `return true`-shaped
   regressions and pins that the step does not auto-skip.
5. **The getter is live, not frozen.** Construct with a thunk over a mutable array that is empty at
   construction, push a user message afterwards, `flushSync()` → advances. Kills the by-value capture the
   fix's comment warns about — without this spec, `createTutorial(…, chatState.messages)` (no arrow) would
   pass specs 1–4 written with a pre-filled array and still be dead in the app.
