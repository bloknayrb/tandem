# W13m — #2039 a mid-turn Y.Doc swap suppresses the local-model turn's terminal effects but does not abort the turn

Branch `fix/local-model-abort-on-doc-swap-2039`. Closes #2039 (references nothing else). Ledger: `docs/plans/2026-09-06-open-issues-sweep.md:118` (NOT-scheduled row, now scheduled) and the settled decision at `:1281`. Probe: none — the path is dark; the repro is the existing `swapDoc()` / `swapMidTurn()` helpers in `tests/server/local-model/collaborator.test.ts:151,687`.

Bryan settled the design on 2026-09-17 (issue comment, and sweep decision 2): **abort the turn, and make it visible. Do not re-resolve.** This spec implements exactly that and reopens nothing.

## Problem

`executeRun` (`src/server/local-model/collaborator.ts:335-342`) gates every *terminal* effect on `stillOwner()`, whose third conjunct `requireDocument(req.docName)?.doc === ydoc` is false after a Hocuspocus Y.Doc swap (#1657). But the turn itself keeps running: `executeRun` is parked in `await deps.runTurn({ ydoc, ... })` and `runLoop` keeps dispatching tool calls against the **captured, destroyed** `ydoc`.

Correction carried from Bryan's comment, because it decides the mechanism: those writes **succeed** — `Y.Doc.destroy()` clears neither `share` nor `_start` and `transact` has no destroyed guard. They are invisible only because both observers were detached synchronously during the swap (`events/queue.ts:511-512`, `events/file-sync-registry.ts:124-137`), so the record lands in an orphan and never reaches disk. **Nothing throws, so no post-hoc detection is possible — the check must be positive.**

A swap is a browser connecting/reconnecting to a room Hocuspocus is not holding (`yjs/provider.ts:295`, the only instance replacement in `src/server`), and `provider.ts:288-289` merges the old state in before `destroy()`, so the fresh doc is content-identical. Abort wins anyway: after a swap the final chat flush is already suppressed, so a continuing turn half-delivers — annotations land, the reply does not.

## Fix

Three source files, one predicate threaded one level, one new exit member, one sibling notification branch — plus two test files and one ledger row.

1. **`src/server/local-model/loop.ts`**
   - `LoopMetrics.exit` gains `"doc-swapped"` (union only; no exhaustive `switch` exists on it — `collaborator.ts` is an `if/else` chain, and `loop.test.ts`/`collaborator.test.ts` are the only other referents). Its doc comment gains one sentence, because the member name is narrower than the condition it records: **"`doc-swapped` means the run's captured Y.Doc is no longer the room's live instance — a Hocuspocus swap, or the document being untracked; the collaborator distinguishes the two before notifying."**
   - `RunLoopOpts` gains `isDocCurrent?: () => boolean` — "still the same Y.Doc instance this run captured". Omitted ⇒ treated as `true`, so every library/test caller is byte-identical.
   - One call site, in the turn body **immediately after** the existing post-await abort re-check (`loop.ts:204-207`) and **before** the `res.toolCalls.length === 0` branch:
     ```ts
     if (opts.isDocCurrent && !opts.isDocCurrent()) {
       metrics.exit = "doc-swapped";
       break;
     }
     ```
     Placement is the whole fix and each half of it is load-bearing:
     - **Post-await, pre-dispatch** is the only interleave point inside a turn — `dispatch` is synchronous (`loop.ts:231`) — and it is the only point a **tool-only turn reaches at all**. Hanging detection off the streaming sink's `write()` is the mechanism that was cut from #1657 for exactly that reason. A top-of-loop placement would leave the real shape (the swap lands *during* the await, so this turn's tool calls dispatch onto the destroyed instance) unfixed, which is why tests 1–3 flip the predicate mid-await rather than starting it false.
     - **Before the no-tool-calls branch**, so a final-answer turn also exits `doc-swapped` instead of `clean` and cannot hand the collaborator a reply to flush.
     - **After** the abort check, so an abort that has already propagated still reports `aborted` and raises no swap notification.
     - The break precedes `opts.onTurnEnd?.(...)`, which is **deliberate**: no terminal flush follows a `doc-swapped` exit, so the sink needs no turn boundary here, and the pending flush timer is released by `sink.dispose()` in the collaborator's existing `finally`.
   - **Plain `break` + exit member. Do NOT call `ctx.abort.abort()`** — `sink.isOwner()` includes `!abort.signal.aborted`, and an abort landing between the `truncated` latch and its scheduled write strands #1292's marker. (The constraint is about aborting at all, not about placement relative to the latch.)
   - No Y.Doc write is added anywhere, so Critical Rule 2 has nothing to tag here. Confirmed at the other end too: `pushNotification` is an in-memory ring buffer plus subscriber fan-out (`src/server/notifications.ts:14-32`), with no `transact` on the path — the build stage need not re-litigate this.
2. **`src/server/local-model/index.ts`** — `RunTurnOpts` gains the same optional `isDocCurrent` and `runLocalModelTurn` forwards it to `runLoop`. Pure passthrough, but it is the **only** line that makes `doc-swapped` reachable in production (`runLocalModelTurn` hand-enumerates every forwarded field and TypeScript cannot object to an omission of an optional one), so test 5 exists to pin it.
3. **`src/server/local-model/collaborator.ts`**
   - Extract the identity conjunct so the loop and `stillOwner` cannot drift: `const docUnchanged = () => requireDocument(req.docName)?.doc === ydoc;` defined **below** `const ydoc = open.doc` (it closes over `ydoc`; the TDZ ordering fact #1657 recorded applies unchanged), and `stillOwner()` becomes `current?.token === token && !abort.signal.aborted && docUnchanged()`. The comment block explaining the identity test stays.
   - Pass `isDocCurrent: docUnchanged` into the `deps.runTurn({...})` call.
   - **The visible half sits OUTSIDE `if (stillOwner())`** (`collaborator.ts:365`) — this is the trap Bryan named: `stillOwner()` is false after a swap *by construction*, so a `doc-swapped` arm inside that block is dead code and the abort ships silent, reproducing this bug. Make it a sibling branch in front — **and gate only the notification (not the exit) on the room still being tracked**, because `docUnchanged()` is *also* false for a CLOSED document (`requireDocument` returns null once `closeDocument` drops the `openDocs` row, `registry.ts:301-309,354-364`), and in production a close does **not** arrive as `aborted`: the collaborator's close-abort depends on `document:closed`, which #2069 records as never firing (`events/observers/ctrl-meta.ts:66` skips the `withInternal` broadcast origin). A bare arm would therefore tell a user who just closed a tab that the document "reconnected", with a remedy no retry can satisfy, where today that path is silently dropped:
     ```ts
     if (result.metrics.exit === "doc-swapped") {
       // A null lookup means the document is CLOSED, not swapped — that inherits
       // the existing silent-drop contract (#2069: close never arrives as an abort).
       if (requireDocument(req.docName)) {
         pushNotification({
           id: generateMessageId(),
           type: "general-error",
           severity: "warning",
           message:
             "The local model stopped: this document reconnected mid-turn, so it stopped early — any comments it already added are still there, but its reply was not delivered. Ask again to continue.",
           documentId: req.docName,
           timestamp: Date.now(),
         });
       }
     } else if (stillOwner()) { /* existing clean/budget/timeout/error arms, unchanged */ }
     ```
     The **abort itself is unchanged in both cases** — a run must not keep dispatching into a doc the registry dropped. Only the message is suppressed on close.
     The copy is deliberately narrower than "the rest of its work was discarded": `provider.ts:285-295` merges the old state into the fresh doc before `destroy()`, so annotations written by turns that completed *before* the swap survive; only the terminal reply is dropped.
     The arm deliberately carries **no ownership/token test**. A run that is both superseded and swapped can therefore notify while a newer run is already in flight; that is judged better than the dead-code failure Bryan named, and it is recorded here so a later reader does not "tidy" `current?.token === token` back in and silently re-create it.
     `pushNotification` is already imported (`:39`) and bypasses the sink, so it is unaffected by the sink's presence-based `isOwner()`. **No `sink.flushFinal()` on this branch** — dropping the terminal reply is #1657's guarantee and stays. `sink.dispose()` in the existing `finally` still runs.
   - The sink is **not** touched: it writes only to `CTRL_ROOM`, which a document-room swap never touches (#1657's recorded divergence).
4. **`docs/plans/2026-09-06-open-issues-sweep.md`** — strike #2039 from the NOT-scheduled row at `:118` (leaving #2041 and #2037, and dropping its "awaiting Bryan's design call" sentence) and add the wave-13 `W13m` status row. `tests/docs/sweep-ledger-table-claims.test.ts` checks column counts only, so this prose would otherwise stay green while claiming a decision is still owed after the PR closes the issue.

Dark guarantee: `startLocalModelCollaborator()` still early-returns on `BYO_MODELS_ENABLED` (`src/shared/constants.ts`, literal `const false`). The flag is not flipped, no UI surface is added or documented, `config-source.ts` is untouched.

## Tests

Ten cases. `tests/server/local-model/loop.test.ts`, new `describe("runLoop — mid-turn doc swap (#2039)")`, in the shape of the existing abort describe at `:129` (stubbed `fetch`, real Y.Doc from `makeMarkdownDoc`). **Cases 1–3 must flip `isDocCurrent` DURING the first `await chat()`, never start it false** — a statically-false predicate is satisfied by a top-of-loop placement (it breaks before `chat()` and yields `turns === 0`, `toolCalls === 0`, an empty annotation map and `exit === "doc-swapped"`), so it would leave the post-await placement — "the whole fix" — pinned by nothing. The discriminating shape already exists at `loop.test.ts:138-155`, where the fetch stub flips the abort flag mid-await.

1. **Tool-only turn**: `let swapped = false; const isDocCurrent = () => !swapped;` and a `fetch` stub that sets `swapped = true` and then resolves `v1ToolCallArgs("comment_on_quote", { quoted_text: "body text here", comment: "x" })`. Assert `exit === "doc-swapped"`, `metrics.turns === 1`, `metrics.toolCalls === 0`, `getAnnotationsMap(opts.ydoc).size === 0`, `fetchMock` called once. *Kills:* any detection hung off `onContentDelta`/the sink (a tool-only turn produces no content), **and** a check placed only at the top of the loop — under that mutant turn 1 dispatches, so `toolCalls === 1` and one annotation lands.
2. **Final-answer turn**: same mid-await flip, stub resolves `v1Text("the reply")`. Assert `exit === "doc-swapped"`, `turns === 1`, `finalContent === ""`. *Kills:* a check placed after the `toolCalls.length === 0` branch, which reports `clean` and hands the collaborator a reply to flush; and, via the flip, the top-of-loop placement again.
3. **Omitted predicate**: same stub, no `isDocCurrent`. Assert `exit === "clean"`. *Kills:* a required arg or a falsy-default that would break every existing caller and silently abort real turns.
4. **Abort precedence**: the abort must land **during** `chat()`, not before it — an already-aborted signal breaks at the top-of-loop guard (`loop.ts:167-171`, `turns === 0`) and never reaches either post-await check, so it cannot pin their order and merely duplicates the existing case at `loop.test.ts:130-136`. Use a `fetch` stub that calls `controller.abort()`, flips `swapped = true`, and then resolves a mutating tool call, with `signal: controller.signal` and `isDocCurrent: () => !swapped`. Assert `exit === "aborted"`, `turns === 1`, `toolCalls === 0`. *Kills:* ordering the swap check above the post-await abort re-check — that mutant reports `doc-swapped`.
5. **The production entry point forwards the predicate**: in the same file, call `runLocalModelTurn({ ydoc, config: CONFIG, task: "go", isDocCurrent: () => false })` with a tool-call stub; assert `metrics.exit === "doc-swapped"` and `metrics.toolCalls === 0`. *Kills:* omitting the `isDocCurrent` line from `index.ts`'s hand-enumerated forward, which leaves the fix completely inert in production while cases 1–4 (which call `runLoop` directly) and case 10 (which stubs `deps.runTurn`) all stay green.
6. **Source-text guards for the two hand-checked Done-when clauses** (the repo's `tests/docs/*-claims.test.ts` shape): read `src/server/local-model/loop.ts` and assert `/metrics\.exit = "doc-swapped"/g` matches exactly once; read `src/server/local-model/collaborator.ts` and assert no `abort.abort()` appears inside `executeRun`. The second guards a real silent regression (an abort between the `truncated` latch and its scheduled write strands #1292's marker, via the sink's presence-based `isOwner()` at `collaborator.ts:420-424`).

`tests/server/local-model/collaborator.test.ts`, extending the `#1657` describe (reusing `swapDoc`/`swapMidTurn`) with a `swappedResult()` factory beside `cleanResult`/`limitResult`:

7. **The notification is pushed although `stillOwner()` is false**: `deps.runTurn` resolves a result with `exit: "doc-swapped"` after the doc is swapped mid-turn; assert `getBuffer().filter(n => n.documentId === id)` holds exactly one `severity: "warning"` entry **and** that its `message` matches `/reconnected/` — without the message assertion a regression pushing the budget-exhausted copy ("reached its step limit", `collaborator.ts:376-382`) stays green, and that misleading copy is the failure mode this issue is about. *Kills:* the obvious implementation that puts the arm inside `if (stillOwner())` — the buffer would be empty. This is the discriminating test for the whole issue and is the mutation target.
8. **A CLOSED document notifies nothing**: same `swappedResult()` run, but `removeDoc(id)` (registry row dropped) instead of `swapDoc(id, ...)`; assert `getBuffer().filter(n => n.documentId === id)` is empty. *Kills:* re-merging swap and close into one unconditional arm, which tells a user who closed a tab that it "reconnected". `swapDoc` deliberately leaves the registry row in place (`collaborator.test.ts:146-153`), so 7 and 8 genuinely separate the two.
9. **No terminal reply on either path**: same run as 7; assert no finalized chat message is minted (same assertion shape as the existing `:714` arm). *Kills:* a fix that "makes it visible" by also flushing, undoing #1657.
10. **The predicate is really wired**: a `deps.runTurn` that captures its opts; assert `typeof captured.isDocCurrent === "function"` first, then `captured.isDocCurrent!()` is `true` before `swapDoc(...)` and `false` after. The explicit `typeof` check is what stops a later tidy-up to `toBeFalsy()` from silently accepting "not threaded at all" (`opts.isDocCurrent?.()` is `undefined` when the field is absent). *Kills:* adding the exit member without threading `isDocCurrent` at the collaborator seam.

Both files honour the existing microtask timing rule in `swapMidTurn` (the swap must land with only microtasks between the delta push and the swap).

## For `bryan` (PR body)

- **#2070 gets cheaper, not harder**: the `isDocCurrent` thunk is exactly the seam a content-generation check would need, evaluated once per turn post-await/pre-dispatch. It is still invisible to an *identity* predicate, so #2070 is untouched by this PR.
- **#2069 is partially side-stepped, not fixed**: because `docUnchanged()` answers false for an untracked document, a run whose document is closed mid-turn now stops at the next turn boundary even though `document:closed` never fires. The event-queue defect itself is upstream in `events/observers/ctrl-meta.ts:66` (the `shouldSkipChannel` origin skip over `broadcastOpenDocs`'s `withInternal` write) and this PR does not touch it — a close still does not abort the in-flight `chat()` and still reports `doc-swapped` rather than `aborted`. Widening the same predicate is, however, the cheap shape if that is the direction chosen.
- **Pre-existing (#1657 class), now newly observable**: `provider.ts:288-303` re-applies merged state and calls `documents.set(...)` *before* `lifecycle.onDocSwapped(...)` reattaches the durable-sync observer, so annotations merged across a swap can sit unpersisted until the next mutation. Out of scope here, but the abort makes it easier to notice, since the run no longer keeps mutating the orphan.
