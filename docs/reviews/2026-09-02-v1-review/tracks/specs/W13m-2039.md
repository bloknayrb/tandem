# W13m — #2039 a mid-turn Y.Doc swap suppresses the local-model turn's terminal effects but does not abort the turn

Branch `fix/local-model-abort-on-doc-swap-2039`. Closes #2039 (references nothing else). Probe: none — the path is dark; the repro is the existing `swapDoc()` / `swapMidTurn()` helpers in `tests/server/local-model/collaborator.test.ts:151,687`.

Bryan settled the design on 2026-09-17 (issue comment): **abort the turn, and make it visible. Do not re-resolve.** This spec implements exactly that and reopens nothing.

## Problem

`executeRun` (`src/server/local-model/collaborator.ts:335-342`) gates every *terminal* effect on `stillOwner()`, whose third conjunct `requireDocument(req.docName)?.doc === ydoc` is false after a Hocuspocus Y.Doc swap (#1657). But the turn itself keeps running: `executeRun` is parked in `await deps.runTurn({ ydoc, ... })` and `runLoop` keeps dispatching tool calls against the **captured, destroyed** `ydoc`.

Correction carried from Bryan's comment, because it decides the mechanism: those writes **succeed** — `Y.Doc.destroy()` clears neither `share` nor `_start` and `transact` has no destroyed guard. They are invisible only because both observers were detached synchronously during the swap (`events/queue.ts:511-512`, `events/file-sync-registry.ts:124-137`), so the record lands in an orphan and never reaches disk. **Nothing throws, so no post-hoc detection is possible — the check must be positive.**

A swap is a browser connecting/reconnecting to a room Hocuspocus is not holding (`yjs/provider.ts:295`, the only instance replacement in `src/server`), and `provider.ts:288-289` merges the old state in before `destroy()`, so the fresh doc is content-identical. Abort wins anyway: after a swap the final chat flush is already suppressed, so a continuing turn half-delivers — annotations land, the reply does not.

## Fix

Three source files: one optional predicate threaded one level, one new exit member, one sibling notification branch.

1. **`src/server/local-model/loop.ts`**
   - `LoopMetrics.exit` gains `"doc-swapped"` (union only; no exhaustive `switch` exists on it). Its doc comment gains one sentence, because the member name is narrower than the condition it records: **"`doc-swapped` means the run's captured Y.Doc is no longer the room's live instance — a Hocuspocus swap, or the document being untracked; the collaborator distinguishes the two before notifying."**
   - `RunLoopOpts` gains `isDocCurrent?: () => boolean` — "still the same Y.Doc instance this run captured". Omitted ⇒ treated as `true`, so every existing caller is byte-identical.
   - One call site, in the turn body **immediately after** the existing post-await abort re-check (`loop.ts:204-207`) and **before** the `res.toolCalls.length === 0` branch:
     ```ts
     if (opts.isDocCurrent && !opts.isDocCurrent()) {
       metrics.exit = "doc-swapped";
       break;
     }
     ```
     Placement is the whole fix and each half is load-bearing:
     - **Post-await, pre-dispatch** is the only interleave point inside a turn — `dispatch` is synchronous (`loop.ts:231`) — and the only point a **tool-only turn reaches at all**. A top-of-loop placement leaves the real shape (the swap lands *during* the await, so this turn's tool calls dispatch onto the destroyed instance) unfixed, which is why tests 1–3 flip the predicate mid-await rather than starting it false.
     - **Before the no-tool-calls branch**, so a final-answer turn exits `doc-swapped` instead of `clean` and cannot hand the collaborator a reply to flush.
     - **After** the abort check, so an abort that has already propagated still reports `aborted` and raises no swap notification.
     - The break precedes `opts.onTurnEnd?.(...)`, **deliberately**: no terminal flush follows a `doc-swapped` exit, and the pending flush timer is released by `sink.dispose()` in the collaborator's existing `finally`.
   - **Plain `break` + exit member. Do NOT call `ctx.abort.abort()`** — `sink.isOwner()` includes `!abort.signal.aborted`, and an abort landing between the `truncated` latch and its scheduled write strands #1292's marker.
   - No Y.Doc write is added anywhere, so Critical Rule 2 has nothing to tag. `pushNotification` is an in-memory ring buffer plus subscriber fan-out (`src/server/notifications.ts:14-32`) with no `transact` on the path.
2. **`src/server/local-model/index.ts`** — `RunTurnOpts` gains the same optional `isDocCurrent` and `runLocalModelTurn` forwards it to `runLoop`. Pure passthrough, but it is the **only** line that makes `doc-swapped` reachable in production (`runLocalModelTurn` hand-enumerates every forwarded field and TypeScript cannot object to an omitted optional), so test 5 pins it.
3. **`src/server/local-model/collaborator.ts`**
   - Extract the identity conjunct so the loop and `stillOwner` cannot drift: `const docUnchanged = () => requireDocument(req.docName)?.doc === ydoc;` defined **below** `const ydoc = open.doc` (it closes over `ydoc`; the TDZ ordering fact #1657 recorded applies unchanged), and `stillOwner()` becomes `current?.token === token && !abort.signal.aborted && docUnchanged()`. The comment block explaining the identity test stays.
   - Pass `isDocCurrent: docUnchanged` into the `deps.runTurn({...})` call.
   - **The visible half sits OUTSIDE `if (stillOwner())`** (`collaborator.ts:365`) — the trap Bryan named: `stillOwner()` is false after a swap *by construction*, so a `doc-swapped` arm inside that block is dead code and the abort ships silent, reproducing this bug. Make it a sibling branch in front — **and gate only the notification (not the exit) on the room still being tracked**, because `docUnchanged()` is *also* false for a CLOSED document (`requireDocument` returns null once `closeDocument` drops the `openDocs` row, `registry.ts:301-309,353-364`), and in production a close does **not** arrive as `aborted`: the collaborator's close-abort depends on `document:closed`, which #2069 records as never firing (`events/observers/ctrl-meta.ts:66` skips the `withInternal` broadcast origin). A bare arm would tell a user who just closed a tab that the document "reconnected", with a remedy no retry can satisfy, where today that path is silently dropped:
     ```ts
     if (result.metrics.exit === "doc-swapped") {
       // A null lookup means the document is CLOSED, not swapped — that inherits
       // the existing silent-drop contract (#2069: close never arrives as an abort).
       if (requireDocument(req.docName)) {
         pushNotification({
           id: generateMessageId(),
           type: "general-error",
           severity: "warning",
           message:
             "The local model stopped: this document reconnected mid-turn, so it stopped early — any comments it already added are still there, but its reply was not delivered. Ask again to continue.",
           documentId: req.docName,
           timestamp: Date.now(),
         });
       }
     } else if (stillOwner()) { /* existing clean/budget/timeout/error arms, unchanged */ }
     ```
     The **abort itself is unchanged in both cases** — a run must not keep dispatching into a doc the registry dropped. Only the message is suppressed on close.
     The copy is deliberately narrower than "the rest of its work was discarded": `provider.ts:285-295` merges the old state into the fresh doc before `destroy()`, so annotations from turns that completed *before* the swap survive; only the terminal reply is dropped.
     The arm deliberately carries **no ownership/token test**. A run that is both superseded and swapped can therefore notify while a newer run is in flight; that is judged better than the dead-code failure Bryan named, and it is recorded here so a later reader does not "tidy" `current?.token === token` back in.
     `pushNotification` is already imported (`:39`) and bypasses the sink. **No `sink.flushFinal()` on this branch** — dropping the terminal reply is #1657's guarantee and stays. `sink.dispose()` in the existing `finally` still runs.
   - The sink is **not** touched: it writes only to `CTRL_ROOM`, which a document-room swap never touches (#1657's recorded divergence).

Dark guarantee: `startLocalModelCollaborator()` still early-returns on `BYO_MODELS_ENABLED` (`src/shared/constants.ts`, literal `const false`). The flag is not flipped, no UI surface is added or documented, `config-source.ts` is untouched.

## Tests

`tests/server/local-model/loop.test.ts`, new `describe("runLoop — mid-turn doc swap (#2039)")`, in the shape of the existing abort describe at `:129` (stubbed `fetch`, real Y.Doc from `makeMarkdownDoc`). **Cases 1–3 must flip `isDocCurrent` DURING the first `await chat()`, never start it false** — a statically-false predicate is satisfied by a top-of-loop placement (it breaks before `chat()` and yields `turns === 0`, `toolCalls === 0`, an empty annotation map and `exit === "doc-swapped"`), leaving the post-await placement pinned by nothing. The discriminating shape already exists at `loop.test.ts:138-155`.

1. **Tool-only turn**: `let swapped = false; const isDocCurrent = () => !swapped;` and a `fetch` stub that sets `swapped = true` then resolves `v1ToolCallArgs("comment_on_quote", { quoted_text: "body text here", comment: "x" })`. Assert `exit === "doc-swapped"`, `turns === 1`, `toolCalls === 0`, `getAnnotationsMap(opts.ydoc).size === 0`, `fetchMock` called once. *Kills:* detection hung off `onContentDelta`/the sink (a tool-only turn produces no content), **and** a top-of-loop check — under that mutant turn 1 dispatches, so `toolCalls === 1` and one annotation lands.
2. **Final-answer turn**: same mid-await flip, stub resolves `v1Text("the reply")`. Assert `exit === "doc-swapped"`, `turns === 1`, `finalContent === ""`. *Kills:* a check placed after the `toolCalls.length === 0` branch (reports `clean` and hands the collaborator a reply to flush); and, via the flip, the top-of-loop placement.
3. **Omitted predicate**: same stub, no `isDocCurrent`. Assert `exit === "clean"`. *Kills:* a required arg or falsy default that would silently abort every real turn.
4. **Abort precedence**: the abort must land **during** `chat()` — an already-aborted signal breaks at the top-of-loop guard (`loop.ts:167-171`, `turns === 0`), never reaches either post-await check, and merely duplicates `loop.test.ts:130-136`. Use a `fetch` stub that calls `controller.abort()`, flips `swapped = true`, then resolves a mutating tool call, with `signal: controller.signal` and `isDocCurrent: () => !swapped`. Assert `exit === "aborted"`, `turns === 1`, `toolCalls === 0`. *Kills:* ordering the swap check above the post-await abort re-check — that mutant reports `doc-swapped`.
5. **The production entry point forwards the predicate**: call `runLocalModelTurn({ ydoc, config: CONFIG, task: "go", isDocCurrent: () => false })` with a tool-call stub; assert `exit === "doc-swapped"` and `toolCalls === 0`. *Kills:* omitting the `isDocCurrent` line from `index.ts`'s hand-enumerated forward, which leaves the fix inert in production while cases 1–4 (direct `runLoop`) and 6–9 (stubbed `deps.runTurn`) stay green.

`tests/server/local-model/collaborator.test.ts`, extending the `#1657` describe (reusing `swapDoc`/`swapMidTurn`) with a `swappedResult()` factory beside `cleanResult`/`limitResult`:

6. **The notification is pushed although `stillOwner()` is false**: `deps.runTurn` resolves `exit: "doc-swapped"` after the doc is swapped mid-turn; assert `getBuffer().filter(n => n.documentId === id)` holds exactly one `severity: "warning"` entry **and** its `message` matches `/reconnected/` — without the message assertion a regression pushing the budget copy ("reached its step limit", `collaborator.ts:376-382`) stays green, and that misleading copy is what this issue is about. *Kills:* putting the arm inside `if (stillOwner())` — buffer empty. This is the discriminating test for the whole issue.
7. **A CLOSED document notifies nothing**: same `swappedResult()` run, but `removeDoc(id)` instead of `swapDoc(id, ...)`; assert `getBuffer().filter(n => n.documentId === id)` is empty. *Kills:* re-merging swap and close into one unconditional arm. `swapDoc` deliberately leaves the registry row in place (`collaborator.test.ts:146-153`), so 6 and 7 genuinely separate the two.
8. **No terminal reply on either path**: same run as 6; assert no finalized chat message is minted (same assertion shape as the existing `:714` arm). *Kills:* a fix that "makes it visible" by also flushing, undoing #1657.
9. **The predicate is really wired**: a `deps.runTurn` that captures its opts; assert `typeof captured.isDocCurrent === "function"` first, then that it returns `true` before `swapDoc(...)` and `false` after. The `typeof` check stops a later tidy-up to `toBeFalsy()` from accepting "not threaded at all" (`opts.isDocCurrent?.()` is `undefined` when absent). *Kills:* adding the exit member without threading `isDocCurrent` at the collaborator seam.

Both files honour the existing microtask timing rule in `swapMidTurn`.

## For `bryan` (PR body)

- **#2070 gets cheaper, not harder**: the `isDocCurrent` thunk is exactly the seam a content-generation check would need, evaluated once per turn post-await/pre-dispatch. It is still invisible to an *identity* predicate, so #2070 is untouched by this PR.
- **#2069 is partially side-stepped, not fixed**: because `docUnchanged()` answers false for an untracked document, a run whose document is closed mid-turn now stops at the next turn boundary even though `document:closed` never fires. The defect itself is upstream in `events/observers/ctrl-meta.ts:66` and this PR does not touch it — a close still does not abort the in-flight `chat()` and still reports `doc-swapped` rather than `aborted`. Widening the same predicate is the cheap shape if that direction is chosen.
- **Pre-existing (#1657 class), now newly observable**: `provider.ts:288-303` re-applies merged state and calls `documents.set(...)` *before* `lifecycle.onDocSwapped(...)` reattaches the durable-sync observer, so annotations merged across a swap can sit unpersisted until the next mutation. Out of scope here.
