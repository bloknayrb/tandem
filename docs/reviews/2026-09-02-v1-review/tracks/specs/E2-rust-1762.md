# E2-rust — #1762 the Windows updater's exe-unlock wait probes a filename that never exists on an installed build

Branch `fix/desktop-sidecar-lifecycle-and-start-at-login-repair-1762`. Closes #1762 (both halves of the suggested fix: the name, and the missing-file branch). Ledger: `docs/reviews/2026-09-02-v1-review/areas/tauri.md:16`. Probe: none automatable — verification is the Windows `rust-test` leg plus the §1 smoke row at `docs/release-smoke-checklist.md:34`.

## Problem

`sidecar_exe_path` (`src-tauri/src/sidecar.rs:2316`) builds `format!("node-sidecar-{}.exe", env!("TARGET_TRIPLE"))` at `:2325`. tauri-build strips the `-<triple>` when it copies an `externalBin` into the bundle, and the runtime asks for the bare name at `sidecar.rs:1712` (`.sidecar("node-sidecar")`). **Measured on this machine, both halves:** the installed app dir holds `node-sidecar.exe` and the dev target dir holds `node-sidecar.exe`; the triple-suffixed name exists nowhere outside `src-tauri/binaries/`.

Live reproduction, tracked: `docs/release-smoke-checklist.md:150-160`, written by #1932 (`7ee66a5c`) out of the v0.25.0 smoke run.

```
[2026-09-10][01:22:37][app_lib][WARN] Sidecar exe not on disk at
C:\Users\blokn\AppData\Local\Tandem\node-sidecar-x86_64-pc-windows-msvc.exe
  — skipping unlock wait (packaging bug?)
```

So `Ok(p) if p.exists()` misses and `wait_for_sidecar_unlock` (`:2333`) returns `true` — **it reports "unlocked" having never found the file to check.** That flows to `lib.rs`'s `tokio::join!`, whose `if !file_ok` arm is therefore dead, leaving the NSIS `NSIS_HOOK_PREINSTALL` kill as the only layer between an update and a running `node-sidecar.exe`.

**Not deletion.** The wait is not a thing nobody needs; it is a thing nobody has ever run. With the name corrected it probes a real file a running sidecar really holds open on Windows, and the failure it prevents (NSIS overwriting a locked exe) is real. Deleting it would make the kill hook the only layer *by decision* rather than by accident — worse than the two-line repair.

## Fix

- `sidecar.rs`: add `pub(crate) const SIDECAR_BIN_NAME: &str = "node-sidecar";` beside the other spawn constants (near `SIDECAR_BIND_HOST`, `:167`), with a docblock saying the triple is a *build-time* convention (`src-tauri/binaries/node-sidecar-<triple>[.exe]`) that tauri-build strips, so this is the only name runtime code may use. Use it at `:1712` (`.sidecar(SIDECAR_BIN_NAME)`) and in `sidecar_exe_path`. **The const is the fix**, not a tidy-up: divergence between the spawn name and the reconstructed path is exactly what #1762 is.
- `sidecar_exe_path` (`:2317-2329`): `let name = format!("{SIDECAR_BIN_NAME}.exe");`. Drop the inner `if cfg!(target_os = "windows")` / `else` — the function already carries `#[cfg(target_os = "windows")]` (`:2315`), so the else arm is unreachable and would silently reintroduce a second naming rule if the gate were widened.
- **Extract the missing/unresolvable verdict as a pure function**, so the release behaviour is pinned rather than merely read:

  ```rust
  /// Should `wait_for_sidecar_unlock` report "unlocked" when it cannot find or
  /// resolve the sidecar exe? Dev has no bundled sidecar in some layouts and must
  /// proceed; a release build that cannot find it has a packaging bug and must
  /// not let that pass as unlocked.
  fn unlock_verdict_when_absent(is_debug: bool) -> bool { is_debug }
  ```

  Both arms of `wait_for_sidecar_unlock` call it: the missing-file arm (`:2336-2344`) and the `Err(e)` resolve-failure arm (`:2345-2352`) each `return unlock_verdict_when_absent(cfg!(debug_assertions));` instead of a bare `return true;`. The function is **cross-platform** (outside the `#[cfg(target_os = "windows")]` gate) so the ubuntu and macOS `rust-test` legs reach it; add `#[cfg_attr(not(target_os = "windows"), allow(dead_code))]` if the lint complains. Release log line becomes `log::warn!("Sidecar exe not on disk at {} — reporting still-locked (packaging bug)", p.display())`; the dev line keeps `log::debug!` and its "(dev mode)" wording.
- `lib.rs`'s `if !file_ok` message currently asserts a cause it no longer always knows. Reword to `format!("Sidecar exe lock not confirmed released within {SIDECAR_UNLOCK_DEADLINE_SECS}s -- installer may prompt for retry")`, interpolating the const per `warn_port_still_responding`'s precedent. **#1808 moves this exact block down inside `perform_install`, and #1762 lands first** — #1808 moves it *as amended here*.
- Docs — three sites state the defect as live and one carries a stale citation; the same edit fixes both:
  - `docs/architecture.md:855` ends "the one place that does not is #1762, below." After `SIDECAR_BIN_NAME` there is no such place: say the stripped name is carried by the shared const in `sidecar.rs`, and drop the pointer.
  - `docs/architecture.md:998` — "(inert on an installed build — see #1762 below)". Drop the parenthetical.
  - `docs/architecture.md:1019` — "on an installed build it polls nothing (#1762, open)". Rewrite to say the wait probes the installed name and a missing file now reports still-locked. **Correct the embedded citation in the same edit**: it says `sidecar.rs:2064-2077`; the function is at `:2316-2329`.
  - `docs/release-smoke-checklist.md:34`'s "While you are here, check #1762" paragraph — the grep target becomes `reporting still-locked (packaging bug)`. **Do not edit the "What the v0.25.0 run settled" section (`:145-167`)** — it records what a run observed, not a claim about current code.

**Rules that bite:** `strip_win_prefix()` is *not* wanted here — `sidecar_exe_path` builds a path for `std::fs::OpenOptions`, not for the sidecar, and the `\\?\` form is fine for Win32. Nothing here touches `TAURI_HOSTNAME`, the licensing consts or any `/api` route.

## Tests

Two, in a named `#[cfg(test)] mod sidecar_name_tests` in `src-tauri/src/sidecar.rs` — `sidecar.rs`'s test modules are all named and `lib.rs` has no `mod tests` at all. The Windows `rust-test` leg exists (`ci.yml:62`) and is a required check, so a `#[cfg(target_os = "windows")]` test here genuinely runs.

1. `#[cfg(target_os = "windows")] fn sidecar_exe_path_uses_the_installed_name_not_the_build_time_triple()` — `sidecar_exe_path().unwrap()`; assert `file_name() == "node-sidecar.exe"`. **Scoped to the file name, not the whole path**: the function is `current_exe().parent().join(name)`, and a developer running `cargo test --target x86_64-pc-windows-msvc` would false-red a whole-path scan. (CI passes no `--target`.)
2. `fn a_missing_sidecar_exe_reports_still_locked_in_release()` — cross-platform, on the pure function: `assert!(unlock_verdict_when_absent(true))` and `assert!(!unlock_verdict_when_absent(false))`. This is the half Track E's Done-when asks for ("a test that fails … on a missing sidecar path").

**Mutation check:** revert `:2325` to the triple form and test 1 goes red; change `unlock_verdict_when_absent` to `|_| true` and test 2 goes red. Restore from a file copy, never `git checkout`.
