# D1 — #1852 autosave of an unedited review README rewrote a markdown table separator row

Branch `fix/markdown-fidelity-1753`. Closes #1852. No area-ledger row (field report from the 2026-09-02/03 release-gate programme, not the read/ran sweep). **Reproducing the measurement.** The review's round-trip probe **is tracked** — `npx tsx docs/reviews/2026-09-02-v1-review/experiments/rt.ts` is the 107-construct sweep (`git ls-files docs/reviews/2026-09-02-v1-review/experiments/` lists 44 files, none gitignored). For the single-file figure below, a scratch `npx tsx` script that reads the file, runs `loadMarkdown` -> `saveMarkdown`, and prints every differing line pair plus the idempotency check. Run over the **real** repo document 2026-09-09 — the wave note requires a real doc here, not a synthetic fixture.

## Problem

The report's shape is confirmed exactly. `loadMarkdown` → `saveMarkdown` over `docs/reviews/2026-09-02-v1-review/README.md` as it stands on master:

```
DIFF docs/reviews/2026-09-02-v1-review/README.md  lines(src=63 out=63) differing=1 idempotent=true
  line 29:  - "|---|---|"
            + "| - | - |"
```

Exactly one differing line, and it is the table delimiter row — the hunk the reporter remembered before the evidence was lost. The second save is a fixed point.

**Root cause is the already-known one, not a new defect.** `markdown.ts`'s `remarkGfm({ tablePipeAlign: false })` comment says it: "It does NOT reproduce hand-authored `|---|---|` geometry, and no option can — mdast carries no source markers — so compact delimiter rows still change once, and only once." The corpus already registers `tests/fixtures/roundtrip/table-compact.md` with `blockedOn: "table geometry"`. This README is the same fixture in the wild. The issue's own ask allows for that outcome: "either be shown to be the same root cause or get its own fixture."

**The "unedited" half of the title is partly refuted, and the refutation matters.** `autoSaveAllToDisk` (`src/server/mcp/document-service.ts:1124-1140`) skips any document that is not dirty — `if (!isDirty(docId)) continue;`, the #851/#605 fix whose comment is literally "Merely opening a file to view it must not round-trip it through the serializer + rewrite it on disk." So autosave of an *unedited* document cannot write at all, and the observed write means the document was **dirty**. `documents/dirty.ts` bumps the version on ANY body-fragment change regardless of origin — deliberately, so Claude's `mcp` writes persist — which means a normalization applied by the browser's Tiptap schema on first sync marks a document dirty with no human edit. Settling *which* normalization did it needs a live client and is not decidable from the server; it goes to Bryan, not into this fix.

## Fix

**No serializer change.** Reproducing hand-authored delimiter geometry needs a per-node source-marker layer; #1448 already scoped that out, and inventing one here would be the exact "calibration mechanism" this sweep parks groups for. What lands instead is the pin the issue asks for:

`tests/server/file-io/roundtrip-corpus.test.ts` gains one spec over the **real** file `docs/reviews/2026-09-02-v1-review/README.md`. **The test resolves no repo root today** — `CORPUS_DIR` is `fileURLToPath(new URL("../../fixtures/roundtrip/", import.meta.url))` (`roundtrip-corpus.test.ts:27`), a fixtures path only — so the new spec adds one: `fileURLToPath(new URL("../../../", import.meta.url))` from `tests/server/file-io/`, joined to the doc path. Spell it out rather than implying one exists.

**Classify, never zip by line index.** The neighbouring repo-metric suite already documents why (`roundtrip-repo-metric.test.ts:7-13`: "That list changes with every docs PR … a snapshot people regenerate reflexively stops being a signal"), and a positional pairing breaks on the first hard-wrapped paragraph added to that README — the soft-wrap reflow class this spec's own Not-in-scope excludes. So:

- Round-trip it; collect the differing content by **classifying each difference**, either by comparing after collapsing intra-paragraph line breaks on both sides, or by pairing on content rather than index.
- Assert **every** difference is one of two named kinds and fail on anything else:
  - `delimiter-row` — `/^\s*\|[\s:|-]+\|\s*$/` matches old and new. This is the measured one: `|---|---|` → `| - | - |` at line 29, one differing line, 2026-09-09.
  - `soft-wrap-reflow` — the two sides are equal after collapsing intra-paragraph breaks **AND the new side has no fewer lines than the old**. The second clause is not decoration: without it, a defect that MERGES two prose lines is also "equal after collapsing breaks", so the reflow arm would silently absorb a real corruption — the one class this spec exists to catch. **Measured 2026-09-09, this arm is currently unexercised on the target**: the README round-trips with `differing=1`, `idempotent=true`, and the single hunk is the line-29 delimiter row — zero reflow hunks. It ships anyway because the target is a document this sweep programme itself edits and a hard-wrapped paragraph is one PR away; state in the PR body that it is dead on today's input so nobody reads a green run as evidence the arm works.
- Assert `differing.length > 0`, with a failure message pointing at the `table-compact.md` registration. Without it the `every` passes vacuously the day the geometry defect is fixed, and the spec silently stops testing anything.
- Print the actual old/new pairs in the failure message — a bare "an unexpected kind" on a 63-line file costs the next reader a bisect.
- Assert the transform is idempotent (`rt(rt(x)) === rt(x)`).

**One known third kind, named here so a reader does not widen the predicate to admit it.** Measured on the sibling file `areas/server-data.md`: `- #1693 …` → `- \#1693 …`, an escape `remark-stringify` **adds** to a line-leading `#` inside a list item (opposite direction from #1753, renders identically). That README currently contains **zero** such bullets (measured), but one new bullet beginning `- #1234` would turn a required `check` job red on a docs-only change. The correct response when that happens is to **edit the bullet** (or extend the classifier with a third *named* kind and a comment), never to relax the assertion into a count or a `<= N`.

Written that way it is stable under ordinary prose edits and it fails by name the moment a real repo document starts differing in a *third* way. It also fails if someone widens the table normalization further (e.g. re-introducing width padding), which is the regression that actually costs users.

Then update `roundtrip-corpus.test.ts`'s `table-compact.md` entry `why` to name this issue alongside #1448, so the next reader of that allowlist finds the real-world instance rather than re-deriving it.

Rules that bite: no source change, no Y.Doc write, no MCP surface — `docs/mcp-tools.md` needs no Errors edit. The spec must read the file through the repo root, not a fixture copy: a copy is exactly the synthetic fixture the wave note rules out, and it would go stale silently.

## Tests

The spec above *is* the test. Two things it must be built to kill:

- A "fix" that special-cases the delimiter row by memorizing source text: it would make the differing-line count zero, and the spec would pass — so the spec is not the guard against that; the corpus's `table-compact.md` registration is (it asserts that fixture is STILL broken, and a memorizing fix makes it fail and forces the registration to be removed deliberately). Keep that entry.
- A lazy implementation that asserts only `differing <= 1`: it would pass on a file that gained a completely unrelated one-line corruption. Assert the *kind* of every difference, not the count — and pair by content, not by line index, so a reflowed paragraph does not read as a corruption.

Also add the observed second real-world kind to the PR body as measured-not-fixed: `docs/reviews/2026-09-02-v1-review/areas/server-data.md` differs in two lines — the delimiter row, and `- #1693 …` → `- \#1693 …`, an escape `remark-stringify` **adds** to a line-leading `#` inside a list item. It renders identically and is the opposite direction from #1753.

## Done when

The real-file spec is green and would go red on an **unnamed** hunk kind; `table-compact.md` stays registered as broken with this issue named; `roundtrip-repo-metric.test.ts` unchanged and green.

**Re-run this spec after the whole D1 stack is applied.** It is authored before #1850 and #1813 but *after* three serializer changes in the same branch — #1753's `activeRefDefs` scan, #1799's inline-image predicate and #1799's fence-meta carry — any of which can move the round-trip output of a repo doc containing those constructs. And the target is the wave ledger this very sweep programme edits: CLAUDE.md's "Where to look" row points at it and the wave notes update it. A **new differing KIND** is the intended failure and means a real regression; a **new construct appearing in the file** is a maintenance edit to the document or a new named kind. Neither is a reason to weaken the kind assertion into a count.
