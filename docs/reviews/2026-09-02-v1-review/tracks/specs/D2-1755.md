## Problem

**Half 1 — docx.** mammoth emits a body picture as `<p><img src="data:image/png;base64,…"/></p>` (measured on `corpus.buildEmbeddedImage`: exactly one `<img>`, always inside a `<p>`). `docx-html.ts` handles `img` in `domNodeToYxml`'s block switch (`:400-421`), but the paragraph arm defers its children to `processInlineNodes` (`:573-633`), which has arms for text, `br`, `a`, mark tags and `code` and ends in "unknown inline element — recurse (best effort)". An `<img>` has no children, so an `<img>` reached through the **inline** path is **discarded**. Nothing in `scanDocxLostFeatures` mentions images, so the fidelity report is silent, and `tandem_save` then regenerates the `.docx` through `exportYDocToDocx` and overwrites the user's file without them. `tests/server/docx-roundtrip-fidelity.test.ts:250-258` already records the loss as `"breaks"`.

**Half 2 — markdown.** `mdast-ydoc.ts#imageToYxml` (`:482-493`) downgrades a `sanitizeImageSrc`-rejected URL to a paragraph carrying `node.alt || node.title || ""`. Measured now: `![Architecture diagram](file:///C:/…/diagram.png)` and `![svg](data:image/svg+xml;base64,…)` save back as the bare words `Architecture diagram` and `svg`. The URL is gone from the user's file.

## Fix

**1. Report the docx loss.** In `src/server/file-io/index.ts`'s `docxAdapter.parse`, after the `Promise.all`, count the images mammoth surfaced that the model will not hold — a new `countDroppedImages(html, footnoteBodies): number` exported from `docx-html.ts`.

**The count is of DROPPED images, not of all `<img>` tags, and the difference is load-bearing.** `domNodeToYxml`'s block `case "img"` (`docx-html.ts:400-421`) **does** build a real `image` `Y.XmlElement` for a `sanitizeImageSrc`-accepted src; several other paths discard one. Today mammoth always nests `<img>` inside a `<p>`, so "every `<img>`" and "every dropped `<img>`" coincide — but that is a measurement on one fixture, not an invariant, and the failure direction is bad: an over-count refuses the save **forever**, with no override (see Not in scope), so the user's edits could never be written back.

**Normative definition — ONE clause, computed by the module's own dispatch. Do NOT mirror the dispatch with a tag list; round 2's two-clause definition and its `INLINE_DEFERRING_BLOCK_TAGS` constant are DELETED, and the reason is measurement, not taste.** An `<img>` is **kept** iff `domNodeToYxml`'s block `case "img"` runs on it **and** `sanitizeImageSrc` accepts its `src`, in which case exactly one `image` `Y.XmlElement` reaches the fragment. Everything else is dropped. So:

> `droppedImages` = (`<img>` elements in the DOM `htmlToYDoc` actually consumes) − (`image` elements `htmlToYDoc` produces from it)

**Why the list approach is not merely fragile but wrong in three directions, all measured on this worktree** (`htmlToYDoc` on a `data:image/png` src, counting surviving `image` elements):

| fixture | `image` elements kept | round-2 spec said |
|---|---|---|
| `<p><img></p>`, `<h1><img></h1>` | 0 — dropped | dropped ✓ |
| `<pre><img></pre>` | 0 — dropped | **not listed → under-count** |
| `<li><img></li>`, `<td><img></td>`, `<blockquote><img></blockquote>` | **1 — KEPT** | **listed as dropped → over-count** |
| `<li><span><img></span></li>`, `<td><span><img></span></td>` | 0 — dropped | **not listed → under-count** |
| `<section><span><img></span></section>` | 0 — dropped | **not listed → under-count** |
| `<div><span><img></span></div>` | 1 — kept | — |
| `<ul><img></ul>` | 0 — dropped, by neither path | **not expressible → under-count** |
| top-level `<img src="data:image/png…">` | 1 — kept | kept ✓ |
| top-level `<img src="data:image/svg+xml…">` | 0 — dropped (rejected src) | dropped ✓ |

The mechanism: **`"img"` is itself a member of `BLOCK_TAGS`** (`docx-html.ts:33-53`, line 50), and `collectBlockChildren` (`:490-497`) routes any child in `BLOCK_TAGS` back through `domNodeToYxml`. So a *direct* `<img>` child of `li` / `td` / `th` / `blockquote` takes the **block** arm and is preserved — while the same `<img>` one level down inside a non-block wrapper (`<span>`) lands in that function's `inlineBuffer`, is deferred, and is dropped. `pre` (`:391-397`) and the `default:` pure-inline arm (`:444-459`) defer wholesale like `p` and the heading arm; the `ul`/`ol`/`table`/`tr` arms silently ignore a non-`li`/non-`tr` child, which is a **third** drop mode the two-clause definition cannot express at all. No hand-written ancestor list can be right here, and both error directions are real: over-count is the permanently unsaveable file, under-count is #1755's silent loss returning.

**Implementation — audit the real walk, do not re-walk.** Add an optional final parameter to `htmlToYDoc`, `onImageAudit?: (audit: { total: number; kept: number }) => void`, fired once after pass 2. Existing callers (`docxAdapter.apply`, `docx-verify.ts:329`, four test files) are unchanged by construction.

- `total` is the number of `<img>` elements in `parsed.children` **after** `pruneFootnoteListItems` (`:265`) — a plain recursive tag count, no dispatch knowledge, **not a regex** (which would count the string inside a text node). Counting post-prune is what keeps a footnote-body image out of the number: those `<li>`s are removed before the walk and their bodies are reconstructed through `Y_MAP_FOOTNOTE_BODIES`, so counting them would refuse the save on a document whose body pictures are all intact.
- `kept` is incremented on the **same line that constructs the `image` element** in `domNodeToYxml`'s `case "img"` — that placement is the whole guarantee, so do not move it to the arm's top. Thread it however is cleanest in that module (a second threaded parameter alongside `deferred`, or promoting `deferred: DeferredText[]` to a small `{ deferred, imagesKept }` walk context across the six functions that already pass it); the spec's requirement is only that the counter is incremented by the real arm, never by a copy of its conditions.
- `countDroppedImages(html, footnoteBodies)` then runs `htmlToYDoc` against a **throwaway `Y.Doc`**, captures the audit, `destroy()`s the doc and returns `total − kept`. Wrap the dry run in `withInternal(probe, …)` — Critical Rule 2 is satisfied literally, and `htmlToYDoc` documents that it needs an outer transaction anyway (`docx-verify.ts:329` does the same for the same reason). The probe doc is never registered with Hocuspocus, never persisted and never observed.
- **Skip the audit when `options.scanLostFeatures === false`.** That is the `docx-verify.ts` re-import path, which reads no `prepared.issues` at all; skipping it means the extra conversion costs one pass per real document open and **zero** per save-verification.

This needs no exported tag list, no paired source comments and **no source-scan drift test** — a future block arm cannot drift from a definition that is computed by the arms themselves. What replaces the drift test is behavioural: test 4's routing fixtures below, whose negative half (`<li><img></li>` → 0) is the thing that goes red if `"img"` is ever removed from `BLOCK_TAGS`.

Annotations are unaffected either way — they persist through the durable annotation store, not through `saveSession`. Record the choice in Done-when so it is reviewable.
