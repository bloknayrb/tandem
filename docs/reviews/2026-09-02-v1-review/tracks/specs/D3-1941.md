## Problem

`document-service.ts:496` refuses a binary save whenever the persisted fidelity report carries
`droppedImages > 0`. Correct as a default, and the file is provably untouched — but total: no
parameter, no body field, no control (`saveAnyway` appears nowhere in `src/`). The only exit is
`tandem_convertToMarkdown`, which needs a Claude attached, so a browser user with none is at a dead
end. The count is `total − kept` (D2-1755.md:15, :117), so an over-count refuses that document
forever; the override is what bounds that.

Do not overstate the pre-#1939 behaviour in the PR body: `snapshotBeforeFirstWrite` covers the
`.docx` binary branch, so images were recoverable-but-undiscoverable, not silently destroyed.

## Fix

**1. The flag.** `saveDocumentToDisk(docId, source, opts?: { allowImageLoss?: boolean })` — a third
optional parameter, so `reload-family.ts`, `autoSaveAllToDisk` and `document-service.ts:1206` are
unchanged by construction. The gate at `:496` becomes
`if (!opts?.allowImageLoss && reportCount(fidelityReportOf(doc), "droppedImages") > 0)`. Scoped to
`import-image-loss` only: the second throw (`:547`, `verdict.kind === "blocked"`) is untouched —
those reasons say *the regenerated file is broken*, a different claim.

- `tandem_save` (`document.ts:1319-1323`): `allowImageLoss: z.boolean().optional()` in the
  inputSchema, destructured at `:1324`, passed at the `saveDocumentToDisk` call. `.describe()` it as
  destructive.
- `POST /api/save` (`routes/save.ts`, branch 1 at `:130`):
  `const allowImageLoss = body.allowImageLoss === true`. **Strict `=== true`** — `express.json()`
  has no `type` option, so a `text/plain` POST leaves `req.body` undefined and `body` falls back to
  `{}`; every parse failure must land on `false`. Do not touch `assertOriginAllowlisted` at `:51`.
  Branches 2 and 3 do not take the field.

**Critical Rule 9 — verified, no new row.** Both tables key on the surface:
`license-gate-coverage.test.ts:72` (`tandem_save`) and `license-gate-api-coverage.test.ts:87`
(`API_SAVE`), both ungated; a parameter is not a surface. `NON_LOOPBACK_ALLOWED` untouched.
**#1654's bound holds**: the flag changes *whether* a save proceeds, never *where* it lands.

**2. Copy — and `blockReasonMessage` stays content-free.**

- `docx-verify.ts:448` must **name the override**, surface-neutrally: the same string is the pushed
  notification and `tandem_save`'s `reason` (`document.ts:1383`). No path, filename or count
  (`builtin.svelte.ts:55`, `activityCenter.ts:63`, `document-service.ts:749` assert this). Proposed:
  "this file's pictures couldn't be imported, so saving would remove them — save anyway if you
  accept that (allowImageLoss), or convert it to Markdown instead" + the existing tail. Pin it with
  `expect(blockReasonMessage("import-image-loss")).toMatch(/save anyway/i)` in
  `docx-verify.test.ts:285-296`; the §3 button label shares the phrase.
- `file-io/index.ts:291-292` ("can't be saved back as .docx — ask Claude to convert") is falsified
  by this PR and is the line the banner lists immediately above the new button. Reword to a
  refusal-with-an-exit; update `docx-roundtrip-fidelity.test.ts:263` and `:266`. `:264` (the
  `won't be in the saved file` negative) constrains the replacement wording — the line must not read
  as a lossy-save-by-default. Keep it green.
