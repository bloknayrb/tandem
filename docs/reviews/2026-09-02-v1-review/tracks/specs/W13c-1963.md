# W13c — #1963 Active-annotation pulse class lost on decoration rebuild (Editor.svelte, #1824 item A)

Branch `fix/client-rail-pulse-outline-and-tutorial-fixes-2014`. Closes #1963 (one of the six carve-outs
keeping #1824 open — **no closing keyword for #1824**). Ledger:
`docs/reviews/2026-09-02-v1-review/areas/client-editor.md:26` (the row citing `Editor.svelte:287-303`).

## Problem

`src/client/editor/Editor.svelte:286-302` — the `$effect` that strips and re-applies
`.tandem-annotation-active` reads exactly two reactive inputs, `editor` and `activeAnnotationId`. The class
is written onto DOM nodes the **annotation decoration plugin** produced. When that plugin rebuilds — the
#1669 case, where y-prosemirror's `_typeChanged` replaces the PM doc and ProseMirror re-renders the
`[data-annotation-id]` spans — neither input changes, the effect does not re-run, and the pulse class is
silently gone from a still-active annotation. Nothing throws, nothing warns; the highlight just stops.

## Fix

The mechanism #1963's body asks for. Two files.

**New `src/client/editor/deco-revision.ts`** — one pure, exported predicate and nothing else:

```ts
export function shouldBumpDecoRevision(tr: Transaction): boolean {
  return tr.docChanged || !!tr.getMeta(ySyncPluginKey) || !!tr.getMeta(annotationPluginKey);
}
```

`ySyncPluginKey` from `@tiptap/y-tiptap`, `annotationPluginKey` from `./extensions/annotation` — the same
two imports `extensions/annotation.ts:5,20` already uses, so no new dependency. The gate exists because
`transaction` fires on **every cursor move**: `docChanged` is the ordinary rebuild, the `ySyncPluginKey` meta
is the #1669 remote-sync replacement (`annotation.ts:347` keys on the same meta for the same reason), and the
`annotationPluginKey` meta is the plugin's own explicit rebuild signal. It is a separate module purely so it
is unit-testable without mounting a Tiptap editor.

**`Editor.svelte`:**

- `let decoRevision = $state(0);`
- A new `$effect` subscribing to the editor's `transaction` event, **bridged through `createCoalescingTick`**
  (`src/client/utils/coalescing-tick.ts`): `transaction` is emitted synchronously from ProseMirror's
  `dispatch`, so a bare `decoRevision++` throws `state_unsafe_mutation` **in production too**. Precedent:
  `FormattingToolbar.svelte:56-70` (identical shape). The filter runs **outside** the tick —
  `if (!shouldBumpDecoRevision(tr)) return; bump();` — so a burst of qualifying transactions collapses to one
  write while a cursor-move burst schedules nothing. **Copy that precedent verbatim, including its three
  `isDestroyed` guards**: capture `const ed = editor` with `if (!ed || ed.isDestroyed) return;` at effect
  entry (the reactive prop getter is null during tab switch); guard the deferred body,
  `createCoalescingTick(() => { if (!ed.isDestroyed) bump(); })`, because the tick fires in a microtask that
  can land after teardown and the pulse effect then touches `ed.view.dom`; and guard the cleanup. **The
  cleanup must be `return () => { if (!ed.isDestroyed) ed.off("transaction", handler); };`** — a bare
  `return ed.off(...)` returns the `Editor`, not a teardown function, and Svelte would call it.
- In the pulse effect at `:286`, read the counter: `void decoRevision;` on its own line with a comment naming
  why (a decoration rebuild re-creates the spans; neither `editor` nor `activeAnnotationId` moves). `void x`
  is the codebase's idiom for a dependency-only read — `FormattingToolbar.svelte:130,136`.

Nothing else moves: the effect body, `CSS.escape`, the strip-then-add order and the null-id branch at `:448`
stay. No `data-testid`, no Y.Doc write (so no origin helper), no colour.

## Tests

### `tests/client/deco-revision.test.ts` (new)

Plain vitest — nothing touches the DOM. Transactions are hand-built plain objects
(`{ docChanged, getMeta: (k) => ... }`) cast to `Transaction`, the shape `annotation-decoration.test.ts`
already uses.

1. `{ docChanged: true }`, no meta → `true`. Kills a meta-only predicate.
2. `{ docChanged: false }` + `ySyncPluginKey` meta → `true`. Kills a `docChanged`-only gate — the #1669
   remote-sync rebuild this fix exists for.
3. `{ docChanged: false }` + `annotationPluginKey` meta → `true`. Kills dropping the plugin's own signal.
4. **`{ docChanged: false }`, `getMeta` returns `undefined` for everything → `false`.** The discriminating
   negative: without it `return true` passes 1–3 and the cursor-move churn the gate suppresses comes back.
5. **A truthy non-`true` meta → `true`.** `getMeta(annotationPluginKey)` returns the real object shape,
   `{ type: "toggle-decorations", visible: { comment: true, highlight: false, note: true } }`. **This is the
   case that kills `=== true`**: the meta is typed `AnnotationToggleMeta | true | undefined`
   (`extensions/annotation.ts:277`) and `App.svelte:1081` dispatches the object form, so `=== true` would
   drop every decoration-visibility toggle and silently reinstate the missing pulse. (Round 1 proposed
   pairing this with a `false`-meta case as a second kill; it is not one — `!!false` and `false === true`
   both answer `false` — so the pair is cut to this half.)

Full re-apply behaviour is deliberately not unit-tested here (the issue says so): it needs a real bound
editor and a real y-sync replacement. The E2E covers it.

### `tests/e2e/deco-pulse-survives-rebuild.spec.ts` (new), one spec

**Not optional**: an implementation that ships `deco-revision.ts` and wires the counter but omits the

## Review round 1 — the design above does not work, and was replaced

Two reviewers (crdt-reviewer `cr-1`, svelte-migration-reviewer) reported that the counter re-applies the
class once and the redraws that follow a remote write strip it again milliseconds later, so #1963's
user-visible symptom survives. Widening `shouldBumpDecoRevision` to those plugins' metas (`yCursorPluginKey`,
`awarenessPluginKey`, `authorshipPluginKey`) was tried first and **measured still red** on the E2E's
steady-state assertion. The instrumented run says why:

```
273 attr old="tandem-comment tandem-comment--claude" new="… tandem-annotation-active"   ← our write
273 childList add=1                                                                     ← the span is replaced
FINAL class="tandem-comment tandem-comment--claude"
```

The stripper is **ProseMirror's own DOMObserver**: a `classList.add` on a span the view owns is an attribute
it did not write, so it marks the node dirty and re-renders it from the DecorationSet ~1ms later. A DOM
repair dispatches **no transaction**, so no transaction-keyed re-apply can ever win that race — the whole
counter mechanism is unfixable in principle, not underspecified.

**What shipped instead.** The class is part of the annotation **decoration's own attrs**:

- `extensions/annotation.ts` gains `AnnotationActiveMeta` (`{type:"set-active", id}`) and a plugin-scoped
  `activeId`; `buildDecorations` takes it and appends `tandem-annotation-active` to the type's class.
  Appended, not replacing, so the underline/highlight survives. An unchanged id returns the existing set —
  that is the #798 A6a "pulse on becoming-active, not on re-click" rule, which a rebuild would otherwise
  break by re-creating the span and restarting the keyframe.
- `Editor.svelte` drops `decoRevision`, the `transaction` subscriber and the imperative effect, and
  dispatches the meta from one `$effect` (inside `untrack`, matching `App.svelte`'s visibility effect).
- `deco-revision.ts` and its unit spec are **deleted** — the module existed only for the counter.
- `tests/client/decoration-survives-sync.test.ts` gains three specs on a real bound editor (tint survives a
  y-sync rebuild, the type's own class is kept, focus-out clears it); the E2E now asserts the class is the
  **resting** state across a 600ms continuous window, which is what a transient re-application fails.
- The `editor.css` A6a comment, `Editor.svelte`'s click-handler comment and `highlight-ux.spec.ts`'s header
  all asserted the imperative mechanism as fact and were corrected.

The "not in scope: any change to the annotation decoration plugin itself" line above is **void**: the plugin
is where the fix has to live.
