## Problem

`sidecar.rs:3931` spells a line-comment marker as `const LINE_COMMENT: &str = concat!("/", "/");`, used at `:3933` as `!src[line_start..macro_at].contains(LINE_COMMENT)`. The comment paragraph above it (`:3923-3930`) justifies the spelling with a claim that is now false in both halves:

1. *"`tests/docs/rust-sources.ts` strips comments with a regex … that regex is not string-aware"* — since #1861's fix (PR #1973, `3ab75719`) `stripRustComments` (`tests/docs/rust-sources.ts:114`) is a literal-aware character scanner reusing `skipRustLiteral`; it is not a regex at all.
2. *"It fails loudly rather than silently"* — measured false even before that fix; the old stripper silently truncated `autostart.rs` and dropped eight production symbols from every `rustSources()` guard. That measurement is already recorded in `rust-sources.ts:105-112`, so nothing here needs to restate it.

Bryan's 2026-09-11 comment on #1970 corrects the issue body's own "leave it as-is for the *other* still-live reason": `tests/shared/unc-check-duplication.test.ts:103`'s `RAW_PREFIX` is `/\.starts_?[wW]ith\(\s*r?"(?:\\|\/\/)/` and matches only a `.starts_with(` / `.startWith(` call. The `concat!` site is a `.contains(` call, so that detector cannot reach it under any reading. #1968's real `.starts_with('/')` workaround at `sidecar.rs:2919` is an unrelated hazard that merely sits in the same `crash_restart_tests` module — **do not touch it.**

## Fix

Comment/literal only. No Rust behaviour change: the `.contains(…)` check is unaffected by how its argument is spelled.

In `src-tauri/src/sidecar.rs`, and cited by content rather than by count, because the neighbouring lines are code and an off-by-one here deletes an assertion:

- **Delete** the justifying paragraph that begins `// `concat!`, not a spelled-out "//" literal.` and ends `// hole, but the crate has to step around it.` (today `:3923-3930`, eight comment lines).
- **Delete** the line `const LINE_COMMENT: &str = concat!("/", "/");` (today `:3931`).
- **Rewrite** the single `assert!` condition that reads `!src[line_start..macro_at].contains(LINE_COMMENT)` (today `:3933`) to `!src[line_start..macro_at].contains("//")`. The assert's message string is unchanged.
- **Keep verbatim** the preceding paragraph that begins `// …and that macro must not itself be commented out.` and ends `// a comment, real call gone) that the previous mechanism died of.` (today `:3915-3920`) — it documents the *assertion*, not the spelling, and is the anchor-failure lesson the guard exists for. The two lines after it (`let macro_at = …`, `let line_start = …`, today `:3921-3922`) are code and stay.
- Nothing else in the crate changes. `RAW_PREFIX`, `rust-sources.ts` and `unc-check-duplication.test.ts` are read-only here.

File set: `src-tauri/src/sidecar.rs` only (this spec).

## Tests

No new test file, and that is the deliberate call: the minimality rule forbids adding a scanner, and every guard that could regress here already exists. What must be *run*, and recorded in the PR body as the re-verification Bryan's comment asks for:

1. `npx vitest run tests/docs tests/shared/unc-check-duplication.test.ts` — green. The seven `rustSources()`-based consumers are the discriminating population: if the literal `"//"` still desynced the stripper, `sidecar.rs`'s `code` view would truncate and at least one of them would report a missing symbol.
2. A one-off measurement pasted into the PR body, killing the "it passes because the guards do not look at `sidecar.rs`" reading. **The property at stake is non-truncation, not length equality** — the edit deletes eight comment lines *and* a real code line and shortens the literal, so the stripped length necessarily shrinks by tens of bytes; an "unchanged length" assertion would be false by construction and would read as the very truncation it exists to rule out. So, with `tsx`, after the edit:
   - `stripRustComments(readFileSync("src-tauri/src/sidecar.rs", "utf8"))` still **reaches the end of the file** — assert it contains the file's last production symbol and that its trimmed tail is the file's own closing `}`.
   - `rustSources().find(f => f.rel.endsWith("sidecar.rs")).code` still contains `crash_restart_decision`, `restart_sidecar_for` and `RestartCause`. This is the half that does the work.
   - Report the before/after stripped lengths as **data**, not as an equality claim, alongside the raw file lengths, so a reader can see the delta is the removed bytes and nothing more.
3. `CARGO_TARGET_DIR=… cargo test --manifest-path src-tauri/Cargo.toml` — the in-file guard at `:3933` still passes, i.e. the `.contains` assertion is unchanged in meaning.
