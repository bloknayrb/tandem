# Gc2b — #1775 The slash-command menu opens inside code blocks; Enter then converts the block or deletes text

Branch `fix/keyboard-and-a11y-1777`. **Closes #1775.** Ledger: `docs/reviews/2026-09-02-v1-review/areas/client-editor.md:20` (High, `[ran] Reproduced`). Probe: `docs/reviews/2026-09-02-v1-review/experiments/harness/a-bugs.test.ts` and the same directory's `e-keys.test.ts` case `E1` (repo-relative — there is no `experiments/` at the repo root) — `/e` + Enter inside a code block converts it to a paragraph, `cd /t` + Enter deletes text. Also verified in a real browser (Playwright lane, `docs/reviews/2026-09-02-v1-review/raw/verify-client.txt`).

## Problem

`resolveActiveSlashCommand` (`src/client/editor/slash-menu/extension.ts`) gates on `isSlashMenuSuppressed()` and `selection.empty`, then reads `$from.parent.textBetween(0, $from.parentOffset, …)` and matches. It never asks what kind of block the caret is in. `suppression.ts` is DOM-presence probes only (find bar focused, command palette mounted, selection-popup testids present) — it cannot see document structure, so it is the wrong layer for this.

Consequence: any `/` inside a code block — a path, a regex, a URL, a comment — opens the `Slash commands` listbox offering Paragraph, Heading 1, …, Horizontal rule. The plugin's `handleKeyDown` then claims Enter (`event.preventDefault(); return executeSlashCommand(editor, active)`), so the keystroke the user meant as a newline runs a block conversion instead, deleting the matched `/query` text on the way.

## Fix

One guard, in `resolveActiveSlashCommand`, immediately after `const $from = selection.$from;` and before the `textBetween` read:

```ts
// A "/" inside a code block is literal text (a path, a regex, a URL) and Enter
// there means a newline, not a block conversion. Same exemption
// `PlaintextBreaksExtension#splitInsteadOfBreak` uses, for the same reason.
if ($from.parent.type.spec.code) return null;
```

The precedent is `src/client/editor/extensions/plaintext-breaks.ts`, which already declines on `this.editor.state.selection.$from.parent.type.spec.code` and whose comment states the rule ("a newline typed inside one is genuinely a newline and the node stores it literally"). `spec.code` rather than a `type.name === "codeBlock"` comparison, so any future code-ish node inherits it.

Placing the guard in the **resolver** rather than in `handleKeyDown` is what makes the Enter half impossible: the resolver is the single entry point for both initial activation and every subsequent keystroke (its own comment says so), so `active` is never non-null inside a code block and the `Enter` / `ArrowUp` / `ArrowDown` / `Escape` branches at the plugin's `handleKeyDown` are unreachable there. A guard added at the Enter branch alone would still flash the menu open.

Nothing here touches `$state`, Y.Doc writes, `data-testid` selectors or the suppression list.

**One user-facing sentence goes stale and is fixed in the same commit.** `docs/user-guide.md:76` reads "…it stays out of the way while the find bar, command palette, or an annotation popup is open." After the guard it also stays out of the way inside a code block, so append `, or when the caret is inside a code block` to that sentence (before the closing period). Nothing reads it: `tests/docs/slash-menu-guide-claims.test.ts` parses only the command/alias enumeration in the paragraph above, so this line drifts unread — which is why the two-person "fix rather than file" rule applies to a one-line edit rather than a follow-up issue.

## Tests

- `tests/client/slash-menu-code-block.test.ts` (new, `@vitest-environment happy-dom`) — the harness `E1` cases converted with the assertions **inverted**, using a real Tiptap `Editor` built from `buildSchemaExtensions()` + `SlashCommandExtension` exactly as `experiments/harness/e-keys.test.ts` does:
  1. `content: "<pre><code>echo hi\n</code></pre>"`, caret at the end, `insertContent("/")` then `"e"` → `slashCommandPluginKey.getState(editor.state)?.active` is `null`. Kills the fix-at-the-Enter-branch variant, which leaves `active` set.
  2. Same setup, then dispatch a `keydown` `{key:"Enter"}` on `editor.view.dom` → `editor.getHTML()` still contains `<pre>` and the code block's text still **contains** `echo hi` (no paragraph conversion, no deleted characters). **Do not assert strict equality with the pre-Enter text**: with the slash plugin declining, ProseMirror's base `Enter` chain reaches `newlineInCode` and appends a literal `
` — which is the correct post-fix behaviour and what the user asked for. This is the user-visible half and it is what the issue reports.
  3. `content: "<pre><code>cd </code></pre>"`, type `/t`, Enter → the code block's text still **contains** `cd /t` (again, a trailing `
` is expected, not a failure). The space-then-slash shape is a distinct `findSlashCommandMatch` path from case 1.
  4. **Discriminating positive:** the same `/e` typed in a plain paragraph still activates (`active` non-null with `query === "e"`). Without it, `return null` at the top of the resolver passes every negative case and disables the feature entirely.
  5. **Discriminating negative:** `/` typed inside an inline `code` **mark** in a paragraph still activates — `spec.code` is a node-spec property, so the guard is deliberately blind to marks, and pinning that stops a later "tidy" into a mark-aware check nobody asked for. **This is a decision, not an oversight, and the PR body must say so in one sentence:** the issue reports the code-*block* case, where Enter must be a literal newline because the node stores one; inside an inline `code` mark the caret is still in a paragraph, Enter there is a genuine block-level Enter, and `newlineInCode` would not fire — so declining the menu would leave the user with a plain paragraph split and no way to reach the commands from a formatted run. Widening the guard to `$from.marks()` is a separate product call; if Bryan wants it, invert this case in its own commit.

## Done when

**All five** unit cases pass — including case 5, the inline `code` **mark** still activating, which is the pin that stops a later widening to `$from.marks()` and must not be dropped as an optional extra — and the E2E case passes with both its pre-Enter (menu never appears) and post-Enter (text intact) assertions. `docs/user-guide.md:76` names the code-block exemption. `npm run typecheck`, `npm test`, `npm run test:e2e` green; the harness `E1` cases are represented under `tests/` with inverted assertions so the reproduction has a permanent home.
