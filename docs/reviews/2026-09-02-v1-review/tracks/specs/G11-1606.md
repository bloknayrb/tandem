## Fix

Insert a new paragraph into `CLAUDE.md`'s Development Workflow section, immediately after the dated-gates block's closing sentence ("...a gate that can be deferred indefinitely is not a gate.") and before "This is a two-person project (Bryan + Claude)...":

```
**Route new work by whether it's answerable from tracked files, not by apparent difficulty
(#1606).** The same test as above applies before you start, not only at gate review: work
derivable from the code and the ticket — coordinate math, range invariants, schema/migration,
anything with an in-repo signpost — is worth trusting a model on. Work whose correctness depends
on the world — what users put in their documents, what a real upgrade does, what a specific OS or
Claude Code build does — needs the missing fact landed in the repo first, or needs Bryan; no
amount of investigation inside the repo substitutes. `needs-human-evidence` marks the second
bucket (#316, #2034) — release urgency is independent of the bucket, so the label is not a
priority signal.
```

This states the routing question over information availability (not difficulty), names the label and its two current members, and states the corollary the issue asks for explicitly ("be explicit that the sort is not blocker-versus-not... release-urgency and bucket are independent") — without re-narrating `CLAUDE.md`'s own Status section, which already lists the v1.0 blockers in detail.
