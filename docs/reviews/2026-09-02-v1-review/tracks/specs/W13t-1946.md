# W13t — #1946 the Settings token panel reports a file the desktop server does not read

Branch `fix/settings-read-only-radiogroup-and-desktop-token-panel-1964`. Closes #1946. Ledger:
`docs/plans/2026-09-06-open-issues-sweep.md:794` (the H-c closeout paragraph that filed it).
Probe: start the server with `TANDEM_AUTH_TOKEN=x` set (the desktop sidecar's own shape,
`src-tauri/src/integrations_probe.rs:316`) and `GET /api/info` from loopback — it still reports
`tokenRotatedAt`, stat'd from a file this process never read.

## Problem

`src/server/mcp/routes/info.ts:68-86` stats `deps.getTokenFilePath()` for every loopback caller
and emits `tokenRotatedAt` (mtime, or `null` on ENOENT). But `getTokenFilePath`
(`src/shared/auth/token-file.ts:6`) derives its path from the `env-paths` root **directly**,
deliberately ignoring `TANDEM_APP_DATA_DIR` (`docs/data-locations.md:61`;
`src/server/app-data-owner.ts:94-98`), while `loadOrCreateToken`
(`src/server/auth/token-store.ts:65-69`) prefers `process.env.TANDEM_AUTH_TOKEN` — which the
desktop sets from the OS keychain before spawning the sidecar. So on a desktop install the field
describes a file with no reader:

1. **It always renders.** The Tauri WebView reaches the sidecar over loopback, so the field is
   never `undefined` and `NetworkSettings.svelte:263`'s `{#if}` never hides the block.
2. **"Auth token not yet created" is false** on a desktop-only machine — a token exists and is in
   active use. On a machine with *both* installs it is worse: the desktop app silently shows the
   **npm** install's rotation time.
3. **The remedy is unrunnable** — `NetworkSettings.svelte:272` tells the user to run
   `tandem rotate-token`, and the desktop bundle ships no `tandem` binary (#1789(a)); even if it
   did, it would rotate a file the desktop server never reads.

`SettingsAboutTab.svelte:139-146` renders the same field as an About row, with the same three
defects minus the hint.

## Fix

**Server-side only.** The client already gates both surfaces on `tokenRotatedAt !== undefined`,
so making the server stop emitting the field when it is not the truth fixes both at once — no
new copy, no new `data-testid`, no testid-snapshot regeneration, no client diff.

- `src/server/auth/token-store.ts`: export
  `export function tokenFileIsAuthoritative(): boolean { return !(process.env.TANDEM_AUTH_TOKEN?.trim()); }`
  — placed beside `loadOrCreateToken`, because it mirrors that function's first branch
  (`envToken && envToken.trim().length > 0`) exactly and co-location is what makes the mirroring
  reviewable. It does **not** unify the codebase's env-token tests, and the spec does not claim
  it does: there are three branches today and they already differ —
  `token-store.ts:65-66` (trimming), `src/server/index.ts:670`
  (`process.env.TANDEM_AUTH_TOKEN || (await readTokenFromFile())`, truthy), and
  `src/server/mcp/routes/rotate-token.ts:55` (`if (process.env.TANDEM_AUTH_TOKEN)`, bare truthy,
  no trim). With `TANDEM_AUTH_TOKEN="   "` the new predicate reports the file authoritative
  (panel shown, hint says run `tandem rotate-token`) while `rotate-token.ts:55` answers 409
  "Token is managed by Tauri". **`rotate-token.ts:55` is deliberately NOT migrated onto the new
  predicate** — doing so would widen rotation to the whitespace-env case, a behaviour change on a
  security-sensitive route and out of this spec's scope.
  The predicate is also the *exact* one, not a proxy: `npmCliSharesAppDataRoot()` (the #1789
  precedent for "which install answered you") would read false for an npm user who merely set
  `TANDEM_APP_DATA_DIR`, whose token file is still live.
- `src/server/mcp/routes/info.ts`: add **required** dep
  `tokenFileIsAuthoritative: () => boolean` to `InfoHandlerDeps` and guard the stat with it —
  `if (loopback && deps.tokenFileIsAuthoritative())`. Required, not optional-defaulting-true:
  optional fails *open* (a forgotten wiring keeps the lie), required fails at compile time at
  every construction site, and `tests/` is typechecked (`typecheck:tests`). When the guard is
  false, omit `tokenRotatedAt` from the body entirely — the same shape a non-loopback caller
  already gets — and do not stat at all.
- `src/server/mcp/server.ts:883`: pass `tokenFileIsAuthoritative` beside the existing
  `getTokenFilePath`.
- `tests/server/info-route.test.ts:208` — `BASE_DEPS` gains
  `tokenFileIsAuthoritative: () => true`. This is the one test-side construction site: the ~12
  `makeInfoHandler(BASE_DEPS)` calls (`:222, :257, :273, :288, :309, :334, :352, :368, :393,
  :409, :424`) all feed from it, and the required dep breaks `typecheck:tests` until it is added.
  Defaulting it to `true` keeps every existing unit spec on the authoritative arm. (The
  `Parameters<typeof makeInfoHandler>[0]` pass-through at `src/server/mcp/api-routes.ts:376`
  needs no edit.)
- `src/client/types.ts:200`: amend the `tokenRotatedAt` jsdoc — absent now means *either*
  non-loopback *or* "this server's token did not come from that file", and the client must keep
  treating absence as "say nothing", never as "no token".
- `docs/data-locations.md:61` already states the npm-only rule; add one clause recording that
  `/api/info` now omits the field in the desktop case rather than reporting `null`.
- `docs/mcp-tools.md` is the canonical `/api` reference (CLAUDE.md "Where to look") and is
  currently left asserting the opposite in two places. Amend `:1260` ("All fields are returned for
  loopback (127.0.0.1) callers") to note the one exception, and the `tokenRotatedAt` row at
  `:1299` to read that the field is present only when the running server's token came from the
  token file — omitted entirely when `TANDEM_AUTH_TOKEN` is set. Leave the loopback example body
  at `:1271` as the npm/authoritative case, with a one-clause note.
- **Deliberately unchanged:** `POST /api/rotate-token` keeps its current gates. It must **not**
  gain `assertOriginAllowlisted` — the CLI posts it via Node `fetch` with no `Origin` and that
  gate fails closed on a missing one (CLAUDE.md → Security). `NON_LOOPBACK_ALLOWED` does not
  grow. No MCP tool or `/api` route is added, so the license-gate tables are untouched.
- **The token value itself is never read, logged, or placed in any attribute** — only an mtime
  ever crossed this wire, and after this change not even that on desktop.

## Tests

Specs 1–3 go in the **`makeInfoHandler` unit suite** of `tests/server/info-route.test.ts` — the
one that starts at `:217` and uses `makeMockReq` / `makeMockRes` / `BASE_DEPS` (`:189-216`), each
spreading `BASE_DEPS` with a per-spec override. Not beside the loopback spec at `:96`: that is
inside the live-server integration `describe` (`beforeEach` at `:64-69` does
`startMcpServerHttp`), which accepts no dep override.

1. With `{ ...BASE_DEPS, tokenFileIsAuthoritative: () => false }`, a loopback response has
   `"tokenRotatedAt" in body === false` **while `storagePath` and `generationId` are still
   present** — the paired assertion is what kills a fix that accidentally narrows the whole
   loopback block.
2. Same suite: `getTokenFilePath` returning a path that does not exist, with
   `tokenFileIsAuthoritative: () => false`, must not call `stat` — pass a `getTokenFilePath` spy
   and assert it was never invoked. Kills a fix that computes the value and then drops it, which
   would leave the ENOENT `console.error` branch reachable on desktop.
3. Same suite: the authoritative arm is unchanged — `() => true` plus a real temp file still
   reports its mtime, and plus a missing file still reports `null` (not omitted). Without this,
   "omit always" passes 1 and 2 and silently removes the panel for every npm user.
4. **Unit-test the real predicate.** A direct spec of the exported `tokenFileIsAuthoritative()`
   (in `tests/server/token-store.test.ts`, or its own `describe` in `info-route.test.ts`): save
   `process.env.TANDEM_AUTH_TOKEN` in `beforeEach` and restore in `afterEach`; assert `true` when
   unset, `true` when `""`, `true` when `"   "` (mirroring `loadOrCreateToken`'s
   `envToken.trim().length > 0`), and `false` when set to a real token. **Specs 1–3 all inject a
   fake predicate, so without this one an implementation that reads the wrong variable name — or
   returns a constant `true` — passes everything while `/api/info` keeps lying on every desktop
   install.** The only pre-existing coverage (`:96-110`, live server) runs with the env var unset,
   i.e. the npm arm only.
5. **Pin the integration spec's new precondition.** `tests/server/info-route.test.ts:108`'s
   `expect("tokenRotatedAt" in b).toBe(true)` holds only while `process.env.TANDEM_AUTH_TOKEN` is
   unset in the vitest process — nothing in `vitest.config.ts` guarantees that, and other suites
   set and delete it (`tests/cli/mcp-stdio.test.ts:1142-1151`,
   `tests/channel/fetch-with-timeout.test.ts:27`). Save and `delete process.env.TANDEM_AUTH_TOKEN`
   in that `describe`'s `beforeEach`, restore in `afterEach`, and add a comment at `:108` naming
   the precondition.
6. **Client pin, in its own file: `tests/client/network-settings-token-panel.test.ts`.** Not in
   `tests/client/settings-readonly-ui.test.ts`: that file's `beforeEach` (`:57-59`) stubs `fetch`
   as a never-resolving promise for the whole file and already renders `NetworkSettings` in the
   `CASES` loop, so a spec added there would (a) inherit a stub under which `appInfo.info` stays
   `null`, the `{#if tokenRotatedAt !== undefined}` block never renders, and the negative
   assertion passes vacuously **with no server change at all**, and (b) race the module-scope
   `/api/info` cache with every other render in the file.
   The spec's shape:
   - `fetchAppInfo` caches at module scope (`src/client/hooks/useAppInfo.ts:9, :28`). Call
     `_resetAppInfoCache()` (imported from `src/client/hooks/useAppInfo.js`, re-exported from
     `useAppInfo.svelte.ts:5`, as `tests/client/useAppInfo.test.ts:40, :46` already does) in both
     `beforeEach` and `afterEach`, **and between the two arms** — the cache reset is the only
     thing that makes the two arms distinguishable; without it the second render is served the
     first body.
   - Each arm installs its own `vi.stubGlobal("fetch", ...)` that **resolves** the arm's payload,
     and awaits the `$effect`'s fetch settling (`await Promise.resolve()` / a macrotask, then
     `await tick()`) before asserting.
   - Negative arm (`/api/info` **without** `tokenRotatedAt`): the rendered text contains neither
     `"tandem rotate-token"` nor `"not yet created"` — **anchored** by a positive assertion that
     the component really rendered a loopback body (e.g. the `network-retry-strategy` testid is
     present, or `storagePath`'s row rendered), so the absence is evidence rather than an
     un-delivered response.
   - Positive arm (`tokenRotatedAt: <ms>`): the text contains "Last rotated".
