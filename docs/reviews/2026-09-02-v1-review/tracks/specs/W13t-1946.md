# W13t — #1946 the Settings token panel reports a file the desktop server does not read

Branch `fix/settings-read-only-radiogroup-and-desktop-token-panel-1964`. Closes #1946. Ledger:
`docs/plans/2026-09-06-open-issues-sweep.md:794` (the H-c closeout paragraph that filed it).
Probe: start the server with `TANDEM_AUTH_TOKEN=x` set (the desktop sidecar's own shape,
`src-tauri/src/integrations_probe.rs:316`) and `GET /api/info` from loopback — it still reports
`tokenRotatedAt`, stat'd from a file this process never read.

## Problem

`src/server/mcp/routes/info.ts:68-86` stats `deps.getTokenFilePath()` for every loopback caller
and emits `tokenRotatedAt` (mtime, or `null` on ENOENT). But `getTokenFilePath`
(`src/shared/auth/token-file.ts:6`) derives its path from the `env-paths` root **directly**,
deliberately ignoring `TANDEM_APP_DATA_DIR` (`docs/data-locations.md:61`;
`src/server/app-data-owner.ts:94-98`), while `loadOrCreateToken`
(`src/server/auth/token-store.ts`) prefers `process.env.TANDEM_AUTH_TOKEN` — which the desktop
sets from the OS keychain before spawning the sidecar. So on a desktop install the field
describes a file with no reader:

1. **It always renders.** The Tauri WebView reaches the sidecar over loopback, so the field is
   never `undefined` and `NetworkSettings.svelte:263`'s `{#if}` never hides the block.
2. **"Auth token not yet created" is false** on a desktop-only machine — a token exists and is in
   active use. On a machine with *both* installs it is worse: the desktop app silently shows the
   **npm** install's rotation time.
3. **The remedy is unrunnable** — `NetworkSettings.svelte:272` tells the user to run
   `tandem rotate-token`, and the desktop bundle ships no `tandem` binary (#1789(a)); even if it
   did, it would rotate a file the desktop server never reads.

`SettingsAboutTab.svelte:139-146` renders the same field as an About row, with the same three
defects minus the hint.

## Fix

**Server-side only.** The client already gates both surfaces on `tokenRotatedAt !== undefined`,
so making the server stop emitting the field when it is not the truth fixes both at once — no
new copy, no new `data-testid`, no testid-snapshot regeneration, no client diff.

- `src/server/auth/token-store.ts`: export
  `export function tokenFileIsAuthoritative(): boolean { return !(process.env.TANDEM_AUTH_TOKEN?.trim()); }`
  — placed beside `loadOrCreateToken`, whose first branch it mirrors, so the two cannot drift
  into disagreement in separate files. This is the *exact* predicate, not a proxy:
  `npmCliSharesAppDataRoot()` (the #1789 precedent for "which install answered you") would also
  read false for an npm user who merely set `TANDEM_APP_DATA_DIR`, whose token file is still
  live.
- `src/server/mcp/routes/info.ts`: add **required** dep
  `tokenFileIsAuthoritative: () => boolean` to `InfoHandlerDeps` and guard the stat with it —
  `if (loopback && deps.tokenFileIsAuthoritative())`. Required, not optional-defaulting-true:
  optional fails *open* (a forgotten wiring keeps the lie), required fails at compile time at
  every construction site, and `tests/` is typechecked (`typecheck:tests`). When the guard is
  false, omit `tokenRotatedAt` from the body entirely — the same shape a non-loopback caller
  already gets — and do not stat at all.
- `src/server/mcp/server.ts:883`: pass `tokenFileIsAuthoritative` beside the existing
  `getTokenFilePath`.
- `src/client/types.ts:200`: amend the `tokenRotatedAt` jsdoc — absent now means *either*
  non-loopback *or* "this server's token did not come from that file", and the client must keep
  treating absence as "say nothing", never as "no token".
- `docs/data-locations.md:61` already states the npm-only rule; add one clause recording that
  `/api/info` now omits the field in the desktop case rather than reporting `null`.
- **Deliberately unchanged:** `POST /api/rotate-token` keeps its current gates. It must **not**
  gain `assertOriginAllowlisted` — the CLI posts it via Node `fetch` with no `Origin` and that
  gate fails closed on a missing one (CLAUDE.md → Security). `NON_LOOPBACK_ALLOWED` does not
  grow. No MCP tool or `/api` route is added, so the license-gate tables are untouched.
- **The token value itself is never read, logged, or placed in any attribute** — only an mtime
  ever crossed this wire, and after this change not even that on desktop.

## Tests

1. `tests/server/info-route.test.ts`, beside the loopback spec at `:96`: with
   `tokenFileIsAuthoritative: () => false`, a loopback `makeInfoHandler` response has
   `"tokenRotatedAt" in body === false` **while `storagePath` and `generationId` are still
   present** — the paired assertion is what kills a fix that accidentally narrows the whole
   loopback block.
2. Same file: `getTokenFilePath` returning a path that does not exist, with
   `tokenFileIsAuthoritative: () => false`, must not call `stat` — pass a `getTokenFilePath` spy
   and assert it was never invoked. Kills a fix that computes the value and then drops it, which
   would leave the ENOENT `console.error` branch reachable on desktop.
3. Same file: the authoritative arm is unchanged — `() => true` plus a real temp file still
   reports its mtime, and plus a missing file still reports `null` (not omitted). Without this,
   "omit always" passes 1 and 2 and silently removes the panel for every npm user.
4. `tests/client/settings-readonly-ui.test.ts` or a sibling client spec: render
   `NetworkSettings` with `/api/info` answering **without** `tokenRotatedAt` and assert the
   rendered text contains neither `"tandem rotate-token"` nor `"not yet created"`; with
   `tokenRotatedAt: <ms>` it contains "Last rotated". That is the discriminating pin that the
   client's `!== undefined` gate is genuinely the one doing the hiding.

## Done when

`/api/info` omits `tokenRotatedAt` whenever the running server's token came from the
environment; the four specs above are green; `server.ts` wires the new dep (compile-enforced);
the two doc lines updated; no client component, `data-testid`, snapshot, gate list or
`rotate-token` handler changed.
