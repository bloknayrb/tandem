# E1 — #1763 Deferred start-at-login launcher can never be released: the Rust caller sends no Origin

Branch `fix/desktop-core-1761`. Closes #1763. Ledger: `docs/plans/2026-09-06-open-issues-sweep.md:413`; area row `docs/reviews/2026-09-02-v1-review/areas/tauri.md:17`. Probe: the two route tests below; the end-to-end verification is a smoke line (Bryan).

## Problem

On a login launch the sidecar starts with the launcher deferred and `show_main_window` → `note_user_presence` (`src-tauri/src/lib.rs:733-767`) is the single release point. It calls `request_launcher_start` (`lib.rs:673-712`), a two-hop `reqwest` flow: `GET LAUNCHER_NONCE_URL` then `POST LAUNCHER_START_URL`, both with `Authorization` only.

**Both hops are gated, and the issue names the wrong one as the blocker.** `makeNonceHandler` (`src/server/launcher/api-routes.ts:268-274`) calls `assertOriginAllowlisted` *first*, so the flow 403s at the **GET**, before the POST is ever built. `assertOriginAllowlisted` (`src/server/integrations/api-routes.ts:361-371`) fails closed on a missing header: `isLocalhostOrigin(undefined)` is false. `note_user_presence` restores the `LAUNCHER_DEFERRED` latch on failure (`lib.rs:759-766`), so it retries on every later presence signal and fails identically every time — the UI shows "deferred" for the life of the session. No client caller of `API_LAUNCHER_START` exists, so nothing else releases it.

## Fix

**Send the Origin from Rust. Do not remove either gate.** The track file offers "drop `assertOriginAllowlisted` and rely on the loopback invariant plus a parsed-JSON-body proof as `rotate-token` does" as the alternative; it is the wrong half here for a reason that only shows up once you notice the nonce route is the blocker: **`GET /api/launcher/nonce` is a GET**, so `enforceLoopbackMutation` (non-GET only, CLAUDE.md Security) does not cover it, and `assertOriginAllowlisted` is its *only* origin-level control. Dropping it would hand a single-use nonce — the CSRF token that also gates `relaunch` and `start-fresh` — to any caller that can reach the port. The CLAUDE.md precedent for `open` and `rotate-token` is a rule about **not adding** the gate to routes that never had it; it is not a licence to remove one from a route that spawns processes.

- `src-tauri/src/lib.rs`: add `const LOOPBACK_ORIGIN: &str = "http://127.0.0.1:3479";` beside the existing URL constants at `:149-156`, and have the `with_auth` closure in `request_launcher_start` also set `.header("Origin", LOOPBACK_ORIGIN)`. Rename the closure or leave the name — it now applies both headers; a one-line doc comment saying so is enough.
- **Why this value and not `tauri.localhost`:** `LOCALHOST_ORIGIN_RE` (`src/server/mcp/api-routes.ts:112-114`) accepts `^https?://(127\.0\.0\.1|tauri\.localhost)(:\d+)?$`, so both pass. `http://127.0.0.1:3479` is the *actual* origin of the URL being requested, making the header a same-origin declaration rather than a claim to be the WebView; it also keeps CLAUDE.md's "use the `TAURI_HOSTNAME` constant, never a raw `\"tauri.localhost\"`" rule out of play — there is no Rust-side `TAURI_HOSTNAME`, and hand-writing that literal in Rust is exactly what the rule forbids. Deriving the constant from the same `127.0.0.1:3479` the sibling URLs already hardcode also keeps it inside #1825's existing "the constants are hardcoded" debt rather than adding a new spelling.
- **`CLAUDE.md` and `tests/docs/loopback-gate-claims.test.ts` are untouched.** That test scans `src/server/mcp/api-routes.ts` only, the launcher file is a different registrar, and no gate is being added or removed anywhere — so the "no-Origin route list grows by one" line in the track file does **not** apply to this shape. Say that explicitly in the PR body; a reviewer reading the track file will expect a CLAUDE.md edit.
- Not touched: `note_user_presence`'s latch handling, the nonce protocol, `assertLoopbackForMutation` on either route.

## Tests

1. `tests/server/launcher/api-routes.test.ts` — the file already drives a real express app with an `Origin` header (`:105`, `:864-873`) and already has a `rejects missing Origin` case for the nonce route at `:204-212`. Add, in the same describes: `GET /api/launcher/nonce` **and** `POST /api/launcher/start` each succeed past the origin gate with `Origin: http://127.0.0.1:3479`. **What they kill:** a fix that sends `Origin: http://localhost:3479` (bare `localhost` is rejected by `LOCALHOST_ORIGIN_RE` — the #477 PR 2 narrowing) or an origin without the port. Keep the existing missing-Origin rejection specs untouched: they are the discriminating twin proving the gate is still armed.
2. `src-tauri/src/lib.rs`, `mod url_constants_tests` (`:2932`) — extend `supervisor_urls_use_loopback_ip_not_localhost`'s sibling set with a new test asserting `LAUNCHER_NONCE_URL.starts_with(LOOPBACK_ORIGIN)` and `LAUNCHER_START_URL.starts_with(LOOPBACK_ORIGIN)`. **What it kills:** a later port change to one constant that silently turns the Origin header into a cross-origin claim the server then 403s — the current failure, re-created with no new symptom.
3. No test asserts reqwest actually emits the header (no seam without a live server); the constant test plus the route test bracket it. State that in the PR body.

## Done when

Both route tests pass, the missing-Origin rejections still pass, `cargo test` carries the constant pin, and the PR body records that no gate was removed and CLAUDE.md's enumeration is unchanged.
