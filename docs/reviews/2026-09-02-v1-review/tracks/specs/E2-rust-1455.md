## Problem

The issue names exactly one sliver that needs no hardware:

> `src-tauri/src/firewall.rs:405` is the only in-code reference to this decision … **ADR-045 shipped as "MCP Transport Multiplexing — One `McpServer` Per Session, Keyed by `Mcp-Session-Id`"**, an unrelated subject. Anyone following that pointer lands somewhere wrong and reasonably concludes the matter was decided. Fix the comment to point at this issue regardless of when the test runs — that part needs no hardware.

Verified on current master: the comment has drifted to `src-tauri/src/firewall.rs:910-912`, on `add_cowork_deny_rule`'s docblock —

```
/// Kept (the disable path's `remove_cowork_rules` still cleans up any deny rule a
/// past elevated run may have written) and pending the Cowork-transport matrix
/// outcome; see the cowork-detection plan / forthcoming ADR-045.
```

Both halves of the pointer are wrong. ADR-045 exists and is about MCP transport multiplexing (`docs/decisions.md:1517`), so "forthcoming" is false and the subject is unrelated; and "the cowork-detection plan" names no tracked file — the plan it means is `~/.claude/plans/i-ve-just-tried-enabling-deep-alpaca.md`, outside the repo, the exact CLAUDE.md #1308 rule-2 failure #1455 was filed to record.

## Fix

One comment, in `src-tauri/src/firewall.rs:911-912`. Replace the trailing clause with a pointer to the two things a reader can actually reach:

- the tracked matrix, `docs/plans/archived/cowork-transport-test-matrix.md` — and say it is **unrun**, because its `archived/` location reads as done;
- issue **#1455**, which carries the dated gate (review by 2026-10-15) and the keep/replace/retire rule.

Drop "forthcoming ADR-045" entirely; do not substitute another ADR number. Keep the "Kept (…)" first half verbatim — it states why the function survives at all and is unrelated to the pointer.

Nothing else in `firewall.rs` changes. In particular the `FirewallError` enum, `run_netsh`'s missing elevation path and the `#[allow(dead_code)]` on `add_cowork_deny_rule` all stay exactly as they are: they are what the matrix may delete, and pre-empting that verdict is the opposite of what this gate asks.
