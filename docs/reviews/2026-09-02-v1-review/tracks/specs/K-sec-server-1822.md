## Problem

1. **Channel-error log injection (`src/server/mcp/channel-routes.ts:101-117`).** `message` is interpolated raw into `console.error` on both arms (`:108`, `:114`), and `String(error)` is too on the `UNKNOWN_CODE` arm — which logs the rejected value *before* the 400, directly contradicting the comment two lines above it ("Validate the code so a future caller can't smuggle a free-form string through unfiltered logs"). ESC/BEL/CR/LF and a full OSC-0 title sequence reach the operator's terminal verbatim, with no length bound. `POST /api/channel-error` is in `NON_LOOPBACK_ALLOWED` (`api-routes.ts:214-225`), so under a LAN bind any **bearer-authenticated** peer reaches it. The same shape sits at `:160` (`toolName`, `requestId`) and `:182` (`requestId`) on two more carved-out routes.
2. **No `maxPayload` on Hocuspocus (`src/server/yjs/provider.ts:101-212`).** `startHocuspocus` calls `hocuspocusInstance.listen()` with no websocket options, so `Server`'s `new WebSocketServer({ noServer: true, ...websocketOptions })` takes ws's 100 MiB default. Measured in the issue: an *unauthenticated* peer's 90 MiB frame moved RSS 179→331 MB; 120 MiB closed 1009. Hocuspocus always binds `127.0.0.1`, so this is loopback-only. `events/wake-socket.ts:172` already caps its own socket at 1024 with a comment describing exactly this hazard — the in-repo precedent.
3. **413 ships an HTML stack trace with the install path (`src/server/mcp/server.ts:560`, `:761`).** Re-measured on `8924d54f` with a real server: a 200 kB `application/json` body to `POST /mcp` returns `413 text/html; charset=utf-8` whose `<pre>` is `PayloadTooLargeError: request entity too large` followed by absolute `C:\Users\…\node_modules\raw-body\index.js:163` frames. Loopback-only. **The `docs/security.md` half of this item is already done** — `:166` no longer claims 50 MB is a body limit; it states the 70 MB / 100 kB split correctly. What is stale is its citation, `src/server/mcp/server.ts:517-547`, which now misses `largeBody` (`:549`) and `createMcpExpressApp` (`:560`).
4. **Item 7 — phantom 200s (`server.ts:851-857`).** The SPA fallback answers any unmatched path with `index.html`, byte-identical, so `/.git/HEAD` returns 200 without a file ever being read. `refuted.md:13` records the traversal claim itself as refuted. Bryan: *"returning index.html at a dotfile-shaped URL is not evidence that the requested file was read. No scanner-appeasement change is planned on that basis."*
5. **Item 8 — the dark license wire (`src/server/mcp/routes/license.ts:38-51`, `:88-97`).** While the gate is dark both wires emit `status: "licensed"` next to `gateActive: false`, and the LAN-scrubbed wire additionally carries `licenseInstalled` (`:95`).

## Fix

**Item 1 — `channel-routes.ts`.** Add one module-private helper and use it at all four interpolation sites:

```ts
function sanitizeForLog(value: unknown): string
```
— `String(value)`, then strip **C0 including `\n`/`\r`/`\t`, C1 (`\x80-\x9f`), DEL, and the Trojan-Source bidi set** (`\u200e\u200f\u202a-\u202e\u2066-\u2069\u061c`), then clamp to 200 characters with a `…` marker. Model: `stripControlChars` (`src/client/utils/diagnostics.ts:73`) and the clamp reasoning in `cli/doctor.ts:1150-1170`. **Two deliberate divergences to write into the comment:** it is *not imported* from `diagnostics.ts` because `src/server` imports nothing from `src/client` today (verified: zero such imports; the five greps that match are prose in comments), and it strips `\x0a`, which `stripControlChars` deliberately preserves (`client-log.ts:138`) — a bare LF forges a second log line, which is the whole point here. Sites: `:108` (both `error` and `message`), `:114` (`message`), `:160` (`toolName`, `requestId`), `:182` (`requestId`). Keep the `UNKNOWN_CODE` log where it is — the diagnostic trail is the comment's stated intent; sanitizing is what makes the comment true. Rewrite that comment so it describes the sanitize-and-clamp rather than claiming the schema check alone prevents smuggling. **`NON_LOOPBACK_ALLOWED` does not change**; the carve-out is this finding's premise.

**Item 2 — `provider.ts`.** Add a module constant and pass it as `listen`'s **third positional argument**:

```ts
export const MAX_SYNC_PAYLOAD_BYTES = MAX_FILE_SIZE + 16 * 1024 * 1024; // 66 MiB
…
await hocuspocusInstance.listen(null, null, { maxPayload: MAX_SYNC_PAYLOAD_BYTES });
```

`MAX_FILE_SIZE` comes from `src/shared/constants.ts:155` (50 MB, enforced on both open paths at `documents/open.ts:568` and `:718`) — **do not add a new constant to `shared/constants.ts`**; import the existing one. The ceiling is derived, not round, because a cap below a real document's sync is a data-loss bug strictly worse than the DoS it prevents. **The derivation, measured during planning** (`yjs` in this worktree, record it in the PR body): the largest legitimate inbound message is one client's full document state, and Yjs encodes a fresh document at **1.08×** its text length (100 kB → 107,923 B; 10 MB → 10,842,841 B), a char-by-char-typed document at **1.00×** (adjacent same-client items merge), and 500 annotation records carrying a 200-char body, a 200-char `textSnapshot` and a 120-char `relRange` at **299,712 B**. So a maximal 50 MB document syncs in ≈56.6 MB and 16 MiB of headroom covers the annotation map and awareness with room to spare. ws enforces this at the **frame header** — `receiver.js:439-451` (`haveLength`) rejects on the declared `_payloadLength` before any payload is accumulated — so the rejection is structurally before Hocuspocus's `onAuthenticate`, which is what the issue asks for. `listen`'s signature is `(portOrCallback = null, callback = null, websocketOptions = {})` and `typeof null !== "number"`, so the port already set in the constructor config survives; the options reach `new Server(this, websocketOptions)` → `new WebSocketServer({ noServer: true, ...websocketOptions })`. **Per Bryan: no connection-count ceiling.**

**Item 3 — `server.ts`.** Register a four-argument JSON error handler on **`mcpApp`**, immediately after the three `mcpApp.*("/mcp", …)` route definitions (the last ends at `:667`; register before the `app.use(mcpApp)` mount at `:761`). Verified by a standalone Express reproduction during planning that this placement (a) converts the over-limit 413 to `application/json` with no stack, (b) leaves normal `/mcp` routing at 200, and (c) leaves the outer app's SPA fallthrough intact — an error thrown in a mounted sub-app is offered to that sub-app's own error handlers before the parent's `finalhandler`. Shape: bail to `next(err)` when `res.headersSent`; use `err.status` when it is a number, else 500; body `{ error: "PAYLOAD_TOO_LARGE" | "INTERNAL_ERROR", message: <static copy> }` with **no `err.message` and no `err.stack`** on the wire. Also update `docs/security.md:166`'s citation from `src/server/mcp/server.ts:517-547` to the range that actually holds both parsers, and add one clause saying an over-limit body is answered with a JSON 413 carrying no stack. **Do not "fix" the 50 MB sentence — it is already correct.**

**Item 4 (issue item 7) — no code change.** The analysis and the reason are the deliverable. A 404 rule narrow enough to be safe cannot be written from the shape of the path: the SPA fallback is what serves every client route, and any route containing a dot — which is every deep link to a document whose id or name carries one — is indistinguishable from `/.git/HEAD` by pattern alone. Nothing is disclosed either way (`refuted.md:13`). Bryan's triage already records the disposition; this spec records the mechanism so the next reviewer does not re-derive it. **Post it as a comment on #1822 at ship time** so the "consider" item has a tracked outcome rather than silence.

**Item 5 (issue item 8) — split, and only half is code.**

- **`status: "licensed"` while dark: do NOT change.** Every consumer was enumerated and **all six are guarded** — `deriveLicenseUi` (`client/utils/license-ui.ts:69`, `!state.gateActive` early return), `useLicense.svelte.ts:47-48` (`s.gateActive && s.status === "restricted"`) and `:118` (`gateActive` only), `SettingsLicenseTab.svelte:36` and `:78` (`status?.gateActive &&`), `src-tauri/src/lib.rs:2565` (`update_route` returns `Public` on `!probe.gate_active`, before it reads `status`), and `cli/license.ts:62,66,73,91,161` (which reads `LicenseState` in-process, never the wire, and conjoins `state.gateActive` every time). So the issue's premise — "any consumer that forgets `gateActive`" — describes zero consumers today. Against that, three costs: the sentinel is documented at `routes/license.ts:22-28` as existing so an **older** client or Tauri shell talking to a newer sidecar stays byte-identical; `CLAUDE.md` requires the gate to stay byte-identical while dark; and `"inactive"` is not in `LicenseStatus` (`license/license-types.ts:31`) or in `LicenseStatusResponse["status"]` (`client/utils/license-ui.ts:15`), so it is a type change in two languages plus Rust's `Option<String>`. **Effect at the flip, which is the fact that settles it:** the sentinel lives only on the `!state.gateActive` arm, and that arm is unreachable once `LICENSE_GATE_ENABLED` flips — so changing it buys nothing after the flip and risks the dark window before it. Recommend to Bryan rather than change; listed under `bryan`.
- **`licenseInstalled` on the LAN-scrubbed wire: remove it.** Delete `licenseInstalled: darkInstallInfo().installed` from `scrubForNonLoopback`'s dark arm (`routes/license.ts:95`) and the field from that function's return type (`:86`). The loopback arm (`toLicenseStatusWire`, `:48-49`) is **untouched** — that is the one the desktop shell and a same-machine browser get, since `handleGetLicenseStatus` branches on `isLoopback(req.socket.remoteAddress)` (`:140`). A remote LAN caller cannot activate a license at all (`handleActivateLicense` runs `assertLoopbackForMutation`), so the field drove a confirmation for an action that caller can never take; `SettingsLicenseTab.svelte:40` reads `status?.licenseInstalled === true`, so absence renders as "no confirmation", not as a broken panel. Removing it also drops a real signal about the operator's purchase state from the LAN wire. **Critical Rule 9 does not bite** — this route reads, mutates nothing, and its row in `tests/server/license-gate-api-coverage.test.ts` is unchanged.
