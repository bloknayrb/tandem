## Fix

**BOM only.** `src/server/file-io/line-endings.ts` already owns the "source-encoding facts that must survive a round trip" pattern, with `normalizeAndRecordLineEnding(doc, text)` / `restoreLineEndings(doc, text)` called from exactly the two places a BOM has to be handled. Add the sibling pair beside them, and widen the module header from "line endings" to name both facts:

```ts
export function stripAndRecordBom(doc: Y.Doc, text: string): string {
  const has = text.charCodeAt(0) === 0xfeff;
  doc.getMap(Y_MAP_DOCUMENT_META).set(Y_MAP_BOM, has);
  return has ? text.slice(1) : text;
}
export function restoreBom(doc: Y.Doc, text: string): string {
  return doc.getMap(Y_MAP_DOCUMENT_META).get(Y_MAP_BOM) === true ? `<U+FEFF>${text}` : text;
}
```

Call sites, mirroring the line-ending ones exactly:
- `src/server/file-io/markdown.ts`: `mdParser.parse(stripAndRecordBom(doc, normalizeAndRecordLineEnding(doc, markdown)))` on load; `restoreBom(doc, restoreLineEndings(doc, …))` on save.
- `src/server/file-io/index.ts`, `plaintextAdapter`: the same two wrappings, so `.txt`/`.html` get it too.

**Third site, and it is not optional: the session-restore fallback mirror.** `src/server/documents/open.ts:991` mirrors exactly the adapter-import-written `documentMeta` keys — `for (const key of [Y_MAP_FOOTNOTE_BODIES, Y_MAP_FIDELITY_REPORT, Y_MAP_LINE_ENDING] as const) { if (scratchMeta.has(key)) liveMeta.set(…) else liveMeta.delete(key) }`. `Y_MAP_BOM` is a fourth key with `Y_MAP_LINE_ENDING`'s exact mechanism, so it **joins that array**, and the two comments that enumerate the set are updated with it: the mirror's own header at `:928-932` (which says set/delete rather than copy-when-present exists so "a 'copy when present' clone would leave the WINNER's value live over the FALLBACK's fragment") and the residue table at `:960-968` ("seven keys, four mechanisms, so nobody 'simplifies' one away" — now eight keys). Leaving it out is silent by construction: a fallback clone would keep the *winner's* BOM flag live over the *fallback's* fragment, writing a U+FEFF into a file that never had one, or dropping a real one, and nothing in the `loadMarkdown`/`saveMarkdown` specs below reaches `cloneFallbackIntoDoc`.

`Y_MAP_BOM = "bom"` joins `src/shared/constants.ts` next to `Y_MAP_LINE_ENDING`, with the same doc-comment shape — a `Y_MAP_DOCUMENT_META` field whose write is **inert for the channel and durable-sync subsystems** (no observer on per-doc `documentMeta`), which is the accurate form `populate.ts:91` already uses. Do **not** call it client-invisible: per-document `documentMeta` syncs to every connected browser over Hocuspocus, and the client reads the same map for `readOnly` / `fileName` / `format`.

Rules that bite, each having already broken something here: **Critical Rule 1** — the key is a `Y_MAP_*` constant, never a literal. **Critical Rule 2** — both functions write a Y.Map, so they run *inside* the caller's already-origin-tagged transact, exactly as `normalizeAndRecordLineEnding`'s header instructs; they add no `doc.transact` of their own (a raw one in `src/` is forbidden). **Strip before parse, restore after serialize** — a BOM left in the parsed text becomes a character in the first text node and shifts every flat offset by one, which is an annotation-coordinate bug, not a formatting one. `restoreBom` runs after `restoreLineEndings` as a convention (it survives a future `restoreLineEndings` that normalizes more than `\n`); it is not a tested invariant, because a BOM contains no `\n` or `\r` and the two compositions are byte-identical.

No MCP surface, no route, no error code — `docs/mcp-tools.md` unchanged.

## Tests

`tests/server/file-io/line-endings.test.ts` (existing home for the sibling pair):

1. `"<U+FEFF># Title\n"` round-trips byte-identical through `loadMarkdown`/`saveMarkdown`. Kills the whole defect.
2. A file **without** a BOM does not gain one (`"# Title\n"` unchanged) — kills a `restoreBom` that reads a missing key as truthy.
3. `"<U+FEFF>"` + CRLF content round-trips with the BOM first **and** CRLF endings intact — the two facts survive together, which is what a `.md` file from a Windows editor looks like.
4. **The discriminating one — the BOM lands off-body and offsets are unshifted.** `doc.getMap(Y_MAP_DOCUMENT_META).get(Y_MAP_BOM) === true`; `extractText(doc)` starts with `#`, not `<U+FEFF>`, and is byte-identical to the BOM-less twin's; and an `anchoredRange` over the first heading resolves to the same offsets as the twin. A "fix" that kept the BOM in the doc and stripped it at save time passes 1-3 and silently shifts every annotation.
5. Specs 1, 2 and 4 through the plaintext adapter for a `.txt` — a second call-site pair, and a fix applied only to `markdown.ts` passes every markdown spec.
6. **The fallback mirror carries `bom`.** One spec over `open.ts`'s `cloneFallbackIntoDoc`: with a live doc holding `bom: true` and a scratch (fallback) doc without it, the clone **deletes** `bom` from the live `documentMeta` — and with the scratch holding it, the clone sets it. Minimally acceptable substitute if the clone is awkward to drive in isolation: a source-level assertion that the mirror array at `open.ts:991` and the set of adapter-written `documentMeta` keys are the same set. Without either, a missing `Y_MAP_BOM` in that array is invisible to every test in this file.
7. No corpus fixture is added: `.gitattributes` normalization makes a committed BOM fixture unreliable in the way the corpus header already documents for CRLF. Synthesize the BOM in the spec.
