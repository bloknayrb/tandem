## Problem

`registerAnnotationObserver` (`src/server/annotations/sync.ts:253-255`) returns `(phase?: ObserverCleanupPhase) => void`, and its body is `return (phase: ObserverCleanupPhase = "close") => {` (`:303`). `loadAndMerge` repeats the optional form at `:548`. `src/server/events/file-sync-registry.ts` carries it three more times: the map value type (`:21`), `safeCleanup`'s `cleanup` parameter (`:32`), and `setFileSyncContext`'s `cleanup` parameter (`:63`).

Choosing `"close"` over `"swap"` decides whether the per-doc tombstone ledger survives. The wrong one serializes `tombstones: []` from an in-flight debounced write (#333). In production the default is never read: all four `safeCleanup` call sites pass a phase (`file-sync-registry.ts:72` `"close"`, `:89` `"close"`, `:112` `"swap"`, `:127` `"close"`). Its only audience is a *future* caller that omits the argument, and the type still permits that caller. `tests/server/annotations/sync.test.ts:1708` ("cleanup with no argument defaults to the close phase") describes what happens to such a caller. It does not refuse it.

**Measured on `caf54391`:** with the default dropped and all five `phase?` made required, `tsc -p tsconfig.server.json` stays **green** and `tsc -p tsconfig.tests.node.json` reports **55** errors:
- 52 are TS2554 in `tests/server/annotations/sync.test.ts`.
- 2 are TS2554 in `tests/server/annotations/perf.test.ts`, at `:97` and `:120`.
- 1 is TS2345 in `tests/server/remove-annotation.test.ts:38`: `observerCleanups: Array<() => void>` receives a handle.

The tests.client and tests.e2e programs were not probed, because the handle is server-only. `npm run typecheck:tests` runs all three and is the gate. The issue body also names `event-queue.test.ts`, `event-queue-observer-split.test.ts` and `rename-document.test.ts`, but **none of them errors**. Their cleanups are either passed a phase or are zero-arg lambdas, which remain assignable to a one-parameter function type.

## Fix

- `sync.ts:303`: `return (phase: ObserverCleanupPhase) => {`, with no default.
- `sync.ts:255` and `:548`: change `(phase?: ObserverCleanupPhase)` to `(phase: ObserverCleanupPhase)`. Update the doc comment at `:240-251` so it says the phase is required and why: #333, and a wrong phase is silent.
- `file-sync-registry.ts:21`, `:32` and `:63`: the same `phase?:` → `phase:` change. **`safeCleanup`'s body and its four call sites do not change.**
- Tests: turn every bare `cleanup()` reported by the probe into `cleanup("close")`. That is exactly the behaviour the default supplied at runtime, so no spec's meaning changes. Give `remove-annotation.test.ts:38`'s array the element type `Array<(phase: ObserverCleanupPhase) => void>`, and make its drain call pass `"close"`. **Touch only the sites `tsc` reports.** There are about 185 bare `cleanup()` calls tree-wide and most belong to unrelated helpers.
- **Delete** `sync.test.ts:1708`'s spec, "cleanup with no argument defaults to the close phase". It would guard something the type system now makes unrepresentable, as the issue itself says. Keep its two explicit-phase siblings, the close-phase ledger spec just above it and the swap-phase spec.
- No `src/` behaviour changes, no Y.Doc write (so Critical Rule 2 does not apply), and no Y.Map key.

## Tests

The type system is the test. Run `npm run typecheck:tests` and `npm run typecheck`, then vitest on `tests/server/annotations/sync.test.ts`, `annotations/perf.test.ts`, `remove-annotation.test.ts`, `event-queue.test.ts` and `event-queue-observer-split.test.ts`.

Mutation checks. Record each in the PR body, and restore from a file copy, never with `git checkout`.
1. Remove the `"close"` argument from one production call site, say `file-sync-registry.ts:89`, and watch `tsc -p tsconfig.server.json` go red with TS2554. This kills a future caller that omits the phase.
2. Put `?` back on `sync.ts:255` only, leaving the default removed. The test program stays **green**, because the fixed test sites all pass a phase. That shows the `?` is what made omission legal. Then remove one fixed `"close"` in `sync.test.ts` while the `?` is still restored: `tsc` stays green, but at runtime `phase` is `undefined`, the `=== "close"` branch is skipped, and the ledger leaks. Required-ness is the only guard, and this is the case it exists for.
3. Put `= "close"` back as a default while keeping the parameter required. `tsc` still refuses the bare call. That proves the pin spec's subject is gone, which justifies deleting it.
