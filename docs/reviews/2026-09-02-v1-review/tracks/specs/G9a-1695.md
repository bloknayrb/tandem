## Problem

`registerAnnotationObserver` (`src/server/annotations/sync.ts:253-255`) returns `(phase?: ObserverCleanupPhase) => void`, and its body is `return (phase: ObserverCleanupPhase = "close") => {` (`:303`). `loadAndMerge` repeats the optional form at `:548`. `src/server/events/file-sync-registry.ts` repeats it three more times: `:21` (map value), `:32` (`safeCleanup`'s `cleanup` parameter) and `:63` (`setFileSyncContext`'s `cleanup` parameter).

The wrong phase silently drops the per-doc tombstone ledger (#333).

- **The handle is invoked in exactly one production place:** `cleanup(phase);` at `file-sync-registry.ts:37`.
- `safeCleanup`'s OWN `phase` parameter (`:33`) is already required. Its call sites are `:72`, `:106`, `:129` and `:144`; `:144` is inside `resetForTesting` and is test-only. Removing an argument at any of them is TS2554 on `caf54391` already, so none of them can be evidence for this change.

**Measured on `caf54391`:** with the default dropped and all five `phase?` made required, `tsc -p tsconfig.server.json` stays green and `tsc -p tsconfig.tests.node.json` reports 55 errors:
- 52 are TS2554 in `tests/server/annotations/sync.test.ts`.
- 2 are TS2554 in `tests/server/annotations/perf.test.ts` (`:97`, `:120`).
- 1 is TS2345 in `tests/server/remove-annotation.test.ts:38`.

## Fix

- `sync.ts:303`: `return (phase: ObserverCleanupPhase) => {`, with no default.
- `sync.ts:255` and `:548`, and `file-sync-registry.ts:21`, `:32` and `:63`: change `phase?:` to `phase:`. Update the doc comment above `:253` so it says the phase is required, and why (#333, and a wrong phase fails silently).
- Tests: change only the sites `tsc` reports. A bare handle `cleanup()` becomes `cleanup("close")`, which is the value the default supplied at runtime. At `remove-annotation.test.ts:38` (where the handle is pushed), type the `observerCleanups` array as `Array<(phase: ObserverCleanupPhase) => void>`, and make its drain pass `"close"`. There are about 185 unrelated bare `cleanup()` calls; do not touch them.
- **Delete** the spec at `sync.test.ts:1708`, "cleanup with no argument defaults to the close phase". It guards a call the type now makes unrepresentable.
- No behaviour change in `src/`, no Y.Doc write and no Y.Map key.
