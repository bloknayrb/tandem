- **Bullet 2, second half** → **new file `tests/docs/license-header-parity.test.ts`**, in the established `tests/docs/*-claims` pattern and using the existing helper `tests/docs/rust-sources.ts` (already on master — `rustSourceDefining(pattern, what)`, which matches `.code` with comments and `#[cfg(test)]` modules stripped, and fails loudly on zero *or* two matches). The test:
  - **Locates by shape, never by the value under assertion, and reads a scoped body.** The round-1 draft prescribed `rustSourceDefining(/\.header\(\s*"X-Tandem-License-Id"/, …)`, which bakes the asserted literal into the resolver: a Rust-side rename then yields zero hits and fails *inside the locator* with "expected exactly one Rust source … to define …" — a message `rust-sources.ts`'s own docblock warns reads as "the walk is broken" rather than as drift — and it never reaches the equality assert or the positive control. Instead:
    - resolve the file with `rustSourceDefining(/async\s+fn\s+build_updater\s*\(/, "build_updater")` — the same anchor H-a's `compactBuildUpdaterBody()` uses (`tests/docs/license-flip-consts.test.ts:281-297`, written precisely because a whole-crate search matched the wrong `Ok(None)`);
    - brace-match `build_updater`'s body out of `source.code` — **`.code`, never `.text`** — and scan **only that body**. `lib.rs` holds three other `.header("…")` calls (`:297`, `:689`, `:691`), so a whole-file scan is ambiguous by construction;
    - extract with the **value-agnostic** `/\.header\(\s*"([^"]+)"\s*,\s*lid\s*\)/`, anchored on the second argument, and read capture group 1.
  - reads `LICENSE_HEADER` out of `infra/license-update-worker/src/worker.ts` by import, not by regex — it is a real export, so import it;
  - asserts the two are equal, **case-sensitively as written** (HTTP header names are case-insensitive on the wire, so this pins the source convention rather than a protocol requirement — say that in the comment, or the next reader will "fix" it to `toLowerCase()` and delete the drift signal). Both drift directions now fail on the equality assert, with a message naming the two values;
  - carries a **positive control**: assert the Rust file the helper resolved is `src-tauri/src/lib.rs`, so a walk that silently matched nothing cannot satisfy the assertion. `rust-sources.ts`'s own docblock requires this of every caller. **Re-verified post-rebase**: `build_updater` and the header write are both still in `lib.rs` after H-a's 456-line addition, so the control was checked rather than assumed.
  - `tests/docs/**` is in `tsconfig.tests.node.json` and runs in the required `check` job, so no further wiring is needed — this is a three-assert parity test, not a scanner.
  - **Its own comments spell section references in full — `docs/licensing-operations.md §N`, never a bare or parenthesised `§N`.** `tests/build/invariant-citations.test.ts:47` is `SCANNED_ROOTS = ["src", "src-tauri/src", "tests", "scripts", "infra"]` and only `tests/build/dangling-citations.ts` and `invariant-citations.test.ts` are self-excluded (`:53-56`), so this new file sits inside the scan exactly as an `infra/` file does. `H-b-1793.md` scoped that rule to `infra/**` through round 2; round 3 widened it to every file this PR adds or edits under any scanned root, and this file is one of them.
- **Bullet 3** → no code. Add nothing: `docs/licensing-operations.md` §8 already carries the line ("…and that the Worker's Ed25519 import works on real Cloudflare — it never has, and a key-import failure fails closed to 503 on *every* webhook"). Listed for Bryan.

## Tests

`tests/docs/license-header-parity.test.ts`, three assertions, all discriminating:

1. **The literals match.** Kills a rename on either side. Mutation-check by hand both ways (edit the Rust literal to `X-Tandem-Licence-Id`; edit `LICENSE_HEADER`) and restore **from a file copy, never `git checkout`** — a pin never seen red is not a pin. With the value-agnostic locator, **both** mutations now fail here with a message naming the two values, rather than one of them failing inside the locator.
2. **The resolved Rust file is `src-tauri/src/lib.rs`.** The positive control: without it, a helper that matched zero files would throw, but a future refactor that moves `build_updater` into a new module and leaves a stale duplicate would resolve ambiguously and the failure would read as a missing file rather than a drift.
3. **The extraction reads `.code`, and the scan is scoped to `build_updater`.** Two hand-run mutations, and round 2 replaced the second because it discriminated nothing:
   - **`.code`-vs-`.text`:** paste a commented-out `.header("X-Tandem-Licence-Id", lid)` **inside `build_updater`'s body, directly above the live line**, and confirm the test stays **green** — a red here means the extraction is reading `text`, which is the defeat the helper exists to close. This control only works because the pattern is value-agnostic: the round-1 draft's decoy did not match its own value-carrying pattern in `.text` either, so it stayed green under both extractions and proved nothing.
   - **Scoping needs a LIVE second match, not a commented-out one.** The round-1 draft's second variant ("the **correct** literal commented out") pins nothing: the extraction reads `source.code`, and `tests/docs/rust-sources.ts:89-92` strips every comment before matching, so a commented-out decoy of *any* value is invisible under a scoped and an unscoped implementation alike — the variant stays green either way. Measured: `lib.rs` holds `.header("…")` calls at `:297`, `:689` and `:691`, but **none takes `lid` as its second argument**, so `/\.header\(\s*"([^"]+)"\s*,\s*lid\s*\)/` already has exactly one hit file-wide and the scoping is currently unobservable. So: temporarily add a **live** `.header("X-Tandem-Wrong-Id", lid)` inside a *different* function in `lib.rs` (not `build_updater`), confirm the test stays green, and restore **from a file copy, never `git checkout`**. If that mutation is judged too invasive to run, drop the scoping claim from § Fix instead and record that the `, lid)` anchor — not the brace-matched body — is what makes the match unique today; do not leave a control in the spec that cannot fail.

The `isAlertable` and `revoke()` cases are covered by `H-b-1793.md` § Tests items 4 and 6–7. **Bullet 1's own control was strengthened in round 3**: round 2's `isAlertable` truth table could not distinguish the prescribed enumeration from `stage?.startsWith("config")` on any listed row, because `FailStage` (`infra/license-issuance-worker/src/worker.ts:121-127`) holds no non-alerting stage beginning `config`. `H-b-1793.md` Test 4 now carries an unknown-`config-*` row — the rule stated in § Tests 3 below (*do not leave a control in the spec that cannot fail*), applied to the bullet this spec maps onto.
