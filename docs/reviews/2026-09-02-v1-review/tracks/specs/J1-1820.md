## Problem

Four numbered gaps, all in `skills/tandem/SKILL.md` unless noted, plus four smaller "Also fold in" items — all named in #1820's own body:

1. **Hard Rule 4 is stale both ways** (`SKILL.md:25`). "Newlines become literal characters" is stated unconditionally. Since #1460 (`src/server/mcp/document.ts:689-696`), a literal newline in `newText` is refused `INVALID_ARGUMENT` in a plaintext-adapted document (`.txt`/an unrecognized extension). **Do not cite `.html` as an example** — `.html` opens read-only and answers `FORMAT_ERROR` first, per Rule 8, before the newline check runs. Markdown keeps a newline as a soft-wrapped literal break; `.docx` keeps it as a real run-level break (`src/shared/plaintext-format.ts`). The rule never names `tandem_appendContent` (Markdown-only, appends at the document end) or `tandem_editList` (Markdown/`.docx` only, list-shape changes) — the tools that actually take multi-block content.
2. **`tandem_annotationReply` is never named** (`SKILL.md:60`, "User comments"). The skill tells Claude to answer a user's reply on an annotation thread with `tandem_reply` (chat) or a new `tandem_comment` — never the actual reply tool (`src/server/mcp/annotations.ts:866-877`, "Reply to an annotation thread. Only works on pending annotations."). A thread reply gets answered in chat while the thread itself shows nothing.
3. **No rule against `Edit`/`Write` on a file open in Tandem.** Such a write bypasses Tandem's self-write-suppression pair (only Tandem's own `atomicWrite` call sites arm it), so the watcher (`src/server/documents/watcher.ts`) sees a genuine unexplained external change. If the session already holds unsaved edits, `tandem_save` later answers `EXTERNAL_CONFLICT`; if the session is clean, the watcher silently reloads from disk and re-anchors annotations with no signal at all. The skill has no rule warning against either outcome and no Error Recovery entry for the first.
4. **Sub-agent inbox polling** (`docs/workflows.md`, Multi-Model Workflow). `surfacedIds` (`src/server/mcp/awareness.ts:50`) is a process-global `Map`, not scoped per caller — a sub-agent's `tandem_checkInbox` marks items surfaced there, so the orchestrator's own next poll never sees them; the same call also durably stamps chat messages `read: true` in the Y.Doc. **Decision H** (2026-09-06): document orchestrator-only polling — a sub-agent must never call `tandem_checkInbox`. This must not contradict the skill's existing unconditional "poll every 2-3 tool calls" instructions (Workflow step 6, Collaboration Etiquette, Getting Woken While Idle).

Also fold in (all named in #1820's own body):

- **Rule 2 omits `textSnapshotTruncated`** (`src/server/mcp/output-schemas.ts:74-79`) — a stored annotation's `textSnapshot` can be capped at 200 chars; reusing a truncated one as a range guard elsewhere resolves a shorter span than the annotation covers.
- **Error Recovery has no `EXTERNAL_CONFLICT` or `NO_DOCUMENT` entry** — the latter is one of the most commonly returned codes (every `noDocumentError()` call site).
- **"Reacting to Document Events" says `selection` where the field is `anchor`** (`SKILL.md:75`; `src/server/mcp/awareness.ts:370` spreads `msg.anchor`).
- **The `.docx` workflow omits `heldFromExport`** (`SKILL.md:112` step 4) — `tandem_exportAnnotations` withholds Solo-held annotations and discloses the count as `heldFromExport` (`annotations.ts:826,845`; absent, not zero, when nothing is withheld; it does not count withheld replies).

## Fix

All in `skills/tandem/SKILL.md` (shipped skill — version bump required) except item 4's second half, which also touches `docs/workflows.md`.

**Hard Rules** (`SKILL.md:18-27`):

- Rewrite Rule 4 to state the format-conditional behavior above; do not cite `.html`. Name `tandem_appendContent`/`tandem_editList` as the tools for real multi-block content.
- Append one sentence to Rule 2: check `textSnapshotTruncated` before reusing a *stored* `textSnapshot` as a range guard elsewhere — a truncated one resolves short.
- Add a new Hard Rule: never edit a Tandem-open file with `Edit`/`Write` on your own initiative — you already know what's open from `tandem_status`/`tandem_listDocuments`; read it once this session if you haven't, before editing any file on disk. Name both consequences inline: an unsaved-work collision surfaces later as `tandem_save` answering `EXTERNAL_CONFLICT` — the user resolves it via the editor's Keep/Reload banner; `tandem_open({ force: true })` also clears it, but destructively (wipes the whole document's annotations, including private notes and un-promoted Word comments you cannot see — ADR-027), so never call it on your own initiative, ask the user first. A clean session instead silently reloads from disk with annotations re-anchored, with no error at all — so treat every out-of-band edit as unsafe. Cross-reference the existing "Absence of the toolset means stop" rule and distinguish scope: that one covers a session with no `tandem_*` tools at all; this one covers a file that *is* open with the real tools available.
- Add a new Hard Rule for decision H: a sub-agent dispatched by another Claude session must never call `tandem_checkInbox` — only the orchestrator polls in a multi-agent workflow, because the surfaced-item ledger and the chat `read: true` stamp are process-global rather than per-caller, and a sub-agent's poll durably drops the orchestrator's view of both. Reference "Multi-Model Workflow" as the absolute URL `https://github.com/bloknayrb/tandem/blob/master/docs/workflows.md#multi-model-workflow` (`SKILL.md` ships standalone via the npm `skills/` folder; a repo-relative link is dead in the installed copy and fails `npm run check:links`, which also scans `skills/`).
- Append a short "(orchestrator only in a multi-agent workflow)" parenthetical to the three existing unconditional polling mentions: Workflow step 6 (`SKILL.md:37`), Collaboration Etiquette (`:81`), Getting Woken While Idle (`:102`).
- Renumber the `.docx` rule after the two new rules; no wording change to it.

**Annotation Guide → "User comments"** (`SKILL.md:60`): make `tandem_annotationReply` the primary answer to a reply *on an annotation thread*, reserving `tandem_reply` for chat messages and a fresh `tandem_comment` for a new textual annotation. Name its refusal conditions: a resolved, note (ADR-027), highlight, or private (non-outbound) comment parent is refused, and `tandem_reply` is the fallback. Extend the adjacent "Before responding, check whether you already did" idempotency sentence to name all three tools (`tandem_reply`, `tandem_comment`, `tandem_annotationReply`) as non-idempotent.

**Reacting to Document Events** (`SKILL.md:75`): change "attached as a `selection` field" to "attached as an `anchor` field".

**.docx Review Workflow** (`SKILL.md:112` step 4): note that `heldFromExport` counts withheld Solo-held *annotations* (absent, not zero, when none are withheld) but not withheld *replies* on an otherwise-visible comment — a floor, not a total.

**Error Recovery** (`SKILL.md:166-171`): add `EXTERNAL_CONFLICT` (the user resolves it via the editor's Keep/Reload banner; `force: true` clears it too, destructively, and only on the user's say-so) and `NO_DOCUMENT` (call `tandem_open` first, or check `tandem_listDocuments`).

**`docs/workflows.md`** (Multi-Model Workflow, after the `tandem_getAnnotations({ author: "claude", status: "pending" })` example): add one sentence stating only the orchestrator polls `tandem_checkInbox`, because the surfaced-item ledger is process-global and the same poll marks chat read. Do not state a tool count — `docs/workflows.md` is on `tests/docs/tool-count-drift.test.ts`'s `DE_NUMBERED` list.

## Review corrections (scope cut)

Three adversarial rounds grew this spec well past what #1820 asks for — ten section-extraction helpers, fourteen assertions, and two mutation-pair tests, several of which turned out unsatisfiable against the spec's own prescribed Fix. Rather than adding an eleventh helper to repair the mismatch, the scaffolding is cut:

- **Removed the per-list-item extraction scheme** (`rule4()`, `rule6()`, and the Hard-Rules renumbering pinned by exact list position) — replaced with one `hardRules()` section-level helper. Rule content is what the tests check now, not list position, so the Fix no longer has to land in one exact renumbered shape.
- **Removed the two-helper `userCommentsParagraph()`/`beforeRespondingParagraph()` split.** That split produced an unsatisfiable Test 3: the first helper's terminator stopped right before the sentence the Fix actually edits. Replaced with a single `annotationGuideSection()` helper and one proximity assertion (Test 5) that doesn't depend on which paragraph the idempotency sentence lands in. This makes moot every finding restating that mismatch (three near-duplicates across rounds).
- **Removed both mutation-pair tests** (the Rule 7 direction-reversal harness, the Rule 6/Error-Recovery `force: true` strip-and-fail harness) — the issue asks for correct shipped content, not a mutation-testing harness proving each assertion is "load-bearing." Direction and proximity are pinned by the single regexes in Tests 2 and 3 without a second harness. This makes moot the Test-6 absence-check-vacuity finding: there is no longer a bare absence check to be vacuous against.
- **Removed the separate `collaborationEtiquette()`/`errorRecovery()`/`documentEvents()`/`workflowSection()` helpers and their three individual carve-out tests** for the "poll always" sites. The Fix still qualifies all three; the Done-when probe (reading the shipped file) verifies them, matching this group's original round-1 position that prose/etiquette sites are better checked by hand than pinned by brittle wording assertions.
- Two findings targeting the sibling `J1-1771.md` spec (the "always empty" wording, the claims-test fence scoping) were already resolved there in that spec's own round-3 corrections and needed no further change here.
