## Problem

Four numbered gaps in the issue body, plus four smaller "Also fold in" items, all in `skills/tandem/SKILL.md` unless noted:

1. **Hard Rule 4 is stale both ways** (`SKILL.md:25`). It says "Newlines become literal characters" unconditionally. Since #1460 (`src/server/mcp/document.ts:689-696`), a literal `\r`/`\n` in `newText` is refused with `INVALID_ARGUMENT` when the document is plaintext-adapted (`isPlaintextFormat`, `src/shared/plaintext-format.ts` — `.txt`, `.html`/`.htm`, and any unrecognized extension; Markdown and `.docx` are the two exemptions and there newlines really are still literal text). The rule also never names `tandem_appendContent` (`document.ts:1072`, Markdown-only, appends at the document end) or `tandem_editList` (`document.ts:901-905`, "Markdown and .docx documents only" — list-shape changes), which are the tools that actually take multi-block content.
2. **`tandem_annotationReply` is never named** (`SKILL.md:60`, "User comments"). It tells Claude to answer user comments with `tandem_reply` (chat) or a new `tandem_comment` — never the actual reply tool (`src/server/mcp/annotations.ts:866-877`, "Reply to an annotation thread. Only works on pending annotations."). So a user reply on an annotation thread gets answered in the chat panel while the thread itself shows nothing.
3. **No rule against `Edit`/`Write` on a file open in Tandem, and the consequence is two-branched.** A Claude Code session with the skill loaded routinely has the open file's path and reaches for its own `Edit`/`Write` tools. That write bypasses Tandem's self-write-suppression pair entirely (`docs/gotchas.md` "File-watcher self-write filtering" — `suppressNextChange()` / `recordSelfWrite()` are only called from Tandem's own `atomicWrite` call sites), so the watcher (`src/server/documents/watcher.ts:437-441`) sees a genuine unexplained external change. What happens next depends on session state, and the skill currently describes neither branch:
   - If the session **already holds unsaved edits** (`isDirty(id)`) or is already conflicted, the watcher sets `Y_MAP_EXTERNAL_CONFLICT` — the first the session hears of it is `tandem_save` answering `EXTERNAL_CONFLICT` (`document.ts:1247-1257`) with no rule that explains why.
   - **Otherwise** (a clean Y.Doc), the watcher takes the *other* branch: a silent `reloadFromDisk` (`watcher.ts:120-175`) that replaces the whole document body and re-anchors annotations via `refreshAllRanges` plus a `textSnapshot`-based relocation pass for stragglers — no error, no signal to Claude at all, and annotation ranges can relocate or degrade with nothing surfacing that it happened.

   The skill has no rule warning against either outcome and no scripted recovery in the Error Recovery table.
4. **Sub-agent inbox polling** (`docs/workflows.md:257-262`, Multi-Model Workflow). `surfacedIds` (`src/server/mcp/awareness.ts:50`) is a bare module-level `Map`, scoped only by `${documentId}:${annotationId}` — not by caller/session — so it is process-global across every MCP caller talking to one server. A sub-agent dispatched by an orchestrator (as the Multi-Model Workflow shows) that calls `tandem_checkInbox` marks those items surfaced in that same ledger; the orchestrator's own next `tandem_checkInbox` then sees them as already-shown and never receives them. **Decision H** (recorded 2026-09-06): document orchestrator-only polling — the shipped skill gains a rule that sub-agents must not call `tandem_checkInbox`; no per-session ledger keying. **This new rule must not be left to contradict the two existing unconditional polling instructions the skill already carries** — "Collaboration Etiquette" (`SKILL.md:81`, "**Call `tandem_checkInbox` every 2-3 tool calls**... steady polling is the reliable path, always... When in doubt, poll.") and "Getting Woken While Idle" (`SKILL.md:102`, "Keep polling every 2-3 tool calls regardless"). Left as-is, a sub-agent that loads this skill reads both "never poll" and "poll always" — a self-contradicting shipped behavioural document.

"Also fold in" (all four are named in #1820's own body, in scope for this PR):

- **Hard Rule 2 omits `textSnapshotTruncated`** (extends #1486). `textSnapshotTruncated` (`src/server/mcp/output-schemas.ts:74-79`) marks a stored annotation `textSnapshot` capped at 200 chars; reusing a truncated one as a range guard resolves to a shorter span than the annotation covers. Rule 2 tells Claude to pass `textSnapshot` but never mentions checking this flag before reusing a *stored* one. (It is documented only on the MCP output schema today — not in the skill at all.)
- **The Error Recovery table (`SKILL.md:166-171`) is narrow/stale.** It has no entry for `EXTERNAL_CONFLICT` (needed by item 3's new rule) or for `NO_DOCUMENT` (one of the most commonly returned codes — every `noDocumentError()` call site, 22 of them per the A8-1796 spec's audit — and currently entirely absent from the table).
- **"Reacting to Document Events" says `selection` where the field is `anchor`** (`SKILL.md:75`). The `chat:message` payload spreads `msg.anchor` (`src/server/mcp/awareness.ts:370`, `...(msg.anchor ? { anchor: msg.anchor } : {})`) — there is no `selection` field on it. (`activity.selectedText`, mentioned in the same paragraph, is correct as written — `awareness.ts:389,444` — and stays.)
- **The `.docx` workflow omits `heldFromExport`** (`SKILL.md:112`, step 4). `tandem_exportAnnotations` withholds Solo-held annotations from the export and discloses the withheld count as `heldFromExport` (`src/server/mcp/annotations.ts:647,826,845`; `docs/mcp-tools.md:781`) rather than silently omitting them — the skill's one-line description of the tool says nothing about this.

## Fix

All changes are in `skills/tandem/SKILL.md` (shipped skill — version bump required) except item 4's second half, which also touches `docs/workflows.md`.

**Hard Rules section** (`SKILL.md:18-27`) — rewrite rule 4, insert three new rules after it, renumbering the former rule 5 (`.docx` files) to 8, and qualify the two later polling bullets so they no longer contradict the new rule 7:

- Rule 4 (rewrite): state the real, format-conditional behavior — a literal newline in `newText` stays literal text in Markdown/`.docx` (soft wrap) but is refused `INVALID_ARGUMENT` in a plaintext-adapted document — and name `tandem_appendContent` / `tandem_editList` as the tools for real multi-paragraph/list content.
- Rule 5 (new, closes #1737 — see its own spec, `J1-1737.md`, for the exact text; the two issues land in the same commit range because they touch the same Hard Rules block and the wave notes group them together).
- Rule 6 (new, item 3): never edit a Tandem-open file with `Edit`/`Write`; check `tandem_listDocuments` first. Name **both** consequences up front, in the rule itself (not deferred entirely to the Error Recovery table, since the destructive half is exactly what CLAUDE.md's own gotcha for `force: true` warns is easy to miss at the point of use): if the session holds unsaved work, the write trips `EXTERNAL_CONFLICT` (recover via the editor's Keep/Reload banner, or `tandem_open({ force: true })` — which **discards unsaved edits and annotations, never mid-review**); if the session is clean, the write is silently reloaded from disk with annotations re-anchored (and possibly relocated) with no error at all — so treat every out-of-band edit as unsafe, not just the one that happens to surface. Cross-reference the existing "Absence of the toolset means stop" rule (`SKILL.md:134-137`, in "When the tandem_* Tools Are Absent") and distinguish scope explicitly: that rule covers a session with **no** `tandem_*` tools at all; this rule covers a session that **has** them, for a file that **is** open — the failure mode here is reaching for `Edit`/`Write` anyway despite having the real tools available.
- Rule 7 (new, item 4): only the orchestrator calls `tandem_checkInbox` in a multi-agent workflow; name the process-global ledger as the reason and point at "Multi-Model Workflow" in `docs/workflows.md`.
- Renumber former rule 5 (`.docx` files editable) to rule 8. No wording change to it.
- **Qualify the two contradicting polling bullets** so a sub-agent reading either one does not conclude it should poll:
  - "Collaboration Etiquette" (`SKILL.md:81`): append a clause to the existing bullet — e.g. "...always, **if you are the session talking directly to the user. A sub-agent dispatched by another Claude session must not call `tandem_checkInbox` at all — see Hard Rule 7.**" Keep the rest of the bullet (the de-duplication/`alreadyPushed` explanation) unchanged; it's still true for the orchestrator.
  - "Getting Woken While Idle" (`SKILL.md:102`, "Keep polling every 2-3 tool calls regardless"): append the same carve-out in short form, e.g. "(orchestrator only — a dispatched sub-agent does not poll at all; Hard Rule 7)".

**Rule 2** (textSnapshot): append one sentence — check `textSnapshotTruncated` before reusing a *stored* annotation `textSnapshot` as a range guard elsewhere; a truncated one resolves short.

**"Annotation Guide" → "User comments"** (`SKILL.md:60`, item 2): rewrite to make `tandem_annotationReply` the primary answer to a reply *on an annotation thread* (keeps the thread together), reserving `tandem_reply` for chat messages and a fresh `tandem_comment` for a new textual annotation rather than a threaded reply. Add a half-sentence naming its refusal conditions, since the rule now sends Claude to a tool it hasn't been told can say no: `tandem_annotationReply` only works on a **pending** thread — a resolved annotation, a note (ADR-027), or a private (non-outbound) comment parent is refused, and `tandem_reply` (chat) is the fallback when it is. Keep the existing "Before responding, check whether you already did" paragraph (`:62-64`) unchanged — it already covers both reply mechanisms generically.

**"Reacting to Document Events"** (`SKILL.md:75`): change "attached as a `selection` field" to "attached as an `anchor` field".

**".docx Review Workflow"** (`SKILL.md:112`, step 4, `tandem_exportAnnotations`): add a clause noting Solo-held annotations are withheld from the export and the count is disclosed as `heldFromExport`.

**Error Recovery** (`SKILL.md:166-171`): add two entries.

- `EXTERNAL_CONFLICT` — cite the exact recovery `document.ts:1253-1257` already gives at the tool-response level (editor Keep/Reload; `tandem_open({ force: true })` discards unsaved edits and annotations) — restated briefly, since Hard Rule 6 above is where the *cause* (an out-of-band `Edit`/`Write`, and the silent-reload alternative when the session was clean) is explained; don't duplicate that half here.
- `NO_DOCUMENT` — call `tandem_open` first, or check `tandem_listDocuments` for the right `documentId`.

**`docs/workflows.md`** ("Multi-Model Workflow", after the `tandem_getAnnotations({ author: "claude", status: "pending" })` example at `:257-262`): add one sentence stating only Opus (the orchestrator) polls `tandem_checkInbox`, because the surfaced-item ledger is process-global rather than per-caller, and dispatched sub-agents get their work directly rather than by polling the inbox themselves.
