# C — #1733 Server-side mode provenance: record which connection last wrote `mode`

Branch `fix/privacy-and-authority-1769`. Closes #1733, scoped as the sweep ledger says: the conditional release lands under C-1769; this spec is **the provenance field and nothing more**. Ledger: `docs/plans/2026-09-06-open-issues-sweep.md:80`. Probe: the v0.24.1 measurement in the issue body (`tandem_status` said `solo` for minutes while the toggle read Tandem, with no signal on either side).

## Problem

The client-side detector (`useTandemModeBroadcast.svelte.ts:235-266`) compares the room against `lastBroadcast`, so it sees only disagreements this client is party to and can never say WHO wrote the other value. The server can: every client write reaches CTRL_ROOM through Hocuspocus, which applies it with the `Connection` as the transaction origin (`node_modules/@hocuspocus/server/dist/hocuspocus-server.esm.js:1408` — `connection ?? this.defaultTransactionOrigin`; `Connection` carries `socketId`, `:1456-1470`). Server-side writes carry a helper tag string (`shared/origins.ts:33-73`), and the ctrl-session restore applies with no origin at all (`session/manager.ts:827`). Nothing records any of it, so `tandem_status` (`mcp/document.ts:1341`) and `tandem_checkInbox` (`awareness.ts:386`) report a value with no provenance.

## Fix

- **`src/server/mode.ts`** — this file is pinned as a reader by `tests/shared/mode-writer-set.test.ts` ("keeps every mention-only file free of awareness-map writes"): the addition observes and never writes. Add:
  - `export type ModeProvenance = { source: "client"; connection: string; at: number } | { source: "server"; origin: string; at: number } | { source: "restore" | "unknown"; at: number }`.
  - A module-level `let lastModeWrite: ModeProvenance | null = null` and `export function readModeProvenance(): ModeProvenance | null`.
  - `export function installModeProvenanceObserver(ctrlDoc: Y.Doc): () => void`: observes `ctrlDoc.getMap(Y_MAP_USER_AWARENESS)` (Critical Rule 1 — both keys from `shared/constants.ts`); on `event.keysChanged.has(Y_MAP_MODE)` classify `txn.origin`: an object with a string `socketId` → `client` with `connection: socketId.slice(0, 8)` (an opaque tag, enough to tell two windows apart; never the request or headers); a string → `server` with `origin` = the tag (`"internal"`, `"test"`, …); anything else → `unknown`. At install time, if the key is already present and nothing is recorded, set `{ source: "restore", at: Date.now() }` — `restoreCtrlSession` runs before `attachCtrlObservers` (`src/server/index.ts:488,506`), so the replayed write is never observed and this is the only honest label for it. Returns the unobserve cleanup.
- **`events/queue.ts:533` `attachCtrlObservers`** — push `installModeProvenanceObserver(ctrlDoc)` into `ctrlCleanups`, so `reattachCtrlObservers` re-installs it after the Hocuspocus doc swap (CLAUDE.md, `onDocSwapped`). `queue.ts` already imports `readModeState` from `../mode.js` (`:21`).
- **Surface it, additively.** `tandem_status` read mode (`document.ts:1352-1367`) adds `modeProvenance: readModeProvenance()`; `tandem_checkInbox` (`awareness.ts`, beside `mode` in the structured result) adds the same. `output-schemas.ts`: one `modeProvenanceSchema` (`z.object({ source: z.enum([...]), at: z.number(), connection: z.string().optional(), origin: z.string().optional() }).nullable()`), added as `.optional()` on `statusOutputShape` (`:141`, beside `mode`) and required-nullable on `checkInboxOutputShape` (`:243`). The MCP SDK hard-validates structured output (`awareness.ts:648-653`), so the schema must admit every shape the union produces — pin it with the round-trip test below.
- **`docs/mcp-tools.md`** `:432-446` (status return) and `:1016-1040` (checkInbox return + notes): one line each — `modeProvenance` says who last wrote the mode (`client` + connection tag, `server` + origin, `restore`, `unknown`) and when; `null` before any write is observed.
- `EXPECTED_MENTIONS` in `mode-writer-set.test.ts` is unchanged: `mode.ts`, `document.ts` and the hook already mention `Y_MAP_MODE`; `awareness.ts` reads provenance through the function, not the constant.

## Tests

`tests/server/mode-provenance.test.ts`, fixture from `mode-release.test.ts:42-49` (`setMode` under `withInternal`) plus the scratch-doc `sync` helper from `tests/client/tandem-mode-race.test.ts:23-25` with a `{ socketId: "0123456789abcdef" }` origin:

1. Install on an empty ctrl doc → `readModeProvenance()` is `null` (kills a default that fabricates `restore`).
2. Apply a `"solo"` write with the socket-shaped origin → `{ source: "client", connection: "01234567", at }`; `at` within the test's clock bounds. A second write with a different `socketId` replaces it (kills "first writer wins").
3. `withInternal` write → `{ source: "server", origin: "internal" }`; `Y.applyUpdate` with no origin → `unknown`.
4. Seed the key BEFORE install (the restore order) → `restore`; then a client write overrides it.
5. `reattachCtrlObservers()` → a later client write is still recorded (kills an observer that dies with the first doc), and the old observer is unobserved (write count on the old doc stays flat — the `:399` "exactly one observer per ctrl doc" pattern).
6. Handler round-trip in `tests/server/mcp-tool-integration.test.ts` (`setupMcpClient()`, `:54-66`): after a socket-origin write, `tandem_status` and `tandem_checkInbox` both carry `modeProvenance.source === "client"`; before any write both carry `null` — the structured-output validation is what this pins (a schema that omits `connection` throws `InvalidParams` on the whole response).

## Done when

Six cases green; both tools carry the field; docs updated; `mode-writer-set` unchanged and green.

## Not in scope
