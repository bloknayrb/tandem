# C — #1733 Server-side mode provenance: record which connection last wrote `mode`

Branch `fix/privacy-and-authority-1769`. Closes #1733, scoped as the sweep ledger says: the conditional release lands under C-1769; this spec is **the provenance field and nothing more**. Ledger: `docs/plans/2026-09-06-open-issues-sweep.md:80`. Probe: the v0.24.1 measurement in the issue body (`tandem_status` said `solo` for minutes while the toggle read Tandem).

## Problem

The client-side detector (`useTandemModeBroadcast.svelte.ts:235-266`) compares the room against `lastBroadcast`, so it sees only disagreements this client is party to and can never say WHO wrote the other value. The server can: every client write reaches CTRL_ROOM through Hocuspocus, which applies it with the `Connection` as transaction origin (`hocuspocus-server.esm.js:1408`; `Connection.socketId` is a `uuid.v4()`). Server-side writes carry a helper tag string (`shared/origins.ts:33-73`); the ctrl-session restore applies with no origin (`session/manager.ts:827`). Nothing records any of it.

## Fix

- **`src/server/mode.ts`** — pinned as a reader by `tests/shared/mode-writer-set.test.ts` (its third describe forbids `.set(` shapes against the awareness map; exports are fine): the addition observes and never writes.
  - `export type ModeProvenance = ({ source: "client"; connection: string } | { source: "server"; origin: string } | { source: "restore" | "unknown" }) & { at: number; value: ModeState }`.
  - Module-level `let lastModeWrite: ModeProvenance | null = null`; `export function readModeProvenance()`; `export function _resetModeProvenanceForTests()` (the `queue.ts#resetForTesting` pattern — module state with no reset makes every "is `null`" row depend on suite order).
  - `export function installModeProvenanceObserver(ctrlDoc: Y.Doc): () => void`: observes `ctrlDoc.getMap(Y_MAP_USER_AWARENESS)` (Critical Rule 1 — both keys from `shared/constants.ts`); on `event.keysChanged.has(Y_MAP_MODE)` classify `txn.origin`: an object with a string `socketId` → `client` with `connection: socketId.slice(0, 8)` (an opaque per-connection tag Tandem keys nothing on; never the socket, request or headers); a string → `server` with `origin` = the tag; anything else → `unknown`. `value` is `readModeState()` at observation time. At install, if the key is already present AND `lastModeWrite === null`, record `{ source: "restore", at, value }` — `restoreCtrlSession` runs before `attachCtrlObservers` (`src/server/index.ts:488`, `:506`), so the replayed write is never observed. The `=== null` conjunct is load-bearing: the production swap (`yjs/provider.ts:171-172`) copies the old doc's state, so the key IS present when `reattachCtrlObservers` re-installs, and without it a live `client` record is relabelled `restore` mid-session. Returns the unobserve cleanup; the cleanup does NOT reset `lastModeWrite`.
  - Docblock: the field names the last TRANSACTION that touched the key, not necessarily the writer of the value `mode` reports — under a lost concurrent tie (#1621) the losing write still puts `Y_MAP_MODE` in `keysChanged`, so `connection` can name one writer while `mode` carries another's value; recording `value` is what lets a reader see the two diverge.
- **`events/queue.ts:533` `attachCtrlObservers`** — push `installModeProvenanceObserver(ctrlDoc)` into `ctrlCleanups` so the doc swap re-installs it (`queue.ts` already imports from `../mode.js`).
- **Surface, additively.** `tandem_status` read mode (`document.ts:1352-1367`) and `tandem_checkInbox` (`awareness.ts`, beside `mode`) add `modeProvenance: readModeProvenance()`. `output-schemas.ts`: one `modeProvenanceSchema` (`z.object({ source: z.enum(["client","server","restore","unknown"]), at: z.number(), value: z.enum(["solo","tandem","indeterminate"]), connection: z.string().optional(), origin: z.string().optional() }).nullable()`), `.optional()` on `statusOutputShape` (`:141`) and required-nullable on `checkInboxOutputShape` (`:243`). The SDK hard-validates structured output (`awareness.ts:648-653`), so the schema must admit every arm of the union — Test 6 pins it.
- **`docs/mcp-tools.md`** `:432-446` (status) and `:1016-1040` (checkInbox): one line each — `modeProvenance` says who last wrote the mode key (`client` + opaque connection tag, `server` + origin, `restore`, `unknown`), when, and what the key read at that moment; `null` before any write is observed; under a lost concurrent tie it is not necessarily the writer of the reported `mode` — compare `value` against `mode`. The field reaches MCP only (loopback, or token-gated on LAN); **keep it off `GET /api/mode`** (`routes/mode.ts:4-8`, LAN-readable).
- `EXPECTED_MENTIONS` in `mode-writer-set.test.ts` is unchanged by this spec (`mode.ts` and `document.ts` already mention the constant; `awareness.ts` reads through the function). C-1769 is the one edit to that file.

## Tests

`tests/server/mode-provenance.test.ts`, fixture from `mode-release.test.ts:42-49` (`setMode` under `withInternal`) plus the sync-first remote-write shape from `tests/client/tandem-mode-race.test.ts:88-93` with a `{ socketId: "0123456789abcdef" }` origin. `beforeEach` calls `_resetModeProvenanceForTests()` and `resetForTesting()`.

1. Install on an empty ctrl doc → `readModeProvenance()` is `null` (kills a default that fabricates `restore`).
2. A `"solo"` write with the socket-shaped origin → `{ source: "client", connection: "01234567", at, value: "solo" }`; a second write with a different `socketId` replaces it (kills "first writer wins").
3. `withInternal` write → `{ source: "server", origin: "internal", value }`; `Y.applyUpdate` with no origin → `unknown`.
4. Seed the key BEFORE install → `restore`; a client write then overrides it.
5. Reattach: after a client write, `removeDocument(CTRL_ROOM)` (`yjs/provider.ts:64`; `annotation-promote-pull-surface.test.ts` does this), apply the old doc's state to the new ctrl doc (as the production swap does — the key must be PRESENT at re-install), then `reattachCtrlObservers()` → the pre-swap `client` record is still there with `source` unchanged (kills both a reset in the cleanup and a relabel-as-`restore`), and a client write on the NEW doc is recorded.
6. Handler round-trip in `tests/server/mcp-tool-integration.test.ts` (`setupMcpClient()`): after a socket-origin write, `tandem_status` and `tandem_checkInbox` carry `modeProvenance.source === "client"` and `.value`; after the reset both carry `null` — the structured-output validation is what this pins.

## Done when

Six cases green; both tools carry the field; docs updated with the "last write that touched the key" wording; `mode-writer-set` green with C-1769's edit and nothing else.
