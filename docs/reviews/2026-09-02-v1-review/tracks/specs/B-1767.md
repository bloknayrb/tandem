# B — #1767 The 200-unit `textSnapshot` slice has no surrogate guard, so a split emoji becomes U+FFFD

Branch `fix/annotation-anchors-1764`. Closes #1767. Ledger: `docs/reviews/2026-09-02-v1-review/areas/crdt.md:22`. Probe: `experiments/e6-snapshot.ts`, `experiments/e6b.ts` (`post-roundtrip contradicts: true`; the JSON disk path stays `false`).

## Problem

`captureSnapshot` (`src/server/mcp/annotations.ts:186-202`) caps at `SNAPSHOT_CAP` with a plain `text.slice(0, SNAPSHOT_CAP)`. When the 200th UTF-16 unit is the high half of a surrogate pair the stored snapshot ends in a lone surrogate. In process it still matches. After any Yjs `encodeStateAsUpdate` round-trip — session persist, doc swap, every client sync — the lone surrogate is re-encoded as U+FFFD, and the snapshot no longer occurs in the document. The watcher's relocation pass (`src/server/documents/watcher.ts:250`) searches with `snapshotSearchPrefix` and gets nothing, so the annotation is `RANGE_GONE` and stays pinned to its stale coordinates permanently; `snapshotContradicts` flips true, so Accept refuses the suggestion. The JSON envelope on disk is lossless — only the CRDT path corrupts, which is why this looks fine until a restart.

Every corrupted record is by construction a **truncated** one: the lone surrogate can only appear at the cap, and the cap sets `truncated: true`. That is what makes the healing half a one-line change in one place — **and it is why the change has to go on the flag-bearing branch, not the legacy one.**

## Fix

Two edits, both on the one code path each rule already lives on.

- **`src/server/mcp/annotations.ts` `captureSnapshot`** — when capping, back the slice off by one if the cut splits a pair:
  ```
  const cap = splitsSurrogatePair(text, SNAPSHOT_CAP) ? SNAPSHOT_CAP - 1 : SNAPSHOT_CAP;
  const kept = capped ? text.slice(0, cap) : text;
  ```
  `splitsSurrogatePair` is the existing **paired** predicate exported from `src/server/positions.ts` (`annotations.ts` already re-exports `refreshRange`/`refreshAllRanges` from that module, so the edge exists). Use it, not a one-sided `charCodeAt` test — CLAUDE.md Critical Rule 4 and the predicate's own docstring record why the one-sided form is wrong. `truncated` still comes from `text.length > SNAPSHOT_CAP`, unchanged: the record is truncated whether or not the back-off happened, and `isSnapshotTruncated`'s legacy branch keys on `length === SNAPSHOT_CAP` **and** a trailing ellipsis, so a 199-unit snapshot does not become undetectable. The `breaks` filter is already bounded by `from + kept.length`, so it follows the shorter slice with no change.
- **`src/shared/snapshot.ts` `snapshotSearchPrefix`** — heal both truncated branches. **The placement is the whole point of this edit and the obvious phrasing gets it wrong.** The function is:
  ```
  const snapshot = ann.textSnapshot;
  if (typeof snapshot !== "string") return "";
  if (!isSnapshotTruncated(ann)) return snapshot;          // non-truncated: untouched
  if (ann.textSnapshotTruncated === true) return snapshot;  // <- flag-bearing records return HERE
  return snapshot.slice(0, -LEGACY_ELLIPSIS.length);        // <- the "legacy-ellipsis trim"
  ```
  Every record this fix targets carries `textSnapshotTruncated: true` (`captureSnapshot` has set it since #1486), so it takes the **third** line and never reaches the trim. A trim added "after the legacy-ellipsis trim" is unreachable for exactly the population it is for. Restructure instead, so both truncated paths are healed and the non-truncated equality path is untouched:
  ```
  if (!isSnapshotTruncated(ann)) return snapshot;
  const base =
    ann.textSnapshotTruncated === true ? snapshot : snapshot.slice(0, -LEGACY_ELLIPSIS.length);
  return dropSplitTail(base);
  ```
  where `dropSplitTail` drops one trailing unit when it is an unpaired high surrogate (a record written before this fix, read back before any Yjs round-trip) or a trailing `U+FFFD` (the same record after one).
  **`dropSplitTail` defines its own trailing-unit test locally, in `src/shared/snapshot.ts`, and that one-sided form is correct there.** `src/shared/` cannot import `src/server/positions.ts`, and the one-sided helpers there are module-private on purpose — `isLowSurrogate`'s docblock (`positions.ts:172-182`) records that it was un-exported because "is this unit a surrogate" is the wrong question *about an offset*. This is not an offset test: it asks whether the **last unit of a string** is a high surrogate, which is unpaired by construction because there is no following unit. So it is not a fifth reading of Critical Rule 4's predicate and must not be "fixed" into `splitsSurrogatePair`, which needs a following unit to compare against. This is the single place the rule can live: the watcher's relocation probe (`watcher.ts:250`) and `snapshotContradicts`' truncated branch (`snapshot.ts:174-175`) both read this function, so one edit heals both, and `src/shared/snapshot.ts`'s own header says a second copy of the rule is how the two drift. Shortening a search prefix is always safe — a prefix of a prefix is still a prefix — so the false-positive cost of also stripping a legitimate trailing U+FFFD is one character of search specificity.
  Do **not** touch `snapshotContradicts`' non-truncated branch — but not for the reason it is tempting to write. An uncapped snapshot **was** sliced: `captureSnapshot` does `const text = fullText.slice(from, to)` unconditionally (`annotations.ts:190`), before the cap ever comes up. What actually makes the non-truncated branch safe is a **standing constraint on the callers**: both `captureSnapshot` call sites validate their range with the default `surrogates: "reject"` — `annotations.ts:316` through `store.anchorRange` (`document-store.ts:283-289`) and `local-model/tools.ts:253` through `anchoredRange(..., { rejectHeadingOverlap: true })` — so `from` and `to` are pair-safe by the time the slice happens. A future `captureSnapshot` caller passing `surrogates: "ignore"` would reopen this on the non-truncated branch, where no cap and therefore no `truncated` flag exists to route it through the heal.

**Rules that bite.** Critical Rule 4: the surrogate predicate is the paired form and the four `surrogates: "ignore"` callers are unchanged — this fix adds none. Critical Rule 2: no Y.Doc write is added; `captureSnapshot` is read-only.

## Tests

**One typing constraint for tests 1 and 4.** Do **not** assert with `String.prototype.isWellFormed()`: it is ES2024 and this repo's `lib` is `["ES2022", "DOM", "DOM.Iterable"]` (`tsconfig.json:3`, which `tsconfig.tests.node.json` extends adding only `noEmit`/`allowJs`), so the call is TS2339 and fails `npm run typecheck:tests` — the very gate these specs' Done-when names. (`experiments/e6-snapshot.ts:38` had to work around it with a cast.) Use a lone-surrogate regex instead: `expect(/[\uD800-\uDBFF](?![\uDC00-\uDFFF])|(?<![\uD800-\uDBFF])[\uDC00-\uDFFF]/.test(snap.text)).toBe(false)`. Do not raise `lib` for a test.

1. `tests/server/annotation-text-snapshot.test.ts` — build text whose unit at index 199 is the high half of a pair (199 filler units then an astral character); `captureSnapshot` returns a snapshot of length **199**, no lone surrogate (per the regex above), `truncated: true`. Kills the unguarded slice and a fix that returns 200 units with a replacement character.
2. Same file — the **negative twin**: a cap that lands on a normal boundary still returns exactly `SNAPSHOT_CAP` units. Kills an unconditional `- 1`.
3. Same file — a cap landing between two *adjacent* astral characters (the boundary at 200 is legal because the unit before it is a low surrogate) still returns 200. Kills a one-sided "is the unit at the cap a surrogate" check, which is the wrong predicate and the reason `splitsSurrogatePair` exists.
4. Same file — **round-trip, through the Y.Map**. `captureSnapshot` returns a detached plain object (`{ text, truncated, breaks }`) and writes nothing; the caller at `annotations.ts:316-325` is what stores `textSnapshot` into the annotation record. Encoding a doc whose Y.Map never held the snapshot exercises no lib0 UTF-8 encode and would pass on the unfixed code. So: capture, **write the snapshot into the annotation record in the Y.Map**, `Y.encodeStateAsUpdate` into a second doc, **read the record back from the second doc's map**, and assert the snapshot is unchanged, carries no lone surrogate (the regex above), and is still found by `indexOf` in the second doc's flat text. This is `e6-snapshot.ts` as a spec, and it is the test that actually reproduces the issue rather than the slice arithmetic.
5. `tests/shared/snapshot-contradicts.test.ts` — the healing, with both truncated shapes named correctly:
   - **a record this build wrote** (`textSnapshotTruncated: true`, `textSnapshot` ending in `U+FFFD`, `actual` the real text): `snapshotContradicts` is **false** and `snapshotSearchPrefix` returns the string minus the U+FFFD. Same with a trailing lone high surrogate. This is the case the old placement instruction could not reach, so it is also the test that kills the wrong placement.
   - **a legacy ellipsis record** (no `textSnapshotTruncated`, `length === SNAPSHOT_CAP`, trailing `"..."`, and one trailing split unit before it): the ellipsis **and** the split unit are both trimmed.
   - the discriminating negatives: a snapshot ending in U+FFFD on a record that is **not** truncated is untouched (still compared by equality); and a truncated snapshot whose text genuinely no longer matches still contradicts. Without the last one the fix could make `snapshotContradicts` unreachable and nothing would notice.
6. `tests/server/snapshot-truncation-reload.test.ts` — the relocation pass finds and relocates an annotation whose stored snapshot ends in U+FFFD, instead of logging `RANGE_GONE`.

## Assumptions

- **The back-off shortens the snapshot rather than extending past the cap.** The cap bounds record size against pathological ranges (#1000 review R2) and must not be exceeded, so 199 is the answer, not 201.
- **Legacy healing is a search-prefix trim, not a stored-record migration.** Rewriting snapshots already on disk would be a write from a read path — exactly what #1764 is removing.
- **"Legacy" here means the ellipsis writer, and it is not the corrupted population.** The records this fix heals are the flag-bearing ones this build writes; the ellipsis branch is healed too, for completeness, but it cannot hold a lone surrogate at the cap.
- **`textSnapshotTruncated` stays keyed on the original `text.length > SNAPSHOT_CAP`**, not on the length of the kept slice.

## Not in scope

`src/client/layout/rail-content.svelte.ts`'s own `slice(0, SNAPSHOT_CAP - 3)` for the chat anchor: a `ChatAnchor` is never written back into the document and is explicitly excluded from `SnapshotBearing`, and the issue names `annotations.ts` alone. Widening `SNAPSHOT_CAP`. Grapheme-cluster (ZWJ sequence, combining mark) boundaries — only the lone surrogate is corrupted by the encode.
