# B — #1767 The 200-unit `textSnapshot` slice has no surrogate guard, so a split emoji becomes U+FFFD

Branch `fix/annotation-anchors-1764`. Closes #1767. Ledger: `docs/reviews/2026-09-02-v1-review/areas/crdt.md:22`. Measurement: `experiments/e6-snapshot.ts`, `experiments/e6b.ts`.

## Problem

`captureSnapshot` (`src/server/mcp/annotations.ts:186-202`) caps at `SNAPSHOT_CAP` with a plain `text.slice(0, SNAPSHOT_CAP)`. When the 200th UTF-16 unit is the high half of a surrogate pair the stored snapshot ends in a lone surrogate. In process it still matches. After any Yjs `encodeStateAsUpdate` round-trip — session persist, doc swap, every client sync — the lone surrogate is re-encoded as U+FFFD and the snapshot no longer occurs in the document: the watcher's relocation pass (`src/server/documents/watcher.ts:250`) searches with `snapshotSearchPrefix`, finds nothing, reports `RANGE_GONE`, and the annotation stays pinned to stale coordinates forever; `snapshotContradicts` flips true, so Accept refuses the suggestion. The JSON envelope on disk is lossless — only the CRDT path corrupts, which is why this looks fine until a restart.

Every corrupted record is by construction a **truncated** one: the lone surrogate can only appear at the cap, and the cap sets `truncated: true`.

## Fix

Two edits, each on the path its rule already lives on.

- **`src/server/mcp/annotations.ts` `captureSnapshot`** — back the slice off by one when the cut splits a pair:
  ```
  const cap = splitsSurrogatePair(text, SNAPSHOT_CAP) ? SNAPSHOT_CAP - 1 : SNAPSHOT_CAP;
  const kept = capped ? text.slice(0, cap) : text;
  ```
  `splitsSurrogatePair` is the existing **paired** predicate exported from `src/server/positions.ts` (`annotations.ts` already imports from that module). Use it, not a one-sided `charCodeAt` test — Critical Rule 4 and the predicate's own docstring record why the one-sided form is wrong. `truncated` still comes from `text.length > SNAPSHOT_CAP`, unchanged: the record is truncated whether or not the back-off happened, and `isSnapshotTruncated`'s legacy branch keys on `length === SNAPSHOT_CAP` **and** a trailing ellipsis, so a 199-unit snapshot does not become undetectable. The `breaks` filter is already bounded by `from + kept.length`.
- **`src/shared/snapshot.ts` `snapshotSearchPrefix`** — heal both truncated branches. **The placement is the whole point and the obvious phrasing gets it wrong.** The function reads:
  ```
  if (!isSnapshotTruncated(ann)) return snapshot;           // non-truncated: untouched
  if (ann.textSnapshotTruncated === true) return snapshot;   // <- every record this fix targets returns HERE
  return snapshot.slice(0, -LEGACY_ELLIPSIS.length);         // <- the "legacy-ellipsis trim"
  ```
  `captureSnapshot` has set `textSnapshotTruncated` since #1486, so a heal added "after the legacy-ellipsis trim" is unreachable for exactly the population it is for. Restructure:
  ```
  if (!isSnapshotTruncated(ann)) return snapshot;
  const base =
    ann.textSnapshotTruncated === true ? snapshot : snapshot.slice(0, -LEGACY_ELLIPSIS.length);
  return dropSplitTail(base);
  ```
  `dropSplitTail` drops one trailing unit when it is an unpaired high surrogate (a record written before this fix, read back before any round-trip) or a trailing `U+FFFD` (the same record after one). Shortening a search prefix is always safe — a prefix of a prefix is still a prefix — so stripping a legitimate trailing U+FFFD costs one character of search specificity. One edit heals both readers: the watcher's relocation probe and `snapshotContradicts`' truncated branch both go through this function, and `src/shared/snapshot.ts`'s own header says a second copy of the rule is how the two drift.
  **`dropSplitTail` defines its trailing-unit test locally, and the one-sided form is correct there.** `src/shared/` cannot import `src/server/positions.ts`, and the one-sided helpers there are module-private on purpose (`isLowSurrogate`'s docblock, `positions.ts:172-182`) because "is this unit a surrogate" is the wrong question *about an offset*. This asks whether the **last unit of a string** is a high surrogate, unpaired by construction because nothing follows it. It is not a fifth reading of Critical Rule 4 and must not be "fixed" into `splitsSurrogatePair`, which needs a following unit.
- **`snapshotContradicts`' non-truncated branch is untouched**, and the reason is a standing constraint on the callers, not "an uncapped snapshot was never sliced" (`captureSnapshot` slices unconditionally at `annotations.ts:190`): both call sites validate their range with the default `surrogates: "reject"` (`annotations.ts:316` → `document-store.ts:283-289`; `local-model/tools.ts:253` → `anchoredRange`), so `from` and `to` are pair-safe. A future `captureSnapshot` caller passing `"ignore"` would reopen this, where no cap and therefore no `truncated` flag exists to route it through the heal.

**Rules that bite.** Critical Rule 4: the surrogate predicate is the paired form and the four `"ignore"` callers are unchanged — this adds none. Critical Rule 2: no Y.Doc write is added; `captureSnapshot` is read-only.

## Tests

**One typing constraint for tests 1 and 4.** Do **not** assert with `String.prototype.isWellFormed()` — it is ES2024 and this repo's `lib` is `["ES2022", "DOM", "DOM.Iterable"]` (`tsconfig.json:3`), so it is TS2339 under `typecheck:tests`. Use a lone-surrogate regex: `/[\uD800-\uDBFF](?![\uDC00-\uDFFF])|(?<![\uD800-\uDBFF])[\uDC00-\uDFFF]/`. Do not raise `lib` for a test.

1. `tests/server/annotation-text-snapshot.test.ts` — text whose unit at index 199 is the high half of a pair (199 filler units then an astral character): `captureSnapshot` returns length **199**, no lone surrogate, `truncated: true`. Kills the unguarded slice and a fix that returns 200 units with a replacement character.
2. Same file — the **negative twin**: a cap landing on a normal boundary still returns exactly `SNAPSHOT_CAP` units. Kills an unconditional `- 1`.
3. Same file — a cap landing between two *adjacent* astral characters (legal, because the unit before it is a low surrogate) still returns 200. Kills a one-sided "is the unit at the cap a surrogate" check.
4. Same file — **round-trip through the Y.Map**. `captureSnapshot` returns a detached plain object and writes nothing (`annotations.ts:186-202`); its caller at `:316-325` stores it. So: capture, **write the snapshot into the annotation record in the Y.Map**, `Y.encodeStateAsUpdate` into a second doc, **read the record back from the second doc's map**, and assert the snapshot is unchanged, carries no lone surrogate, and is still found by `indexOf` in the second doc's flat text. Encoding a doc whose map never held the snapshot exercises no lib0 UTF-8 encode and would pass on the unfixed code.
5. `tests/shared/snapshot-contradicts.test.ts` — the healing, with both truncated shapes: **a record this build wrote** (`textSnapshotTruncated: true`, snapshot ending in U+FFFD, `actual` the real text) ⇒ `snapshotContradicts` **false** and `snapshotSearchPrefix` returns the string minus the U+FFFD, same for a trailing lone high surrogate — this is the case the wrong placement cannot reach; **a legacy ellipsis record** (no flag, `length === SNAPSHOT_CAP`, trailing `"..."` with one split unit before it) ⇒ both are trimmed. Plus the discriminating negatives: a snapshot ending in U+FFFD on a record that is **not** truncated is untouched, and a truncated snapshot whose text genuinely no longer matches still contradicts (without which the fix could make `snapshotContradicts` unreachable).
6. `tests/server/snapshot-truncation-reload.test.ts` — the issue's symptom: the relocation pass finds and relocates an annotation whose stored snapshot ends in U+FFFD instead of logging `RANGE_GONE`.

## Done when

The six specs pass; `npm run typecheck` + `npm run typecheck:tests` + suite green. (`e6b.ts` printing `post-roundtrip contradicts: false` and `e6-snapshot.ts` case (a) printing `relocate(after round-trip)` as `"valid (no move)"` are a useful manual confirmation, not the gate.)

## Assumptions

- **The back-off shortens the snapshot rather than extending past the cap** — the cap bounds record size against pathological ranges (#1000 review R2), so 199 is the answer, not 201.
- **Legacy healing is a search-prefix trim, not a stored-record migration.** Rewriting snapshots already on disk would be a write from a read path — what #1764 is removing.
- **"Legacy" means the ellipsis writer and is not the corrupted population.** The records this heals are the flag-bearing ones this build writes; the ellipsis branch is healed for completeness but cannot hold a lone surrogate at the cap.
- **`textSnapshotTruncated` stays keyed on the original `text.length > SNAPSHOT_CAP`**, not on the kept slice's length.

## Not in scope

`src/client/layout/rail-content.svelte.ts`'s own `slice(0, SNAPSHOT_CAP - 3)` for the chat anchor — a `ChatAnchor` is never written back into the document and is excluded from `SnapshotBearing`; the issue names `annotations.ts` alone. Widening `SNAPSHOT_CAP`. Grapheme-cluster (ZWJ, combining mark) boundaries — only the lone surrogate is corrupted by the encode.
