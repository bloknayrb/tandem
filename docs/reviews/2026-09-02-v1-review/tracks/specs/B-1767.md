# B — #1767 The 200-unit `textSnapshot` slice has no surrogate guard, so a split emoji becomes U+FFFD

Branch `fix/annotation-anchors-1764`. Closes #1767. Ledger: `docs/reviews/2026-09-02-v1-review/areas/crdt.md:22`. Probe: `experiments/e6-snapshot.ts`, `experiments/e6b.ts` (`post-roundtrip contradicts: true`; the JSON disk path stays `false`).

## Problem

`captureSnapshot` (`src/server/mcp/annotations.ts`) caps at `SNAPSHOT_CAP` with a plain `text.slice(0, SNAPSHOT_CAP)`. When the 200th UTF-16 unit is the high half of a surrogate pair the stored snapshot ends in a lone surrogate. In process it still matches. After any Yjs `encodeStateAsUpdate` round-trip — session persist, doc swap, every client sync — the lone surrogate is re-encoded as U+FFFD, and the snapshot no longer occurs in the document. The watcher's relocation pass (`src/server/documents/watcher.ts`) searches with `snapshotSearchPrefix` and gets nothing, so the annotation is `RANGE_GONE` and stays pinned to its stale coordinates permanently; `snapshotContradicts` flips true, so Accept refuses the suggestion. The JSON envelope on disk is lossless — only the CRDT path corrupts, which is why this looks fine until a restart.

Every corrupted record is by construction a **truncated** one: the lone surrogate can only appear at the cap, and the cap sets `truncated: true`. That is what makes the legacy half of the fix a one-line change in one place.

## Fix

Two edits, both on the one code path each rule already lives on.

- **`src/server/mcp/annotations.ts` `captureSnapshot`** — when capping, back the slice off by one if the cut splits a pair:
  ```
  const cap = splitsSurrogatePair(text, SNAPSHOT_CAP) ? SNAPSHOT_CAP - 1 : SNAPSHOT_CAP;
  const kept = capped ? text.slice(0, cap) : text;
  ```
  `splitsSurrogatePair` is the existing **paired** predicate exported from `src/server/positions.ts` (`annotations.ts` already re-exports `refreshRange`/`refreshAllRanges` from that module, so the edge exists). Use it, not a one-sided `charCodeAt` test — CLAUDE.md Critical Rule 4 and the predicate's own docstring record why the one-sided form is wrong. `truncated` still comes from `text.length > SNAPSHOT_CAP`, unchanged: the record is truncated whether or not the back-off happened, and `isSnapshotTruncated`'s legacy branch keys on `length === SNAPSHOT_CAP` **and** a trailing ellipsis, so a 199-unit snapshot does not become undetectable. The `breaks` filter is already bounded by `from + kept.length`, so it follows the shorter slice with no change.
- **`src/shared/snapshot.ts` `snapshotSearchPrefix`** — after the existing legacy-ellipsis trim, drop one trailing unit when it is an unpaired half or a U+FFFD:
  a trailing high surrogate (a record written before this fix, read back before any Yjs round-trip) or a trailing `�` (the same record after one). This is the single place the rule can live: the watcher's relocation probe and `snapshotContradicts`' truncated branch both read this function, so one edit heals both, and `src/shared/snapshot.ts`'s own header says a second copy of the rule is how the two drift. Shortening a search prefix is always safe — a prefix of a prefix is still a prefix — so the false-positive cost of also stripping a legitimate trailing U+FFFD is one character of search specificity.
  Do **not** touch `snapshotContradicts`' non-truncated branch: an uncapped snapshot was never sliced and cannot be split.

**Rules that bite.** Critical Rule 4: the surrogate predicate is the paired form and the four `surrogates: "ignore"` callers are unchanged — this fix adds none. Critical Rule 2: no Y.Doc write is added; `captureSnapshot` is read-only.

## Tests

1. `tests/server/annotation-text-snapshot.test.ts` — build text whose unit at index 199 is the high half of a pair (199 filler units then an astral character); `captureSnapshot` returns a snapshot of length **199**, `String.prototype.isWellFormed()` true, `truncated: true`. Kills the unguarded slice and a fix that returns 200 units with a replacement character.
2. Same file — the **negative twin**: a cap that lands on a normal boundary still returns exactly `SNAPSHOT_CAP` units. Kills an unconditional `- 1`.
3. Same file — a cap landing between two *adjacent* astral characters (the boundary at 200 is legal because the unit before it is a low surrogate) still returns 200. Kills a one-sided "is the unit at the cap a surrogate" check, which is the wrong predicate and the reason `splitsSurrogatePair` exists.
4. Same file — round-trip: capture, `Y.encodeStateAsUpdate` into a second doc, read the snapshot back, and assert it is unchanged and still found by `indexOf` in the second doc's flat text. This is `e6-snapshot.ts` as a spec, and it is the test that actually reproduces the issue rather than the slice arithmetic.
5. `tests/shared/snapshot-contradicts.test.ts` — legacy record: `textSnapshotTruncated: true`, `textSnapshot` ending in `�`, `actual` the real text; `snapshotContradicts` is **false** and `snapshotSearchPrefix` returns the string minus the U+FFFD. Same with a trailing lone high surrogate. Then the discriminating negatives: a snapshot ending in U+FFFD on a record that is **not** truncated is untouched (still compared by equality); and a truncated snapshot whose text genuinely no longer matches still contradicts. Without the last one the fix could make `snapshotContradicts` unreachable and nothing would notice.
6. `tests/server/snapshot-truncation-reload.test.ts` — the relocation pass finds and relocates an annotation whose stored snapshot ends in U+FFFD, instead of logging `RANGE_GONE`.

## Done when

`e6-snapshot.ts` shows `contradicts: false` after the round-trip; the six specs pass; typecheck + suite green.

## Assumptions

- **The back-off shortens the snapshot rather than extending past the cap.** The cap bounds record size against pathological ranges (#1000 review R2) and must not be exceeded, so 199 is the answer, not 201.
- **Legacy healing is a search-prefix trim, not a stored-record migration.** Rewriting snapshots already on disk would be a write from a read path — exactly what #1764 is removing.
- **`textSnapshotTruncated` stays keyed on the original `text.length > SNAPSHOT_CAP`**, not on the length of the kept slice.

## Not in scope

`src/client/layout/rail-content.svelte.ts`'s own `slice(0, SNAPSHOT_CAP - 3)` for the chat anchor: a `ChatAnchor` is never written back into the document and is explicitly excluded from `SnapshotBearing`, and the issue names `annotations.ts` alone. Widening `SNAPSHOT_CAP`. Grapheme-cluster (ZWJ sequence, combining mark) boundaries — only the lone surrogate is corrupted by the encode.
