# D2 — #1754 the docx walker's flat text disagrees with mammoth on tab, break and symbol

Branch `fix/docx-contract-walker-mammoth-flat-text-disagreement-and-dropped-body-images-1754`. **Refs #1754 only — the PR does NOT close it.** [Decision B](../../../../plans/2026-09-06-open-issues-sweep.md) (#1827 B, Bryan 2026-09-06): `tandem_applyChanges` ships **marked experimental**, only the cheap walker fixes land (tab, break, symbol), and the rest of the walker/mammoth reconciliation stays deferred on this issue. Ledger: `docs/reviews/2026-09-02-v1-review/areas/server-data.md:21`.

## Problem

`walkDocumentBody` (`src/server/file-io/docx-walker.ts:168,267-269`) maps every member of `SINGLE_CHAR_ELEMENTS` to the literal `" "`. Measured against the real import (`rawDocx` → `loadDocx` → `htmlToYDoc` → `extractText`):

| element | walker | real import | delta |
|---|---|---|---|
| `w:tab` (in a run) | `" "` | `"\t"` | content |
| `w:br` (none / `textWrapping`) | `" "` | `"\n"` | content |
| `w:noBreakHyphen` / `w:softHyphen` | `" "` | `"‑"` / `"­"` | content |
| `w:sym`, BMP glyph | `" "` | the glyph (`"✓"`) | content |
| `w:sym`, astral glyph | `" "` (1) | the surrogate pair (2) | **+1 per symbol** |
| `w:sym`, unmapped font/char | `" "` (1) | `""` (mammoth warns and drops) | **−1 per symbol** |
| `w:br` with an unrecognised `w:type` | `" "` (1) | `""` (mammoth warns and drops) | **−1** |
| **`w:tab` inside `<w:pPr><w:tabs>`** | `" "` (1) | `""` — a tab-STOP DEFINITION | **+1 per declared tab stop** |
| `w:br type="page"` / `"column"`, empty `<w:p>`, and the rest | — | — | **deferred (decision B)** |

mammoth's mapping: `node_modules/mammoth/lib/docx/body-reader.js:315-327,360-368` plus `document-to-html.js:337-352,373`; `readSymbol` (`:233-249`) resolves through **`dingbat-to-unicode`** with a documented `F0..` → `..` retry.

**The `w:pPr` row is the one this spec exists to fix.** mammoth lists `w:pPr` (and `w:rPr`, `w:sectPr`, `w:tblPr`, `w:tblGrid`, `w:trPr`, `w:tcPr`) in `ignoreElements` (`body-reader.js:700-720`), and an ignored element returns `emptyResult()` **with no recursion** (`:45-56`). The walker's catch-all `else { walk(node.children) }` (`docx-walker.ts:276-278`) descends into `w:pPr` and matches the literal `<w:tab/>` inside `<w:tabs>`. Measured on this worktree, `<w:p><w:pPr><w:tabs><w:tab w:val="left" w:pos="720"/><w:tab w:val="right" w:pos="9000"/></w:tabs></w:pPr><w:r><w:t>Name</w:t><w:tab/><w:t>Value</w:t></w:r></w:p>` walks to `{"totalLength":12,"flatText":"  Name Value"}` against a real import of `"Name\tValue"` (10). Custom tab stops are the commonest real shape of a tabbed Word document, so fixing only the emitted character would leave `applyTrackedChanges` throwing on exactly the files #1754 is about.

Consequence: `src/server/file-io/docx-apply.ts:519-527` compares the walker's flat text against the Y.Doc's and throws a bare `Error("Flat text mismatch: …")` — no `code`, so `tandem_applyChanges` answers `INTERNAL_ERROR` on any Word file containing a tab, a break or a declared tab stop. Imported Word comments (`docx-comments.ts:437`) anchor off by the same deltas.

## Fix

**1a. Skip the property containers mammoth never enters.** Next to `INVISIBLE_TEXT_ELEMENTS`, add a set of the seven `ignoreElements` names, matched by `localName(node.name)` like that set is, given its own arm in `walk` **before** the catch-all so the subtree is not entered:

```
// mammoth's `ignoreElements` (body-reader.js:700-720). An ignored element
// returns emptyResult() with NO recursion (:45-56), so nothing inside reaches a
// reader — while the walker's catch-all used to recurse and count every
// <w:tab/> inside <w:pPr><w:tabs>, a tab-STOP DEFINITION, as a character.
const SKIPPED_SUBTREE_ELEMENTS = new Set(["pPr", "rPr", "sectPr", "tblPr", "tblGrid", "trPr", "tcPr"]);
```

`detectHeadingLevel` (`:110-125`) reads `w:pPr` **directly off the paragraph element**, not through `walk` — verify that when implementing rather than assuming it.

**1b. `flatTextForElement(el: Element): string | null`**, module-private, replacing `SINGLE_CHAR_ELEMENTS`, returning `null` for "not one of mine". **Keep today's `w:`-prefixed name matching on this arm** — widening it to `localName` is a namespace change that belongs to the deferred half (it would newly count DrawingML text-box characters and an unbound-prefix `x:tab`, neither of which mammoth reads). Transcribe mammoth, do not paraphrase:

- `w:tab` → `"\t"`.
- `w:noBreakHyphen` → `"‑"`; `w:softHyphen` → `"­"`. **Write the `\u` escapes in source, not the literal glyphs** — U+00AD is invisible in a diff and a mis-transcription to ASCII `-` would ship silently.
- `w:br` → `"\n"` **only** when `w:type` is absent or `textWrapping`; an **unrecognised** `w:type` returns `""` (mammoth's `else` arm emits nothing, `:360-368`). Do not route an unknown type to the page-break placeholder.
- `w:br type="page"` / `"column"` keeps today's one-character placeholder, and empty `<w:p>` keeps its `"\n"` — the half decision B defers. Comment both, naming #1754, so nobody "finishes the table".
- `w:sym` → **return `""` when `w:font` or `w:char` is absent, before calling `hex`** (`dingbat-to-unicode`'s `codePoint()` calls `typeface.toUpperCase()`, so `hex(undefined, char)` throws; `walkDocumentBody` also runs at apply time against bytes re-read from disk, where mammoth is not in the path). Otherwise `dingbatToUnicode.hex(font, char) ?? (/^F0..$/.test(char) ? dingbatToUnicode.hex(font, char.slice(2)) : null)`, then `.string`, else `""`.
- `offset += s.length`, not `+= 1` — an astral symbol is two UTF-16 units.

**Dependency.** `dingbat-to-unicode@1.0.1` is already in the tree as mammoth's transitive dep and ships its own `.d.ts`. Add the direct edge with `npm install dingbat-to-unicode@^1.0.1` (never hand-edit `package-lock.json`).

**2. `src/server/file-io/docx-apply.ts:519-527`** (the flat-text `Error`, **not** `src/server/mcp/docx-apply.ts`) — append **"Some documents are a known limitation (#1754)."** Deliberately not an enumeration: decision B defers the rest of the reconciliation, so naming two causes would misdiagnose every file that trips a third. No `code` is added; `INTERNAL_ERROR` stays the wire answer.

**3. Fence the run rewriter against what Fix 1 newly lets through.** The flat-text guard used to throw on any tabbed document *first*, which is the only reason `COMPLEX_RUN_ELEMENTS` (`docx-apply.ts:22-28`) never needed `w:tab`/`w:br`/`w:sym`. After Fix 1 a tabbed document passes the guard, `applySingleSuggestion` (`:340-373`) collects every intervening `w:r` into `runsToDelete`, and the replacement is emitted via `buildRun("w:t", newText, …)` where a literal `\t` is **not** a `<w:tab/>` — a suggestion spanning a tab would silently destroy it where today it is a loud refusal.

**Derive the fence from the walk that produces the offsets, not from a name list.** Any element `flatTextForElement` handled is by construction something `buildRun` cannot reproduce. Add an `onSpecialChar?: (span: { offsetStart: number; length: number; paragraph: Element; run: Element | undefined }) => void` callback to `walkDocumentBody`, fired from the same arm that pushes the string — `walk` already tracks `currentRun` (`docx-walker.ts:238-243`), so pass it — and fire it **for the `""` returns too**, not only for the arms that push characters. `buildOffsetMap` records the spans; rejections go into the existing `rejectedDetails` arm.

**The fence is TWO predicates, ORed, and the run-keyed one is the load-bearing half.** Reject a suggestion when either holds:

1. **Offset overlap**, half-open on both sides — `s.from < span.offsetStart + span.length && s.to > span.offsetStart` — so a suggestion ending exactly at the special character, or starting exactly at its end, still applies. A closed-interval test passes every straddling fixture identically while silently refusing ordinary adjacent suggestions on any tabbed document, which is the outcome this issue exists to remove.
2. **Run membership** — the span's recorded `run` is a member of the run set the suggestion would touch: the same `fromEntry.run`..`toEntry.run` walk the existing complex-element check already performs at `docx-apply.ts:583-604`.

**Predicate 1 alone is not enough, and this spec's own headline fixture is the counterexample.** `applySingleSuggestion` destroys whole `<w:r>` elements, not offset ranges: `:349-373` collects paragraph-direct runs from-run..to-run into `runsToDelete`, `:395-401` rebuilds the deletion text from `findTextNode(run)` — which returns only the **first** `<w:t>` in the run (`:475-480`) — and `:456-459` `removeChild(run)` takes the whole run with it. On `<w:r><w:t>Name</w:t><w:tab/><w:t>Value</w:t></w:r>` a suggestion over `Name` alone is `[0,4)` against a tab span at `[4,5)`: `0 < 5 && 4 > 4` is **false**, so predicate 1 lets it through. Measured on this worktree through the real `applyTrackedChanges`: `applied 1, rejected 0, []`, with the serialized body coming back as `<w:del …><w:r><w:delText>Name</w:delText></w:r></w:del><w:ins …><w:r><w:t>Label</w:t></w:r></w:ins>` — the `<w:tab/>` and `<w:t>Value</w:t>` gone from the user's `.docx`, silently. This is unreachable today only because the flat-text guard throws first on any tabbed document, and **Fix 1 is precisely what makes it reachable**, so predicate 2 ships with Fix 1 or not at all. Predicate 2 is also **length-independent**, which is what covers the two elements Fix 1 itself turns zero-width (an unrecognised `w:br w:type`, an unmapped `w:sym`) — a zero-length span sitting in the same run as the suggestion is invisible to predicate 1 by construction.

Predicate 2 does **not** widen the refusal on the separate-run shapes: in `<w:r><w:t>alpha</w:t></w:r><w:r><w:tab/></w:r><w:r><w:t>beta</w:t></w:r>` a suggestion covering exactly `alpha` touches only alpha's run, so both boundary fixtures in test 5 still apply. Because it is the same walk, the fence needs no name list, no prefix decision and no nesting depth — it covers a `<w:ins><w:r><w:tab/></w:r></w:ins>` and a bare `<w:tab/>` under `<w:p>` for free (the latter records `run: undefined` and is left to predicate 1, which is correct: there is no run of it for `runsToDelete` to take). The deferred page-break placeholder emits a character and is fenced by the same mechanism, which is correct. Widen the reason string to cover both fences ("Overlaps a footnote, drawing, field, tab, break or symbol and couldn't be applied"). Per-suggestion rejection is the point: a sibling suggestion in a plain text run must still apply.

Do **not** add names to `COMPLEX_RUN_ELEMENTS`, and leave `runsToDelete`'s direct-child-only loop alone: a suggestion whose endpoints sit inside `<w:ins><w:r>` is invisible to that collector today and stays so — pre-existing, unchanged by this PR, and failing **closed** at `:373-394` ("No runs found in deletion range") or `:325-329` ("Split failed"), never as a silent wrong rewrite. Do not write "3a makes it unreachable" into a source comment; it is false.

## Review corrections (post-cut)

Four findings, all adopted into the sections above rather than added as new machinery. Every one
of them is a consequence of Fix 1: removing the flat-text throw is what makes previously
unreachable rewrite paths reachable, so the fence has to grow with it.

- **The span fence is now run-keyed as well as offset-keyed (Fix 3, predicate 2).** The
  half-open overlap test is correct for what it measures and wrong about what
  `applySingleSuggestion` actually destroys: whole `<w:r>` elements, not offset ranges. Measured
  on this worktree, the spec's own headline fixture — a suggestion over `Name` in
  `<w:r><w:t>Name</w:t><w:tab/><w:t>Value</w:t></w:r>` — returned `applied 1, rejected 0` and
  emitted a body with the `<w:tab/>` and `<w:t>Value</w:t>` deleted. `onSpecialChar` therefore
  carries the enclosing `run`, and a suggestion is refused when its touched-run set holds one.
  The run set is the walk the complex-element check already performs (`docx-apply.ts:583-604`),
  so this is a second read of an existing loop, not a new scan.
- **`onSpecialChar` fires for the `""` returns too, and the run-keyed predicate is what covers
  them.** A zero-length span cannot satisfy `s.from < span.offsetStart + 0` for any suggestion
  starting at or after it, so offset overlap alone never fences an unrecognised `w:br w:type` or
  an unmapped `w:sym` sharing a run with the suggestion. These are the two elements **Fix 1
  itself** converts from one space to zero width, which is also why the scope-cut note on Fix 3b
  no longer claims the cut elements' zero-widthness covers them: `w:drawing`, `w:pict` and
  `w:fldChar` were zero-width already, these two are newly so.
- **Test 4 asserts the produced bytes, not the status.** `applied === 1` is green on exactly the
  output that destroys the tab, so the fixture now re-reads the returned buffer's flat text and
  `toBe`s `"NEW\tValue"`, with the `<w:tab/>` moved into its own run; the single-run shape
  becomes a second case that must be **rejected** with `<w:tab/>` and `Value` still in the output.
- **Test 5 gains two zero-width fixtures** (separate-run and single-run `w:sym`), the second
  being the only case in the suite that the run-keyed predicate alone can catch.

Nothing here changes the walker's emitted characters, so the Critical Rule 4 blast radius is
unchanged: no fifth `surrogates: "ignore"`, and the `.docx` comment EXPORT resolver keeps its
outward SNAP.
