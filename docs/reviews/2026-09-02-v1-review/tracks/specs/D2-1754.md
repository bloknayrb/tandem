## Problem

`walkDocumentBody` (`src/server/file-io/docx-walker.ts:168,267-269`) maps every member of `SINGLE_CHAR_ELEMENTS` to the literal string `" "`. Measured against the real import (`rawDocx` → `loadDocx` → `htmlToYDoc` → `extractText`), **every one of them is wrong**, and three are wrong in length as well as content:

| element | walker | real import | delta |
|---|---|---|---|
| `w:tab` (in a run) | `" "` | `"\t"` | content |
| `w:br` (none / `textWrapping`) | `" "` | `"\n"` (`<br>` → `hardBreak`, 1 flat char) | content |
| `w:noBreakHyphen` | `" "` | `"‑"` | content |
| `w:softHyphen` | `" "` | `"­"` | content |
| `w:sym`, BMP glyph | `" "` | the glyph (`"✓"`) | content |
| `w:sym`, astral glyph | `" "` (1) | the pair (**2** — surrogate pair) | **+1 per symbol** |
| `w:sym`, unmapped font/char | `" "` (1) | `""` (mammoth warns and drops) | **−1 per symbol** |
| **`w:tab` inside `<w:pPr><w:tabs>`** | `" "` (1) | `""` — a tab-STOP DEFINITION, never a character | **+1 per declared tab stop** |
| `w:br` with an unrecognised `w:type` | `" "` (1) | `""` (mammoth warns and drops) | **−1** |
| text inside `<w:drawing>` (a DrawingML text box) | counted via the catch-all recurse | `""` — `readDrawingElement` extracts the blip and never recurses | **+n** — fixed here by 1a, and **not** in the round-1 table |
| text inside `<w:pict>` (a VML text box) | counted **in place** | present, but **relocated** to a trailing `<p>` | **ordering**, not length — unfixed, pinned |
| `w:br type="page"` / `"column"` | `" "` (1) | `""` | **−1** — deferred, see below |
| empty `<w:p>` | `"\n"` | dropped (`ignoreEmptyParagraphs`) | **+1** — deferred |
| `<x:tab/>` under an **unbound** `x:` prefix | `""` (0) today — `SINGLE_CHAR_ELEMENTS.has("x:tab")` is false, so the catch-all recurses a childless element; `"\t"` (1) **after** this fix | `""` (mammoth logs "An unrecognised element was ignored: tab") | **0 → +1 — a mismatch this fix INTRODUCES**, pinned, see 1b |

mammoth's mapping is `node_modules/mammoth/lib/docx/body-reader.js:315-327,360-368` (readers) plus `document-to-html.js:337-352,373` (`tab → "\t"`, line break → `<br>`, page/column break → `htmlPaths.empty`), and `readSymbol` at `:233-249` resolves through **`dingbat-to-unicode`**, with a documented `F0..` → `..` retry.

**The `w:pPr` row is the one this spec exists to fix and the round-1 review is what surfaced it.** mammoth lists `"w:pPr"` (and `w:rPr`, `w:sectPr`, `w:tblPr`, `w:tblGrid`, `w:trPr`, `w:tcPr`) in `ignoreElements` (`body-reader.js:700-720`), and an ignored element returns `emptyResult()` **with no recursion** (`:45-56`) — so mammoth never sees a `w:tab` inside `<w:pPr><w:tabs>`. The walker's final arm is the catch-all `else { walk(node.children) }` (`docx-walker.ts:276-278`, whose own comment says "Recurse into w:ins, w:hyperlink, **w:pPr** children, etc."), so it descends into `w:pPr` and the `SINGLE_CHAR_ELEMENTS.has(node.name)` check at `:267` matches the literal `w:tab` inside `<w:tabs>`. **Measured on this worktree** (`npx tsx`, body `<w:p><w:pPr><w:tabs><w:tab w:val="left" w:pos="720"/><w:tab w:val="right" w:pos="9000"/></w:tabs></w:pPr><w:r><w:t>Name</w:t><w:tab/><w:t>Value</w:t></w:r></w:p>`): `walkDocumentBody` returns `{"totalLength":12,"flatText":"  Name Value"}`, while the real import is `"Name\tValue"` (10). Custom tab stops are the *commonest* real-world shape of a tab-bearing Word document, so changing only the emitted character would leave `applyTrackedChanges` still throwing on exactly the file #1754 is about.

Consequences: `src/server/file-io/docx-apply.ts:524` compares the walker's whole flat text against the Y.Doc's and throws a bare `Error("Flat text mismatch: …")` — no `code`, so `tandem_applyChanges` answers `INTERNAL_ERROR` on any Word file containing a tab, a line break, or a declared tab stop. Imported Word comments (`docx-comments.ts:437`) anchor off by ±1 per symbol and +1 per declared tab stop.

## Fix

**1. `docx-walker.ts` — skip the property containers, then replace the placeholder with mammoth's own mapping.** Two changes, and the first is what makes the second true.

**1a. A skip set for the subtrees mammoth never enters.** Add, next to `INVISIBLE_TEXT_ELEMENTS`:

```
// Subtrees mammoth never reads. Two different reasons — DO NOT collapse this
// comment into one claim, and do not "reconcile" the set against
// `ignoreElements`: `drawing` is not in that list and deleting it here
// silently reopens the DrawingML over-count.
//
// The seven property containers ARE `ignoreElements` (body-reader.js:700-720),
// and an ignored element returns emptyResult() with NO recursion (:45-56), so
// nothing inside them reaches a reader. The walker used to fall through to its
// catch-all recurse arm and count every <w:tab/> inside <w:pPr><w:tabs> — a
// tab-STOP DEFINITION — as a character.
//
// `drawing` is here for the opposite reason: it IS read, by
// `readDrawingElement` (body-reader.js:437,445-446), which extracts the image
// blip and never recurses into the shape's text body. Measured: a <w:drawing>
// wrapping a <w:txbxContent> paragraph imports as no text at all, while the
// walker's catch-all recursed into it and counted every character.
const SKIPPED_SUBTREE_ELEMENTS = new Set([
  // ignoreElements (seven):
  "pPr", "rPr", "sectPr", "tblPr", "tblGrid", "trPr", "tcPr",
  // read-but-never-recursed:
  "drawing",
]);
```

Matched by `localName(node.name)`, and given its own arm in `walk` **before** the catch-all: the subtree is not entered at all. `detectHeadingLevel` (`docx-walker.ts:110-125`) reads `w:pPr` **directly off the paragraph element**, not through `walk`, so heading detection is unaffected — verify that when implementing rather than assuming it.

**`drawing` is an additional flat-text fix, not merely a fence for 1b's widening**, and the round-1 draft understated it as the latter. Today's catch-all already recurses into `w:drawing` (`docx-walker.ts:276-278`), so a DrawingML text box's `<w:t>` is counted by the walker at full length while mammoth contributes nothing — a live over-count under the *current* prefix matching, independent of localName. It gets its own Problem-table row and its own contract-test fixture (test 1), because nothing pinned it before.

**1b. `flatTextForElement(el: Element): string | null`**, module-private, returning `null` for "not one of mine". Delete `SINGLE_CHAR_ELEMENTS`. Match by `localName(node.name)`, not the `w:`-prefixed literal — the file's own `localName` doc comment (`:27-35`) is the measurement that says prefix-matching is unsafe for any reader whose wrong answer is an offset shift, and the current `SINGLE_CHAR_ELEMENTS.has(node.name)` check is exactly that mistake. (Keep the other arms as they are; this PR does not widen the `w:p` / `w:t` / `w:del` dispatch — see the note in Tests item 5.)

localName matching on this arm is *wider* than prefix matching in one direction, and `drawing` is the fence: mammoth maps `"w:drawing": readChildElements` (`body-reader.js:437`) and its children `wp:inline` / `wp:anchor` to `readDrawingElement` (`:445-446`), which extracts the image blip and **never recurses into the shape's text**, so every `<a:br/>` / `<a:tab/>` in a DrawingML text body is absent from the import. Without the skip the walker would newly count them. `w:pict` must **NOT** be skipped: mammoth genuinely recurses it (`"w:pict"` → `readChildElements`, plus readers for `v:shape`, `v:textbox`, `w:txbxContent` at `:438-449`).

**But do not read "not skipped" as "agrees".** Measured on this worktree, a body of `<w:p><w:r><w:t>A</w:t></w:r><w:r><w:pict><v:shape><v:textbox><w:txbxContent><w:p><w:r><w:t>BOXED</w:t></w:r></w:p></w:txbxContent></v:textbox></v:shape></w:pict></w:r><w:r><w:t>B</w:t></w:r></w:p>` imports as `"<p>AB</p><p>BOXED</p>"` — mammoth **relocates** the textbox text to a trailing paragraph, while the walker emits it in place (A/BOXED/B). Recursing into `w:pict` therefore trades a length mismatch for an ordering one; it is still the right call (the characters exist on both sides, so no offset past the box shifts by their count), but it is not agreement and must not be pinned with a `toBe`. The same body with `w:drawing` in place of `w:pict` imports as `"<p>AB</p>"` — no text at all — which is what the skip makes the walker match exactly. **Neither decision is pinned by any test today** (`grep -rn "txbxContent\|w:pict\|w:drawing" tests/ src/` finds no walker fixture), so a later edit adding `pict` to the skip set, or dropping `drawing` from it, would shift every offset in such a document with nothing going red. Contract test 1 gains one discriminating clause per side.

Mapping — transcribe mammoth, do not paraphrase:

- `tab` → `"\t"`.
- `noBreakHyphen` → `"‑"`; `softHyphen` → `"­"`. **Write the `\u` escapes in the source, not the literal glyphs** — U+00AD is invisible in a diff and a mis-transcription to ASCII `-` would ship silently, caught only by contract test 1. mammoth itself writes them as escapes (`body-reader.js:321-327`).
- `br` → `"\n"` **only** when `w:type` is absent or `textWrapping`. Any **unrecognised** `w:type` returns `""` (zero characters) — mammoth's `else` arm is `emptyResultWithMessages([warning("Unsupported break type: …")])` (`:360-368`), i.e. it emits nothing. Do **not** route an unknown type to the deferred page/column placeholder.
- `sym` → **return `""` when `w:font` or `w:char` is absent, before calling `hex`** (`dingbat-to-unicode`'s `codePoint()` calls `typeface.toUpperCase()`, so `hex(undefined, char)` throws a TypeError; mammoth gets away with it because a font-less `<w:sym>` already makes the import throw, but `walkDocumentBody` also runs at apply time against bytes re-read from disk where mammoth is not in the path). Otherwise `dingbatToUnicode.hex(font, char) ?? (/^F0..$/.test(char) ? dingbatToUnicode.hex(font, char.slice(2)) : null)`, then `.string`, else `""`. Transcribe mammoth's retry exactly; `w:char="FC"` and `w:char="F0FC"` must both give `"✓"`.
- **`br` with `w:type="page"` or `"column"` keeps the 1-character placeholder**, unchanged from today. This is the half decision B defers, and it is the only remaining reason to write a placeholder at all. Comment it as such, naming #1754, so nobody "finishes the table". Empty `<w:p>` likewise stays at one `\n`.
- `offset += s.length` (not `+= 1`) — an astral symbol is two UTF-16 units.

**Attribute reads stay prefix-bound.** `getAttr(el, "w:type")` / `"w:font"` / `"w:char"` return `undefined` under a non-`w:` alias, so in the exact namespace shape localName matching exists for, a `<x:br x:type="page"/>` is counted as `"\n"` and an `<x:sym/>` as `""`. This is knowingly narrower than mammoth (which canonicalizes by URI) and is left alone because the deferred half of #1754 owns the rest of the namespace question; say so in a comment at `flatTextForElement`, so the next reader does not infer the walker is namespace-clean.

**localName matching also INTRODUCES one new mismatch, in the same metric this issue is about, and it must be pinned rather than buried in a test comment.** For a prefix that is **not bound to any namespace**, mammoth's reader — which canonicalizes by namespace URI (`node_modules/mammoth/lib/xml/reader.js:53-62`) — sees an unrecognised element and drops it ("An unrecognised element was ignored: tab", producing `"AB"`). Today the walker agrees at zero, because `SINGLE_CHAR_ELEMENTS.has("x:tab")` is false and the catch-all recurses a childless element. After 1b the walker returns 1 and mammoth 0, so `applyTrackedChanges` throws `INTERNAL_ERROR` on such a file and imported comment anchors shift by +1. It is accepted, not fixed, on one measured ground: **an unbound prefix is namespace-ill-formed XML**, so no Word-produced `.docx` contains one — the shape is reachable only by hand-authored bytes. It gets a Problem-table row, a Not-in-scope entry, and a `not.toBe` pin in contract test 1 carrying the same "CURRENT LOSS" comment the page break gets, so a later namespace fix turns it red instead of passing unnoticed. The **bound**-alias case (test 5) is the opposite and is genuinely fixed: mammoth resolves it by URI to a real tab, and after 1b so does the walker.

**Dependency.** `dingbat-to-unicode@1.0.1` is already in the tree as mammoth's own transitive dep and ships its own `.d.ts`. Add it as a **direct** dependency with `npm install dingbat-to-unicode@^1.0.1` (never hand-edit `package-lock.json`); this adds a dependency *edge*, not a package. `mammoth` is pinned `^1.8.0`, so the two could drift on a minor bump — which is why the test below compares against a real import rather than against hard-coded strings.

**2. `src/server/file-io/docx-apply.ts:524`** (the flat-text `Error("Flat text mismatch: …")` — **not** `src/server/mcp/docx-apply.ts`, a different module with the same basename) — amend the thrown message. After this PR the honest remaining causes are the deferred ones plus whatever the reconciliation has not reached, so "The file may have changed since it was loaded." alone is a wrong diagnosis. Append **"Some documents are a known limitation (#1754)."** — deliberately *not* an enumeration of "empty paragraphs or page breaks": decision B defers the full walker/mammoth reconciliation, so naming two causes would misdiagnose every file that trips a third. No `code` is added and no handler arm changes — `INTERNAL_ERROR` stays the wire answer, and `docs/mcp-tools.md` says so.

**3. Fence the run rewriter against the shapes the guard used to keep out — and the fence must be at least as wide as what Fix 1 newly lets through.** Today `COMPLEX_RUN_ELEMENTS` (`src/server/file-io/docx-apply.ts:22-28`) is `{w:footnoteReference, w:endnoteReference, w:drawing, w:pict, w:fldChar}`; `w:tab` / `w:br` / `w:sym` / `w:noBreakHyphen` / `w:softHyphen` are absent. That was safe only because the flat-text guard at `:519-527` threw on any such document **first**. Fix 1 removes that accident: a tabbed document now passes the guard, and `applySingleSuggestion` (`:340-373`) collects **every** `w:r` between the endpoints into `runsToDelete` — a `<w:r><w:tab/></w:r>` between them is wrapped in `w:del` — while the replacement is emitted via `buildRun("w:t", newText, …)`, where a literal `\t` / `\n` is **not** a `<w:tab/>` / `<w:br/>`. A suggestion spanning a tab would silently destroy it in the user's `.docx`, where today it is a loud refusal.

**Adding names to `COMPLEX_RUN_ELEMENTS` is NOT sufficient, and the round-1 draft's "so add five names" was the whole of its error.** The existing scan (`docx-apply.ts:588-605`) is matched *more narrowly* than Fix 1 makes the walker count, in two independent ways, so the exact shapes Fix 1 newly lets past the flat-text guard can still be silently rewritten:

- **(a) prefix vs. localName.** The set holds `w:`-prefixed literals and the scan tests `COMPLEX_RUN_ELEMENTS.has(rc.name)`, while 1b makes the walker match `localName`. Test 5's bound-alias fixture — `<x:tab/>` inside a `w:r`, declared supported — is exactly this: measured, mammoth canonicalizes by namespace URI (`node_modules/mammoth/lib/xml/reader.js:53-62`) and imports `<w:p><w:r xmlns:x="…wordprocessingml/2006/main"><w:t>alpha</w:t><x:tab/><w:t>beta</w:t></w:r></w:p>` as `"<p>alpha\tbeta</p>"`, a real tab. So after Fix 1 the flat texts agree, the guard passes, `offsetMap.get()` resolves both endpoints (both sit in real `w:t` nodes), the scan sees `rc.name === "x:tab"` ∉ the prefixed set, and the run is wrapped in `w:del`.
- **(b) direct children only.** Both the complex scan (`:588-605`) and `runsToDelete` (`:353-372`) iterate `paragraph.children` and `continue` on any child whose `name !== "w:r"`. The walker's catch-all recurses into `w:ins` and `w:hyperlink` (`docx-walker.ts:276-278`), so a `<w:ins><w:r><w:tab/></w:r></w:ins>` between the endpoints **is** counted into the flat text and is invisible to the fence. `w:ins` is the single most likely nesting in a tracked-changes document — `tandem_applyChanges`' entire domain. Separately, mammoth's `readParagraph` calls `readXmlElements(element.children)`, so a bare `<w:tab/>` sitting **directly under `<w:p>`** with no enclosing run is read as one character; the walker counts it too, and it is neither fenced nor collected.

So the fence gets two parts, and the first is the load-bearing one:

**3a. Derive a span fence from the walk that produces the offsets.** Any element `flatTextForElement` emitted characters for is, by construction, a character in the flat text that `buildRun("w:t", newText, …)` cannot reproduce. Add an `onSpecialChar?: (span: { offsetStart: number; length: number; paragraph: Element }) => void` callback to `walkDocumentBody`, fired from the same arm that pushes `flatTextForElement`'s string; have `buildOffsetMap` record the spans; and reject any suggestion whose `[from, to)` overlaps one. This is immune to both gaps above **because it is the same walk**: it needs no name list, no prefix decision and no knowledge of nesting depth, so it cannot drift from 1b the way a second scan can. The deferred page/column-break placeholder emits a character too and is fenced by the same mechanism, which is correct — a suggestion spanning a page break would destroy it just as surely.

**3b. Widen the existing run scan for the ZERO-width complex elements**, which emit no character and therefore have no span: `w:footnoteReference`, `w:endnoteReference`, `w:drawing`, `w:pict`, `w:fldChar`. Two clauses, both fail-safe (they only ever widen a refusal): store `COMPLEX_RUN_ELEMENTS` as **local names** and compare `localName(rc.name)` — which also makes the two matchers agree within one PR; and make the scan **descend** through non-`w:r` paragraph children (`w:ins`, `w:hyperlink`) rather than `continue`-ing on them.

Do **not** add `w:tab` / `w:br` / `w:sym` / `w:noBreakHyphen` / `w:softHyphen` to `COMPLEX_RUN_ELEMENTS`: 3a already covers them at every depth and under every prefix, and listing them in both places is the drift this fix exists to remove. Widen the `rejectedDetails` reason string to cover both fences ("Overlaps a footnote, drawing, field, tab, break or symbol and couldn't be applied"). Per-suggestion rejection is the point: a sibling suggestion inside a plain text run in the same document must still apply.

**`runsToDelete`'s own direct-child-only loop is left alone**, and deliberately: with 3a in place no suggestion that reaches `applySingleSuggestion` spans a character-emitting element, and 3b covers the zero-width ones, so the collector is never asked to reason about a nested run. Widening it too would be a second, unfenced rewrite path added in the same PR that is fencing the first.

Without it Claude receives #1755's refusal as a deliberately content-free `VERIFY_BLOCKED` message (`document-service.ts:676-683`) naming no next step, while the line that *does* name the exit is user-facing only — `src/shared/types.ts:521-536` states in as many words that no MCP tool returns `importLosses`. - `docs/mcp-tools.md:856-880` — experimental marking on the heading paragraph, and rewrite the `**Errors:**` line, which today lists two of the eleven codes the handler actually returns. The real set, read off `src/server/mcp/docx-apply.ts:496-528`: `NO_DOCUMENT`, `NO_SUGGESTIONS`, `FORMAT_ERROR` (not a `.docx`, or an `upload://` path), `BACKUP_FAILED`, `INVALID_PATH` (a symlinked `backupPath`), `READ_ONLY`, `EXTERNAL_CONFLICT`, `FILE_MODIFIED`, `SOURCE_MISSING`, `FILE_LOCKED`, and `INTERNAL_ERROR` — the last being the flat-text mismatch above. Rows for `NO_SUGGESTIONS`, `BACKUP_FAILED`, `FILE_MODIFIED`, `SOURCE_MISSING` and `READ_ONLY` already exist in the global table at `:59-66`; do not duplicate them. `LICENSE_REQUIRED` is deliberately **not** in the eleven: `gatedTool` (`src/server/mcp/license-gate.ts:65-74`) can return it ahead of the handler, but it is ambient to every gated tool, already carries a global row, and is never returned while the gate ships dark — say so in one clause rather than adding a twelfth code.

**CLAUDE.md rules that bite here.** Critical Rule 4: this changes what a `.docx` flat offset *means*, so the two `surrogates: "ignore"` walker sites and the `.docx` capture / comment-import callers are all in the blast radius — **do not add a fifth `"ignore"`**. None is needed: `w:sym` is emitted atomically and `w:commentRangeStart/End` sit between elements, so no marker offset can land inside a surrogate pair the walker mints. The `.docx` comment EXPORT resolver keeps its distinct outward SNAP. No Y.Doc write is added, so no origin helper changes; no new MCP tool or `/api` route, so the two license-gate tables are untouched.

**No durable migration is needed for already-imported Word comments, and the reason is a specific code path, not an assumption.** The change moves imported-comment offsets, and those offsets are part of the annotation map KEY (`importAnnotationId` hashes `(commentId, from, to, bodyText)` — `docx-comments.ts:139-151`). The #1150 secondary dedup axis (`:534-540`) indexes existing `author: "import"` records by their stable Word `commentId`, precisely so "a comment whose flat offsets drifted between imports is updated in place instead of duplicated under a new offset-derived key"; the next open re-derives and rewrites the shifted range through `anchoredRange` (`:620-626`). That is what makes the ±1 self-healing. **Bounded residue:** a pre-#1068 record carrying no `importSource.commentId` matches neither the offset key nor the commentId axis, and the #1068 backfill (`:697-710`) only fires while the OLD offsetId still matches — which is exactly what this change breaks. Such a record duplicates once, on one open. Known, bounded, not fixed here.

## Tests

All in `tests/server/docx-walker.test.ts` unless named otherwise.

1. **The contract test — `exp6.ts`/`exp7.ts` converted into tracked vitest fixtures** (which is also what makes this spec's criterion answerable from tracked files; the probes themselves are collected by nothing). New `describe("flat text matches the real import")`: for each fixture, build it with `rawDocx` (`tests/helpers/docx-corpus.ts`), run `loadDocx` → `htmlToYDoc` → `extractText`, and assert against `walkDocumentBody(documentXml).flatText`. This is the only test that survives a `mammoth` minor bump changing a mapping; a string-literal test would go silently stale.

That clause is what pins Fix 1a's `drawing` skip, which nothing checked.

   - **`w:pict` wrapping a `w:txbxContent` paragraph** — new in round 2.
