# D2 — #1754 the docx walker's flat text disagrees with mammoth on tab, break and symbol

Branch `fix/docx-contract-walker-mammoth-flat-text-disagreement-and-dropped-body-images-1754`. **Refs #1754 only — the PR does NOT close it.** [Decision B](../../../../plans/2026-09-06-open-issues-sweep.md) (#1827 B, Bryan 2026-09-06) governs the scope: `tandem_applyChanges` ships **marked experimental**, the cheap walker fixes land now, and the empty-paragraph / page-break anchor shift stays deferred on this issue. Ledger: `docs/reviews/2026-09-02-v1-review/areas/server-data.md:21`. Probes: `experiments/e1-docx.ts`, `exp6.ts`, `exp7.ts`.

## Problem

`walkDocumentBody` (`src/server/file-io/docx-walker.ts:168,267-269`) maps every member of `SINGLE_CHAR_ELEMENTS` to the literal string `" "`. Measured against the real import (`rawDocx` → `loadDocx` → `htmlToYDoc` → `extractText`), **every one of them is wrong**, and three are wrong in length as well as content:

| element | walker | real import | delta |
|---|---|---|---|
| `w:tab` | `" "` | `"\t"` | content |
| `w:br` (none / `textWrapping`) | `" "` | `"\n"` (`<br>` → `hardBreak`, 1 flat char) | content |
| `w:noBreakHyphen` | `" "` | `"‑"` | content |
| `w:softHyphen` | `" "` | `"­"` | content |
| `w:sym`, BMP glyph | `" "` | the glyph (`"✓"`) | content |
| `w:sym`, astral glyph | `" "` (1) | `"🖉"` (**2** — surrogate pair) | **+1 per symbol** |
| `w:sym`, unmapped font/char | `" "` (1) | `""` (mammoth warns and drops) | **−1 per symbol** |
| `w:br type="page"` / `"column"` | `" "` (1) | `""` | **−1** — deferred, see below |
| empty `<w:p>` | `"\n"` | dropped (`ignoreEmptyParagraphs`) | **+1** — deferred |

mammoth's mapping is `node_modules/mammoth/lib/docx/body-reader.js:315-327,360-368` (readers) plus `document-to-html.js:337-352,373` (`tab → "\t"`, line break → `<br>`, page/column break → `htmlPaths.empty`), and `readSymbol` at `:233-249` resolves through **`dingbat-to-unicode`**, with a documented `F0..` → `..` retry.

Consequences: `docx-apply.ts:522` compares the walker's whole flat text against the Y.Doc's and throws a bare `Error("Flat text mismatch: …")` — no `code`, so `tandem_applyChanges` answers `INTERNAL_ERROR` on any Word file containing a tab or a line break. Imported Word comments (`docx-comments.ts:437`) anchor off by ±1 per symbol.

## Fix

**1. `docx-walker.ts` — replace the placeholder with mammoth's own mapping.** Delete `SINGLE_CHAR_ELEMENTS`; add a module-private `flatTextForElement(el: Element): string | null` returning `null` for "not one of mine". Match by `localName(node.name)`, not the `w:`-prefixed literal — the file's own `localName` doc comment (`:27-35`) is the measurement that says prefix-matching is unsafe for any reader whose wrong answer is an offset shift, and the current `SINGLE_CHAR_ELEMENTS.has(node.name)` check is exactly that mistake. (Keep the other arms as they are; this PR does not widen the `w:p` / `w:t` / `w:del` dispatch.)

- `tab` → `"\t"`; `noBreakHyphen` → `"‑"`; `softHyphen` → `"­"`.
- `br` → `"\n"` **only** when `w:type` is absent or `textWrapping`.
- `sym` → `dingbatToUnicode.hex(font, char) ?? (/^F0..$/.test(char) ? dingbatToUnicode.hex(font, char.slice(2)) : null)`, then `.string`, else `""`. Transcribe mammoth's retry exactly; `w:char="FC"` and `w:char="F0FC"` must both give `"✓"`.
- **`br` with `w:type="page"` or `"column"` keeps the 1-character placeholder**, unchanged from today. This is the half decision B defers, and it is the only remaining reason to write a placeholder at all. Comment it as such, naming #1754, so nobody "finishes the table". Empty `<w:p>` likewise stays at one `\n`.
- `offset += s.length` (not `+= 1`) — an astral symbol is two UTF-16 units.

**Dependency.** `dingbat-to-unicode@1.0.1` is already in the tree as mammoth's own transitive dep and ships its own `.d.ts`. Add it as a **direct** dependency with `npm install dingbat-to-unicode@^1.0.1` (never hand-edit `package-lock.json`); this adds a dependency *edge*, not a package. `mammoth` is pinned `^1.8.0`, so the two could drift on a minor bump — which is why the test below compares against a real import rather than against hard-coded strings.

**2. `docx-apply.ts:522`** — amend the thrown message. After this PR the honest remaining causes are the deferred ones, so "The file may have changed since it was loaded." alone is a wrong diagnosis: append "Documents containing empty paragraphs or page breaks are a known limitation (#1754)." No `code` is added and no handler arm changes — `INTERNAL_ERROR` stays the wire answer, and `docs/mcp-tools.md` says so.

**3. Mark `tandem_applyChanges` experimental** (decision B), in all three places that reach a caller:
- `src/server/mcp/docx-apply.ts:481-482` tool description — prefix `"EXPERIMENTAL. "` and add the one-sentence reason ("refuses documents whose flat text it cannot reproduce, including empty paragraphs and page breaks").
- `skills/tandem/SKILL.md:130` — same marking in the bullet. **Bump frontmatter `version: 18` → `19` and the `/^version:\s*18$/m` literal at `tests/skill-instruction-contract.test.ts:87` in the SAME commit.**
- `docs/mcp-tools.md:856-880` — experimental marking on the heading paragraph, and rewrite the `**Errors:**` line, which today lists two of the eleven codes the handler actually returns. The real set, read off `src/server/mcp/docx-apply.ts:494-526`: `NO_DOCUMENT`, `NO_SUGGESTIONS`, `FORMAT_ERROR` (not a `.docx`, or an `upload://` path), `BACKUP_FAILED`, `INVALID_PATH` (a symlinked `backupPath`), `READ_ONLY`, `EXTERNAL_CONFLICT`, `FILE_MODIFIED`, `SOURCE_MISSING`, `FILE_LOCKED`, and `INTERNAL_ERROR` — the last being the flat-text mismatch above. Rows for `NO_SUGGESTIONS`, `BACKUP_FAILED`, `FILE_MODIFIED`, `SOURCE_MISSING` and `READ_ONLY` already exist in the global table at `:59-66`; do not duplicate them.

**CLAUDE.md rules that bite here.** Critical Rule 4: this changes what a `.docx` flat offset *means*, so the two `surrogates: "ignore"` walker sites and the `.docx` capture / comment-import callers are all in the blast radius — **do not add a fifth `"ignore"`**. None is needed: `w:sym` is emitted atomically and `w:commentRangeStart/End` sit between elements, so no marker offset can land inside a surrogate pair the walker mints. The `.docx` comment EXPORT resolver keeps its distinct outward SNAP. No Y.Doc write is added, so no origin helper changes; no new MCP tool or `/api` route, so the two license-gate tables are untouched.

## Tests

All in `tests/server/docx-walker.test.ts` unless named otherwise.

1. **The contract test — `exp6.ts`/`exp7.ts` converted.** New `describe("flat text matches the real import")`: for each of tab, line break, page break, BMP symbol, astral symbol, unmapped symbol, noBreakHyphen, softHyphen, build the fixture with `rawDocx` (`tests/helpers/docx-corpus.ts`), run `loadDocx` → `htmlToYDoc` → `extractText`, and assert `walkDocumentBody(documentXml).flatText === extractText(doc)`. This is the only test that survives a `mammoth` minor bump changing a mapping; a string-literal test would go silently stale. **Page break is asserted as a KNOWN mismatch** (`not.toBe`) with a comment naming decision B — the `docx-roundtrip-fidelity.test.ts` "CURRENT LOSS" precedent — so deleting the deferral turns that assertion red rather than passing unnoticed.
2. Kills "map everything to one space with a different character": the astral case pins `totalLength` 4 and the unmapped case 2, so a fix that changes only the character still fails.
3. Kills "resolve symbols without mammoth's `F0..` retry": `w:char="F0FC"` and `w:char="FC"` in `Wingdings` both give `"A✓B"`.
4. Kills prefix-matching: one fixture binds WML to `xmlns:x` and emits `<x:tab/>`; it must count as a tab. (`localName` already exists; nothing in the walker used it for this dispatch.)
5. Existing `:120-176` specs assert `totalLength` only and stay green; extend each with the `flatText` assertion so the content half is pinned too.
6. `tests/server/docx-apply.test.ts` — a fixture whose body holds a tab applies cleanly end-to-end (this is the issue's headline: `applyTrackedChanges` no longer throws on an ordinary Word file); a fixture with a page break still throws, and the message names #1754.
7. `tests/skill-instruction-contract.test.ts` — the `version: 19` literal, plus an assertion that the `tandem_applyChanges` bullet says experimental.

## Done when

The walker's flat text equals the real import's for tab, break, all three symbol shapes and both hyphens; page break and empty paragraph remain the only mismatches and are pinned as such; `applyTrackedChanges` accepts a tabbed document; the tool description, `SKILL.md` (v19) and `docs/mcp-tools.md` all say experimental and the docs Errors line lists the eleven real codes; `npm run typecheck` + `npm test` green.
