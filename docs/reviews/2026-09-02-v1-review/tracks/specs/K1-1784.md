sound because every item in it belongs to a *different* tracked issue (decision F / #1788 / track H,

`docs/plans/2026-09-06-open-issues-sweep.md:224`; area rows
`docs/reviews/2026-09-02-v1-review/areas/tests.md:17` (the derivation) and `:18` (the stem check).

## Problem

**Half 1.** `tests/server/license-gate-coverage.test.ts:139-151` is the completeness net Critical
Rule 9 leans on. It builds `registered` from `/(?:gatedTool|withErrorBoundary)\(\s*"(tandem_\w+)"/`
— the two **wrapper** names. A tool registered as `server.tool("tandem_zzz", schema, handler)` with
no wrapper is in neither `registered` nor `GATED`/`UNGATED`, `unclassified` stays empty, and the
suite is green while the tool ships ungated. `tests/docs/tool-count-drift.test.ts:62-66` already has
the right derivation (`server\.(?:tool|registerTool)\(\s*"(tandem_\w+)"`) but compares only counts.
Measured on this branch: both derivations yield the same **33** names, `reg-not-wrapped` and
`wrapped-not-reg` both empty — latent, exactly as the issue says. Also measured: **34** raw
`.tool(`/`.registerTool(` call sites, the extra one being the docblock at
`src/server/mcp/license-gate.ts:60`, which carries no `"tandem_…"` literal and so is invisible to a
name-capturing regex.

Second, `GATED` (`:53-67`) and `UNGATED` (`:73-109`) are two arrays with their justifications in
block comments above each. Decision F (sweep doc, taken 2026-09-06) moves `tandem_resolveAnnotation`
and the other annotation mutators across in track H (#1788) — a cross-array move plus a comment
rewrite in a third place.

**Half 2.** `tests/scripts/coverage-gate-wiring.test.ts:105-119` proves each policy row's `suite`
"actually references the module" with `source.includes(stem)`. `suite` is the half of ADR-051 that
detects *deleted* behaviour, so this is load-bearing. Measured over all 14 rows: **12 statically
import their module; 2 do not** —

- `src/server/annotations/projection.ts` → `tests/server/events/channel-projection-characterization.test.ts`
  imports nothing from it; the stem matches five `describe(...)` titles. The check passes on prose.
- `src/server/documents/watcher.ts` → `tests/server/file-watcher.test.ts`, which imports
  `src/server/file-watcher.js` — a **different module**. The stem `watcher` matches the test's own
  filename, so a row aimed at the wrong module's suite has been green since it was written.

## Fix

### `tests/server/license-gate-coverage.test.ts`

- Replace `GATED`/`UNGATED` with one data list, the shape track H widens by editing one row:
  `type ToolGate = { name: string; gate: "gated" | "ungated"; why: string }` and
  `const TOOL_GATES: ToolGate[]`. Today's block comments are **two kinds and split two ways**:
  the per-tool sentences become `why` values verbatim (`tandem_resolveAnnotation`'s "would
  needlessly block triage", `tandem_open`'s in-handler `force` gate note at `:75-79`,
  `tandem_diagnostics`' self-diagnose note at `:105-107`) — **do not move the
  `tandem_resolveAnnotation` row; decision F is track H's change, not this PR's**. The two
  **list-scoped** rationales are statements about the partition, not any row, and copying either
  into 12 `why` fields would duplicate or drop it: `:53-57` ("the deprecated stubs … are gated for
  consistency") and `:82-92` (which ends "Enumerated so the drift-guard ALSO catches a read tool
  being *accidentally gated* … not just a mutator being left ungated") move **verbatim into the
  docblock above `const TOOL_GATES`**, alongside the two facts the next bullet-but-one requires
  there. Derive
  `const GATED = TOOL_GATES.filter(r => r.gate === "gated").map(r => r.name)` and `UNGATED`
  likewise. The two `it.each` loops at `:112-129` are unchanged.
- Add `it("partitions the table")`: `GATED.length + UNGATED.length === TOOL_GATES.length`, and each
  length `> 0`. Deriving the arrays introduces a failure the literals could not have — `it.each([])`
  registers zero tests, reports `Tests 1 passed`, and exits 0, so a mis-typed `gate` value would
  silently delete all 33 per-tool assertions.
- Factor **two** derivations side by side and **union** them — the registration one is added, the
  wrapper one is kept, neither replaces the other:
  `function registeredNames(src)` over `/\.(?:tool|registerTool)\(\s*"(tandem_\w+)"/g`
  (**receiver-agnostic** — `\.` not `server\.` — so `mcp.tool("tandem_zzz", …)` is seen), and
  `function wrapperNames(src)` over the existing `/(?:gatedTool|withErrorBoundary)\(\s*"(tandem_\w+)"/g`.
  Rewrite the completeness `it` at `:139` to compare
  `new Set([...registeredNames(SRC), ...wrapperNames(SRC)])` against the `TOOL_GATES` name set in
  both directions (unclassified, stale), keeping the existing failure messages. **Replacing rather
  than unioning relocates the hole instead of closing it**: a tool whose `.tool(` name argument is a
  const while its `gatedTool("tandem_zzz", …)` wrapper carries the literal is invisible to
  `registeredNames` alone, and nothing else in the repo catches it (`tool-count-drift.test.ts` is
  name-at-registration too, over the same directory). Both sets are the same 33 names today, so the
  union costs nothing.
- Three facts go in the rewritten docblock, because a green gate otherwise reads wider than it is:
  a name reaching **either** derivation must be classified; the scan root is `src/server/mcp/**`
  only, so a registration outside it is unseen; and both derivations key on a **name literal** at a
  `.tool(`/`.registerTool(`/wrapper call, so a tool exposed through the channel shim's low-level
  `setRequestHandler` path is outside this gate **by construction** — `src/channel/run.ts:75`
  advertises `tandem_reply` in a `ListTools` result and dispatches it at `:97` with neither shape.
  (`tandem_reply` is ungated today, so nothing is open; the clause exists because Critical Rule 9's
  net reads as tool-wide once the docblock says "either derivation".)
- **Same commit**: `tests/server/search-worker.test.ts:267` enumerates the shapes that must not
  appear in `WORKER_SOURCE`, and names this suite as the reason. Losing the `server\.` anchor
  desynchronises it, so widen `'server.tool("tandem_'` to `'.tool("tandem_'` there.

### `tests/scripts/coverage-gate-wiring.test.ts` + `scripts/ci/coverage-policy.json`

- Replace the `includes(stem)` body at `:105-119` with a local pure
  `importsModule(suiteSource: string, suiteDir: string, moduleAbs: string): boolean`: scan
  `/from\s*"(\.[^"]*)"/g`, resolve each against `suiteDir`, and accept the module if it equals the
  specifier as written, with `.js` → `.ts`, or with `.ts` appended (that triple covers all 12
  passing rows, `.svelte.ts` included). Rename the `it` to say **imports**, and rewrite its comment:
  the old one argues *for* a text reference ("a suite may reach a module through a harness"), and
  the two rows below are what that argument cost. Matching only `from "…"` is what keeps this free
  of any `vi.mock` handling — a mock call is never of that form — so **do not add a mock resolver**;
  a future row that can only reach its module through a mock gets repointed instead. Alias
  specifiers (`@server/…`, `@shared/…`, `@client/…`, defined in `vitest.config.ts:8-12`) are
  deliberately **not** matched — measured, no row uses one today; a future row that reaches its
  module only through an alias is repointed the same way. The scan is **textual**, so a suite that
  embeds its module's path as string *data* (the shape `tests/server/documents-open.test.ts` uses to
  pin an importer set) would satisfy it; accepted — measured, no row does today, and the alternative
  is the general resolver the wave note forbids. Record that in the rewritten comment.
- Repoint the two failing rows in `scripts/ci/coverage-policy.json`, `suite` field only (`path`,
  floors and `observed` untouched; `coverage-gate.mjs` never reads `suite`):
  `src/server/documents/watcher.ts` → `tests/server/reload-from-disk-persistence.test.ts` (imports
  `documents/watcher.js` at `:67`; its header already says the last two describes "are the rest of
  `documents/watcher.ts`'s reload wiring"), and `src/server/annotations/projection.ts` →
  `tests/server/events/channel-eligible-brand.test.ts` (imports six of projection's exports at
  `:20-28`, 18 `it`s over `narrowForChannel` / the payload builders). The alternative for projection
  is `tests/server/annotation-create-lifecycle.test.ts`, which also imports it directly but is
  already `lifecycle.ts`'s named suite.

## Tests

Each new spec kills one wrong implementation; both live in the file they guard, so no new module.

1. `license-gate-coverage.test.ts` — `it("the derivation sees a registration with no wrapper")`:
   `registeredNames('server.tool("tandem_zzz", {}, async () => {});\nmcp.registerTool("tandem_yyy", {}, h);')`
   equals `{tandem_zzz, tandem_yyy}`. Kills the shipped wrapper-derived regex and a `server\.`-anchored
   replacement in one synthetic source.
2. `license-gate-coverage.test.ts` — `it("the union also sees a wrapper whose registration is variable-named")`:
   over `'server.tool(TOOL_NAME, {}, gatedTool("tandem_zzz", h));'` the union yields `{tandem_zzz}`
   while `registeredNames` alone yields the empty set. Kills the replace-instead-of-union rewrite.
3. `license-gate-coverage.test.ts` — the partition spec above. Kills the silent-empty `it.each([])`.
4. `coverage-gate-wiring.test.ts` — `it("a suite that only names the module does not count")`,
   **three cases, and the third is the load-bearing one**: `importsModule('describe("projection", …)',
   dir, abs)` is `false`; the same source plus
   `import { createdPayload } from "../../../src/server/annotations/projection.js";` is `true`; and,
   taken from the real failing row,
   `importsModule('import { watchFile } from "../../src/server/file-watcher.js";', <tests/server>,
   <ROOT>/src/server/documents/watcher.ts)` is **`false`** while the same source against
   `<ROOT>/src/server/file-watcher.ts` is `true`. The first two alone are passed by a
   `/from\s*"[^"]*<stem>[^"]*"/` predicate — which is exactly what keeps the `watcher.ts` row green
   today, since `watcher` is a substring of `file-watcher.js`. **The third case is what forces
   resolve-and-compare rather than substring matching**, and without it the repoint below reads as
   optional.
5. The real rows are their own test: with `importsModule` in place and the policy repointed, the
   existing per-row loop is red before the repoint and green after. Record that ordering in the PR body.
