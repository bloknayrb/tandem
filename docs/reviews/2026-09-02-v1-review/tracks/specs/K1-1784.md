## Problem

**Half 1.** `tests/server/license-gate-coverage.test.ts:139-151` is the completeness net Critical
Rule 9 leans on. It builds `registered` from `/(?:gatedTool|withErrorBoundary)\(\s*"(tandem_\w+)"/`
— the two **wrapper** names. A tool registered as `server.tool("tandem_zzz", schema, handler)` with
no wrapper is in neither `registered` nor `GATED`/`UNGATED`, `unclassified` stays empty, and the
suite is green while the tool ships ungated. `tests/docs/tool-count-drift.test.ts:62-66` already has
the right derivation (`/server\.(?:tool|registerTool)\(\s*"(tandem_\w+)"/g`) but compares only
counts. Measured on this branch: both derivations yield the same **33** names, so the bug is latent,
exactly as the issue says.

`GATED` (`:53-67`) and `UNGATED` (`:73-109`) are also two arrays with their justifications in block
comments above each, so track H's cross-array move (decision F / #1788) edits three places.
**Half 2.** `tests/scripts/coverage-gate-wiring.test.ts:105-119` proves each policy row's `suite`
"actually references the module" with `source.includes(stem)`. `suite` is the ADR-051 half that
detects *deleted* behaviour, so this is load-bearing. Measured over all 14 rows: **12 statically
import their module; 2 do not** —

- `src/server/annotations/projection.ts` → `tests/server/events/channel-projection-characterization.test.ts`
  imports nothing from it; the stem matches five `describe(...)` titles, so the check passes on prose.
- `src/server/documents/watcher.ts` → `tests/server/file-watcher.test.ts`, which imports
  `src/server/file-watcher.js` — a **different module**. The stem `watcher` is a substring of that
  specifier, so a row aimed at the wrong module has been green since it was written.

## Fix

### `tests/server/license-gate-coverage.test.ts`

- Replace `GATED`/`UNGATED` with one data list, the shape track H widens by editing one row:
  `type ToolGate = { name: string; gate: "gated" | "ungated"; why: string }` and
  `const TOOL_GATES: ToolGate[]` with today's 33 names. The three **per-tool** sentences in the
  current comments become `why` values verbatim (`tandem_resolveAnnotation`'s "would needlessly
  block triage", `tandem_open`'s in-handler `force` note at `:75-79`, `tandem_diagnostics`' self-
  diagnose note at `:105-107`); the two **list-scoped** rationales (`:53-57` and `:82-92`) are
  statements about the partition rather than any row, so they move verbatim into the docblock above
  `const TOOL_GATES`. **Do not move the `tandem_resolveAnnotation` row — decision F is track H's
  change, not this PR's.** Derive
  `const GATED = TOOL_GATES.filter(r => r.gate === "gated").map(r => r.name)` and `UNGATED`
  likewise; the two `it.each` loops at `:112-129` are unchanged. (A mis-typed `gate` value cannot
  silently empty a loop: the union type is a compile error, and `tests/` is typechecked by
  `npm run typecheck:tests`.)
- Rewrite the completeness `it` at `:139` to derive `registered` from the **registration** shape.
  The derivation is **one module-scope binding in this file, used by both call sites** —
  `const REGISTRATION_RE = /server\.(?:tool|registerTool)\(\s*"(tandem_\w+)"/g;` plus
  `function registeredToolNames(src: string): Set<string>` — reusing `tool-count-drift.test.ts`'s
  regex **verbatim**. The completeness `it` and the synthetic-negative `it` in `Tests` both call
  `registeredToolNames`; **neither restates the pattern literal.** A test that re-spells the regex is
  worthless: it passes against its own copy while `:139` stays on the shipped wrapper-derived form,
  which is the one defect #1784 names. The `it` compares the derived set against the `TOOL_GATES`
  name set in both directions (unclassified, stale), keeping the existing failure messages. Reusing
  the anchored form is deliberate: it keeps the two name-at-registration derivations identical, so
  no other suite (`tests/server/search-worker.test.ts:267` pins `'server.tool("tandem_'` as a
  forbidden shape) desynchronises, and nothing outside this file changes.
- Two sentences in the rewritten docblock, because a green gate otherwise reads wider than it is:
  the scan root is `src/server/mcp/**` only, so a registration outside it is unseen; and the
  derivation keys on a **string-literal** `"tandem_…"` name at the registration call, so a tool
  whose name is a `const` there is unseen too (measured absent — all 33 carry literals). The review
  inventory in `docs/licensing-explained.md`, not the regex, is what covers those shapes.

### `tests/scripts/coverage-gate-wiring.test.ts` + `scripts/ci/coverage-policy.json`

- Replace the `includes(stem)` body at `:105-119` with a local pure
  `importsModule(suiteSource: string, suiteDir: string, moduleAbs: string): boolean`: scan
  `/from\s*"(\.[^"]*)"/g`, resolve each specifier against `suiteDir`, and accept the module if it
  equals the specifier as written, with `.js` → `.ts`, or with `.ts` appended (that triple covers
  all 12 passing rows, `.svelte.ts` included). Rename the `it` to say **imports**, and rewrite its
  comment: the old one argues *for* a text reference, and the two rows below are what that argument
  cost. Matching only `from "…"` is what keeps this free of any `vi.mock` handling — a mock call is
  never of that form — so **do not build a mock resolver**; a row that can only reach its module
  through a mock (or through a `@server/…` alias, none today) gets **repointed** instead.
- Repoint the two failing rows in `scripts/ci/coverage-policy.json`, `suite` field only (`path`,
  floors and `observed` untouched; `coverage-gate.mjs` never reads `suite`):
  `src/server/documents/watcher.ts` → `tests/server/reload-from-disk-persistence.test.ts` (imports
  `documents/watcher.js` at `:67`, and its last two describes are about that module's reload
  wiring), and `src/server/annotations/projection.ts` →
  `tests/server/events/channel-eligible-brand.test.ts` (imports six of projection's exports at
  `:20-28`).

## Tests

Both live in the file they guard, so no new module.

1. `license-gate-coverage.test.ts` — `it("the derivation sees a registration with no wrapper")`:
   `registeredToolNames('server.tool("tandem_zzz", {}, async () => {});\nserver.registerTool("tandem_yyy", {}, h);')`
   yields `{tandem_zzz, tandem_yyy}`. It calls the same helper the completeness `it` uses and does
   **not** re-declare the pattern — a copied regex literal asserted against a string is a tautology
   that stays green with `:139` still wrapper-derived. Kills the shipped wrapper-derived regex on a
   synthetic negative.
2. `coverage-gate-wiring.test.ts` — `it("a suite that only names the module does not count")`,
   **three cases, the third load-bearing**: `importsModule('describe("projection", …)', dir, abs)` is
   `false`; the same source plus
   `import { createdPayload } from "../../../src/server/annotations/projection.js";` is `true`; and,
   taken from the real failing row,
   `importsModule('import { watchFile } from "../../src/server/file-watcher.js";', <tests/server>,
   <ROOT>/src/server/documents/watcher.ts)` is **`false`** while the same source against
   `<ROOT>/src/server/file-watcher.ts` is `true`. The first two alone are passed by a
   `/from\s*"[^"]*<stem>[^"]*"/` predicate — which is exactly what keeps the `watcher.ts` row green
   today — so the third is what forces resolve-and-compare.
3. The real rows are their own test: with `importsModule` in place the existing per-row loop is red
   before the repoint and green after — record that ordering in the PR body.

off the `server\.` receiver, and the `search-worker.test.ts` / `tool-count-drift.test.ts` edits that

## Review corrections (scope cut)

The three earlier review rounds grew this spec into a framework. Removed, with reasons:

- **The wrapper/registration set union, and its dedicated test.** #1784's body is about a *bare*
  registration; the union addressed a different, measured-absent shape (const name at `.tool(`,
  literal at the wrapper). Removed, and named in `Not in scope` so it is a stated residual rather
  than an oversight.
- **Dropping the `server\.` anchor**, and with it the same-commit edits to
  `tests/server/search-worker.test.ts:267` and `tests/docs/tool-count-drift.test.ts:64`. Reusing
  tool-count-drift's regex verbatim gives the same 33 names with zero files outside the issue touched.
- **The partition `it`** (`GATED.length + UNGATED.length === TOOL_GATES.length`). It guarded a
  mis-typed `gate` value, which the `"gated" | "ungated"` union plus `typecheck:tests` already
  rejects at compile time.
- **Two of the four docblock facts** — the channel-shim `setRequestHandler` surface and
  `local-model/tools.ts`'s `MUTATING_TOOLS`. Both are true and both are already enumerated in
  `docs/licensing-explained.md`; restating them here is doc drift with two homes.
- **The alternative-suite comparisons** for the two repoints. The chosen rows import their module
  directly, which is the whole criterion.

No blocking finding from round 3 targeted this spec; nothing was repaired here, only cut.
