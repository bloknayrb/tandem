# C — #1710 ADR-027 says highlights are not sent to Claude; `tandem_getAnnotations` filters type only

Branch `fix/privacy-and-authority-1769`. Closes #1710, folded with #1619 (the same audience filter, C-1619 carries the mechanism). Ledger: `areas/annotations.md:31-32`. Probe: `docs/decisions.md:307` ("`highlight` (visual marker, not sent to Claude)") against `src/server/mcp/annotations.ts:409-410` (`a.type !== "note"`).

## Problem

Two independent writers stamp user highlights `audience: "private"` — `Toolbar.svelte:803` and `shared/sanitize.ts:82-87` — and the channel honours it (`projection.ts:262`), but `tandem_getAnnotations` and `tandem_exportAnnotations` never read `audience`, so every user highlight is returned to Claude on each read and written into the export sidecar. The issue's open question is which side is wrong: the ADR line and the stamp, or the filter. It also flags that ADR-027's 2026-05-15 revision (`decisions.md:315`) says notes are "surfaced via `tandem_getAnnotations`", which the code (`annotations.ts:408-410`) and the 2026-06-17 revision (`:317`) both contradict.

## Fix

**Decision, applied (option 1 of the issue): ADR-027 means it.** `audience: "private"` is the privacy field, four surfaces already honour it, the shipped skill tells Claude "Highlights are also user-only" (`skills/tandem/SKILL.md:61`), and the sweep notes say so. The filter is what changes; the ADR line and the stamp stay. The mechanism is entirely C-1619's `isClaudeFacing` — nothing further to code here. What is #1710's own:

- **Effect on highlights.** After C-1619, `tandem_getAnnotations({ type: "highlight" })` returns only Claude-authored highlights carrying `audience: "outbound"` — today that is the tutorial seed (`mcp/tutorial-annotations.ts`, stated outbound per `projection.ts:45-48`) and nothing else, since `tandem_highlight` is a refusing stub. The export's `## Highlights` section shrinks the same way. Both are the intended reading of the ADR, and each surface discloses its own shrink: `getAnnotations` through the `privateExcluded` field on `getAnnotationsOutputShape`, and the export through the SEPARATE `privateExcluded` count C-1619 adds beside `heldFromExport` in the sidecar JSON, the response and the markdown footer (the export has no output schema and does not carry `getAnnotations`'s field).
- **`docs/decisions.md:315`** — replace "visible to the user, surfaced via `tandem_getAnnotations`, but not auto-pushed to Claude" with "visible to the user and excluded from every Claude-facing read (`tandem_getAnnotations`, `tandem_exportAnnotations`, `tandem_checkInbox`) as well as the channel". Add a dated amendment line at the end of ADR-027 (the file's convention, e.g. `:317-318`): 2026-09-07 — the pull surfaces filter on `audience` as the channel does (#1619, #1710); highlights stamped `private` are never sent to Claude, as `:307` has always said.
- **`docs/mcp-tools.md:634-641`** — the `type` filter row for `highlight` gets "(Claude-authored, outbound highlights only; user highlights are private — ADR-027)".
- **`skills/tandem/SKILL.md:61`** — already correct ("Highlights are also user-only"); no edit. The version bump this PR makes belongs to C-1770.

The review criterion in the issue ("whether `annotations.ts`'s read filter mentions `audience` at all, and whether `decisions.md`'s ADR-027 highlight line still says 'not sent to Claude'") is answerable from tracked files after this lands: yes and yes, and they agree.
