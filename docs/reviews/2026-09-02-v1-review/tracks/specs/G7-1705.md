## Problem

`textSize` lives in `src/client/hooks/useTandemSettings.ts:119` (`TEXT_SIZE_PX` `:241`, default `"m"` `:264`, normalized `:574-577`). The only thing that writes it is the radiogroup in `src/client/components/AppearanceSettings.svelte:161-189` (`createRadioGroup` `:57-61`). App applies it as `--tandem-editor-font-size` on `<html>` (`src/client/App.svelte:1131-1135`).

There is no control outside the modal. Changing the size mid-read means opening Settings, finding the tab, and closing it again.

## Fix

One shared **display menu** carries both text size (this issue) and reading measure (#1706). Both issues allow a shared control, and one trigger avoids adding two buttons to a bar that already truncates at 640px.

The menu has **two homes**: the persistent formatting bar, and the selection popup's format row. The popup copy is required, not optional. The popup is documented to mirror every bar control so each stays reachable when the bar is hidden (`src/client/editor/toolbar/Toolbar.svelte:61-63`, `:1066-1067`), and it already renders `<DecorationsMenu>` for that reason. A bar-only menu would make that guarantee false. It would also leave users who hide the bar with no quick control, which fails #1705's first criterion.

### `src/client/shell/DisplayMenu.svelte` (new)

Model it on `DecorationsMenu.svelte` in the same directory. Copy the menu mechanics as they are rather than reinventing them:

- An explicit `import "../editor/toolbar/toolbar-chrome.css"`. `toolbar-chrome-cascade.test.ts` requires this direct import in every file that uses `tandem-toolbar-ctl`.
- One `use:clickOutside={closeMenu}` wrapper holding both the trigger and the menu (`:97-104`).
- `ESCAPE_OWNER_ATTR` while the menu is open (`:101`).
- `focusMenuEntryPoint(menuEl)` called from an `$effect` on open (`:45-47`).
- `handleMenuArrowKeys`, then Escape → `closeMenu()`, with focus restored to the trigger (`:67-82`).
- The menu body renders **only behind `{#if menuOpen}`**, as DecorationsMenu's does (`:149`). Its items therefore never count as bar buttons at rest.

**The focus `$effect` reads only `menuOpen` and `menuEl`.** This menu stays open after a choice. If the effect also read `textSize` or `editorMeasure`, it would re-run on every pick and pull focus back to the checked radio. A unit case below pins this.

**Props:** `textSize: TextSize`, `editorMeasure: EditorMeasure` (the #1706 half), `sourceViewActive?: boolean` (default `false`), and `onUpdate(partial: { textSize?: TextSize; editorMeasure?: EditorMeasure })`. **The menu holds no copy of either value.** Everything it renders comes from props, so Settings and the menu cannot disagree. That is the issue's "no second state" criterion.

**Trigger:**

- Markup: `<button type="button" class="dm-trigger tandem-toolbar-ctl" data-testid="display-menu-trigger" aria-haspopup="menu" aria-expanded={menuOpen} title="Display options">` with an `Aa` glyph marked `aria-hidden`.
- Keep the class attribute static. The cascade test does not parse `class:` directives for this class.
- **The accessible name carries the current value:** `aria-label={`Display options: text ${TEXT_LABEL[textSize]}, measure ${MEASURE_LABEL[editorMeasure]}`}`.
- The trigger keeps the shared 26px / 1px `tandem-toolbar-ctl` metrics, with no height or border override (`toolbar-a8-fidelity.spec.ts:201-202` measures every bar button).

**Menu:**

- Structure: `<div data-testid="display-menu">` wraps `role="menu" aria-label="Display"`.
- The first group is `role="group" aria-label="Text size"`. It holds one `role="menuitemradio"` button for each of `s|m|l`, labelled "Small", "Medium" and "Large".
- Each item has `aria-checked={textSize === size}`, `data-testid={`display-menu-text-size-${size}`}` and `onclick={() => onUpdate({ textSize: size })}`.
- Labels come from `const TEXT_LABEL: Record<TextSize, string>`, so a missing preset is a compile error.
- **The menu stays open after a choice.** The user sees the change behind it and can adjust the other group. Escape, a click outside, or the trigger closes it.
- `menuitemradio` has precedent in `TitleBar.svelte:270` and `FormattingToolbar.svelte:432`, and `focusMenuEntryPoint` already opens on the checked radio. `menuKeys.ts:67` `items()` queries every `[role^="menuitem"]` descendant, so arrow keys cross group boundaries with no extra code.

**Source view (decision).** The menu stays enabled, and both presets apply to the formatted editor only. Neither has a visible effect in source view:

- The textarea uses a fixed `font-size: var(--tandem-text-sm)` (`SourceView.svelte:397`).
- The stage that carries `--editor-measure` is replaced by `<SourceView>` (`App.svelte:2972-2985`).

So while `sourceViewActive` is true, the menu shows a non-interactive note under its header: `<p class="menu-note" data-testid="display-menu-source-note">Applies to the formatted editor</p>`. It is not a menu item, so arrow keys skip it. The textarea is deliberately **not** made to follow text size; that is outside these issues.

**Styles:**

- Copy `.menu`, `.mi` and `.menu-head` from `DecorationsMenu.svelte:430-491`, and set `min-width: 200px`.
- Show the checked state with a check glyph (`color: var(--tandem-accent)`, opacity keyed on `[aria-checked="true"]`). **Never use an accent background or border.** This is a design rule, not a tested one: `pressed-toggle-state.test.ts`'s `ACTIVE_STATE_RE` (`:45-46`) matches neither `[aria-checked` nor `[aria-expanded`, so neither sweep sees these rules.
- **Resting `.dm-trigger:hover`:** `background: var(--tandem-surface-muted); color: var(--tandem-fg)`. That is a tint, not the sunk surface, following DecorationsMenu `.ib:hover` (`:333`).
- **`.dm-trigger:focus-visible`:** an accent outline, following `.ib:focus-visible` (`:337`).
- Both rules above are required by `toolbar-chrome-cascade.test.ts:240-265`, which accepts only a RESTING hover. A `[aria-expanded="true"]:hover` rule does not count.
- **Open state:** `.dm-trigger[aria-expanded="true"]` copies `.half-caret[aria-expanded="true"]` (`--tandem-surface-sunk` plus `var(--tandem-shadow-inset)`, `:367-373`), **for visual consistency with that caret**.
- **Forced colors:** copy the caret's block too (`DecorationsMenu.svelte:383-389`) as `@media (forced-colors: active) { .dm-trigger[aria-expanded="true"] { border-color: Highlight; } }`. Forced colors suppresses both the fill and the inset.
- **Pin the inset:** add `["src/client/shell/DisplayMenu.svelte", '.dm-trigger[aria-expanded="true"]']` to `PRESSED_TOGGLES` in `tests/design-system-impl/pressed-toggle-state.test.ts` (`:99-105`). The derived sweep cannot see this rule, so the positive pin is what holds the inset.
- Any `transition` gets its reduced-motion guards in the same file, after the rule (`reduce-motion-guards.test.ts`).
- Tokens only (`npm run check:tokens`).
- All CSS goes in this component's `<style>`, none in `index.html` (the two-CSS-pipelines gotcha).

## Tests

### 1. New `tests/client/DisplayMenu.svelte.test.ts`

happy-dom with `@testing-library/svelte`, following `highlight-color-picker-keyboard.test.ts`.

- **Settings → quick, mount state:** for `textSize: "m"`, the trigger's `aria-label` contains "Medium". After `rerender({ textSize: "s" })` it contains "Small", and `display-menu-text-size-s` is `aria-checked="true"`. **Kills** a menu that copies the prop into local state at mount.
- **Focus on open:** opening the menu focuses `display-menu-text-size-m`, the checked item, not "Small". **Kills** a menu that skips `focusMenuEntryPoint`, or one whose arrow keys never reach the handler.
- **Keyboard open:** with focus on the trigger, `Enter` opens the menu (`aria-expanded="true"`, focus on the checked item). **Kills** a pointer-only trigger.
- **One write, menu stays open:** clicking `display-menu-text-size-l` calls `onUpdate` exactly once with `{ textSize: "l" }`, and the menu stays open. **Kills** a second state, and a write under the wrong key.
- **No focus pull-back:** open the menu and move focus to `display-menu-text-size-l`. After `rerender({ textSize: "s" })`, `document.activeElement` is still `display-menu-text-size-l`. **Kills** a focus `$effect` that reads a preset prop.
- **Source note:** `display-menu-source-note` is absent by default. It is present after `rerender({ sourceViewActive: true })`, and it has no `role^="menuitem"`.
- **Escape:** Escape closes the menu and returns focus to the trigger. **Kills** focus stranded on `<body>`.
