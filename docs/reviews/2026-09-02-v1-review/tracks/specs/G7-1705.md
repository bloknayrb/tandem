## Problem

`textSize` (`src/client/hooks/useTandemSettings.ts:119`, default `"m"` `:264`) has one writer: the radiogroup in `src/client/components/AppearanceSettings.svelte`. App applies it as `--tandem-editor-font-size` (`App.svelte:1132`). Nothing outside the Settings modal can change it.

## Fix

A single **display menu** holds text size here and reading measure in #1706. Both issues allow a shared control. It has two homes: the formatting bar, and the selection popup's format row. The popup copy is needed because the popup is documented to mirror every bar control so each stays reachable when the bar is hidden (`Toolbar.svelte:61-63`, `:1066-1067`). The popup already renders `<DecorationsMenu>` for that reason.

**`src/client/shell/DisplayMenu.svelte` (new).** Copy the mechanics of `DecorationsMenu.svelte` rather than reinventing them:
- the `toolbar-chrome.css` import
- `use:clickOutside`
- `ESCAPE_OWNER_ATTR` while open
- `focusMenuEntryPoint` on open
- `handleMenuArrowKeys`
- Escape → `closeMenu()` with focus returned to the trigger
- the menu body rendered only behind `{#if menuOpen}`

Behaviour:
- **Props:** `textSize`, `editorMeasure` (used by #1706), `onUpdate(partial)`. The menu keeps no local copy of either value; that is the issue's "no second state" requirement.
- **Trigger:** `<button type="button" class="dm-trigger tandem-toolbar-ctl" data-testid="display-menu-trigger" aria-haspopup="menu" aria-expanded={menuOpen}>` with an `Aa` glyph marked `aria-hidden`. Its `aria-label` includes the current value, e.g. `Display options: text Medium, measure Comfortable`.
- **Menu:** `<div data-testid="display-menu">` wrapping `role="menu"`. Inside it, `role="group" aria-label="Text size"` holds one `menuitemradio` each for Small, Medium and Large. Each has `aria-checked={textSize === size}`, `data-testid="display-menu-text-size-{s|m|l}"` and `onclick` → `onUpdate({ textSize })`.
- **Picking an item closes the menu** and returns focus to the trigger, as Decorations items do.

Styles are copied from DecorationsMenu, using tokens only. The existing `toolbar-chrome-cascade.test.ts` requires a resting `.dm-trigger:hover` and a `.dm-trigger:focus-visible` rule. Show the checked state with a check glyph, never an accent fill.

**`src/client/shell/FormattingBar.svelte`.**
- Add optional `textSize = "m"`, `editorMeasure = "comfortable"` and `onUpdateDisplay`.
- Render `{#if onUpdateDisplay}` + separator + `<DisplayMenu>`, placed after the Decorations block (`:203`) and before the source toggle (`:221`).
- It must sit outside `formatting-bar-track` (`:196`) so it never truncates.

**`src/client/editor/toolbar/Toolbar.svelte`.**
- Add the same three optional props.
- In `popup-format-row` (`:1104`), after the Decorations block, render `<DisplayMenu>`. Wrap it in the same `onmousedown={(e) => e.preventDefault()}` wrapper DecorationsMenu uses so the selection survives.
- Amend the two mirror comments to name the display menu.

**`src/client/App.svelte`.** At both `<Toolbar>` (`:2306`) and `<FormattingBar>` (`:2331`), pass:
- `textSize={settingsState.settings.textSize}`
- `editorMeasure={settingsState.settings.editorMeasure}`
- `onUpdateDisplay={(p) => settingsState.updateSettings(p)}`

That is the path Settings already writes through. Read-only blobs are refused centrally (#1722), and no Tiptap handler is involved.

## Tests

**1. New `tests/client/DisplayMenu.svelte.test.ts`** (happy-dom, `@testing-library/svelte`):
- **Settings → quick:** mount with `textSize: "m"`; the trigger label contains "Medium". After `rerender({ textSize: "s" })`, the label contains "Small" and `display-menu-text-size-s` is `aria-checked="true"`.
- **Keyboard:** Enter on the trigger opens the menu with focus on the checked item. Escape closes it and focus returns to the trigger.
- **One write:** clicking `display-menu-text-size-l` calls `onUpdate` exactly once with `{ textSize: "l" }`.

**2. New `tests/e2e/display-menu.spec.ts`.**

`beforeEach` writes `tall.md` into `tmpDir`: an H1 plus 150 short paragraphs, the same shape as `scroll-pill.spec.ts` `openTall` (`:97`). It opens the file with `tandem_open`. The 241-byte `sample.md` cannot scroll, so it is not used.

Locator scoping: bar locators go under `[data-testid='formatting-bar']`, popup locators under `[data-testid='popup-format-row']`.

- **Quick → Settings:** pick Large. `--tandem-editor-font-size` polls to `18px`, `localStorage` has `textSize: "l"`, and in Settings `text-size-l-btn` is `aria-checked="true"`.
- **Settings → quick, and persistence:**
  1. Pick `text-size-s-btn` in the modal.
  2. Press Escape, then wait for `settings-modal` to reach `toHaveCount(0)`.
  3. Small is checked in the menu.
  4. After `page.reload()`, Small is still checked.
- **Preserves the document:**
  - **Setup:** tag `.tandem-editor` (the ProseMirror `view.dom`) with `__g7`. Set `.editor-scroll` `scrollTop = 500` and assert `> 200` as a precondition. Read `__tandemTest.activeDocumentId()`.
  - **After picking Large:** the tag survives, `scrollTop > 0`, and the document id is unchanged.
  - The tag is what detects a remount. The #1055 per-tab scroll memory (`App.svelte:1782-1832`) restores `scrollTop` across a remount, so scroll alone would not catch one. The scroll check covers the issue's "does not reset scroll" criterion.
  - Selection lives on the same view, so no remount means the selection is kept.
- **Bar hidden, popup mirror:**
  1. Click `formatbar-hide-btn`.
  2. Select the first paragraph with `selectTextStable`.
  3. Pick Small from the popup's display menu.
  4. The font size polls to `14px` and `.selection-popup` is still visible. Small is not the default, so this passes only if the popup's write landed.

**3. Mutation checks,** each restored from a file copy:
