## Problem

`textSize` (`src/client/hooks/useTandemSettings.ts:119`, `TEXT_SIZE_PX` `:241`, default `"m"` `:264`, normalized `:574-577`) is written only by the radiogroup in `src/client/components/AppearanceSettings.svelte:161-189` (`createRadioGroup` `:57-61`). App applies it as `--tandem-editor-font-size` on `<html>` (`src/client/App.svelte:1131-1135`). There is no control outside the modal, so changing it mid-read means opening Settings, finding the tab, and closing it again.

## Fix

One shared **display menu** in the persistent formatting bar carries both text size (this issue) and reading measure (#1706). Both issues allow a shared control; one trigger avoids adding two buttons to a bar that already truncates at 640px.

- **New `src/client/shell/DisplayMenu.svelte`**, modelled on `DecorationsMenu.svelte` (same directory). Copy its menu mechanics as they are, don't reinvent them: explicit `import "../editor/toolbar/toolbar-chrome.css"` (`toolbar-chrome-cascade.test.ts` requires the direct import in every file that uses `tandem-toolbar-ctl`); one `use:clickOutside={closeMenu}` wrapper holding both the trigger and the menu (`:97-104`); `ESCAPE_OWNER_ATTR` while open (`:101`); `focusMenuEntryPoint(menuEl)` from an `$effect` on open (`:45-47`); `handleMenuArrowKeys` then Escape → `closeMenu()` with focus restored to the trigger (`:67-82`).
  - Props: `textSize: TextSize`, `editorMeasure: EditorMeasure` (the #1706 half), and `onUpdate(partial: { textSize?: TextSize; editorMeasure?: EditorMeasure })`. **The menu holds no copy of either value.** Everything it renders comes from props, so Settings and the menu cannot disagree (the issue's "no second state" criterion).
  - Trigger: `<button type="button" class="dm-trigger tandem-toolbar-ctl" data-testid="display-menu-trigger" aria-haspopup="menu" aria-expanded={menuOpen} title="Display options">` with an `Aa` glyph (`aria-hidden`). The class attribute stays static, because the cascade test does not parse `class:` directives for this class. **Accessible name carries the current value**: `aria-label={`Display options: text ${TEXT_LABEL[textSize]}, measure ${MEASURE_LABEL[editorMeasure]}`}`.
  - Menu: `role="menu" aria-label="Display"`. The first `role="group" aria-label="Text size"` holds one `role="menuitemradio"` button per `s|m|l` ("Small"/"Medium"/"Large"), with `aria-checked={textSize === size}`, `data-testid={`display-menu-text-size-${size}`}` and `onclick={() => onUpdate({ textSize: size })}`. Labels are `const TEXT_LABEL: Record<TextSize, string>`, so the `Record` type makes a missing preset a compile error. **The menu stays open after a choice**, so the user sees the change behind it and can adjust the other group. Escape, clicking outside, or the trigger closes it.
  - `menuitemradio` is the precedent in `TitleBar.svelte:270` and `FormattingToolbar.svelte:432`, and `focusMenuEntryPoint` already opens on the checked radio. `menuKeys.ts:67` `items()` queries every `[role^="menuitem"]` descendant, so arrow keys cross group boundaries with no extra code.
  - Styles: copy `.menu`/`.mi`/`.menu-head` from `DecorationsMenu.svelte:430-491` and set `min-width: 200px`. Show the checked mark with a check glyph (`color: var(--tandem-accent)`, opacity keyed on `[aria-checked="true"]`), **never an accent background or border**, which `pressed-toggle-state.test.ts` bans on activated states. The trigger's open state copies `.half-caret[aria-expanded="true"]` (`--tandem-surface-sunk` plus `var(--tandem-shadow-inset)`, `:367-373`), because the sunk-without-inset sweep fails otherwise. Any `transition` gets its reduced-motion guards in the same file, after the rule (`reduce-motion-guards.test.ts`). Tokens only (`npm run check:tokens`). All CSS goes in this component's `<style>` and none in `index.html` (two CSS pipelines gotcha).
- **`src/client/shell/FormattingBar.svelte`**: add optional `textSize`, `editorMeasure` and `onUpdateDisplay` props. Render `<DisplayMenu>` after the Decorations block (`:203-214`) and before the source toggle (`:215`), preceded by a `tandem-toolbar-sep`. It goes **outside `formatting-bar-track`** (`:195-202`) so it never truncates. The `:has([aria-expanded="true"])` z-index lift (`:286`) covers it with no change, because the trigger publishes `aria-expanded`.
- **`src/client/App.svelte`** at the `<FormattingBar>` call (`:2331-2347`): `textSize={settingsState.settings.textSize}`, `editorMeasure={settingsState.settings.editorMeasure}`, `onUpdateDisplay={(partial) => settingsState.updateSettings(partial)}`. This is the same path Settings writes through (`useTandemSettings.svelte.ts` `updateSettings` → `mergeAndClampSettings` → `localStorage` in try/catch). A read-only (newer-schema) blob is refused and notified centrally (#1722), exactly like DecorationsMenu, so the menu needs no read-only branch. No Tiptap event handler is involved, so no `$state` write needs `createCoalescingTick`.
- Testids are additive (Critical Rule 7): `display-menu`, `display-menu-trigger`, `display-menu-text-size-{*}`. Regenerate `tests/design-system-impl/__snapshots__/testid-set.snap.txt` with `npx vitest run tests/design-system-impl/testid-coverage.test.ts -u` in the same commit, and add a "Display menu" bullet under the formatting-bar group in `docs/design-system-impl/testid-manifest.md` (`:75-88`).
- `docs/user-guide.md:57`: one sentence saying the bar's display menu sets text size and reading measure without opening Settings.

## Tests

1. **New `tests/client/DisplayMenu.svelte.test.ts`** (happy-dom, `@testing-library/svelte`, following `highlight-color-picker-keyboard.test.ts`):
   - The trigger's `aria-label` contains "Medium" for `textSize: "m"`. After a `rerender({ textSize: "s" })` it contains "Small" and the `display-menu-text-size-s` item is `aria-checked="true"`. **Kills** a menu that copies the prop into local state at mount (Settings → quick direction).
   - Opening the menu focuses `display-menu-text-size-m`, the checked item, not "Small". **Kills** a menu that skips `focusMenuEntryPoint`, or the arrow keys never reach the handler.
   - Clicking `display-menu-text-size-l` calls `onUpdate` exactly once with `{ textSize: "l" }`, and the menu stays open. **Kills** a second state, and a write under the wrong key.
   - Escape closes the menu and focus returns to the trigger. **Kills** focus stranded on `<body>`.
2. **New `tests/e2e/display-menu.spec.ts`** (MCP-opened `sample.md` fixture, following `settings-and-filters.spec.ts:56-125`):
   - **Quick → Settings:** pick Large in the menu. `--tandem-editor-font-size` on `<html>` polls to `18px`, and `localStorage["tandem:settings"]` has `textSize: "l"`. After `openSettingsViaBrandMenu` (`helpers.ts:375`), `text-size-l-btn` is `aria-checked="true"`.
   - **Settings → quick:** pick `text-size-s-btn` in the modal, press Escape, open the menu: `display-menu-text-size-s` is checked.
   - **Persists:** `page.reload()`, open the menu: Small is still checked.
   - **Preserves the document:** before the change, tag the `.tandem-editor` node (`el.__g7 = 1`), scroll `.editor-scroll` down, and read `__tandemTest.activeDocumentId()` (`App.svelte:833`). After the change the tag survives, `scrollTop > 0`, and the id is unchanged. **Kills** a `{#key}` remount or a reload-based apply. Selection preservation follows from no remount, because ProseMirror selection lives on the view. A direct selection assertion is not used: headless ProseMirror drops the DOM selection around synthesized clicks (header of `formatting-bar-popovers.spec.ts`).
3. **Mutation checks, each restored from a file copy:** (a) delete the `aria-checked` binding → the unit rerender case goes red; (b) make the item's `onclick` a no-op → both the E2E quick→Settings case and the unit `onUpdate` case go red; (c) delete `onUpdateDisplay` from App's `<FormattingBar>` → the E2E quick→Settings case goes red.
