# E2-rust — #1810 `refresh_registration` runs only on autostart launches, so a moved app or a flagless registration is never repaired

Branch `fix/desktop-sidecar-lifecycle-and-start-at-login-repair-1762`. Closes #1810. Ledger: `docs/reviews/2026-09-02-v1-review/areas/tauri.md:20`. Probe: none automatable (the repair is an OS registration write); verification is `cargo test` plus a smoke line for Bryan.

## Problem

`refresh_registration` (`src-tauri/src/autostart.rs:138`) re-writes an existing login item with the current executable path and argument list. It is idempotent by construction — it only calls `manager.enable()` when `manager.is_enabled()` already returns `Ok(true)`, so it can never turn autostart on.

Its single call site (`src-tauri/src/lib.rs:1518-1531`) sits inside `if autostart_launch {` (`:1486`), the branch that runs only when the app was itself launched *by* the registration. The repair therefore requires the thing it repairs to be working:

- A user enables start-at-login, then moves or renames the app (or a macOS update changes the bundle path). The login item points at the old path, autostart never fires, and the repair path is unreachable forever.
- A registration written by a Tandem older than `--tandem-autostart` boots visible and spawns Claude — the exact behaviour the flag exists to prevent — and is only upgraded on a launch *that registration* produced.

The existing comment at `:1523-1526` states the rationale as "a user who moved the app will autostart at least once before the path matters", which is the assumption the issue refutes: a moved app does not autostart at all.

## Fix

Hoist the spawn block out of the `if autostart_launch {` branch so it runs on **every** launch.

- Move `lib.rs:1518-1531` (the `{ let refresh_handle = app.handle().clone(); tauri::async_runtime::spawn_blocking(move || { autostart::refresh_registration(&refresh_handle); }); }` block) to just **before** `if autostart_launch {` at `:1486`, still after the tray build. It does not read `tray_available`, `hide`, or anything else from that branch, so nothing else moves with it.
- Rewrite its comment. The "Scoped to autostart launches" sentence and the "will autostart at least once" claim are now wrong and are precisely what a later reader would restore the `if` from. New text: runs on every launch because a *moved* app never autostarts, which makes an autostart-only repair unreachable for the one case it exists to fix; still only ever refreshes an existing registration (`is_enabled()` is the gate inside the function); still off the startup critical path.
- `refresh_registration`'s own docblock (`autostart.rs:130-137`) gains one line: it is called on every launch, and the `Ok(false)` arm is what keeps that from being an enable.

**Why this is safe on each platform, checked rather than assumed:**

- **Windows** — an HKCU `Run` value write per launch, off the critical path via `spawn_blocking`. No prompt, no elevation.
- **macOS** — the plugin is registered with `MacosLauncher::LaunchAgent` (`lib.rs:1098-1099`), so `enable()` writes a `LaunchAgents` plist. It does **not** take the AppleScript path that `autostart.rs`'s module docblock warns needs Automation (TCC) approval, so there is no per-launch consent prompt. This was the one real risk in running the refresh unconditionally and it does not apply. **Read, not run — there is no macOS hardware here.**
- **Linux** — a `~/.config/autostart/*.desktop` file write. Same shape as Windows.

**Rules that bite, all three from CLAUDE.md's start-at-login rule and none of them touched by this change:** the `LAUNCHER_DEFERRED` latch is stored once at `lib.rs:1148` from `resolve_autostart_launch` and re-read per sidecar spawn at `sidecar.rs:1752` — this edit does not move, capture or re-derive it. `show_main_window` remains the single release point. **No `tandem:settings` field is added**: the registration state is deliberately read from the OS on every call (`AutostartStatus`'s docblock, `autostart.rs:35-39`) precisely because it is mutable outside Tandem, and a mirrored boolean would drift.

**#1599 / `tests/docs/config-writer-set-claims.test.ts`:** that test pins the set of *Tandem config* writers in `src/`. `refresh_registration` writes an OS login item through `tauri-plugin-autostart`, not a Tandem config file, and is Rust — it is outside that test's sweep and the accepted finding's bound is not widened. State this in the PR body rather than leaving a reviewer to re-derive it.

## Tests

`refresh_registration` needs an `AppHandle`, so the discriminating test is structural, following `sidecar.rs:4107`'s `include_str!` precedent. Put it in `lib.rs`'s test module.

1. `fn refresh_registration_runs_on_every_launch_not_only_autostart_ones()` — `include_str!("lib.rs")`; find the single `autostart::refresh_registration(` call and the `if autostart_launch {` that opens the visibility block, and assert the call's byte offset is **before** that `if`. Goes red on today's code and on any re-nesting. Assert there is exactly **one** `autostart::refresh_registration(` occurrence first, with its own message — a fix that adds a second call rather than moving the first would otherwise pass by coincidence.
2. `autostart.rs`: `fn refresh_registration_is_gated_on_an_existing_registration()` — `include_str!("autostart.rs")`, slice the function body, assert it contains `is_enabled()` and that the `Ok(false)` arm is present (`Ok(false) => {}`). This is the invariant that makes "run it on every launch" safe: without the gate, an unconditional call would *enable* start-at-login for every user on their next launch. That is the single worst outcome of this change and nothing else pins it.

The three existing `autostart.rs` tests (`error_codes_are_path_free`, `io_errors_map_to_the_io_code`, and the anyhow one) are unaffected and must stay green.

**Mutation check:** move the block back inside `if autostart_launch {` and test 1 goes red; delete the `Ok(true)` guard from `refresh_registration` and test 2 goes red. Restore from a file copy, never `git checkout`.
