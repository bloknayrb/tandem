## Problem

1. `editPendingAnnotation` (`src/server/annotations/lifecycle.ts:891-953`) and `replyForClaude` (`:1279-1313`) have no author guard; the comment at `:939-945` admits Claude edits a USER-authored pending comment under the user's byline.
2. `transitionPending` (`:807-859`) lets Claude accept its own annotation, and records it indistinguishably from the user: `awareness.ts:636` puts every `author: claude` non-pending record into `userResponses`; `output-schemas.ts:246-248` documents that bucket as user decisions. An MCP accept never applies `suggestedText` (`applySuggestion` is client-only), so it flips status without editing.
3. The inbox ledger keys on `editedAt` alone (`awareness.ts:566-569`, `:635`, `:638`); the client's Undo writes `status: "pending"` without touching it (`useAnnotationReview.svelte.ts:732`), so accept → poll → undo → dismiss → poll returns `userResponses: []`.

## Fix

**Item 1 — author guard, `lifecycle.ts`.** In `editPendingAnnotation` after the ADR-027 guard (`:905`, C-1803's `isPrivateForClaude`) and before the pending check: `if (ann.author !== "claude") return { kind: "not-owned", author: ann.author };`. `EditResult` (`:378-384`) gains `| { kind: "not-owned"; author: Annotation["author"] }`. Same line in `replyForClaude` after `:1305-1307`; `ClaudeReplyResult` (`:251`) gains the arm, `ReplyRefusalCode` (`:254`) gains `"NOT_OWNED"`, `describeReplyWriteRefusal` (`:283`) gains the case (message: "Claude can only reply on annotations it authored; answer a user's comment with tandem_reply or a fresh tandem_comment"), and `routes/annotation-reply.ts:29-33` `REFUSAL_STATUS` gains `NOT_OWNED: 403` (the `Record` is exhaustive; the browser route never produces the code — it calls `addUserReply`). MCP: `annotations.ts:559` edit switch gains `case "not-owned": return mcpError("NOT_OWNED", …)`; the reply handler (`:906`) needs no change. **Order is the contract: not-found → sanitize → private → not-owned → pending.** So a user's note or private comment answers `invalid-note`, never `not-owned`; a USER highlight answers `not-owned` on both (the existing arms already disclose `annotationType` via `invalid-suggestion-target` / `not-repliable`, so this is not a new oracle — the family-wide note at `lifecycle.ts:130-150` covers it; one PR-body sentence). Guards go on `editPending`/`reply` only — never on `addUserReply` or `removeAnnotationRecord` (seam tests). Rewrite the `:939-945` docblock to the author-scope rule and the order above. The local-model loop (`local-model/tools.ts:294`, dark) inherits the reply guard.

- **Promotion no longer enables a Claude in-thread reply — a decision to state.** `promotedAnnotation` (`src/client/panels/annotation-actions.ts:74-77`) writes `author: "user"`, so a promoted note or Word comment answers `NOT_OWNED` on `tandem_annotationReply`; the replacement is `tandem_reply` (chat) or a fresh `tandem_comment`. Decision 4 forces this; the PR body says so, and the three surfaces describing the old flow change together: `annotation-promote-pull-surface.test.ts:286-318` (Tests 1), `skills/tandem/SKILL.md:118`, `docs/mcp-tools.md`'s reply section.

**Item 2 — never accept your own; stamp who resolved.** `transitionPending`, after the pending check (`:846-848`, so `not-pending` keeps precedence): `if (nextStatus === "accepted") { if (ann.author === "claude") return { kind: "accept-refused", reason: "own-annotation" }; if (ann.suggestedText !== undefined) return { kind: "accept-refused", reason: "unapplied-suggestion" }; }`. `LifecycleResult` (`:152-156`) gains `| { kind: "accept-refused"; reason: "own-annotation" | "unapplied-suggestion" }` — the deviation the `EditResult` docblock at `:347-353` argues against, taken knowingly (one function serves both verbs, one consumer); one sentence beside the union. The decision allowed "apply `suggestedText` or refuse": **refuse** — applying would make the tool write document content, falsifying `license-gate-coverage.test.ts:69` and pre-empting decision F. The `updated` literal (`:850-854`) adds `resolvedBy: "claude"`. Dismiss stays open to every non-private record (existing flow — no author check today). `mcp/annotations.ts:466-483`: `case "accept-refused"` → `mcpError("INVALID_ARGUMENT", …)` naming the reason, plus a `default: { const unhandled: never = result; … }` in the shape of `:520-528`; the tool description (`:443-447`) becomes "Claude may dismiss (withdraw) its own annotations; accept is the user's decision. Accepting a user-authored comment never applies text."

- `src/shared/types.ts:233` area: `resolvedBy?: "user" | "claude"` on `AnnotationBase` (docblock: absent means the user; it names who performed the CURRENT resolution). **`shared/sanitize.ts:130-146` is a strict allowlist** — add `...(ann.resolvedBy === "user" || ann.resolvedBy === "claude" ? { resolvedBy: ann.resolvedBy } : {})` or every Claude-facing read strips it (the `heldInSolo` lesson at `:132-138`). Durable schema is `.passthrough()`; no change. `output-schemas.ts` `annotationBaseShape` (`:53-95`) gains `resolvedBy: z.enum(["user", "claude"]).optional().describe("Who resolved this record; absent means the user")` — declared, not tolerated (`:68-79` states the rule).
- `awareness.ts:636`: `&& ann.resolvedBy !== "claude"`. `output-schemas.ts:248` describe: "The USER's accept/dismiss decisions; Claude's own resolves never appear."
- `applyChanges` needs no edit: `docx-apply.ts:199-204` writes only `accepted` records carrying `suggestedText`, and the `unapplied-suggestion` refusal means Claude can never produce one. Say so in a comment at `:204` rather than adding a guard for an unreachable record.
