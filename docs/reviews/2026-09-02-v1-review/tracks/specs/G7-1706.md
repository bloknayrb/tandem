# G7 — #1706 reading measure is reachable only through Settings → Editor

Branch `fix/editor-quick-controls-text-size-and-reading-measure-outside-settings-and-source-view-line-wrap-1705`. Closes #1706.

Sweep wave 9 group G7. Not a v1-review ledger row. Lands after G7-1705.md and adds a second group to its `DisplayMenu`, so it reaches both the bar and the popup copy. Anchors hold on `origin/master` `5b1454d2`.

## Problem

`editorMeasure` has one writer: the radiogroup in `src/client/components/EditorSettings.svelte`. Its anchors in `useTandemSettings.ts`:
- field `:115`
- `EDITOR_MEASURES` `:30`
- default `"comfortable"` `:260`
- `isEditorMeasure` clamp on write `:988`

App feeds it to `createEditorStageModel` (`App.svelte:1423`), which writes `--editor-measure` on the stage. Rails are separate grid tracks. No control outside the modal changes it.

## Fix

**`src/client/shell/DisplayMenu.svelte`.**
- Add a separator and a `role="group" aria-label="Reading measure"` group.
- The group has one `menuitemradio` per entry, **iterated from `EDITOR_MEASURES`**, labelled from `const MEASURE_LABEL: Record<EditorMeasure, string>` ("Narrow", "Comfortable", "Wide", "Full").
- Each item has `aria-checked={editorMeasure === m}`, `data-testid="display-menu-measure-{m}"` and `onclick` → `onUpdate({ editorMeasure: m })`.
- The trigger label already names the measure (G7-1705).

**No other source file changes.** G7-1705 already threads `editorMeasure` and `onUpdateDisplay` through App, FormattingBar and Toolbar.

- **Validation:** writes pass through `mergeAndClampSettings`, whose `isEditorMeasure` clamp is the existing write guard.
- **Rails:** the menu writes only `editorMeasure`. It never touches rail visibility or width.
- **Narrow widths:** the bar trigger sits outside the clipped `formatting-bar-track`, so it is visible at 640px.

**docx:** the stage ignores the measure for docx (`editor-stage.svelte.ts:279-281`), and the Settings control has had the same limit since it shipped. #1706 asks for a quick control for the existing setting, not a change to what that setting drives. It is recorded as an assumption, not as remaining work.

**Testids and docs.**
- `display-menu-measure-{*}` is additive. Regenerate the snapshot and extend the manifest bullet.
- `docs/user-guide.md:364` gets one clause: reading measure is also in the display menu.
