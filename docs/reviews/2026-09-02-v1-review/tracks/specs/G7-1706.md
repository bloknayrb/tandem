# G7 — #1706 reading measure is reachable only through Settings → Editor

Branch `fix/editor-quick-controls-text-size-and-reading-measure-outside-settings-and-source-view-line-wrap-1705`. Closes #1706.

Sweep wave 9 group G7 (`docs/plans/2026-09-06-open-issues-sweep.md:107`, `:471`). This is not a v1-review ledger row, and there is no experiment and no refuted entry. The probe is the E2E cases below.

This spec lands after G7-1705.md and adds the second group to the `DisplayMenu` that spec creates, in both of its homes (the formatting bar and the selection popup). Anchors hold on `origin/master` `5b1454d2`; see G7-1705.md.

## Problem

`editorMeasure` has a single writer: the radiogroup in `src/client/components/EditorSettings.svelte:130-174`. The field's anchors in `src/client/hooks/useTandemSettings.ts`:

- field at `:115`, union `EDITOR_MEASURES` at `:30`, `EDITOR_MEASURE_CH` at `:34`
- default `"comfortable"` at `:260`
- `isEditorMeasure` check on load at `:561` and on write at `:988`

App passes the value to `createEditorStageModel` (`App.svelte:1423`). `stageLayerStyle` then writes it as `--editor-measure` on the non-docx grid stage (`src/client/layout/editor-stage.svelte.ts:283-293`). Rail widths are separate grid tracks.

No control exists outside the modal.

## Fix

- **`src/client/shell/DisplayMenu.svelte`** (created by G7-1705): add a second `role="group" aria-label="Reading measure"`.
  - It holds one `role="menuitemradio"` item for each `EDITOR_MEASURES` entry, in the array's order.
  - Labels come from `const MEASURE_LABEL: Record<EditorMeasure, string>`: "Narrow", "Comfortable", "Wide", "Full".
  - Each item has a secondary hint span ("58ch", "68ch", "82ch", "Fills the editor") matching the Settings hints (`EditorSettings.svelte:130-135`).
  - Each item has `aria-checked={editorMeasure === m}`, `data-testid={`display-menu-measure-${m}`}` and `onclick={() => onUpdate({ editorMeasure: m })}`.
  - A `menu-div` separator sits between the two groups.
  - The trigger's `aria-label` already names the measure (G7-1705).
  - **Iterate `EDITOR_MEASURES`; never hand-type the list.** No test can enforce this. A hand-typed four-item list in the right order renders identical DOM, so reviewers check it in code review. What tests do pin is covered in Tests 1: the menu renders all four presets, and `MEASURE_LABEL`'s keys equal `EDITOR_MEASURES`, so a fifth preset fails both the `Record` type and that unit case.
- **`FormattingBar.svelte`, `Toolbar.svelte` and `App.svelte`:** G7-1705 already wires the `editorMeasure` prop and `onUpdateDisplay` in both homes.
  - `onUpdate` goes through `mergeAndClampSettings`. Its `isEditorMeasure` clamp (`:988`) is the write-side guard, so no new validation is needed.
- **Rails and width:**
  - The menu writes only `editorMeasure`. It never touches `leftPanelVisible`, `rightPanelVisible` or rail widths, and the stage keeps rails in their own tracks.
  - The bar trigger sits outside the clipped `formatting-bar-track`, so it stays visible at 640px, the width where the track truncates (`formatting-bar-popovers.spec.ts:293`).
  - The menu opens at `right: 0`, as Decorations does.
- **docx (pre-existing limit, not remaining work under #1706):**
  - `stageLayerStyle` ignores the measure for docx (`editor-stage.svelte.ts:279-281`). The Settings control has had the same limit since it shipped.
  - #1706 asks for a quick control that changes *the existing setting* and what that setting drives. It does not ask to extend the setting to docx.
  - The menu shows and writes the value on docx tabs exactly as Settings does, and no docx branch is added. It is recorded in `assumptions` so Closes stays derivable.
- **Testids** are additive (Critical Rule 7): `display-menu-measure-{*}`. Regenerate the snapshot in the same commit and extend the manifest's Display menu bullet.
- **User guide:** `docs/user-guide.md:364` gets one clause saying reading measure is also in the formatting bar's display menu (and the selection popup's copy of it).

## Tests

1. **`tests/client/DisplayMenu.svelte.test.ts`** (extends G7-1705's file):
   - **Four presets, in order:** the menu renders exactly four `display-menu-measure-*` items, in `EDITOR_MEASURES` order. **Kills** a dropped preset. Hand-typing the list is a code-review rule this case does not cover (see Fix).
   - **Labels cover the union:** `Object.keys(MEASURE_LABEL)` equals `[...EDITOR_MEASURES]`, provided `MEASURE_LABEL` is exported from the component's `<script module>`. **Kills** a label table that drifts from the union.
   - **Narrow write:** clicking `display-menu-measure-narrow` calls `onUpdate` exactly once with `{ editorMeasure: "narrow" }`. **Kills** a write under the wrong key, and a write that also sends `textSize`.
   - **Settings → quick, prop change:** `rerender({ editorMeasure: "full" })` sets `display-menu-measure-full` to `aria-checked="true"` and puts "Full" in the trigger label.
   - **Arrow keys cross groups:** with focus on `display-menu-text-size-l` (the last text-size item), ArrowDown moves focus to `display-menu-measure-narrow`. **Kills** splitting the groups into separate `role="menu"` elements, which leaves one group unreachable by keyboard.
2. **`tests/e2e/display-menu.spec.ts`** (extends G7-1705's file):
   - **Fixture and scoping:** use G7-1705's generated `tall.md` fixture. Scope bar locators under `[data-testid='formatting-bar']`.
   - **Quick → Settings:** pick Wide in the menu.
     - The stage's `--editor-measure` polls to `82ch`, read the same way as `settings-and-filters.spec.ts:98-99`.
     - `localStorage["tandem:settings"].editorMeasure === "wide"`.
     - In Settings → Editor, `editor-measure-wide` is `aria-checked="true"`.
   - **Settings → quick:**
     1. Pick `editor-measure-narrow` in the modal.
     2. Press Escape.
     3. Wait for `await expect(page.locator("[data-testid='settings-modal']")).toHaveCount(0)`.
     4. Open the menu: `display-menu-measure-narrow` is checked.
   - **Rails do not move:** loop over `side` in `["left", "right"]` and `visible` in `[true, false]`. On each iteration, call `setRailVisible(page, side, visible)` (`helpers.ts:414`), then pick Full and then Narrow in the menu.
     - `--editor-measure` follows (`100%`, then `58ch`).
     - **Visible arm:** record the handle's `boundingBox()` x and width before the picks. After each pick, the handle box is unchanged within 1px.
     - **Closed arm:** after each pick, `page.locator(`[data-testid='${RAIL_HANDLE_TESTID[side]}']`)` still has `toHaveCount(0)` (`helpers.ts:396-399`).
     - **Kills** an implementation that resizes panels, and one that opens a rail or writes rail state while the rails are closed.
   - **Narrow viewport:** `setViewportSize({ width: 640, height: 800 })`.
     - The trigger is visible.
     - `elementFromPoint` at the centre of both the trigger and `display-menu-measure-wide` resolves to that element (the #1302 hit-test idiom from `formatting-bar-popovers.spec.ts`).
     - Clicking Wide sets `--editor-measure` to `82ch`.
     - **Kills** placing the control inside the clipped track.
3. **Mutation checks, each restored from a file copy:**
   - **(a)** Replace the `EDITOR_MEASURES` iteration with a literal three-item list → the unit "four presets, in order" case goes red.
   - **(b)** Move `<DisplayMenu>` in `FormattingBar.svelte` to be the **last child of `formatting-bar-track`, after `<HighlightColorPicker>`** (`:199-201`). The track truncates from the end of the row → the E2E narrow-viewport case goes red. Placing it at the start of the track would leave it hittable, so that placement is not a valid mutation.
   - **(c)** Change a measure item's `onclick` to `onUpdate({ textSize: "l" })` → the unit narrow-write case goes red.
   - **(d)** Delete one key from `MEASURE_LABEL` while casting past the type error → the unit "labels cover the union" case goes red.

## Not in scope

- A second width preference.
- Drag-to-resize of the measure.
- Extending the measure to docx: a pre-existing limit shared with Settings, recorded as an assumption.
- Keyboard shortcuts that step through presets.
