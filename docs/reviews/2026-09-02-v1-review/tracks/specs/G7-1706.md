# G7 — #1706 reading measure is reachable only through Settings → Editor

Branch `fix/editor-quick-controls-text-size-and-reading-measure-outside-settings-and-source-view-line-wrap-1705`. Closes #1706. Sweep wave 9 group G7 (`docs/plans/2026-09-06-open-issues-sweep.md:107`, `:471`); not a v1-review ledger row, no experiment, no refuted entry. Probe: the E2E cases below. Lands after G7-1705.md and adds the second group to the `DisplayMenu` that spec creates.

## Problem

`editorMeasure` (`src/client/hooks/useTandemSettings.ts:115`, union `EDITOR_MEASURES` `:30`, `EDITOR_MEASURE_CH` `:34`, default `"comfortable"` `:260`, `isEditorMeasure` on load `:561` and on write `:988`) is written only by the radiogroup in `src/client/components/EditorSettings.svelte:130-174`. App feeds it to `createEditorStageModel` (`App.svelte:1423`), and `stageLayerStyle` writes it as `--editor-measure` on the non-docx grid stage (`src/client/layout/editor-stage.svelte.ts:282-293`). Rail widths are separate grid tracks. No control exists outside the modal.

## Fix

- **`src/client/shell/DisplayMenu.svelte`** (created by G7-1705): add a second `role="group" aria-label="Reading measure"` with a `role="menuitemradio"` item for each `EDITOR_MEASURES` entry, in the array's order. Labels come from `const MEASURE_LABEL: Record<EditorMeasure, string>` ("Narrow"/"Comfortable"/"Wide"/"Full"), with a secondary hint span ("58ch"/"68ch"/"82ch"/"Fills the editor") matching the Settings hints (`EditorSettings.svelte:130-135`). Each item has `aria-checked={editorMeasure === m}`, `data-testid={`display-menu-measure-${m}`}` and `onclick={() => onUpdate({ editorMeasure: m })}`. A `menu-div` separator sits between the groups. **Iterate `EDITOR_MEASURES`, never a hand-typed list**, so a fifth preset reaches the menu through the `Record` exhaustiveness error. The trigger's `aria-label` already names the measure (G7-1705).
- `FormattingBar.svelte` / `App.svelte`: the `editorMeasure` prop and `onUpdateDisplay` wiring are already in place from G7-1705. `onUpdate` goes through `mergeAndClampSettings`, whose `isEditorMeasure` clamp (`:988`) is the write-side guard. No new validation.
- **Rails and width:** the menu writes only `editorMeasure`. It never touches `leftPanelVisible`/`rightPanelVisible` or rail widths, and the stage keeps rails in their own tracks. The trigger sits outside the clipped `formatting-bar-track`, so it stays visible at 640px, the width where the track truncates (`formatting-bar-popovers.spec.ts:293`). The menu opens `right: 0`, like Decorations.
- **docx:** `stageLayerStyle` ignores the measure for docx (`editor-stage.svelte.ts:279-281`). That is existing behaviour, and Settings has the same limit today. The menu still shows and writes the value. No docx branch is added.
- Testids are additive (Critical Rule 7): `display-menu-measure-{*}`. Regenerate the snapshot in the same commit and extend the manifest's Display menu bullet. `docs/user-guide.md:364` gets one clause saying reading measure is also in the formatting bar's display menu.
