## Problem

**Reproduced on `a6e7352f`**, in-process through the production functions (`openFromDisk`, `removeAnnotationRecord(doc, id, "browser")`, `closeStore`, `closeDocumentById`) against a temp `…/sample/welcome.md`:

1. First open injects all four seeds.
2. Deleting `tutorial-comment-1` writes the envelope tombstone `{id: "tutorial-comment-1", rev: 2}`.
3. Close and reopen, in the same process with the room kept: the reopen is `kind: "fresh"` and `tutorial-comment-1` is back.
4. Simulated restart (registry and room dropped, store reset): it is back again, at `rev 1`.

The order is the cause. In `openFromDisk` (`src/server/documents/open.ts`), `finalizeDocOpen` → `wireAnnotationStore` → `loadAndMerge` applies the ledger first. Only after that does `injectTutorialAnnotations(doc)` run, guarded by `if (map.has(def.id)) continue` (`src/server/mcp/tutorial-annotations.ts`). The merge has just made `map.has` false.

**The issue's "never reaches disk" mitigation is false (measured).** The seed write is `withInternal` (`DURABLE_SKIP`), but `snapshot()` serializes the whole map. So the first unrelated durable write, such as a browser edit to `tutorial-highlight-1`, persists the re-minted `tutorial-comment-1@1` into the envelope next to its `@2` tombstone. The file then contradicts itself. The merge's `winningTombstoneIds` keeps the stale copy out of the Y.Map on the next load, and the injector puts it back.

## Fix

Make the injector ask "was it deliberately removed?" as well as "is it present?", using the ledger `loadAndMerge` has just seeded.

- `src/server/mcp/tutorial-annotations.ts`: the signature becomes `injectTutorialAnnotations(doc: Y.Doc, filePath: string)`.
  - The parameter is **required**, not defaulted. A default empty set is the silent-default trap: a call site that forgets it compiles and re-injects.
  - Before the loop, compute `const deleted = new Set(getTombstones(docHash(filePath)).map((t) => t.id))`. The guard becomes `if (map.has(def.id) || deleted.has(def.id)) continue`.
  - `getTombstones` comes from `../annotations/sync.js` and `docHash` from `../annotations/doc-hash.js`. No cycle: `sync.ts` imports `mcp/document-model.ts`, which this module already imports. No boundary pin covers `mcp/tutorial-annotations.ts` edges; the `tests/docs/documents-boundary.test.ts` rows are `server/documents/*` only.
  - Any tombstone suppresses the seed, whatever its rev. **Why a tutorial tombstone means a real deletion (measured, not assumed):** the observer records a tombstone for a delete from EVERY origin, file-sync and internal included (`registerAnnotationObserver`'s "Record tombstones unconditionally for ALL origins"). The conclusion holds only because every bulk clear runs with the observer detached or before it is wired:
    - `clearAndReload` (force, restore, source-view commit) runs `clearFileSyncContext` before `clearDocMaps`;
    - `evictPartialDocState` (the fallback eviction) does the same;
    - the populate-failure cleanup in `populate.ts` runs before `wireAnnotationStore`;
    - the watcher reload keeps annotations and deletes only awareness keys.

    So only real deletes (browser Archive, `AnnotationLifecycle.remove`, a stale-tab merge) leave a tutorial tombstone. **Record this dependency in the injector docblock:** a future path that deletes annotations with the observer attached would permanently suppress the seeds without any signal.
  - Update the docblock to say "Idempotent, and never re-mints a deleted seed (#1696)", followed by the dependency above.
- `src/server/documents/open.ts`, the call site: `injectTutorialAnnotations(doc, resolved)`. Replace the "idempotent — safe to call on session-restored docs" comment with one line naming the ledger check. It must stay AFTER `finalizeDocOpen`, because the ledger is seeded inside `wireAnnotationStore`.
  - **No empty-ledger window on the normal path:** `loadAndMerge` sets `tombstonesByDoc` for the hash BEFORE its `fileEmpty` fast-path return, and that fast path is taken only when the file has zero tombstones. Cite this by function name in the comment, not by line.
  - **Hash identity:** `wireAnnotationStore` registers under `docHash(resolved)`, the same `resolved`, so the two keys match.
  - No new `open.ts` import edge, so the exact-set pin is untouched.
- `src/server/annotations/sync.ts`: `getTombstones`' docblock says "Read-only accessor for tests and (future) diagnostic tools". Update it to name `mcp/tutorial-annotations.ts` as its production reader (#1696). Docblock only; no code diff.
- **Rejected alternative: move injection ahead of `loadAndMerge`.** The merge's veto would then cover the seeds, but two paths change behaviour:
  - On a first open, `fileEmpty && ymapHasState` takes the first-upgrade fast path and snapshots the seeds into the envelope.
  - `recoverRenamedEnvelope` would run against a seeded Y.Map.

  The ledger check changes behaviour only where a tombstone for a tutorial id exists.
- Critical Rule 2: the seed write stays `withInternal`. `annotation-create-lifecycle.test.ts` "tutorial seeding still writes under the INTERNAL origin" pins it; only its call gains the path argument.
- **User-visible consequence, no code change:** if a user deletes all four seeds before resolving any, the welcome tutorial holds at step 0 across reopens. `useTutorial.svelte.ts` returns early when there are no tutorial annotations, and never auto-skips. Before this fix the re-injected seeds hid that. The tutorial's dismiss control (`dismissTutorial`) is the exit, so the user is not trapped.

## Done when

When the annotation store wired (`wireAnnotationStore` returned `{ wired: true }`), deleted seeds stay deleted across a reopen and a restart. No re-minted seed reaches the envelope. First-open injection is unchanged. The three test groups pass, and typecheck and the suite are green. When wiring fails, its `catch` seeds no ledger and a deleted seed can return. That matches today's behaviour and is out of scope. **CI legs:** everything changed is platform-neutral server code, and the ubuntu `check` job is the leg that executes the new tests.

## Not in scope

- Tombstone compaction. `cleanupStaleTombstones` (`src/server/session/manager.ts`) drops a CLOSED document's tombstones older than `SESSION_MAX_AGE` (30 days), so a seed deleted and not reopened for 30 days can return. That is the same horizon every annotation's anti-resurrection has, accepted as the model's bound.
- Undo-of-delete merge semantics (`sync.ts`, unchanged).
- Deterministic `import-` Word comment ids: the merge's veto already covers them, per the issue body.
- The step-0 tutorial hold after all four seeds are deleted (Fix, last bullet): `dismissTutorial` is the exit.
