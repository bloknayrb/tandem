(deactivation) escalated rather than invented — see *For Bryan* — and a follow-up issue filed for it
before the close, so nothing lands only in a merged PR body. Ledger:
`docs/reviews/2026-09-02-v1-review/areas/armed-license-gate.md:24`. Probe:
`npx vitest run tests/client/license-store.svelte.test.ts tests/cli/license.test.ts`. Lands **after**

## Problem

Five named gaps. Two have moved since the review, and saying which is half the work:

**(a) The CLI is real, the bundle genuinely does not ship it — and even a user who *has* it cannot
license a desktop install with it.** Two independent reasons, and the second is the sharper one:

- **The bundle.** Measured: `src-tauri/tauri.conf.json` `bundle.resources` ships `dist/server`,
  `dist/channel`, `dist/stdio-bridge`, `dist/client`, `sample/`, `skills/`, `CHANGELOG.md`,
  `docs/workflows.md` — **no `dist/cli`** — and `externalBin` is the two sidecars. So a desktop buyer
  reading `SettingsLicenseTab.svelte:78-80` ("…or run `tandem activate <file>` from the command
  line") is told to run a binary that does not exist on their machine.
- **Different app-data roots.** `resolveAppDataDir()` (`src/server/platform.ts:11-15`) returns the
  `env-paths` default unless `TANDEM_APP_DATA_DIR` is set, and the CLI sets nothing
  (`src/cli/license.ts:112,129`). The desktop launches its sidecar with `TANDEM_APP_DATA_DIR` pointed
  at the Tauri app-data dir (`src-tauri/src/sidecar.rs:1591`), and the one-time npm import is
  recorded by `npm-migration-complete` (`docs/data-locations.md:61`). So after first launch a
  `tandem activate` from a separately-installed npm CLI writes `license.json` somewhere the desktop
  app never reads: a **silent no-op activation**, which is worse than a missing binary. That second
  reason also weakens the `isTauriRuntime()` discriminant at the edges — a desktop sidecar's UI
  opened in a plain browser reports `false` and would be shown the CLI clause on a machine where it
  would no-op — which is accepted, because the browser arm is the one where the CLI clause is
  usually right and the Part 1 doc sentence covers the rest.

**This is a copy gap, not a capability gap:** in-app activation already exists
(`LicenseActivateForm.svelte` → `POST /api/license/activate`), and the same tab renders it three
lines above. The issue's "in-app activation (file picker + paste)" is already half-shipped; the paste
half is what a buyer actually has, because the email carries the key as text.

**(b) Already fixed on master — do not re-fix it.** `docs/licensing-explained.md:39-44` now reads
"**double-clicking the file does nothing** — Tandem registers no `.license` file association", with
the four real associations cited. The claim the issue objected to is gone; the remaining half of its
"drop the claim **or** add the association" is a product choice, and the answer is *drop*, recorded
below with a reason rather than left implicit.

**(c) The 60 s poll swallows every failure, and the tab answers with a confident falsehood.**
`useLicense.svelte.ts`'s `poll()` catch is a bare comment; `status` keeps its last value and nothing
on screen changes. Two shapes, and the first one is **not** the "blank tab" an earlier draft of this
spec described:

- **A *first*-poll failure leaves `status === null`, and the pill still renders — asserting that
  licensing is not enforced.** `deriveLicenseUi(null)` returns `statusLabel: ""`
  (`src/client/utils/license-ui.ts:58-69`, the same arm as gate-dark). In
  `SettingsLicenseTab.svelte`, `gateDark` (`:21`) is `status != null && !status.gateActive`, so with
  `status === null` both `gateDark` and `darkInstalled` (`:25`) are false and `pillLabel`'s `||`
  fallback (`:26-33`) fires unconditionally: the pill reads **"Not enforced in this version"**. Post
  flip, on a restricted device whose very first poll fails, that is a definite, wrong statement about
  enforcement presented as truth — and adding an unavailability line that says "this is the last
  known state" makes it two false statements, since there is no last known state. `status` is only
  ever assigned on success (`useLicense.svelte.ts:65-75`), so nothing else corrects it.
- **A later failure** freezes a trial countdown or a pill at a value the server may no longer agree
  with. This is the case the "last known state" wording is actually for.

**(d) The pinned signing key has no dated home.** `src/server/license/public-key.ts` pins one Ed25519
key — its own comment says "THIS KEY IS NOT ROTATABLE TODAY. There is one const and no `keyId`"
(`:10`) — with no rotation date anywhere in `gh issue list`, which is exactly the failure CLAUDE.md's
dated-gate rule names ("a date living only in a doc comment never surfaces").

**(e) No deactivation path** — `tandem activate` has no inverse; removing a license means deleting
`license.json` by hand (`docs/data-locations.md:62` documents that). Policy as much as code.

Two small true things in the issue body that ride along because they are in the same files and cost
three lines each: `tandem activate <a-directory>` is **uncaught** (`src/cli/license.ts:126` sits
*outside* the `try` at `:127`, so `existsSync` says yes, `readFileSync` throws `EISDIR`, and the
buyer gets a stack trace instead of the per-cause copy the next eight lines exist to print); and
`TANDEM_APP_DATA_DIR` relocates `license.json` and `trial.json` while `docs/configuration.md:50`
lists only "sessions, the auth token, and durable annotations".

## Fix

- **`SettingsLicenseTab.svelte`, the CLI clause** — `import { isTauriRuntime } from
  "../../cowork/cowork-helpers"` (exported; `EditorSettings.svelte:2,89` is the precedent for using
  it as a render-time discriminant in a settings surface, and it is captured once at init there).
  **The copy precedent is `SettingsClaudeCodeTab.svelte:448-457`**, which already says, under
  `{:else if isTauriRuntime()}`, "the desktop app doesn't include the `tandem` command needed to —
  install it with `npm install -g tandem-editor@latest`". This tab deliberately **omits** that
  `npm install -g` escape hatch: for the channel shim the global install is the whole point, whereas
  here paste is sufficient *and* a separately-installed CLI would activate a different app-data root
  (Problem (a), second bullet), so offering it would send a buyer down a silently-failing path.
  Desktop: the hint offers paste only, and says the emailed key is the whole path. Browser/npm: keep
  the `tandem activate <file>` clause verbatim — there the CLI is the process the user launched
  Tandem with. **No new testid** on this hint (it has none today), so no snapshot churn from this
  edit.
- **`useLicense.svelte.ts`** — the store exposes `statusUnavailable: boolean` as
  **`let statusUnavailable = $state(false)` plus a getter on the returned object**, mirroring `status`
  at `:28`/`:78-80`. The returned object literal is constructed once (`:77-108`), so a plain property
  would freeze at store-creation time and never update. Set it in the `poll()` catch; **clear it on
  any successful poll, in `stop()` with the rest of the baseline, and in `set()`** — `set(next)`
  (`:104-107`) is a separate write path from `poll()`, used by `LicenseActivateForm` to apply the
  activate response immediately, and it is a successful state observation by definition; without it a
  just-activated license renders next to a stale "could not reach the local server" warning. Add a
  `console.warn` on the **transition into** failure (not per tick: the timer fires every 60 s forever
  and a per-tick warn is a log flood on an offline laptop). Last-known `status` is still kept, and
  **`deriveLicenseUi` must NOT take `statusUnavailable`** — `ui` stays a pure function of `status`,
  so a transient fetch failure structurally cannot flip the wall or the editor's editability.
- **`SettingsLicenseTab.svelte`, the unavailability surface — two parts, and the pill is the
  load-bearing one:**
  - **Gate the `"Not enforced in this version"` fallback on `status != null`.** When
    `status === null`, `pillLabel` renders an unknown label ("Status unknown", or an em-dash) instead
    of asserting that enforcement is off. This is the fix for the *discriminating surface*; the
    warning line alone leaves the lie on screen.
  - Render one `.license-warning` line when `statusUnavailable`, **split on whether there is a last
    known state**: with `status != null`, Tandem could not reach its own local server, so this is the
    last known state; with `status === null`, Tandem has not been able to reach its local server
    *yet* and no license state is known on this device. **New
    `data-testid="license-status-unavailable"`** ⇒ regenerate
    `tests/design-system-impl/__snapshots__/testid-set.snap.txt` in the same commit (additive; the
    contract forbids removals, not additions).
- **`src/cli/license.ts:126`** — move `resolveLicenseInput` into its own `try`, and on a read failure
  print `[Tandem] Could not read a license from <input>.` + the paste hint, then `process.exit(1)`
  **followed by an explicit `return`**. `process.exit` is typed `never`, so TS is satisfied without
  it, but under a spied `exit` the function falls through into
  `activateLicense(resolveAppDataDir(), blob)` with `blob` undefined, `rawBlob.length` throws, and
  the second catch prints the generic `License activation failed.` copy on top of the new message —
  the exact outcome this change exists to prevent, and it would be invisible in production while
  making the test non-discriminating. Echoing `input` is safe **because that branch is only reachable
  when `existsSync(input)` was true**, i.e. it is a path, not blob bytes — the file's no-blob-bytes
  rule is preserved, and the reason is worth one inline comment.
- **`src/cli/license.ts`, `resolveLicenseInput` — a three-line UNC refusal ahead of `fileExists`.**
  Today `resolveLicenseInput` calls `fileExists(arg)` (wired to `fs.existsSync` at `:126`) with no
  path screening, so `tandem activate \\attacker\share\x.license` performs the SMB handshake — the
  NTLM-hash class screened at `src/server/mcp/document-service.ts:825`,
  `src/server/integrations/node-binary.ts:152` ("refused before the `stat`") and
  `src/server/launcher/supervisor.ts:1597`, and the same class as open finding #1609. It is
  pre-existing, but this spec is already moving that call into its own `try`, it is the same file and
  the same three lines, and the *Not in scope* section below declines the `.license` association
  citing precisely this rule — declining an association on UNC grounds while leaving an unscreened
  UNC read in the activation path is incoherent. Refuse a `\\`- or `\\?\`-prefixed argument **before**
  any filesystem call, and do not echo it back through the new error line. Note it in the PR body so
  a reviewer sees it was deliberate rather than scope creep.
- **`src/client/components/NetworkSettings.svelte:271`** — `To rotate: run
  <code>tandem rotate-token</code> in the CLI.` is the same unrunnable-on-desktop copy, in the same
  class, fixed with the **same `isTauriRuntime()` conditional this PR already writes**. Bundled in
  per CLAUDE.md's two-person rule ("bundle small tangential fixes in") rather than deferred with no
  issue number, which is the untracked-deferral shape. Desktop arm: say the token is rotated from
  Settings, or that rotation needs the npm CLI — whichever the surrounding copy supports; do not mint
  a new mechanism.
- **`docs/configuration.md:50`** — name `license.json` and `trial.json` in the
  `TANDEM_APP_DATA_DIR` row, and add the consequence in `docs/data-locations.md`'s `trial.json` row:
  pointing the var somewhere new presents a fresh trial and an apparently-unlicensed device. This is
  the whole of the issue's `TANDEM_APP_DATA_DIR` item; it is documentation, not a behaviour change
  (the soft clock is ADR-040 §3, and #1787 already settled the two-var confusion).
- **`docs/licensing-explained.md`** — one sentence in the Part 1 activation paragraph saying the
  desktop app activates by paste in Settings → License, and that **the `tandem` command activates the
  npm install's own app-data directory** — not merely that the bundle does not ship it. The
  wrong-root failure is silent, so the doc has to name it. Part 3 mechanism prose is H-b's; this is
  Part 1 user copy.
- **File the dated issue** (not code): `Rotate the license signing key — review 2027-03-01`, body
  naming `src/server/license/public-key.ts` as the pinned key and
  **`docs/licensing-operations.md` §0 "Key management"** as the procedure — **by section name, not
  number.** §7 is "Refunds, revocation, and the kill switch" (`:511`); key management and the
  rotation discussion are §0 (`:21`, rotation at `:32-34`). H-b owns that file and may renumber, so a
  number is doubly wrong — the same lesson `license-flip-consts.test.ts:183-208` already pins ("names
  consts and functions, which grep finds, rather than `lib.rs:<n>`"). The criterion must be
  answerable from tracked files, so state it as **two file questions** rather than as an operations
  fact: *(1) does `src/server/license/public-key.ts` accept an array of keys or carry a `keyId` —
  i.e. has the single const been superseded — and has `EXPECTED_PUBLIC_KEY_SHA256`
  (`tests/server/license.test.ts:192`) changed? (2) does the runbook's Key-management section carry a
  step-by-step rotation procedure?* Both are answerable by reading three tracked files. "Is a
  rotation procedure exercised" is an operations fact with no tracked evidence, and per CLAUDE.md's
  dated-gate rule 2 such a criterion fails silently — **toward deletion**. Record the number in the
  PR body; **do not** add the date to a doc comment as well, which is the anti-pattern.
- **File the deactivation follow-up** (not code, and **before** closing #1789): one issue covering
  `tandem deactivate` — policy as much as code, so it goes to the PR body's *For Bryan* list with a
  recommendation, not with an invented policy — and recording on it the deliberate decision **not**
  to add a file picker to `LicenseActivateForm.svelte` (a `<textarea>` only, `:38-46`). Track H's row
  for #1789 names "a file picker or paste field", so both halves need a tracked home before the close
  or they survive only in a merged PR body, which never appears in `gh issue list`. Put that issue
  number in the PR body next to the For-Bryan line. If Bryan would rather not carry a second issue,
  the alternative is to downgrade #1789 to refs-only and leave it open.

## Tests

1. **`tests/client/license-store.svelte.test.ts`** — a rejecting `fetchLicenseStatus` sets
   `statusUnavailable` and **leaves `status` and `ui` at their last successful values**; a subsequent
   success clears it; **`set(licensedStatus)` after a failed poll also clears it**; two consecutive
   failures produce exactly **one** `console.warn` (kills the per-tick flood); `stop()` resets it.
   The `ui`-unchanged row is only a real guard because the Fix forbids `deriveLicenseUi` from taking
   `statusUnavailable` — with `ui` a pure `$derived` of `status` (`useLicense.svelte.ts:31`) it is
   otherwise true by construction; state that dependency in the test's comment so a later widening of
   `deriveLicenseUi`'s signature is caught here rather than passing silently.
2. **`tests/client/…` mounted component test for `SettingsLicenseTab`.** **Required — there is no
   source-level fallback.** An earlier draft allowed "otherwise assert the copy split at the source
   level"; that is structurally non-discriminating, because after the change **both** branch strings
   live in `SettingsLicenseTab.svelte`, so any source read matches `tandem activate` regardless of
   which arm renders — it passes on the unfixed component, which is exactly the failure the negative
   row exists to kill. Mounting is well supported: `tests/client/settings-push-routes.test.ts:39-43`
   mocks this identical discriminant with a mutable cell
   (`let tauri = false; vi.mock("../../src/client/cowork/cowork-helpers", … isTauriRuntime: () => tauri)`)
   and `:128` `render(SettingsClaudeCodeTab, …)` mounts a settings tab; `tests/client/cowork-settings-mounted.test.ts:20`
   is the other precedent, written for precisely this reason ("four of the testids #1366 added existed
   only in the snapshot"). `SettingsLicenseTab` takes one `SettingsTabContext` prop (`:13`) and its
   only external dependency is the `licenseStore` singleton, so it mounts more cheaply than the tab
   those precedents cover. Prefer the mutable-cell `vi.mock`; a bare
   `(window as any).__TAURI_INTERNALS__ = {}` / `delete` also works, since `isTauriRuntime()` is a
   pure `typeof window !== "undefined" && "__TAURI_INTERNALS__" in window`
   (`src/client/cowork/cowork-helpers.ts:480-486`), but either way it must be set **before** mount —
   `EditorSettings.svelte:89` is the precedent for capturing the discriminant once at init. Rows:
   - `isTauriRuntime() === true` ⇒ `expect(container.textContent).not.toContain("tandem activate")`.
     That negative is the whole point of (a): a fix that adds a paste sentence without removing the
     CLI offer passes any "mentions paste" assertion.
   - `isTauriRuntime() === false` ⇒ it **does** contain `tandem activate`.
   - **`status === null && statusUnavailable === true` ⇒ the pill text is not
     `"Not enforced in this version"`.** This row is what makes the (c) pill fix discriminating; test
     1 asserts only that `status`/`ui` are *preserved*, and in the first-poll case there is nothing
     to preserve.
3. **`tests/cli/license.test.ts`** — this file gets its **first `runActivate` coverage**; it has
   exactly two describes today, `resolveLicenseInput` (`:5`) and `formatLicenseStatus` (`:27`), and
   nothing calls `runActivate`, so there is no existing case to extend and no harness to inherit.
   Name the seam: `vi.spyOn(process, "exit").mockImplementation(() => { throw new Error("exit"); })`
   plus a **named** temp `TANDEM_APP_DATA_DIR` (`mktemp -d -t tandem-XXXXXX` — a bare `mktemp -d`
   fails `platform.test.ts`). `runActivate` with a path that exists but cannot be read (a directory)
   exits 1 with the new message and does not throw past the spy — **and, negatively,
   `expect(errors.join("\n")).not.toContain("License activation failed")`**, which is what pins the
   explicit `return` after `process.exit(1)`; without that assertion the fall-through prints both
   messages and the positive assertion still passes, telling a buyer their license is invalid when
   their argument was a folder. Add the UNC-refusal row alongside it (a `\\host\share\x` argument is
   refused with no filesystem call — assert via an injected `fileExists` that records calls).
4. **Snapshot**: `tests/design-system-impl/testid-coverage.test.ts` green after regeneration.

No new scanner, no drift guard, no wiring test: every claim above is either pinned by one of these
four or is a doc sentence.

## Not in scope

**Adding a `.license` file association** — recommended against, and this is the reason rather than an
omission: `validate_open_candidate` is the single argv + macOS `RunEvent::Opened` validator, so a new
extension inherits a UNC refusal that must precede any filesystem call and an NTFS-ADS colon scan on
the resolved path (CLAUDE.md, *Files, Sessions & Lifecycle*), i.e. a second OS-level entry point and
its threat model, to save one paste of a key the buyer already has in an email. The doc already tells
the truth. **A file picker in `LicenseActivateForm`** — declined, recorded on the deactivation
follow-up issue so the decision is tracked rather than implicit. **`tandem deactivate`** — For Bryan,
with the follow-up issue filed before #1789 closes. **The issue's remaining scattered bullets**, each
measured and left alone: `status: "licensed"` on the dark wire is a deliberate, documented back-compat
sentinel (`routes/license.ts` `toLicenseStatusWire` docblock) and `licenseInstalled` is documented
non-PII with its own reason; `LicenseUi.editable` **is** dead (the only `.editable` in `src/client/`
is Tiptap's `view.editable`), but deleting a field is a K-lows simplification, not this issue's gap;
the verifier's brand-without-shape check is a crypto-boundary question that belongs with the key
rotation.
