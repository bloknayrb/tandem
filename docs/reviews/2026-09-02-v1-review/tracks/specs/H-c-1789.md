(deactivation) escalated rather than invented — see *For Bryan* — and a follow-up issue filed for it
before the close, so nothing lands only in a merged PR body. Ledger:
`docs/reviews/2026-09-02-v1-review/areas/armed-license-gate.md:24`. Probe:
`npx vitest run tests/client/license-store.svelte.test.ts tests/cli/license.test.ts`. Lands **after**

## Problem

Five named gaps. Two have moved since the review, and saying which is half the work:

**(a) The CLI is real, the bundle genuinely does not ship it — and even a user who *has* it cannot
license a desktop install with it.** Two independent reasons, and the second is the sharper one:

- **The bundle.** Measured: `src-tauri/tauri.conf.json` `bundle.resources` ships `dist/server`,
  `dist/channel`, `dist/stdio-bridge`, `dist/client`, `sample/`, `skills/`, `CHANGELOG.md`,
  `docs/workflows.md` — **no `dist/cli`** — and `externalBin` is the two sidecars. So a desktop buyer
  reading `SettingsLicenseTab.svelte:78-80` ("…or run `tandem activate <file>` from the command
  line") is told to run a binary that does not exist on their machine.
- **Different app-data roots.** `resolveAppDataDir()` (`src/server/platform.ts:11-15`) returns the
  `env-paths` default unless `TANDEM_APP_DATA_DIR` is set, and the CLI sets nothing
  (`src/cli/license.ts:112,129`). The desktop launches its sidecar with `TANDEM_APP_DATA_DIR` pointed
  at the Tauri app-data dir (`src-tauri/src/sidecar.rs:1591`), and the one-time npm import is
  recorded by `npm-migration-complete` (`docs/data-locations.md:61`). So after first launch a
  `tandem activate` from a separately-installed npm CLI writes `license.json` somewhere the desktop
  app never reads: a **silent no-op activation**, which is worse than a missing binary. That second
  reason also weakens the `isTauriRuntime()` discriminant at the edges — a desktop sidecar's UI
  opened in a plain browser reports `false` and would be shown the CLI clause on a machine where it
  would no-op — which is accepted, because the browser arm is the one where the CLI clause is
  usually right and the Part 1 doc sentence covers the rest.

**This is a copy gap, not a capability gap:** in-app activation already exists
(`LicenseActivateForm.svelte` → `POST /api/license/activate`), and the same tab renders it three
lines above. The issue's "in-app activation (file picker + paste)" is already half-shipped; the paste
half is what a buyer actually has, because the email carries the key as text.

**(b) Already fixed on master — do not re-fix it.** `docs/licensing-explained.md:39-44` now reads
"**double-clicking the file does nothing** — Tandem registers no `.license` file association", with
the four real associations cited. The claim the issue objected to is gone; the remaining half of its
"drop the claim **or** add the association" is a product choice, and the answer is *drop*, recorded
below with a reason rather than left implicit.

**(c) The 60 s poll swallows every failure, and the tab answers with a confident falsehood.**
`useLicense.svelte.ts`'s `poll()` catch is a bare comment; `status` keeps its last value and nothing
on screen changes. Two shapes, and the first one is **not** the "blank tab" an earlier draft of this
spec described:

- **A *first*-poll failure leaves `status === null`, and the pill still renders — asserting that
  licensing is not enforced.** `deriveLicenseUi(null)` returns `statusLabel: ""`
  (`src/client/utils/license-ui.ts:58-69`, the same arm as gate-dark). In
  `SettingsLicenseTab.svelte`, `gateDark` (`:21`) is `status != null && !status.gateActive`, so with
  `status === null` both `gateDark` and `darkInstalled` (`:25`) are false and `pillLabel`'s `||`
  fallback (`:26-33`) fires unconditionally: the pill reads **"Not enforced in this version"**. Post
  flip, on a restricted device whose very first poll fails, that is a definite, wrong statement about
  enforcement presented as truth — and adding an unavailability line that says "this is the last
  known state" makes it two false statements, since there is no last known state. `status` is only
  ever assigned on success (`useLicense.svelte.ts:65-75`), so nothing else corrects it.
- **A later failure** freezes a trial countdown or a pill at a value the server may no longer agree
  with. This is the case the "last known state" wording is actually for.

**(d) The pinned signing key has no dated home.** `src/server/license/public-key.ts` pins one Ed25519
key — its own comment says "THIS KEY IS NOT ROTATABLE TODAY. There is one const and no `keyId`"
(`:10`) — with no rotation date anywhere in `gh issue list`, which is exactly the failure CLAUDE.md's
dated-gate rule names ("a date living only in a doc comment never surfaces").

**(e) No deactivation path** — `tandem activate` has no inverse; removing a license means deleting
`license.json` by hand (`docs/data-locations.md:62` documents that). Policy as much as code.

Two small true things in the issue body that ride along because they are in the same files and cost
three lines each: `tandem activate <a-directory>` is **uncaught** (`src/cli/license.ts:126` sits
*outside* the `try` at `:127`, so `existsSync` says yes, `readFileSync` throws `EISDIR`, and the
buyer gets a stack trace instead of the per-cause copy the next eight lines exist to print); and
`TANDEM_APP_DATA_DIR` relocates `license.json` and `trial.json` while `docs/configuration.md:50`
lists only "sessions, the auth token, and durable annotations".

## Fix

- **`SettingsLicenseTab.svelte`, the CLI clause** — `import { isTauriRuntime } from
  "../../cowork/cowork-helpers"` (exported; `EditorSettings.svelte:2,89` is the precedent for using
  it as a render-time discriminant in a settings surface, and it is captured once at init there).
  **The copy precedent is `SettingsClaudeCodeTab.svelte:448-457`**, which already says, under
  `{:else if isTauriRuntime()}`, "the desktop app doesn't include the `tandem` command needed to —
  install it with `npm install -g tandem-editor@latest`". This tab deliberately **omits** that
  `npm install -g` escape hatch: for the channel shim the global install is the whole point, whereas
  here paste is sufficient *and* a separately-installed CLI would activate a different app-data root
  (Problem (a), second bullet), so offering it would send a buyer down a silently-failing path.
  Desktop: the hint offers paste only, and says the emailed key is the whole path. Browser/npm: keep
  the `tandem activate <file>` clause verbatim — there the CLI is the process the user launched
  Tandem with. **No new testid** on this hint (it has none today), so no snapshot churn from this
  edit.
- **`useLicense.svelte.ts`** — the store exposes `statusUnavailable: boolean` as
  **`let statusUnavailable = $state(false)` plus a getter on the returned object**, mirroring `status`
  at `:28`/`:78-80`. The returned object literal is constructed once (`:77-108`), so a plain property
  would freeze at store-creation time and never update. Set it in the `poll()` catch; **clear it on
  any successful poll, in `stop()` with the rest of the baseline, and in `set()`** — `set(next)`
  (`:104-107`) is a separate write path from `poll()`, used by `LicenseActivateForm` to apply the
  activate response immediately, and it is a successful state observation by definition; without it a
  just-activated license renders next to a stale "could not reach the local server" warning. Add a
  `console.warn` on the **transition into** failure (not per tick: the timer fires every 60 s forever
  and a per-tick warn is a log flood on an offline laptop). Last-known `status` is still kept, and
  **`deriveLicenseUi` must NOT take `statusUnavailable`** — `ui` stays a pure function of `status`,
  so a transient fetch failure structurally cannot flip the wall or the editor's editability.
- **`SettingsLicenseTab.svelte`, the unavailability surface — two parts, and the pill is the
  load-bearing one:**
  - **Gate the `"Not enforced in this version"` fallback on `status != null`.** When
    `status === null`, `pillLabel` renders an unknown label ("Status unknown", or an em-dash) instead
    of asserting that enforcement is off. This is the fix for the *discriminating surface*; the
    warning line alone leaves the lie on screen.
  - Render one `.license-warning` line when `statusUnavailable`, **split on whether there is a last
    known state**: with `status != null`, Tandem could not reach its own local server, so this is the
    last known state; with `status === null`, Tandem has not been able to reach its local server
    *yet* and no license state is known on this device. **New
    `data-testid="license-status-unavailable"`** ⇒ regenerate
    `tests/design-system-impl/__snapshots__/testid-set.snap.txt` in the same commit (additive; the
    contract forbids removals, not additions).
- **`src/cli/license.ts:126`** — move `resolveLicenseInput` into its own `try`, and on a read failure
  print `[Tandem] Could not read a license from <input>.` + the paste hint, then `process.exit(1)`
  **followed by an explicit `return`**. `process.exit` is typed `never`, so TS is satisfied without
  it, but under a spied `exit` the function falls through into
  `activateLicense(resolveAppDataDir(), blob)` with `blob` undefined, `rawBlob.length` throws, and
  the second catch prints the generic `License activation failed.` copy on top of the new message —
  the exact outcome this change exists to prevent, and it would be invisible in production while
  making the test non-discriminating.
  **The new `try` must be a SIBLING of the existing one at `:127`, never nested inside it.** Nesting
  puts the new catch's own control flow under the `catch` at `:136`, which prints the generic
  `License activation failed.` copy — reintroducing the double message by structure and turning the
  Tests-3 negative assertion into a false red.
  **Echo justification.** `input` is safe to echo because the read-failure branch is reachable only
  after `fileExists(input)` returned true — it is a path, not blob bytes, so the file's
  no-blob-bytes rule is preserved. The UNC refusal below **does not disturb that**, because it is a
  non-throwing early return that never reaches this branch; phrase the required inline comment that
  way ("reachable only after `existsSync` returned true; the UNC guard returns early and never lands
  here") rather than as the round-1 wording, which asserted a control-flow fact the guard would have
  falsified in the same commit.
- **Same file, the no-argument branch (`src/cli/license.ts:121-126`) gets the explicit `return`
  too.** `if (!input) { console.error("Usage: …"); process.exit(1); }` is the identical shape twelve
  lines above and falls through into `resolveLicenseInput(undefined, fs.existsSync, …)` under the
  same spied `exit`, throwing a TypeError past the spy. Applying the rule in one of two places in
  one file is how it gets read as incidental. Three lines, inside CLAUDE.md's bundle-small-fixes-in
  rule, with a Tests-3 row.
- **`src/cli/license.ts`, `resolveLicenseInput` — screen the path with the repo's OWN helper, ahead
  of `fileExists`.** Today `resolveLicenseInput` calls `fileExists(arg)` (wired to `fs.existsSync` at
  `:126`) with no path screening, so `tandem activate \\attacker\share\x.license` performs the SMB
  handshake — the NTLM-hash class screened at `src/server/mcp/document-service.ts:825`,
  `src/server/integrations/node-binary.ts:152` ("refused before the `stat`") and
  `src/server/launcher/supervisor.ts:1597`, and the same class as open finding #1609. It is
  pre-existing, but this spec is already moving that call into its own `try`, it is the same file,
  and the *Not in scope* section below declines the `.license` association citing precisely this
  rule — declining an association on UNC grounds while leaving an unscreened UNC read in the
  activation path is incoherent. Two things are pinned, and round 1 got both wrong:
  - **Use `rejectUnsafeWindowsPrefix` (`src/shared/windows-path-safety.ts:59-86`), not a bespoke
    check.** A hand-rolled "starts with `\\` or `\\?\`" test is the exact enumerate-the-separators
    shape that helper's own comment (`:60-67`) records as a **verified two-character bypass**:
    Windows treats `/` and `\` as interchangeable, so `/\host\share` and `\/host/share` reach the
    redirector too, and the helper normalises rather than enumerating. It is the canonical guard,
    already imported from the CLI (`src/cli/doctor.ts:47`,
    `src/cli/annotation-store-scan.ts:39`) and it is what `probeNodeBinary`
    (`src/server/integrations/node-binary.ts:152`) uses — one of the three screens cited above. So:
    `import { rejectUnsafeWindowsPrefix } from "../shared/windows-path-safety.js"`.
  - **The SHAPE is a non-throwing early return, at the top of `resolveLicenseInput`:**
    `if (rejectUnsafeWindowsPrefix(arg) !== null) return arg.trim();` — before `fileExists`.
    It performs no filesystem call (closing the #1609-class handshake), preserves the `string` return
    type and both existing unit tests (`tests/cli/license.test.ts:5-25`), echoes nothing, and lets
    the existing no-blob-bytes activation-failure copy handle the outcome (a UNC path is not a valid
    license blob, so activation fails `MALFORMED`). A **throwing** guard would instead land in the
    new `try` this spec adds, echo the UNC path back through the new error line — violating this
    bullet's own "do not echo it back" — and falsify the echo justification above. Note the whole
    change in the PR body so a reviewer sees it was deliberate rather than scope creep.
- **`src/client/components/NetworkSettings.svelte:263-271`** — `To rotate: run
  <code>tandem rotate-token</code> in the CLI.` is the same unrunnable-on-desktop copy, in the same

  - `tandem rotate-token` **cannot rotate a desktop install's token even when the CLI is present**.

    `token_store::get_or_create_token()`, which reads the **OS keyring**
