(deactivation) escalated rather than invented — see *For Bryan*. Ledger:
`docs/reviews/2026-09-02-v1-review/areas/armed-license-gate.md:24`. Probe:
`npx vitest run tests/client/license-store.svelte.test.ts tests/cli/license.test.ts`. Lands **after**

## Problem

Five named gaps. Two have moved since the review, and saying which is half the work:

**(a) The CLI is real, and the bundle genuinely does not ship it.** Measured:
`src-tauri/tauri.conf.json` `bundle.resources` ships `dist/server`, `dist/channel`,
`dist/stdio-bridge`, `dist/client`, `sample/`, `skills/`, `CHANGELOG.md`, `docs/workflows.md` —
**no `dist/cli`** — and `externalBin` is the two sidecars. So a desktop buyer reading
`SettingsLicenseTab.svelte:78-80` ("…or run `tandem activate <file>` from the command line") is told
to run a binary that does not exist on their machine. **This is a copy gap, not a capability gap:**
in-app activation already exists (`LicenseActivateForm.svelte` → `POST /api/license/activate`), and
the same tab renders it three lines above. The issue's "in-app activation (file picker + paste)" is
already half-shipped; the paste half is what a buyer actually has, because the email carries the key
as text.

**(b) Already fixed on master — do not re-fix it.** `docs/licensing-explained.md:39-44` now reads
"**double-clicking the file does nothing** — Tandem registers no `.license` file association", with
the four real associations cited. The claim the issue objected to is gone; the remaining half of its
"drop the claim **or** add the association" is a product choice, and the answer is *drop*, recorded
below with a reason rather than left implicit.

**(c) The 60 s poll swallows every failure.** `useLicense.svelte.ts`'s `poll()` catch is a bare
comment; `status` keeps its last value and nothing on screen changes. Two shapes: a *first*-poll
failure leaves `status === null`, so the tab renders neither pill nor hint and the user cannot tell
"no license problem" from "we never asked"; a later failure freezes a trial countdown or a pill at a
value the server may no longer agree with.

**(d) The pinned signing key has no dated home.** `src/server/license/public-key.ts` pins one Ed25519
key with no rotation date anywhere in `gh issue list`, which is exactly the failure CLAUDE.md's
dated-gate rule names ("a date living only in a doc comment never surfaces").

**(e) No deactivation path** — `tandem activate` has no inverse; removing a license means deleting
`license.json` by hand (`docs/data-locations.md:62` documents that). Policy as much as code.

Two small true things in the issue body that ride along because they are in the same files and cost
three lines each: `tandem activate <a-directory>` is **uncaught** (`src/cli/license.ts:126` sits
*outside* the `try` at `:127`, so `existsSync` says yes, `readFileSync` throws `EISDIR`, and the
buyer gets a stack trace instead of the per-cause copy the next eight lines exist to print); and
`TANDEM_APP_DATA_DIR` relocates `license.json` and `trial.json` while `docs/configuration.md:50`
lists only "sessions, the auth token, and durable annotations".

## Fix

- **`SettingsLicenseTab.svelte`** — `import { isTauriRuntime } from "../../cowork/cowork-helpers"`
  (exported; `EditorSettings.svelte:2,89` is the precedent for using it as a render-time discriminant
  in a settings surface). Desktop: the hint offers paste only, and says the emailed key is the whole
  path. Browser/npm: keep the `tandem activate <file>` clause verbatim — there the CLI is the
  process the user launched Tandem with. **No new testid** on this hint (it has none today), so no
  snapshot churn from this edit.
- **`useLicense.svelte.ts`** — the store exposes `statusUnavailable: boolean`, set in the `poll()`
  catch and cleared on any successful poll, plus a `console.warn` on the **transition into** failure
  (not per tick: the timer fires every 60 s forever and a per-tick warn is a log flood on an offline
  laptop). Last-known `status` is still kept and `ui` is unchanged — a transient fetch failure must
  never flip the wall or the editor's editability. `stop()` clears it with the rest of the baseline.
- **`SettingsLicenseTab.svelte`** — when `statusUnavailable`, render one `.license-warning` line:
  Tandem could not reach its own local server, so this is the last known state. **New
  `data-testid="license-status-unavailable"`** ⇒ regenerate
  `tests/design-system-impl/__snapshots__/testid-set.snap.txt` in the same commit (additive; the
  contract forbids removals, not additions).
- **`src/cli/license.ts:126`** — move `resolveLicenseInput` into its own `try`, and on a read failure
  print `[Tandem] Could not read a license from <input>.` + the paste hint, then `process.exit(1)`.
  Echoing `input` is safe **because that branch is only reachable when `existsSync(input)` was
  true**, i.e. it is a path, not blob bytes — the file's no-blob-bytes rule is preserved, and the
  reason is worth one inline comment.
- **`docs/configuration.md:50`** — name `license.json` and `trial.json` in the
  `TANDEM_APP_DATA_DIR` row, and add the consequence in `docs/data-locations.md`'s `trial.json` row:
  pointing the var somewhere new presents a fresh trial and an apparently-unlicensed device. This is
  the whole of the issue's `TANDEM_APP_DATA_DIR` item; it is documentation, not a behaviour change
  (the soft clock is ADR-040 §3, and #1787 already settled the two-var confusion).
- **`docs/licensing-explained.md`** — one sentence in the Part 1 activation paragraph saying the
  desktop app activates by paste in Settings → License and the `tandem` command belongs to the npm
  install. Part 3 mechanism prose is H-b's; this is Part 1 user copy.
- **File the dated issue** (not code): `Rotate the license signing key — review 2027-03-01`, body
  naming `src/server/license/public-key.ts` as the pinned key, `docs/licensing-operations.md` §7 as
  the procedure, and the criterion — *is a rotation procedure exercised, or the key superseded?* —
  answerable from those two tracked files, per the dated-gate rule's second half. Record the number
  in the PR body; **do not** add the date to a doc comment as well, which is the anti-pattern.

## Tests

   "fix" that nulls `status` on failure and blanks the tab, and kills one that flips `ui.showWall`);
   a subsequent success clears it; two consecutive failures produce exactly **one** `console.warn`
   (kills the per-tick flood); `stop()` resets it.
2. **`tests/client/…` component test for `SettingsLicenseTab`** if the file's existing pattern
   supports mounting — otherwise assert the copy split at the source level. Two rows: `isTauriRuntime
   () === true` renders no `tandem activate` string; `false` renders it. That negative is the whole
   point of (a) — a fix that adds a sentence without removing the CLI offer passes any
   "mentions paste" assertion.
3. **`tests/cli/license.test.ts`** — `runActivate` with a path that exists but cannot be read (a
   directory) exits 1 with the new message and **does not throw**; the existing bad-blob case still

   activation copy, which would tell a buyer their license is invalid when their argument was a
   folder.
4. **Snapshot**: `tests/design-system-impl/testid-coverage.test.ts` green after regeneration.

No new scanner, no drift guard, no wiring test: every claim above is either pinned by one of these
four or is a doc sentence.

## Not in scope

**Adding a `.license` file association** — recommended against, and this is the reason rather than an
omission: `validate_open_candidate` is the single argv + macOS `RunEvent::Opened` validator, so a new
extension inherits a UNC refusal that must precede any filesystem call and an NTFS-ADS colon scan on
the resolved path (CLAUDE.md, *Files, Sessions & Lifecycle*), i.e. a second OS-level entry point and
its threat model, to save one paste of a key the buyer already has in an email. The doc already tells
the truth. **`tandem deactivate`** — For Bryan. **The issue's remaining scattered bullets**, each
measured and left alone: `status: "licensed"` on the dark wire is a deliberate, documented back-compat
sentinel (`routes/license.ts` `toLicenseStatusWire` docblock) and `licenseInstalled` is documented
non-PII with its own reason; `LicenseUi.editable` **is** dead (the only `.editable` in `src/client/`
is Tiptap's `view.editable`), but deleting a field is a K-lows simplification, not this issue's gap;
the verifier's brand-without-shape check is a crypto-boundary question that belongs with the key
rotation. `NetworkSettings.svelte:271` offers `tandem rotate-token` with the same desktop problem —
same class, different issue, deliberately untouched here.
