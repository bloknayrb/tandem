## Problem

**(a) The bundle does not ship the CLI, and a user who has it still cannot license a desktop
install.** Measured: `tauri.conf.json` `bundle.resources` carries **no `dist/cli`** and `externalBin`
is the two sidecars, so `SettingsLicenseTab.svelte:77-81` ("…or run `tandem activate <file>` from the
command line") names a binary that is not on the buyer's machine. Sharper half: `resolveAppDataDir()`
(`src/server/platform.ts:11-15`) returns the `env-paths` default unless `TANDEM_APP_DATA_DIR` is set
and the CLI sets nothing (`src/cli/license.ts:112,129`), while the desktop points its sidecar at the
Tauri app-data dir (`src-tauri/src/sidecar.rs:1591`) — so a separately installed npm CLI writes
`license.json` where the desktop never reads it: a **silent no-op activation**. A copy gap, not a
capability gap — paste activation already renders three lines above (`LicenseActivateForm.svelte`).

**(b) Premise refuted — already fixed on master.** `docs/licensing-explained.md:39-44` now says
"**double-clicking the file does nothing** — Tandem registers no `.license` file association", citing
the four real ones. The remaining half ("drop the claim **or** add the association") is a product
call: For Bryan, recommendation *drop*. No code change.

**(c) The 60 s poll swallows every failure, and the tab then asserts a falsehood.**
`useLicense.svelte.ts:65-75`'s catch is a bare comment. A **first**-poll failure leaves `status ===
null`, and `SettingsLicenseTab`'s `pillLabel` fallback (`:26-33`) then fires unconditionally —
`gateDark` (`:21`) and `darkInstalled` (`:25`) are both false — so the pill reads **"Not enforced in
this version"**. A **later** failure freezes a countdown the server may no longer agree with: that is
what "last known state" wording is for.

**(d)** `src/server/license/public-key.ts:10` says "THIS KEY IS NOT ROTATABLE TODAY" with no date in
`gh issue list`. **(e)** No deactivation path; removing a license means deleting `license.json` by
hand (`docs/data-locations.md:62`) — policy, so For Bryan. Two riders from the issue body, same file:
`tandem activate <a-directory>` is **uncaught** (`src/cli/license.ts:126` sits *outside* the `try` at
`:127`, so `existsSync` says yes, `readFileSync` throws `EISDIR`, and the buyer gets a stack trace
instead of the per-cause copy the next eight lines print); and `TANDEM_APP_DATA_DIR` relocates
`license.json`/`trial.json` while `docs/configuration.md:50` names only sessions, the auth token and
annotations.

## Fix

- **`SettingsLicenseTab.svelte`, the CLI clause** — gate on `isTauriRuntime()` from
  `../../cowork/cowork-helpers` (`EditorSettings.svelte:2,89` is the precedent for a render-time
  discriminant captured once at init). Desktop: paste only. Browser/npm: keep the `tandem activate
  <file>` clause verbatim. **No `npm install -g tandem-editor` escape hatch** (unlike
  `SettingsClaudeCodeTab.svelte:448-457`) — a separately installed CLI activates a different app-data
  root. **No new testid on this hint.**
- **`useLicense.svelte.ts`** — `let statusUnavailable = $state(false)` plus a getter on the returned
  object, mirroring `status` at `:28`/`:78-80` (the object is built once at `:77-108`, so a plain
  property would freeze). Set it in the `poll()` catch; clear it on a successful poll, in `stop()`
  with the rest of the baseline, and in `set()` (`:104-107` is the activate path and a successful
  observation by definition — else a just-activated license renders beside a stale warning).
  `console.warn` on the **transition into** failure only; the timer fires forever, so per-tick is a
  flood. **`deriveLicenseUi` must NOT take `statusUnavailable`** — `ui` stays a pure function of
  `status`, so a transient failure structurally cannot flip the wall or editability.
- **`SettingsLicenseTab.svelte`, the unavailability surface.** **Gate the `"Not enforced in this
  version"` fallback on `status != null`** — with `status === null` render an unknown label instead;
  the pill is the discriminating surface and a warning line alone leaves the lie on screen. Then one
  `.license-warning` line when `statusUnavailable`, **split on whether there is a last known state**:
  `status != null` ⇒ could not reach the local server, this is the last known state; `status === null`
  ⇒ has not reached it *yet*, no license state known here. **New
  `data-testid="license-status-unavailable"`** ⇒ regenerate
  `tests/design-system-impl/__snapshots__/testid-set.snap.txt` in the same commit (additive).
- **`src/cli/license.ts:126`** — move `resolveLicenseInput` into its own `try`, **a SIBLING of the one
  at `:127`, never nested** (nesting routes the new catch through `:136`, which prints the generic
  `License activation failed.` copy on top — the double message reintroduced by structure). On a read
  failure print `[Tandem] Could not read a license from <input>.` plus the paste hint, then
  `process.exit(1)` **followed by an explicit `return`**: `exit` is typed `never`, so TS is satisfied
  without it, but under a spied `exit` the function falls through into `activateLicense(…, undefined)`
  and prints the generic copy anyway. Echoing `input` is safe — that branch is reachable only after
  `fileExists(input)` returned true, so it is a path, not blob bytes. **The no-argument branch
  (`:121-126`) gets the same explicit `return`.**
- **Docs.** `docs/configuration.md:50`: name `license.json` and `trial.json` in the
