# Gc2a — #1776 `activity.cursor` is written as a ProseMirror position and published where flat offsets are expected

Branch `fix/position-mapping-1776`. Closes #1776. Ledger: `docs/reviews/2026-09-02-v1-review/areas/client-editor.md:18`.

## Problem

`src/client/editor/extensions/awareness.ts` plugin 2 writes `state.selection.from` — a ProseMirror position — into `Y.Map('userAwareness')` under `Y_MAP_ACTIVITY`. `Y_MAP_SELECTION`, written 40 lines earlier in the same `update()`, goes through `pmSelectionToFlat`. So two numbers in one payload sit in two coordinate systems and neither is labelled on the wire. The server publishes the value unchanged in `tandem_getActivity` and `tandem_checkInbox`.

Measured on this branch 2026-09-08: on `# Title\n\nSome text here\n\n- one\n- two three`, with one `Z` inserted where `three` begins, `activity.cursor` is `38` (PM) while `Y_MAP_SELECTION.from` from the same transaction is `32` (flat). **Reproduce this derivation in the PR body.**

Two source lines carry the defect: `lastCursor = state.selection.from` in the doc-changed branch (published verbatim by the 200 ms typing write) and `cursor: view.state.selection.from` in the `TYPING_DEBOUNCE` typing-clear write.

`refuted.md:43` downgrades the issue's own "documented as flat" premise: no doc *stated* a system when the issue was filed. Since then `docs/mcp-tools.md` (#1903) and the tool description (#1907) were both corrected to say **ProseMirror position** — accurate bug notices, not a contract. The bug itself stands.

**The fix changes the UNITS, not the freshness.** `Y_MAP_ACTIVITY` is written only when the document changes, debounced 200 ms / 3000 ms, and carries no `textSnapshot` — so moving the caret never refreshes it and `tandem_getActivity` keeps returning the last-written value after `active` flips false. The "use it as a proximity hint, not a range endpoint" restriction is a **staleness** claim, not a units claim: **every surface this fix rewrites must keep it.**

## Fix

**Convert the value; keep the field name.** Renaming to a PM-labelled field is rejected: no MCP client holds a ProseMirror document, so a structural position is uninterpretable off-client.

- `src/client/editor/extensions/awareness.ts`, plugin 2 `update()` — two lines, modelled on the existing `pmSelectionToFlat` call in the same function:
  - `lastCursor = state.selection.from` → `lastCursor = pmPosToFlatOffset(state.doc, toPmPos(state.selection.from))`. Convert at capture time, against the doc the position came from. (Style preference, not an invariant: `lastCursor` is re-captured on every doc-changing transaction, so converting inside the timer would read the same doc and no test here discriminates the two.)
  - The typing-clear write: compute `const cursor = pmPosToFlatOffset(view.state.doc, toPmPos(view.state.selection.from))` **before** the `withBrowser(...)` call and pass it in, so both halves read one `view.state`.
  - The `cursor: lastCursor` line in the typing write is byte-identical before and after — it publishes the already-converted value.
  - Imports: add `pmPosToFlatOffset` to the existing `../../positions` import; `toPmPos` is already imported.
  - **Critical Rule 2 holds unchanged**: both writes stay inside their existing `withBrowser(...)` wrappers. Do not put the doc walk inside the transaction callback.
  - Cost: on a local keystroke the selection branch already runs two `pmPosToFlatOffset` walks, so this is a third of the same order. On a remote doc change that does not move the local caret, this goes 0 → 1 walk per synced transaction. `pmPosToFlatOffset` returns as soon as `pmPos < nodeEnd`, so each walk is proportional to the caret's distance from the document start. Acceptable; do not optimise here.
- `src/server/mcp/awareness.ts`: **no value change** — both publish sites are pass-through and stay so. Replace the `` "`cursor` is a ProseMirror position, not a flat offset (#1776)." `` clause in the `tandem_getActivity` description with: "`cursor` is a flat text offset in UTF-16 code units — the same coordinate system as annotation ranges. It is a proximity hint, not an edit anchor: it is written only when the document changes and carries no snapshot, so take ranges from tandem_resolveRange or tandem_search."
- `docs/mcp-tools.md`, four edits, all keeping the proximity-hint restriction:
  - The coordinate-systems preamble (`:91`): delete ", with one documented exception noted under [`tandem_getActivity`](#tandem_getactivity)" so the sentence ends at "MCP tools handle the conversion." Leaving it points the canonical offsets section at an exception that no longer exists.
  - The `tandem_getActivity` bold warning paragraph (`:1044`): replace with two sentences — the units ("`cursor` is a flat text offset in UTF-16 code units — the same coordinate system as annotation ranges, and the system `tandem_checkInbox`'s `activity.selectedText` is sliced from") **and the surviving restriction** ("It is written only when the document changes — 200 ms debounced while typing, then again at the `TYPING_DEBOUNCE` typing-clear — so moving the caret never refreshes it and it carries no `textSnapshot`. Use it as a proximity hint; take real ranges from `tandem_resolveRange` or `tandem_search`."). Drop "It is the one place in this document where an offset is not in the flat coordinate system", the units premise of "**Do not feed `cursor` to…**", and "treat it as unlabelled until #1776 lands". **Carry no source line numbers** — the current paragraph's `awareness.ts:309` citation is already stale.
  - The `cursor` Notes bullet (`:1063`) and the `tandem_checkInbox` bullet (`:1105`): flat/UTF-16 plus the same one-clause proximity qualifier. `:1105` already words the `selectedText` relationship correctly ("sliced from flat offsets") — keep that phrasing.
  - The bullet at `:1064` says "read `tandem_checkInbox`'s `activity.selectedText`, which *is* in flat offsets", but `selectedText` is a **string** (written from `state.doc.textBetween(...)`). Reword to `:1105`'s phrasing. One line, one bullet above a line this fix is already editing; in scope under the two-person "fix rather than file" rule.

## Tests

One new file, `tests/client/activity-cursor-flat.test.ts`.

**Fixture (load-bearing).** Build the Y.Doc with `loadMarkdown` on `# Title\n\nSome text here\n\n- one\n- two three\n` **first**, then bind a `Collaboration` editor with `AwarenessExtension` to it (the pattern in `tests/client/authorship-anchor.test.ts:14`) — not `new Editor({ content })` into an empty doc. Assertion (3) compares the client's `pmPosToFlatOffset` against the server's `extractText`, and that is only sound if the heading `level` reaches the Y.XmlElement as a JS **number**: `isHeadingLevel` requires `typeof level === "number"`, and a non-numeric attribute makes `extractText` charge 0 for the `# ` prefix while the client charges 2. **A two-character mismatch on (3) is the heading attribute, not the conversion.** The fixture must carry a heading and a list: in a single-paragraph document PM and flat coincide and every assertion below passes with the bug in place.

**Caret placement (load-bearing).** `const flat = extractText(ydoc); const target = toFlatOffset(flat.indexOf("three")); editor.commands.setTextSelection(flatOffsetToPmPos(editor.state.doc, target)); editor.commands.insertContent("Z");` — one character inserted immediately before `three`. Typed elsewhere, (1) and (3) are unsatisfiable.

Write `editor.state.selection.from` and `Y_MAP_SELECTION.from` in full throughout — this spec's subject is two identically-named fields in two coordinate systems.

1. **Discriminating-fixture guard.** `editor.state.selection.from` (38, PM) ≠ `pmPosToFlatOffset(editor.state.doc, toPmPos(editor.state.selection.from))` (32, flat). Kills a fixture that silently stops discriminating.
2. **Typing write is flat.** After the keystroke and 250 ms, `expect(activity.cursor).toBe(pmPosToFlatOffset(editor.state.doc, toPmPos(editor.state.selection.from)))`. Derived independently of the sibling key so it survives a fixture where `Y_MAP_SELECTION` is absent. **It does not discriminate a `cursor: userAwareness.get(Y_MAP_SELECTION).from` shortcut** — on this fixture the selection branch writes the same number with no debounce from the same `state`. What forbids that shortcut is the Fix section, not this test.
3. **Flat means flat, not merely self-consistent.** `extractText(ydoc).slice(cursor, cursor + 5) === "three"`, asserted with the slice being non-empty. Kills a conversion that is internally consistent but in the wrong system.
4. **The typing-clear site too.** After `TYPING_DEBOUNCE`, that write's `cursor` satisfies (2)'s derivation and (3). Kills fixing only the typing burst and leaving the clear write.
5. Drive the timers with `vi.useFakeTimers()` + `await vi.advanceTimersByTimeAsync(...)` — the plugin's timers are plain `setTimeout`. Restore real timers in `afterEach` and `editor.destroy()`.

**Mutation-check.** Revert each of the two changed source lines individually **from a file copy, never `git checkout`**: (2) and (3) must red on the capture line; (4) must red on the typing-clear line. Do not "revert" the `cursor: lastCursor` publish line — it is byte-identical before and after, so it pins nothing.

No test asserts the server publish sites: they are pass-through and stay so.
