# G7 — #1738 the Markdown source view cannot wrap long lines

Branch `fix/editor-quick-controls-text-size-and-reading-measure-outside-settings-and-source-view-line-wrap-1705`. Closes #1738.

Sweep wave 9 group G7 (`docs/plans/2026-09-06-open-issues-sweep.md:107`, `:471`). This is not a v1-review ledger row, and it has no experiment and no refuted entry. Probe: the E2E case below (long lines, off/on). This is the third of three specs and is independent of the display menu. Anchors hold on `origin/master` `5b1454d2`; see G7-1705.md.

## Problem

In `src/client/editor/SourceView.svelte`, `.source-view-textarea` (`:386-402`) sets `white-space: pre` (`:400`) and `overflow: auto` (`:401`). A Markdown paragraph is one source line, so any paragraph wider than the pane scrolls sideways. There is no setting to change this. The issue asks for a persisted toggle in Settings, modelled on `showRawMarkdown`.

## Fix

- **`src/client/hooks/useTandemSettings.ts`:**
  - Add `sourceViewLineWrap: boolean` to `TandemSettings`, next to `showRawMarkdown` (`:177`), with a comment.
  - Default it to `false` in `DEFAULTS` (next to `:284`).
  - Normalize it in `normalizeKnownFields`, next to `:626`, as `sourceViewLineWrap: parsed.sourceViewLineWrap === true`. This is the same opt-in idiom as `marginView` and `smartTypography` (`:622`, `:639`). Because the field is returned there, it joins `knownKeys` for the forward-compat passthrough with no further work.
  - **No schema bump and no migration step.**
    - This follows `showRawMarkdown` exactly: `tests/client/use-tandem-settings-migration.test.ts:68-70` records it as "a pure read in `normalizeKnownFields` (no version bump)".
    - The field-preservation contract (`useTandemSettings.ts:408-420`) says a later-added field "needs NO migration step of its own".
    - `CURRENT_SCHEMA_VERSION` stays `20`, so a downgraded client is not turned read-only over a cosmetic boolean.
    - The trade-off: a same-schema older client drops the key on its next write, just as it does for `showRawMarkdown`. That behaviour was verified: at the same schema, `normalizeKnownFields(parsed)` returns only known keys (`useTandemSettings.ts:907-938`).
  - **Default off, and why:** off keeps every existing user's source view exactly as it is today. Wrapping on is a visible change nobody asked for, and the issue asks for an *option*. This is recorded as an assumption so Bryan can flip the default in one line if the screenshots argue for it.
- **`src/client/components/EditorSettings.svelte`:** add a checkbox block after the raw-markdown block (`:349-372`), copying its markup.
  - Markup: `<label data-testid="editor-source-line-wrap">` containing `<input type="checkbox" checked={settings.sourceViewLineWrap} disabled={readOnly} onchange={(e) => onUpdate({ sourceViewLineWrap: (e.target as HTMLInputElement).checked })} style="accent-color: var(--tandem-accent); {disabledControlStyle(readOnly)}">`.
  - Label: "Wrap long lines in Markdown source".
  - Help line: "Long lines wrap to the pane instead of scrolling sideways. Display only — the file is unchanged."
  - The issue says "Appearance section", but the raw-markdown toggle it names as precedent has lived in EditorSettings since #1262. Source-view display belongs next to it.
- **`src/client/editor/SourceView.svelte`:**
  - Add a `lineWrap?: boolean` prop (default `false`) to `Props` (`:9-33`) and to the destructure (`:41-42`).
  - The textarea gets `class:wrap={lineWrap}`.
  - Add a scoped rule after `.source-view-textarea` containing `white-space: pre-wrap; overflow-wrap: anywhere;`.
    - Use standard properties only. Component CSS goes through lightningcss, so do not hand-write prefixes.
    - `overflow-wrap: anywhere` is required, not decorative. `pre-wrap` alone breaks only at spaces, so a long URL would still scroll sideways. The E2E below pins this.
  - `overflow: auto` stays, so vertical scrolling is unchanged.
  - The prop is read reactively. Toggling the setting while source view is open re-styles the textarea without a remount, and the draft, caret and node all survive.
- **`src/client/App.svelte`:** at the `<SourceView>` call (`:2975-2984`), pass `lineWrap={settingsState.settings.sourceViewLineWrap}`.
- **Quick control: not added to the display menu.** The issue requires only Settings. The display menu is about the formatted editor's reading layout; G7-1705 records that its presets do not apply in source view. A wrap toggle in that menu would be the one item that applies *only* in source view, and it would mix the two. See assumptions.
- **Testid, manifest and user guide:**
  - The new `editor-source-line-wrap` testid is additive (Critical Rule 7). Regenerate the snapshot in the same commit.
  - In the manifest, add the testid to the "Settings — Editor" group, next to `appearance-show-raw-markdown` (`:243`).
  - In `docs/user-guide.md:351`, add "source-view line wrap" to the Editor row.

5. **`tests/e2e/source-view.spec.ts`, new test.**
   - **Fixture:** write a file with two long lines after the heading:
     - a ~600-character paragraph of ordinary words
     - a single unbroken ~300-character token (for example `https://example.com/` followed by 280 letters, with no spaces)
   - Enter source view.
   - **Setting off:**
     - The textarea's computed `white-space` is `pre`.
     - `scrollWidth > clientWidth + 1`.
   - **Keep-state setup**, before changing the setting:
     - Type an edit into the textarea: place the caret at the end with `End` and type ` EDITED`.
     - Tag the node (`el.__g7 = 1`).
     - Set `selectionStart = selectionEnd = 10`.
     - Record the value.
   - **Turn the setting on:** enable `editor-source-line-wrap` in Settings → Editor (source view stays open). Press Escape, then `await expect(page.locator("[data-testid='settings-modal']")).toHaveCount(0)`.
   - **After:**
     - Computed `white-space` is `pre-wrap`.
     - `scrollWidth <= clientWidth + 1`. With the unbroken token in the fixture, this holds only if `overflow-wrap: anywhere` is applied.
     - The tag survives.
     - `selectionStart` is still `10`.
     - The value still equals the recorded edited value.
     - `localStorage["tandem:settings"].sourceViewLineWrap === true`.
   - **Kills:**
     - a class that never applies (lost scoping, or the rule placed in `index.html`)
     - a missing `overflow-wrap: anywhere`
     - a remount of the textarea, which the tag and caret detect
   - **Why value alone is not enough:** comparing the value by itself cannot tell a remount from a live update, because SourceView restores `initialDraft` on mount (`SourceView.svelte:13-18`, `App.svelte:2975-2984`).
