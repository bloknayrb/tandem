# G7 — #1738 the Markdown source view cannot wrap long lines

Branch `fix/editor-quick-controls-text-size-and-reading-measure-outside-settings-and-source-view-line-wrap-1705`. Closes #1738. Sweep wave 9 group G7 (`docs/plans/2026-09-06-open-issues-sweep.md:107`, `:471`); not a v1-review ledger row, no experiment, no refuted entry. Probe: the E2E case below (a long single-line paragraph, off/on). Third of three, and independent of the display menu.

## Problem

`src/client/editor/SourceView.svelte` `.source-view-textarea` (`:386-402`) sets `white-space: pre` (`:400`) and `overflow: auto` (`:401`). A Markdown paragraph is one source line, so any paragraph wider than the pane scrolls sideways, and there is no setting to change it. The issue asks for a persisted toggle in Settings, modelled on `showRawMarkdown`.

## Fix

- **`src/client/hooks/useTandemSettings.ts`:** add `sourceViewLineWrap: boolean` to `TandemSettings`, next to `showRawMarkdown` (`:177`), with a comment. Default `false` in `DEFAULTS` (next to `:284`). Normalize in `normalizeKnownFields` next to `:626` as `sourceViewLineWrap: parsed.sourceViewLineWrap === true`, the same opt-in idiom as `marginView`/`smartTypography` (`:622`, `:639`). Because the field is returned there, it joins `knownKeys` for the forward-compat passthrough without further work.
  - **No schema bump, no migration step.** This follows `showRawMarkdown` exactly: `tests/client/use-tandem-settings-migration.test.ts:68-70` records it as "a pure read in `normalizeKnownFields` (no version bump)". The field-preservation contract (`useTandemSettings.ts:408-420`) says a later-added field "needs NO migration step of its own". `CURRENT_SCHEMA_VERSION` stays `20`, so a downgraded client is not turned read-only for a cosmetic boolean. The trade: a same-schema older client drops the key on its next write, the same as `showRawMarkdown`.
  - **Default off, and why:** off keeps every existing user's source view exactly as it is today. Turning wrapping on is a visible change nobody has asked for, and the issue asks for an *option*. Recorded as an assumption so Bryan can flip the default in one line if the screenshots argue for it.
- **`src/client/components/EditorSettings.svelte`:** add a checkbox block after the raw-markdown block (`:349-372`), copying its markup: `<label data-testid="editor-source-line-wrap">`, `<input type="checkbox" checked={settings.sourceViewLineWrap} disabled={readOnly} onchange={(e) => onUpdate({ sourceViewLineWrap: (e.target as HTMLInputElement).checked })} style="accent-color: var(--tandem-accent); {disabledControlStyle(readOnly)}">`, label "Wrap long lines in Markdown source", and a help line: "Long lines wrap to the pane instead of scrolling sideways. Display only — the file is unchanged." The issue text says "Appearance section", but the raw-markdown toggle it names as precedent has lived in EditorSettings since #1262, and source-view display belongs with it.
- **`src/client/editor/SourceView.svelte`:** add a `lineWrap?: boolean` prop (default `false`) to `Props` (`:9-33`) and the destructure (`:41-42`). The textarea gets `class:wrap={lineWrap}`. Add a scoped rule after `.source-view-textarea` containing `white-space: pre-wrap; overflow-wrap: anywhere;` (standard properties only; component CSS goes through lightningcss, so no hand-written prefixes). `overflow-wrap: anywhere` is needed because `pre-wrap` alone breaks only at spaces, so a long URL would still scroll sideways. `overflow: auto` stays, so vertical scrolling is unchanged. The prop is read reactively, so toggling the setting with source view open re-styles the textarea without a remount and the draft is kept.
- **`src/client/App.svelte`** `<SourceView>` call (`:2975-2984`): `lineWrap={settingsState.settings.sourceViewLineWrap}`.
- Quick control: **not added to the display menu.** The issue requires Settings only, and the menu is about the rich editor's reading layout. See assumptions.
- Testid is additive (Critical Rule 7): `editor-source-line-wrap`. Regenerate the snapshot in the same commit, and add it to the manifest's "Settings — Editor" group next to `appearance-show-raw-markdown` (`:243`). `docs/user-guide.md:351`: add "source-view line wrap" to the Editor row.
