# J1 — #1771 SKILL.md's Word-comment recipe `tandem_getAnnotations({author:"import"})` can never return anything

Branch `fix/skill-and-workflows-doc-1771`. Closes #1771. Ledger: `docs/reviews/2026-09-02-v1-review/areas/skill-plugin.md:19`. Probe: read `skills/tandem/SKILL.md` and `docs/workflows.md` after the fix and confirm neither names the dead recipe, and both name `notesExcluded` + `importSource`.

## Problem

`skills/tandem/SKILL.md:110` (`.docx Review Workflow` step 2) and `docs/workflows.md:311` (the "Reviewing a .docx with Imported Word Comments" example) both tell Claude to call `tandem_getAnnotations({ author: "import" })` to see imported Word comments. That call's `annotations` array can never hold anything, in either state an import can be in:

- **Un-promoted.** `writeImportAnnotation` (`src/server/file-io/docx-comments.ts`) always stamps `author: "import"`, and imports land as `type: "note"` (W8 batch-promote flow). `tandem_getAnnotations`'s handler (`src/server/mcp/annotations.ts:403-412`) filters by `author` first, then unconditionally strips every `type === "note"` result (ADR-027 — notes are private) before returning.
- **Promoted.** The user's promote action (`src/client/panels/annotation-actions.ts:59-87`, `promotedAnnotation()`) flips the record to `type: "comment"`, `author: ann.author === "import" ? "user" : ann.author` (i.e. `"user"`), `audience: "outbound"`, and stamps `promotedFrom: "note"`. So a promoted import no longer has `author: "import"` either.

`author: "import"` is a valid enum value (`AuthorSchema`), so the call is accepted — but **the response is not silent**: `notesExcluded` (`annotations.ts:408-409`) is computed from what survives the author/type/status filters, BEFORE the note-type filter removes it. So `tandem_getAnnotations({ author: "import" })` against an un-promoted import returns `{ annotations: [], count: 0, notesExcluded: N }`, where N is exactly the "Word comments awaiting user promotion" the tool's own description already promises (`annotations.ts:386`, "notesExcluded reports how many were filtered, including imported Word comments awaiting user promotion"). The bug in the two docs isn't that the recipe returns nothing and looks like "no comments" — it's that both docs read only the empty `annotations` array and never mention `notesExcluded`, so the one real signal the call does carry is invisible in the documented recipe.

`docs/workflows.md:308-316` compounds this: its worked example shows `tandem_getAnnotations({ author: "import" })` returning two `type: "comment"` records — a shape direct-from-import annotations never have (they're `type: "note"` until promoted). The example is invented, not merely stale.

**The discriminator for a *promoted* import is `importSource`, not `promotedFrom`.** `promotedFrom: "note"` is stamped by the single shared `promotedAnnotation()` helper (`annotation-actions.ts:53-58`, "shared between the single-card `sendNoteToClaude` path and the batch `promoteNotesToComments` helper") on EVERY promoted note — including the user's own private note sent via `sendNoteToClaude` ("Send to Claude" on a single card, author-gated to `"user"`), which carries no `importSource` at all. A recipe keyed on `promotedFrom` alone would tell Claude to treat the user's own promoted personal notes as an outside Word reviewer's comments — the exact ADR-027 boundary promotion exists to make explicit. Only `importSource` (`{ author, file, commentId? }`, declared on the output schema at `output-schemas.ts:91-98`, set exclusively by the .docx import path at `docx-comments.ts:495-505`, and passed through `sanitizeAnnotation` untouched at `src/shared/sanitize.ts:145-146`) actually identifies an import.

## Fix

No server change — `writeImportAnnotation`, the note filter, `notesExcluded`, and `promotedAnnotation()` are all working as designed (W8, #756); the bug is entirely in the two docs describing a recipe, and a discriminator, the design never supported. Per the ledger's decided approach (`docs/reviews/2026-09-02-v1-review/tracks/J-words.md:12`), adding a new filter parameter is the larger option the MINIMALITY rule rejects here — everything needed is already expressible with the existing schema.

- `skills/tandem/SKILL.md:107-119` (`.docx Review Workflow`), step 2: replace the single dead call with the real two-step recipe and lifecycle note:

  Imported Word comments land as private notes (invisible to Claude, ADR-027) until the user batch-promotes them from the SidePanel.
  1. `tandem_getAnnotations({ author: "import" })` — expect the `annotations` array to be empty: imports live as private notes until the user promotes them, so they don't survive the note-type filter. **If anything does appear there, it is a real imported comment — act on it** (an un-promoted import is never `type: "comment"`, so this is not a state the current write path produces, but the recipe should not tell Claude to ignore a comment it can actually see). `notesExcluded` in the response is the "N Word comments awaiting promotion" probe. **The field is absent, not zero, when nothing is awaiting promotion** (`annotations.ts:434-435` only includes it when the count is `> 0`) — absence means zero, not unknown.
  2. Once promoted, they arrive via `tandem_checkInbox` (the pull surface for the promotion action itself) and show up on a catch-up read as `tandem_getAnnotations({ author: "user" })` filtered client-side on a populated `importSource` field, which carries the original reviewer's name and file. `promotedFrom: "note"` is also present on these records but is NOT a reliable import marker — it's stamped on every promoted note, including one the user sent to Claude personally with no `importSource` at all. **In Solo mode, "arrive via `tandem_checkInbox`" doesn't hold**: `promotedAnnotation()` stamps `heldInSolo: true` on the just-promoted record when the session is in Solo (`annotation-actions.ts:118-122`), and both `tandem_checkInbox`'s awareness ledger and `tandem_getAnnotations` filter held records out (`awareness.ts:611`, `annotations.ts:415`) — so the recipe returns nothing until the user switches back to Tandem mode. Add a half-clause: "(in Solo, the promotion is held like any other user comment and arrives on the first poll after the user switches back to Tandem — see Collaboration Mode)."

- `docs/workflows.md:299-330` ("Reviewing a .docx with Imported Word Comments"): rewrite to match — the opening paragraph states comments land as notes first; the worked example calls `tandem_getAnnotations({ author: "import" })` and reads `notesExcluded` (not a fabricated `annotations` array — an empty array here is the normal, expected result, not a bug to explain away), then shows the promoted-state read via `tandem_getAnnotations({ author: "user" })` returning a record with `importSource` (and, incidentally, `promotedFrom: "note"`) — not a bare `author: "import"` one. **These two examples land in the same contiguous section, one after the other** — see the Tests section below for why that shape matters to how the claims test must be scoped. Keep the rest of the workflow (reading context, replying) unchanged.
- No source change.
