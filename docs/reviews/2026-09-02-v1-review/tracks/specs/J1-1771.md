# J1 — #1771 SKILL.md's Word-comment recipe `tandem_getAnnotations({author:"import"})` can never return anything

Branch `fix/skill-and-workflows-doc-1771`. Closes #1771. Ledger: `docs/reviews/2026-09-02-v1-review/areas/skill-plugin.md:19`. Probe: read `skills/tandem/SKILL.md` and `docs/workflows.md` after the fix and confirm neither names the dead recipe.

## Problem

`skills/tandem/SKILL.md:110` (`.docx Review Workflow` step 2) and `docs/workflows.md:311` (the "Reviewing a .docx with Imported Word Comments" example) both tell Claude to call `tandem_getAnnotations({ author: "import" })` to see imported Word comments. That call can never return anything, in either state an import can be in:

- **Un-promoted.** `writeImportAnnotation` (`src/server/file-io/docx-comments.ts:483-486`) always stamps `author: "import"`, and the doc comment above it (`:490-500`) confirms imports land as `type: "note"` (W8 batch-promote flow). `tandem_getAnnotations`'s handler (`src/server/mcp/annotations.ts:390-396`) filters by `author` first, then unconditionally strips every `type === "note"` result (ADR-027 — notes are private) before returning. So an un-promoted import matches the author filter and is then deleted by the note filter two lines later.
- **Promoted.** The user's batch-promote action (`src/client/panels/annotation-actions.ts:59-87`, `promotedAnnotation()`) flips the record to `type: "comment"`, `author: ann.author === "import" ? "user" : ann.author` (i.e. `"user"`), `audience: "outbound"`, and stamps `promotedFrom: "note"`. So a promoted import no longer has `author: "import"` either.

`author: "import"` is a valid enum value (`AuthorSchema`, `src/shared/types.ts:23`), so the call is accepted and silently returns `{ annotations: [], count: 0 }` — Claude reads that as "no comments in this file" rather than "the recipe is wrong." The tool's own description (`annotations.ts:386`, "including imported Word comments awaiting user promotion (promoted ones surface as user comments)") already states the true behavior; the two docs just never matched it.

`docs/workflows.md:308-316` compounds this: its worked example shows `tandem_getAnnotations({ author: "import" })` returning `type: "comment"` records — a shape that direct-from-import annotations never have (they're `type: "note"` until promoted), so the example is invented, not merely stale.

## Fix

Both `promotedFrom` (`z.literal("note").optional()`) and `importSource` (`{ author, file, commentId? }`) are already declared on the MCP output schema (`src/server/mcp/output-schemas.ts:91-98`) and pass through `sanitizeAnnotation` untouched (`src/shared/sanitize.ts:145-146`), so a promoted import is fully visible to Claude with its original-reviewer attribution intact — no server change needed. Per the ledger's decided approach (`docs/reviews/2026-09-02-v1-review/tracks/J-words.md:12`, "or add an `includeImports`..."): adding a new filter parameter is the larger option the MINIMALITY rule rejects here — the promoted-state truth is already fully expressible with the existing schema, so document that instead.

- `skills/tandem/SKILL.md:107-119` (`.docx Review Workflow`), step 2: replace

  ```
  2. `tandem_getAnnotations({ author: "import" })` — check for imported Word comments; read and act on them
  ```

  with text that states the real lifecycle: imported Word comments land as private notes (invisible to Claude, ADR-027) until the user batch-promotes them from the SidePanel; once promoted they surface as ordinary `author: "user"` `type: "comment"` annotations, distinguishable by `promotedFrom: "note"`, with the original Word reviewer's name and file in `importSource`. The recipe becomes `tandem_getAnnotations({ author: "user" })` filtered client-side on `promotedFrom === "note"`, not a server-side filter (there isn't one, and adding one is the larger option this fix rejects).
- `docs/workflows.md:299-330` ("Reviewing a .docx with Imported Word Comments"): rewrite the section to match — the opening paragraph states comments land as notes first; the worked example calls `tandem_getAnnotations({ author: "user" })`, shows a `promotedFrom: "note"` + `importSource` record (not a bare `author: "import"` one), and a sentence acknowledging that Claude sees nothing until the user promotes. Keep the rest of the workflow (reading context, replying) unchanged.
- No source change. `writeImportAnnotation`, `annotations.ts`'s note filter, and `promotedAnnotation()` are all working as designed (W8, #756) — the bug is entirely in the two docs describing a recipe the design never supported.
