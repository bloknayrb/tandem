# E2-rust — #1809 a sidecar crash after boot is never restarted; `MAX_RESTARTS` is a boot-window budget only

Branch `fix/desktop-sidecar-lifecycle-and-start-at-login-repair-1762`. Closes #1809 — **but only because this spec implements the behaviour half.** The doc half is already done (below), so a doc-only PR would not close it. The issue's toast clause is filed as **#1959**, so the `Closes` carries no unfiled remainder. Ledger: `docs/reviews/2026-09-02-v1-review/areas/tauri.md:19`. Probe: none automatable; the decision function is unit-tested directly.

## Problem

`start_sidecar` (`src-tauri/src/sidecar.rs:1607`) runs `for attempt in 0..=MAX_RESTARTS` (`:1686`) and returns `Ok(SpawnOutcome::Started)` the moment `wait_for_health` first succeeds (`:1872`). The retry budget is therefore confined to the boot window. The per-spawn drain task's `CommandEvent::Terminated` arm (`:1812-1821`) logs a warn, sets `dead_flag`, calls `on_child_terminated` to clear the pid-keyed slot, and breaks. Nothing respawns. A crash minutes or hours in (#1757's EPIPE crash is one reachable cause) leaves the desktop app with no server, no dialog and no toast, until the user finds Settings → Network → Restart server.

**The doc half is already fixed and must not be re-claimed.** `docs/architecture.md:857` was rewritten in `b89b07f0` (#1821 group A) and now states the boot-window confinement explicitly, citing #1809. So the only work left is the behaviour — and that doc line then has to be rewritten again, because it currently documents the absence as the design.

**Scope decision, taken deliberately rather than left to the implementer:** the behaviour is in scope, the restart policy is bounded by a breaker, and nothing else about the boot loop changes. A doc-only PR is not an option here, because the doc is already correct about today's code.

## Fix

Restart on an unexpected steady-state exit, bounded by a breaker, reusing the existing restart machinery.

**The decision is a pure function**, so it is testable without an `AppHandle`:

```rust
pub(crate) enum CrashRestartDecision { Ignore, Restart, BreakerTripped }

fn crash_restart_decision(
    was_current_child: bool,
    healthy: bool,
    spawn_allowed: bool,
    history: &mut Vec<Instant>,
    now: Instant,
) -> CrashRestartDecision
```

- **`!was_current_child` -> `Ignore`, history untouched. This guard is FIRST and it is not optional.** `Terminated` is delivered per spawn attempt over a `channel(1)` behind `child.wait()`, drain tasks are never cancelled, and the drain loop is a serial `while let Some(event) = rx.recv().await` that logs every stdout/stderr line before reaching `Terminated` — so **child A's `Terminated` can land after child B is already in the slot and already healthy**. The repo says so itself in `terminated_clears_slot`'s docblock (`sidecar.rs:1041-1047`: "child A's `Terminated` can land *after* child B has been stored … #1756 reintroduced by its own fix"), and `clear_terminated_slot` (`:1077-1096`) has a live `else` arm logging "leaving it (newer child)". Concrete path: the retry loop kills child A on a health failure (`:1868`), sleeps 1 s, spawns child B, and B reaches `promote_healthy_and_drain` → `SIDECAR_HEALTHY = true` (`lib.rs:330`) before A's backlog drains. Without this input the decision sees `healthy = true, spawn_allowed = true` and returns `Restart`; `restart_sidecar` then calls `stop_sidecar_gracefully`, whose `owns_child` is read from the slot (`:587-591`) **still holding the live child B**, so it POSTs `/api/shutdown` at the healthy sidecar and hard-kills it.

  **Source the input from the identity test that already runs**, rather than adding a second one: make `clear_terminated_slot` → `on_child_terminated_in` → `on_child_terminated` each return the `terminated_clears_slot(slot_pid, pid)` verdict as a `bool`, and pass that value at the call site. One signature change through three one-line wrappers; no new state, no new predicate to keep in sync.
- `!healthy` -> `Ignore`, history untouched. **The second load-bearing guard.** During boot the same drain task fires `Terminated` while `start_sidecar`'s loop is still retrying; a handler that respawns there double-spawns into the slot the loop is about to fill. `SIDECAR_HEALTHY` is exactly "the boot loop already returned `Started`", and `restart_sidecar` clears it via `clear_healthy_under_lock` *before* stopping, so a user-initiated restart also lands here as `Ignore`.
- `!spawn_allowed` -> `Ignore`, history untouched. Covers `EXITING` (quit) and `SIDECAR_SHUTTING_DOWN` — which, **after #1808 lands in this same PR, is held across the download as well as the install**. A crash during a long update download is therefore not restarted until the guard drops; that is accepted and stated in full in `E2-rust-1808.md`'s "residual" paragraph. The PR body states it once, from there.
- Otherwise prune `history` of entries older than `CRASH_RESTART_WINDOW`, push `now`, and return `Restart` while `history.len() <= MAX_CRASH_RESTARTS`, else `BreakerTripped`.

**Every termination is treated as a crash, deliberately.** The arm binds `CommandEvent::Terminated(status)` and the decision does not read `status.code`. An outside `/api/shutdown` and a Task-Manager kill both produce the same event with `SIDECAR_HEALTHY` still true, so both are respawned up to the budget: the desktop app owns this sidecar, and the two deliberate stops that matter (Quit, install) are already covered by `spawn_allowed`.

Constants beside `MAX_RESTARTS` (`:152`): `const MAX_CRASH_RESTARTS: usize = 3;` and `const CRASH_RESTART_WINDOW: Duration = Duration::from_secs(300);` — the issue's own suggestion. The docblock must say why the window matters: a lifetime counter would make a day-long session permanently unrecoverable after three unrelated crashes.

Two accepted consequences, recorded in the docblock so a reviewer does not re-derive them as bugs: **the window is never reset by a successful manual recovery** (clearing the history on a user-initiated spawn puts a reset on a path that has no idea whether the fault is fixed; the window self-heals in five minutes), and **the budget is consumed before `restart_sidecar` reports anything** (it early-returns on a failed `RestartGate::try_acquire()` at `:313-317` and again on `!spawn_allowed()` at `:351-354`; threading that verdict back would make the decision impure).

State: `static CRASH_RESTARTS: Mutex<Vec<Instant>> = Mutex::new(Vec::new());` (a `std::sync::Mutex`, const-constructible since Rust 1.63).

Call site — `sidecar.rs:1812-1821`, immediately after the `on_child_terminated(...)` call, **taking that call's new return value**:

```rust
let was_current = on_child_terminated(&terminated_handle, child_pid);
// Bind and DROP the guard before the match. A `MutexGuard` created in a match
// scrutinee lives to the end of the match body, and this block sits inside a
// `tauri::async_runtime::spawn` future whose loop awaits — so a scrutinee-held
// `!Send` guard compiles today only because no arm awaits, and breaks with an
// error naming the spawn the moment one does. Poisoning is recovered the way
// `clear_terminated_slot` does it.
let decision = {
    let mut history = CRASH_RESTARTS.lock().unwrap_or_else(|p| p.into_inner());
    crash_restart_decision(
        was_current,
        crate::sidecar_is_healthy(),
        spawn_allowed(),
        &mut history,
        Instant::now(),
    )
};
match decision {
    CrashRestartDecision::Ignore => {}
    CrashRestartDecision::Restart => {
        log::warn!("[sidecar] crashed after boot — restarting (…)");
        restart_sidecar(terminated_handle.clone());
    }
    CrashRestartDecision::BreakerTripped => {
        log::warn!("…{MAX_CRASH_RESTARTS} crash restarts in {…}s — giving up");
        let _ = terminated_handle.emit("sidecar-restart-failed", "SIDECAR_CRASH_BREAKER_TRIPPED");
    }
}
```

**Reuse `restart_sidecar` (`:312`), do not hand-roll a spawn.** It already does `RestartGate::try_acquire` (so a crash-restart and a user click cannot race), `clear_healthy_under_lock`, `clear_startup_rejection`, the `spawn_allowed()` re-check inside the spawned task, `stop_sidecar_gracefully` — which, **now that `was_current_child` guarantees the slot really was cleared for this pid**, takes `owns_child = false`, skips the POST and reaches `kill_sidecar_inner` on an empty slot — then `start_sidecar` with its full `Started`/`Declined`/`Err` arms including the existing `sidecar-restart-failed` emit.

**`lib.rs`** gains one accessor: `pub(crate) fn sidecar_is_healthy() -> bool { SIDECAR_HEALTHY.load(Ordering::Acquire) }`, beside `await_sidecar_healthy` (`:796`). The static stays private — an unlocked *read* is already what `await_sidecar_healthy` does at `:799`, and the doc comment at `:206` says the mutex requirement is narrowed to writes.

**The auto-launcher consequence, named.** A crash-restart goes through `start_sidecar`, which re-reads `LAUNCHER_DEFERRED` per spawn (`sidecar.rs:1756`); `note_user_presence` consumes the latch with `swap(false)` (`lib.rs:752`) once the window is shown, so in the steady state a crash-restart spawns *without* the defer flag — exactly what today's Settings → Restart server already does. Accepted: the re-read is required behaviour (CLAUDE.md forbids capturing the latch), and passing `TANDEM_DEFER_LAUNCHER` unconditionally on the crash path would make automatic recovery differ from the manual one. This is also the "rules that bite" item for this issue; nothing else here touches a Y.Doc write, an `/api` route or a `data-testid`.

**No success toast in this PR.** The issue asks for a visible "Server restarted after a crash" toast; that is `src/client/**`, owned by the concurrent K-client group, and is **filed as #1959**. The `warn!` clears the release log floor, and the user-visible recovery is already correct (tabs go Disconnected and reconnect via the Hocuspocus generation gate). The **breaker trip** does get a toast, by reusing the existing `sidecar-restart-failed` event `App.svelte:285` already listens for.

**Docs:** rewrite `docs/architecture.md:857`'s step 5 — it currently says the boot-window confinement *is* the behaviour and cites #1809 as an open defect. New text: the boot loop is unchanged, plus the steady-state breaker (3 in 5 minutes), what trips it, and that a trip surfaces the same toast as a failed manual restart. **Correct the embedded citations in the same edit**: `:857` cites `sidecar.rs:1517` for the loop and `:1707` for the early return; they are now `:1686` and `:1872`.

## Tests

`src-tauri/src/sidecar.rs`, in a new named `#[cfg(test)] mod crash_restart_tests`. **Five pure unit tests on `crash_restart_decision`, no source scanning.**

1. `crash_restart_decision_ignores_a_terminated_event_for_a_superseded_child()` — `(false, true, true)` -> `Ignore`, history **empty** afterwards. **First, because it kills the worst bug**: without the guard a stale `Terminated` from a killed retry attempt gracefully stops and respawns a live, healthy sidecar.
2. `crash_restart_decision_ignores_a_crash_before_the_first_healthy_poll()` — `(true, false, true)` -> `Ignore`, history untouched (a version recording the attempt before checking `healthy` would burn the boot retries out of the steady-state budget).
3. `crash_restart_decision_ignores_a_crash_while_a_spawn_is_disallowed()` — `(true, true, false)` -> `Ignore`, history untouched. Kills a version that respawns during Quit or during an update install/download.
4. `crash_restart_decision_allows_three_in_the_window_then_trips()` — four calls at `now`, `+1s`, `+2s`, `+3s` -> `Restart, Restart, Restart, BreakerTripped`. Kills a breaker that never trips and an off-by-one that allows four.
5. `crash_restart_decision_forgets_crashes_older_than_the_window()` — three entries at an old instant, then one call at `old + CRASH_RESTART_WINDOW + 1s` -> `Restart`, `history.len() == 1`. Kills a lifetime counter and a prune that drops nothing.

**Build every `Instant` forward, never backward.** Seed `let old = Instant::now();`, push the old entries at `old`, and pass `now = old + CRASH_RESTART_WINDOW + Duration::from_secs(1)`. **`Instant - Duration` panics** when the result precedes the monotonic origin, and on Windows `Instant` is QPC-since-boot — so a backward-built instant would *panic* on a runner with under ~301 s of uptime.

**Mutation check:** invert the `was_current_child` guard and test 1 goes red; invert the `!healthy` guard and test 2 goes red; flip `spawn_allowed` and test 3 goes red; change `<=` to `<` in the budget check and test 4 goes red; delete the prune and test 5 goes red. Restore from a file copy, never `git checkout`.

## Done when

A post-boot crash respawns within the budget; a stale `Terminated` from a superseded child never does; a fourth crash in five minutes trips the breaker and emits `sidecar-restart-failed`; boot, Quit and update-install/download crashes all take `Ignore`; five tests pass; `architecture.md:857` describes the new behaviour with corrected citations; `cargo test` green.

## Not in scope

A "Server restarted after a crash" success toast — client-side, **tracked in #1959**. Any change to `MAX_RESTARTS`, the boot backoff, or the "Retry Server Start" dialog. Diagnosing #1757's EPIPE crash itself — this makes it survivable, not impossible.
