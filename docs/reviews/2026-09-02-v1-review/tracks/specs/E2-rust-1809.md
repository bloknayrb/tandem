# E2-rust — #1809 a sidecar crash after boot is never restarted; `MAX_RESTARTS` is a boot-window budget only

Branch `fix/desktop-sidecar-lifecycle-and-start-at-login-repair-1762`. Closes #1809 — **but only because this spec implements the behaviour half.** The doc half the issue names is already done (see below), so a doc-only PR would not close it. Ledger: `docs/reviews/2026-09-02-v1-review/areas/tauri.md:19`. Probe: none automatable; the decision function is unit-tested directly.

## Problem

`start_sidecar` (`src-tauri/src/sidecar.rs:1607`) runs `for attempt in 0..=MAX_RESTARTS` (`:1686`) and `return Ok(SpawnOutcome::Started)` the moment `wait_for_health` first succeeds (`:1872`). The retry budget is therefore consumed by, and confined to, the boot window. The per-spawn drain task's `CommandEvent::Terminated` arm (`:1812-1821`) logs a warn, sets `dead_flag`, calls `on_child_terminated` to clear the pid-keyed slot, and breaks. Nothing respawns. A crash minutes or hours in (the #1757 EPIPE crash is one reachable cause) leaves the desktop app with no server, no dialog and no toast, until the user finds Settings → Network → Restart server.

**The doc half is already fixed and must not be re-claimed.** `docs/architecture.md:857` was rewritten in `b89b07f0` (#1821 group A) and now states the boot-window confinement explicitly, citing #1809. Verified against current master. So the only work left is the behaviour, and the doc line has to be rewritten *again* once the behaviour changes, because it currently documents the absence as the design.

## Fix

Restart on an unexpected steady-state exit, bounded by a breaker, reusing the existing restart machinery rather than building a second one.

**The decision is a pure function**, so it is testable without an `AppHandle`:

```rust
pub(crate) enum CrashRestartDecision { Ignore, Restart, BreakerTripped }

fn crash_restart_decision(
    healthy: bool,
    spawn_allowed: bool,
    history: &mut Vec<Instant>,
    now: Instant,
) -> CrashRestartDecision
```

- `!healthy` -> `Ignore`. **This is the load-bearing guard.** During boot the same drain task fires `Terminated` while `start_sidecar`'s own loop is still retrying; a handler that respawns there double-spawns into the slot the loop is about to fill. `SIDECAR_HEALTHY` is exactly "the boot loop has already returned `Started`", and `restart_sidecar` clears it via `clear_healthy_under_lock` *before* stopping, so a user-initiated restart also lands here as `Ignore`.
- `!spawn_allowed` -> `Ignore`. Covers `EXITING` (quit) and `SIDECAR_SHUTTING_DOWN` (an update install holding the latch across `install()`).
- Otherwise prune `history` of entries older than `CRASH_RESTART_WINDOW`, push `now`, and return `Restart` while `history.len() <= MAX_CRASH_RESTARTS`, else `BreakerTripped`.

Constants beside `MAX_RESTARTS` (`:152`): `const MAX_CRASH_RESTARTS: usize = 3;` and `const CRASH_RESTART_WINDOW: Duration = Duration::from_secs(300);` — the issue's own suggestion (3 per 5 minutes). The docblock must say why the window matters: a lifetime counter would make a day-long session permanently unrecoverable after three unrelated crashes, which is a worse failure than the one being fixed.

State: `static CRASH_RESTARTS: Mutex<Vec<Instant>> = Mutex::new(Vec::new());` (a `std::sync::Mutex`, const-constructible since Rust 1.63; no lock is held across an `await`).

Call site — `sidecar.rs:1812-1821`, immediately after `on_child_terminated(&terminated_handle, child_pid);`:

```rust
match crash_restart_decision(crate::sidecar_is_healthy(), spawn_allowed(), &mut CRASH_RESTARTS.lock()…, Instant::now()) {
    Ignore => {}
    Restart => { log::warn!("[sidecar] crashed after boot — restarting (…)"); restart_sidecar(terminated_handle.clone()); }
    BreakerTripped => { log::warn!("…{MAX_CRASH_RESTARTS} crash restarts in {…}s — giving up"); let _ = terminated_handle.emit("sidecar-restart-failed", "SIDECAR_CRASH_BREAKER_TRIPPED"); }
}
```

**Reuse `restart_sidecar` (`:312`), do not hand-roll a spawn.** It already does everything the crash path needs and nothing it does not: `RestartGate::try_acquire` (so a crash-restart and a user click cannot race), `clear_healthy_under_lock`, `clear_startup_rejection`, the `spawn_allowed()` re-check inside the spawned task, `stop_sidecar_gracefully` — which with an already-cleared slot takes `owns_child = false`, skips the POST and reaches `kill_sidecar_inner` on an empty slot — then `start_sidecar` with its full `Started`/`Declined`/`Err` arms including the existing `sidecar-restart-failed` emit and `report_pending_opens_with`. A hand-rolled respawn would have to re-derive all of it.

**`lib.rs`** gains one accessor: `pub(crate) fn sidecar_is_healthy() -> bool { SIDECAR_HEALTHY.load(Ordering::Acquire) }`, beside `await_sidecar_healthy` (`:792`). `SIDECAR_HEALTHY` is a private static (`lib.rs:192`) and stays private — an unlocked *read* is already what `await_sidecar_healthy` does at `:799`, and the doc comment at `:206` explicitly says the mutex requirement is narrowed to writes, so this accessor is not a new licence.

**No success toast, deliberately.** The issue asks for a visible "Server restarted after a crash" toast; that is `src/client/**`, owned by the concurrently-running K-client group, and a new event would need a listener there. The `warn!` clears the release log floor, and the user-visible recovery is already correct — tabs go Disconnected and reconnect on their own via the Hocuspocus generation gate. The **breaker trip** does get a toast, by reusing the existing `sidecar-restart-failed` event that `App.svelte:285` already listens for (it ignores the payload and hardcodes its message), so the terminal case is not silent. Assumption; recorded in `assumptions` and in the PR body.

**Docs:** rewrite `docs/architecture.md:857`'s step 5 — it currently says the boot-window confinement *is* the behaviour and cites #1809 as an open defect. New text: the boot loop is unchanged, plus the steady-state breaker (3 in 5 minutes), what trips it, and that a trip surfaces the same toast as a failed manual restart. `docs/architecture.md:1193`'s `src/sidecar.rs` file-map line should gain "the post-boot crash breaker" to its list.

**Rules that bite:** the `LAUNCHER_DEFERRED` latch is re-read on every spawn (`sidecar.rs:1752`) — a crash-restart goes through `start_sidecar` and therefore re-reads it, which is the required behaviour and must not be short-circuited. No Y.Doc write, no `/api` route, no `data-testid`.

## Tests

`src-tauri/src/sidecar.rs` `#[cfg(test)] mod tests`. Four tests on the pure function, each killing a specific wrong implementation:

1. `crash_restart_decision_ignores_a_crash_before_the_first_healthy_poll()` — `healthy = false` -> `Ignore`, and asserts `history` is **untouched** (a version that records the attempt before checking `healthy` would burn the boot retries out of the steady-state budget). Kills the double-spawn-during-boot implementation, the most dangerous one.
2. `crash_restart_decision_ignores_a_crash_while_a_spawn_is_disallowed()` — `healthy = true, spawn_allowed = false` -> `Ignore`, history untouched. Kills a version that respawns during Quit or during an update install.
3. `crash_restart_decision_allows_three_in_the_window_then_trips()` — four calls at `now`, `now+1s`, `now+2s`, `now+3s` -> `Restart, Restart, Restart, BreakerTripped`. Kills a breaker that never trips and an off-by-one that allows four.
4. `crash_restart_decision_forgets_crashes_older_than_the_window()` — three at `now`, then one at `now + CRASH_RESTART_WINDOW + 1s` -> `Restart`, with `history.len() == 1` afterwards. Kills a lifetime counter, which would make a long session unrecoverable, and kills a prune that never actually drops entries.

`Instant` is not constructible from an epoch, so seed with `Instant::now()` and build the others with `+ Duration::from_secs(n)`; for test 4 use `base - CRASH_RESTART_WINDOW - Duration::from_secs(1)` for the old entries and `base` for the new one, so no wall-clock time passes.

5. `fn the_terminated_arm_routes_through_the_crash_decision()` — `include_str!` its own source, slice the `CommandEvent::Terminated(status) => {` arm to its closing brace, and assert it contains `crash_restart_decision`. One structural test, because the arm itself needs a live `AppHandle`; it is what stops the pure function from being correct and unreferenced.

**Mutation check:** invert the `!healthy` guard and test 1 goes red; delete the prune and test 4 goes red; change `<=` to `<` in the budget check and test 3 goes red. Restore from a file copy, never `git checkout`.

## Done when

A post-boot crash respawns within the budget; a fourth crash in five minutes trips the breaker and emits `sidecar-restart-failed`; boot, Quit and update-install crashes all take `Ignore`; five tests pass; `architecture.md:857` describes the new behaviour; `cargo test` green.

## Not in scope

A "Server restarted after a crash" success toast (client-side, K-client's territory — see above). Any change to `MAX_RESTARTS`, the boot backoff, or the "Retry Server Start" dialog. Diagnosing #1757's EPIPE crash itself — this makes it survivable, not impossible.
