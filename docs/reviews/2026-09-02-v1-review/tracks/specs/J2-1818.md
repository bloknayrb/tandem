# J2 — #1818 Three names for one restart action; `NetworkSettings.svelte` hints a non-existent `tandem start --port` flag

Branch `fix/product-copy-1814`. Closes #1818. Ledger row: `docs/reviews/2026-09-02-v1-review/areas/product.md:24`. Probe: none (source-confirmed: `runStart()` takes no args).

## Problem

**Part 1 — three names.** `NetworkSettings.svelte:115-122` labels the restart button *"Restart sidecar"* / *"Restarting…"* (`data-testid="network-restart-sidecar"`). `docs/troubleshooting.md:159`, `docs/architecture.md:822,912`, and `docs/release-smoke-checklist.md:36` all instead say *"Settings → Network → **Restart server**"* — i.e. every doc that tells a user where to find this exact button already calls it "Restart server"; the button itself is the one outlier. `App.svelte:290` names the SAME action's failure toast *"Sidecar failed to restart — see logs"* with no way to reach the logs from the toast (`show_in_file_manager` + `appLogDir()` already exist and are wired to a working "Open Log Folder" button in `SettingsAboutTab.svelte:67-78` — nothing routes them to this toast).

**Part 2 — dead flag.** `NetworkSettings.svelte:212` (inside the read-only Loopback Port row, `{#if isHttp}`) reads: *"Port used when transport is HTTP… To change, run `tandem start --port <N>`."* `src/cli/index.ts` and `src/cli/start.ts`: `runStart()` takes no arguments; the only port controls are the `TANDEM_PORT`/`TANDEM_MCP_PORT` env vars (documented at `docs/troubleshooting.md:141-148`). Following the hint prints the CLI's unknown-flag usage error.

## Fix

**Part 1**, `NetworkSettings.svelte`: rename the button's visible text only — *"Restart sidecar"* → **"Restart server"**; *"Restarting…"* → **"Restarting server…"** (keep `data-testid="network-restart-sidecar"` unchanged — renaming a `data-testid` requires regenerating `tests/design-system-impl/__snapshots__/testid-set.snap.txt` per Critical Rule 7, and the id is not user-facing copy, so leave it). No doc changes needed — `troubleshooting.md`, `architecture.md`, and the smoke checklist already say "Restart server"; this fix is the one place that disagreed with all three.

`App.svelte:290`: change the toast text to name the same action — *"Sidecar failed to restart"* → **"Tandem server failed to restart"** — and give it a real action instead of a dead "see logs" clause, using the `ToastAction` mechanism already defined at `useNotifications.svelte.ts:19-22` and already passed as `push`'s second argument (`push: (notification, action?: ToastAction) => void`, `:58`).

**The listener body has no seam a test can reach** — it is inline in `App.svelte`'s instance script (~L279-300), and nothing in the repo mounts `App.svelte` (its three existing suites are `readFileSync` source-text assertions, not renders — see Tests). Extract the notification + action into a small exported factory so it can be unit-tested on its own, and have `App.svelte` call it: new file `src/client/utils/sidecar-restart-toast.ts`, modeled on `SettingsAboutTab.svelte:67-78`'s `handleOpenLogFolder` (`appLogDir()` from `@tauri-apps/api/path` + `invoke("show_in_file_manager", { path })` via `loadInvoke()` from `../cowork/cowork-invoke.js`, both dynamically imported):

```ts
// The toast message is a fixed, hard-coded string — deliberately (#631): no path, errno
// text, env var, or auth token from the underlying sidecar failure can ever reach the DOM
// through this surface. Do not interpolate failure detail into `notification.message`.
export async function openLogFolder(push: (n: TandemNotification) => void): Promise<void> {
  try {
    const [{ appLogDir }, invoke] = await Promise.all([
      import("@tauri-apps/api/path"),
      loadInvoke(),
    ]);
    await invoke("show_in_file_manager", { path: await appLogDir() });
  } catch {
    push({
      id: `open-log-folder-failed-${Date.now()}`,
      type: "general-error",
      severity: "error",
      message: "Couldn't open the log folder",
      timestamp: Date.now(),
    });
  }
}

export function sidecarRestartFailedToast(push: (n: TandemNotification) => void): {
  notification: TandemNotification;
  action: ToastAction;
} {
  return {
    notification: {
      id: `sidecar-restart-failed-${Date.now()}`,
      type: "general-error",
      severity: "error",
      message: "Tandem server failed to restart",
      dedupKey: "sidecar-restart-failed",
      timestamp: Date.now(),
      errorCode: "SIDECAR_RESTART_FAILED",
    },
    action: { label: "Open Log Folder", onClick: () => void openLogFolder(push) },
  };
}
```

`App.svelte`'s `listen("sidecar-restart-failed", …)` callback becomes `const { notification, action } = sidecarRestartFailedToast(notifications.push); notifications.push(notification, action);` — `notifications.push` (`useNotifications.svelte.ts:58`, `(notification: TandemNotification, action?: ToastAction) => void`) is the only notifier `App.svelte` holds; there is no separate `ctx.notify(severity, message)` helper outside the settings-tab context, so `openLogFolder` takes `push` directly and builds its own `TandemNotification`, rather than the `(severity, message)` shape `SettingsAboutTab.svelte`'s `ctx.notify` exposes. Label text matches the existing About-tab button (`:180`) so the same action reads the same everywhere, per the issue's "one word everywhere" ask. **`openLogFolder`'s own failure path is caught and surfaced, not silent**: it reuses `SettingsAboutTab.svelte:76`'s exact string, "Couldn't open the log folder," so a rejecting `loadInvoke()`/`show_in_file_manager` (e.g. `TAURI_NOT_AVAILABLE` from `cowork-invoke.ts:25`) never escapes `action.onClick()` as an unhandled rejection and the toast button never silently no-ops. Adjust field names to whatever `TandemNotification`'s type actually requires (check `useNotifications.svelte.ts`'s type definition) rather than assuming this shape is exact — the `id`/`type`/`severity`/`message`/`timestamp` fields above mirror the sibling `sidecar-restart-failed` notification literally above them.

**Part 2**, `NetworkSettings.svelte:212`: delete the `tandem start --port <N>` hint sentence. Per the wave-table note ("delete the hint rather than add the flag"), do not add CLI flag support and do not substitute an env-var-based replacement sentence — the row is inside `{#if isHttp}`, which renders in BOTH the desktop app (no CLI at all, per Part 1's `doctor.ts` caveat) and the npm/CLI build, and a correct env-var instruction is only actionable for the latter; inventing per-runtime copy here is exactly the scope the wave-table note is declining. Leave the bare port-number display (`{bindPort ?? "—"}`) and its label; remove only the trailing `<div>` line with the false instruction.

## Tests

No test currently pins `NetworkSettings.svelte`'s button text, the toast message, or the port hint (`grep -rl "Restart sidecar\|Restart server\|tandem start --port"` over `tests/` returns nothing) — none of this is a discriminating-test gap to fill retroactively; add coverage for the new behavior only:

1. Extend `tests/client/network-settings-autostart.test.ts` (the existing `NetworkSettings.svelte` suite) with cases asserting the button's visible text is "Restart server" (not "Restart sidecar") and the port-hint sentence is gone. **The port-hint case needs a positive control, or it passes against the unfixed component**: the suite's module-level `createAppInfo` mock (`:59-61`) is a fixed literal (`() => ({ info: null, loading: false, error: null })`), and the Loopback Port row — hint included — lives inside `{#if isHttp}` (`NetworkSettings.svelte:203-214`), which is `false` whenever `info` is `null`. That renders the row absent today, unfixed, so a bare `not.toContain("tandem start --port")` is a false pass. **A per-test override needs a mutable cell, not a per-case `vi.doMock`** — the mock factory is hoisted and module-scoped, and `NetworkSettings` is imported at module scope, so convert it to the same shape the file already uses for autostart (`autostartStatusCell`, `:40-52`): `let appInfoCell: { info: AppInfoData | null; loading: boolean; error: string | null } = { info: null, loading: false, error: null }; vi.mock(".../useAppInfo.svelte.js", () => ({ createAppInfo: () => appInfoCell }))`. Set `appInfoCell = { info: { transport: "http", bindPort: 3479 }, loading: false, error: null }` before `render()` in the port-hint case, first assert a positive control — the `Loopback Port` label or the `3479` value is present in the DOM — then assert `container.textContent` does not contain `tandem start --port`, and reset `appInfoCell` to its `info: null` default in the file-scope `afterEach` so the other cases keep rendering with `info: null`. A case rendered with `info: null` does not exercise this row at all and is not a valid instrument for the assertion.
2. `src/client/utils/sidecar-restart-toast.ts` (new, see Fix): unit-test `sidecarRestartFailedToast(push)` directly — no `App.svelte` mount required. Assert `action.label === "Open Log Folder"`; mock `@tauri-apps/api/path`'s `appLogDir` and `../cowork/cowork-invoke.js`'s `loadInvoke` (returning a mock `invoke`), call `action.onClick()`, and assert `invoke` was called with `("show_in_file_manager", { path: <appLogDir's resolved value> })`. **Add a second case for the catch path**: make `loadInvoke()` (or the mocked `invoke`) reject, call `action.onClick()`, `await` a microtask flush, and assert (a) the call does not reject out of `onClick` — no unhandled rejection — and (b) the mock `push` was called once with a notification whose `message` is exactly `"Couldn't open the log folder"`. This is the desktop-only unit coverage the wave-table note asks for; note in the PR body that it substitutes for Playwright, which never runs under Tauri.
3. **`tests/client/app-action-mount-contract.test.ts`** (new `it`, using the file's existing `prepare`/`readFileSync`/`ROOT` source-text helpers — see `:361-374` for the pattern this mirrors): assert `src/client/App.svelte`'s source matches `/sidecarRestartFailedToast\(/` AND `/notifications\.push\(\s*notification\s*,\s*action\s*\)/`, and does **not** match `/Sidecar failed to restart/`. Without this, an implementation that adds the new module and its own green unit test while leaving `App.svelte`'s inline `notifications.push({ message: "Sidecar failed to restart — see logs" })` untouched satisfies every other item in this list while the shipped toast never changes — items 1 and 2 test the new module in isolation and neither one notices whether `App.svelte` actually calls it.
4. `tests/client/notification-dedup.test.ts:51`'s `makeNotification` default `message: "Sidecar failed to restart — see logs"` is unpinned decorative fixture text (no assertion reads it) — leave it; changing it is optional polish, not required by any test.
