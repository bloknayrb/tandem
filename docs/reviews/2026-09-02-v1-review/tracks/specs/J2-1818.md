# J2 — #1818 Three names for one restart action; `NetworkSettings.svelte` hints a non-existent `tandem start --port` flag

Branch `fix/product-copy-1814`. Closes #1818. Ledger row: `docs/reviews/2026-09-02-v1-review/areas/product.md:24`. Probe: none (source-confirmed: `runStart()` takes no args).

## Problem

**Part 1 — three names.** `src/client/components/NetworkSettings.svelte:115-122` labels the restart button *"Restart sidecar"* / *"Restarting…"* (`data-testid="network-restart-sidecar"`). `docs/troubleshooting.md:159`, `docs/architecture.md:822,912`, and `docs/release-smoke-checklist.md:36` all instead say *"Settings → Network → **Restart server**"* — every doc that tells a user where to find this button already calls it "Restart server"; the button itself is the one outlier. `App.svelte:290` names the same action's failure toast *"Sidecar failed to restart — see logs"* with no way to reach the logs from the toast.

**Part 2 — dead flag.** `src/client/components/NetworkSettings.svelte:212` (inside the read-only Loopback Port row, `{#if isHttp}`) reads: *"Port used when transport is HTTP… To change, run `tandem start --port <N>`."* `runStart()` (`src/cli/start.ts`) takes no arguments; the only port controls are the `TANDEM_PORT`/`TANDEM_MCP_PORT` env vars. Following the hint prints the CLI's unknown-flag usage error.

## Fix

**Part 1**, `src/client/components/NetworkSettings.svelte`: rename the button's visible text only — *"Restart sidecar"* → **"Restart server"**; *"Restarting…"* → **"Restarting server…"** (keep `data-testid="network-restart-sidecar"` unchanged — renaming it requires regenerating `tests/design-system-impl/__snapshots__/testid-set.snap.txt` per Critical Rule 7, and the id is not user-facing copy).

`App.svelte:290`: change the toast text to name the same action and drop the dead clause — *"Sidecar failed to restart — see logs"* → **"Tandem server failed to restart."** No link, no new action, no new module: `show_in_file_manager`/`appLogDir()` already have a working "Open Log Folder" button on `SettingsAboutTab.svelte:67-78`, and wiring an equivalent action onto this toast is a small but real feature build (a new exported module, dynamic `@tauri-apps/api/path` + `cowork-invoke` imports, its own failure-handling path) that this copy-focused issue doesn't ask for — the issue's complaint is the disagreeing names and the dead "see logs" clause, not a missing action button. Deleting the dead-end clause closes both, the same way Part 2 and #1781 both close their own "on-screen instructions → dead end" defects by deletion rather than by building the missing affordance.

**Part 2**, `src/client/components/NetworkSettings.svelte:212`: delete the `tandem start --port <N>` hint sentence. Per the wave-table note ("delete the hint rather than add the flag"), do not add CLI flag support and do not substitute an env-var-based sentence — the row renders in both the desktop app (no CLI at all) and the npm/CLI build, and a correct env-var instruction is only actionable for the latter. Leave the bare port-number display (`{bindPort ?? "—"}`) and its label; remove only the trailing `<div>` line with the false instruction.
