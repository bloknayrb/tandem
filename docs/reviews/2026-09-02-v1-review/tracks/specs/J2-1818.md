# J2 — #1818 Three names for one restart action; `NetworkSettings.svelte` hints a non-existent `tandem start --port` flag

Branch `fix/product-copy-1814`. Closes #1818. Ledger row: `docs/reviews/2026-09-02-v1-review/areas/product.md:24`. Probe: none (source-confirmed: `runStart()` takes no args).

## Problem

**Part 1 — three names.** `NetworkSettings.svelte:115-122` labels the restart button *"Restart sidecar"* / *"Restarting…"* (`data-testid="network-restart-sidecar"`). `docs/troubleshooting.md:159`, `docs/architecture.md:822,912`, and `docs/release-smoke-checklist.md:36` all instead say *"Settings → Network → **Restart server**"* — i.e. every doc that tells a user where to find this exact button already calls it "Restart server"; the button itself is the one outlier. `App.svelte:290` names the SAME action's failure toast *"Sidecar failed to restart — see logs"* with no way to reach the logs from the toast (`show_in_file_manager` + `appLogDir()` already exist and are wired to a working "Open Log Folder" button in `SettingsAboutTab.svelte:67-78` — nothing routes them to this toast).

**Part 2 — dead flag.** `NetworkSettings.svelte:212` (inside the read-only Loopback Port row, `{#if isHttp}`) reads: *"Port used when transport is HTTP… To change, run `tandem start --port <N>`."* `src/cli/index.ts` and `src/cli/start.ts`: `runStart()` takes no arguments; the only port controls are the `TANDEM_PORT`/`TANDEM_MCP_PORT` env vars (documented at `docs/troubleshooting.md:141-148`). Following the hint prints the CLI's unknown-flag usage error.

## Fix

**Part 1**, `NetworkSettings.svelte`: rename the button's visible text only — *"Restart sidecar"* → **"Restart server"**; *"Restarting…"* → **"Restarting server…"** (keep `data-testid="network-restart-sidecar"` unchanged — renaming a `data-testid` requires regenerating `tests/design-system-impl/__snapshots__/testid-set.snap.txt` per Critical Rule 7, and the id is not user-facing copy, so leave it). No doc changes needed — `troubleshooting.md`, `architecture.md`, and the smoke checklist already say "Restart server"; this fix is the one place that disagreed with all three.

`App.svelte:290`: change the toast text to name the same action — *"Sidecar failed to restart"* → **"Tandem server failed to restart"** — and give it a real action instead of a dead "see logs" clause, using the `ToastAction` mechanism already defined at `useNotifications.svelte.ts:19-22` and already passed as `push`'s second argument (`push: (notification, action?: ToastAction) => void`, `:58`). Model: `SettingsAboutTab.svelte:67-78`'s `handleOpenLogFolder` (`appLogDir()` from `@tauri-apps/api/path` + `invoke("show_in_file_manager", { path })`, both dynamically imported). Extract or duplicate that logic at the `notifications.push(...)` call site in `App.svelte` (~L286-294) and pass `{ label: "Open Log Folder", onClick: () => void handleOpenLogFolder() }` as the second argument — label text matches the existing About-tab button (`:180`) so the same action reads the same everywhere, per the issue's "one word everywhere" ask.

**Part 2**, `NetworkSettings.svelte:212`: delete the `tandem start --port <N>` hint sentence. Per the wave-table note ("delete the hint rather than add the flag"), do not add CLI flag support and do not substitute an env-var-based replacement sentence — the row is inside `{#if isHttp}`, which renders in BOTH the desktop app (no CLI at all, per Part 1's `doctor.ts` caveat) and the npm/CLI build, and a correct env-var instruction is only actionable for the latter; inventing per-runtime copy here is exactly the scope the wave-table note is declining. Leave the bare port-number display (`{bindPort ?? "—"}`) and its label; remove only the trailing `<div>` line with the false instruction.
