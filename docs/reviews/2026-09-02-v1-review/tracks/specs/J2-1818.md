# J2 — #1818 Three names for one restart action; `NetworkSettings.svelte` hints a non-existent `tandem start --port` flag

Branch `fix/product-copy-1814`. Closes #1818. Ledger row: `docs/reviews/2026-09-02-v1-review/areas/product.md:24`. Probe: none (source-confirmed: `runStart()` takes no args).

## Problem

**Part 1 — three names.** `src/client/components/NetworkSettings.svelte:115-122` labels the restart button *"Restart sidecar"* / *"Restarting…"* (`data-testid="network-restart-sidecar"`). `docs/troubleshooting.md:159`, `docs/architecture.md:822,912`, and `docs/release-smoke-checklist.md:36` all instead say *"Settings → Network → **Restart server**"* — i.e. every doc that tells a user where to find this exact button already calls it "Restart server"; the button itself is the one outlier. `App.svelte:290` names the SAME action's failure toast *"Sidecar failed to restart — see logs"* with no way to reach the logs from the toast (`show_in_file_manager` + `appLogDir()` already exist and are wired to a working "Open Log Folder" button in `SettingsAboutTab.svelte:67-78` — nothing routes them to this toast).

**Part 2 — dead flag.** `src/client/components/NetworkSettings.svelte:212` (inside the read-only Loopback Port row, `{#if isHttp}`) reads: *"Port used when transport is HTTP… To change, run `tandem start --port <N>`."* `src/cli/index.ts` and `src/cli/start.ts`: `runStart()` takes no arguments; the only port controls are the `TANDEM_PORT`/`TANDEM_MCP_PORT` env vars (documented at `docs/troubleshooting.md:141-148`). Following the hint prints the CLI's unknown-flag usage error.

## Fix

**Part 1**, `src/client/components/NetworkSettings.svelte`: rename the button's visible text only — *"Restart sidecar"* → **"Restart server"**; *"Restarting…"* → **"Restarting server…"** (keep `data-testid="network-restart-sidecar"` unchanged — renaming a `data-testid` requires regenerating `tests/design-system-impl/__snapshots__/testid-set.snap.txt` per Critical Rule 7, and the id is not user-facing copy, so leave it). No doc changes needed — `troubleshooting.md`, `architecture.md`, and the smoke checklist already say "Restart server"; this fix is the one place that disagreed with all three.

`App.svelte:290`: change the toast text to name the same action — *"Sidecar failed to restart"* → **"Tandem server failed to restart"** — and give it a real action instead of a dead "see logs" clause, using the `ToastAction` mechanism already defined at `useNotifications.svelte.ts:19-22` and already passed as `push`'s second argument (`push: (notification, action?: ToastAction) => void`, `:58`).

**The listener body has no seam a test can reach** — it is inline in `App.svelte`'s instance script (~L279-300), and nothing in the repo mounts `App.svelte` (its three existing suites are `readFileSync` source-text assertions, not renders — see Tests). Extract the notification + action into a small exported factory so it can be unit-tested on its own, and have `App.svelte` call it: new file `src/client/utils/sidecar-restart-toast.ts`, modeled on `SettingsAboutTab.svelte:67-78`'s `handleOpenLogFolder` (`appLogDir()` from `@tauri-apps/api/path` + `invoke("show_in_file_manager", { path })` via `loadInvoke()` from `../cowork/cowork-invoke.js`, both dynamically imported):

```ts
// The toast message is a fixed, hard-coded string — deliberately (#631): no path, errno
// text, env var, or auth token from the underlying sidecar failure can ever reach the DOM
// through this surface. Do not interpolate failure detail into `notification.message`.
export async function openLogFolder(push: (n: TandemNotification) => void): Promise<void> {
  try {
    const [{ appLogDir }, invoke] = await Promise.all([
      import("@tauri-apps/api/path"),
      loadInvoke(),
    ]);
    await invoke("show_in_file_manager", { path: await appLogDir() });
  } catch {
    push({
      id: `open-log-folder-failed-${Date.now()}`,
      type: "general-error",
      severity: "error",
      message: "Couldn't open the log folder",
      timestamp: Date.now(),
    });
  }
}

export function sidecarRestartFailedToast(push: (n: TandemNotification) => void): {
  notification: TandemNotification;
  action: ToastAction;
} {
  return {
    notification: {
      id: `sidecar-restart-failed-${Date.now()}`,
      type: "general-error",
      severity: "error",
      message: "Tandem server failed to restart",
      dedupKey: "sidecar-restart-failed",
      timestamp: Date.now(),
      errorCode: "SIDECAR_RESTART_FAILED",
    },
    action: { label: "Open Log Folder", onClick: () => void openLogFolder(push) },
  };
}
```

`App.svelte`'s `listen("sidecar-restart-failed", …)` callback becomes `const { notification, action } = sidecarRestartFailedToast(notifications.push); notifications.push(notification, action);` — `notifications.push` (`useNotifications.svelte.ts:58`, `(notification: TandemNotification, action?: ToastAction) => void`) is the only notifier `App.svelte` holds; there is no separate `ctx.notify(severity, message)` helper outside the settings-tab context, so `openLogFolder` takes `push` directly and builds its own `TandemNotification`, rather than the `(severity, message)` shape `SettingsAboutTab.svelte`'s `ctx.notify` exposes. Label text matches the existing About-tab button (`:180`) so the same action reads the same everywhere, per the issue's "one word everywhere" ask. **`openLogFolder`'s own failure path is caught and surfaced, not silent**: it reuses `SettingsAboutTab.svelte:76`'s exact string, "Couldn't open the log folder," so a rejecting `loadInvoke()`/`show_in_file_manager` (e.g. `TAURI_NOT_AVAILABLE` from `cowork-invoke.ts:25`) never escapes `action.onClick()` as an unhandled rejection and the toast button never silently no-ops. Adjust field names to whatever `TandemNotification`'s type actually requires (check `useNotifications.svelte.ts`'s type definition) rather than assuming this shape is exact — the `id`/`type`/`severity`/`message`/`timestamp` fields above mirror the sibling `sidecar-restart-failed` notification literally above them.

**Part 2**, `src/client/components/NetworkSettings.svelte:212`: delete the `tandem start --port <N>` hint sentence. Per the wave-table note ("delete the hint rather than add the flag"), do not add CLI flag support and do not substitute an env-var-based replacement sentence — the row is inside `{#if isHttp}`, which renders in BOTH the desktop app (no CLI at all, per Part 1's `doctor.ts` caveat) and the npm/CLI build, and a correct env-var instruction is only actionable for the latter; inventing per-runtime copy here is exactly the scope the wave-table note is declining. Leave the bare port-number display (`{bindPort ?? "—"}`) and its label; remove only the trailing `<div>` line with the false instruction.

## Tests

No test currently pins `src/client/components/NetworkSettings.svelte`'s button text, the toast message, or the port hint (`grep -rl "Restart sidecar\|Restart server\|tandem start --port"` over `tests/` returns nothing) — none of this is a discriminating-test gap to fill retroactively; add coverage for the new behavior only:

1. Extend `tests/client/network-settings-autostart.test.ts` (the existing `src/client/components/NetworkSettings.svelte` suite) with cases asserting the button's visible text is "Restart server" (not "Restart sidecar") and the port-hint sentence is gone. **The port-hint case needs a positive control, or it passes against the unfixed component**: the suite's module-level `createAppInfo` mock (`:59-61`) is a fixed literal (`() => ({ info: null, loading: false, error: null })`), and the Loopback Port row — hint included — lives inside `{#if isHttp}` (`src/client/components/NetworkSettings.svelte:203-214`), which is `false` whenever `info` is `null`. That renders the row absent today, unfixed, so a bare `not.toContain("tandem start --port")` is a false pass. **A per-test override needs a mutable cell, not a per-case `vi.doMock`** — the mock factory is hoisted and module-scoped, and `NetworkSettings` is imported at module scope, so convert it to the same shape the file already uses for autostart (`autostartStatusCell`, `:40-52`): `let appInfoCell: { info: AppInfoData | null; loading: boolean } = { info: null, loading: false }; vi.mock(".../useAppInfo.svelte.js", () => ({ createAppInfo: () => appInfoCell }))`. **Match the real `AppInfoState`/`AppInfoData` shapes exactly** — `AppInfoState` (`useAppInfo.svelte.ts:7-10`) has only `info`/`loading`, no `error`; `AppInfoData` (`types.ts:171-178`) requires `version: string`, `toolCount: number | null` and `mcpSdkVersion: string` alongside the optional `transport`/`bindPort` — a literal missing the required three or adding a stray `error` field fails `typecheck:tests`, which is a `check` gate, not an optional run. Set `appInfoCell = { info: { version: "0.0.0-test", toolCount: null, mcpSdkVersion: "0.0.0", transport: "http", bindPort: 3479 }, loading: false }` before `render()` in the port-hint case, first assert a positive control — the `Loopback Port` label or the `3479` value is present in the DOM — then assert `container.textContent` does not contain `tandem start --port`, and reset `appInfoCell` to its `info: null` default in the file-scope `afterEach` so the other cases keep rendering with `info: null`. A case rendered with `info: null` does not exercise this row at all and is not a valid instrument for the assertion.
2. `src/client/utils/sidecar-restart-toast.ts` (new, see Fix): unit-test `sidecarRestartFailedToast(push)` directly — no `App.svelte` mount required. Assert `action.label === "Open Log Folder"`; mock `@tauri-apps/api/path`'s `appLogDir` and `../cowork/cowork-invoke.js`'s `loadInvoke` (returning a mock `invoke`), call `action.onClick()`, and assert `invoke` was called with `("show_in_file_manager", { path: <appLogDir's resolved value> })`. **Add a second case for the catch path**: make `loadInvoke()` (or the mocked `invoke`) reject, call `action.onClick()`, `await` a microtask flush, and assert (a) the call does not reject out of `onClick` — no unhandled rejection — and (b) the mock `push` was called once with a notification whose `message` is exactly `"Couldn't open the log folder"`. This is the desktop-only unit coverage the wave-table note asks for; note in the PR body that it substitutes for Playwright, which never runs under Tauri.
3. **`tests/client/app-action-mount-contract.test.ts`** (new `it`, using the file's existing `prepare`/`readFileSync`/`ROOT` source-text helpers — see `:361-374` for the pattern this mirrors): the three assertions must NOT all run over the same instrument. `prepare()` (`:104-116`, via `blankNonCode`, `:154-192`) blanks the *contents* of every quoted string inside a script span — "Sidecar failed to restart — see logs" is one such string, so `expect(prepare(source)).not.toMatch(/Sidecar failed to restart/)` passes today, against the **unfixed** file, and would keep passing against an implementation that adds `sidecarRestartFailedToast(` and calls it while leaving the old inline `notifications.push({ message: "Sidecar failed to restart — see logs" })` sitting right next to it. Split the instruments: run the two positive matches — `/sidecarRestartFailedToast\(/` and `/notifications\.push\(\s*notification\s*,\s*action\s*\)/` — against `prepare(source)` as written (both are identifier/call-shape matches, unaffected by string-blanking), but run the negative match against the **raw** source instead: `` expect(readFileSync(APP_SVELTE, "utf-8")).not.toMatch(/Sidecar failed to restart/); `` — the file already reads `App.svelte` raw at `:252` for a different check, so the instrument already exists in this file. Without a raw-source negative, this item is non-discriminating and an implementation could satisfy every other item in this list while the shipped toast never changes.
4. `tests/client/notification-dedup.test.ts:51`'s `makeNotification` default `message: "Sidecar failed to restart — see logs"` is unpinned decorative fixture text (no assertion reads it) — leave it; changing it is optional polish, not required by any test.

## Done when

Button text, docs, and the failure toast all say "Restart server"/"Tandem server"; the toast carries a working "Open Log Folder" action backed by the new `sidecar-restart-toast.ts` module and its own unit test (including the catch-path case); `openLogFolder`'s failure path is caught and surfaced via `push`, never left as an unhandled rejection or a silently-dead button; the port-hint test renders the row via a positive `isHttp: true` control (set through the converted mutable-cell `createAppInfo` mock) before asserting the hint's absence; the new `app-action-mount-contract.test.ts` case pins that `App.svelte` actually calls `sidecarRestartFailedToast` and passes both fields to `notifications.push` (asserted against `prepare(source)`), and its raw-source assertion (against `readFileSync(APP_SVELTE, "utf-8")`, not `prepare(...)`) confirms the old inline toast string is gone; the dead port-flag hint is gone; typecheck + `npm test` clean; new tests pass.

## Not in scope

Adding a real `tandem start --port` CLI flag (explicitly declined by the wave-table note); the cold-start "Server Error" dialog's own "Retry Server Start" button (`src-tauri/src/lib.rs:1767-1784`) — measured, not merely argued by scenario: `lib.rs:1759` already reads "Close this dialog, then use Settings → Network → Restart server" and `:1783`'s button is "Retry Server Start," so this third wave-table-named surface is already consistent with "Restart server" and needs no edit; `tests/client/notification-dedup.test.ts`'s fixture string (decorative, unpinned).

**Why Part 1 builds a small module instead of deleting the toast's dead clause**, unlike J2-1781 and Part 2 of this same spec, which both chose deletion for the same "on-screen instructions → dead end" defect class: the minimal fix — just dropping "— see logs" so the toast reads "Tandem server failed to restart" — would close the issue's literal complaint (no link) but leave the toast strictly worse than `SettingsAboutTab.svelte`'s existing "Open Log Folder" button for the identical failure, and #1818's own wave-table note asks for "one word everywhere," which the action label achieves directly. The module is small (one file, reusing an existing dynamic-import pattern) rather than a new framework, so it stays inside the wave-1 "minimal copy fix" lesson in spirit if not in line count. If a reviewer judges even this small a build out of scope for the wave, the fallback is the deletion-only fix: drop "— see logs" and stop there, accepting the toast has no action.
