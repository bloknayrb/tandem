# G4 — #1614 every `.svelte` component boundary in `tests/` is untyped

Branch `fix/typecheck-tests-three-configs-and-a-mock-idiom-that-check-nothing-1613` (one branch for
the whole group). Closes #1614 (both the cheap half and the broader half of its "Likely fix"). No `areas/*.md`
ledger row — non-review issue, `docs/plans/2026-09-06-open-issues-sweep.md:110`. Probe:
`npx svelte-check --tsconfig ./tsconfig.tests.client.json` against a tree where
`npm run typecheck:tests` exits 0.

## Problem

The mechanism holds; one anchor moved and every count understated. Svelte's ambient
`declare module '*.svelte'` is at `node_modules/svelte/types/index.d.ts:3319` (not `:3199` — a
dependency bump since filing; svelte 5.57.0) and is still prop-agnostic, so plain `tsc` resolves
`import Foo from "./Foo.svelte"` through it and never parses the component's `<script>` block.
Re-measured on `f6559305`: **152** component import sites (issue: 78) across **94** test files
(issue: 60), and 5 `.svelte.ts` rune modules under `tests/helpers/` (which *are* typechecked, by
the client config).

**The issue's "no drift today — the hazard is structural, not present" is true of the three
harnesses and false of the wider surface.** All three re-declarations still agree with production.
But pointing `svelte-check` at the existing `tsconfig.tests.client.json` reports **3 errors, 0
warnings, in 2 files**, while `npm run typecheck:tests` exits 0 on the same tree — so these are
live, and nothing in CI can see them:

- `tests/client/MarginColumn.import-author.test.ts:36` and `:84` — both `render(MarginColumn, …)`
  calls omit `mode`, a **required** prop (`src/client/panels/MarginColumn.svelte:38`,
  `MarginMode = "full" | "narrow" | "stub" | "off"`). The prop was added after the test.
- `tests/client/settings-models-tab.test.ts:64` — `render(SettingsModelsTab, { props: { readOnly:
  false } })` is missing the other five members of `SettingsTabContext`
  (`SettingsModal.svelte:20-33`).

Neither is a production bug: both components read only the fields the tests supply, which is why
all 65 of those tests pass. They are stale test call sites — the shape #1614 predicted.

**No new tsconfig is needed, which the issue did not know.** `tsconfig.tests.client.json`'s
include set is already exactly the right one (`src/client`, `src/shared`,
`src/server/express.d.ts`, `tests/client`, `tests/design-system-impl`, `tests/helpers`), and
`src/server/express.d.ts` is what keeps ~29 spurious TS7016s out. Measured cost of adding it:
**16 s**.

## Fix

1. **`package.json`** — `typecheck:tests` gains a fourth command:
   `&& svelte-check --tsconfig ./tsconfig.tests.client.json --fail-on-warnings`. `--fail-on-warnings`
   matches the production `typecheck` script and is free today (0 warnings measured).
2. **`tests/scripts/typecheck-tests-wiring.test.ts`** — the `SCRIPT` constant is pinned by **exact
   equality**, so it must be updated in the same commit or `check` goes red. That pin is
   deliberate (#1229) — update it, never relax it to `toContain`. Nothing else in the file changes:
   the `ci.yml` step's body is still `npm run typecheck:tests`, and `configsCiInvokes()` skips the
   new command because it matches neither the `tsc` regex nor `typecheck:tests` — verify that
   holds rather than assuming it.
3. **The two hand-copied declarations** (the issue's cheap, independent half):
   - `tests/client/fixtures/PendingUpdateBannerHarness.svelte:14-18` — drop the local `Props` and
     annotate `$props()` as `ComponentProps<typeof PendingUpdateBanner>`.
   - `tests/client/fixtures/SourceViewCommandRegistryHarness.svelte:5-9` — drop the local
     `SourceCommands` and derive it:
     `NonNullable<Parameters<ComponentProps<typeof SourceView>["onCommandsChange"]>[1]>`. Its own
     `Props` (`documentId`, `ydoc`) is a harness-local shape, not a copy of production — leave it.
   - **Why derived rather than an import: neither production type is exported, and neither can
     be.** `SourceViewCommands` (`SourceView.svelte:40`) and `Props`
     (`PendingUpdateBanner.svelte:25`) are bare `interface` declarations inside
     `<script lang="ts">`, and Svelte 5 can only export a type from a `<script module>` block
     (the `SettingsTabContext` precedent, `SettingsModal.svelte:1-20`). `ComponentProps` needs no
     production change. **Probed: both edits compile, still 3 errors / 0 warnings, no new ones.**
   - Constraint that bites: a **named type import from a `.svelte` file is legal only inside
     another `.svelte` file** here — `tsc` still resolves `.ts` files through the ambient
     declaration, which exports only a default. `tests/client/settings-about-tab-cli-vocabulary.test.ts:50-56`
     documents this and works around it with a local shape; do not "tidy" that into an import.
4. **The three drift fixes** — add `mode: "full"` to both `render(MarginColumn, …)` calls; give
   `settings-models-tab.test.ts` a full context in the shape of that same file's `makeProps`
   (`open: true`, `settings: {} as TandemSettings`, `onUpdate: vi.fn()`, `connected: true`,
   `reconnectAttempts: 0`, `readOnly: false`).
5. **Docs** — `CLAUDE.md:215` ("Three configs now own it") and `docs/cli.md:199` ("three configs")
   both become stale; add svelte-check to each sentence. `CLAUDE.md` overlaps wave 10's G11 — keep
   the edit to the one clause.

## Tests

1. **Mutation, per drift fix.** Remove `mode: "full"` again (restore from a file copy, never
