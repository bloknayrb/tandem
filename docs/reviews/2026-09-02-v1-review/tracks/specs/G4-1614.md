# G4 — #1614 every `.svelte` component boundary in `tests/` is untyped

Branch `fix/typecheck-tests-three-configs-and-a-mock-idiom-that-check-nothing-1613` (one branch for
the group). Closes #1614 if the whole of it lands — see Boundary. Non-review issue,
`docs/plans/2026-09-06-open-issues-sweep.md:110`. Probe:
`npx svelte-check --tsconfig ./tsconfig.tests.client.json` against a tree where
`npm run typecheck:tests` exits 0.

## Problem

The mechanism holds; one anchor moved and every count understated. Svelte's ambient
`declare module '*.svelte'` is at `node_modules/svelte/types/index.d.ts:3319` (not `:3199` — a
dependency bump; svelte 5.57.0) and is still prop-agnostic, so plain `tsc` resolves
`import Foo from "./Foo.svelte"` through it and never reads the component's `<script>` block.
Re-measured on `f6559305`: **152** component import sites (issue: 78) across **94** test files
(issue: 60).

**The issue's "no drift today — the hazard is structural, not present" is true of the three harnesses
and false of the wider surface.** All three re-declarations still agree with production. But pointing
`svelte-check` at `tsconfig.tests.client.json` reports **3 errors, 0 warnings, in 2 files** while
`npm run typecheck:tests` exits 0 on the same tree: `tests/client/MarginColumn.import-author.test.ts:36`
and `:84` omit `mode`, a **required** prop (`src/client/panels/MarginColumn.svelte:38`) added after
the test; `tests/client/settings-models-tab.test.ts:64` is missing the other five members of
`SettingsTabContext` (`SettingsModal.svelte:20-33`). Neither is a production bug — both components
read only the fields the tests supply, which is why all 65 of those tests pass. Stale call sites, the
shape #1614 predicted.

**No new tsconfig is needed, but the existing one's `include` SHAPE has to change.**
`tsconfig.tests.client.json`'s include *set* is already right, and `src/server/express.d.ts` is what
keeps ~29 spurious TS7016s out. But every entry is a `**/*.ts` **suffix** glob, so **no `.svelte` file
is in the program at all.** Measured here with
`ts.parseJsonConfigFileContent(…, extraFileExtensions: [".svelte"])`:

| include form | plain `tsc` files | svelte-aware files | `.svelte` | `fixtures/*.svelte` |
|---|---|---|---|---|
| current (`**/*.ts` globs) | 559 | 559 | **0** | **0** |
| directory form | **559** | 669 | **110** | **7 of 7** |

The config's own KNOWN GAP comment already says so. Nothing announces it either: svelte-check
suppresses its `NO_SVELTE_INPUT` warning for any config whose basename is not
`tsconfig.json`/`jsconfig.json`, so `--fail-on-warnings` stays silent on a zero-`.svelte` program. The
3 errors above fire only because they sit at `.ts` call sites reading a component's props as a
*dependency* — **a diagnostic located inside a `.svelte` file cannot fire under the current include.**
