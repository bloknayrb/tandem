# G4 — #1614 every `.svelte` component boundary in `tests/` is untyped

Branch `fix/typecheck-tests-three-configs-and-a-mock-idiom-that-check-nothing-1613` (one branch for
the whole group). Closes #1614 (both the cheap half and the broader half of its "Likely fix"). No `areas/*.md`
ledger row — non-review issue, `docs/plans/2026-09-06-open-issues-sweep.md:110`. Probe:
`npx svelte-check --tsconfig ./tsconfig.tests.client.json` against a tree where
`npm run typecheck:tests` exits 0.

## Problem

The mechanism holds; one anchor moved and every count understated. Svelte's ambient
`declare module '*.svelte'` is at `node_modules/svelte/types/index.d.ts:3319` (not `:3199` — a
dependency bump since filing; svelte 5.57.0) and is still prop-agnostic, so plain `tsc` resolves
`import Foo from "./Foo.svelte"` through it and never parses the component's `<script>` block.
Re-measured on `f6559305`: **152** component import sites (issue: 78) across **94** test files
(issue: 60), and 5 `.svelte.ts` rune modules under `tests/helpers/` (which *are* typechecked, by
the client config).

**The issue's "no drift today — the hazard is structural, not present" is true of the three
harnesses and false of the wider surface.** All three re-declarations still agree with production.
But pointing `svelte-check` at the existing `tsconfig.tests.client.json` reports **3 errors, 0
warnings, in 2 files**, while `npm run typecheck:tests` exits 0 on the same tree — so these are
live, and nothing in CI can see them:

- `tests/client/MarginColumn.import-author.test.ts:36` and `:84` — both `render(MarginColumn, …)`
  calls omit `mode`, a **required** prop (`src/client/panels/MarginColumn.svelte:38`,
  `MarginMode = "full" | "narrow" | "stub" | "off"`). The prop was added after the test.
- `tests/client/settings-models-tab.test.ts:64` — `render(SettingsModelsTab, { props: { readOnly:
  false } })` is missing the other five members of `SettingsTabContext`
  (`SettingsModal.svelte:20-33`).

Neither is a production bug: both components read only the fields the tests supply, which is why
all 65 of those tests pass. They are stale test call sites — the shape #1614 predicted.

**No new tsconfig is needed, which the issue did not know — but the existing one's `include`
SHAPE has to change, which the first draft of this spec missed.** `tsconfig.tests.client.json`'s
include *set* is already the right one (`src/client`, `src/shared`, `src/server/express.d.ts`,
`tests/client`, `tests/design-system-impl`, `tests/helpers`), and `src/server/express.d.ts` is what
keeps ~29 spurious TS7016s out. But every entry is a `**/*.ts` **suffix** glob, so **no `.svelte`
file is in the program at all.** Measured on this worktree with
`ts.parseJsonConfigFileContent(…, extraFileExtensions: [".svelte"])`:

| include form | total files | `.svelte` | `tests/client/fixtures/*.svelte` |
|---|---|---|---|
| current (`**/*.ts` globs), plain `tsc` | 559 | 0 | 0 |
| current, svelte-aware parse | 559 | **0** | **0** |
| directory form, plain `tsc` | **559** | 0 | 0 |
| directory form, svelte-aware parse | 669 | **110** | **7 of 7** |

The config's own comment already says this ("The three harness components under
`tests/client/fixtures/` are therefore NOT typechecked by this config"). Nothing announces the gap
either: svelte-check's `checkSvelteInput` suppresses its `NO_SVELTE_INPUT` warning for any config
whose basename is not `tsconfig.json`/`jsconfig.json`, so `--fail-on-warnings` stays silent on a
zero-`.svelte` program. The 3 real errors below still fire because they are diagnostics at `.ts`
call sites that read a component's props as a *dependency* — **a diagnostic located inside a
`.svelte` file cannot fire at all under the current include.** So without the shape change, this
spec's Test 2 (the harness mutation) could not go red and Fix 3's harness derivation would be
unenforced.

## Fix

0. **`tsconfig.tests.client.json`** — change `include` from suffix globs to **directory form**:
   `["src/client", "src/shared", "src/server/express.d.ts", "tests/client",
   "tests/design-system-impl", "tests/helpers"]`. This is the edit that puts the 7 harness
   components in the program (table above); plain `tsc` resolves the identical **559** files either
   way, so the three `tsc` legs are byte-identical in coverage and the change is free to them.
   **No guard edit is needed:** `typecheck-tests-wiring.test.ts`'s suffix-glob assertion skips any
   pattern containing no `*` (`if (!pattern.includes("*")) continue;`), so directory entries are
   already legal — it is the same shape `tsconfig.client.json` uses. Update that config's **KNOWN
   GAP** comment in the same edit: it currently states the fixtures are not typechecked and that
   only `--tsconfig ./tsconfig.client.json` would cover them, and both halves become false.
   *Verify, do not assume:* re-run the orphan sweep and the whole
   `typecheck-tests-wiring.test.ts` suite after the change.
1. **`package.json`** — `typecheck:tests` gains a fourth command:
   `&& svelte-check --tsconfig ./tsconfig.tests.client.json --fail-on-warnings`. `--fail-on-warnings`
   matches the production `typecheck` script and is free today (0 warnings measured).
   **Coordinate before editing:** D3 (#1941) runs concurrently and `package.json` is the named
   overlap — confirm with the orchestrator first, and keep the edit to the single `typecheck:tests`
   value so any conflict is one line.
   **Record the measurement, do not inherit it:** after item 0 lands, run
   `npx svelte-check --tsconfig ./tsconfig.tests.client.json --fail-on-warnings --output machine`
   and put the `COMPLETED … FILES … ERRORS … WARNINGS` line in the PR body. Directory form newly
   pulls ~103 `src/client/**/*.svelte` components into this run, duplicating the production
   `--tsconfig ./tsconfig.client.json` pass (measured clean: 1196 files, 0 errors, 0 warnings), so
   the added CI time and the zero-warning claim must both be measured post-change.
2. **`tests/scripts/typecheck-tests-wiring.test.ts`** — the `SCRIPT` constant is pinned by **exact
   equality**, so it must be updated in the same commit or `check` goes red. That pin is
   deliberate (#1229) — update it, never relax it to `toContain`. Nothing else in the file changes:
   the `ci.yml` step's body is still `npm run typecheck:tests`, and `configsCiInvokes()` skips the
   new command because it matches neither the `tsc` regex nor `typecheck:tests`. **The reason is
   structural and worth stating in the commit body** so the `SCRIPT` pin update is not mistaken for
   a wider guard change: `configsCiInvokes()` iterates `ci.yml`'s `job.steps` and matches each
   step's `run:` string; that body is still exactly `npm run typecheck:tests`, which takes the
   `run.includes("typecheck:tests")` branch and fans out to the three `TEST_CONFIGS`. It never
   reads `package.json` — only the exact-equality `SCRIPT` assertion does. Confirm by running the
   suite, not by reading.
3. **The two hand-copied declarations** (the issue's cheap, independent half):
   - `tests/client/fixtures/PendingUpdateBannerHarness.svelte:14-18` — drop the local `Props` and
     annotate `$props()` as `ComponentProps<typeof PendingUpdateBanner>`.
   - `tests/client/fixtures/SourceViewCommandRegistryHarness.svelte:5-9` — drop the local
     `SourceCommands` and derive it:
     `NonNullable<Parameters<ComponentProps<typeof SourceView>["onCommandsChange"]>[1]>`. Its own
     `Props` (`documentId`, `ydoc`) is a harness-local shape, not a copy of production — leave it.
   - **Why derived rather than an import: neither production type is exported, and neither can
     be.** `SourceViewCommands` (`SourceView.svelte:40`) and `Props`
     (`PendingUpdateBanner.svelte:25`) are bare `interface` declarations inside
     `<script lang="ts">`, and Svelte 5 can only export a type from a `<script module>` block
     (the `SettingsTabContext` precedent, `SettingsModal.svelte:1-20`). `ComponentProps` needs no
     production change. **Probed: both edits compile, still 3 errors / 0 warnings, no new ones.**
   - Constraint that bites: a **named type import from a `.svelte` file is legal only inside
     another `.svelte` file** here — `tsc` still resolves `.ts` files through the ambient
     declaration, which exports only a default. `tests/client/settings-about-tab-cli-vocabulary.test.ts:50-56`
     documents this and works around it with a local shape; do not "tidy" that into an import.
4. **The three drift fixes** — add `mode: "full"` to both `render(MarginColumn, …)` calls; give
   `settings-models-tab.test.ts` a full context in the shape of that same file's `makeProps`
   (`open: true`, `settings: {} as TandemSettings`, `onUpdate: vi.fn()`, `connected: true`,
   `reconnectAttempts: 0`, `readOnly: false`).
5. **Docs** — `CLAUDE.md:215` ("Three configs now own it") and `docs/cli.md` (the
   `npm run typecheck:tests` row, "three configs (`tsconfig.tests.{node,client,e2e}.json`)") both
   become stale; add svelte-check to each sentence. `CLAUDE.md` overlaps wave 10's G11 — keep the
   edit to the one clause. **G4-1613 item 5 rewrites the final clause of the SAME `CLAUDE.md`
   bullet** (the `tests/tauri-driver` sentence). #1613's commit lands first and this edit is applied
   on top of it, so the two are sequential edits to one paragraph rather than a conflict.

## Boundary

**Coverage of `.svelte` files is by CONFIG after item 0, and the fixtures are in the program
directly — but state the residual shape anyway.** With directory-form includes, all 7
`tests/client/fixtures/*.svelte` and ~103 `src/client` components resolve into the svelte-check
program, so an orphan fixture that no `.ts` imports is still checked. What remains outside is any
`.svelte` under a directory in **no** config; the orphan sweep in `typecheck-tests-wiring.test.ts`
walks `.ts/.mts/.cts/.tsx` only, so it cannot see a stray `.svelte`. That is accepted and stated
rather than guarded: adding `.svelte` to the sweep is a separate change and buys nothing today.

**If svelte-check surfaces more than can be cleared cleanly in this PR**, land item 0 + the script
wiring + the errors actually fixed, and **file the remainder as a tracked issue BEFORE writing the
PR body**, with its number in the body — and in the same edit move #1614 from `Closes` to `Refs`,
so the returned `closes[]` is derived from what was filed rather than from intent. Do not disable
the check to make it green.
