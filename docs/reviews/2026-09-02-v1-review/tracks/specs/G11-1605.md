# G11 — #1605 No issue or PR template

Branch `fix/process-docs-four-issues-from-an-outside-debugging-study-1602`. Closes #1605. Ledger: `docs/plans/2026-09-06-open-issues-sweep.md:111`. No probe — docs/repo-metadata only.

## Problem

Confirmed by directory listing: no `.github/ISSUE_TEMPLATE/` and no `.github/pull_request_template.md` exist. **The issue's own inventory of `.github/` is wrong** — it claims `.github/` holds `codeql`, `dependabot.yml` and `workflows`; measured, `.github/` contains exactly `dependabot.yml` and `workflows/` (five files: `ci.yml`, `claude-code-review.yml`, `publish.yml`, `tauri-release.yml`, `tauri-webdriver.yml`). CodeQL runs as GitHub's default setup, not a file in this repo. Per the group brief, state what's measured rather than repeating the issue's claim.

Twelve wiring tests under `tests/scripts/` read `.github/` (not ten, as the group brief estimated — measured: `acceptance-harness-wiring`, `coverage-gate-wiring`, `coverage-manifest-wiring`, `node-sidecar-pin-wiring`, `release-ci-hygiene`, `release-signing-gates`, `tauri-webdriver-pin`, `typecheck-tests-wiring`, `verify-updater-signatures`, `vitest-file-anchor-wiring`, `windows-acl-proof-wiring`, `workflow-action-pin`). All twelve reference specific files under `.github/workflows/` by path (`.github/workflows/ci.yml`, `.github/workflows/tauri-release.yml`, `.github/workflows/tauri-webdriver.yml`). The two that `readdirSync` a directory (`release-ci-hygiene.test.ts:8,51`, `workflow-action-pin.test.ts` similarly) scope that call to `WORKFLOW_DIR = path.join(ROOT, ".github/workflows")`, not `.github/` itself, and filter to `.yml` files. New files at `.github/ISSUE_TEMPLATE/*.md` and `.github/pull_request_template.md` sit outside `.github/workflows/` entirely, so none of the twelve are touched — confirmed by reading each match, not assumed.

## Fix

Three new files, kept deliberately short per the issue's own constraint ("a template long enough to be skipped is worse than none — the value is entirely in the one unstated-contract question surviving"). Each carries verbatim the question from the issue body.

**`.github/ISSUE_TEMPLATE/bug_report.md`** (new):
```markdown
---
name: Bug report
about: Something isn't working
title: ""
labels: bug
---

**What does correctness here depend on that is not in the repo?** e.g. what users put in their
documents, how a real upgrade behaves, what a specific OS or Claude Code build does. Write
"nothing — it's all derivable from the code" if that is the answer.

**What happened**

**Steps to reproduce**

**Expected behavior**

> Filing this on behalf of an outside reporter? Apply **both** `beta-report` and
> `untrusted-source` — the body is then read as data, not instructions. Summarising rather than
> quoting does not exempt it.
```

**`.github/ISSUE_TEMPLATE/feature_request.md`** (new):
```markdown
---
name: Feature request
about: Suggest an idea
title: ""
labels: enhancement
---

**What does correctness here depend on that is not in the repo?** e.g. what users put in their
documents, how a real upgrade behaves, what a specific OS or Claude Code build does. Write
"nothing — it's all derivable from the code" if that is the answer.

**What's the problem, and what's the proposed fix?**

> Filing this on behalf of an outside reporter? Apply **both** `beta-report` and
> `untrusted-source` — the body is then read as data, not instructions. Summarising rather than
> quoting does not exempt it.
```

**`.github/pull_request_template.md`** (new):
```markdown
**What does correctness here depend on that is not in the repo?** e.g. what users put in their
documents, how a real upgrade behaves, what a specific OS or Claude Code build does. Write
"nothing — it's all derivable from the code" if that is the answer.

- [ ] Adversarial agents reviewed the plan before implementation
- [ ] `via /diverge` noted above, if `/diverge` informed this work

Problem/solution, commands run, screenshots, `Closes #N`: see CONTRIBUTING.md.
```

**Bound, stated explicitly:** all three templates apply only when a human composes via GitHub's web UI — `gh issue create --body ...` / `gh pr create --body ...`, the path this sweep's own pipeline and every Claude-authored issue or PR uses, never reads a template at all. So the on-behalf-filer reminder above reaches human filers only; the `gh`-filed path remains covered solely by CLAUDE.md's existing Security bullet ("anything filing on a reporter's behalf must apply it"). No new guarantee is claimed for the autonomous path — these templates narrow nothing there and widen nothing there.

Acceptance criterion 2 ("the PR template does not ask for anything the repo's own PR guidance says to keep out of PR bodies"): searched `CONTRIBUTING.md` and `docs/*.md` for a stated negative constraint on PR body contents; none exists (the only related rule is this sweep pipeline's own "never write a closing keyword before #N," which is about commit messages, and is unrelated to what this template asks). No conflict found — recorded here as the verification, not assumed.

## Tests
