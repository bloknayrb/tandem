## Problem

In `spawnOnce` (`src/server/launcher/supervisor.ts`), the failed-write callback inside `sendTurn` (:1055) runs `clearLatch(); pendingWake = true;`. `teardownTurnDelivery` (:1121) promotes the flag with `if (pendingWake) wakeOwedAcrossSpawns = true` (:1125). When teardown runs first, the late callback sets `pendingWake` inside a dead closure. The next spawn reads only `wakeOwedAcrossSpawns` (:1161), so the wake is lost.

Criterion 5 ("no carried wake after an explicit user stop") has no implementation today either. `stop()` (:1566) is `withLock(() => stopInternal())`, and it tears the child down through the same promotion.

## Fix (all in `supervisor.ts`)

Semantics: an explicit `stop()` carries no wake to a later spawn. `relaunch()` and `startFresh()` are recovery. They carry an owed wake, whether a crash owed it or it is pending on the live child they replace. Dropping it there would be #1866's own symptom.

1. Add a supervisor-level `let userStopped = false;` beside `stopRequested` (:579). Only the public `stop()` raises it. `startInternal` (:1422) and `respawn` (:1490) lower it next to their `stopRequested = false`. `stop()` becomes `withLock(async () => { userStopped = true; wakeOwedAcrossSpawns = false; await stopInternal(); })`. The clear goes in `stop()`, **not** in `stopInternal`. `respawn` calls `stopInternal` first (:1482), so a clear there would drop a crash-owed wake on every Restart.
2. Per spawn, beside `pendingWake`, add `let tornDown = false; let carryOwedWake = true;`. `teardownTurnDelivery` begins with `if (!tornDown) { tornDown = true; carryOwedWake = !userStopped; }`, and its promotion becomes `if (pendingWake && carryOwedWake) wakeOwedAcrossSpawns = true;`.
3. The write callback becomes `clearLatch(); if (tornDown) { if (carryOwedWake) wakeOwedAcrossSpawns = true; } else { pendingWake = true; }`. It touches only its own closure and one supervisor-level boolean, never `child` or any stdin (criterion 3). Because the flag is a boolean, N late callbacks, or a callback plus the stream `'error'`, still make one wake. `onTandemEvent` and `flushPendingWake` are untouched (criterion 4).
4. In the `sendTurn` docblock, replace "strands it (pre-existing, #1866 follow-up)" with a description of the latch and its bounded cost. A callback that lands after a successor consumed the flag sets it again, so the worst case is one extra payload-free wake, never a lost one.

Critical Rule 3 applies: log only via `console.error`. Keep the `child === spawned` identity-guard convention.

## Shared test harness

New file: `tests/server/launcher/supervisor-turn-delivery.test.ts`. It has to be a new file because `vi.mock` of `node:child_process` applies to the whole file. G1-1868, G1-1867 and G1-1780 add their tests to it. The harness must behave exactly like this:

- `vi.mock("node:child_process", async (importOriginal) => ({ ...(await importOriginal()), spawn: vi.fn() }))`. Spread the original: on win32, `integrations/storage.ts` → `acl-win.ts` imports `execFile`.
- **Fake child.** An `EventEmitter` with `pid`, `exitCode = null`, `signalCode = null` and `killed = false`. `spawn` is emitted on `setImmediate`.
  - `kill(sig)` sets `killed = true` synchronously and returns `true`.
  - On `setImmediate`, unless `exitCode`/`signalCode` is already set, it sets `signalCode = sig` and emits `exit(null, sig)`.
  - Neither step may be synchronous. Real Node sets `signalCode` only at exit. `stopInternal` calls `c.kill` before it registers `c.once("exit")`, so a synchronous emit would be missed and every `stop()` would wait out the grace timers.
- `exitChild(child, code, signal = null)` sets the fields and emits `exit`. It is for crashes the supervisor did not cause.
- **Fake stdin.** An `EventEmitter` that keeps its listeners, so the `'error'` listener from `attachChildStreamErrorHandlers` is live. It has a mutable `writable = true`, and `write(data, cb) { writes.push({ data, cb }); return true; }` holds every callback.
- `failWrite(child, entries = all held)` sets `stdin.writable = false`, runs each `cb(EPIPE)`, then `setImmediate(() => stdin.emit("error", EPIPE))`. That is the order recorded in the `attachChildStreamErrorHandlers` docblock. `failCallbacksOnly(entries)` runs the callbacks and emits no stream error.
- **Environment.**
  - `stdout` and `stderr` are `PassThrough`, and `TANDEM_REAPER_PATH = process.execPath`.
  - The integrations file is real, under `fs.mkdtempSync(path.join(os.tmpdir(), "tandem-"))`.
  - `subscribeToEvents` and `probeCliUsable` are injected (`probeCliUsable` defaults to `() => true`), and `restartBackoffsMs` is `[0]` unless a test says otherwise.
  - `afterEach` awaits `sup.stop()` and removes the temp dir.
- **Fresh vs resumed** follows the real session file. A fresh spawn persists its id, a signal exit keeps it, and `exitChild(resumed, 1)` inside `RESUME_CONFIRM_MS` clears it (`shouldClearSession`, :294).

## Tests

1. **Teardown before the callback → exactly one wake.** `startFresh(dir)` gives child 1, with bootstrap write B held. Push a `result`, then emit an annotation event → W1, held. In one synchronous block, call `exitChild(child1, 1)` and then `failCallbacksOnly([B, W1])`. Child 2 (resumed) writes exactly `[SUPERVISOR_WAKE_PROMPT]`. *Kills* the unfixed callback (0 writes) and a queue (2 writes).
2. **Callback before teardown is unchanged.** Same flow, but `failCallbacksOnly([W1])` runs before `exitChild`. Child 2 writes `[WAKE]`. *Kills* deleting the teardown promotion.
3. **A stale callback cannot reach the successor (a control).** Test 1's flow, with B's callback held back. After child 2's `[WAKE]` is recorded, run `failCallbacksOnly([B])`. Child 1's writes are still `[B, W1]`, child 2's writes are still `[WAKE]`, and child 2's `kill` was not called. *Kills* a callback that calls `sendTurn` or `flushPendingWake`, or that touches `child`.
4. **User stop: a late callback carries nothing, even after `start()` has lowered the flags.** Child 1, a `result`, then an event → W1, held. `await sup.stop()`. Then call `sup.start()`. In the child-2 `spawn` mock, run `failCallbacksOnly([W1])` before returning the fake; that point is after `startInternal` lowered the flags and before the resumed branch reads the wake flag. Child 2 writes `[]`. Use `start()`, not `relaunch()`: `respawn` → `stopInternal` would mask the mutants. *Kills* a callback that ignores `carryOwedWake`, and one that reads the live `userStopped`.
5. **User stop: a wake pending at teardown is not promoted.** Child 1, a `result`, an event → W1, then `failCallbacksOnly([W1])` while child 1 is alive. `await sup.stop()`, then `await sup.start()`. Child 2 writes `[]`. *Kills* a teardown promotion that ignores the latch.
6. **User stop drops a wake owed by a crash.** Use `restartBackoffsMs: [5_000]`. Child 1, a `result`, an event → W1, `failCallbacksOnly([W1])`, then `exitChild(child1, 1)`. `await sup.stop()`, then `await sup.start()`. Child 2 writes `[]`. *Kills* deleting the clear in `stop()`.
7. **Relaunch keeps a wake owed by a crash.** Test 6's crash, then `await sup.relaunch(dir)`. Child 2 writes `[WAKE]`. *Kills* moving the clear into `stopInternal`.
8. **Relaunch keeps a wake pending on the live child.** Test 5's setup, then `await sup.relaunch(dir)`. Child 2 writes `[WAKE]`. *Kills* latching on `stopRequested` instead of `userStopped`.
9. The existing cases in `stream-json-protocol.test.ts` at :449, :509 and :701 (crash carry, coalescing, and failed wake write) stay green unchanged.
