# H-b — #1786 the "You're up to date forever" failure has no detector: the update Worker's `reason` is logged to a store nobody retains, and nothing tells a human

Branch `fix/issuance-worker-hardening-and-a-detector-for-the-silent-no-update-failure-1793`. **Closes #1786.** Ledger: `areas/infra-license-worker.md` row 2, `areas/armed-license-gate.md:20`. Probe: `npx vitest run tests/server/license-update-worker.test.ts`. **Code only, NO DEPLOY** — the detector is **merged but inert** until Bryan redeploys both Workers with `[observability]` and sets `ALERT_WEBHOOK_URL`; both flip consts stay dark. Rebased onto `52fa195c` (H-a, PR #1940).

## Problem

The mechanism is established and not re-derived: `build_updater`'s `.endpoints()` **replaces** the manifest list rather than falling back, so a licensed install whose `LICENSE_KV` entry is gone gets a 204, `tauri-plugin-updater` early-returns `Ok(None)`, and the app says "You're up to date" forever while starved. `docs/licensing-operations.md:250-252` lists five ways in.

`CLAUDE.md:244`, `docs/licensing-explained.md:514-515`, `docs/licensing-operations.md:252-253`, `docs/security.md:181` and `infra/license-update-worker/src/worker.ts:19-30` (the docblock of the type being changed) all call the `reason` enum the only detector. It is not one:

- **Nothing retains it.** `worker.ts:147` is a bare `console.log`; neither `wrangler.toml` has `[observability]`, so the lines are kept nowhere. The only reader is `wrangler tail`, which the runbook itself (§5c) calls *"a debugging tool, not an alert"*.
- **Nothing notifies.** The update Worker has no `ALERT_*` wiring at all; the issuance Worker has the whole plumbing (`worker.ts:845-945`).

**A detector reaches a human without a user reporting it.** Retention alone is not one — it makes evidence readable after someone already suspects. Both halves are needed.

**Two measurements that change the design.**

1. **`unknown-id` is NOT "structurally zero in health".** `applyRefund` (`infra/license-issuance-worker/src/worker.ts:434`) deletes the entitlement while the offline blob still verifies, and §7's revocation procedure deletes the same key by hand. After H-a, `update_route` returns `Licensed(id)` whenever `probe.license_id` is present *regardless of window*, so a refunded or revoked install keeps sending `X-Tandem-License-Id` on every check for the life of the blob. Alerting on that pages the operator for their own deliberate action, forever — and a muted channel detects nothing.
2. **`unknown-id` is reachable by any unauthenticated caller.** `worker.ts:97-101` reads the header and does one KV `get` — no signature, no shape check — and `wrangler.toml:16-18` leaves `[[routes]]` commented out, so the Worker is on a public `*.workers.dev` host. Scanner traffic would page on a healthy system, and a low-rate flood holds the throttle slot and suppresses the genuine event.

**What H-a already did, and must not be rebuilt.** H-a (#1785) added `UpdateRoute::NoUpdates(WithheldReason)` and `show_update_withheld_dialog`, covering what the *device* can see (restricted, unreachable probe). Its own spec hands over the residue: *"a `Licensed` device whose Worker-side entitlement has lapsed receives a 204 from the Worker and is still told 'up to date'. The client genuinely cannot distinguish that."* That is this issue's case, and it is the Worker's to detect.

**The issue's client-side suggestion is not implementable as written.** It asks the licensed app to "record the last successful licensed check and warn after N days". There is no such observable: `updater.check()` collapses a 204 (no entitlement) and a 200 whose manifest is not newer (perfect health) into the same `Ok(None)`, and the plugin exposes neither status nor headers. Distinguishing them needs a second, parallel updater request. The other client surface the issue names — the Settings warning keyed on local `updateWindowCurrent` — is license UX copy owned by **H-c (#1789 #1819)**. So this group fixes the Worker halves and records both boundaries.

## Fix

### Make deliberate removal distinguishable from loss

Without this the alert is a pager, not a detector. A refund and a revocation are the operator's own action; an entitlement that vanished is not. Today both are an absent key.

- **`applyRefund` (`infra/license-issuance-worker/src/worker.ts:433-438`) writes a tombstone instead of deleting.** `await deps.entitlementKv.delete(rec.licenseId)` becomes a `put` of `{"updateWindowEnd": null, "status": "revoked"}`. **The guard is unchanged and the `put` sits INSIDE it** — the line is `if (!deps.isTest && rec.licenseId) …`; `rec.licenseId` is `""` on the refund-before-paid path, which is what that half skips. Rewrite the docblock (`:429-432`, "delete its entitlement") in the same edit, and add a matching assertion to the refund-outraces-paid case (`tests/server/license-issuance-worker.test.ts:686`), whose `entitlementKv.map.size === 0` is the only thing that would catch a tombstone written under an empty key.
- **Seven existing assertions in `tests/server/license-issuance-worker.test.ts` change with it** (`baseDeps` sets `isTest: false`, so the write really happens). Five read the post-refund key as **absent** and become the exact parsed value — `expect(JSON.parse(deps.entitlementKv.map.get(licenseId) as string)).toEqual({updateWindowEnd: null, status: "revoked"})` — at `:617`, `:652`, `:664`, `:669`, `:780`. Two already read it as **present** and stop discriminating (`:626`, `:640`, both `toBeDefined()`): strengthen them to the **live** value (`status: "personal"`, non-null `updateWindowEnd`). **Never `toBeDefined()`** — a tombstone satisfies it as readily as a resurrected live entitlement, which deletes what `:669` and `:780` exist to catch.
- **`infra/license-update-worker/src/worker.ts` gains a `"revoked"` member of `NoUpdateReason`**, returned when `entry.status === "revoked"`. **Placement is load-bearing: the check goes immediately after the JSON parse and BEFORE the `updateWindowEnd` comparison** — `null updateWindowEnd` currently means *never expires (grandfathered)*, so a tombstone read by the window branch would **serve the manifest to a refunded customer**. Say that in the comment; it is the one way this change goes wrong. `"revoked"` is deliberately **not** alertable.
- **Stale comments in that file change in the same edit:** the two *"all five reasons / all five branches"* counts (`:19-21`, `:90-91`) become six; the "single detector … a rising `unknown-id` count is the only evidence" docblock (`:23-30`) gains the alert and its deployment precondition; `"THE alert-worthy one"` on `unknown-id` (`:35`) now that `unparseable` is alertable too. Add one sentence to the lockstep docblock (`:66-76`): the namespace now holds entitlements **and** revocation tombstones, and a tombstone is deliberately not a `LicenseEntitlement` — only `applyRefund` and the hand-run §7/§9 `kv key put` write one.
- **`docs/licensing-operations.md` §7 and §9.** §7 says "delete" in two places — the revocation bullet (`:521-524`) and the refund clause (`:514`) — and §9's quick-reference row (`:602`) is `kv key delete`, the most copy-pasted revocation path in the runbook. All three become a `kv key put` of the tombstone, with one sentence saying why: a deleted key is indistinguishable from a lost one and would page the operator for their own action forever. (`:602` is also #1793's wrangler-pin line — the two specs land one line, not two.) Three further prose clauses say "deletes the entitlement" and go stale: `docs/licensing-operations.md:248` and `docs/licensing-explained.md:510-511`, plus `applyRefund`'s docblock above.

### The retention half

- **Both `wrangler.toml` files** gain `[observability]` / `enabled = true`. The update one also gains a commented `# ALERT_WEBHOOK_URL = "REPLACE_WITH_INCOMING_WEBHOOK_URL"` under `[vars]`, worded like the issuance toml's `:32-40` block, with the note that an incoming-webhook URL is a bearer credential and `wrangler secret put ALERT_WEBHOOK_URL` is the safer form (`[vars]` is kept only to match the issuance precedent).
- **Say what retention costs — honestly, and only about what Tandem controls.** The update Worker's header (`:11-16`) records the invariant that the log line carries no license id, because per-customer update-check logs would be telemetry. That invariant is about **Tandem's own log line**, and it is the only half this change may assert. **Do not write anything about what Cloudflare's invocation record contains** — the license id travels in a request header (`:64`, `:97`), so an invocation record that carries request headers *is* the per-customer update history the invariant exists to prevent, and this group is `NO DEPLOY` by constraint and cannot measure it. Asserting it would be `CLAUDE.md`'s own *"do not read a gate as a guarantee"*, applied to a gate nobody has seen run.

  - `docs/licensing-terms.md` — the data-inventory row at `:96` (`| Update endpoint logs | {result, reason, ts} | No licence id, no IP recorded by us. |`) says that those lines are now retained by Tandem's own configuration; and the open question at `:110-112`, which quotes the `security.md` sentence this PR rewrites, is re-answered rather than left pointing at replaced text. Shipping without these two edits ships a tracked privacy doc asserting something this PR made untrue.
  - `docs/licensing-operations.md` §8 gains **one checklist line for Bryan**: verify against a real deployment what Cloudflare's retained invocation record holds; if it carries request headers it holds `X-Tandem-License-Id`, and the response is to drop `[observability]` on the update Worker or stop sending the id in a header. That is where an unverified operational fact belongs.

### The notification half

In `infra/license-update-worker/src/worker.ts`, mirror the issuance Worker's plumbing rather than inventing a shape — the two Workers are separate Cloudflare builds with no shared module, so say in a comment that the duplication is deliberate.

- Add the local `ExecutionContext` interface and widen `export default { fetch }` to `(request, env, ctx?)`; `ctx` optional so the two-arg harness still calls it. `WorkerEnv` gains `ALERT_WEBHOOK_URL?: string`. **No `ALERT_EMAIL`** — no Resend binding here, and adding one gives the update endpoint a reason to hold a mail secret.
- `export function isAlertable(entry)` → `reason === "unknown-id" || reason === "unparseable"`. Enumerated; the other four are the discriminating half — `no-header` is an ordinary unlicensed client, `expired` is expected and benign, `revoked` is the operator's own action, `upstream` is a GitHub-side blip that would storm.
- **A second precondition lives at the call site, not in `isAlertable`: the id must be UUID-shaped** (`/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i`), because the endpoint is unauthenticated. Both mint sites are UUIDs today — the issuance Worker's `globalThis.crypto.randomUUID()` and the out-of-band `scripts/sign-license.ts:142` — and the comment names both plus one sentence: a future non-UUID generator must stay UUID-shaped or the alert stops covering its cohort. Non-UUID input still **logs** `unknown-id`; it just never pages. **Record the residual** in that comment and in §5c: a UUID-shaped flood still reaches the channel and consumes the throttle slot. Do not add a KV counter for it.
- `shouldAlert(key, nowMs)` + `ALERT_THROTTLE_MS = 5 * 60 * 1000` + `_resetAlertThrottleForTests()`, copied from the issuance file's `:845-866`. **The key is built at the call site and this Worker's is different**: `` `${entry.result}:${entry.reason ?? "-"}` ``. Keying on `result` alone collapses `unknown-id` and `unparseable` into one slot — every no-update logs the same `"no-update"` — so an `unparseable` storm would suppress the genuine event. Test 6 discriminates it.
- `alertBody(entry)` carries `reason` and the repair pointer (`re-PUT the entitlement from the ledger`, `docs/licensing-operations.md §3` spelled in full — `tests/build/invariant-citations.test.ts:47` scans `infra`) and **nothing else**; the license id never enters it. `sendOperatorAlert(env, entry)` posts `{text: body}` to `ALERT_WEBHOOK_URL`, treats a non-ok response as failure (a retired Slack webhook 404s rather than throwing), and logs `{result: "alert-undeliverable", ts, reason}` when the channel is absent or exhausted so the consumed slot leaves a trace.
- Wire it in the `fetch` `log` callback — **not inside `handleUpdateRequest`**, which stays pure and I/O-injected — and hand the promise to `ctx.waitUntil` with `.catch(() => {})`. The alert must never delay the request or change the response bytes; `revoked` joins the byte-identical 204 unchanged.
- **Alert on occurrence, throttled — not on a rate.** The issue says "keyed on `unknown-id` rate". With the tombstone, `unknown-id` means *an entitlement we did not remove is gone*; a rate threshold could only add a way to miss the first one, and rate state on a stateless Worker means a KV counter. Recorded as an assumption.

## Tests

In `tests/server/license-update-worker.test.ts`, extending the `no-update reasons (the silent-failure detector)` suite (`:189`), with `beforeEach(_resetAlertThrottleForTests)`. **Two structural rules, neither visible to CI:**

- **Anything asserting about alerting must drive `default.fetch(request, env, ctx)`** with `ALERT_WEBHOOK_URL` set and a stubbed global `fetch` — items **2, 3, 5, 6, 7, 8 and the no-alert half of 9**. The suite's existing helper `reasonFor` (`:190-204`) calls `handleUpdateRequest` directly, which by design holds **no alert plumbing**, so a "does not alert" assertion written against it is green whatever the implementation does. `reasonFor` may carry only `reason` / status / body / manifest assertions: items 1, 4's comparison arm, 9's reason-and-not-served half, and 10.
- **Every pair of cases sharing a throttle key sits in its own `it()`** (or resets between them). `shouldAlert` returns false for 5 minutes on a repeated key and the reset is a `beforeEach` firing per `it()`, so a second case in the same block is suppressed — the stub is never called, and *"still returns 204"* and *"zero webhook POSTs"* both hold trivially. Item 5's two halves are the named instance.
- Every test asserting on `console.log` or `fetch` captures `ctx.waitUntil`'s argument and `await`s it first, except item 7's no-channel case, which is synchronous.

1. **`isAlertable` truth table.** True for `unknown-id` and `unparseable`; false for `no-header`, `expired`, `revoked`, `upstream` and `{result:"served"}`.
2. **Wiring.** Unknown **UUID-shaped** id → exactly one POST to the webhook; body contains `unknown-id`; **body does NOT contain the id that was sent** (the privacy pin).
3. **A non-UUID id logs but does not page.** `X-Tandem-License-Id: not-a-uuid` → 204, log line still `unknown-id`, **zero webhook POSTs**. The anti-flood pin.
4. **The response is unchanged by alerting.** 204, empty body, byte-identical to the same request with no `ALERT_WEBHOOK_URL`.
5. **A failing alert channel cannot fail the request. Two separate `it()` blocks** — both provoke `unknown-id` and share the key `no-update:unknown-id`. (a) webhook `fetch` **rejects** → still 204. (b) webhook `fetch` resolves **404** → still 204.
6. **Throttle, and the throttle KEY.** Two unknown-id requests in one isolate → one POST; after `_resetAlertThrottleForTests()`, a third → two. **The discriminating case:** one `unknown-id` then one `unparseable` in the same isolate with no reset → **two** POSTs. Without it, an implementation keying on `entry.result` alone passes everything else while collapsing the two alertable reasons into one slot.
7. **No channel configured → no alert fetch, and an `alert-undeliverable` log line.** Kills silently burning the throttle slot with no trace.
8. **`expired` does not alert** — the case an operator would otherwise be paged for on every out-of-window customer, forever. Through `default.fetch`: zero webhook POSTs.
9. **The tombstone, both halves.** (a) through `reasonFor`: `{updateWindowEnd: null, status: "revoked"}` → 204, reason `revoked`, and — the discriminating assertion — **not** a served manifest (a `revoked` check placed after the window comparison serves it as grandfathered). (b) through `default.fetch` with the webhook configured: **zero webhook POSTs**.
10. **The no-existence-oracle test learns the sixth reason.** `:245-265` hand-enumerates five results, asserts `new Set(...).size === 5` and one indistinguishable `${status}:${body}`. Add the tombstone row and bump to **6** — byte-identity is the privacy invariant this file is built around, and a new branch outside it is the one way `revoked` can leak an oracle.

Plus, in `tests/server/license-issuance-worker.test.ts`: the seven rewritten assertions enumerated in § Fix and the `:686` addition, in this commit.
