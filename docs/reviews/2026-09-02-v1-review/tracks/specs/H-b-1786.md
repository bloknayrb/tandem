# H-b — #1786 the "You're up to date forever" failure has no detector: the update Worker's `reason` is logged to a store nobody retains, and nothing tells a human

Branch `fix/issuance-worker-hardening-and-a-detector-for-the-silent-no-update-failure-1793`. **Closes #1786.** Ledger: `docs/reviews/2026-09-02-v1-review/areas/infra-license-worker.md` row 2 and `areas/armed-license-gate.md:20`. Probe: `npx vitest run tests/server/license-update-worker.test.ts`. **Code only, NO DEPLOY** — the detector is inert until Bryan deploys and sets `ALERT_WEBHOOK_URL`; both flip consts stay dark.

## Problem

The mechanism is established and is not re-derived here: `build_updater`'s `.endpoints()` **replaces** the manifest list rather than falling back, so a licensed install whose `LICENSE_KV` entry is gone gets a 204, `tauri-plugin-updater` early-returns `Ok(None)`, and the app says "You're up to date" forever while starved. `docs/licensing-operations.md:246-250` lists five ways in: a failed KV write, a refund (`applyRefund` deletes the entitlement while the blob still verifies forever), the §7 revocation procedure, KV eviction, and a namespace-id mismatch between the two `wrangler.toml` files.

`CLAUDE.md` and `docs/licensing-explained.md:493` both call the Worker's `reason` enum "the only detector". It is not a detector:

- **Nothing retains it.** `infra/license-update-worker/src/worker.ts:147` is a bare `console.log`; neither `wrangler.toml` has an `[observability]` block, so the lines are kept nowhere. The only reader is `wrangler tail`, which the runbook itself (§5c) calls "a debugging tool, not an alert: no history, no thresholds, no notification, and it dies with the terminal session."
- **Nothing notifies.** The update Worker has no `ALERT_*` wiring at all. The issuance Worker has the whole plumbing (`isAlertable` / `shouldAlert` / `alertBody` / `sendOperatorAlert`, `worker.ts:850-946`); the update Worker got none of it.

**A detector is something that reaches a human without a user reporting it.** Retention alone is not one either — it makes the evidence readable after someone already suspects. Both halves are needed.

**What is already done, and must not be rebuilt.** H-a (#1785, PR #1940) added `UpdateRoute::NoUpdates(WithheldReason)` and `show_update_withheld_dialog`, which covers the cases the *device itself* can see: restricted, and an unreachable loopback probe. Its own spec hands over the residue explicitly: *"a `Licensed` device whose Worker-side entitlement has lapsed receives a 204 from the Worker and is still told 'up to date'. The client genuinely cannot distinguish that."* That is this issue's case, and it is the Worker's to detect.

**The issue's client-side suggestion is not implementable as written, and I am saying so rather than half-building it.** It asks the licensed app to "record the last successful licensed check and warn after N days without one". There is no such observable: `updater.check()` collapses a 204 (no entitlement) and a 200 whose manifest is not newer (perfect health, no release this week) into the same `Ok(None)` — the plugin exposes neither status nor headers. Distinguishing them needs the app to issue its own parallel request to the endpoint, i.e. a second updater. The remaining client surface named in the issue — the Settings warning keyed on local `updateWindowCurrent` (`SettingsLicenseTab.svelte`) — is license UX copy and belongs to **H-c (#1789 #1819)**, which runs concurrently and owns those components. So this group fixes the Worker halves and records both boundaries.

## Fix

- **`infra/license-update-worker/wrangler.toml`** — add `[observability]` / `enabled = true`, and a commented `# ALERT_WEBHOOK_URL = "REPLACE_WITH_INCOMING_WEBHOOK_URL"` under `[vars]` with the same wording as the issuance toml's `:32-40` block, plus the sentence that this Worker's alert is the *only* automatic detector of a licence issued without an entitlement.
- **`infra/license-issuance-worker/wrangler.toml`** — add the same `[observability]` block. One line; the issue asks for both files.
- **`infra/license-update-worker/src/worker.ts`** — mirror the issuance Worker's alert plumbing rather than inventing a shape. The two Workers are separate Cloudflare builds with no shared module (the issuance one imports only `./crypto.js`), so this is a **deliberate duplication, not an oversight** — say so in a comment where the copy starts.
  - Add the local `ExecutionContext` interface (copy `worker.ts:81-83`'s convention) and widen `export default { fetch }` to `(request, env, ctx?)`. `ctx` optional, so the two-arg test harness still calls it.
  - `WorkerEnv` gains `ALERT_WEBHOOK_URL?: string`. **No `ALERT_EMAIL` here** — this Worker has no Resend binding, and adding one would give the update endpoint a reason to hold a mail secret it otherwise never needs.
  - `export function isAlertable(entry: LogEntry): boolean` → `entry.reason === "unknown-id" || entry.reason === "unparseable"`. **Enumerated, and the other three are the discriminating half:** `no-header` is an ordinary unlicensed client, `expired` is expected and benign (the Worker is working correctly), and `upstream` is a GitHub-side blip that would alert-storm. `unparseable` joins `unknown-id` because it is the same family — an entry we wrote that we can no longer read — and is likewise impossible in a healthy system.
  - `alertBody(entry)` carries `reason` and a pointer to §3's repair (`re-PUT the entitlement from the ledger`) and **nothing else**. The file's own privacy invariant is that the license id never reaches a log; an alert channel is a log with a bigger audience, so the id must not reach it either.
  - `shouldAlert(key, nowMs)` + `ALERT_THROTTLE_MS = 5 * 60 * 1000` + `_resetAlertThrottleForTests()`, copied verbatim from `worker.ts:851-866` including its comment about isolates being short-lived.
  - `sendOperatorAlert(env, entry)` posts `{text: body}` to `ALERT_WEBHOOK_URL`; a non-ok response counts as a failure (a retired Slack webhook 404s rather than throwing); when the channel is absent or exhausted, log `{result: "alert-undeliverable", ts, reason}` so the consumed throttle slot leaves a trace. Same reasoning as `:930-940`.
  - Wire it in the `fetch` `log` callback — **not inside `handleUpdateRequest`**, which stays pure and I/O-injected — and hand the promise to `ctx.waitUntil` with `.catch(() => {})`. **An alert must never delay or fail the request it reports on, and must never change the response bytes**: the no-existence-oracle invariant in this file's header is the reason the 204 is byte-identical across all five reasons.
- **Alert on occurrence, throttled — not on a rate.** The issue says "keyed on `unknown-id` rate". Measured against the source: an unlicensed client sends no header and lands on `no-header`, and after H-a a restricted device issues no request at all, so `unknown-id` is structurally zero in health. A rate threshold could only add a way to miss the first one, and rate state on a stateless Worker means a KV counter — new mechanism for less detection. Recorded as an assumption.
- **Docs, four small edits.** `docs/licensing-operations.md`: §3c gains one line naming the alert as the automatic detector and `[observability]` as the retention; §5c gains a short "update Worker" paragraph (one channel, no Resend, and why); §8 gains a checklist line — `ALERT_WEBHOOK_URL` set **on the update Worker too**, without which the silent failure is still undetected. `docs/licensing-explained.md:493-494` — replace *"Detection: a rising `unknown-id` count. Nothing else distinguishes it from health."* with the alert. That is a Part 3 mechanism line, not user-facing copy, so it does not collide with H-c. `CLAUDE.md`, licensing section, last bullet — *"The Worker's `reason` enum is the only detector"* gains "…and it is now retained (`[observability]`) and alerted on `unknown-id`". One clause; do not restructure.

## Tests

All in `tests/server/license-update-worker.test.ts`, extending the existing `no-update reasons (the silent-failure detector)` suite (`:189`). `beforeEach(_resetAlertThrottleForTests)` — the issuance suite's own comment records that without it the second test to provoke a given key is silently suppressed and every "does not alert" assertion passes vacuously.

1. **`isAlertable` truth table.** True for `unknown-id` and `unparseable`; **false for `no-header`, `expired`, `upstream` and `{result:"served"}`**. The false rows kill both an alert-on-every-no-update (which would fire on every unlicensed client) and an alert-on-nothing.
2. **Wiring, through `default.fetch`.** A request with an unknown id, env carrying `ALERT_WEBHOOK_URL`, a stubbed global `fetch`: exactly one POST to the webhook URL; body contains `unknown-id`; **body does NOT contain the license id that was sent**. The negative is the privacy pin — it kills an alert body that echoes the header.
3. **The response is unchanged by alerting.** Status 204, `await res.text()` empty, and byte-identical to the same request with no `ALERT_WEBHOOK_URL`. Kills any implementation that leaks the alert into the response.
4. **The alert is off the response path.** `ctx.waitUntil` called exactly once with a promise. Kills an `await`ed alert, which would add a webhook round trip to every unknown-id update check.
5. **A failing alert channel cannot fail the request.** Webhook `fetch` rejects, then a variant where it resolves 404: both still return 204.
6. **Throttle.** Two unknown-id requests in one isolate → one webhook POST. Then `_resetAlertThrottleForTests()` and a third → two.
7. **No channel configured → no alert fetch, and an `alert-undeliverable` log line.** Kills silently burning the throttle slot with no trace.
8. **`expired` does not alert** even though it is a no-update — the case an operator will otherwise be paged for on every out-of-window customer, forever.

Verify: `npm run lint`, `npx biome check .`, `npm run typecheck:tests`, full `npx vitest run`. No E2E, no Rust, no client change.

## Done when

Both `wrangler.toml` files carry `[observability] enabled = true`; the update Worker alerts on `unknown-id`/`unparseable` through `ALERT_WEBHOOK_URL`, throttled, off the response path, with no license id in the body and no change to the 204; the five non-alerting reasons are pinned; §3c, §5c and §8 name the new detector and the new var; the `licensing-explained` and `CLAUDE.md` "only detector" sentences match reality; eight test groups green.
