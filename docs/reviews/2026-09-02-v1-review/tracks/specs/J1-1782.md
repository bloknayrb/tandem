# J1 — #1782 Troubleshooting recovery step names `sessions/CTRL_ROOM.json`; the real file is `__tandem_ctrl__.json`

Branch `fix/skill-and-workflows-doc-1771`. Closes #1782. Ledger: `docs/reviews/2026-09-02-v1-review/areas/docs.md:19`. Probe: read `docs/troubleshooting.md` and `docs/configuration.md` after the fix and confirm both name the file that actually exists on disk.

## Problem

`docs/troubleshooting.md:451,465` and `docs/configuration.md:109` tell a user to delete `sessions/CTRL_ROOM.json` to reset cross-document state. `CTRL_ROOM` (`src/shared/constants.ts:245`) is the string `"__tandem_ctrl__"` — a Y.Doc room name, not a file name — and the session manager never writes a file literally called `CTRL_ROOM.json`. The write sites (`src/server/session/manager.ts:732,793`) build the path as `` path.join(SESSION_DIR, `${CTRL_SESSION_KEY}.json`) `` where `CTRL_SESSION_KEY = CTRL_ROOM` (`:616`) — the raw string, unencoded. A comment at a third call site (`:867`, the listing-skip path) notes it is "encode-invariant" only because `CTRL_ROOM` happens to contain no characters `encodeURIComponent` would touch — underscores pass through unchanged. So the actual on-disk name is `__tandem_ctrl__.json`. A user following the documented recovery step deletes nothing (no file by that name exists), gets no error, and the wedged state persists.

Two more drift items in the same two docs, both source-confirmed:

- `docs/troubleshooting.md:447` lists the openable extensions as `.md`, `.txt`, `.docx`, `.html` and `.htm` — omitting `.markdown`, which `SUPPORTED_EXTENSIONS` (`src/shared/constants.ts:117`, `new Set([".md", ".markdown", ".txt", ".html", ".htm", ".docx"])`) includes as a first-class alias (`src/server/mcp/document-model.ts:34-38` handles it identically to `.md`).
- `docs/troubleshooting.md:467` and `docs/configuration.md:110` say a corrupt annotation file is "renamed to `.corrupt.json`". The actual rename target (`src/server/annotations/store.ts:594`, `` `${target}.corrupt.${Date.now()}` `` where `target` already ends in `.json`) is `<name>.json.corrupt.<timestamp>` — the same full shape the session-quarantine path uses and that `docs/troubleshooting.md:471` already states correctly two paragraphs later. So the doc contradicts itself between line 467 and line 471.

## Fix

- `docs/troubleshooting.md:447`: add `.markdown` to the extension list.
- `docs/troubleshooting.md:451`: change `` `CTRL_ROOM.json` `` to `` `__tandem_ctrl__.json` ``.
- `docs/troubleshooting.md:465`: change "delete just `CTRL_ROOM.json`" to "delete just `__tandem_ctrl__.json`".
- `docs/troubleshooting.md:467`: change "renamed to `.corrupt.json`" to "renamed to `<name>.json.corrupt.<timestamp>`" (matching the full shape already correct at `:471`, not the bare suffix).
- `docs/configuration.md:109`: change the table key from `` `sessions/CTRL_ROOM.json` `` to `` `sessions/__tandem_ctrl__.json` ``.
- `docs/configuration.md:110`: change "renamed to `.corrupt.json`" to "renamed to `<name>.json.corrupt.<timestamp>`".

No source change — `constants.ts`, `manager.ts` and `store.ts` are all correct; only the two docs drifted.
