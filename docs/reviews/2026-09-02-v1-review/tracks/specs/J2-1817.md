# J2 — #1817 Desktop shows CLI-only push-path instructions to customers with no CLI

Branch `fix/product-copy-1814`. Closes #1817. Ledger row: `docs/reviews/2026-09-02-v1-review/areas/product.md:23`. Probe: none (read-verified against source).

## Problem

Two surfaces show the channel-shim recovery instructions ungated by runtime: `IntegrationWizardModal.svelte`'s `{:else}` (non-registered) push-route arm (~L1160-1180) and `SettingsClaudeCodeTab.svelte`'s equivalent (~L440-452). Both tell the user to run `tandem setup --apply --with-channel-shim` from a terminal. The Tauri desktop build bundles no `dist/cli` (`doctor.ts`'s own npm-package caveat says as much), so a desktop user cannot run that command at all, and the text gives them no path forward.

## Fix

Both files already import `isTauriRuntime` — no new import needed. In each file's non-registered `{:else}` arm, split it in two with `{:else if isTauriRuntime()}` inserted before the existing `{:else}`:

- **New desktop arm** (`isTauriRuntime()` true): name the npm install step first, with a **pinned** command and a caveat naming the dependency and the non-destructive remedy — *"This wizard cannot register it, and the desktop app doesn't include the `tandem` command needed to — install it with `npm install -g tandem-editor@latest`, then run `tandem setup --apply --with-channel-shim` from a terminal, then start each session with `claude --dangerously-load-development-channels server:tandem-channel`. (Keep the global installed — the shim entry runs from it.)"* The `@latest` pin matches `docs/troubleshooting.md`'s own #1177 alternative. **Post-cut correction: no `tandem doctor` clause and no Troubleshooting section pointer.** A desktop user runs `tandem doctor` FROM the global they were just told to install, so the check compares that global's own bundled version against itself and always reports pass — it can never surface the drift the earlier draft's sentence promised (`src/cli/doctor.ts`'s `evaluateStaleGlobal` compares `globalVersion` to `__TANDEM_VERSION__` of the *running* build, which for this invocation is the same global). A Troubleshooting pointer is out for the same reason flagged in the earlier draft: that section's lead instruction is `npm uninstall -g tandem-editor`, which breaks the shim entry `apply.ts:518-527` just registered, since it runs *from* that global — the keep-and-upgrade alternative sits only in a trailing parenthetical most readers won't reach. Deleting both clauses leaves the one claim this arm can actually stand behind: keep the global installed.
- **Existing `{:else}` arm** (npm/CLI runtime, unchanged in substance): drop only the now-redundant parenthetical explaining the desktop doesn't have the CLI (that fact moved to the new arm).

Update the doc comment directly above the push-route block in both files (it currently claims "both arms" name the CLI flag; after this fix there are three). **Keep "wizard"/"settings" within ~25 characters of a denial word ("cannot"/"can't"/"does not"/"no") and within ~15 of "regist(er)" in the new desktop arm's own sentence** — `tests/docs/channel-shim-optin-claims.test.ts`'s `DENIES` regex is what excuses "This wizard cannot register it" from also matching `APP_REGISTERS`; a rewrap that separates those words scores as a false claim that the app registers the shim.

A matching implementation sits uncommitted in this worktree for both files — verify the desktop arm's install command is the pinned `npm install -g tandem-editor@latest` form (not a bare `npm install -g tandem-editor`) before committing.

## Review corrections (post-cut)

Two findings from a post-cut review, both adopted directly, on the desktop arm's copy:

- **Deleted the `tandem doctor` drift-warning clause.** It promised `tandem doctor` "warns when the global drifts from your Tandem version," but a desktop user only ever runs `tandem doctor` FROM the global they were just told to install — `evaluateStaleGlobal` (`src/cli/doctor.ts`) compares `globalVersion` to `__TANDEM_VERSION__` of the *running* build, which for that invocation is the same global, so the check always passes and can never surface the drift promised. Shipping a diagnostic that cannot detect what it claims to detect, in the wave whose whole premise is "user follows on-screen instructions into a dead end," reproduces the defect the group exists to close.
- **Deleted the Troubleshooting → Stale global pointer.** That section's lead instruction is `npm uninstall -g tandem-editor` in a fenced code block; the keep-and-upgrade alternative sits only in a trailing parenthetical most readers won't reach. Following the pointer's first instruction breaks the shim entry the wizard just registered, since it runs *from* that global (`apply.ts:518-527`).

The desktop arm now ends after "(Keep the global installed — the shim entry runs from it.)" — the one claim it can actually stand behind. Both findings targeted the spec's copy only; the implementation already in this worktree never carried the removed clauses, so no source or test change was needed for these two.
