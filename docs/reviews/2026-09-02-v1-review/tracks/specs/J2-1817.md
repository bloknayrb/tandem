# J2 — #1817 Desktop shows CLI-only push-path instructions to customers with no CLI

Branch `fix/product-copy-1814`. Closes #1817. Ledger row: `docs/reviews/2026-09-02-v1-review/areas/product.md:23`. Probe: none (read-verified against source).

## Problem

Two surfaces show the channel-shim recovery instructions ungated by runtime: `IntegrationWizardModal.svelte`'s `{:else}` (non-registered) push-route arm (~L1160-1180, HEAD) and `SettingsClaudeCodeTab.svelte`'s equivalent (~L440-452, HEAD). Both tell the user to run `tandem setup --apply --with-channel-shim` from a terminal. The Tauri desktop build bundles no `dist/cli` — `doctor.ts`'s own npm-package caveat says as much — so a desktop user cannot run that command at all, and the text gives them no path forward.

## Fix

Both files already import `isTauriRuntime` (`IntegrationWizardModal.svelte` L36; `SettingsClaudeCodeTab.svelte` L16) — no new import needed. In each file's non-registered `{:else}` arm, split it in two with `{:else if isTauriRuntime()}` inserted before the existing `{:else}`:

- **New desktop arm** (`isTauriRuntime()` true): name the npm install step first, in one line, before the command that needs it, with a **pinned** install command and a caveat that names the dependency and points to the non-destructive remedy — *"This wizard cannot register it, and the desktop app doesn't include the `tandem` command needed to — install it with `npm install -g tandem-editor@latest`, then run `tandem setup --apply --with-channel-shim` from a terminal, then start each session with `claude --dangerously-load-development-channels server:tandem-channel`. (Keep the global installed — the shim entry runs from it. If Tandem later reports "Server disconnected," `tandem doctor` warns when the global drifts from your Tandem version; see Troubleshooting → Stale global `tandem-editor` to update it.)"* The `@latest` pin matches `docs/troubleshooting.md`'s own "if you deliberately run a global CLI" alternative for #1177, and the reworded parenthetical is deliberately **not** that section's headline fix (`npm uninstall -g tandem-editor`): the shim entry the wizard just registered (`apply.ts:518-527`, `entries["tandem-channel"] = { command: resolveNodeBinary(), args: [channelPath] }` where `channelPath` is `CHANNEL_DIST`, derived from the same global install's `PACKAGE_ROOT`) runs *from* that global, so sending a desktop user to uninstall it would break the very setup this copy just created. Point at the keep-and-upgrade alternative instead.
- **Existing `{:else}` arm** (npm/CLI runtime, unchanged in substance): drop only the now-redundant parenthetical explaining the desktop doesn't have the CLI (that fact moved to the new arm) — *"…run `tandem setup --apply --with-channel-shim` from a terminal (that flag is its only opt-in), then start each session with…"*. **This arm's wording is pinned by two existing tests** (see Tests below) — the npm-caveat assertion currently anchored here moves to the new desktop arm, it does not disappear.

The `{#if wizard.channelRegistered}` arm (shim already registered) is untouched — it needs no CLI command, just `claude --dangerously-load-development-channels …`. Update the doc comment directly above the push-route block in both files (it currently claims "both arms" name the CLI flag; after this fix there are three arms) — match the wording already drafted in the uncommitted work described below rather than re-deriving it. **Keep "wizard" (or "settings") within ~25 characters of a denial word ("cannot"/"can't"/"does not"/"no") and within ~15 of "regist(er)" in the new desktop arm's own sentence** — `tests/docs/channel-shim-optin-claims.test.ts`'s `DENIES` regex is what excuses "This wizard cannot register it" from also matching `APP_REGISTERS`; a rewrap that separates those words onto different lines or beyond that window scores as a false claim that the app registers the shim.

**A matching implementation already sits uncommitted in this worktree** for both files (the `isTauriRuntime()` branch and the updated doc comments), but its desktop-arm command is the unpinned `npm install -g tandem-editor` this round of review flagged as a live breakage path — replace it with the pinned form above before committing.

## Tests

No existing automated test renders this block with `isTauriRuntime()` forced true (E2E cannot — it runs in a plain browser, never Tauri, per the wave-table note). **Two existing tests already pin the non-Tauri arm's npm caveat and go RED the moment the `{:else}` arm's wording is trimmed** — they are not new coverage to add, they are existing coverage that must move with the copy in the same commit:

Once the `{:else}` arm is trimmed, this assertion must move: mock `../../src/client/cowork/cowork-helpers` with a mutable cell — `settings-claude-code-tab-cowork.test.ts:25-28` is the file's own precedent for that shape (`let tauri = …; vi.mock(..., () => ({ ...actual, isTauriRuntime: () => tauri }))`) — and split the test into a Tauri-true case asserting `npm install -g tandem-editor@latest` (and the shadowing-caveat sentence) and a Tauri-false case asserting the trimmed `{:else}` wording with neither the npm line nor the caveat present. **Forcing `isTauriRuntime()` true in this file also mounts `CoworkSettings`** (`SettingsClaudeCodeTab.svelte:481-491`, `{#if isTauriRuntime()}{#await import("../CoworkSettings.svelte")}…`), whose `createCoworkStatus(() => true)` holds a live `$effect` and a real `invoke` call — copy the **whole** mock block `settings-claude-code-tab-cowork.test.ts:25-47` (the `cowork-helpers` cell mock, the `useCoworkStatus.svelte` mock, and the `cowork-invoke` mock), not just its first four lines, or the Tauri-true case reaches the network. Reword the file's docblock (~L14-20, "both arms … must carry `doctor.ts`'s caveat") to say the **desktop** arm carries it.
- `tests/client/integration-wizard-push-support.test.ts:594` — inside `"tells the user the ONLY thing that registers the shim: the CLI flag"` (`mountPushMode(false)`), same assertion, same fix shape. That file already mocks `cowork-helpers` at ~L139-142 keyed off `isTauriRuntime: () => coworkStub.status !== null`. **Do not reuse `coworkStub.status` to force the Tauri arm** — it simultaneously enables `IntegrationWizardModal.svelte`'s Cowork sub-view (`:95`), the autostart hook (`:106`, `createAutostart(() => open && isTauriRuntime() && wizard.step === "done")`), and the autostart UI block (`:1133`), none of which this file mocks (`useAutostart.svelte` has no mock here) and `mountPushMode` already puts the wizard on the `done` step. Instead, change this file's `cowork-helpers` mock to read a **separate** `let tauri = false;` cell (`isTauriRuntime: () => tauri`), leaving `coworkStub.status` untouched, and reset `tauri = false` in `afterEach`.

Both suites must still assert the non-Tauri arm contains `tandem setup --apply --with-channel-shim` and does **not** contain `npm install -g tandem-editor` (kills a fix that always shows the desktop instructions, silently reintroducing the bug for CLI users), and the Tauri arm contains the pinned npm command and does **not** render the bare CLI-flag sentence without it preceding. **Exact substrings, since the two arms' wording differs and "the same assertion" is not itself executable**: Tauri-true case asserts the text contains `npm install -g tandem-editor@latest` AND the sentence fragment `desktop app doesn't include the` AND `Server disconnected`; Tauri-false case asserts the text contains `tandem setup --apply --with-channel-shim` and does **not** contain `npm install -g tandem-editor`.
