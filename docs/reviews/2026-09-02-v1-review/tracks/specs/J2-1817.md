# J2 — #1817 Desktop shows CLI-only push-path instructions to customers with no CLI

Branch `fix/product-copy-1814`. Closes #1817. Ledger row: `docs/reviews/2026-09-02-v1-review/areas/product.md:23`. Probe: none (read-verified against source).

## Problem

Two surfaces show the channel-shim recovery instructions ungated by runtime: `IntegrationWizardModal.svelte`'s `{:else}` (non-registered) push-route arm (~L1160-1180, HEAD) and `SettingsClaudeCodeTab.svelte`'s equivalent (~L440-452, HEAD). Both tell the user to run `tandem setup --apply --with-channel-shim` from a terminal. The Tauri desktop build bundles no `dist/cli` — `doctor.ts`'s own npm-package caveat says as much — so a desktop user cannot run that command at all, and the text gives them no path forward.

## Fix

Both files already import `isTauriRuntime` (`IntegrationWizardModal.svelte` L36; `SettingsClaudeCodeTab.svelte` L16) — no new import needed. In each file's non-registered `{:else}` arm, split it in two with `{:else if isTauriRuntime()}` inserted before the existing `{:else}`:

- **New desktop arm** (`isTauriRuntime()` true): name the npm install step first, in one line, before the command that needs it — *"This wizard cannot register it, and the desktop app doesn't include the `tandem` command needed to — install it with `npm install -g tandem-editor`, then run `tandem setup --apply --with-channel-shim` from a terminal, then start each session with `claude --dangerously-load-development-channels server:tandem-channel`."*
- **Existing `{:else}` arm** (npm/CLI runtime, unchanged in substance): drop only the now-redundant parenthetical explaining the desktop doesn't have the CLI (that fact moved to the new arm) — *"…run `tandem setup --apply --with-channel-shim` from a terminal (that flag is its only opt-in), then start each session with…"*.

The `{#if wizard.channelRegistered}` arm (shim already registered) is untouched — it needs no CLI command, just `claude --dangerously-load-development-channels …`. Update the doc comment directly above the push-route block in both files (it currently claims "both arms" name the CLI flag; after this fix there are three arms) — match the wording already drafted in the uncommitted work described below rather than re-deriving it.

**A matching implementation already sits uncommitted in this worktree** for both files (the `isTauriRuntime()` branch, the updated doc comments, and the `{:else}` arm's trimmed parenthetical). Verify it against this spec and commit rather than re-deriving.
