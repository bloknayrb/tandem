VERIFIED FINE
================================================================
- Byte-identical while dark (question 9): dist/server/index.js and dist/cli/index.js both contain
  `defineValue = true ? false : void 0`, so readGateFlag never consults TANDEM_LICENSE_GATE in a built
  bundle and GATE_ENABLED is false. tsup.config.ts:20,85,121 injects the define into exactly the server and
  cli bundles. resolveLicenseState returns `{gateActive:false}` before touching disk (license-state.ts:72-74),
  ensureTrialStarted no-ops (license-state.ts:181), applyConnectionGate no-ops (connection-gate.ts:32),
  licenseGateResult no-ops (license-gate.ts:42). The one thing the dark path does do is darkInstallInfo()'s
  read+verify on the status route — see the Low finding. [ran: grep over dist/]
- Surface A never clamps CTRL_ROOM: connection-gate.ts:17 tests `documentName !== ctrlRoom` and
  applyConnectionGate is called with CTRL_ROOM from the shared constant. Chat/mode/awareness survive.
- The force-reload gate sits BEFORE any mutation on both halves: document.ts:409 before openFromDisk,
  routes/open.ts:15 before openFromDisk, both outside the inner try.
- Canonicalization is injective for the attack that matters: canonicalize() sorts keys recursively over the
  PARSED object, so stripping a field, adding a field, or re-ordering keys all change the signed bytes and
  yield BAD_SIGNATURE; a duplicate JSON key collapses before canonicalization, so it cannot smuggle a
  different value past a valid signature. Null-prototype accumulator blocks __proto__ key loss.
- Size bounds are layered and each is applied to the string that is actually consumed: raw <= 20_000 before
  any allocation (verifier.ts:70), post-normalize <= 10_000 (verifier.ts:93, correctly re-checked because
  stripping an interior `=` can lengthen the decode), decoded payload <= 4096 before JSON.parse and before
  canonicalObject's recursion (verifier.ts:106).
- SignatureVerified brand does its job: resolveLicenseState's `verify` dep is typed to it, so the
  expiry-checking verifyLicense cannot be wired into the run gate. Paid licenses run forever;
  updateWindowCurrent is computed separately from expiresAt (license-state.ts:100-107).
- Activation is verify-then-persist (license-state.ts:229-254): a bad blob after a good one never overwrites
  license.json, and WRITE_FAILED is isolated in its own try so a filesystem error is reported as ours (500)
  rather than as a bad key (400).
- license.json is written 0600 via atomicWriteConfigFile (integrations/storage.ts:139-168, `open(tmp,"wx",0o600)`
  plus a chmod backstop) — correct for the only identity PII Tandem writes to disk.
- Blob bytes and crypto messages never cross to the wire: only LicenseVerifyCode/LicenseActivationCode do
  (verifier.ts:43-52, routes/license.ts:169-179), and the copy is static per code (shared/license-copy.ts).
- Dismissing the LicenseWall does not re-enable editing: `dismissed` is local to the component, ui.showWall
  stays true, and App.svelte:1791 keeps editorReadOnly true. "Continue in read-only mode" is honest.
- The mid-session restricted->licensed direction works: licenseStore.set() from the activate response fires
  reconcileTransition, which calls yjsSync.rebuildForLicenseChange() and re-runs onAuthenticate.
- The update Worker is a genuine non-oracle: all five rejection reasons return byte-identical 204, including
  a thrown upstream fetch (worker.ts:118-133).
- resolveLiveLicenseState is cache-free, so activation elsewhere takes effect on the next dispatch.
