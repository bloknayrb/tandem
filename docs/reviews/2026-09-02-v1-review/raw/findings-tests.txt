H1. `tandem_comment rejects invalid arguments` cannot fail — High
  tests/server/mcp-tool-integration.test.ts:307-318  [read: tests/server/mcp-tool-integration.test.ts:305-320]
  The body is `try { await client.callTool({name:"tandem_comment", arguments:{from:0,to:5}}) } catch { /* expected */ }` with no `expect` on either branch, so it is green whether Zod rejects, the SDK throws, or the tool silently creates an annotation with no text. A regression that drops the `text` requirement (or the whole schema) leaves this "rejects invalid arguments" spec passing. Confidence: high.

H2. Critical Rule 9's "MCP half is CI-enforced" has a bare-registration hole — High
  tests/server/license-gate-coverage.test.ts:~125-140  [read: tests/server/license-gate-coverage.test.ts:1-152; ran: grep of registration sites in src/server/mcp]
  The completeness spec derives `registered` from `/(?:gatedTool|withErrorBoundary)\(\s*"(tandem_\w+)"/`, i.e. it only sees tools that already went through one of the two wrappers, so a new mutator registered bare as `server.tool("tandem_x", …, handler)` is neither GATED, UNGATED, nor "unclassified" — it is invisible and ships ungated with the suite green. `tests/docs/tool-count-drift.test.ts:~27` does derive names from `server.(tool|registerTool)("tandem_*")` (all 33 are currently wrapped, verified), but it compares only against the *counts* in docs/mcp-tools.md and CLAUDE.md, so updating "33/30" in the docs is enough to pass both; the license test should reuse that derivation and assert registered ⊆ classified. Confidence: high.

H3. coverage-gate-wiring's "suite references the module" check is vacuous — Medium
  tests/scripts/coverage-gate-wiring.test.ts:~100-112  [read: tests/scripts/coverage-gate-wiring.test.ts:1-306]
  The check is `read(m.suite).includes(stem)` where the stems are `registry, dirty, open, reload-family, watcher, lifecycle, projection, sync, schema, annotations, replies, useDocumentWorkspace, model, rail-content`; nine of those are ordinary English or ubiquitous identifiers, so any test file that says "open" or "sync" satisfies the "suite for open.ts / sync.ts" claim. Combined with the existence-only check above it, the "deletion half" of the gate is defeated by hollowing the suite (delete every `it`, or `describe.skip`) while the file stays on disk; ADR-051's promise that "deleting the suite reds a REQUIRED job" holds only for `rm`. Confidence: high.

  tests/e2e/annotation-lifecycle.spec.ts:196-222, tests/e2e/*.spec.ts  [ran: grep -rnoE "tandem_checkInbox|tandem_reply|tandem_save|Control\+s" tests/e2e/*.spec.ts]

Solo-mode E2E (keyboard-shortcuts:222, settings-and-filters:393, mode-toggle-geometry) asserts pill geometry and toggle state, never that annotations are held/released. Unit coverage exists (mcp-tool-integration, events/queue), so this is a journey gap, not a hole. Confidence: high.
