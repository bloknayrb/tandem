## Findings — high confidence

H1. High — `.docx` review recipe `tandem_getAnnotations({ author: "import" })` can never return anything
  skills/tandem/SKILL.md:110 (also docs/workflows.md:311-316)
  [read: src/server/file-io/docx-comments.ts:496-504,636,742,766; src/server/mcp/annotations.ts getAnnotations handler]
  Imported Word comments land as `type:"note"`, `audience:"private"`, `author:"import"`, and the
  `tandem_getAnnotations` handler applies `results.filter(a => a.type !== "note")` after the author filter,
  so the skill's recipe returns an empty list every time; once the user promotes a comment its author is
  rewritten to `"user"` and its type to `"comment"`, so `author:"import"` matches nothing post-promotion either.
  A Claude following the skill literally reports "no reviewer comments in this .docx" for a document full of
  them, and the same dead recipe is reproduced in workflows.md. Not in the open-issue list (#1714/#1693 are
  adjacent but describe different gaps). Confidence: high.

H2. High — Accepting a `suggestedText` annotation via `tandem_resolveAnnotation` never applies the text
  src/server/mcp/annotations.ts (tandem_resolveAnnotation handler → store.acceptAnnotation); src/client/panels/useAnnotationReview.svelte.ts:509-545
  [read: useAnnotationReview.svelte.ts:505-545; src/server/annotations/lifecycle.ts accept path; grep applySuggestion src/server → no hits]
  `applySuggestion` is invoked only inside the client-side `resolveAnnotation` handler; the server lifecycle
  `accept` flips `status` only and no server observer reacts to it, so an MCP accept leaves the document text
  untouched. The tool description ("Accept or dismiss an annotation") and SKILL.md never say this, so a
  Claude that "applies" its own suggestions by accepting them (which the inbox then reports as a user response
  — already reported by another reviewer) ends with an unchanged `.md` and a resolved annotation. No matching
  open issue (search returned #694, #1680 — unrelated). Confidence: high.

H3. Medium — Skill content changed without a version bump; upgraders on v0.18–v0.20.1 never received it
  skills/tandem/SKILL.md frontmatter; src/server/integrations/apply.ts:~2091-2141 (`refreshSkillIfNewer`)
  [ran: curl raw.githubusercontent.com/bloknayrb/tandem/<tag>/skills/tandem/SKILL.md for every tag v0.16.0–v0.24.1 + md5sum]
  v0.18.0 and v0.19.0 shipped `version: 4` (md5 55d1e8ea); commits 1c9a9306a/6261ea460/3c92732d7 (2026-07-28)

  v0.20.1 shipped a different v4 (md5 68fa0ce0) that `refreshSkillIfNewer` skipped on disk (`onDisk >= bundled`).
  Anyone who upgraded within v0.18→v0.20.1 ran the stale skill until v0.21.0 (v9) — historical now, but the
  gate is unguarded: `tests/skill-instruction-contract.test.ts` pins `version: 12` only, so the same slip
  recurs on the next content-only edit. Per-tag table: v0.16.0 v3/901ffa84; v0.17.0 v3/901ffa84;
  v0.18.0 v4/55d1e8ea; v0.19.0 v4/55d1e8ea; v0.20.0 v4/68fa0ce0; v0.20.1 v4/68fa0ce0; v0.21.0 v9/46d35ce1;

  0c8978a8d v2; 4cf2544aa v3; c47aed758 v4; 1c9a9306a/6261ea460/3c92732d7 v4 (no bump); ac517f0a7 v5;
  4ad567c5f v6; d3e8cba6f v6 (no bump, same-day pre-release, harmless); e3f120d23 v7; 33b3fb56f v8;

H4. Medium — Marketplace plugin ships the channel shim unconditionally, silencing the wake advisory
  .claude-plugin/plugin.json (`mcpServers.tandem-channel`); pinned by tests/plugin-manifest.test.ts:42-56
  [read: .claude-plugin/plugin.json; src/server/mcp/wake-advisory.ts:80-101; docs/architecture.md:566-577; src/channel/run.ts:207]
  `tandem setup --apply` makes the shim opt-in (`--with-channel-shim`) precisely because a shim whose host never
  negotiated channels is "attached-and-inert" and holds the external-subscriber slot, which is the condition
  under which the wake advisory (fires only when `externalConsumerCount === 0`) goes quiet. The plugin manifest
  spawns `tandem-editor@0.24.1 channel` for every plugin session regardless of the
  `--dangerously-load-development-channels` flag, so plugin users get the inert-shim hazard by default and the
  test locks it in. Closed #985 is related; whether this is a deliberate trade-off is unverified. Confidence: medium.

H5. Medium (extends #1737) — Hard Rule 4 steers away from the tools that do handle structure and is stale for plaintext
  skills/tandem/SKILL.md:25
  [read: SKILL.md:22-26; src/server/mcp/document.ts tandem_appendContent/tandem_editList/tandem_edit descriptions; #1460 changelog]
  The rule says newlines "become literal characters" and prescribes multiple `tandem_edit` calls or
  `suggestedText`, but never names `tandem_appendContent` or `tandem_editList`, and since #1460 (v0.23.0,
  2026-08-18 — before skill v12 on 08-19) a plaintext newline is REFUSED with INVALID_ARGUMENT rather than
  inserted literally. Delta over #1737: the skill text is now wrong in both directions (false mechanism for
  .txt, missing the escape hatch for .md). Confidence: high.

## Addendum (after 2 further non-write calls: manifest read + ADR check)

CORRECTION to H4 — downgrade to Low, and move U2 to resolved.
  .claude-plugin/plugin.json `mcpServers.tandem-channel`; docs/decisions.md:378-400
  [read: docs/decisions.md:376-400]
  The entry is a recorded, permanent KEEP (ADR update 2026-08-08, closed 2026-08-09 via #1349), so it is
  deliberate, not an oversight. What the ADR reasons about is the `exit 127` noise and whether the host spawns
  the entry; it does not address the inert-consumer interaction that architecture.md:566-577 uses to make the
  SAME entry opt-in for `setup --apply`. The remaining delta is narrow: in a plugin session the manifest monitor
  is itself an external consumer, so the wake advisory is already (legitimately) silent whenever the monitor is
  active; the shim only matters when the monitor fails to activate (`-p` mode, or the unmeasured macOS/Linux
  path), where it alone holds the external-subscriber slot and hides the advisory from a Claude that has no
  other push path. Worth one sentence in architecture.md §"Why tandem-channel Is Opt-In" saying the plugin
  manifest is the exception and why. Confidence: high that it is deliberate; medium that the residual case matters.
