=== PROBE 7 (empty firstRunAt resets the trial) — RESULT: CONFIRMED ===
Wrote <scratch>/exp-probe/data/trial.json = {"version":1,"firstRunAt":""} and restarted with
TANDEM_LICENSE_GATE=1.
  trial.json on disk after boot: {"version":1,"firstRunAt":""}   (NOT rewritten — startTrialClock uses
  flag "wx", so an existing file is never replaced)
  GET /api/license/status ->
    {"gateActive":true,"status":"trial","updateWindowCurrent":false,
     "trial":{"firstRunAt":"2026-09-02T19:07:23.576Z","expiresAt":"2026-09-16T19:07:23.576Z","daysRemaining":14}}
src: src/server/license/license-state.ts:128-130
    const tf = readJson<TrialFile>(trialFilePath(appDataDir));
    const firstRunAt = tf?.firstRunAt ? new Date(tf.firstRunAt).getTime() : nowMs;
    const expiresAt = firstRunAt + TRIAL_MS;
`""` is falsy, so it takes the `: nowMs` branch — the same branch as an ABSENT file. Because the state is
re-resolved per dispatch (no cache) and the file is never rewritten, this is not a one-time reset but a
PERPETUAL 14-days-remaining trial: firstRunAt is recomputed as "now" on every call.
SEVERITY: low / by design. The header comment on the same block says "Trial clock (soft by design —
ADR-040 §3). Absent file => day 0", so a local user editing their own trial.json is inside the accepted
model. Two things worth stating anyway, because neither is written down: (1) the reset is achieved by
BLANKING a field rather than deleting the file, which is not the shape the "absent file" comment
describes; (2) a NON-EMPTY but unparseable value behaves oppositely — new Date("nope").getTime() is NaN,
so expiresAt is NaN, `nowMs < NaN` is false, and it falls through to `restricted`, i.e. fails CLOSED.
So the trial file's failure direction depends on whether the corruption is falsy or merely invalid.
