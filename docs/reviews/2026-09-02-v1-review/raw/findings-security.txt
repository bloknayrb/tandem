## Findings — high confidence

### F2 — Low — `/api` JSON body cap is 100 kB (not the documented 50 MB) and oversize/malformed bodies answer with an Express HTML stack trace
- Location: `<repo>/src/server/mcp/server.ts:737` (`app.use(mcpApp)` mounted at root, before `registerApiRoutes` at :740); `node_modules/@modelcontextprotocol/sdk/dist/esm/server/express.js:29` (`app.use(express.json())`, default 100 kb); `<repo>/src/server/mcp/api-routes.ts:526~` (`largeBody` 70 MB parser that never runs for JSON because the SDK parser already consumed the stream).
- Evidence: `[ran: curl -sS -i -H 'Content-Type: application/json' --data-binary @big.json http://127.0.0.1:4919/api/upload]` → `413` with HTML body `PayloadTooLargeError: request entity too large at readStream2 (file://<repo>/dist/server/index.js:102834:21)`; 50 kB body → 200; `POST /api/open` 300 kB → 413; body `"str"` → 400 HTML `SyntaxError` page.
- Failure: any JSON POST to `/api/*` above ~100 kB (an `upload` of a 200 kB markdown file from the browser, a large `apply-changes` payload) is rejected before the route's own 70 MB parser, so the documented 50 MB limit is unreachable over HTTP JSON. The default Express error handler also leaks the absolute install path and bundle line numbers in an HTML body; disclosure is loopback-only (no ACAO on the early error path, LAN POST is stopped by `enforceLoopbackMutation`).
- Recommendation: mount the SDK app under `/mcp` only (`app.use("/mcp", mcpApp)`) or register the `/api` parser before it; add a JSON error handler so parser failures return `{error}` without a stack.
- Confidence: high.

## Findings — remaining

### F1 — Low — Launcher home-confinement bypass via `POST /api/integrations` `workingDirectory`
- Location: `<repo>/src/server/launcher/supervisor.ts:723-739` (`resolveCwd` → `resolveSafeCwd` only), `:1450-1474` (`resolveSafeCwd`, no `homeConfines`), `:1550-1563` (`resolveRouteCwd`, the confined one — used only by the launcher routes); `<repo>/src/server/integrations/api-routes.ts:565-596` (`makePostIntegrationsHandler` accepts `IntegrationsFileSchema`); `<repo>/src/server/integrations/schema.ts:127` (`workingDirectory: AbsolutePath.optional()`).
- Evidence: `[read: supervisor.ts:723-739,1450-1563; integrations/api-routes.ts:565-596; schema.ts:33,127]`.
- Failure: the launcher routes confine `cwd` to the home directory, but the same override reaches the supervisor through the integrations file, which `POST /api/integrations` writes for any origin matching `127.0.0.1:*` after the nonce dance (`GET /api/integrations/first-run` hands out the nonce ungated). A page on any 127.0.0.1 port POSTs `{integrations:[{kind:"claude-code",…,workingDirectory:"/tmp/evil"}]}` then `POST /api/launcher/relaunch`, and Claude Code is spawned with a cwd outside home (where a planted `CLAUDE.md`/`.claude/settings.json` shapes the session). Precondition: an attacker page on a 127.0.0.1 origin, which the code already treats as inside the trust boundary; this is a consistency gap, not a new boundary crossing.
- Recommendation: apply `homeConfines` in `resolveCwd` (or reject a non-home `workingDirectory` in the integrations POST handler and leave the hand-edited file path as the only bypass, as the docblock at :1537-1542 assumes).
- Confidence: high on the code path; not live-probed.

### F3 — Low — Supervisor spawns the reaper/Claude with the full `process.env`, propagating `TANDEM_AUTH_TOKEN` and `TANDEM_SENTRY_DSN` into every Bash subprocess of the launched session
- Location: `<repo>/src/server/launcher/supervisor.ts:822-827` (`spawn(reaper, reaperArgs, { cwd, stdio: pipe, env: process.env, windowsHide })`); contrast `<repo>/src/server/integrations/install-claude-cli.ts:257-279` (minimal env); `src-tauri/src/sidecar.rs:430-520` (sidecar passes `TANDEM_AUTH_TOKEN` in env).
- Evidence: `[read: supervisor.ts:804-835; install-claude-cli.ts:257-279; sidecar.rs:430-520]`.
- Failure: under the desktop app the sidecar's environment carries the LAN bearer token and the Sentry DSN, and the supervisor hands the whole environment to Claude Code, whose Bash tool inherits it, so any command the model runs (including ones a prompt-injected document steers) can read `$TANDEM_AUTH_TOKEN`. Impact is bounded because the token only matters when LAN mode is on, and the launched session is already trusted to call the loopback MCP surface; but it widens the token's exposure from one process to an arbitrary subprocess tree.
- Recommendation: build an explicit env for the spawn (PATH, HOME, locale, `TANDEM_*` that the child genuinely needs) and drop `TANDEM_AUTH_TOKEN`/`TANDEM_SENTRY_DSN`.
- Confidence: medium (env content depends on how the sidecar launched the server; the spawn line is unambiguous).

### F4 — Low — Tauri `keychain_get` returns plaintext secrets to the WebView
- Location: `<repo>/src-tauri/src/keychain.rs:54-62`; `<repo>/src-tauri/src/lib.rs:1578-1640` (invoke handler registers `keychain_get/set/delete`); `<repo>/src/client/keychain/keychain-invoke.ts:50`.
- Evidence: `[read: keychain.rs:30-100; lib.rs:1578-1640; keychain-invoke.ts]`.
- Failure: the command is reachable from any script running in the WebView, so a single XSS in the client (none found — see Verified fine) escalates to reading every stored provider key. Only reachable over Tauri IPC, which the capability files restrict to the app window; not reachable from the browser build.
- Recommendation: consider keeping secrets in the Rust side and exposing only "use key for request" or an opaque handle; at minimum keep this in the register as an XSS-amplifier.
- Confidence: high that the path exists; impact is Info/Low.

## Doc drift
- `docs/security.md` (Privacy section) states a 50 MB file-size limit as the request bound; over HTTP JSON the effective cap is the SDK's 100 kB (F2). The 50 MB gate is real for file opens from disk (`open.ts:620-678`) and for the `largeBody` route parser, but the latter is unreachable for JSON.
- `<repo>/src/server/launcher/supervisor.ts:1537-1542` docblock: "The integration-file path bypasses this — advanced users who hand-edit integrations.json" — the file is also written by `POST /api/integrations` from any 127.0.0.1 origin (F1), so the bypass is HTTP-reachable, not hand-edit-only.
- The "any page served from 127.0.0.1:* is inside the trust boundary" assumption is stated in code comments (`api-routes.ts` `LOCALHOST_ORIGIN_RE` and the loopback-gate comments) but not in the `docs/security.md` findings register or threat model; F1/F3 both depend on it and a reader of the doc alone would not know it was a deliberate acceptance.
- CLAUDE.md's six-route inventory (open, upload, close, annotation-reply, remove-annotation, rotate-token) matches the source exactly — no drift there (live-probed, see below).
