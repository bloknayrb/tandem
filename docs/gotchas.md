# Gotchas — the silent-failure catalogue

> Mechanism and evidence for the rules listed under **Gotchas** in
> [CLAUDE.md](../CLAUDE.md#gotchas). Each rule stays inline there because violating it
> fails silently; the *why* lives here so it is one link away rather than ambient
> context in every session.
>
> Narrative lessons with issue archaeology live in
> [lessons-learned.md](lessons-learned.md); this file is the operational detail behind
> the inline rules.

### Desktop / Tauri

`cargo tauri dev` / `cargo tauri build`. Layout, sidecar lifecycle, origin handling and the
logging/DevTools split are in [architecture.md](architecture.md). These bite silently:

- **`single-instance` must be the FIRST plugin registered** in `lib.rs` — later registration breaks instance detection with no error.
- **Two `externalBin`s: `node-sidecar` AND `tandem-reaper`.** Both must exist or `cargo tauri dev/build` fails its existence check. The reaper shipped missing in every desktop build before #1268 — "Relaunch Claude" could not spawn.
- **`create_overlay_titlebar()` must be called post-page-load**, from the component's `onMount` — the hit-test JS `tauri-plugin-decorum` injects is cleared on WebView navigation. No error; the titlebar just stops hit-testing.
- **The `devtools` feature is mutually exclusive with `tauri-plugin-log`** — both install a global `tracing` subscriber, so the log plugin is `#[cfg(not(feature = "devtools"))]`-gated.
- **Cowork detection scans TWO roots** (ADR-044) and candidate dirs must be UUID-shaped or carry a `cowork_plugins\` marker — **never write plugin-registry files into other siblings**. All four write entry points re-run `revalidate_resolved_path` at write time (#433 TOCTOU); `check_acl` fails closed.

### Origin tagging — which helper to use (Critical Rule 2)

Raw `doc.transact(...)` is forbidden anywhere in `src/`. Pick one of the six helpers from
`src/shared/origins.ts`. **Picking the wrong one is a silent bug — the helper choice is the
contract, not a label.** See ADR-031.

| Helper | Use for |
|---|---|
| `withMcp` | Claude-initiated writes from MCP tools |
| `withFileSync` | Echoes from the durable-annotation file-writer / the file-watcher reload path's JSON→Y.Map merge |
| `withInternal` | Server-internal setup writes: session restore, mdast/docx population, tutorial seeding, scratchpad seeding, force-reload, server metadata broadcasts |
| `withReload` | The `reloadFromDisk` file-watcher flow, including the post-reload `refreshAllRanges` continuation |
| `withModeRelease` | The server-owned Solo→Tandem release sweep. Behaviourally mirrors `mcp` today, but a server-owned sweep is not a Claude-initiated write and carries its own semantic identity |
| `withBrowser` | User edits originating in the browser |

Who skips what: the durable-annotation sync observer skips `file-sync` and `internal`. The
channel event queue skips `mcp`, `file-sync`, `internal`, `reload` and `mode-release` — so
**only `browser` writes generate channel events.**

Enforcement is warn-only: the `check-raw-transact.sh` PostToolUse hook plus the
`npm run audit:origins` static walk. There is no blocking pre-commit hook and no Biome rule.

### Y.js / CRDT
- **Y.XmlText must be attached before populating.** Inserting formatted text into a detached Y.XmlText reverses segment order. Always attach to Y.Doc first, then insert (two-pass pattern in `mdast-ydoc.ts`).
- **Y.XmlElement.setAttribute needs `as any` for numbers.** TypeScript types say string-only but Tiptap stores numeric heading levels.
- **Stale browser tabs are auth-rejected after a server restart (generation gate).** Historically a tab surviving a restart would CRDT-merge its old Y.Doc state back on reconnect, duplicating/reverting content whenever the server loaded fresh from disk (disjoint histories). Now every `HocuspocusProvider` pins the server run's `generationId` (from `GET /api/info`, loopback-only field) as its auth token at construction; the server's `onAuthenticate` hook (`yjs/provider.ts`) rejects mismatches for **every** room including `CTRL_ROOM` — sync messages queue until auth passes, so a rejected stale doc never merges. On `authenticationFailed` the client re-fetches the generation and rebuilds ctrl + all tabs with fresh Y.Docs (`scheduleRebuild` in `yjsSync.svelte.ts`). The generation id lives in module state (`getGenerationId()`) and travels over HTTP only — deliberately never broadcast via the ctrl Y.Map, where a stale merge could clobber it (concurrent YMap set → clientID coin flip). Unsaved browser edits from before the restart are dropped by design (the shutdown disk flush + session save make graceful restarts lossless for synced edits). Tokens are pinned strings, not closures: a provider whose ydoc predates the restart must never re-authenticate. In stdio mode no HTTP route serves the generation, so browser clients are fully locked out — they were already non-functional there (the editor needs the :3479 API).
- **Force-reload clears in-place.** `tandem_open` with `force: true` clears annotations, awareness, and content in a single transaction. Don't use mid-review -- annotations are still lost. See observer ownership table in [architecture.md](architecture.md#ymap-observer-ownership).
- **CRDT fallback logging.** `buildDecorations()` emits `console.warn` when an annotation falls back to flat offsets. Check the browser console -- these indicate CRDT degradation.
- **Dead CRDT RelativePositions must be stripped, not preserved.** After `reloadFromDisk` replaces Y.Doc content, old `relRange` RelativePositions reference deleted items. `refreshRange` strips dead `relRange` and re-anchors from flat offsets. A stale `relRange` that resolves to null blocks the lazy re-attachment recovery path -- deletion is better than preservation.
- **Hocuspocus replaces Y.Doc in `onLoadDocument`.** The `onDocSwapped` callback in `provider.ts` reattaches server event queue observers to the new instance. A runtime warning fires if the callback is missing. See #178 audit.
- **Annotation-sync cleanups distinguish swap vs close.** `registerAnnotationObserver` returns `(phase?: "swap" | "close") => void`. A Y.Doc swap keeps the per-doc tombstone ledger alive so in-flight debounced writes still serialize tombstones; only `"close"` drops the ledger. `reattachObservers` passes `"swap"`; `clearFileSyncContext` / `setFileSyncContext`'s replace path pass `"close"`. See #333.
- **Y.js "Invalid access" warnings** during session restore are harmless stderr noise.
- **`getElementText()` strips inline marks and separates nested blocks.** The function uses `toDelta()` (not `toString()`) for XmlText content, emitting `\n` for embedded elements (hardBreaks) **to preserve XmlText index alignment**. Child XmlElements (listItem, paragraph, blockquote) are separated by `\n`. This matches ProseMirror's block structure for correct flat-offset alignment.

### MCP / Server
- **Channel shim uses low-level `Server`, not `McpServer`.** The Channels spec requires `import { Server } from '@modelcontextprotocol/sdk/server/index.js'` with explicit `setRequestHandler()` calls. The HTTP MCP server uses the high-level `McpServer` wrapper.
- **Channel meta keys use underscores only.** The Channels API silently drops meta keys containing hyphens. Use `document_id`, `annotation_id`, `event_type` -- not `document-id`.
- **`APP_VERSION` is baked at build time** via the `__APP_VERSION__` tsup define in `src/server/mcp/server.ts`. Falls back to `createRequire("../../package.json")` in tsx dev and vitest. `__MCP_SDK_VERSION__` follows the same pattern. `findChangelogPath()` in the same file walks up from `__dirname` to find `CHANGELOG.md` (handles both `src/server/mcp/` in dev and `dist/server/` in production).
- **MCP must start before Hocuspocus** in stdio mode -- init timeout fires if order is reversed.
- **HTTP MCP is multi-session: one `McpServer` per transport, keyed by `Mcp-Session-Id`** (`mcp/transport-registry.ts`, ADR-045). **This is the *legacy* branch as of MCP `2026-07-28`, which removed protocol-level sessions, the `Mcp-Session-Id` header and the `initialize` handshake** — accurate today (no SDK implements the new revision yet) and required for as long as un-upgraded clients exist, but do not key new per-client state on it. See ADR-045's 2026-07-30 amendment and #1249. `initialize` never evicts another session. Two SDK facts are load-bearing: `Protocol.connect()` throws if a server already has a transport (so servers can *not* be shared), and `transport.sessionId` is minted while *handling* the initialize request, so entries can only be registered from the `onsessioninitialized` callback -- not after `connect()`. Unknown session id → 404 `-32001`, never 503. `X-Claude-Session-Id` (the *Claude Code* session, distinct from the MCP session) is **optional**: only the stdio-bridge config path carries it; the direct-HTTP entry `buildMcpEntries` writes for Claude Code CLI has no subprocess and sends nothing. Never assume it is present. Read it inside a tool handler via `getCurrentSessionId()` (`sessions/context.ts`); the `AsyncLocalStorage.run()` must wrap the **entire awaited** `handleRequest`.
- **Mutating integration routes (`POST /api/integrations`, `POST /api/integrations/apply`, `POST/DELETE /api/integrations/secrets/:ref`, `POST /api/integrations/install-claude-code`) require both `assertOriginAllowlisted` AND `assertLoopbackForMutation` at handler top, BEFORE any state mutation.** The apply route additionally gates on a constant-time nonce compare + in-process mutex + `IntegrationsFileSchema.safeParse` defense-in-depth. The install-claude-code route gates on origin + loopback + a dedicated in-process mutex (`getInstallGate()`/`_resetInstallGateForTests()`, mutex set inside the `try`) but **deliberately carries NO nonce** (S3: no persisted intent to bind, host-pinned + idempotent install). Read-only `GET` routes are intentionally exempt from the loopback gate; `GET /api/integrations/existing` scrubs `env`/`headers` so the bearer token in `~/.claude.json` never reaches the wire (`extractEntry` in `src/server/integrations/existing-config.ts`). `GET /api/integrations/claude-cli-status` is also ungated and LAN-reachable, so its response is **enum-only** (`{ presence }`) — never the resolved `~/.local/bin` path (F6). The installer itself (`install-claude-cli.ts`) fetches the pinned `https://claude.ai/install.{sh,ps1}` script and `execFile`s the interpreter on a locked-down temp file — never `| bash`/`| iex`; minimal allowlisted env so the wire-fetched script never sees the auth token (F1).

### Client / UI
- **ChatPanel + SidePanel are always mounted** (CSS display toggle, not conditional rendering) so local state persists across panel switches.
- **localStorage access needs try-catch.** Some browsers (incognito, storage-disabled) throw on access. Without the guard, the tutorial component crashes the app.
- **`tandem_editAnnotation` only works on pending annotations.** Accepted or dismissed annotations return an error.
- **Tutorial annotations are injected idempotently.** `injectTutorialAnnotations()` checks for existing IDs before inserting. Tutorial only activates on `sample/welcome.md`.
- **Never write `$state` synchronously from a Tiptap event handler — bridge through `createCoalescingTick`** (`src/client/utils/coalescing-tick.ts`). Tiptap emits `update`/`transaction` synchronously from ProseMirror's `dispatch`, and ProseMirror dispatches from DOM handlers including a native `blur` that can fire *during* a render. A `$state` write landing inside an active Svelte reaction throws `state_unsafe_mutation` — **in production too** (`state_unsafe_mutation()` has an `else` branch; it is not a dev-only assert). The error message is misleading: it names only `$derived`/`$inspect`/template expressions, but the real condition is `active_reaction.f & (DERIVED | BLOCK_EFFECT | ASYNC | EAGER_EFFECT)`, so a plain `{#if}` block triggers it. Also note `transaction` vs `update`: the blur transaction sets `setMeta('blur')` with no doc change and `update` is gated on `docChanged`, so only `transaction` subscribers are exposed — and `transaction` fires on every cursor move, which is why the tick coalesces. Fixed at four sites (`StatusBar`, `FormattingToolbar`, `FindReplaceBar`, `FormattingBar`); `useMarginPositions` already defers via its own scheduler. `OutlinePanel` / `useTutorial` write state from `update` only, which needs `docChanged` — same class, no observed instance.
- **Tab drag-reorder (A30) targets off a frozen snapshot, and its transforms must stay imperative.** `dropTarget` comes from a geometry snapshot captured once at the 5px threshold (`src/client/tabs/tabDragMotion.ts` — pure, no DOM), compared against **static** midpoints; `document.elementFromPoint` survives only behind the single `dragDegraded` flag, which also re-shows the edge wedge. Never re-introduce live hit-testing on the healthy path: parting a sibling opens a void exactly under the pointer, so the drop target clears and the drop silently no-ops (lesson 88). Parting magnitudes must come from running the real `applyReorder` and diffing — a mirror of it would run against a different array. The transform writes are deliberately **imperative DOM, not `$effect`-driven**: `animate:flip` IS the settle, and it only works because the clear lands in a `queueMicrotask` *between* flip's `measure()` (transforms still on, so `from` is what the user sees) and its `apply()`. An `$effect` would run inside the flush, before both, inverting the invariant. The one deliberate exception is degraded mode's clear, which is `$effect`-driven and benign — it's carved out in a comment; don't "fix" it. Release animation control with `cancel()` (never `finish()`, which destroys an outroing node) on non-`inert` wrappers before snapshotting, or a tab re-grabbed within 200 ms of any settle won't follow the pointer — a running Web Animation outranks inline style.
- **Two CSS pipelines — identical CSS text compiles differently depending on which file it lives in.** `index.html`'s inline `<style>` (the token + floating-pill recipe home) is emitted **verbatim**: no minification, no autoprefixing. Component `<style>` blocks and `src/client/**/*.css` go through **lightningcss** (`build.cssMinify: true` falls through to it; dev runs neither). Consequences: (1) **in bundled CSS, write the standard property alone** — lightningcss autoprefixes it from `build.cssTarget` (`safari16.4` today). Hand-writing a `backdrop-filter` + `-webkit-backdrop-filter` pair *collapses it to the `-webkit-` form alone* when the prefixed line comes last, and Chromium never implemented that form, so the declaration goes **inert** — this is exactly how #798's `backdrop-filter: none` reset silently evaporated for 6 weeks (#1189/#1188). (2) **In `index.html`, hand-write prefixes** — nothing adds them for you. (3) The rule is not "never hand-write a prefix": `-webkit-line-clamp` is **required** (lightningcss won't add it). (4) A **cross-file override** between `index.html` and a component crosses the seam and is the general hazard. `tests/design-system-impl/css-pipeline-contract.test.ts` pins all of this against the real minifier. See lesson 83.

- **Margin-view density has TWO independent pressures.** **Width** → `MarginMode` (`full`→`narrow`→`stub`→`off`, viewport-driven with 32px hysteresis) sets the track size; `narrow` renders `clamped` (no action row — 160px can't fit one). **Height** → `marginPressure.resolveCrowding` simulates the stack from RAW anchor tops plus the annotation *model* and returns a crowded set, which renders `compact` (one-line teaser, action row KEPT). `cardDensity` is the single arbiter. **Never feed measured `heights` or `adjustedPositions` into the pressure pass** — that reopens the density→height→collision→density cycle rejected in #917. Margin tracks are elastic (`full` column 240→400px) via a `clamp((100% − measure)/2, …)` grid track that only consumes surplus gutter, so it is content-width-neutral; expressing that ceiling as anything else would close the cycle through text reflow.
- **Post-Wave-I rails are fixed:** left = outline, right = Annotations + Chat. The cross-rail tab picker is gone (`RailTabPicker.svelte` deleted, `leftRailTabs`/`rightRailTabs` stripped from settings via the v4→v5 migration, `RailTab` type removed). `LayoutModel` exposes visibility helpers only; two independent booleans (`leftPanelVisible`, `rightPanelVisible`) replace the old three-layout-mode system, persisted in `tandem:settings`. `App.svelte` uses inline `{#snippet}` blocks for `resizeHandle` and `tabbedPanel` (right rail); the left rail is rendered inline.

### Files, Sessions & Lifecycle
- **Session files** via `env-paths`: `%LOCALAPPDATA%\tandem\Data\sessions\` on Windows, `~/Library/Application Support/tandem/sessions/` on macOS, `~/.local/share/tandem/sessions/` on Linux. Delete to force fresh load.
- **Start-at-login is opt-in and desktop-only** (#1236, ADR-046). `tauri-plugin-autostart` registers `--tandem-autostart` on the OS entry; a login launch starts hidden (`visible: false` + `should_start_hidden`, with `StateFlags::VISIBLE` masked out of window-state so `setup()` is the sole visibility authority) and defers the Claude launcher via `TANDEM_DEFER_LAUNCHER=1` → `LauncherUnavailableReason "deferred-autostart"`. The `LAUNCHER_DEFERRED` `AtomicBool` in `lib.rs` is a **latch re-read on every sidecar spawn**, not a captured value — `restart_sidecar` re-enters `start_sidecar`, so a snapshot would permanently re-defer after any crash-restart. `show_main_window` is the single release point (`note_user_presence` → `POST /api/launcher/start`); that route checks `unavailableReason() === "deferred-autostart"` **before** the nonce, or it would be an HTTP bypass of `TANDEM_DISABLE_LAUNCHER=1`. State is read live from the OS — **no `tandem:settings` field, no schema-version bump**; don't add one.
- **Auto-open `sample/welcome.md`** on first run. On upgrade, `CHANGELOG.md` opens instead (read-only — prevents the 60s autosave timer from round-tripping it through `remark-stringify` and rewriting the file with escape noise; see lesson #69 and issue #605 for the underlying serializer fix). Both open **before** Hocuspocus/MCP start.
- **Startup document opens must precede server bind (HTTP mode only).** Any document that should appear on startup must be opened before Hocuspocus binds. Stale browser tabs reconnecting can CRDT-merge incomplete `openDocuments` lists, removing tabs that were added after the server started accepting connections. Stdio mode has no startup document opens.
- **OS file-association cold start.** When the Tauri desktop app is launched via the OS file-association handler (e.g. double-clicking a `.md` from Finder / Explorer), `src-tauri/src/lib.rs` reads `std::env::args()` via `extract_file_arg`, validates extension + path, and exports it as `TANDEM_OPEN_FILE` before spawning the sidecar. `src/server/startup-file.ts#maybeOpenStartupFile` consumes the env var and calls `openFileByPath` *before* HTTP bind, naturally preempting the `welcome.md` fallback. Warm-start (second instance) uses the `tauri-plugin-single-instance` callback to POST `/api/open` against the running sidecar. macOS file-association launches deliver paths via `RunEvent::Opened` (Apple Event `kAEOpenDocuments`) — not argv — and are queued in `PendingOpens` until `wait_for_health()` returns, then drained before the `SIDECAR_HEALTHY` flag flips. macOS cold-start can briefly show `welcome.md` before switching to the requested file (known limitation). **Since #1344 both entry points share one validator, `validate_open_candidate`** — argv reaches it via `extract_file_arg`, the macOS Apple Event via the `RunEvent::Opened` handler — so an invariant added to it covers both. It refuses UNC (`\\` / `//`) **before** any filesystem call, because `is_file()` on a network path performs the SMB handshake the check exists to prevent, and it scans the *resolved absolute* path for a stray colon (NTFS alternate data streams); scanning the un-joined candidate let a relative `f:ADS.md` through. **Rejection delivery is two-surfaced and the buffer is the load-bearing half**: a cold-start rejection is classified in `setup()`, before `App.svelte` exists, so an event alone drops silently on exactly the failure it reports. The reason code is buffered unconditionally and drained by the take-once `get_startup_rejection()`; the `startup-file-rejected` event is a **payload-free nudge** to call that drain, never the carrier. That is why Rust never needs to know whether the listener is wired — which it cannot know.
- **File watcher self-write filtering is two-layer (arrival counter + delivery fingerprint).** Layer 1: `suppressNextChange()` is consumed in the `fs.watch` callback (arrival), not inside the debounce timer callback (delivery) — checking at delivery time would let an external edit arriving within the debounce window get suppressed instead of the self-write. But the arrival counter is armed *once* per write while an NTFS atomic rename fires ~2 `change` events, so one leaks past it. Layer 2: pair `recordSelfWrite(filePath, content)` *after* every `atomicWrite`/`atomicWriteBuffer` self-write (save, save-as, restore in `document-service.ts`/`file-opener.ts`) — it stores a content fingerprint (size + SHA-256 of the exact bytes, hashed in-memory so it's synchronous and race-free), and `isSelfWriteEcho` in the debounce timer skips the reload only when the on-disk bytes match it exactly. Must be a **content hash, not size+mtime** (mtime is unreliable on FAT/exFAT/SMB and for mtime-preserving writers; a false match would silently drop a real external edit). The fingerprint is TTL-bounded (`SUPPRESS_TTL_MS`) so it's an echo detector, not a long-lived content oracle. `tandem_applyChanges`'s write is intentionally *not* fingerprinted — its reload re-imports tracked-changes markup (semantic), not an identical-bytes echo.
- **Word comment offsets need re-anchoring.** `.docx` comment ranges reference HTML-converted content. `docx-comments.ts` re-resolves via `anchoredRange()` after Y.Doc population.
- **Exception handler is narrowed, not blanket.** `uncaughtException`/`unhandledRejection` only swallow known Hocuspocus/ws errors (via `isKnownHocuspocusError`). Unknown errors call `process.exit(1)`.
- **Boot-time orphaned-temp reaper.** `reapOrphanedTemps` (`src/server/file-io/reaper.ts`) sweeps `.tandem-tmp-*` atomic-write siblings older than 1 hour from the annotations + sessions dirs **only** (never user document dirs). These orphan when the process is SIGKILLed between `writeFile` and `rename` (dev restarts, force-quits). Fire-and-forget at boot (un-awaited, with `.catch()`), skipped when the store is read-only. The 1-hour age gate — not the store lock — is what makes it safe against a concurrently-starting instance, since session-dir writes aren't lock-gated. The match regex (`^\.tandem-tmp-(\d+)-([0-9a-f]{12})$`) is the safety boundary: `store.lock`, `<hash>.json`, `.corrupt.*`, `.future`, and session files can never match.
- **Pre-overwrite document backups are path-keyed and once-per-run.** `snapshotBeforeFirstWrite` (`src/server/file-io/doc-backup.ts`) copies a `.md`/`.txt`/`.docx` file's on-disk bytes verbatim to `{APP_DATA}/doc-backups/<path-hash>/` before Tandem's FIRST write to that path per server run — the text branch (`atomicWrite`) AND the binary branch (`.docx` via `atomicWriteBuffer`); also called from Save-As when the target exists, and from `restoreDocumentFromBackup` (so a restore is itself reversible). The module is format-agnostic (raw `Buffer` copy), so `.docx` snapshots restore byte-identical; `restoreDocumentFromBackup` reads/writes them as a `Buffer` and routes through `reloadFromDisk` (re-parses + re-injects Word comments). The `tandem_restoreBackup` MCP tool exposes these snapshots for `.docx` too, falling back to the `{name}.backup.docx` sidecar (written by `tandem_applyChanges`) only when no snapshot exists. Keyed by `docHash(filePath)` not docId (docId survives rename; the snapshot question is per-path). Failure contract is the OPPOSITE of `integrations/backup.ts`: a failed snapshot warns and lets the save proceed (gate stays unset → retried next save). Deliberate skips (no source file / byte-identical / 500 MB cap) DO set the gate. Shutdown now flushes dirty docs (`autoSaveAllToDisk`, 5s-bounded) before `saveCurrentSession`; the order is `unwatchAll` → `stopAutoSave` → `autoSaveAllToDisk` → `saveCurrentSession`.

### Testing & E2E
- **E2E tests start their own server** via Playwright `webServer`. `freePort()` kills existing :3478/:3479 -- running E2E alongside `dev:server` will terminate your dev server.
- **Uploaded files (`upload://` paths) are read-only.** `tandem_save` returns a session-only save.
- **`cargo test` requires sidecar stubs + GTK libs — and the pre-push hook runs it**, so a fresh clone cannot push until both are in place. `tauri_build::build()` checks all declared `resources` (`dist/client`, `dist/server`, `dist/channel`, `dist/stdio-bridge`) and both `externalBin`s. **`dist/monitor` is NOT a declared resource** — it was listed here for months and is not in `tauri.conf.json`, so `mkdir`ing it is harmless but proves nothing; `.github/workflows/ci.yml` omits it and passes. Keep this list synced with `bundle.resources`, not with `dist/`:
  ```sh
  TRIPLE=$(rustc -vV | sed -n 's/host: //p')
  mkdir -p src-tauri/binaries dist/{channel,server,client,stdio-bridge}
  touch src-tauri/binaries/{node-sidecar,tandem-reaper}-$TRIPLE{,.exe}
  apt-get install -y libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf libxdo-dev
  ```
  **`libxdo-dev` is required to link and is easy to miss** — it is pulled in by a Cargo feature, so the failure is a bare `rust-lld: error: unable to find library -lxdo` thousands of lines into linker output, long after the GTK packages everyone remembers are installed. Same dependency as the #1227 runtime bug.

### Windows / Cross-platform
- **`core.autocrlf=true` + late `.gitattributes eol=lf` leaves the working tree CRLF-stale.** The `eol` attribute only affects future checkouts — when `biome check .` fails locally on Windows with only CRLF format errors while CI passes, check `git ls-files --eol | grep "w/crlf"` before blaming the change under review; the fix is `git add --renormalize .` committed as its own dedicated PR, never `core.autocrlf=false`.
- **`.husky/pre-commit` needs its `#!/usr/bin/env sh` shebang.** Without it, git-bash on Windows fails the commit with "cannot spawn: Exec format error" — restore the shebang rather than reaching for `--no-verify` (which `block-no-verify.sh` blocks anyway).
- **`path.basename` on Linux doesn't split Windows backslash paths** (`path.basename('C:\\x\\f.md')` returns the whole string in Ubuntu CI). Normalize first — `filePath.replace(/\\/g, "/")` — before any separator-aware `path.*` call (`basename`/`dirname`/`extname`); pattern lives in `docIdFromPath` in `src/server/mcp/document-model.ts`.
